An S1/S2 Bug filed by hand (`asf new bug`) sits undecided until the next daily groom, which can be up to 24 hours away. BUG → FIX only takes decided Bugs, so an urgent defect filed at 18:00 waits until the next day's groom and adjudicate. Observed 2026-09-23: B-0087 and B-0088 (S2) do not appear in `asf next`.

Expected: with approvals.groom: auto, a new S1/S2 Bug is decided within one tick. Either the tick runs the groom policy pass on items new since the last groom, or an S1 Bug is decided on filing, as file_bug: auto already allows for auto-filed Bugs. Time to first session on an S1/S2 Bug should be a tracked metric.

Operator direction (2026-09-23): grooming is continuous. It runs every tick, like the rest, not once a day. Each tick, the groom policy pass takes whatever is new since the last tick: inbox items become cards, and rules decide what they can. It raises questions for the rest, and the adjudicate row answers them in the same or the next tick. The per-date groom file and the daily stamp (asf/tick/steps.py daily_due) were designed for a once-a-day cadence. Rework them so an intra-day groom is idempotent and additive. The rollup/stale parts of the daily step can stay daily.

Found 2026-09-23 19:05: the groom file only lists "Auto-filed Bugs not yet decided" and "Undecided > 3 days". A Bug filed by hand is never asked about until it is 3 days old, so the adjudicator never sees it either. Every undecided open Bug belongs in the groom's questions from its first groom. This Bug was itself stuck behind that gap; the operator's "fix first" decision (2026-09-23) was recorded with `asf set … decided=true` to break it.
