## Symptom

Eight spec branches and three fix branches held by harvest with `conflict in docs/specs/f-XXXX.md` (or a test file), each 6 to 20 commits long, each a tangle of "Merge origin/spec/F-XXXX into spec/F-XXXX", "merge the pushed branch — same spec, rebased onto main", "join the branch's earlier push". Harvest's rebase replays both lineages of the same file and conflicts on the first one; the correction session repeats the merge; the item reaches the round cap.

## Cause

A session whose branch already exists on origin starts in a worktree spawn has rebased onto the trunk (B-0046, B-0048), or finishes a conflicted rebase itself. Its branch then no longer contains `origin/<branch>`, and the only push that publishes a rebased branch is a force — which the standing rules and the worker settings forbid (`git push --force*` is denied). Told "push the same branch, never a force", the session does the one thing left: it merges its own stale remote (or the trunk) into the branch, and pushes the merge. Nothing in the factory publishes a rebased lane branch, and nothing refuses a merge commit on one.

## Fix

- The factory publishes a rebased lane branch, never the session: `asf.workers.lifecycle.publish(worktree, branch, remote_sha)` pushes `--force-with-lease=<branch>:<remote_sha>` (a plain push when the branch is not on origin yet); spawn calls it after its clean takeover rebase, health calls it when a run ends ok with a clean tree whose HEAD is not on `origin/<branch>` — so `finished` means pushed still, and a session never needs a force.
- Harvest refuses a merge commit on a lane branch with the named reason `merge commit on a lane branch: <sha> — rebase onto origin/<main>, never merge` as a correction back to the session.
- The code-generated closing paragraph of every brief (`asf.briefs.build.TAIL`) says it: a branch already on origin is rebased, never merged; a push refused as non-fast-forward after a rebase is reported `pushed: rebased <sha> — the factory publishes`, and the factory publishes it. The `correct` and `spec` templates say the same in their own words.

Tests: `tests/test_lifecycle.py` (publish: a rebased worktree reaches origin, a lease that moved is refused), `tests/test_workers.py` (spawn publishes after its takeover rebase; health publishes a clean rebased run and judges it finished), `tests/test_harvest.py` (a merge commit is held with the named reason), `tests/test_briefs.py` (the closing paragraph carries the rule).
