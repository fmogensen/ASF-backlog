## Statement

Part (b) of D-0048: a correction should continue the **same runtime session** (`--resume <session_id>`, read from the log's `system/init` line), so the fixer keeps its context instead of rebuilding it from the brief.

## Needs a spec first

- `Job.resume_session_id` and `build_command` adding `--resume`; what the fake runtime replays.
- Whether a resumed session gets the correction as the prompt (`-p`) or the brief is rewritten.
- Registry shape: same job record, `rounds`, the new pid; health's judgement of a resumed run (B-0028's reader already reads the last run).
- Cost accounting per round.

Blocked by B-0032 (part a) landing; spec in `docs/specs/` of the code repo, then the plan.
