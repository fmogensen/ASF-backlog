## Description
The reader exposes `repo_dir`, `repo_slug`, `backlog_dir`, `ci.budgets` and `ci.labels`. The product file written for this product nests them as `repo.dir`, `repo.slug`, `backlog.dir`, `ci.budgets_minutes` and `ci.runner_labels`. Loading it returns a product whose `repo_dir`, `repo_slug` and `backlog_dir` are all `None`, and whose `stage_limits` and `approvals` are the string `TODO` rather than maps — so any caller doing `stage_limits.get(...)` raises instead of falling back. Nothing validates the file, so the failure arrives later, as a job that cannot find a repository.

## Fix
One schema, checked: the config loader validates a product file against a declared field list on load and refuses with the offending key and line. `asf doctor` prints the same check as a table row.
