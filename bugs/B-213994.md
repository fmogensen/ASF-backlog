## Description
asf/kernel/trunk.py `missing_ids` reads any loader stand-in as "absent on the parent", including a module that exists there but fails to import on the host (follow-up to PR #1725). The run on the red commit now guards the verdict, but the result and the revert body still say the ids "do not exist". Also docs/specs/f-0357.md D1 and section 2.2 still describe one run on the parent; the code runs the ids on the parent and on the red commit, and retries an unanswerable read at most twice.

## Acceptance
- [ ] An id whose module file exists in the parent tree and fails to import is an error, not `missing`. — tests/kernel/test_blame_before_revert.py::ParseUnittest::test_an_id_whose_module_exists_but_fails_to_import_is_an_error_not_missing
- [ ] An id whose module, class or method is absent in the parent tree is `missing`. — tests/kernel/test_blame_before_revert.py::ParseUnittest::test_an_id_the_loader_stood_in_for_is_missing
- [ ] The spec describes the two-run read and the bounded retry. — tests/kernel/test_blame_before_revert.py::ProbeClass::test_ids_green_on_the_parent_are_run_on_the_red_commit_too_and_both_are_kept
