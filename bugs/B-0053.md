## Symptom

Every push to a worker branch (`fix/B-0039` at acfcd1f, `fix/B-0025` at caaaeff) runs the CI workflow and, when the session's work is mid-way, fails — the operator gets a "Run failed" notification per push while `main` is green. Runner minutes are spent on branches that the harvest gate will test anyway before landing.

## Cause

`.github/workflows/tests.yml` triggers on `push:` for all branches and `pull_request:`. The product's landing convention is fast-forward via harvest, whose gate runs the same suite and checks on the rebased branch; CI on `main` after the landing is the definition of done (D-0047). Branch runs add nothing the record reads.

## Fix

`on: push: branches: [main]` and `pull_request:` (kept for outside contributors and for `landing: pull-request` products). A test in `tests/test_install.py` (or a new `tests/test_workflow.py`) parses the workflow and asserts the push trigger is limited to the trunk. Document in the workflow header why.

## Not in scope

Branch protection / required checks on main (a separate ruling — CI is a signal on this repo, not a gate).
