## Description
S1: signature: lane naming reword force-pushed a green, land-requested PR head (trees identical) and its required CI had to rerun from scratch.

The lane's naming reword force-pushed a PR branch whose PR had just gone green on every required check and carried a `land --priority` request ("reword <branch>: 1 subjects, trees identical — pushed"). The new head has an identical tree but no CI, so the merge queue waits "pending at <new head> — gate (queued)" and a full rerun on a saturated pool costs 45–60 min plus the batch — on a product's goal day this lost the goal PR's window.

## Acceptance
- [ ] The naming reword never rewrites a branch whose PR has a land request, any green required check on its head, or a CI run in flight; it defers the reword until after landing (the squash subject is set at merge time instead).
- [ ] When a new head's tree is byte-identical to a previous head of the same PR whose required checks were all green, the merge queue and landing gate accept that green for the new head (tree-equivalence), recording "green carried from <old head> (identical tree)".
- [ ] Hermetic tests: reword skipped with a land request / green checks / run in flight; identical-tree green carried; a different tree is not carried.

## Extension (2026-10-06 ~20:30) — the same class from "drop copies"
On botseon, batch a2f8aaa (#1205, #1196, #1167) was 60 min into CI with gate-tests running when the lane's `drop copies cloud/T-37354` force-pushed the branch to c3e4bad36. The queue dropped a2f8aaa ("head moved") and the batch stacked on it, 648d2e5: two batches of CI lost. No lane rewrite has an in-batch, land-request or in-flight guard (asf/harvest/lane.py: reword ~2536, drop copies ~2698, normalise ~2766, transplant ~3002).

## Acceptance (extended)
- [ ] One shared guard applies to every lane rewrite: reword, drop copies, normalise, transplant and any rebase. It defers the rewrite (logged "deferred — <reason>") while the branch's PR is in a merge-queue batch, has a land request, has a CI run queued or in flight on its head, or has every required check green on its head.
- [ ] A deferred rewrite runs after landing, or is dropped if the PR landed, with no force-push.
- [ ] Hermetic tests: each rewrite kind is deferred in each of the four cases, and proceeds when none holds.

## Loop case (2026-10-06 23:2x, botseon T-42278 / PR #1216)
A correction session starts from head X. Between rounds the lane rewords or drops copies (a report rename: "asf: report review-t-42278" → "asf(T-42278): report …"), so the branch moves to X'. The session's publish is then refused as non-fast-forward, and the review's C1 commit never lands. This happened three rounds in a row. Added acceptance:
- [ ] When a session's commits sit on top of a head the lane has since rewritten with an identical tree, the lane replays them onto the rewritten head (cherry-pick, tree check) and publishes. It never refuses them as non-fast-forward. Tested.
- [ ] A correction session always starts from the branch's current origin head (its worktree is reset to it at spawn). Tested.
- [ ] `conventions.rewrites: off` (default on) turns off the lane's reword, drop copies and normalise for a product, as an escape hatch. Tested.
