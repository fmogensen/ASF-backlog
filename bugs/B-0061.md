## Symptom

Six spec branches (`spec/F-0076` … `spec/F-0087`) and two fix branches (`fix/B-0025`, `fix/B-0043`) whose content is on the trunk — or whose Bug is Closed — stay on origin, their worktrees under `~/.ASF/state/asf/worktrees/` stay `keep … ended: not in origin/main`, tick after tick. Their runs were marked by hand `end_reason: superseded: the work is on main` (and one by a failed cold retry, `failed: unpushed work`), so they are not `finished`.

## Cause

`run_product_harvest` read the run's verdict first: only a `finished` run's branch was looked at at all, so the content rules of B-0057 (landed when its changes are on the trunk, archived when its Bug is Closed) never reached a branch whose run ended any other way. Health then kept the worktree: not landed, not empty.

## Fix

Content decides before the run's verdict does. For every lane branch on origin whose run has ended (never a live run's), harvest first applies `already_on_trunk` and `superseded_by`; only the gated landing still needs `finished`. Test: `tests/test_harvest.py::ProductHarvestTests::test_b0061_content_decides_whatever_the_run_ended_as` — a branch of a run that ended `failed` is landed when its change is on the trunk and archived when its Bug is Closed; a live run's branch is never touched; an unfinished run with real work is not gated.
