## Description
A revert PR can merge a head the kernel never made. `_Applier.RevertPR` (asf/kernel/apply.py) finalizes with `enable_auto_merge(number)`: an unpinned GitHub auto-merge. When the revert is opened with auto-merge on while its CI runs (asf/kernel/mainline.py, `auto_merge=confirmed == 'green'`), a later push to the revert branch is not cancelled by GitHub. `withdraw_auto_merge` (asf/kernel/decide.py) only runs for item PRs in `_judge_pr`, never for `Facts.revert_prs`. B-218952 closed this for item PRs only.

## Acceptance
- [ ] A revert PR's finalize merges pinned to the head its own CI read green (A.MergePR, --match-head-commit); RevertPR never calls GitHub enable_auto_merge — tests/kernel/test_revert_auto_merge_withdrawn.py::FinalizePinned
- [ ] Any auto-merge left on a revert PR (Facts.revert_prs) is withdrawn every tick, independent of _judge_pr and regardless of main's red/green state — tests/kernel/test_revert_auto_merge_withdrawn.py::FinalizePinned
- [ ] A commit pushed onto the revert branch after finalize changes its head away from the one the kernel confirmed green, so decide() never emits a merge pinned to the new, unconfirmed head — tests/kernel/test_revert_auto_merge_withdrawn.py::PushedAfterFinalize
