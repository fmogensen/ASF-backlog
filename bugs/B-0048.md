## Symptom

06:45 tick: `held fix/B-0025: conflict … — back to its session (round 30)`, `waits adjudicate-b-0025 — spawn failed: git worktree add -b fix/B-0025 …: a branch named 'fix/B-0025' already exists`. Same for fix/B-0043. Since B-0046 the `correct` row can reuse the held branch, but after three rounds the row becomes `adjudicate`, which spawns through the new-branch path and fails every tick — and the round counter keeps climbing (30) instead of stopping at the cap.

## Cause

- `asf/workers/spawn.py`: the branch-reuse from B-0046 is keyed on the row kind `correct`; an `adjudicate` (and any other row whose `row.branch` already exists on origin) still runs `git worktree add -b`.
- `asf/harvest/harvest.py land_ff` increments `rounds` on every hold regardless of the cap, so a branch that cannot be corrected is re-held forever with a growing number and no operator line.

## Fix

- `spawn`: reuse an existing branch for **every** row kind whose branch exists on origin (the check is on the branch, not the kind); create a new one only when it does not exist.
- `land_ff`: at `rounds >= 3` do not increment; print `held <branch>: <reason> — adjudicate pending` once and record `operator_flagged` when the adjudicate row itself cannot launch twice (the NEEDS OPERATOR line from step_health).
- Footprint: `asf/workers/spawn.py`, `asf/harvest/harvest.py`, `tests/test_workers.py`, `tests/test_harvest.py`.
