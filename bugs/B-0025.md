## Description
A session that ended without committing anything (it died at launch, or found nothing to do and did not push) leaves its worktree under `state/<p>/worktrees/<job>`; health keeps it (the reap rule requires a pushed, landed branch), and the next wave's `spawn` refuses `worktree already exists` — so the Bug is never retried. Seen on 2026-09-21 after the first wave died on an unmapped model label: B-0003 and B-0008 could not relaunch.

## Fix
Health reaps a worktree whose session is `ended`, whose pid is dead, and whose branch has zero commits ahead of the base (nothing can be lost) — the complement of B-0019 (a LIVE session or a branch WITH commits is never reaped). Spawn, meeting an existing worktree with a dead session and zero commits, removes it and proceeds; with commits, it refuses with the branch name and the commit count so a human can look. Tests for all three cases.
