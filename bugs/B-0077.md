## Symptom

F-0085, F-0031 and F-0087 have every Task Closed, their code on the trunk and a green run on it, and they sit at `Resolved` for ever. `asf status` has read `Prod — not configured` all along.

## Cause

`asf/evidence/evidence.py feature_state()` closes a Feature only with `all_merged_in_prod` **and** `all_prs_checked`, and `asf/record/ingest.py:373-377` computes the first by asking whether each Task's merge sha is an ancestor of `prod_sha`. A product with no deploy configured has no `prod_sha`, so the test is false for ever: **no Feature of such a product can ever be Closed.** ASF itself is that product — it ships as a package, not a service — and so is any library, CLI or tool a factory builds.

## Fix

A product's definition of "in production" comes from its own config:

- `deploy_sha` configured (a service): unchanged — Closed needs the merge sha in the deploy and the operator's tick.
- No deploy configured (a package or tool): the trunk **is** production. `all_merged_in_prod` is satisfied by every Task's commit being on the trunk with CI green at or after it (D-0047's own definition of done), and `all_prs_checked` by the landing gate that let it in.
- `asf doctor` says which of the two a product is, so an operator sees it before the first Feature stalls.

The evidence line says which rule was used: `on the trunk, CI green (no deploy configured)` or `merge <sha> in deploy <sha>, checked`.
