## Description

At 13:22 the tick stopped writing its log and stayed "running" for over nine minutes. It was not
hung: it had a `claude -p --permission-mode bypassPermissions --model claude-opus-5` process as a
direct child and was waiting for it to finish.

That is a different launch from the wave's, which detaches its sessions, gives each one an
account's settings file and `acceptEdits`, and records it in the registry. This one blocks the
tick, so `health` does not mark dead runs, `harvest` does not land branches, and the operator's
tables are not printed — for as long as a model session takes. The tick fires every 600 s, so a
session of this length also overlaps the next tick.

Compounding it: the gate timeout was raised to 1800 s today (B-0082), so a slow gate can now hold
the tick for half an hour, and this blocking session sits in the same serial line.

## Acceptance

- No tick step waits on a model session: a step that needs one records it in the registry and
  returns, exactly as `wave` does, and the next tick reads its result.
- Every session the factory starts appears in the registry with its job, account and model — a
  session no table can see is a session nobody can stop.
- A tick that exceeds its own interval prints one line saying which step it was in, and the
  scheduler does not start a second tick over it.
- A test: a step that launches a session returns before the session ends, and the run is in the
  registry.
