## Symptom

Six fix sessions in two nights (B-0005, B-0016, B-0039 twice each) ended `success` with the words "I'll stop here and wait for the background test-suite task to finish; I'll continue with the commit and push once it reports back." — no commit, no push, a dirty worktree. Health judged them finished (B-0051 now turns that into a correction), harvest saw nothing, the item was re-emitted.

## Cause

The session runs the full suite as a **background task** (the runtime offers one) and returns its result before the task ends; a `-p` session has no "later". The brief (`asf/briefs/templates/fix-bug.md` and the code templates) says to run the suite and push, but not that both must happen in the foreground before the final message, nor that a result with unpushed work counts as a failure.

## Fix

- Every brief template ends with a fixed closing paragraph (code-generated, in the preamble builder, not per template): "Run the gate in the foreground and wait for it. Your last act is `git push`. Never start a background task you do not wait for. A result with uncommitted or unpushed work is a failed session (B-0051) and comes back to you as a correction."
- The runtime's `--settings` for workers (operator config) denies the background-task tool for `-p` sessions where the runtime allows it; the tick's `doctor` row notes when it is not denied.
- `health` (B-0051) already classifies; add the reason text `unpushed work` to the correction so the resumed session sees why.
- Footprint: `asf/briefs/build.py` (closing paragraph), `asf/briefs/templates/*.md` (remove the duplicated wording), `tests/test_briefs.py` goldens, `~/.claude-workers/settings.json` (operator).

## Tests

`test_every_brief_ends_with_the_closing_paragraph`; goldens updated.
