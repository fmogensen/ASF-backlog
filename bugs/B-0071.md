## Symptom

The suite profiled per module on the operator's machine, 2026-09-22 (835 tests, 318 s serial): `tests.test_cutover` 171.8 s for 26 tests — 54 % of the run; `test_harvest` 26.3 s (38); `test_workers` 20.0 s (58); `test_sample_product` 19.2 s (17); `test_tick_steps` 15.8 s (29); `test_doctor` 15.3 s (29); `test_tick` 13.2 s (33); everything else under 7 s each. The top five modules are 79 % of the time for 168 of the 835 tests; the other 667 tests cost about 20 % together. Sharded across processes (B-0068) the wall time is bounded by the slowest module, so `test_cutover` alone holds the gate at ~3 minutes.

## Cause

Each test builds a whole installation — a fake home, product yamls, a record, one or more git repos with history, clones — in `setUp`, then exercises one thing. Building the fixture is the cost; the assertions are cheap.

## Fix

Build each module's fixture once (`setUpClass` / a module-level template): the installation, the record and the repos as prepared bare templates. Each test clones or copies only what it mutates (a local `git clone` of a prepared bare repo, a `shutil.copytree` of a home) and asserts exactly what it asserted before — the same tests, the same assertions, no shared mutable state between tests. Where two tests genuinely need different installations, build both variants once. Targets: `test_cutover` under 30 s; the same pass over `test_harvest`, `test_sample_product`, `test_tick_steps`, `test_doctor`, `test_tick`, `test_workers` where a per-test `git init`/clone can become a per-class template.

## Tests

No new tests: every touched module keeps exactly the tests it had, passing. `tools/run_tests.py -v` prints the per-module time before and after.

## Acceptance

Full gate green on each push; the per-module before/after numbers in `## History`.
