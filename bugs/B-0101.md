## Description
## What is wrong
`asf file-bugs` mints signature Bugs (CI red, rule violated) whose body is only evidence lines. The
card has an empty `## Acceptance` (`- [ ] `), no statement of what is wrong in general terms and no
fix direction. Since B-0089 an S1/S2 filed this way is `decided: true` at once, so a FIX session can
be launched on a card that tells it nothing but a list of places — or the card sits New for days
because nothing can act on it.

## Evidence (reported by the first customer install)
- 17 filed per-rule Bugs in a product's record, all with an empty Acceptance line, all still
  `state: New` three days after filing with "no evidence found".
- None named what a fix would be checked against, so neither a session nor the groom moved them.

## Fix direction
- The filer writes a generated Acceptance from the source: for a rule violation, "`asf rules check`
  reports no violation of <rule> for N consecutive days" plus the rule's Statement; for a CI
  signature, "`<job>: <step>` unseen for the closing window".
- The body opens with one generated sentence of what is wrong (the rule statement or the failing
  step) before the evidence list.
- `asf check` refuses a decided Bug with an empty Acceptance line.

## Test
Run `asf file-bugs` on a fixture with one rule violation and one repeated CI failure: both new cards
carry a non-empty Acceptance and a first-line statement; `asf check` fails on a hand-made decided
Bug whose Acceptance is `- [ ] `.
