## Symptom

23:10 tick relaunched `fix-bug-b-0003` and `fix-bug-b-0008` (their first sessions had died at 17:27). Next tick: `keep fix-bug-b-0003 ended: pid still alive`, `keep fix-bug-b-0008 ended: session failed, not finished`, `waits fix-bug-b-0003 — spawn failed: worktree already exists`. B-0008's new run finished green and pushed `fix/B-0008`; harvest never offered it.

## Cause

`asf/workers/spawn.py:176-181` appends a fresh launch line `{job, item, pid, started, …}` to `sessions.jsonl`; `pool.load_sessions` folds lines per job with `dict.update`, so the terminal fields of the previous run — `ended`, `end_reason`, `rc`, `corrected`, `operator_flagged` — survive into the new run's record. Health skips any record with `ended` (`health.py:69`), the feeder counts no live session for the item and re-emits it, and `harvest.is_eligible` reads the stale `end_reason: failed`.

## Fix

A launch line is a new run: `spawn` writes `ended: None, end_reason: None, rc: None, corrected: None, operator_flagged: None, harvested: None, correction: None, rounds: None` alongside the new pid (folding with `update` then clears them). `load_sessions` drops keys whose folded value is `None` so callers see a clean record. Test: spawn twice for one job (fake runtime: first run `ok: False`, second `running`) → the folded record has no `ended`/`end_reason`; health with the pid alive keeps it live; after the second run's result, `is_eligible` is True.

## Not in scope

Reaping the old worktree (B-0025 — already in flight); the correction loop (B-0032).
