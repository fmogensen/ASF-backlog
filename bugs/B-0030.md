## Symptom (predicted, not yet seen)

A tick's record commit is dropped whenever the record's origin moved while the tick ran — e.g. a card filed by hand between the tick's `fetch + reset --hard` and its push. `asf.tick.shadow.push` treats a non-fast-forward refusal as "discarded, not an error"; the next tick resets hard to origin. Derived state is rebuilt, but the tick's **appended** lines — launch events, session lines, needs-operator events in `metrics/` — are lost for good. With harvest gates now making a tick run 15–20 minutes, the window is wide.

## Fix

`push`: on a non-fast-forward refusal, `git fetch origin && git rebase origin/<main>` once (the record's appended streams and derived files rebase cleanly by construction; on a conflict, abort and hold as today), then push again. One line `tick: pushed after rebase`. Test: origin moves between commit and push → both commits on origin, streams intact.
