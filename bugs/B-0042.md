## Symptom

23:29: `fix(B-0041)` on origin/main (689e91c), scheduler's checkout at 593c51f, two commits behind. The tick fired at 23:29 ran without it. Same at 22:37 (six behind) and 22:49. Every fix that reaches main without a lane landing in the same tick leaves the factory running old code until some later landing happens to trigger the sync.

## Cause

`asf/harvest/harvest.py:760-761 run_product_harvest()`: `sync_checkout()` runs only `if any(r == 'landed' …)`. B-0036 fixed the landing case; a commit that reached origin any other way (an operator's or agent's push, a merge-queue merge for a `pull-request` product) never syncs the checkout.

## Fix

`run_product_harvest` calls `sync_checkout(repo, trunk, out)` **whenever `origin/<trunk>` is ahead of the checkout's HEAD** — at the start (after the fetch, before gating, so the harvester itself is current) and again after landings as today. `sync_checkout` gains the ahead-check (`git rev-list --count HEAD..origin/<trunk>` > 0; 0 → silent, no line) and keeps its safety rules (on the trunk, clean tree, `--ff-only`, never reset/force). One line when it moves: `harvest: checkout fast-forwarded to <sha>` (existing line).

Footprint: `asf/harvest/harvest.py` (two call sites + the check), `tests/test_harvest.py` (`ProductHarvestTests.test_b0036_*` neighbours).

## Tests

- `ProductHarvestTests.test_b0042_checkout_behind_origin_is_synced_before_gating` — origin/main moved by a direct push, no eligible branch → checkout at origin/main after `run_product_harvest`, one line.
- `test_b0042_checkout_at_origin_prints_nothing` — no move → no sync line.
- Keep green: `test_b0036_landing_fast_forwards_the_checkout`, `test_b0036_dirty_or_off_trunk_checkout_is_left_alone`.

## Acceptance

Full gate green; a tick after a direct push to main prints `harvest: checkout fast-forwarded to <sha>` before any `landed`/`held` line.

## Not in scope

Reinstalling the venv (editable install needs none); products whose `repo_dir` is not the scheduler's code.
