## Symptom

A Feature whose plan the lane landed on the trunk sits at `plan-approved` for ever. The feeder's PLAN → CODE rows come from Task cards (`task_rows` over the Feature's Task children); the record holds none, so `asf next` shows nothing for the Feature and no coder ever launches. The plan template promises the opposite: "the record turns every `### Task N:` heading into a Task card and the feeder launches coders from them".

## Cause

Only `asf migrate` — the one-off against a legacy record — ever turned plan headings into Task cards (`plan_task_records`). The tick's record step (`run_step0`: backfill → ingest → file-bugs → rollup → index) has no such pass, and a session may not mint cards in the record (no grant, no push to the record's trunk).

## Fix

`asf.record.plan_tasks.mint_plan_tasks`, run in `run_step0` after the ingest: for every Feature whose plan is on the trunk (`plan_on_main`, matched by the lane's slug — B-0059) and that has no Task child yet, each `### Task N:` section of the plan becomes a Task card — `parent` the Feature, `writes` from its `writes:`/`Files:` line, `stories` from its `stories:` line (ids the record holds), `links.plan`, the section text as the description, `decided: true`. Ids from `mint_id`, never a session. A Feature with a Task child is left alone, so the pass is a no-op on re-run. Tests: `tests/test_plan_tasks.py` (two Tasks from a landed plan, once; a plan still on its branch mints nothing; a plan without headings is named, not minted).
