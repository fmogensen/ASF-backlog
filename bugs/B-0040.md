## Statement

Harvest should gate **once per tick**: rebase every eligible branch in turn onto the growing trunk candidate in the throwaway worktree, run the full gate once on the combined head, fast-forward main once; on a red gate, bisect by re-adding branches one at a time so one bad branch holds only itself. Replaces the interim cap of B-0031.

## Design (the note the card asked for)

- **Order**: the eligible branches in the order harvest already scanned them (branch name), each rebased in turn onto the growing head in one throwaway worktree off `origin/<trunk>`. A branch whose rebase conflicts is held with its `conflict` correction as today and never enters the set.
- **One gate, one push**: `product_gate` once on the combined head; `push_ff` of that head as the trunk's new tip; every branch in it is marked `harvested: <that sha>` (the same sha for all — the checkout sync of B-0036 runs once at the end as before) and deleted on origin. A trunk that moves between gate and push re-stacks and re-gates the same set once, as the single landing did.
- **Bisect cost**: red → split in half, re-stack each half from the trunk, gate each, recurse. A branch red on its own is held with its own failing line — so a held branch's `correction` (B-0032) always carries *its* failure, never one it was only red in combination with. N branches with one bad one cost about 2·log₂N + 2 gates instead of N.
- **Green apart, red together**: two halves that each pass alone are stacked once more and gated together (that is the head that gets pushed). If that is red, the first half lands and the rest are held for the next tick with **no** correction (`held <branch>: green alone, red with the others — next tick`) — there is nothing to hand the session.
- **Config**: `conventions.harvest.gate: combined` (default) or `per-branch` (the old path, kept and tested); `conventions.harvest.branches_per_tick` (default 12, was the module literal 3 of B-0031) is a safety valve on the tick's clock, no longer the cost driver.
- **Not changed**: the record repo's own harvest (`run_harvest`, `--repo`) keeps its per-branch gate; the tick's step order; `lane_refusal`, the adjudicate hold, the PR lane and B-0057/B-0061/B-0065's content checks all run per branch before the set is built.

## Fix

`asf/harvest/harvest.py`: `land_combined` (the set, the one gate, the push, the marks), `gate_groups` (gate or bisect), `combined_head` (reset to the trunk, rebase each branch on top with `rebase_and_resolve(onto=, tip=)`); `run_product_harvest` builds the set after the per-branch refusals and calls it, or `land_ff` per branch when `harvest.gate` is `per-branch`; `cap_to_tick` reads the conventions. `asf/conventions.py`: `harvest_gate`, `branches_per_tick`, the `harvest:` block. `docs/design/lane-state-machine.md`: one row.

Printed lines kept as they were; added `harvest: N branch(es), one gate` and, on red, `harvest: bisecting N branches`.
