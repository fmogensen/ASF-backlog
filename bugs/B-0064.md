## Symptom

B-0054's landed fix (04a96ab) makes harvest hold a branch carrying an `adjudicate(` commit, but the brief that produced those commits was unchanged: the `adjudicate` template still said "WRITE THE RULING AS A DECISION CARD BODY … Mint its id from `BACKLOG_ID_RANGE`" — a range that never carries `D:` — so the next adjudicate session would again write `docs/reviews/…-ruling.md`, invent `D-nnnn` and commit; harvest would hold it; the item would be flagged. The ruling never reached the record, and a session may not write the record (no grant, no push to its trunk).

## Cause

The ruling had no home a session could reach. The template asked for a Decision card body and an id; the only place a session can write is its worktree, so it wrote there.

## Fix

The ruling is the `ruling:` line of the session's REPORT (`asf.workers.report.ruling`), and the factory files it: `asf.tick.step_health.file_rulings`, run after health every tick, appends `- <stamp> adjudicate (<job>): <ruling>` to the item's `## History` in the tick's record clone (committed and pushed with the tick), marks the run `adjudicated`, writes a `ruling` event, and names a run whose report carries no ruling once. The `adjudicate` template says so: the ruling goes in the report, an upheld finding is an edit under the item's own subject, no ruling, review or decision file is ever committed, no decision id is ever written by a session. Tests: `tests/test_report.py::RulingTests`, `tests/test_tick_steps.py::HealthStepTests::test_b0064_*`, `tests/test_briefs.py::test_b0064_*`.
