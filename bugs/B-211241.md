## Description
The proof before the review (F-0358 §2.1) ships off (kernel.proof.enabled: false, PR #1717). Three defects must be closed before any product turns it on.

1. A whole existing module reads failed. asf/kernel/proof.py `reading` judges green-on-base as failed, a charged round. asf/kernel/needed.py `test_ids` returns every id in `## Acceptance`, including whole modules named as hygiene (tests.test_hermetic). Measured: 164 of 330 open cards with ids name a module the trunk already has. Each would get rounds the author cannot answer, then Stuck, and no review. Decide which ids a proof judges (only ids the PR adds or changes; a module id only when absent at the base) and what an unjudgeable id reads as.

2. The run is ungated. asf/kernel/trunk.py `probe` (the tests-at branch) runs `python -m unittest` on a worktree of the PR head: unreviewed code on the host with only the hermetic env. trunk-tests runs merged code, and the gate probe on a head is admitted by asf.readonly.grant. Give tests-at the same grant or a sandbox.

3. The gate leaks open. asf/kernel/proof_probe.py `read` skips an item whose state is not Review, but asf/kernel/decide.py `_judge_pr` launches the review on the tick the item enters Review. A PR whose CI is already green then is reviewed with no proof.

## Acceptance
- [ ] An id already defined at the merge base — a hygiene module such as tests.test_hermetic chief among them, named by a card that added no change to it — is dropped from the proof's tests and never read as failed for passing without the change; only an id the PR's own diff adds or changes, or a module id absent at the base, is judged — tests/kernel/test_review_proof.py::NeededIds::test_an_id_already_defined_at_the_base_is_dropped_never_judged
- [ ] The tests-at run of a PR's own (unreviewed) head is admitted by the same read-only grant asf.readonly.grant already gives the gate probe (or run in an equivalent sandbox), never bare on the host with only the hermetic env — tests/kernel/test_review_proof.py::ProbeReads::test_tests_at_runs_under_the_same_read_only_grant_as_the_gate_probe
- [ ] A PR whose CI is already green the tick its item first enters Review is still held for its proof — the review never launches on a head facts.proofs has not caught up to yet — tests/kernel/test_review_proof.py::DecideProof::test_an_item_entering_review_this_tick_is_still_gated_by_its_proof
- [ ] With kernel.proof.enabled on, a card naming tests.test_hermetic beside a new test module it adds reads proved once the new module is green on the head (the hygiene id is dropped, only the new id is judged and green) — tests/kernel/test_review_proof.py::DecideProof::test_a_card_naming_an_existing_hygiene_module_beside_a_new_test_module_reads_proved
