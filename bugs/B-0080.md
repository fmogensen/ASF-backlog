## Description

`after:` holds the PLAN → CODE row (`asf/feeder/rows.py`, `task_rows`) and nothing else. The
correction and adjudicate rows are produced by a different path — a held branch after three
rounds — and that path never asks whether the item's predecessor has landed.

Live at 2026-09-23 07:52: `after: [T-0025]` and `after: [T-0022]` were on the cards, the feeder
correctly refused to launch coders for T-0026 and T-0027 — and the same wave launched
`adjudicate-t-0026` and `adjudicate-t-0027` on **Opus**, to re-decide the exact question the
`after:` line answers. T-0026 had already been adjudicated once, at $6.49 across 7 sessions.

An item whose predecessor has not landed is not in dispute. It is waiting.

## Acceptance

- Every row kind — code, correct, adjudicate, review — is held when the item has an unlanded
  `after:` predecessor, not only PLAN → CODE.
- The held row prints `WAITS ON <id>` once, as the code row does, and does not count as a round.
- A property test: no row of any kind is launched for an item with an unlanded predecessor.
