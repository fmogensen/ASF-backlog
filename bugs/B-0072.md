## Symptom

The 19:17 tick's harvest stacked six branches on one head (B-0040) and ran the gate; one branch's new test commits with the repository's own hooks, and `.githooks/pre-commit` runs the whole suite, which runs that test, which commits — an unbounded recursion. The gate (`python3 tools/run_tests.py`) had been running 12 minutes when the operator's session found it, with no end: `harvest.product_gate` runs the test command through `subprocess.run` with no timeout. The tick never ends, launchd starts no second instance, and the next tick — the branch is still eligible — hangs the same way. The factory is stopped by one branch.

## Cause

`asf/harvest/harvest.py` `sh()` has no timeout; `product_gate` and `run_gate` use it for the test command and the checks. A hanging gate is a hanging tick.

## Fix

- `conventions.harvest.gate_timeout_s` (default 600, the tick's clock): the most one gate run may take.
- `harvest.product_gate` / `run_gate` run the test command and the checks in their own process group with that timeout; on expiry the whole group is killed and the gate is red with the line `gate timed out after N s: <command>` — so, with B-0040's bisect, the branch that hangs is held with that correction and everything else still lands.
- Tests: `tests/test_harvest.py` — a product whose test command sleeps past a one-second timeout is held with `gate timed out after 1 s` and its child is gone; `tests/test_conventions.py` — the field and its default.

## Acceptance

Full gate green; the next tick with the hanging branch in its set prints `harvest: bisecting N branches`, holds that one branch with the timeout line, and lands the rest.
