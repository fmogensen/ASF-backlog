## Symptom

`T-0017` and `T-0007` each have a branch on origin with **zero commits**. Their runs ended `finished`, so the lane counts them as work in progress for ever: five other tasks (T-0016, T-0018, T-0019 of F-0031, T-0015 of F-0085) print `WAITS ON T-0017` / `WAITS ON T-0007` every tick and can never start. F-0031 has been at 0/6 for three hours because of it.

## Cause

`lifecycle.judge` reads a session as `finished` when the runtime's result is ok and the branch is pushed (B-0051). "Pushed" does not ask whether anything is **on** the branch: pushing a branch that equals the trunk satisfies it. Harvest then finds nothing to land, the task stays `Active`, and the footprint gate keeps its siblings waiting behind a task that will never finish.

## Fix

- `lifecycle.judge`: a finished run whose branch has no commit ahead of the trunk is `failed` with `empty branch: nothing to land`, which D-0048's loop sends back to the same session with that reason (the worker either commits its work or says why there is none).
- `lifecycle.derive`: `WAITS ON <id>` is only honoured while that id's run is alive or its branch has commits; a waiting task whose blocker failed becomes free at the next tick.
- The tick's summary names it: `held <job>: empty branch` in the DONE table, so the operator sees the cause without reading a log.

## Tests

`test_a_finished_run_with_an_empty_branch_is_failed`; `test_a_waiter_is_freed_when_its_blocker_fails`; keep `test_finished_means_pushed` green.
