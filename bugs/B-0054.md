## Symptom

Six red CI runs in the last hour, all on held lane branches (`fix/B-0016`, `spec/F-0031`), all titled `adjudicate(…): ruling D-7851 / D-7852 / D-7853 / D-8200…D-8203 — no open finding`. The operator gets one failure mail per run. The commits invent Decision ids that exist in no record; the branches gain a ruling commit per tick and never land.

## Cause — three faults in one loop

1. **An adjudicate session commits to the code repo.** Its job is a ruling in the RECORD (a Decision card, or a `## History` line on the item). Instead it writes `docs/reviews/…-ruling-N.md` and a commit on the lane branch, and mints ids (`D-7851`, `D-8200`) from nothing — the record's ids are minted by `asf new`.
2. **The ruling does not end the row.** The item stays held, so the next tick emits another adjudicate row, which commits again: one ruling per tick, for ever.
3. **A push to a held branch fires the old workflow.** GitHub runs the workflow file *of the pushed branch*; branches cut before `fix(B-0053)` carry `on: push:` (all branches), so every one of those commits starts a run that fails — the mail the operator sees. A branch that never lands never gets the new trigger.

## Fix

- `adjudicate` brief and harvest: a session on an adjudicate row writes its ruling to the record (`asf new decision` or `## History` on the item) and **may not commit to the product repo**; harvest refuses a commit whose subject starts `adjudicate(` and holds with `ruling belongs in the record`.
- The ruling **closes the row**: `lifecycle` marks the run `adjudicated` with the decision id or the history sha; the feeder emits no further row for that item until the ruling is superseded (a typed `adjudicated_by:` on the item).
- No id is ever written by a session that did not mint it: the brief says ids come from `asf new`, and `check` refuses a body naming an id that is not in the index (`D-7851` today).
- Rounds: an item whose adjudicate row has run once is `NEEDS OPERATOR` only after the ruling fails to close it — never a second automatic ruling.
- A held branch whose workflow file differs from the trunk's is rebased by the correction session before it pushes (the closing paragraph already says rebase, never merge — B-0054); harvest names `stale workflow` as the hold reason when it sees one.

## Acceptance

No `adjudicate(` commit exists in the product repo; a held item produces at most one ruling; no CI run fires on a branch; the operator's mail stops.
