## Description

`asf/redact.py` (T-0022) turns the value of every environment variable whose *name* matches
`TOKEN|SECRET|KEY|PASSWORD|PASS|CREDENTIAL` into a search pattern, when the value is 12 characters
or longer. `GIT_CONFIG_KEY_0` matches on `KEY` and its value on this machine is
`init.defaultBranch` — so the scanner reports a secret on every line of the repo that mentions
`init.defaultBranch`: the CI workflow, `asf/hermetic.py`, a plan document. Seven findings, none of
them secrets.

The rule is right in shape and wrong in its edges. A secret is not a dotted configuration key and
not a filesystem path, and a name is not a secret merely because it ends in `KEY` —
`GIT_CONFIG_KEY_n` and `GIT_CONFIG_VALUE_n` are git's own config-injection mechanism, and
`*_PATH`, `*_FILE`, `*_DIR` name locations, not credentials.

A false positive here is not harmless: this scanner is a gate on every commit and every push
(F-0075), so a wrong finding blocks the factory, and blocking on ordinary words teaches everyone
to bypass the gate.

## Acceptance

- `GIT_CONFIG_KEY_*`, `GIT_CONFIG_VALUE_*`, `GIT_CONFIG_COUNT` and names ending `_PATH`, `_FILE`
  or `_DIR` are not read as secret names.
- A value that is a filesystem path, or a dotted identifier such as `init.defaultBranch`, is not
  turned into a pattern whatever its variable is called.
- A test sets `GIT_CONFIG_KEY_0=init.defaultBranch` and asserts the tracked tree scans clean, and
  another sets a real AWS-shaped value on `AWS_SECRET_ACCESS_KEY` and asserts it is still caught.
