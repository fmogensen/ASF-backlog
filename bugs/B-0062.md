## Symptom

Every tick prints `NEEDS OPERATOR: session adjudicate-b-0016 (B-0016) died twice — read its log …, then relaunch it or close its item` and writes a `needs-operator` event. The operator: "a manual question for me is a bug". Nothing in the lane moves the item afterwards: the run is `operator_flagged`, and the feeder never sees a correction for it.

## Cause

`asf.tick.step_health.handle_dead`: a dead session gets one cold retry; when that fails too, the step raises the operator and flags the run. Under D-0049 (the factory decides, the operator is informed) that is a dead end by design — the one hold in the lane that is not a correction.

## Fix

A twice-dead session is held like a red gate: `lifecycle.hold` writes a `died` correction on the run (the last log line as the text) and a round on the item, so the feeder's CORRECT row carries it and the ADJUDICATE row takes it at the cap; the event is `held`, the line is the hold line. A hold already pending on the run stands — the next tick does not add a round. Tests: `tests/test_tick_steps.py::test_b0062_already_corrected_is_held_not_a_question`, `test_b0062_failed_correction_holds_the_run`.
