## Description
Bug: a Task the kernel judges done keeps `state: New` on its card. Measured 2026-10-11: of the 0.3 Tasks, 19 carry `kernel_state: done` (18 of them have a commit on origin/main naming them), yet every one still reads `state: New`. Anything that reads `state:` (the backlog board, release readiness, the console's own count) reports 0.3 as ~1 of 57 done when it is 19.

## Acceptance
- [ ] A Task or Bug whose kernel_state already reads done keeps being re-examined by asf ingest on every later tick, not just the tick kernel_state first reached done, and closes (Closed/Resolved) the first time its evidence shows a landed, green trunk commit, with the trunk sha in History — tests/test_ingest.py::IngestRevisitsAlreadyKernelDoneItems
- [ ] A one-shot asf ingest --fresh run closes every existing card whose kernel_state is done and whose work is verified on origin/main (tested on a fixture, then run live against the real backlog) — tests/test_ingest.py::CmdIngestEndToEndTests
- [ ] asf backlog's Task/Story done counts and asf release-readiness's blocking-Features criterion keep reading the same state:/landed derivation asf ingest writes, with no separate count of their own — tests/test_backlog.py::BoardCountsMatchIngestState tests/test_release.py::BlockingLandedMatchesIngestState
