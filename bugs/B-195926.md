## Description
The merge-queue reaper cancels CI runs on any ref that starts with merge_queue.ref_prefix and is not a live batch. A product whose own tooling uses refs with the same prefix gets its CI cancelled ("mq-reaped ... no batch in flight"). There is no exclude or disable setting. Reported by the botseon console on 2026-10-12.

Acceptance:
- The reaper cancels only runs on refs the queue itself created (recorded in its ledger), never by prefix alone; or a product yaml key lists ref patterns it must skip.
- Test: a run on a foreign ref sharing the prefix is not cancelled.

## Acceptance
- [ ] A product lists glob ref patterns under `merge_queue.reap_skip`; `reap_leftover_runs` cancels no run whose ref matches one of them — live batch or not, guarded sha or not — the fix for a product whose own tooling's refs share `ref_prefix` with the queue's batches — tests/test_queue_reap.py::Reap::test_a_ref_matching_reap_skip_is_never_cancelled
- [ ] Unset (the default, empty), `reap_skip` changes nothing: every run the queue actually cut and lost track of is still reaped exactly as before — tests/test_queue_reap.py::Reap::test_a_dropped_batch_s_leftover_run_is_cancelled_and_claimed
