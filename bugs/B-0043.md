## Symptom

00:0x tick held every branch: `test_a_failing_step_never_stops_the_rest_and_exits_1` and `test_inbox_bug_with_no_default_configured_asks_a_question` red in the harvest gate, green in CI. The only change: the operator had just set `default_product: asf` in `~/.ASF/config.yaml`.

## Cause

`asf/env.py:18` resolves `ASF_HOME` from the environment or `~/.ASF` at import. The test suite never sets it, so any test that does not build its own home reads the operator's live config, products, state. CI is green only because the runner has no `~/.ASF`. The gate (B-0033) strips the caller's identity but rightly keeps `ASF_HOME` — the defect is the suite's.

## Fix

`tests/__init__.py` sets `ASF_HOME` to a fresh temporary directory before any test module imports `asf.env` (unittest imports the package first), unless `ASF_TESTS_HOME` names one. Subprocess tests inherit it. A test in `tests/test_env.py` asserts `env.ASF_HOME` is under the temp dir and that a `default_product` written to the real home path is not what `default_product_name()` returns. Footprint: `tests/__init__.py`, `tests/test_env.py`.
