## Description

`run_product_harvest` already says "content decides before the run's verdict does" (B-0061), but
only for a branch whose changes are already on the trunk. A branch with real commits *ahead* of
the trunk is still dropped when its run record is not `finished` — `is_eligible(record)` is the
last gate before the queue. A session that pushed its work and then ended `failed: empty branch`
or `failed: not pushed` (the ledger read the tree a moment too early, or the run was superseded)
leaves commits nobody will ever look at again: harvest skips them, the feeder does not relaunch
the item, and `harvest: none to land` prints every tick while work sits on origin.

Live now: `task/T-0026` (1 commit), `task/T-0027` (3), `task/T-0041` (2), each ahead of `main`,
each with a failed run record, none held, none corrected, none landed.

The rule the factory needs is one invariant: **every branch ahead of the trunk is owned by
exactly one of — a live run, a pending correction, or the harvest queue.** Anything else is an
orphan, and an orphan is a defect, not a resting state.

## Acceptance

- A branch ahead of the trunk whose run is not live and not handed to the PR lane is gated, whatever
  the run's own verdict was; the gate and the lane refusal decide, as they do for every other branch.
- The tick prints one line per adopted branch naming the run verdict it overrode.
- A property test: after a harvest pass, no `origin/<lane prefix>` branch is ahead of the trunk
  without being live, corrected, held or landed.
- `task/T-0026`, `task/T-0027` and `task/T-0041` land or hold — neither is silently skipped.
