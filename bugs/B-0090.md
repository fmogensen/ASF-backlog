The operator's working rules for the orchestrator console exist only as assistant memory notes and CLAUDE.md prose, so they are followed when remembered and broken when not. They were each broken on 2026-09-23. The operator said: "memory should be code". The ASF plugin is generated by asf/plugin_build.py and ships no hooks yet. It should enforce these rules as Claude Code hooks, so that every operator session gets them:

1. Build work goes to the factory, not the orchestrator. A PreToolUse hook on `Agent` denies a subagent that would edit, commit or push, and names `asf new bug --severity S1|S2` / `asf inbox` instead. Read-only types (e.g. Explore) pass. (Operator: "you seem to eat up this session which is the orchestrator".)
2. Fix the software, not the state. A PreToolUse hook on Edit/Write/Bash denies writes to `~/.ASF/state/**` (ledgers such as sessions.jsonl) and to the record's machine blocks, and names "fix it in the ASF code with a test". Operator config (`~/.ASF/*.yaml`) stays writable.
3. Act, don't ask. A Stop hook blocks a turn that ends by asking the operator to choose or approve ("Should I…?", "Want me to…?") and tells the session to decide and act. It is exempt when the next step is destructive and irreversible.
4. The operator never edits. The same Stop hook blocks handing the operator a command or edit to perform ("run `! …`", "add this to your yaml").
5. The console stays free. A long foreground chain (more than N tool calls in one turn without a background task or delegation) gets a PostToolUse reminder.

Each hook ships a test, and `tests/test_plugin.py` checks the hooks against what plugin_build generates. The hooks are generic: no operator or product names. Once they land, the matching memory notes and CLAUDE.md sections are deleted.
