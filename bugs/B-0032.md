## Symptom

Three shapes of the same gap, all seen 2026-09-21:

- `step_health.handle_dead` → `stall.correct_once` gives a dead or failed session **one** cold relaunch, blocking the tick for its length (`wait=True`, 76 s to 5+ min), and only when the next tick notices.
- `harvest` on a red gate **files or bumps a Bug** in the record and holds the branch; the branch's session is never told.
- A session ending with an error result is `failed` and its item is re-emitted as a new attempt next tick — a fresh session with no memory of the failure.

## Fix (D-0048)

- `asf.workers.correct(product, session, error_text, runtime, rounds=3)`: resume the **same** session (`--resume <session_id>`, read from the log's `system/init` line) with the failing output appended; non-blocking launch; the round count on the session record (`rounds: n`). Health judges the resumed run by its result (B-0028's reader). The third failed round → one `ADJUDICATE` row for the item, no Bug.
- `harvest`: a red gate is the correction's input — call `correct` with the gate's tail, hold the branch, no `file-bugs`. Next tick re-gates the resumed run's push.
- A `failed` result at health → `correct`, not `end`; `end_reason: failed` only when the rounds are spent.
- Runtime: `Job.resume_session_id`; `build_command` adds `--resume <id>`; the fake runtime replays it.
- Tests: three rounds then adjudicate; red gate → resume, not a Bug; the tick never blocks on a correction.
