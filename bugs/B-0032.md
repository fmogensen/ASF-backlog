## Symptom

Every held branch tonight — `held fix/B-0002: FAIL: test_…`, `held fix/B-0025: conflict in asf/workers/health.py` — either filed a Bug in the record (`bug filed: harvest gate red fix/B-0002`; B-0034/B-0035 were such cards) or sat held with no one told. The session that wrote the branch has the context to fix it and never hears.

## Cause

`asf/harvest/harvest.py land_ff()`: on a red gate it calls `file_gate_bug(...)` and returns `'held'`; on a conflict `rebase_and_resolve()` returns `(False, reason)` and `land_ff` returns `'held'` with one line. Nothing records the failure on the session, so `step_wave`/feeder cannot re-emit the item to its own session and D-0048's loop has no input.

## Fix

- `land_ff`: no `file_gate_bug` call (delete the helper and its test's expectation of a filed card). On a red gate or a conflict: `pool.update_session(product, job, correction={'kind': 'gate'|'conflict', 'text': <first failing line or conflicting files>, 'at': now_iso()}, rounds=<prev+1>)` and print `held <branch>: <reason> — back to its session (round n)`.
- `asf/feeder/rows.py`: a session record with a `correction` and `rounds < 3` yields a `FIX → CORRECT` row for the item (tier of the item's severity), whose brief kind is `correct` = the original brief + `CORRECTION: the step failed with:` + the text (reuse `stall.CORRECTION_HEAD`). `rounds >= 3` → the existing `ADJUDICATE` row. A landed branch clears `correction`.
- `asf/briefs`: kind `correct` template (one paragraph: rebase onto origin/<main>, fix, run the full suite, push the same branch).
- Footprint: `asf/harvest/harvest.py`, `asf/feeder/rows.py`, `asf/briefs/build.py` + one template, `asf/workers/pool.py` (no schema change: sessions.jsonl is free-form per line), tests: `tests/test_harvest.py` (`test_red_test_command_holds_and_files_a_bug` becomes `…_holds_and_records_a_correction`), `tests/test_feeder.py` (new row), `tests/test_briefs.py` (golden for `correct`).
- Not in scope: `--resume` of the same runtime session (part b, B-0039); changing `correct_once` in `stall.py`; any change to the tick step order.

## Tests

- `HarvestTests.test_red_gate_records_a_correction_and_files_no_bug` — red `test_command` → session has `correction.kind == 'gate'`, `rounds == 1`, no file appears under `bugs/`.
- `HarvestTests.test_conflict_records_a_correction` — conflicting rebase → `correction.kind == 'conflict'`, text names the file.
- `FeederRowTests.test_correction_row_for_a_held_branch` and `…_third_round_is_adjudicate`.
- Keep green: `test_green_branch_lands_on_main`, `test_b0036_*`, the wave/prs step tests.

Full gate green; a tick with a held branch prints `held fix/B-nnnn: … — back to its session (round 1)` and the next tick's wave prints `launched correct-b-nnnn`. `asf next` shows the `FIX → CORRECT` row.
