## Symptom

`step_health.handle_dead` → `stall.correct_once` runs the correction session with `wait=True`: the whole tick blocks for the length of a worker session (76 s to 5+ min seen; unbounded). Nothing else in the tick — wave, prs, harvest — runs meanwhile, and the scheduler's clock is outrun.

## Fix

A correction is a launch like any other: spawn it non-blocking with the corrected brief (`corrected: 1`, a new `pid`, `ended` cleared), and let the next tick's health judge its result (B-0028 gave health the re-judge). `correct_once` returns "launched", not pass/fail; the operator line comes only when the corrected run ends failed.
