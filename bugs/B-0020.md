## Description
The evidence provider hardcodes the first product's branch conventions (`cloud/`, `cloud/spec-`, `cloud/plan-`, `worktree-m-`) and matches work to cards by legacy ids and spec/plan paths only. On the `asf` product the first record tick derived `no evidence found` for all 285 items although B-0013/B-0014/B-0015 and F-0072 landed on main today with their ids in the commit subjects — and `asf next` proposed fix-bug sessions for four Bugs that are already fixed. Derived state that cannot see the repo is the failure the design exists to prevent.

## Fix
1. Branch conventions come from `conventions.branch_prefixes` (code/fix/spec/plan) in the product yaml; no literal prefix in `asf/evidence` or `asf/record/match`.
2. Id tokens are evidence: a branch name, PR title/body or a commit subject on `origin/<main>` containing `<TYPE>-<nnnn>` (or `(<id>)`, `[<id>]`) attaches to that card. A Bug/Task/Story with a commit on main naming it → `Resolved` (evidence `commit <sha> names <id>`); → `Closed` when the CI provider reports a green run on main at or after that commit (`ci.provider` gh-actions) or when the product has `ci: none`. A Feature with such commits → stage `landed`.
3. `stale` reads `stage_limits` from the product yaml, never `tools/limits.json`.
4. Tests: a bare product repo fixture with two commits naming ids, a branch `fix/B-0001`, a fake CI status → the states above; a product with other prefixes yields the same result.
