## Symptom

Every tick since 2026-09-21 17:37Z, on a product whose `steps.batch` is `off` (landing = fast-forward), the tick log ends its `prs` step with:

    prs: fix/B-0014 not opened — pull request create failed: GraphQL: No commits between main and fix/B-0014 (createPullRequest)
    prs: fix/B-0020 not opened — pull request create failed: GraphQL: No commits between main and fix/B-0020 (createPullRequest)
    [step:prs] FAILED 2 PR(s) not opened: fix/B-0014, fix/B-0020

The tick exits 1 every run; `metrics/ticks/2026-09-21.jsonl` shows `prs` `ok: false` on every tick from 17:37:59Z on. Both branches sit on origin with zero commits ahead of the trunk (`git rev-list --count origin/main..origin/fix/B-0014` → `0`); their sessions ended `finished` at 17:37:53Z and carry no `harvested` line.

## Cause

Verified 2026-09-21 against `origin/main` (7c12bea).

- `asf/tick/step_prs.py:88-99 candidates()` keeps every session with `ended`, `end_reason == 'finished'`, a branch under a PR prefix and present in `git ls-remote --heads origin`. It never reads three facts: the product's landing convention, the session's `harvested` mark, and whether the branch is ahead of the trunk.
- `asf/tick/step_prs.py:157-193 run()` hands each candidate to `gh pr create` (line 180); a refusal goes into `failed` (182) and is raised at 192 → `[step:prs] FAILED`. The step cannot tell "nothing to open" from "gh is broken".
- The landing convention already exists and is decided in one place: `asf/harvest/harvest.py:516-525 landing(product)` returns `fast-forward` when `steps.batch` is off or unset (or `conventions.landing` says so), else `pull-request`. `asf/tick/step_harvest.py:3-6` and `harvest.py:501-505` state that with fast-forward landing a pull request is never the mechanism. `step_prs` never calls `landing()`.
- Why the two branches are at the trunk and stay there: harvest skips a branch with zero commits ahead silently (`harvest.py:711-714`) — no mark, no delete — so it lives on origin forever and `candidates()` offers it again every tick.
- NOT the cause: `gh` auth or the PR host (the error text is the host's own "No commits between …"; the same `gh` opened PRs before); `has_open_pr` (77-85 answers correctly — there is no PR); pr hygiene (190, runs after the loop, unrelated).

## Fix

Two rules, both in `asf/tick/step_prs.py`; nothing else under `asf/` changes.

1. `run()`: before `repo_slug()` and before any `gh` call, read the landing through `harvest_mod.landing(product)` (`from asf.harvest import harvest as harvest_mod`; compare with `harvest_mod.LANDING_FF` — do not spell the literal in step_prs). When the landing is fast-forward: print exactly one line `prs: landing is fast-forward — harvest lands the branches`, make no `gh` call, run no hygiene, return 0. Same shape as the existing "no PR host" branch (166-170); the landing check comes first.
2. `candidates(product, out=None)`: (a) skip a session that carries `harvested`; (b) when the list is non-empty, run one `git fetch -q --prune origin` in `product.repo_dir` (this step runs before harvest's own fetch, so the remote-tracking refs may be stale), then drop every branch whose `git rev-list --count origin/<product.main>..origin/<branch>` is `0` or empty, printing through `out` (when given) one line per dropped branch: `prs: <branch> at trunk — nothing to open`. `run()` passes its `out`. A dropped branch is not a failure and never enters `failed`.

Module docstring (`step_prs.py:1-14`): one sentence per rule.

Must NOT change: `title_and_body`, `pr_create_argv`, `has_open_pr`, the `prs_per_tick` cap, the hygiene call for pull-request products, the `RuntimeError` on a real `gh` refusal (`test_gh_refusal_fails_the_step_after_hygiene` stays as written), and anything in `asf/harvest/harvest.py` (the silent skip at 711-714 is a separate card if wanted).

Config keys: none new. `conventions.landing` (`fast-forward` | `pull-request`; default derived from `steps.batch` per `harvest.py:516`) is the existing key the step now honours.

Footprint — every file the session touches:
- `asf/tick/step_prs.py`
- `tests/test_tick_steps.py` (class `PrsStepTests` only)

No fixture change: `sample/product.yaml` already has `steps.batch: off` and no PR host, so the sample tick prints the fast-forward line and exits 0.
