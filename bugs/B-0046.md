## Symptom

01:1x tick: `waits correct-b-0025 B-0025 — spawn failed: git worktree add -q -b fix/B-0025 … origin/main: fatal: a branch named 'fix/B-0025' already exists`. The first `FIX → CORRECT` row (B-0032) never launched; the held branch stays held.

## Cause

`asf/workers/spawn.py` creates every job's worktree with `git worktree add -b <branch> <path> origin/<main>` — a **new** branch from the trunk. A correction is the opposite case: the branch exists (locally, from the original session's worktree, and on origin) and the corrected run must continue **on it**, rebased onto the trunk, so the correction lands as the same branch.

## Fix

- `spawn`: when the row's kind is `correct` (or `row.branch` already exists on origin), add the worktree **on the existing branch** — `git fetch origin <branch>`, `git worktree add <path> <branch>` (create the local branch from `origin/<branch>` if only the remote exists; if a stale local worktree still holds it, remove that worktree first when its session has ended). Then `git rebase origin/<main>` in the new worktree, so the session starts from the conflict it has to resolve (the conflict is left in place; the brief says so).
- Job name `correct-<id>` keeps its own worktree path; the branch is the original `fix/<id>`.
- Footprint: `asf/workers/spawn.py`, `asf/briefs/templates/correct.md` (mention the rebase state), `tests/test_workers.py`.

## Tests

`TestSpawn.test_correction_reuses_the_existing_branch` — a pushed `fix/<id>` + a `correct` row → worktree on `fix/<id>`, HEAD has the original commit, no new branch; `test_correction_with_a_stale_worktree_of_an_ended_session`.

## Acceptance

The next tick prints `launched correct-b-nnnn` for a held branch; the corrected push lands under the same branch name.
