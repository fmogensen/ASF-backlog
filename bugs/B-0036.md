## Symptom

2026-09-21: the tick that ended about 20:05Z landed five branches on `origin/main` — `landed fix/B-0010 → 9136269…`, `fix/B-0011 → 868e1d5…`, `fix/B-0019 → b689632…`, `fix/B-0024 → b182620…`, `fix/B-0026 → 7c12bea…`. At 20:10Z the checkout the scheduler runs (`repo_dir`) was still at `1f620da`: on `main`, clean, 6 commits behind `origin/main`. Its reflog of `main` holds only hand commits and hand fast-forwards (`merge worker/…: Fast-forward`), never a harvest landing. Every tick since ran the code from before those fixes: B-0010's reap rule, B-0019's health rule and B-0024's model-label refusal were "landed" and none was in effect until a hand `git pull`.

## Cause

Verified 2026-09-21 against `origin/main` (7c12bea) and the live install.

- The scheduler entry runs `<venv python> -m asf.cli tick --product <p> --steps …` with `WorkingDirectory` = the product's `repo_dir`. The package is installed editable: under that interpreter `import asf; asf.__file__` resolves to `<repo_dir>/asf/__init__.py`. The code that runs is the checkout's working tree at whatever commit its `main` sits.
- `asf/harvest/harvest.py:645-687 land_ff()`: `git worktree add --detach <tmp> origin/<branch>` (652), rebase (656), gate (660), `push_ff(repo, sha, trunk)` (674 → 354-362: `git push origin <sha>:refs/heads/<trunk>` run from `repo_dir`), `mark_session` (680), `git push origin --delete <branch>` (681). The push updates origin and the remote-tracking ref `origin/<trunk>` inside `repo_dir`; nothing moves the checkout's own `<trunk>` branch or its working tree. `run_product_harvest()` (690-730) loops the branches and returns.
- The reset in `asf/tick/shadow.py ensure_clone()` is the record clone's, not the product checkout's; `asf/workers/health.py:120` fetches `origin/<main>` in `repo_dir` — a fetch, no merge.
- NOT the cause: a stale copy in the venv (the install is editable — verified); the scheduler's working directory (it is the checkout); the record clone. The fix is not a `git pull` in the tick's record step and not a reinstall of the package.
- Bridge (D-0046, D-0047): a hand `git pull --ff-only` in the checkout after each landing kept the factory current today; it retires with this card.

## Fix

`asf/harvest/harvest.py` — one new function, one call site.

`sync_checkout(repo, trunk, out) -> str` fast-forwards the product checkout onto the trunk harvest just pushed, only when that is safe:
1. `git symbolic-ref -q --short HEAD` in `repo` must equal `trunk`; otherwise `out(f'harvest: {repo} is on {head or "a detached HEAD"}, not {trunk} — not fast-forwarded')` and return `'skipped'`.
2. `git diff --quiet` and `git diff --cached --quiet` must both return 0 (tracked changes only; untracked files never block — git refuses by itself when one would be overwritten, which is case 3); otherwise `out(f'harvest: {repo} has local changes — not fast-forwarded')`, return `'skipped'`.
3. `git merge --ff-only origin/<trunk>`: rc 0 → `out(f'harvest: {repo} fast-forwarded to {sha}')` with `sha` = `git rev-parse HEAD` after the merge, return `'synced'`; rc ≠ 0 → `out(f'harvest: {repo} not fast-forwarded: {tail(stderr)}')`, return `'skipped'`.
Never `reset`, `checkout`, `stash`, `pull` or any `--force`. Use the module's `sh()` (it strips the git hook variables — `clean_env`, lines 60-74).

Call site: the end of `run_product_harvest()` (after the loop at 707-729, before `return results`), once per tick: `if not dry_run and 'landed' in results.values(): sync_checkout(repo, trunk, out)`. Not inside `land_ff()` (five landings → one sync), not in `run_harvest()` (the record-repo path — the record is not code the scheduler runs). `origin/<trunk>` is already current: `push_ff` pushed to it from `repo`, which updates the remote-tracking ref; a `git fetch -q origin <trunk>` before the merge is acceptable but not required.

Known and accepted: the steps after harvest in the same tick (`batch`, a subprocess; `daily`, imported lazily) may see the new tree; the next tick is a fresh interpreter.

Docstrings: the module docstring's cleanup paragraph (`harvest.py:33-34`) and `run_product_harvest()`'s docstring (691-694) each gain one sentence: after a landing, a product checkout that is on the trunk and clean is fast-forwarded.

Must NOT change: `land_ff()`'s order and lines (`landed <branch> → <sha>` is asserted verbatim), `push_ff`, `reap`, the gate, the record-repo path, `mark_session`. No new config key (a product that wants its checkout left alone keeps it on another branch — rule 1).

Footprint — every file the session touches:
- `asf/harvest/harvest.py`
- `tests/test_harvest.py` (class `ProductHarvestTests`: one existing assertion updated, three tests added)

No fixture change: `ProductHarvestTests.self.repo` is already a checkout on `main` with a clean tree (`test_harvest.py:407-421`); `sample/` is untouched (the sample tick lands nothing — its fake session commits nothing).
