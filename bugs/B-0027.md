## Description
Nothing lands a session's branch on a product without a merge queue. `asf harvest` enumerates LOCAL branches under the `code` prefix only, in the record repo by default, and looks a session up by the branch name with its prefix stripped — so for a product repo it finds nothing: sessions push `fix/<id>` (and `code` branches) to `origin`, and the registry keys them by job (`fix-bug-b-0024`). The manifest has no `harvest` step: with `batch: off` (a product whose landing is a fast-forward, not a train) two green lane fixes sat on their branches with no owner (2026-09-21 20:05: `fix/B-0024`, `fix/B-0026`).

## Fix
1. `harvest` works on the PRODUCT repo (`repo_dir`): `git fetch origin` then every `origin/<prefix>*` for every prefix in `branch_prefixes` (code, fix, spec, plan, imported); a session is found by its registry `branch` field, not by stripping the name; eligible = `ended` and `rc 0` (or `end_reason: finished`), not yet `harvested`, ≥ 1 commit ahead of `origin/<main>`, every commit subject naming the branch's item.
2. Landing is a convention: `landing: fast-forward` (default when `batch` is off) — rebase onto `origin/<main>` in a throwaway worktree, run the gate (the product's `test_command`, plus `check_generic`/`check_conventions` when the repo is ASF itself), push `HEAD:<main>`, mark the session `harvested`, delete the remote branch; `landing: pull-request` — open/refresh the PR and leave landing to the product's queue (the `prs` step already opens; harvest then only marks). A red gate holds the branch with one line and files/bumps a Bug with the failing test's name.
3. `harvest` is a manifest step owned by asf, after `prs`; `asf tick --manifest` shows it.
4. Tests: a bare product origin with a `fix/B-0001` branch and a registry line → landed, branch gone, session marked; a branch whose commits do not name the item → held; a red `test_command` → held + Bug; `landing: pull-request` → not pushed to main.
