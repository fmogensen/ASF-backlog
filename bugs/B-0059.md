## Symptom

The eight specs landed on `main` in one commit, `spec(F-0031, F-0075, F-0076, F-0078, F-0082, F-0085, F-0086, F-0087): …`. The next ingest set F-0031, F-0075, F-0085 and F-0087 to `state: Resolved`, `stage: landed` with the evidence `commit cc168ab names F-0031; CI green on main at or after it`. Four Features with a spec and nothing else read as delivered; the feeder emits no row for a Resolved item, so the lane would never plan or build them. Before that, a spec landed on `main` read as `spec-draft` and the feeder's answer to `spec-draft, no session` is another spec session — the same spec written again, for ever.

## Cause

Three readings of the lane's own conventions were missing from the evidence:

1. `evidence.id_evidence` takes any commit subject naming an id as the newest landing commit. A `spec(…)`, `plan(…)`, `review(…)` or `adjudicate(…)` commit names its item by the lane's subject convention, not because the item's work landed. D-0047: a commit naming an id is linkage, never proof.
2. `ingest.match_feature` matched a Feature to its documents only through a typed `links.spec`/`links.plan`, a `legacy_id`, `links.branches` or `links.prs`. The lane writes none of those: `spec/F-0085` lands `docs/specs/f-0085.md` — the slug is the id. The Feature never met its own spec, so the "commit names it" rule was all that was left.
3. The fast-forward lane has no reviewer row: harvest's gate is the review. A spec on `main` with no `APPROVED` review file stayed `spec-draft`, and the feeder re-specced it.

## Fix

- `evidence.DOC_LANE_SUBJECT`: a commit whose subject starts `spec(`, `plan(`, `review(` or `adjudicate(` is skipped by `id_evidence`.
- `ingest.match_feature` falls back to the card's own id, lower-cased, as the slug.
- A matched Feature: a spec on `main` is `spec-approved`, a plan on `main` is `plan-approved`; a matched Feature with no Task children and a code commit on `main` naming it is `landed` (as before for an unmatched one).

Tests: `tests/test_evidence.py::DocLaneCommitTests`, `tests/test_ingest.py` (`test_b0059_*`). Failing first: the spec commit was the landing commit, the id-slug match returned `None`, the spec on main read `spec-draft`.
