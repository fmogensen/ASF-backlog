## Description
`new` refuses to mint in a linked worktree unless `BACKLOG_ID_RANGE` names a block, which is right — parallel writers collide otherwise. But nothing allocates a block: there is no command that reserves one, records it, or releases it, so the only way through is the `BACKLOG_ALLOW_MINT` escape hatch, which is precisely the collision the refusal exists to prevent. This seed used the escape hatch.

## Fix
A command reserves an id block per job against the operator state, prints it for the launcher to export, and releases it when the job ends; the escape hatch is then only for a single-writer record.
