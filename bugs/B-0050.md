## Symptom

`/asf:groom` from a product repo's directory printed `groom 2026-09-22: applied 0, inbox 0 card(s) — … 0, 0, 0` while the record had six inbox cards and 80 open questions — and wrote `groom/2026-09-22.md` **into the product repo**. The same holds for `asf new`, `check`, `index`, `ingest`, `evidence`, `stale`, `file-bugs`: they take the cwd as the record.

## Cause

`asf/cli.py:167` — `root = os.getcwd()` for the record commands; `--product` is accepted by the parser but the record directory is not taken from `env.load_product(product).backlog_dir` (the views at `cli.py:225` do it right).

## Fix

One rule for every record command: the record is `load_product(--product | $ASF_PRODUCT | default_product).backlog_dir`; the cwd is used only when it **is** a record (an `index.json` beside `epics/`… and no product resolves) — printed as `record: <path>` on the first line so the operator always sees which one. A cwd that is a product repo is never a record. Footprint: `asf/cli.py` (one resolver used by all record commands), `tests/test_cli.py`.

## Tests

`test_record_commands_use_the_products_backlog_dir_from_any_cwd` (groom/new/check from a temp cwd act on the product's record; nothing written under the cwd); `test_cwd_that_is_a_record_still_works_without_a_product`.
