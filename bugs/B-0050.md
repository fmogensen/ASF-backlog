## Symptom

`/asf:groom` from a product repo's directory printed `groom 2026-09-22: applied 0, inbox 0 card(s) — … 0, 0, 0` while the record had six inbox cards and 80 open questions — and wrote `groom/2026-09-22.md` **into the product repo**. The same holds for `asf new`, `check`, `index`, `ingest`, `evidence`, `stale`, `file-bugs`: they take the cwd as the record.

## Cause

`asf/cli.py:167` — `root = os.getcwd()` for the record commands; `--product` is accepted by the parser but the record directory is not taken from `env.load_product(product).backlog_dir` (the views at `cli.py:225` do it right).

## Fix (widened after the read-only audit of every command, 2026-09-22 07:50)

One resolver in `asf/cli.py`, used by every record command: the record is `load_product(--product | $ASF_PRODUCT | default_product).backlog_dir`; the cwd is used only when it **is** a record (`index.json` beside the item folders) and no product resolves; the first output line is `record: <path>`. A cwd that is a product repo is never a record, and no record command writes anywhere before that check.

The audit found nine commands on the cwd root (`cli.py:167` → new, check, index, ingest, migrate, groom, stale, file-bugs, rules) — five of them **write** (new, index, ingest, migrate, groom, file-bugs) — and these companions the resolver alone would miss; all in scope:

1. `--product` is missing from six parsers (`cli.py:39-57` new/check/index/ingest, `:71-75` stale/file-bugs) — add it to all record commands.
2. `ingest` and `migrate` read evidence from the **default** product whatever record they write (`ingest.py:217`, `migrate.py:336`) — thread the resolved product into `evidence.load`.
3. `_git_sha()` (`cli.py:15-23`) stamps the shell's repo (`doctor@unknown` from /tmp) — `git -C <product repo_dir>` (or the record for record commands).
4. `steps.run_command` (`asf/tick/steps.py:113`) runs a product's command step in the tick's cwd — `cwd=product.repo_dir`.
5. `asf init` defaults `--repo` to the cwd silently (`init.py:235`) — print `repo: <path>` and refuse when the cwd is not a git work tree; `asf plugin build` prints `plugin: <dir>` (cwd by design, B-0047).
6. `asf scheduler status` defaults `--steps record` and reports the installed job as not loaded — default to the labels actually installed.
7. Module-mode defaults `metrics.py:956` (`--root=os.getcwd()`) and `rules.py:33-40` (`__file__`-relative) follow the same resolver; `rules.py:67` hint text names a tool that no longer exists.

Not in scope (by design, documented in the command's help): `hook` runs in the project cwd (a runtime hook); `tools/check_*.sh` use the cwd's `git rev-parse --show-toplevel` (gate scripts run under harvest with `cwd=`).

Footprint: `asf/cli.py`, `asf/record/ingest.py`, `asf/tick/migrate.py`, `asf/tick/steps.py`, `asf/init.py`, `asf/scheduler.py`, `asf/plugin_build.py`, `asf/metrics/metrics.py`, `asf/rules/rules.py`, `tests/test_cli.py` (new), `tests/test_tick_steps.py`.
