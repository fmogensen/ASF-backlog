## Symptom

Since B-0030 landed, a tick whose origin moved still ends `tick: state committed, push refused — re-derived next run` whenever the hand commit touched a card the tick also wrote (four of six ticks tonight: groom answers, `decided:` edits). The tick's appended events and the two `harvest gate red` cards it filed are lost each time.

## Cause

`asf/tick/shadow.py push()` rebases the tick's commit onto the moved origin; the rebase conflicts on machine-owned content — `index.json`, the `## Children` / `## Backlinks` sections and the `# ---- machine ----` block of a card that the hand commit also changed (a typed field above the block). Git sees one file changed on both sides; the conflict is textual, not semantic: typed fields belong to the hand side, machine fields and derived files to the tick side, always.

## Fix

In `push()`'s rebase, resolve conflicts by ownership instead of aborting: for `index.json` and every conflicted card, take the hand side's typed frontmatter and body, then re-run the derivation (`ingest` machine block + `index` for Children/Backlinks/index.json) in the clone and continue the rebase; abort only when a conflict falls outside those regions (a body both sides edited). One line either way: `tick: origin moved — re-derived onto origin/<branch> and pushed` or the existing refusal. Footprint: `asf/tick/shadow.py`, `asf/record/index.py` (a re-derive entry point if none is callable), `tests/test_tick.py`.
