`asf new` and `asf inbox` write the card into the operator's backlog checkout (the resolved record) and stop there: no commit, no push. The tick reads its own clone (~/.ASF/state/<product>/record), which pulls from origin, so a card filed from the console never reaches the factory until someone commits and pushes it by hand. Observed 2026-09-23: four inbox cards and B-0087..B-0090 sat uncommitted for about 30 minutes. `asf next` never showed them, and nothing said why.

Expected: a command that files an item into a record publishes it, as a commit of that item's files alone, pushed with a rebase on conflict. It prints the commit, or NEEDS OPERATOR if the push is refused. The operator's index.json is regenerated, not committed, since the tick owns the canonical one. A test files an item into a temp record with an origin and asserts that the origin has it.
