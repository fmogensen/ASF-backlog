## Symptom

A lane branch whose content is already on the trunk — the spec file landed by another commit, or a fix superseded by a later fix of the same Bug (fix/B-0025 with B-0025 Closed, fix/B-0043 with B-0043 Resolved) — is eligible for harvest every tick: `git rev-list --count origin/main..origin/<branch>` is not zero, the rebase replays commits that add a file the trunk already has, and the branch is held with `conflict in …` for ever. The worktree is never reaped, the correction rounds climb to the cap, the floor never gets clean.

## Cause

Harvest decides "something to land" by counting commits, not by comparing content, and never reads the item's state. A branch with nothing new is treated as work.

## Fix

Two rules in `asf.harvest.harvest.run_product_harvest`, checked before the gate:

- `nothing_to_land`: the branch's changes are already on the trunk — every file it touched (`origin/<main>...origin/<branch>`) is identical between `origin/<main>` and `origin/<branch>`; for a `spec/` or `plan/` branch the deliverable is its one document (`docs/specs/<id>.md`, `docs/plans/<id>.md` — the template says "create only that file"), so the branch is landed when that document is on the trunk, and the line names whatever else it carried. The run is marked `harvested: <trunk sha>` with the correction cleared, the remote branch is removed as after any landing, and the line reads `landed <branch>: already on <main> at <sha>`.
- `superseded`: the branch's item is Closed or Resolved in the record (the index the tick passes) and its changes are not on the trunk — the branch is archived under `archive/<branch>` on origin and removed from the lane, the run marked `harvested: superseded`, the line `superseded <branch>: <item> is <state> — archived as archive/<branch>`.

Health then reaps the worktree under the landed rule (B-0049). Tests in `tests/test_harvest.py`: a branch whose spec is on main is landed without a gate and its extras are named; a branch of a Closed item is archived, not held.
