## Description
The tick's first step ran inside the same checkout the operator and the harvest step use, and a blanket stage committed whatever happened to be in the tree — including content that was mid-harvest, with colliding ids, which only a later failing check caught. A tick must never commit from a tree it does not own.

## Fix
The tick runs its first step in its own clone: pull, write, commit, push. The shared checkout is for people and for harvest only.
