The groom digest (groom/2026-09-23-digest.md) and `asf status` report "55 for you" while the adjudicator has already ruled on many of the same items. F-0002, F-0022, F-0023 and others appear under "Ruled by the adjudicator" as `decided → true` and also under "For you" as `NEEDS OPERATOR: … — no Stories`. With approvals.groom: auto, the operator is told to act on questions that were already answered. Nothing tells them which of the 55 are real.

Expected: an item the adjudicator ruled on leaves the "for you" list and its count. "For you" holds only what the approval matrix reserves for the operator (human-now classes) or what the adjudicator explicitly escalated, each with a reason. A test covers a digest built from a groom file plus an answers file that overlap.

Related: the adjudicator removed 24 Features in one pass with the reason "no Stories". Removal is a scope change. It should appear in the digest as its own section with a one-line reason per item, so the operator can see what the factory dropped from the roadmap.
