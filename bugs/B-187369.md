## Description
`asf correct <item> --why` on an item that is Stuck after 3 fix rounds records the correction but never relaunches the item. On 2026-10-12, T-159854 got its correction at 08:05Z and was still Stuck at 08:15Z. An `asf answer` on the same item re-judged it within one tick ("escalated: one more fix round on the strong model").

Acceptance:
- A correction on a Stuck item re-judges it on the next tick, the same way an answer does.
- Test: a replay with a Stuck(3 rounds) item plus a correction produces a launch on the next tick.

## Acceptance
- [ ] `asf correct <item> --why` appends the same operator-answers.jsonl record `asf answer` writes, so the text is recorded as an operator answer, not only as a correction on the legacy session ledger — tests/test_correct.py::CorrectTests::test_a_correction_writes_the_operator_answers_ledger_the_kernel_reads
- [ ] A replay with an item Stuck at the fix-round cap (owner operator, reason ending "after N fix rounds") plus a correction via `asf correct` launches a build session on the next tick, the same as `asf answer` does — tests/kernel/test_answers.py::CappedAnswer::test_a_correction_on_a_capped_stuck_item_launches_next_tick
