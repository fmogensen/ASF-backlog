## Symptom

The tick of 20:38 ran 20+ minutes: `harvest` rebased four lane branches and ran the product's full `test_command` (~4.5 min) once per branch, in sequence, inside the tick. The scheduler's 10-minute clock was outrun; wave, health and the record waited behind the gate. With ten branches the tick would run an hour.

## Fix

Gate once per tick: rebase every eligible branch in turn onto the growing trunk candidate in the throwaway worktree, run the gate **once** on the combined head, push the fast-forward; on a red gate, bisect by re-adding branches one at a time (or fall back to per-branch) so one bad branch holds only itself. Cap `harvest.branches_per_tick` (product yaml, default 8). Print `harvest: N branch(es), one gate, <duration>`.
