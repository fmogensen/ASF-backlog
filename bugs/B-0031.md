## Symptom

The 22:21 tick ran 23 minutes: eight lane branches, each rebased and gated with the full suite (~4.5 min). While it ran, main moved every 4–5 minutes and a fixer needed six fast-forward attempts to land (each attempt re-gated). The scheduler's clock is 10 minutes.

## Cause

`asf/harvest/harvest.py run_product_harvest()` iterates every eligible session and calls `land_ff` for each with no cap; nothing in the product yaml limits it.

## Fix (interim — the one-gate design is B-0040)

- Conventions: `harvest.branches_per_tick` in the product yaml, default **3**, read through `asf.conventions.Conventions` (add the field with its default there; no literal elsewhere).
- `run_product_harvest`: after `branches_per_tick` landings-or-holds, stop and print `harvest: cap N reached — M more next tick`. Order stays as today (session start time).
- Footprint: `asf/conventions.py` (one field), `asf/harvest/harvest.py` (the loop), `asf/init.py` if it writes the conventions block (add the key with its default so `asf init` lays it down), `tests/test_harvest.py`, `tests/test_conventions.py` (the defaults table if one is asserted).
- Not in scope: gating several branches in one run; changing the tick's step order; the scheduler interval.

## Tests

- `ProductHarvestTests.test_branches_per_tick_cap_stops_and_reports` — 4 eligible branches, cap 3 → three `landed`, one `harvest: cap 3 reached — 1 more next tick`, the fourth lands on the next call.
- `ConventionsTests`: the field and its default; a product yaml overriding it.
- Keep green: `test_b0036_landing_fast_forwards_the_checkout` (the checkout sync still runs once at the end).

## Acceptance

Full gate green; the next tick with >3 eligible branches prints the cap line and ends within the clock.
