## Symptom

The 20:38 tick held all four lane branches on a red gate — three on `test_groom … test_inbox_bug_with_no_default_configured_asks_a_question`, one on `test_sample_product … test_next_shows_the_bug_in_flight_and_a_feature_waiting`. The same branches, rebased onto the same main, are green in a shell.

## Cause

`asf.tick.tick` sets `os.environ['ASF_PRODUCT'] = product.name` for its own steps. `harvest.gate_env()` strips only `BACKLOG_ID_RANGE` and the git-hook variables, so the product's `test_command` inherits the tick's `ASF_PRODUCT=asf`. ASF's own tests that model "no product / no default configured" then read the live product and fail. Reproduced: `ASF_PRODUCT=asf python3 -m unittest tests.test_groom…` → FAIL; without it → OK.

## Fix

`gate_env()` strips every variable that names the caller's own identity — `ASF_PRODUCT`, `ASF_JOB`, `BACKLOG_ID_RANGE` — so the gate sees the product's environment, not the tick's. Test: `gate_env` with those set returns none of them. (D-0047: the gate is a named test's result; it must be the branch's result, not the tick's.)
