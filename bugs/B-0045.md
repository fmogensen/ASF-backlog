## Symptom

00:5x: after `fix(B-0003)` landed (the product file is validated against a declared field list), every `asf` command for the product died with a traceback — `ConfigError: products/asf.yaml: line 18: 'backlog_slug' is not a field of the product file` — and the next scheduled tick would have died the same way, silently in its log, stopping the lane.

## Cause

`asf/cli.py main()` calls `env.load_product()` before dispatch with no handling for `ConfigError`; `asf/tick/tick.py` the same. A refusal that is meant for the operator surfaces as a Python traceback, and in the scheduler as a dead tick.

## Fix

- `cli.py main()`: catch `env.ConfigError` → print `NEEDS OPERATOR: <message> — edit the file or run asf init --product <p>` and exit 2 (never a traceback).
- `tick`: the same line to its log and the tick event stream (`kind: needs-operator`), exit 2, so the operator sees it in `asf status` and the record, not only in a log.
- `asf doctor`: the `config` row already goes RED with the message — keep.
- Footprint: `asf/cli.py`, `asf/tick/tick.py`, `tests/test_cli.py` or `tests/test_tick.py`.

## Tests

`test_refused_product_file_is_one_operator_line_exit_2` (CLI) and `test_tick_with_a_refused_product_file_records_needs_operator` (tick).
