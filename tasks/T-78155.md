stories: S-76256

after: none

The spec's §3. A footprint no other Task touches, so this runs in wave 1 beside Tasks 1 and 3.
`dispatch.install` is not re-specified and not edited — `reassert` is a narrow entry point in
front of it (C8), and the one caller it already has (`asf/hooks.py:669`) keeps working unchanged.

**Files**

- `asf/dispatch.py` — a new `reassert(path=None)` after `install` (`:197-253`), with §3's
  docstring. No change to `install`, `render`, `is_ours`, `default_cli` or `MARKER`.
- `asf/tick/tick.py` — `cmd_tick` (`:418`), four lines inside the existing preflight.
- `tests/test_dispatch.py` — the nine arms of PD9.
- `tests/test_tick.py` — `cmd_tick`'s call, its three printing arms, and the three early returns.

**Steps**

1. `reassert(path=None)` returning `(changed, detail)`, built as PD9 decides — bytes compared
   across `install`, never its detail string:
   - `path = path or default_path()`;
   - `if not os.path.lexists(path): return False, None` — a host with no factory CLI is not this
     function's business, and this early return is also what keeps `install` from *creating* a
     dispatcher where there was none;
   - `if os.path.islink(path) and is_ours(os.path.realpath(path)): return False, None` — P14, the
     agent home's link to the operator's path; without this arm a bare `install` would move that
     link aside and write a second dispatcher inside the agent home (measured on `install`:
     `is_ours(target)` being True makes the link's own target ineligible as the fallback CLI, and
     the path is overwritten);
   - read the bytes, call `install(path)`, and on `rc != 0` return `(False, detail)` — the
     `NEEDS OPERATOR` line for a foreign file, which `install` never touches;
   - otherwise re-read and return `(after != before, detail if after != before else None)`;
   - wrap the whole body from the first read onward in `except OSError as e` returning
     `(False, f'NEEDS OPERATOR: the dispatcher at {path} could not be written ({e})')`. Never
     raises, and never silent about a write it could not do.
2. §3's docstring verbatim, keeping its four `(False, None)` cases and its `(False, detail)` case.
3. `cmd_tick`: between the `off = upgrade.checkout_off_main()` print and `if
   upgrade.waiting(product.name)` (i.e. at `asf/tick/tick.py:452`, **before** `waiting` and
   `draining`), add a local `from asf import dispatch` — `tick.py` does not import it at module
   level (PD6) — and §3's four lines:

   ```python
       changed, detail = dispatch.reassert()
       if detail:
           print(f'tick: dispatcher — {detail}', file=sys.stderr if not changed else sys.stdout)
   ```

   Before `waiting`, not after: a tick that returns early for a pending upgrade is still a pass,
   and the window this Feature narrows is measured in passes. `sys` is already imported.
4. `tests/test_dispatch.py`: the nine arms PD9 measured, over a fixture with a real
   `install.json` naming a fake pinned venv (the shape `tests/test_dispatch.py:70` and `:166`
   already build) — a `default_cli` that cannot be resolved turns *every* arm into the same
   `NEEDS OPERATOR: no asf to fall back to …` line and proves nothing, which is how the first
   probe of this Task went wrong. Always pass an explicit `path`: `reassert()` with no argument
   reads the real `~/.local/bin/asf`.
5. The "never raises" arm is proven by patching, not by `chmod` — **PD3**:
   `mock.patch.object(dispatch, 'install', side_effect=OSError('read-only file system'))`, then
   assert `reassert(path)` returns `(False, <a NEEDS OPERATOR line>)`. A `chmod 0o500` fixture
   passes for the wrong reason as uid 0, which is how every cloud session and every coder session
   runs. The missing-`config.yaml` half needs no patch: call `reassert` with no `default_product`
   and let `install`'s own `except (env.ConfigError, OSError, ValueError)` answer.
6. Pin the dangling-sym
