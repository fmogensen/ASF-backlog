## Description
stories: S-18608

after: Task 3

§2.6's views and §2.5's overlap measurement. The roster is one row per role; `--check` is the
gate that makes an invalid role dir red rather than fatal (D12); `--overlap` is the measurement
that is the *input* to the later card that cuts the templates, and deletes nothing itself (PD14).
Runs beside Task 4: its writes intersect no other Task's (PD15).

**Files**

- `asf/views/roles.py` — **new**: `render(cfg=None)` → the `ROLES` table of §4 (role, kinds or
  `unbound: <reason>`, the label config resolves, sha, lines); `check()` → `(rc, lines)` with one
  `<file>: <problem>` per breach over `roles.roles_dir()`; `overlap()` → one block per kind naming
  the template lines the role block now duplicates; `cmd_roles(args)`.
- `asf/cli.py` — `p_roles = sub.add_parser('roles', …)` with `--check` and `--overlap` and no
  `--product` (PD11), and a dispatch branch above the record-view block (`:329`).
- `asf/doctor.py` — `check_roles(cfg)` → `(ok, detail)`: `roles  <n> valid, <k> kinds bound`, red
  with the first problem's text when any role is invalid, when a kind has no binding, or when
  `roles:` names a role with no file (D12); one `rows.append(('roles', True, ok, detail))` in
  `run` (`:455-479`), after `drift` and before `capacity`.
- `tests/test_cli.py` — `RolesViewTests` (new, §3/T9's first two sentences).
- `tests/test_doctor.py` — `RolesRowTests` (new, §3/T9's last sentence).

**Steps**

1. `render`: `roles.load_all()` for the roster, `BINDINGS`/`UNBOUND` for the kinds column,
   `build.model_for(None, kind, cfg)` on one of the role's bound kinds for the label column and
   `roles.<name>.model`/`roles.defaults.model` for an unbound role's, `Role.sha` and `Role.lines`
   for the last two. The kinds column is the role's bound kinds in `BINDINGS` order, or
   `unbound: <reason>` truncated to the column width as §4's printed sample shows.
2. `check`: `validate` over every file in `roles.roles_dir()`, exit 1 on any problem, one
   `<file>: <problem>` line each, exit 0 and no output on a clean dir.
3. `overlap`: per kind, the template's lines that also appear in that kind's role block, printed
   once as a count and the lines themselves. No template file is written — that is what makes
   this a measurement and not a cut (In/out, PD14).
4. `asf/cli.py` per PD11 — dispatched on its own, never through `resolve_record`, so
   `asf roles` answers before `asf init` has run.
5. `asf/doctor.py`: `check_roles` reads `roles.load_all()`, `validate`, `BINDINGS` against
   `build.KINDS`, and `cfg['roles']`'s keys against the files. A `RoleError` is a red row with
   its text, never a raise — doctor prints a table, it does not die.
6. `RolesViewTests` and `RolesRowTests` per §3/T9: the roster prints one row per role with its
   bound kinds, its configured label, its sha and its line count, and the three unbound ones carry
   their reason; `--check` exits 0 on the shipped dir and 1 with `<file>: <problem>` on a
   temporary dir holding one broken file; `asf doctor` shows the `roles` row, green on the shipped
   set and red with the first problem when `$ASF_ROLES_DIR` points at the broken one (PD10).
