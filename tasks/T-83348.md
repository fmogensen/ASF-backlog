One cell. A row that spawns nothing leaves no session to count (P15), so the `rule_pass` event is
the only record that the saving happened, and this cell is the only place the card's own claim
about the mix becomes a reading rather than an estimate (P18).

**Files**

- `asf/views/status.py` — `rule_pass_cell(root, product)`, and one entry in `render`'s cell list
  (`:759-790`), directly after `('Decisions', …)` (**PD16**).
- `tests/test_views.py` — one class, `RulePassCellTests(ViewsTestCase)`, the four S-78057 lines.
  `DecisionsCellTests` (`:375-416`) is the shape for all of them, and its
  `test_the_row_sits_directly_after_ready_to_launch` (`:413`) is the shape for the placement
  assertion.

**Steps**

1. `rule_pass_cell(root, product)`:

   ```python
   def rule_pass_cell(root, product):
       """``Rule pass``: what the rule pass ruled over the last 7 days and the adjudicate
       sessions it did not spawn (:mod:`asf.evidence.rulepass`) — ``None`` with the flag off or
       nothing ruled, because a product that has not adopted it grows no row."""
   ```

   `None` first thing when `not root` or `not rulepass.enabled(product)`. Then
   `metrics.read_stream(root, 'events', metrics.days_back(today, 7))`, **one day at a time inside
   a `try`**, so an unreadable or malformed day is skipped and never raised (**PD16**) — the day
   list is `metrics.days_back(datetime.date.today().isoformat(), 7)`. Keep the lines whose
   `kind == rulepass.EVENT`; `None` when none is left.

2. The text, exactly the spec's line:

   ```
   11 ruled in 7d — cosmetic 8 (commit-shape 5, wording 3), precedent 3; 11 adjudicate sessions
   not spawned
   ```

   The `rule` field of an event is the comma-joined rule names of that one ruling, so the split by
   rule is a tally over those names and the cosmetic sub-split is a tally over the classes the
   `why`/`rule` fields name; "N adjudicate sessions not spawned" is the event count, because one
   event is one row that took no session. A rule with no ruling in the window is left out of the
   parenthesis rather than printed as `0` — the module's own rule.

3. One entry in `render`'s list, directly after `('Decisions', …)`:

   ```python
                          ('Rule pass', lambda: rule_pass_cell(root, product)),
   ```

   `render` already wraps every cell in `try/except` and drops a `None` (`:791-797`), so a cell
   that cannot read loses the row, never the table.

4. The tests. Four cases: three events in the window → the count, both splits, the sessions not
   spawned; the flag off, and the flag on with no event → `None`; an event dated outside the
   window not counted and a day file whose first line is `{` skipped without raising; and the
   spec's own worked example — five `commit-shape`, three `wording`, three `precedent` →
   `cosmetic 8 (commit-shape 5, wording 3), precedent 3` and `11 adjudicate sessions not
   spawned`. Plus the placement assertion, in `DecisionsCellTests`' own shape.
