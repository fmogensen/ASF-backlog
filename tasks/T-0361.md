## Description
stories: S-32253

after: Task 1, Task 2, F-0060

§2.5: two context fields, one template section, and the table rendered with the security rows. The
template is created by F-0060's Task 4 and does not exist here yet (PD5), so this Task waits and is
written as an edit. The role and `MODEL_TABLE['precheck']` are unchanged (§1.2): the floor to
`high` moving a small sensitive diff from `CHEAP` to `LIGHT` is the whole cost of this part.

**Files**

- `asf/briefs/build.py` — `security_classes` and `security_files` in `context()`, `precheck_table`
  rendered with `security=row.precheck_dims`, the `{security_section}` value
- `asf/briefs/templates/precheck.md` — one `{security_section}` block
- `tests/test_briefs_security.py` — `SecuritySectionTests`

**Steps**

1. `context()` (`asf/briefs/build.py:361`) gains `security_classes` — the class names of the row's
   `precheck_dims`/`security` fact as `auth, billing` — and `security_files` — the classes with
   their files, capped, from `security_paths.describe`. Both are the empty string for a row with no
   sensitive class, so a non-sensitive brief's context is unchanged.
2. `precheck_table` is rendered `precheck_mod.render_table(level, security=row.precheck_dims)`, so
   the skeleton the reader fills carries one row per class beside the level's.
3. `security_section`: §2.5's markdown block verbatim, formatted with the two fields — and the
   empty string when there is no class, so the golden F-0060 ships does not move. The shape is
   `customer_section`'s (`:448-455`): one function, one string, no branch in the template.
4. `asf/briefs/templates/precheck.md` gains one `{security_section}` placeholder, on its own line,
   after the level's opening and before the table — an edit of F-0060's file, not a rewrite of it.
5. `tests/test_briefs_security.py` per §3's T4, its own file so it does not queue behind F-0060's
   `tests/test_briefs.py` (PD14): a `precheck` brief for a branch touching two classes carries the
   `## This diff touches sensitive paths:` section naming both, the files under each, and a table
   skeleton whose rows are the level's plus one per class; the section is asserted **as one whole
   string**, not by substring. A brief for a branch touching none carries no section and is
   byte-identical to the golden, so `tests.test_briefs.GoldenBriefTest` passes untouched — the
   second half of T4's fence, run and not merely assumed.
6. No new template, no new golden, no `MODEL_TABLE` change, no role change (§1.2, §4).
