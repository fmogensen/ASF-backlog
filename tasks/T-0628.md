## Description
stories: S-36950, S-36951
writes: asf/clockinstall.py, tests/test_clock_install.py
after: none

`asf/clockinstall.py` whole and `tests/test_clock_install.py`'s first two classes — the spec's
`## The design` §§1 and 2 in full. Nothing outside these two new files moves, and nothing in the
factory behaves differently when this lands: the module has no caller yet. That is exactly why it
can go first and be proven alone, and why it must — C1's argument is that the plist is the *one*
authority on which install ticks, and an authority two parallel Tasks each re-derive is the defect
this card exists for.

Read **PD4** (`trunk()` cannot call `drift.trunk_head` for the package's own tree), **PD5**
(`venv_commit` must return three values or the editable row has no sha and no checkout), **PD6**
(`snapshot.current()` answers `None`), **PD7** (the `checkout` kind's plist is written by hand) and
**PD8** (no test in this module may read the operator's `~/Library/LaunchAgents`) before starting.

**Files**

- `asf/clockinstall.py` — **new module**: the docstring, `DIST`, `KINDS`, the `ClockInstall`
  dataclass, `read`, `classify`, `venv_commit`, `venvs_dir`, `for_product`, `trunk`,
  `against_trunk`, and the private `_head`
- `tests/test_clock_install.py` — **new module**: `ClockInstallReadTests`, `TrunkDistanceTests`

**Steps**

1. `asf/clockinstall.py` opens with the spec's §1 module docstring byte for byte — `asf upgrade`
   reinstalls a pipx venv, a clock runs whatever its plist's `ProgramArguments` name, and on a
   machine holding a pinned live install beside an editable dev one those are not the same install
   (F-0111 P3). It names the two readers it feeds and says neither guesses. No product name, no
   account, no host path: a lane is `lane-N` and a venv is `asf-factory` or `asf-factory-live`
   (PD16/P15).
2. The vocabulary from the spec's §1: `DIST = cli.DIST_NAME` with its `#:` comment (*"a suffixed
   install is this plus its `--suffix`"*), `KINDS = ('pinned', 'editable', 'snapshot', 'checkout',
   'unknown')`, and the `ClockInstall` dataclass with its nine fields and their comments —
   `label`, `kind`, `venv`, `suffix`, `interpreter`, `repo`, `sha`, `why`. Import `cli` for
   `DIST_NAME` rather than re-spelling `'asf-factory'`: that string is already spelled in three
   places and a fourth is the bug class this factory's own checks exist for. `from asf import cli`
   is safe at module level — measured, `asf/cli.py` pulls nothing of `asf` but `__version__`
   (PD16).
3. `read(path)` → `(argv, env_vars)` through `plistlib.load`, and `([], {})` for a missing,
   unreadable or non-dict plist. One `try`, catching `OSError` and `plistlib`'s own error, with the
   reason in the docstring: the `SCHEDULER` section already reports a plist launchd cannot hold, so
   an unreadable plist is a missing one *here* — `doctor._job_plist`'s own rule
   (`asf/doctor.py:693`).
4. `venv_commit(venv_dir)` → **`(sha, editable, repo)`** (**PD5**), off the one
   `*.dist-info/direct_url.json` for `DIST` under that venv's `site-packages`, found by glob over
   `<venv_dir>/lib/python*/site-packages/` and matching the distribution's normalised name
   (`asf_factory-*.dist-info`). A pinned install is `(vcs_info.commit_id, False, '')`; an editable
   one is `(<HEAD of the tree at dir_info's url>, True, <that tree>)`, the path taken off the
   `file://` URL and the sha through `snapshot.head_sha`, which raises `SnapshotError` rather than
   answering junk. `('', False, '')` for a missing file, a missing dist, unparseable JSON or a tree
   that is gone. **No subprocess for the pinned case** (C14) — read off disk; the docstring says
   that the editable case is the one exception, at most one `git` call per editable venv, and why
   (PD5). Its sibling is named: `new_install_commit` spawns the venv's own interpreter because it
   must read what an *import* resolves immediately after `pipx install --force` (P2), and this one
   must read venvs whose python it will
