## Description
stories: S-7207

**Files**

- `docs/products.example.yaml`, `docs/config.example.yaml`, `sample/product.yaml`,
  `tests/test_sample_product.py`.

**Steps**

1. `docs/products.example.yaml`: add the spec's four-clock block (`record` every 5m,
   `dispatch` every 10m, `daily` at `"06:50"`, `shadow` every 30m). Add a comment saying each
   entry is one job labelled `<prefix>.<product>.<name>`, plus the rules in two lines: `steps`
   or `shadow: true`, and exactly one of `every: <n><s|m|h|d>` (at least 60s) or `at: "HH:MM"`
   (local time).
2. `sample/product.yaml`: the same block. Its `steps:` already declares `batch: off` and
   `daily: off`, and `off` counts as owned, so the four clocks validate.
3. `docs/config.example.yaml`: the `scheduler:` comment says the clocks live in the product
   file (`products/<name>.yaml`, `clocks:`). It still doesn't mention `interval_s`.
4. `tests/test_sample_product.py`: add `test_sample_declares_clocks`.
   `tests/test_env.py`'s `products.example.yaml` checks must stay green; `clocks` is a product
   field after Task 1.
