## Description
stories: S-14151
writes: asf/tick/step_wave.py, tests/test_tick_steps.py

Runs after Task 1: it imports `asf.briefs.facts` and `preamble.unknown_count`, neither of which
exists until Task 1 lands.

**Files**

- `asf/tick/step_wave.py` (192 lines) — `repo_facts(product, branch)`
  (`asf/tick/step_wave.py:113-122`) becomes a delegate; `run` passes the row
  (`asf/tick/step_wave.py:175`); the `launch` event gains two fields; the module docstring's step 4
  stops promising "two `git` calls at most".
- `tests/test_tick_steps.py` (863 lines) — `WaveStepTests`: one assertion set rewritten
  (`tests/test_tick_steps.py:318-320`), one test rewritten (`tests/test_tick_steps.py:338-341`),
  one test added.

`tests/test_brief_facts.py` is Task 1's file. This Task runs `HeadTests` as a gate and does not
edit it (P6).

**Steps**

1. **Replace `repo_facts`.** The four keys it returns today — `{branch, pushed, remote_sha,
   last_commit}` — are read by nothing that `collect` reads, which is the defect. It becomes
   `return facts.repo_facts(product, row, items, running)`: the **row**, not the branch, because
   the gatherer needs the item id and the brief kind. Keep the name and the module-level `_git`
   helper only if something else still calls them; delete what is now dead.
2. **`run` passes the row** at `asf/tick/step_wave.py:175`, where it passes `row.branch` today.
3. **The `launch` event gains `preamble_lines` and `facts_unknown`** — the length in lines of the
   built preamble, and `preamble.unknown_count(text)` over it. `ctx.event` writes free-form JSON
   with no schema (`asf/tick/tick.py:139-148`), so this needs no migration. `facts_unknown: 0` is
   this card's first acceptance line, measured on every launch rather than once (P9).
4. **The module docstring** says what step 4 now does: one `ls-remote`, three local reads and one
   ledger read per launching row.
5. **Rewrite the three tests**, run the gate, commit with `git commit -s`, push.
