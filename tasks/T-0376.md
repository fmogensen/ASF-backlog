§2.12: the five subcommands, the two doctor rows, and the guide that is the only place an operator
learns what workflow to paste. This Task also lands T8's two remaining integration cases, which
need both the pass and `asf probe consent` (PD9), and asserts the new package sits inside both
whole-tree fences (P10).

**Files**

- `asf/probe/cli.py` — one parser, five subcommands, `register(sub)`
- `asf/cli.py` — the parser registration, as `deploy.register(sub)` is done (l. 351-352)
- `asf/doctor.py` — the `probe` and `probe secrets` rows in `run` (l. 811)
- `docs/guide/production-probe.md` — the guide
- `docs/README.md` — the index line the new page is reachable through (PD12)
- `tests/test_cli.py`, `tests/test_doctor.py` — T9
- `tests/test_probe_fence.py` — T8's two integration cases
- `tests/test_lifecycle.py` — the one-classifier AST fence over the new package

**Steps**

1. `asf probe` with `journeys`, `dispatch [--sha]`, `read`, `lint` and
   `consent --grant | --revoke | --show`, each parsing its flags and calling its function with an
   injectable host, per §2.12's table. `dispatch` refuses for the same reasons the pass does.
2. `asf/cli.py`: `from asf.probe import cli as probe_cli` / `probe_cli.register(sub)`, the two
   lines `deploy` already has.
3. `asf doctor` gains `probe` — red for a product that deploys and has no `probe:` block, a
   non-empty `config_problems`, a lint problem, consents not granted, a newest probe older than
   the newest deploy, or an `abandoned` entry — and `probe secrets`, naming each of the two
   declared repository secrets that is not set, with its `gh secret set` line and **never a value**.
4. `docs/guide/production-probe.md`: the block, the workflow job to paste (its `runs-on`, its two
   secrets, its `permissions: contents: read`, its artifact upload), the `journeys`/`mailbox`
   inputs, the result schema, the five contract clauses of §2.3, the five sign-in steps of §2.4,
   the three one-time operator steps (create the identity, set the two secrets, grant and record
   the consents) and how to read a failed probe's Bug. The pasted job is the one `lint` returns no
   problem for, and the test asserts that against the guide's own fenced block.
5. `docs/README.md`: one line beside the other guide entries (l. 14).
6. `tests/test_probe_fence.py` gains T8's two remaining cases (PD9): the pass with a lint problem
   dispatches nothing and prints it; with no consent stamp the pass dispatches nothing and prints
   the `NEEDS OPERATOR` line, `consent --grant` writes the stamp and the next pass dispatches, and
   `--revoke` stops it again.
7. `tests/test_cli.py`: `asf probe --help` lists the five subcommands, and each parses its flags
   and calls its function with a fake host.
8. `tests/test_doctor.py`: the `probe` row green for a configured, linted, consented product with
   a fresh probe, and red with the reason for each of the six conditions; the `probe secrets` row
   naming each unset secret with its `gh secret set` line and no value.
9. The two whole-tree fences over the new package, run as commands and asserted:
   `tools/check_conventions.sh` (no product convention as a literal in `asf/**/*.py`) and
   `tests/test_lifecycle.py:730`'s one-classifier AST fence (no session state word as a string
   literal anywhere in `asf/**/*.py`). Neither is waived.
10. `tools/check_generic.sh` over the guide, the example config and the code: no product, company,
    person, vendor or host name in any of them (P11).
