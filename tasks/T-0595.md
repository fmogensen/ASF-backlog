The spec's §2, §4 and §5's second half — the lock, `install_due`, and the exit attempt at every
`cmd_tick` path and at the background harvest's `main`. **This is the Task that fixes the card.**
On the trunk today an install is attempted at exactly one moment per tick, the aligned minute when
the floor is fullest (P2, P3); when this lands it is attempted again at the emptiest moment the
factory has, the instant a process leaves the floor — and the exiting process is the one that knows
the floor just lost a member.

**Read PD3 before touching `cmd_tick`**: `--shadow` wins over `--dry-run` today and must keep
winning. **Read PD6 before writing the tests**: `run=subprocess.run` is a default and cannot be
patched; a test that drives `cmd_tick` without wrapping `upgrade.install_due` runs a real
`pipx install --force` on the machine under test.

**What changes for the machine when this lands.** The card's twenty minutes end. A floor that is
busy at 06:25's aligned minute is empty at 06:27 when one of those ticks exits, and that tick
installs — `upgrade: the floor is empty at this exit — installing 5cab3a2`. Every exit that still
finds the floor busy counts a pass and says so by name. A new line appears at a tick's start while
an install is running (`tick: waiting — an install is running`), and two installs can no longer
overlap. Nothing is parked that was not parked before: the exit install writes no pending marker
(PD7). Without Task 3 the drain is still the 180 s poll at the tick's start, so a floor that never
empties by itself is not yet fixed — that is the next Task — but the card's own case, an
*overlapping* floor that empties whenever anything exits, is.

   `open(lock_path(), 'a+', encoding='utf-8')`, `fcntl.flock(f, LOCK_EX | LOCK_NB)` in a `try` that
   yields `None` and returns on `OSError`, else yields `f`, with `f.close()` in the `finally`.
