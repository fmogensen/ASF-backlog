## Description
stories: S-14856
writes: asf/workers/health.py, tests/test_workers.py
after: Task 4

The spec's `asf/workers/health.py` section, D7 and D8. A bad report ends the run and hands the
same branch in the same worktree back to a `correct` session whose whole job is to re-print the
report; the second time on that branch, nothing is held — `report: 'unreadable'` is written, the
run is re-judged on its work, and a `bad-report` entry joins `found` for Task 6 to emit.

**Files**

- `asf/workers/health.py` — one `elif reason.startswith(f'failed: {lifecycle.BAD_REPORT}')` after
  the empty-branch arm (`:315-322`): when `lifecycle.report_spent(registry, s)` is False, hold
  with `lifecycle.REPORT` and `lifecycle.report_text(s.get('kind'), why, tail)` and record PD7's
  printed line; when it is True, `pool_mod.update_session(product, job, report='unreadable')`,
  re-judge with `report_done=True`, write the re-judged `end_reason`, and
  `found.append((job, 'bad-report', why))`. `UNPUSHED_REASON_PREFIXES` is untouched: a bad report
  is not unpushed work.
- `tests/test_workers.py` — `BadReportHoldTest` (new, the spec's six cases).

**Steps**

1. The `why` is the reason's own tail (`reason.split(f'{lifecycle.BAD_REPORT}: ', 1)[-1]`), and
   the `tail` handed to `report_text` is the last 20 lines of the result's text.
2. The hold arm, with PD7's printed line built from `why` and `hold`'s `rounds` — `— adjudicate
   pending` when `hold` returned none.
3. The spent arm: `report='unreadable'`, the re-judged reason on the registry and on `s`, the
   `bad-report` entry. No `correction`, no round spent.
4. `BadReportHoldTest`, then the suite.

- `BadReportHoldTest`
  - `test_a_bad_report_ends_the_run_and_holds_its_branch`: a live session whose log's result is
    prose-only on a pushed branch with commits; one `health(product, fix=True)` → the run's
    `end_reason` is `failed: bad report: …`, its registry line carries a `correction` of kind
    `report`, `rounds` is 1, and the printed line says `held <branch>`.
  - `test_the_correction_is_the_contract_for_that_kind`: the held run's `correction['text']`
    contains the `spec` contract's field names and the tail of what the session said.
  - `test_the_feeder_sends_it_back_to_the_same_branch`: `lifecycle.corrections(path)` has the
    item with `kind: 'report'` and the run's own branch, and `rows.correction_rows` turns it into
    a FIX → CORRECT row whose `branch` is that branch (not a new one).
  - `test_the_second_time_it_is_not_held_again`: the same branch, a second run, again no report →
    no new `correction`, the run carries `report: 'unreadable'`, its `end_reason` is `finished`,
    and `found` has `(job, 'bad-report', why)` (D8).
  - `test_a_good_report_is_untouched`: the same fixture with `report.render('spec', …)` appended
    → `end_reason: finished`, no `correction`, no `report` field.
  - `test_an_unpushed_run_is_still_held_for_the_push`: prose-only *and* unpushed → one hold, of
    kind `unpushed`, and the correction text is the push one.
