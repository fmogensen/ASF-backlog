§2.3 and §2.4. One pure function over one window of CI events, two rows built from it at the end
of the waste table, and `render_daily` hoisting the seven-day CI read it already makes so the row
and the cost table see the same list. The `ci runs` and `runner-minutes` rows are not touched —
the target rows are additional, and both numbers keep the definitions those two already print.

**Files**

- `asf/metrics/metrics.py` — `CI_TARGET_WINDOW_DAYS = 7` and `CI_SPLIT_CAP = 4` beside the other
  module constants; `_conv_int(conv, key, default)` and `_ci_provider(conv)` (P6, P9) beside
  `_pct` (`:404-405`); `ci_waste_numbers(ci, conv=None)`; `scorecard_rows`' new `ci7` keyword
  (`:454`) and the two rows appended after the intake-latency block (`:514-516`, P16);
  `render_daily`'s hoisted `ci7` (`:556-564`).
- `tests/test_metrics.py` — `CiWasteNumberTests` (new, pure, no fixture) and `CiTargetRowTests`
  (new, over a record root through `cmd_rollup`, beside `Rollup` at `:367`).

**Steps**

1. `CI_TARGET_WINDOW_DAYS = 7` and `CI_SPLIT_CAP = 4` with §2.3's comment on the cap.
2. `_conv_int(conv, key, default)` → `(value, complaint)`: the conventions' integer for `key`, or
   `default` and a sentence naming what the product wrote instead. A `bool` is **not** an integer
   here (P9) — `targets: {cancelled_pct: true}` yields the default and the complaint, not the
   target 1. The complaint names the key and the value as written, which is what fills `config`.
3. `_ci_provider(conv)` → the product's provider, or `None` when it is falsy or the literal
   `'none'` (P6). Every reader of the provider in this module goes through it: the row's label,
   the skip test, and — in Task 4 — the Bug's title through the dict this function returns.
4. `ci_waste_numbers(ci, conv=None)` exactly as §2.3 fences it: a two-element list in scorecard
   order, `cancelled` then `red`, each dict carrying `key`, `label`, `provider`, `num`, `den`,
   `unit`, `pct`, `target`, `floor`, `verdict`, `config`, `by_day` and `split`. The numerators and
   denominators are §2.3's table — `cancelled_minutes` over `minutes`, `conclusion == 'failure'`
   over `len(ci)` — read with `.get` and a default (P7). `pct` is `_pct(num, den)`, the same
   integer floor the rest of the table prints; `pct` is `None` and `verdict` is `'no verdict'`
   when `den < floor`, an empty window included; otherwise `verdict` is `'over'` when
   `pct >= target` (a product setting `cancelled_pct: 0` gets a verdict, not an unmeetable
   number), else `'ok'`.
5. `by_day` buckets on `parse_ts(r.get('ts')).date().isoformat()`, oldest first, days with runs
   only; a run whose `ts` will not parse stays in `num` and `den` and is left out of `by_day`,
   never dropped from the number. `split` is `_kind_of_branch(r, conv)` for `cancelled` and the
   name of each failing job for `red`, largest first, at most `CI_SPLIT_CAP` entries.
6. No clock and no filesystem inside the function: the window is the list it was handed. The same
   input twice gives equal output, which is T2's last sentence and is asserted as such.
7. `scorecard_rows(ci, sessions, ticks, conv=None, events=(), ci7=None)` — the keyword is last and
   defaulted, so both existing callers are unchanged (P14). After the `if events:` block, one row
   per number in `ci_waste_numbers(ci7 or ci, conv)` order, rendered as §2.4 fences:
   `| ci cancelled minutes (gh-actions) | 18 % of 4210 runner-minutes (7d) | target 15 % — over; today 9 %; branch 610, batch 120, trunk 30 |`.
   Today's percentage in the note comes from `ci_waste_numbers(ci, conv)` — the day's list, the
   same function.
