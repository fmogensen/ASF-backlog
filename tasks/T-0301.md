§2.7. The reshape row is cleared only when the session marks the Task `removed: split into <ids>`
(§1.1), so a session that pushed the plan half and died relaunches into a brief that asks for
fresh ids and knows nothing of the ones already minted. The row still launches — parts may exist
and be wrong, which is exactly the case the memory file was written about (§1.4). What changes is
that the session is told, in the brief and in the line, that the record holds a half-done split.

**Files**

- `asf/briefs/build.py` — `split_parts(items, item_id)` and the `split_parts` key on `context`
- `asf/briefs/templates/reshape.md` — §2.7's paragraph under DELIVERABLE
- `asf/feeder/rows.py` — the reshape LAUNCH row's reason
- `tests/test_briefs.py` — `ReshapeSplitPartsTests`
- `tests/test_feeder.py` — `ReshapeRelaunchTests` (new: PD9)

**Steps**

1. `asf/briefs/build.py`: `split_parts(items, item_id)` → `'<id> (<writes>)'` per Task of the
   index whose `split_from` is `item_id` and which is not in a done state, joined with `', '`, or
   the string `none yet`. `facts['items']` is already the live index (`index_reader.live` drops
   removed cards, `asf/views/index_reader.py:30-40`), so the openness test is the state check the
   feeder's own rows use, and `<writes>` is the card's `writes:` joined with a space, or `—` when
   it declares none. Sorted by id, so two runs read the same.
2. `context` gains `'split_parts': split_parts(facts['items'], item.get('id'))`. One flat key, as
   the module's docstring requires; every template may use it and only the reshape one does.
3. `asf/briefs/templates/reshape.md` gains §2.7's paragraph under DELIVERABLE, byte for byte,
   with its two placeholders `{item_id}` and `{split_parts}`. Both are context keys, so
   `tests/test_briefs.py`'s existing `PlaceholderTest` — every template placeholder is a context
   key, and an unknown one is a `BriefError` and not an empty string
   (`tests/test_briefs.py:689-707`) — is what proves the wiring, and it runs unchanged.
4. `asf/feeder/rows.py`: the reshape LAUNCH row's reason (`:1090`) becomes
   `f"groom: {t['reshape']}"` plus `f" (parts already minted: {ids})"` when the index holds open
   parts whose `split_from` is this Task, with `ids` the comma-joined ids. With no parts the
   reason is byte-identical to today's — §3's T7 asserts that, and it is what keeps every
   existing row test green. The row's `action`, `kind`, `branch` and `waits_on` do not change: it
   still launches (§1.4).
5. The parts are read from the items the row builder already has; nothing new is loaded and no
   new card field is added (§4, "Rows and events").
6. `tests/test_briefs.py` gains `ReshapeSplitPartsTests`, §3's T7 first half: `build.context` for
   a reshape row carries `split_parts` listing the open `split_from` Tasks with their `writes:`,
   and `none yet` when the record holds none; the rendered brief contains `mint no new id` in the
   first case and not in the second.
7. `tests/test_feeder.py` gains `ReshapeRelaunchTests` (PD9), the second half: the reshape LAUNCH
   row's reason ends with `(parts already minted: T-0190, T-0191)` when the index holds those two
   open parts, and is byte-identical to today's reason when it holds none. The existing
   `ReshapeRowsTest` is left as it is; this class sits beside it.
