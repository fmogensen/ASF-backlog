## Description
stories: S-33453
writes: asf/doctor.py, tests/test_doctor.py
after: Task 3

The spec's `asf/doctor.py` design section: one function, one row, beside the `backlog` row it
refines. It is the standing-still answer to the question the tables answer in motion — and it is
the only place the *git* half of this card lives, because `freshness` is on the path of every
table and must stay git-free (D10). PD10 is binding here: the doctor does not `git fetch` today,
and this row does not get to add an unguarded one.

**Files**

- `asf/doctor.py` — `check_record_checkout(product)`; one row appended in `run`
- `tests/test_doctor.py` — new `RecordCheckoutRow`

**Steps**

1. `check_record_checkout(product)` returning `(ok, detail)`, with the spec's docstring and its
   five details byte for byte: `current — index generated 3m ago`; `<path> is 3 commits behind
   origin/main — the tick will fast-forward it on its next run`; `<path> has local changes: the
   tick cannot fast-forward it — commit or push them, then git -C <path> pull`; `<path> is on
   spec/F-0122, not main — the tick only fast-forwards the trunk`; `<path> has diverged from
   origin/main by 2 commits — push them or reset`. The trunk is read the way `shadow` reads it,
   never a literal — `tools/check_conventions.sh` forbids a branch name in code (PD5).
2. The age in the `current` detail comes from `asf.views.freshness` — `generated_at` plus
   `index_reader.span` — not a second formatter, so the doctor and the tables can never disagree
   about how old the index is (D9). This is the whole of Task 5's dependency on Task 3.
3. **The fetch carries the doctor's own guard (PD10).** `git fetch -q origin` with
   `GIT_TERMINAL_PROMPT=0` in its environment and `timeout=15`, copied from the worker-push-auth
   probe at `asf/doctor.py:325-334`, which is the only network call this command makes today. A
   fetch that fails, times out or raises is caught by name — `subprocess.TimeoutExpired`,
   `subprocess.CalledProcessError`, `OSError` — and becomes a row detail saying the remote could
   not be reached. `asf doctor` never hangs on a credential prompt and never raises out of this
   row.
4. The row, beside the `backlog` row it refines (`asf/doctor.py:822-823`):
   `ok, detail = check_record_checkout(product)` then
   `rows.append(('record', False, ok, detail))`. `required=False` (D11): a checkout an operator is
   working in is behind by design, and the tables now route around it. A row that goes red on an
   ordinary working state teaches an operator to ignore the doctor.
5. `RecordCheckoutRow` in `tests/test_doctor.py`, over real git repositories in a temp directory,
   one case per detail: current, behind, dirty, off-trunk, diverged — each asserting on the detail
   string, including the command it ends with. One case asserts the unreachable-remote detail with
   a broken `origin`, and that it returns rather than hangs.
6. The case that pins D11: a stale checkout makes the `record` row not-ok and `asf doctor`
   **still exits 0** on its own account. Asserted through the exit code, not by reading
   `required` — the point is the operator's experience, not the tuple.
7. `check_backlog` is not touched. The `backlog` row keeps asserting exactly what it asserts today
   (a directory, and a work tree) and stays `required=True`; the new row refines it and does not
   absorb it.

**Gate**

```bash
python3 -m unittest -v tests.test_doctor.RecordCheckoutRow
python3 -m unittest -v tests.test_doctor tests.test_views_freshness
bash tools/check_conventions.sh && bash tools/check_generic.sh && python3 tools/run_tests.py
```

**Acceptance**

exit 1 on its own:
