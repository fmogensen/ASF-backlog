§2.7 and §4: the command a precheck session runs on its own file before it commits, and the read
that makes the card's second acceptance line measurable — findings per expensive round, with a C
item the precheck already named counted as `repeated` and not as new. Plus the three registrations
that put the session in the existing cost table.

**Files**

- `asf/precheck.py` — below a `# ---- the command ----` divider (PD5): `register(subparsers)`,
  `add_arguments`, `cmd_precheck`, `cmd_precheck_report`, `main`
- `asf/cli.py` — the `precheck` parser in `build_parser`, the dispatch in `_main`
- `asf/record/match.py` — `precheck` in `ROLE_PREFIX`
- `asf/metrics/metrics.py` — `precheck` in `KIND_PREFIXES`' review alternation;
  `RECORD_KINDS['precheck'] = 'review'`
- `tests/test_precheck.py` — `CommandTests`, `ReportTests`
- `tests/test_cli.py` — the verb is registered

**Steps**

1. The divider and the command half of `asf/precheck.py` (PD5), with a comment saying the grammar
   above it opens no file and the command below it is the only part that does.
2. `add_arguments(p)`: `target` (a path, or the literal `report` — PD6), `--level`
   `choices=LEVELS`, `--json`, `--days` (default 30, the report's). `register(subparsers)` adds the
   `precheck` verb and `set_defaults(run=cmd_precheck)`, the shape `asf/redact.py:562` has; `main`
   for `python3 -m asf.precheck`.
3. `cmd_precheck(args)`: `report` → `cmd_precheck_report`. Otherwise `--level` missing is exit 2
   with one usage line (PD6); a missing path is exit 2 with one line and no traceback; else read
   the file, `parse` and `faults`, and print §2.7's human output exactly —
   `== PRECHECK <path>  level <l>, <n> rows, <n> findings (<n> high), <n> fault`, one
   `<path>:<line>: <fault>` per fault, then the `blocking: <n>` line, with
   `— this branch will be sent back` when it is non-zero. Exit 1 on a fault, 0 with none — and the
   `blocking:` line prints either way, because finding something is the pass working (§2.7).
   `--json` prints `{"path", "level", "head", "rows", "findings", "blocking", "faults"}` with
   sorted keys.
4. `cmd_precheck_report(args)`: over the last `--days N`, one row per item whose branch carried
   both a precheck and a review — the precheck files in the reviews directory and the review files
   beside them, read through `asf.evidence.review` for the rounds and `c_items` for the C list.
   Per row: the level, the precheck's finding counts by confidence, the expensive rounds that
   followed, the C items those rounds raised, and — counted separately — `repeated`, the C items
   whose `file:line` the precheck already named (`keys` over all its `fail` rows, not only the
   blocking ones: a `medium` finding the reviewer re-raises is the thing this number exists to
   catch). `--json` is the same numbers as one typed object. No git, no network: the record clone
   and the reviews directory are the whole input.
5. `asf/cli.py`: `from asf.precheck import register as register_precheck` beside the other
   `register` imports in `build_parser`, and the dispatch line in `_main` — the parser here, the
   body there, as every other verb is arranged.
6. `asf/record/match.py:31`: `precheck` into `ROLE_PREFIX`'s alternation, so a session named
   `precheck-t-0244` strips to `t-0244` (PD13).
7. `asf/metrics/metrics.py:45`: `(r'(review|prereview|precheck|rr\d*)', 'review')`, and
   `RECORD_KINDS['precheck'] = 'review'` (`:53`) — the feeder row kind onto the `sessions`
   stream's kind, so the pass's cost lands in the existing per-Feature cost table (§4). No new
   stream, no new schema key (§1.3). PD12 says what is deliberately left alone in the scorecard.

   complete table at `--level low` → exit 0, `blocking: 0`; the s
