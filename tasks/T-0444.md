stories: S-32502

after: Task 2

The spec's last **In** bullet and its `docs/guide/product-config.md` design block. The card asks for
this to be documented in the rule-check contract, and the `## Rule cards` section *is* that contract
in prose — the `check:` script, the exit codes, the timeout, `asf rules check` (P15, D14). The
paragraph goes where the spec puts it: after the `exit 0` / `exit 1` sentence
(`docs/guide/product-config.md:603`), before the retirement paragraph (`:605`), so it lands beside
the exit codes it turns on.

**Files**

- `docs/guide/product-config.md` — `## Rule cards`: the paragraph, the two-line example, the
  five-key table, the three exit codes, the `--product` sentence and the check script
- `tests/test_readme.py` — `RuleCheckContractProseTests` (new class)

**Steps**

1. Insert the spec's block byte for byte into `## Rule cards` at the position above: the **Asking
   what ASF already owns** paragraph naming the false positive it removes and
   `asf pr-hygiene --product <p> --lanes` as the supported way to ask; the two example lines; the
   five-key table (`pr`, `branch`, `lane`, `since`, `action`) with the spec's wording for each; the
   sentence that it reads the state the tick's `prs` step already cached and makes no network call,
   so a check may call it every run; the three exit codes — 0 with output, 0 with none when ASF owns
   nothing, 2 when the product or its state cannot be read — and that propagating the 2 makes the
   check a *check failure* rather than a rule the product broke (P14); and the `--product` sentence,
   because `run_check` guarantees `BACKLOG_ROOT` and a cwd and nothing else (D13).
2. The check script fence, byte for byte, including its `product=your-product` line and that line's
   comment — the spec writes a real value there rather than `<p>` precisely because `<p>` inside
   `$( )` is a redirect. No worker account name, no machine path, no product of anyone's: the branch
   names in the example are the record's own `worker/T-000n` shape and the product is the guide's
   placeholder, so `tools/check_generic.sh` has nothing to find (run in this Task's Gate).
3. `RuleCheckContractProseTests` in `tests/test_readme.py`, following `ProductResolutionProseTests`'
   pattern exactly — read `docs/guide/product-config.md` from `REPO_ROOT`, never a fixture (P16,
   D15): the `## Rule cards` section contains `asf pr-hygiene`, `--lanes`, all five key names and
   the three exit codes it promises; the example lines parse with `json.loads` and each has exactly
   the five keys, so the documented shape and `lanes()`' shape cannot drift apart silently; and the
   `sh` fence is written to a temp file and run through `bash -n`, which must exit 0 — a snippet the
   guide tells an operator to copy is at least known to parse (D15). The script is not *executed*:
   it calls `your_conflicting_prs`, which is the product's to write.
