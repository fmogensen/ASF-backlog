**Files**

- `asf/credentials.py` — the second half of the module:
  - `cache_path(product)` → `os.path.join(env.state_dir(product.name), 'credentials.json')`.
  - `read_cache(product)` → `{name: Result}`, `{}` on a missing or unreadable file (the same
    tolerance `file_bugs._read_ledger` has: a corrupt cache is a cache miss, never a raise).
    Exported for the doctor (PD9).
  - `write_cache(product, results, previous=None)` — `{"providers": {name: {state, expires,
    detail, probed_at}}}`, written through a `.tmp` and `os.replace`, the idiom
    `file_bugs._write_ledger` uses. A provider whose new result is `broken` keeps its previous
    entry (PD8); a provider with no previous entry and a broken result is simply absent.
  - `check(product, cfg, fresh=False, now=None, run=subprocess.run)` → `[Result]`, one per
    provider `for_product` returns, in the product's order. An entry is taken from the cache when
    `fresh` is false and its `probed_at` is within `probe_every(cfg)` of `now`; every other
    provider is probed. The probes run together in a
    `concurrent.futures.ThreadPoolExecutor(max_workers=min(8, n))` (PD7), each one
    `run_probe(provider, probe_env(provider, cfg, product), now, run=run)`. The cache is
    rewritten after. Verdicts are **not** stored: `verdict` and `days_left` are recomputed from
    `expires` and `now` on every call, which is what lets a cached entry tick into its window
    without a probe (D6).
  - `render(results, product, cfg, out=print)` — the table of §2.3, one row per provider sorted by
    name, under `views.header.head('credentials check', product.name, clause)` with the clause
    `<n> ok, <n> expiring, <n> invalid` (and `, <n> broken` when any is). An `ok` row reads
    `expires <iso> (<n>d)` or `expiry unknown`; an `EXPIRING` row ends
    `— renew: <the renew command>`; an `INVALID` row reads
    `not signed in — renew: <the renew command>`; a `BROKEN` row reads
    `probe failed exit <rc> — <detail>`.
  - `as_json(results, product, cfg)` → `{"product", "window_days", "providers": [{"provider",
    "state", "verdict", "expires", "days_left", "probed_at", "detail"}]}`, the keys §2.3 names and
    no others. No token: `detail` is the scrubbed one and there is no other field carrying probe
    output. `renew` is a command from operator config and is included.
  - `quiet(results, product, cfg, out=print, err=sys.stderr)` → the rc. Nothing printed and 0 when
    every verdict is `ok` or `unknown`. One line per bad provider and 1 when any is
    `invalid`/`expiring`, each line exactly §2.3's shape:
    `credential <name> expires <iso> (<n>d, window <n>d) — renew: <cmd>` for `expiring`, and
    `credential <name> is not valid — renew: <cmd>` for `invalid`. `credentials: probe broken for
    <name>: <detail>` on stderr and 2 when any probe is broken — 2 beats 1 (PD17), and the bad
    lines are still written to stdout first.
  - `cmd_check(args, product, cfg)` — dispatch over `--json`, `--quiet` and the default table, and
    the rc rules of §2.3: 0 when every verdict is `ok` or `unknown`, 1 when any is
    `invalid`/`expiring`, 2 when any is `broken`. A product that names no provider is 0 with
    `no providers configured` in place of the rows.
