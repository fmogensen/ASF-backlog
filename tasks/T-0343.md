## Description
stories: S-31202, S-31203
writes: asf/briefs/facts.py, tests/test_brief_facts.py
after: Task 3

§2.3 and §2.4: the two reads that answer *who ran here before and where did they stop*. `predecessor`
is the switch the whole Feature turns on (D2) and the owner of the log `last_progress` is read from;
`last_report` becomes branch-scoped with the branch's newest review verdict behind it (D9).
`predecessor` and `last_progress` have no caller yet — Task 5 is their first; `last_report`'s new
`branch=` is passed by `repo_facts` in this Task, and its `review=` only in Task 5 (PD8).

**Files**

- `asf/briefs/facts.py` — `PROGRESS_TAIL_BYTES`, `last_progress`, `_squeeze`, `_cap`, `branch_review`,
  `last_report`, `predecessor`; `repo_facts` passes `branch=`
- `tests/test_brief_facts.py` — `ProgressLineTests`, `PredecessorTests`, `LastReportTests` (new cases)

**Steps**

1. Factor the truncation (PD12): `_squeeze(text, cap=FIELD_CAP)` squeezes whitespace and cuts to
   `cap` with the `…` ellipsis exactly as `_cap` does today; `_cap(label, value)` becomes
   `_squeeze(f'{label}: {value}')`. `_cap`'s output must not move by a byte — the existing
   `test_a_field_is_capped` is the check.
2. Add the constant with §2.3's doc comment (`PROGRESS_TAIL_BYTES = 256 * 1024`) and
   `last_progress(log, tail=PROGRESS_TAIL_BYTES)` with §2.3's docstring verbatim: `seek` to
   `max(0, size - tail)`, read to the end, drop the first partial line when the file was seeked,
   parse each line as JSON and ignore what does not parse, then scan the records **backwards** for
   the first with `rec['type'] == 'assistant'` whose `message.content` holds a
   `{'type': 'text', 'text': …}` block (P12). Take that text's *last* text block, its first
   non-empty line, through `_squeeze`. `''` for no log, an unreadable one, no assistant turn, and
   every `OSError`/`ValueError`. A `result` record is never a progress line (§2.3) — C3 owns the
   REPORT.
3. Add `predecessor(product, item_id, branch, kind)` with §2.5's docstring verbatim: over
   `lifecycle.item_runs(pool.sessions_path(product) or the state dir's sessions.jsonl, item_id)`,
   keep runs with `r.get('ended')`, `r.get('branch') == branch`, `r.get('kind') == kind` (raw — PD6)
   and `not lifecycle.landed(r)`; return the newest by `ended` as
   `{'job', 'ended', 'end_reason', 'attempt'}`, else `{}`. `attempt` is the run's 1-based index
   among *that job's* runs in ledger order, so the block can say "attempt 2". Empty for a falsy
   `item_id`, `branch` or `kind`, and for every read failure.
4. `last_report(product, item_id, branch='', review=None)`: when `branch` is truthy keep only runs
   with `run.get('branch') == branch`; with `branch=''` behave exactly as today (every run of the
   item), so `asf brief --kind` over a row with no branch keeps working. The `<job> ended <ts> —
   <end_reason>` line and the five `_cap`ped `REPORT_FIELDS` are unchanged. When `report.parse`
   yields none of those fields and `review` is given, append one line
   `review round <n> (<path>): verdict <v>` — `v` from `asf.evidence.review.verdict_of(text)`, and
   the line omitted when that returns `None`.
5. Add `branch_review(repo, rev, tree_paths, product, slug, round_)` (PD7): the highest `n` in
   `1..max(round_, 1)` whose `preamble.review_path_for(product, slug, n)` is in `tree_paths`, read
   with one `_git_text(repo, ['cat-file', '-p', f'{rev}:{path}'])`; `(n, path, text)` or `None` for
   no match, an empty read and every failure. It makes no listing of its own — `repo_facts` already
   holds the `ls-tree` output.
6. `repo_facts` passes `branch=plain['branch']` to `last_report`. Nothing else in it changes in this
   Task; the `review=` argument and the three new keys are Task 5's.
7. `ProgressLineTests`, all of T3's cases: two text blocks in the last turn → the last block's first
   non-empty line, squeezed; a `result` line after the last turn → the turn is still found; a line
   over `FIELD_CAP` → cut with the ellipsis; a log
