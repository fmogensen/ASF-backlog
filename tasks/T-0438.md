The spec's "One plan, one set of inputs" bullet and its `asf/tick/step_wave.py` design block: the
`Plan` record and the four functions that make it, and `launch` losing its hand-made plan for a call
to `plan_now`. The wave's own behaviour is bit-for-bit today's (D12) — that is the property this Task
is judged on. Nothing prints anything new here; the lines are Task 3's.

**Files**

- `asf/tick/step_wave.py` — `Plan`, `FETCH_TIMEOUT`, `reader_root`, `behind`, `plan_index`,
  `plan_now`; `fresh_index` bounded; `cloud_readiness` gains `run_cmd`; `launch` rebuilt on `plan_now`
- `tests/test_s1_gate.py` — `NextReadsTheRecordCloneTests`
- `tests/test_tick_steps.py` — the wave's plan asserted to be unchanged, in `WaveStepTests`' idiom

**Steps**

1. `Plan` as the spec's dataclass, field for field and comment for comment: `rows`, `gate`,
   `dropped`, `items`, `inputs`, `capacity`, `inflight`, `root`, `source`. `FETCH_TIMEOUT = 15` with
   the spec's comment.
2. `reader_root(product)`: `shadow.record_dir(product)` when that directory holds a `.git`, else
   `product.backlog_dir` or `None` (PD7). It never calls `ensure_clone` and never resets — a view
   that reset the clone would discard the uncommitted record work of a tick running beside it
   (`asf/tick/shadow.py:69-80`, D14). The `None` answer is what lets `status` fall back to its own
   root and what makes a product with neither honest rather than crashing.
3. `behind(root)`: `git -C <root> merge-base --is-ancestor origin/<default branch> HEAD` — `True`
   when it exits non-zero, `False` when it exits 0 and `False` when the question cannot be asked (no
   `origin/<branch>`, not a repo, the subprocess fails). The branch is `shadow._default_branch`, the
   one `fresh_index` already uses. By ancestry a clone reset at a tick's start, with or without the
   tick's own commits on top, is never behind (D12) — which is why the wave's map does not move.
4. `plan_index(product, root, index=None)`: `index` when given, else `index_reader.load(root)[0]`
   when `root` holds an `index.json`, else `{}`. Then `fresh = fresh_index(root)` when `root` is a
   repo; when `behind(root)` and `fresh` is not `None`, `fresh` is the base map (D13 — the fresher
   record wins, one level up from `blockedBy`), otherwise `overlay_blockers(items, fresh)` exactly as
   the wave applies it today. Then `plan_order.overlay(items, plan_order.trunk_reader(product))` when
   `product.repo_dir`. Returns `(items, source)`, `source` being one of the spec's three strings.
5. `fresh_index` gains `timeout=FETCH_TIMEOUT` on its `git fetch` and one
   `except subprocess.TimeoutExpired: return None` — the answer it already gives for a fetch that
   fails, so "origin unreadable" stays its single failure contract. The `git show` is local and keeps
   no timeout.
6. `cloud_readiness(product, cloud, run_cmd=None)` passes `run_cmd` through to
   `cloud_mod.readiness(cfg, product, run_cmd=run_cmd)`. Its `except Exception` is unchanged: an
   unreadable lane is an unready one, and an unready lane adds no seats.
7. `plan_now(product, root=None, items=None, capacity=None, inflight=None, decision_limit=None,
   out=None)` with the spec's docstring. Every argument is an override for a caller that has the
   answer; what is not given is read here. `root` defaults to `reader_root(product)`; `items` and
