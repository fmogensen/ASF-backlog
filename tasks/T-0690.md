The spec's C8: the hit rate read from the run summaries the sessions' worktrees already hold —
`<worktrees>/*/<summary_glob>`, the newest `summary_max` inside `summary_window_h`, either shape
accepted and the files matching neither *counted*. The rate goes in the pass's line, in the
status table's new `Caches` row and in the doctor detail; it goes in no metric stream (C9).

Read **PD6** (the rate clause's grammar and the `80%` rounding), **PD9** (this Task adds the rate
to `caches.doctor_line` — inside `caches.py`, so `asf/doctor.py` stays Task 2's) and **PD11** (no
`not_configured` in the cell) before starting.

**Files**

- `asf/workers/caches.py`
  - `summary_counts(data)` — `(attempted, cached)` off one summary, or None when it is neither
    shape
  - `hit_rate(product, conv, now=None)` — new
  - `line(var, data, rate)` — the rate clause, the tail **PD6** reserved for it
  - `status_line(product)` — the body: the size against the cap and the rate over the window
  - `doctor_line(product)` — the rate clause appended to Task 2's detail
  - `prune` — `hit_rate` called once a pass, its dict into the state's `summaries`
- `asf/views/status.py`
  - `caches_cell(product)` — new, `return caches.status_line(product)` with the import inside the
    function, the shape `ab_pairs_cell` (`:491-495`) and `gate_cell` (`:460`) already use
  - `render` (`:509-543`) — `('Caches', lambda: caches_cell(product))` appended to the row tuple
    after `('Lane pushes', …)` (`:535`)
- `tests/test_cache_prune.py` — `EXECUTION_SHAPE`, `TASKS_SHAPE` and `class
  CacheHitRate(CacheFixture)` with its seven tests, the spec's block byte for byte

**Steps**

1. `summary_counts(data)`, both shapes and neither: `execution.attempted`/`execution.cached` when
   `execution` is a mapping carrying them, else `tasks[].cache` rows counted as attempted with a
   `status` of `HIT` (or a true `local`/`remote`) counted as cached, else **None**. Two shapes
   because this could not be verified against the tool's real schema (P16) and a reader that
   recognises one shape silently reports 0% against the other; None rather than `(0, 0)` because
   that is what makes an unreadable schema a *number* in the record instead of a wrong rate.
2. `hit_rate(product, conv, now=None)`: glob `<spawn.worktrees_dir(product)>/*/<conv.pruning(
   'summary_glob')>`, keep the files whose mtime is inside `summary_window_h`, take the newest
   `summary_max` of those, read each, and sum. **None when no file is inside the window** — not
   a zero-run dict: `test_a_summary_older_than_the_window_is_not_counted` writes one summary
   48 h old and asserts `assertIsNone`, so "the glob matches nothing" in the spec's docstring
   reads as "nothing the window admits". `runs` counts the summaries `summary_counts` could read
   and `unreadable` the rest — `test_a_summary_of_neither_shape_is_counted_not_guessed` pins the
   pair at `(1, 1)` from two files — and `summary_max` bounds the **files read**, newest first,
   which is `test_summary_max_bounds_the_reads_to_the_newest`'s `runs == 2` out of five.
3. The rate clause in `line()`, per **PD6**: `hit rate <p>% of <n> tasks over <r> runs`, or
   `no run summaries` when `hit_rate` is None. `prune` calls `hit_rate` **once per pass**, not
   once per directory — the state's `summaries` is one dict and the spec's Records table says so —
   and passes it to every `line()`.
4. `status_line(product)`'s body: the variable, the size, `/ <cap> cap`, and the rate over the
   window, off `read_state` alone. `caches_cell` is its one-line delegate and returns whatever it
   returns, including None — which is how the row is absent before the first pass and for a
   product with no cache directory (C10, P9's *"a row that only speaks up when something is
