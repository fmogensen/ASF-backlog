## Description

after: none

§2.2: `head_of` stops throwing away the sha it already paid an `ls-remote` for (P4), and says so
rather than naming a stale commit when the clone does not hold that object yet (D5). Beside it, the
commit list the card's second item asks for. `commits_on` is pure of everything but one `git log`
and has no caller yet — Task 5 is its first.

**Files**

- `asf/briefs/facts.py` — `head_of` (`:64-88`); `COMMIT_LIMIT`, `commits_on`
- `tests/test_brief_facts.py` — `HeadTests` (two cases added), `CommitListTests`

**Steps**

1. `head_of` keeps its signature and its `(head, branch_exists, rev)` contract. Parse the sha out
   of the one `ls-remote` it already runs (`sha = ls.split()[0] if ls else ''`), take `exists` from
   it, and set `rev = sha` when `cat-file -e <sha>^{commit}` passes.
2. When `sha` is truthy and `rev` is empty — origin has moved and this clone has not fetched it —
   return `f'{sha[:9]} (origin/{branch} — not in this clone yet)', True, ''` at once, with the
   comment §2.2 gives: never pass the older ref off as the head, because the commit list would then
   read as the whole of what was done.
3. Carry `own = bool(sha) and bool(rev)` — whether `rev` is the branch's own head — and key the
   parenthetical off it, not off `rev == f'origin/{branch}'` (PD4). `own` → `(origin/<branch>)`;
   the trunk fallback → `(origin/<main> — <branch> is not on origin yet)` when there is a branch,
   `(origin/<main>)` when there is none. The trunk fallback itself, and the `rev-parse --verify -q`
   behind it, are unchanged.
4. Add the constant with §2.2's doc comment:

   ```python
   #: The most commits the brief lists between the trunk and the branch head; over it the block
   #: prints the count and names the `git log` that has the rest.
   COMMIT_LIMIT = 10
   ```
5. Add `commits_on(repo, rev, main, limit=COMMIT_LIMIT)` with §2.2's docstring verbatim: one
   `_git_text(repo, ['log', f'--format=%h %s', f'origin/{main}..{rev}'])`, newest first as git
   gives it, `total` the full line count, `lines` cut to `limit`. `{'total': 0, 'lines': []}` for a
   falsy `repo`/`rev`, for a rev the clone does not hold, for a branch level with the trunk, and
   for every failure — `_git_text` already returns `''` on a non-zero exit, so no raise escapes.
6. `HeadTests` gains: a pushed branch's `rev` is the sha `ls-remote` gave and not the local ref
   (move `refs/remotes/origin/<branch>` back one commit in the fixture, then assert the returned
   head names the newer sha and the parenthetical still reads `(origin/<branch>)`); and a head whose
   object the clone lacks reads `not in this clone yet`, returns `exists=True`, `rev=''`, and yields
   an empty commit list. The existing unpushed-branch case keeps its parenthetical unchanged.
7. `CommitListTests`: three commits above the trunk → three lines, newest first, each
   `<short sha> <subject>`; level with the trunk → `{'total': 0, 'lines': []}`; twelve commits with
   `limit=10` → ten lines and `total: 12`; a rev that does not resolve → empty, no raise.
