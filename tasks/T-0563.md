## Description
stories: S-37304
writes: asf/harvest/lane.py, tests/test_shared_paths.py
after: Task 1

The spec's §`asf/harvest/lane.py` — *serialised per path* — and nothing of the regenerate. Two
changes: `shared_hits` reads the key through the one accessor, and `precheck`'s reservation becomes a
dict keyed by the changed path (PD3). The card's second test — two branches touching the same
lockfile landing one after another — is written here, and today nothing tests any of it (P3).

**Files**

- `asf/harvest/lane.py` — `shared_hits(conv, files)`'s `globs = list(conv.get('shared_paths') or ())`
  becomes `list(footprint.shared_globs(conv))` (D1: one reader; `shared_globs` tolerates the mapping
  the lane holds, Task 1 step 1). `precheck`'s `ready, shared_taken = [], None` becomes
  `ready, shared_taken = [], {}`, and the reservation block is the spec's snippet: the first hit
  already taken makes the branch wait with reason `shared-path <path>` and a line naming the branch
  that holds it; otherwise every hit is reserved for this branch. The `hits` computation stays where
  it is — **after** the approvals and `skip_regate` blocks — so a branch held for an approval never
  takes a reservation it cannot use. `precheck`'s docstring keeps its shape and its *"a shared path
  taken"* clause gains *"— per path, not per tick"*.
- `tests/test_shared_paths.py` — `class SharedSerialisationTests`, importing `LaneFixture` and `sh`
  from `tests.test_lane` the way `tests/test_merge_mode.py:26` already does.

**Steps**

1. `shared_hits` through `footprint.shared_globs`. `asf.feeder.footprint` is already imported by
   this module's neighbours; add the import if the lane does not carry it, and keep it a module-level
   import of a pure module (no cycle: `footprint` imports only `fnmatch` and `asf.record.core`).
2. `precheck`'s dict. Keep the wait **before** the `ready.append`, keep the `continue`, and keep the
   whole block after the gate/`how` decision as it is today — a waiting branch must not be gated,
   which is the assertion the Story's first row makes.
3. The unit rows, against a `SimpleNamespace` fake lane the way `tests/test_customer_content.py:100-111`
   does (no git, no host): two entries both touching `uv.lock` → the first ready, the second waiting
   with reason `shared-path uv.lock`, and `f['how']` never carried into the gate for it; **two
   entries touching different shared paths (`uv.lock`, `package-lock.json`) both ready** (D7 — the
   defect this Task exists to fix, and the row that fails on today's code); one entry touching both
   reserves both, so a third touching either waits.
4. The landing row, over a real `LaneFixture` origin with
   `self.product(shared_paths=['uv.lock'])` and two lane branches each changing `uv.lock` in a
   region of its own (PD7's rule applies here too): one
   `harvest.run_product_harvest(...)` pass lands the first and leaves the second WAITING with
   `shared-path uv.lock`; a second pass gates the second branch on the new trunk and lands it. Assert
   two commits on the trunk in that order, and that the second branch **was** gated again —
   `skip_regate` is False for a trunk move on a lockfile, because `landing_class` reads it as `CODE`
   (P4). Assert it through the pass's own lines, not by patching `skip_regate`.
