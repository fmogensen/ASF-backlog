The spec's §3 and the first half of §4: the groom writes the flag through P2's round-trip writer with
one History line, deletes a flag that no longer matches, and asks about the whole set on **one** line
keyed on `belongs_to:<owner>` — counted as an open question, landing with the adjudicator, added once a
day by `merge_groom_text` and never twice.

**Files**

- `asf/groom/groom.py` — `_write_card_checked`, the flagging loop in `cmd_groom`,
  `groom_foreign_section`, the `GROOM_SECTIONS` entry
- `asf/groom/policy.py` — `OPEN_QUESTION_RE`'s token alternation
- `asf/record/new.py` — `belongs_to` joins `_COMMON_SET`
- `tests/test_adopt.py` — `GroomFlagsForeignCardsTests`

**Steps**

1. `asf/record/new.py:19`: `'belongs_to'` into `_COMMON_SET`, with the comment §3 gives — a suspicion
   is safe to set by hand, a closing is not, which is why `removed` and `moved_to` stay out (PD11).
2. `asf/groom/groom.py`: `_write_card_checked(rec, fields, hist)` beside `_write_card` (`:168-179`) —
   `setfield.set_typed(rec, fields, writer='groom')`, and on a reason returned, print
   `groom: <id>: <reason>` and change nothing; on success append the one History line the way
   `_write_card` does and mirror `fields` into `rec['meta']` (PD10). Returns True when it wrote.
3. `cmd_groom`: after `derived = compute_derived(canonical)` (`:1196`) and before
   `build_groom_sections`, §3's loop — skip entirely when `product is None` (PD6); for each
   `adopt.flagged(canonical, product)` entry whose card already carries that owner, write nothing; else
   `_write_card_checked(rec, {'belongs_to': match.name}, f"- {date} groom: looks like {match.name}'s
   work ({match.why}) — asf move")`. Then the reverse pass: every open card whose `belongs_to:` is set
   and which `flagged` no longer names gets `{'belongs_to': None}` (`write_typed`'s delete form, which
   round-trips through `set_typed` as `None == None`) and
   `- {date} groom: no longer looks like another product's work`. A card whose flag is unchanged is not
   opened, so a second groom in the same day writes nothing and `publish_changes` makes no commit (P3).
4. `groom_foreign_section(canonical, product)`: one line per suspected owner, owners in name order, ids
   in id order, at most ten named — §4's line, byte for byte:
   `- [ ] belongs_to:<name> <n> cards look like <name>'s work — <ids…> — <why> → answer: ____`.
   The `why` is the `Match.why` of the first card in id order. Built off the record's `belongs_to:`
   fields, not off `flagged`'s return, so the section says what the cards now carry. `[]` when
   `product is None`.
5. `GROOM_SECTIONS`: `("Cards that look like another product's", 'foreign')` immediately after
   `('Inbox cards to decide', 'inbox')` (`:839-855`). `_SECTION_BY_TITLE` is derived from that list
   (`:919`), so the section key needs no second registration. Call the builder in `cmd_groom` beside
   the other three `sections[...] =` lines (`:1209-1211`).

   whose token is not a card id alone (PD7), and `rows._split_lines` sends it to the judgement half
   because the token does not start `inbox:` (P13).
