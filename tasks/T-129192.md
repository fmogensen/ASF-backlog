**S-91855 — the bytes reach the card.**

```bash
python3 -m unittest -v tests.test_plan_tasks.CodeSpansSurviveTheMint
```

Asserts, on `PlanTasksTests`' record fixture, through the same `mint_plan_tasks` seam the F-0285
tests use:

* `declared_stories` on a declaration whose acceptance line is
  ``- [ ] a Feature at `PLAN`, `spec_on_main` in lane `lane-1` round 1`` returns that line
  character for character, equal to the source line with `- [ ] ` removed;
* a line whose content is *only* a code span (`` - [ ] `python3 -m unittest tests.test_x` ``) is
  returned, not dropped — P3's four recovered lines, as a case;
* a declaration title holding a code span is returned whole, and the minted card's `title:`
  frontmatter parses back to it (P6);
* the minted `S-…` card's `## Acceptance` block is the declaration's lines in order, each
  prefixed `- [ ] ` and otherwise unchanged;
* trailing whitespace is still trimmed and a `- [ ] ` line with no content is still no line, so
  the one normalisation `CHECKBOX` performs is unchanged;
* a declaration with no backtick anywhere mints exactly what it mints today — the regression
  guard that says this change is a strict widening.

**S-91856 — a fenced declaration still declares nothing.**

```bash
python3 -m unittest -v tests.test_plan_tasks.FencedDeclarationsAreStillSkipped \
                       tests.test_plan_tasks.DeclaredAndPhantomStories
```

`FencedDeclarationsAreStillSkipped` asserts:

* a `### S-…: <title>` heading inside a ```` ```markdown ```` block declares nothing:
  `declared_stories` omits the id, no card is minted for it, and the plan-tasks line counts only
  the real declarations;
* a `- [ ] …` line inside a fenced block under a real declaration is not an acceptance line of it
  (`docs/specs/f-0305.md:332`, as a case);
* a fenced `#` heading between a declaration and its acceptance lines does not end the Story's
  section: the lines after the fence are still the Story's;
* a plan citing only a fenced id is refused whole by `phantom_stories`, with the same line it
  prints today — the fenced example is a phantom, exactly as it is now;
* an unterminated fence leaves the declarations after it declared, as today (Out).

— plus the one case this plan adds, for `D2`'s narrowing (**PD5**): a code span *before* the hashes
(`` `x`### S-nnnn: t ``) is a declaration to today's reader, because the span collapses to a space,
and is no declaration to this one. It is the single id-set difference in either direction, measured
inert over this checkout's documents, and it is pinned so the next reader finds it stated.

`DeclaredAndPhantomStories` is F-0285's own class, unchanged and green: the declared Story is
still minted before the Tasks that cite it, a cited-but-undeclared Story still refuses the plan,
and a Story the *spec* declares is still minted with the plan.

**S-93305 — a card whose title holds a code span is not read as a reuse of its own id.**

```bash
python3 -m unittest -v tests.test_idclaim.VerifyOnLand
```

`VerifyOnLand` exists and is green today (P8); it is where `check_doc`'s redeclaration test is
already covered, by `test_a_heading_reusing_a_record_id_is_refused`
(`tests/test_idclaim.py:221-224`). The class gains cases and keeps every one it has:

* a record card whose `title:` holds a code span, re-declared by the heading that would mint it,
  produces **no** finding and the plan lands — the case that fails today (P11);
* a heading that genuinely reuses a taken id is still refused with the same line,
  `S-… already exists in the record (…)`, and `mint_plan_tasks` still mints nothing — this is
  `test_a_heading_reusing_a_record_id_is_refused`, unchanged;
* a card title with no code span is compared exactly as today, equal and unequal both;
* a card whose `title:` is absent prints the finding it prints today, unchanged — the shape
  `str(was or '')` protects;
* two titles that differ only *inside* a code span produce no finding, which is the cost D8 names
  and the Out table records, asserted so that the next reader finds it stated rather than
  discovers it.
