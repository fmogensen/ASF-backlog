**S-80304 — an open, workable S1 Bug freezes new Feature work for that product**

The gate itself (D-0001, D-0002, D-0004, D-0010) and its boundary: a Feature already in build finishes.

- [ ] A product with an open S1 Bug that a session is on and eight free seats launches no CARD → SPEC row for a Feature not in build
- [ ] Each held row reads action `WAITS ON S1 <id>: no new Feature work while an S1 Bug is open`, waits_on `S1`, and a reason naming the holding Bugs
- [ ] A held row launches nothing and takes no slot, so tiers.select never seats it and the remaining seats stay empty
- [ ] The BUG → FIX row of the holding S1 still launches during the freeze
- [ ] An EPIC → FEATURES row is held by the freeze, though build_cap does not hold it
- [ ] A correction the lane asked for is never held by the freeze
- [ ] A parked item row is never held by the freeze, so the park stays visible
- [ ] A Task of a Feature already in build still launches during the freeze, so no branch is stranded
- [ ] The first Task of a planned Feature none of whose Tasks has started is held by the freeze
- [ ] Resolving the holding S1 Bug releases every held row on the next plan, with no trace of the freeze

**S-80305 — `stability: true` declares the Feature work that runs during an S1 freeze**

The declaration and the exemption (D-0005, D-0006), and the `asf new`/`asf check` machinery it inherits.

- [ ] stability: true on a Feature card starts that Feature during a freeze while its unmarked neighbours stay held
- [ ] stability: true on the Epic above a Feature starts every Feature beneath that Epic during a freeze
- [ ] Exempt stability Features start in the existing tier-2 order of (epic rank, feature rank, id)
- [ ] stability: false on a card or on its Epic is not an exemption and the row stays held
- [ ] stability is settable on both feature and epic, parses true and false as a boolean, and asf new --set stability=yes is refused before the card is written

**S-80306 — an S1 nothing is working and no row launches freezes nothing**

F-0113's invariant (D-0003), and the two workable shapes that do freeze — without them D-0003 would be
indistinguishable from "never freeze".

- [ ] F-0113 five cases — a blocked, undecided, past-the-attempt-limit, parked or Active S1 holds no tier-2 row — still pass unchanged — proven by tests/test_s1_gate.py
- [ ] With seats free, a blocked S1 freezes no Feature row
- [ ] With seats free, an undecided S1 freezes no Feature row
- [ ] With seats free, an S1 past the attempt limit freezes no Feature row
- [ ] With seats free, an S1 parked for a person freezes no Feature row
- [ ] With seats free, an S1 flagged belongs_to another product freezes no Feature row
- [ ] An S1 at the attempt limit whose STALEMATE → ADJUDICATE row launches does freeze new Feature work
- [ ] An Active S1 whose branch, landing or merge is the work does freeze new Feature work

**S-80307 — the S1 gate reports the freeze it performs**

`Row.s1` and `gate()`'s count off the demand pass (D-0008) — the half without which the line reads
`None` while the gate holds every Feature in the product (P11).

- [ ] Row.s1 carries the holding Bug ids on every row the freeze held and is an empty tuple on every other row
- [ ] tiers.gate counts the frozen rows off the demand pass, not off the cut-versus-uncut diff that cannot see them
- [ ] gate_line reads `S1 gate: B-0001 holds 3 rows (CARD → SPEC 3)` when the freeze holds three card rows
- [ ] Two open freezing S1s read `B-0001, B-0002 hold 2 rows` in the same line
- [ ] No freezing S1 means gate and gate_line are both None
- [ ] asf next --json carries an s1 key on every row, empty on the rows the freeze did not hold
