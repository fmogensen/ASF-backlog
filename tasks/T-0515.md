## Description
stories: S-35950
writes: asf/conventions.py, tests/test_retention.py, tests/test_conventions.py
after: none

The spec's second **In** bullet and `## The design` §`asf/conventions.py`. One new
`branch_retention` key, its documentation, and the one-tuple that makes `0` mean "off" rather than
"malformed". Nothing reads the key yet — Task 3 does — so the only observable change in the tree is
that `conv.retention('settled_days')` answers `7`, that a malformed value is named as
`branch_retention.settled_days`, and that `per_tick: 0` still means off through a predicate that now
holds two keys instead of one. That is the point: the key lands provable first, and Task 3 cannot be
written without it.

**Files**

- `asf/conventions.py` — `ZERO_OK`; `DEFAULT_BRANCH_RETENTION` (`:278-279`); the `#:` block above it
  (`:271-277`); the module docstring's yaml sample (`:46-50`); the two `least =` expressions
  (`:613`, `:950`)
- `tests/test_retention.py` — `RetentionConventions`, three cases added
- `tests/test_conventions.py` — the `branch_retention` problem case, if one names the keys

**Steps**

1. `asf/conventions.py`, immediately above `DEFAULT_BRANCH_RETENTION` at `:278`: the constant with
   the spec's `#:` comment, byte for byte —
   `#: Keys whose 0 means "off", not "malformed".` then
   `ZERO_OK = ('per_tick', 'settled_days')`. It is a constant because the two `least` expressions
   below must read one list, not each carry a copy.
2. `DEFAULT_BRANCH_RETENTION` gains `'settled_days': 7`, in the spec's order:
   `{'archive_days': 14, 'legacy_prefixes': [], 'legacy_days': 7, 'per_tick': 50, 'settled_days': 7}`.
   Nothing else about the dict moves — `MAP_CONVENTIONS` (`:307`), the dataclass field (`:720`) and
   the `from_mapping` merge (`:780-782`) all iterate it generically and need no edit (PD12).
3. `_retention_problems` (`:613`) and `Conventions.retention` (`:950`): each `least = 0 if key ==
   'per_tick' else 1` becomes `least = 0 if key in ZERO_OK else 1`. Both lines, and nothing else in
   either function — `legacy_prefixes` keeps its own list arm, and the "is not a retention key"
   arm's message renders the new key automatically because it joins `DEFAULT_BRANCH_RETENTION`.
4. The `#:` block: **leave `:271` byte-identical** — `tests/test_security_paths.py:152` slices the
   source up to the substring `#: ``branch_retention:`` ` and the security block above it must not
   grow (PD13) — and append the spec's sentence **after** `:277`, the block's current last line,
   byte for byte:

   ```
   #: ``settled_days``: a head whose work is over — the trunk carries every commit on it, or the
   #: card its name names is done or removed in the record — goes this many days after its tip was
   #: committed, whatever prefix it wears. 0 turns that rule off.
   ```

5. The module docstring's yaml sample (`:46-50`), under `per_tick: 50`, one line in the sample's own
   comment style: `settled_days: 7           # a head whose work the record says is over (0 = off)`.
   No test reads this block (PD12); it is the only place outside the `#:` comment where an operator
   reads the block's shape, so it does not get to be four keys when the code has five.
6. `tests/test_retention.py`, `RetentionConventions` (`:200-231`): `test_defaults` gains
   `self.assertEqual(conv.retention('settled_days'), 7)`. Three cases added:
   - `test_settled_days_zero_is_off_not_malformed` — `{'branch_retention': {'settled_days': 0}}`
     gives `conv.retention('settled_days') == 0` and **no** `branch_retention.settled_days` entry in
     `dict(conventions.validate_mapping(data))`; and `{'per_tick': 0}` still does the same, so the
     predicate did not stop covering the key it already covered.
   - `test_a_bad_settled_days_is_named_and_reads_as_seven` — `-1`, `True` and `'soon'` each produce a
     `branch_retention.settled_days` problem whose text is `must be a whole number >= 0, not …`, and
     each reads back as `7`. `True` is the case the `isinstance(v, bool)` arm
