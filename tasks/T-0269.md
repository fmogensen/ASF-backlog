§2.5: the acceptance tick. A Story's `- [ ]` line proven by a passing row of a code review becomes
`- [x] … — <review path>`, with one `evidence:` line and one `## History` line. The round's verdict
needs no work here — it arrives through Task 4, and §3.6's Feature cases are the assertion that it
did. The tick reuses the pass, the parser and the ticker that F-0040 already built (PD7, PD8, PD9)
and adds the suffix and the text matching they lack (PD10).

**Files**

- `asf/proves.py` — `tick(body, line_no, note, suffix=None)`; the docstring naming the suffix
- `asf/tick/step_prs.py` — `acceptance` folded onto `proves.bullets`, its return shape kept (PD8)
- `asf/record/ingest.py` — `review_proven(canonical, task_ev)`; the Story branch of `derive` gaining
  the `acceptance n/m proven (<path>)` evidence line; `tick_proven` walking the review claims beside
  the landed ones
- `tests/test_ingest.py` — §3.6's Feature and Story cases
- `tests/test_backlog.py` — `asf check` green over a record after the tick

**Steps**

1. `proves.tick` gains `suffix=None`: when the bullet is newly flipped and `suffix` is given, append
   ` — {suffix}` to the line, the bullet's own text kept byte-identical (D8). A bullet already
   ticked returns `changed=False` and is left exactly as it is, suffix and all, so a re-run is a
   no-op. `note` keeps its position, so `tick_proven`'s present call is unaffected.
2. `step_prs.acceptance(root, relpath)` becomes a read of the file plus `proves.bullets(text)`,
   returning the same list of bullet texts it returns today — one parser, per PD8. `ACCEPT_RE` goes
   with it if nothing else reads it.
3. `ingest.review_proven(canonical, task_ev)` → `{story: [{line, test, task, path, source:
   'review'}]}`: for each Story, the Tasks whose `stories:` name it — the map `derive` already
   builds at `asf/record/ingest.py:615` — then each Task's `checks` from `task_ev`, then
   `{normalize(name): path}` over the passing rows. A Story's unticked acceptance line whose
   normalized text is a key yields a claim whose `line` is that bullet's 1-based ordinal (PD10) and
   whose `test` is the review path. Two Tasks proving one line: the first by Task id order wins
   (§2.5). A Task with `checks` `None` contributes nothing.
4. The Story branch of `derive` gains one evidence line when the Story has review-proven lines:
   `acceptance {n}/{m} proven ({path})`, `m` the bullet count off the card at `rec['path']`, `n` the
   proven ones, `path` the newest round's. No new machine key — `evidence` is already a list of
   derived lines (§4).
5. `tick_proven` walks the review claims beside `ev['proves']`'s: `proves.tick(body, claim['line'],
   None, suffix=claim['path'])` for a review claim, and one History line per Story that changed, in
   §2.5's shape — `- <stamp> ingest: acceptance {n}/{m} ticked ({path})`. The landed-claim History
   line keeps its own wording. The pass already re-reads each Story off `rec['path']` and writes it
   whole, so nothing in the write loop is touched (PD7).
6. `tests/test_ingest.py` per §3.6, end to end through `cmd_ingest` on a fixture record and a
   stubbed evidence dict. The Feature: a spec review whose table is complete and all `pass` →
   `stage: spec-approved`; the same table with one `fail` → `spec-review r1` and `spec.approved`
   false; the same table with a required row removed but a typed `verdict: APPROVED` → still
   `spec-review r1`, never approved. The Story: `S-19950` with three acceptance lines, listed by
   Task `T-19950` whose code review's `checks.passed` covers two — those two become
   `- [x] <text> — <path>`, the third is untouched, the Story gains
   `acceptance 2/3 proven (<path>)` in `evidence:` and one `## History` line. A second `ingest`
