The spec's `## The design` §3 — `check_clock_installs(cfg, product)`, one `required=True` row per
clock appended right after the existing `clock code` row, the R1–R4 rule in one place, and the two
`required=False` rows that are statements about the host rather than about an install. From here
`asf doctor` exits 1 while what ticks a product is editable, a bare checkout, unplaceable, an
unmerged sha, or a snapshot on a product that is not the factory's own source.

The existing `clock code` row is left **exactly** as it is (C4): it answers a different question
from a different source — `code/current`, what the last tick really ran — and this row answers
what the *next* tick will run. `scheduler.clock_code`, `doctor.check_clock_code` and the one test
method that pins them do not move (spec `## Out` (e), PD16/P13).

Read **PD3 first** — the repair phrase the spec prints in two of its four RED rows is a forbidden
token in `asf/doctor.py` and fails `tools/check_conventions.sh`, which the spec lists in its own §F
fence. Then **PD8(b)** (`tests/test_worker_isolation.py`'s `_doctor_rows` must patch the new check
or the one test whose point is that no probe leaves the process starts shelling git) and **PD9**
(the module docstring's rows are numbered in prose and the new one takes no ordinal).

2. `check_clock_installs(cfg, product)` → `[(required, ok, detail)]`, the spec's §3 docstring byte
   for byte. It calls `clockinstall.for_product(product.name, cfg)` once and
   `clockinstall.trunk(cfg)` once, then `clockinstall.against_trunk(inst.sha, repo, head)` per
   clock — the memo of Task 1 step 9 is what makes two clocks on one install cost one git pair.
3. The two rows that are **not** judgements come first and return early, `required=False` so they
   print `skip` (`format_table`, `:1063-1074`):

   `~/.ASF` and `~/Library/...` are the operator's own directories, explicitly allowed
   (`tools/check_conventions.sh:17`), so the second line's path is fine as written.
