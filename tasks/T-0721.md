## Description
stories: S-38351, S-38352
writes: asf/workers/worker_perms.py, tests/test_worker_perms.py
after: Task 1

The spec's §2, its first half. After this Task `worker_perms.allow_rules(product)` is the list a
worker session should be launched with — derived from `harvest.gate_commands`, never kept by hand,
so a lint appended to `ASF_GATE_SCRIPTS` is in it the day it is added. Nothing is composed, nothing
is written, nothing is launched from it yet: this Task ends at a tuple of strings.

The card's own two tests are here, and they are the ones that fail without the fix:
`test_every_lint_the_gate_runs_has_a_rule` and `test_a_lint_added_to_the_registry_is_allowed`.

Read **PD5** (no module-level `harvest` import) and **PD6** (nothing under `allow_rules` may raise)
before writing the import block, and **PD8** (one `shlex.join`, two readers) before `rule_for`.
Read **PD10** before writing a docstring: this module is scanned, and neither a `tools/` path nor
`.claude/` may appear in it.

**Files**

- `asf/workers/worker_perms.py` — new. The module docstring, then the spec's §2 surface in its own
  order, minus the four names that arrive in Tasks 4 and 5: `SELF_DIAGNOSIS`, `rule_for`,
  `gate_allow_rules`, `allow_rules`. Module-level imports: `shlex`, and `asf.approvals` (PD5).
- `tests/test_worker_perms.py` — new: `class GateDerivation` and `class SelfDiagnosis`, the spec's
  own two lists.

**Steps**

1. The module docstring first, the spec's §2 block byte for byte — it is the one place the card's
   *why* is written down for the next reader: a worker session has nobody to answer an approval
   prompt, so a Bash call with no allow rule is refused, lands in `permission_denials`, and is
   reported as a check "left out". Then the three notes §2 ends on, as they are: no `FIXED_ALLOW`,
   no `deny_rules`, no `tools/` or `.claude/` literal.
2. `SELF_DIAGNOSIS = ('Bash(printenv:*)', 'Bash(grep:*)')` with its `#:` block, the spec's two
   sentences. `env` is absent and the comment says why (C8). Two entries, each with its own
   sentence — the moment a third is wanted, it needs a card, which is §2's own third note.
3. `rule_for(argv)` — `f'Bash({shlex.join(argv)}:*)'`, and `None` for an empty argv. One shape per
   command, no exact-match twin: `console_perms` has used the `:*` form alone since B-0131 and it
   covers the bare command, and two shapes per command double the list the operator reads in
   `offer` for nothing (C5).
4. `gate_allow_rules(product)` — `from asf.harvest import harvest` as its **first line** (PD5),
   then `harvest.gate_commands(product.conventions, self_repo, None)` where `self_repo` is
   `harvest.is_asf_repo(product.repo_dir)` guarded per PD6. The returned `env` half is discarded
   here: an environment assignment is not a command and gets no rule. Then, per C4, a command is
   **dropped** when `approvals.full_suite_command(product, shlex.join(argv))` is truthy — the hook
   refuses it whatever the runtime allows, and two fences on one command read as one flaky fence.
   Then `approvals.pre_push_check(product)`, appended as `f'Bash({check}:*)'` when it is set —
   **not** through a `shlex` round trip (PD8) — and never refused by C4, because
   `_allowed_targeted` (`approvals.py:391-397`) makes `full_suite_command` return None for it (P12).
   Order: the gate's own, in the registry's order, then `pre_push_check`. Each rule once.
5. `allow_rules(product)` — `gate_allow_rules(product)` then `SELF_DIAGNOSIS`, deduped, order
   kept. A tuple. Dedupe by first occurrence, never by sorting: the order is what the operator
   reads in `offer`, and the gate's order is the order the gate runs in.
6. `GateDerivation`'s four cases and `SelfDiagnosis`'s one, the spec's list by name. Build the
   product with `env.Product` over a temp checkout; for the asf-repo cases, point `repo_dir` at
   this package's own root so `is_asf_repo` answers True by realpath and no subprocess runs.
   `test_a_lint_added_to_the_registry_is_allowed` patches
