§2.10 and §2.11 — the two rules that are not `PreToolUse`: the one that reports and never refuses,
and the one that refuses exactly once.

**Files**

- `rules/R-0006.md`, `rules/r0006.sh` — `title: a card written is a card checked`,
  `check: tools/checks/r0006.sh`, `hook: [PostToolUse]`.
- `rules/R-0007.md`, `rules/r0007.sh` — `title: a session ends with nothing uncommitted and
  nothing unpushed`, `check: tools/checks/r0007.sh`, `hook: [Stop]`. `merge` writes a `Stop` entry
  with no `matcher` key (`asf/hooks.py:267-268`), which is the shape the runtime wants.
- `asf/rules/hooks/r0006.py` — `Write`/`Edit`/`MultiEdit` only (PD6). When the touched `file_path`
  is inside `ctx.product.backlog_dir`, runs `asf check --product <p> <file_path>` and prints its
  error lines under one `R-0006 asf check <relpath>` heading, ending with the line `fix these
  before you commit — the record's pre-commit refuses them anyway.` **rc is always 0** (D9):
  `PostToolUse` fires after the write, and a refusal there cannot undo it, only confuse. The
  check runs with a 20 s timeout and prints nothing when it is clean; a timeout or a crash is one
  `rule-hook-error` row and a one-line note, never a wall of text. Because the rc is never 2, the
  module does not return refusal lines to `hookcall.run` — it prints its report and returns None,
  and the docstring says why that is not a hole.
- `asf/rules/hooks/r0007.py` — the `Stop` event, no tool input. Reads the session's worktree from
  the call's `cwd`, the branch from `git -C <cwd> rev-parse --abbrev-ref HEAD` under
  `hermetic.git_env()`, and the trunk from `ctx.product.conventions.main`, then calls
  `workers.health.push_gap(cwd, branch, main)` (D10, `asf/workers/health.py:257-274`) — B-0051's
  definition of "not finished" already lives there, and two definitions of finished is how B-0053
  happened. When it says not pushed, refuses the stop with the gap **and what is in it**: §2.11's
  text, the file list from `git status --porcelain` capped at 20 lines with `… and <n> more`, the
  commit count, and an `instead:` naming the three commands. The whole refusal goes through
  `redact.scrub(text, redact.default_patterns(repo))` before it is printed, so no account name and
  no machine path is fed back into a transcript. The refusal is **once per session**: the one-shot
  marker is a file at `<state>/<product>/hooks/stop/<ASF_SESSION>` (built from
  `env.state_dir(product)`, never a literal), and a second `Stop` with the same gap **allows** and
  records `rule-stop-repeat`. A `Stop` hook that refuses forever is an unkillable session, and the
  one thing worse than an unpushed branch is a session that cannot end.

**Steps**

1. `asf/rules/hooks/r0006.py`, then its card and shim. `RecordCheckTests`: a card with two real
   errors (rc 0, both lines printed under the `R-0006` prefix), a clean card (rc 0, no output), a
   file outside `backlog_dir` (no `asf check` run at all — assert the subprocess was never
   spawned), and a hanging check (the 20 s timeout enforced, one line printed, one
   `rule-hook-error` recorded). The hang case uses a stub `asf` on `PATH`, not a real 20 s wait.
2. `asf/rules/hooks/r0007.py`, then its card and shim. `StopRuleTests` over a git fixture
   worktree: the six cases T10 names — a dirty tree refusing with `push_gap`'s exact detail and
   the first `--porcelain` lines; an unpushed commit refusing with the commit count; a clean,
   pushed branch allowing; the 20-line cap with `… and <n> more`; a planted account name absent
   from the refusal; and a second `Stop` with the same gap **allowing** and recording
   `rule-stop-repeat`.
3. `asf doctor --product <p>` by hand: `rule-hooks` green for all seven scripts, and
   `asf hooks install --product <p>` in a fixture reporting seven (PD5).
