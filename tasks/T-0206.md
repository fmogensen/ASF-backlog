## Description
stories: S-18800
writes: asf/size.py, tests/test_size.py
after: none

§2.1. One pure module: three class names, five kind names, and the fixed four-step order that
makes a blocker beat a small count. No filesystem, no `Product`, no path literal of its own — it
takes plain lists and a resolved config, and everything downstream reads what it returns.

**Files**

- `asf/size.py` — **new**: the module docstring, `SMALL`/`MEDIUM`/`LARGE`, `CLASSES`, `KINDS`,
  the `SizeConfig` dataclass, `kind_of(writes, kind_globs)`, `countable(writes)` and
  `classify(writes, cfg)`, each with §2.1's docstring.
- `tests/test_size.py` — **new**: §3.1.

**Steps**

1. `SMALL, MEDIUM, LARGE = 'small', 'medium', 'large'`; `CLASSES = (SMALL, MEDIUM, LARGE)`;
   `KINDS = ('docs', 'test', 'config', 'copy', 'code')`, most specific first with `code` the
   fallback (D8). These names are what the card, the index, the feeder and the cutter all switch
   on, so the test asserts the tuples themselves.
2. `SizeConfig` — a frozen dataclass holding `small_max_files`, `small_max_files_by_kind`,
   `medium_max_files`, `kind_globs` and `never_small_globs`, with every field defaulted, so the
   module is usable with no product at all. It is defined here rather than in `conventions` so
   that `conventions` imports `size` and not the other way round; `Conventions.size_config()`
   (Task 2) builds one.
3. `countable(writes)` → `(n, None)` or `(None, why)`. No count for: an empty or absent footprint
   (`no writes: footprint`), any entry carrying `*`, `?` or `[` (`'asf/**' is a glob, not a file`,
   D1), or any entry with a `<repo>:` prefix (`'record:features/**' names another repository`,
   D6). Otherwise `n` is `len(writes)` — the number of `writes:` entries, which is D1's whole
   ruling, and never an expansion against a tree this module cannot see.
4. `kind_of(writes, kind_globs)` → the one kind of `KINDS` that **every** entry matches, else
   `'code'` (D8). Matching is `asf.feeder.footprint.globs_overlap` — the repository's one
   footprint-matching rule, borrowed rather than reimplemented, so `writes:` and `kind_paths:`
   are the same kind of glob. A footprint no glob matches is `'code'`; so is a footprint of nine
   documents and one module.
5. `classify(writes, cfg)` → `(class, kind, why)`, in §2.1's fixed order, and no other:
   1. an entry matching `cfg.never_small_globs` → at least `MEDIUM`, `why` naming that entry;
   2. `countable` with no count → `LARGE`, `why` the blocker;
   3. `n <= cfg.small_max_files_by_kind.get(kind, cfg.small_max_files)` → `SMALL`;
   4. `n <= cfg.medium_max_files` → `MEDIUM`; else `LARGE`.
   Step 1 raising the floor to `MEDIUM` rather than returning it outright is what lets a blocked
   sixteen-file footprint still be `LARGE`.
6. `why` is one sentence, always: `3 files ≤ 3 (code)`, `'db/migrate/001.sql' is never small`,
   `'asf/**' is a glob, not a file count`. It is what the card's history line, the coder's brief
   and `asf train status` all print, so it is written for a person and asserted as a substring,
   never as a whole string.
7. `tests/test_size.py` per §3.1, as a table of cases: three literal paths → `small`; sixteen →
   `large`; ten → `medium`; the boundaries at exactly 3 and exactly 15; a wildcard entry among two
   literals → never small (D1); `record:features/**` → `large`; an empty footprint → `large`;
   `never_small_paths` matching one entry of two → `medium` with the entry in `why`; a config
   whose `never_small_globs` carries an `amendable_paths` entry that is in no `never_small_paths`
   (D6 — the union is Task 2's, this asserts the classifier honours whatever it is handed);
   `kind_of` → `docs` for all documents, `code` for nine documents and one module (D8), `code` for
   a footprint no glob matches; fifteen documents → `small` under `small_max_files_by_kind` while
   fifteen modules → `medium` (D7); and `CLASSES`/`KINDS` holding exactly those names.
