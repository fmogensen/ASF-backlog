The spec's §6 and C14. After this Task `/asf:center` prints the table in the operator's console
and `/asf:mail` runs the answer loop, both generated from the CLI's own help with
`asf plugin build --check` green; every new console on a product drains its product's mail before
it does anything else, and treats what it finds as a question rather than an instruction; and
`asf doctor` says which products the center cannot see, which have never been looked at, which
have a question rotting and which name a `deliver` that is not there.

Nothing is regenerated by hand: `asf plugin build` writes the five files and `--check` is what CI
runs (P11). Nothing is invented for the skill descriptions either — `render_skill` takes them
straight off the subparsers Tasks 2 and 4 registered.

Read **PD5** before touching either registry (the ordering constraint, and why `mail` is not under
it), **PD4** (the registry entry is required; calling `head()` is not), **PD10** (the required
doctor row is about *sibling* products, and the `deliver` row must not run anything) and **PD12**
(no `.claude/` in the generated skill text; `CONSOLE_RULES` takes no apostrophe or quote).
