## Description
stories: S-37350, S-37351, S-37355, S-37356

after: Task 1

The spec's §2.1 and §2.3 in full, and nothing else. After this lands a product writes
`ci.pool: discover` and never names a runner again: the effective pool is what the host reports, each
box carries the tier its measured speed earns, a box registered a minute ago is in the pool and
raising the CI ceiling at the next tick, and a box that turned slow is moved off the fast tier with
one line saying which reading moved it.

This is the card's centre and the largest footprint in it. Everything downstream — the doctor's rows,
`capacity.batch`'s pair, the queue's two limits, the guide — reads the two files this Task writes.

**Read PD1 before writing the `product_ci` assertion.** §3.1 expects
`(5, 'ci.pool: asf-fast 1, asf-bulk 4')`; `slots_by_role` ends `dict(sorted(...))` so the reachable
string is `'ci.pool: asf-bulk 4, asf-fast 1'`, and O9 forbids reordering that function. The rest of
the sentence is right and is the half that matters. **Read PD4 before writing `apply_tiers`** — the
`Step` it builds by hand, and why its `current` must be the runner's whole label set. **Read PD5
before making the floor conditional on anything** — it is not, and `carried` comes off the census and
never off the host. **Read PD3** for why the census's doctor row is `census_rows` here and not a row
inside `doctor_rows`. **PD10** for the `spread_by` degradation that already works. **PD20** for the
two `register` lines.

Four things are load-bearing. **`load_pool` stays pure** (D1): it is on the `asf status` path
(`views/status.py:98`), in `asf capacity` (`views/capacity.py:51`), in product validation
(`env.py:676`), in `runner_ci_free` and in the queue — a `gh` round trip there puts a `gh` **failure**
behind a dozen read paths that cannot fail. The discovered branch is a **file read**, it never calls
the host, and it never raises. **An un-censused product has an empty pool, not an error** (D2):
`pool_ci` returns `(None, None)`, `drift` returns no rows, `runner_ci_free` returns `None`, and the
in-flight formula decides — the degradation is to today's no-pool behaviour, and one required doctor
row says the next tick will take a census. **The band is the difference between a placement and a
flap** (D6): a ratio between `PROMOTE_AT` and `DEMOTE_AT` keeps the tier the **census** already gave
the runner, and two `refresh` calls over a box sitting at 1.40 produce no move on the second. **The
tick reads no workflow file** (D9): `plan` needs `runs_on`, which is one contents listing plus one
raw read per workflow file; the narrow write needs none, cannot remove a label a job still needs
because it removes only the tier it replaces, and leaves the sweep to `asf ci reconcile`.

**Files**

- `asf/ci_census.py` — new, §2.1's fence as the module's shape. `CENSUS_FILE`, `PLACES_FILE`,
  `CENSUS_VERSION = 1`, `CENSUS_STALE_S = 60 * 60`, `FAST`/`BULK`/`TIERS`,
  `PROMOTE_AT, DEMOTE_AT = 1.25, 1.60`, each with the comment the spec gives it. `cached(product)` →
  `[PoolEntry]` sorted by name, `role` the tier, `provider`/`box`/`size`/`cls` empty (O2, O5),
  `slots` 1 on every entry — *a self-hosted runner takes one job at a time, which is what the host's
  single `busy` flag means* (P2); `[]` on no file, an unreadable file or a wrong `v` (D2), never
  raising, never calling the host. `taken_at(product)`. `tier_of(score, carried=None)` — §2.3's
  fence exactly: no score, no ratio or `n < MIN_READINGS` → `BULK` (D7); flaky → `BULK` (D15);
  `ratio <= PROMOTE_AT` → `FAST`; `ratio >= DEMOTE_AT` → `BULK`; between → `carried` else `BULK`
  (D6). `refresh(product, backend, root=None, now=None, out=print)` — §2.1's docstring, in §2.3's
  order: read the runners (P2), read 14 days of the `ci` stream with
  `read_stream(root, 'ci', days_back(today(), WINDOW_DAYS))` (P13), score them with
  `ci_measure.scores(ci_measure.readings(events))`, tier every **online*
