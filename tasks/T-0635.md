## Description
stories: S-37752

after: Task 4

The spec's `## The design` §4 and §3.3, and the `run_wait_min` half of §3's ladder. After this lands,
the two ways a CI gate cannot run are a line a person can act on and a doctor row that outlives the
tick that printed it, and no `gate/…` ref survives the factory that made it.

Two things are load-bearing. The gate **never falls back to the local suite** (D9): a silent fallback
would put a 15–25 minute suite back on this host at the moment the operator is least likely to be
looking, and would make the card's second acceptance clause untestable in principle — so
`NeedsOperator` patches `product_gate` to raise for the whole pass, exactly as `Cut` does. And a
`NEEDS OPERATOR` printed once is a `NEEDS OPERATOR` nobody sees: the cause goes in the state file and
comes back as a doctor row in `check_gate_speed`'s shape (P22) — one `try/except (OSError, ValueError)`
around one JSON read, one appended row under an `if`, silent while the gate is healthy or `local`.

Read **PD11 before naming the reader** — `needs_operator_line` is a taken name with a different
shape. **PD14 before writing the sweep** — the ref list already exists, and a rehearsal must not
delete.

**Files**

- `asf/ci_gate.py` — the `run_wait_min` bound and the `no-workflow` verdict inserted into `judge`'s
  ladder where §3 puts them (above `pending`); §4's two causes, each printed through `lane.out` and
  written to the state file as `{"needs_operator": {"why": …, "at": …}}`; `needs_operator_line(product)`
  reading it back (PD11); and `clean(lane, st)`, §3.3's sweep.
- `asf/doctor.py` — `check_ci_gate(product)` beside `check_gate_speed` (`:982-990`), and its two
  lines in the row builder beside `slow = check_gate_speed(product)` (`:886-888`). Nothing else.
- `tests/test_ci_gate.py` — `NeedsOperator` and `Sweep`.
- `tests/test_doctor.py` — the row is shown when the state file carries a cause, and there is **no**
  row while the gate is healthy or while `gate_where` is `local`.

**Steps**

1. **The two causes** — `gate_where: ci` with no `conventions.ci_workflow`: nothing is cut, every
   entry `WAITING_CI`, and §4's first line verbatim, which names both remedies (set the workflow, or
   set `harvest.gate_where: local`). A ref pushed with no run after `run_wait_min`: the ref is
   deleted, the members are `WAITING_CI`, and §4's second line verbatim — the next pass cuts again
   and says it again until a person acts, which is correct, because nothing is lost and nothing
   lands. Both write the cause to the state file with the moment.
2. **`needs_operator_line`** and **`doctor.check_ci_gate`** — the reader and the row, in
   `gate_slow_line`/`check_gate_speed`'s shape (P22), returning None when the file is absent,
   unreadable, or carries no cause. PD11: module-qualified at the call site, never imported bare.
3. **`clean`** — over `lane.remote_heads()` filtered by `ref_prefix` (PD14), deleting every ref the
   state file does not claim, through `lane.ref_push(':refs/heads/<ref>', …, lease=…, done=lambda:
   lane.ref_gone(ref))`, bounded by `ORPHANS_PER_PASS` with one line when the bound is hit. Called
   once per pass from `pass_for`, after the `lane.dry_run` guard.
4. **`NeedsOperator`** — both causes print a line beginning `NEEDS OPERATOR:`, nothing is cut and
   nothing lands in either, the local gate is **not** run as a fallback (`product_gate` patched to
   raise), and the cause is readable from the state file afterwards.
5. **`Sweep`** — a `gate/…` ref on origin the state file does not claim is deleted; a claimed one is
   not; the delete goes through `ref_push` with a lease; the count per pass is bounded; and a dry run
   deletes nothing.
6. **`tests/test_doctor.py`** — the row, and its two silences.
7. Run the Gate.

**Not in this Task** — everything Tasks 1–4 landed: the switch, the cut, the ladder's other
verdicts, `land`, the split, the timings
