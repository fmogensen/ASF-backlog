**Steps**

1. Create `asf/record/resolve.py` with the two names §2.5 gives it: `incoming(root, iid)` — every
   card carrying an edge onto `iid`, a scan of `card.refs` over the record — and
   `close(root, iid, how)`, returning the cards it would rewrite and the rewrite for each. The
   four cases are §2.5's table: a Done or Closed target is **satisfied in place** (the id stays and
   the card's `satisfied` array names the field, the id and the date); a retired target is the
   same with the history line saying which; a superseded target is **re-pointed** to
   `superseded_by` with the old id kept in `satisfied`; a deleted target is removed from the field
   with a history line naming what it pointed at.
2. `satisfied` is a declared property of Task 1's schema, which is what lets a resolved card pass
   the write gate — the schema is closed, so an undeclared `satisfied` would fail on
   `additionalProperties`.
3. The whole set lands in **one** `publish.commit_paths` call (D-0014, P13): one record commit, one
   pre-commit run, one push, carrying the derivation the rewrites imply. There is never a window in
   which the record points at a finished card — the state the measured 300 retired-target edges
   are stuck in. An operation that cannot write one of its cards writes **none** of them.
4. Three callers, and K2 names the modules that actually hold the writes: `asf/record/retire.py`'s
   `_retire_card` (`:76`, which writes through `setfield.set_typed`); the supersession path at
   `asf/groom/groom.py:379` and `:384`, two `_write_card` calls setting `superseded_by` on the
   loser and `supersedes` on the survivor — **not** `asf/groom/conflicts.py`, which is read-only;
   and `Apply.Satisfied` (`asf/kernel/apply.py:400-406`), which writes `kernel_state: done`.
5. The operation is idempotent: run twice it rewrites nothing the second time. A card whose
   incoming edge was satisfied is no longer held by that edge; one whose edge was re-pointed is
   held by the superseding card instead.
6. Create `tests/test_card_edge_resolve.py` for S-133161's seventeen lines, including the one that
   pins the seam: the retire command, the close path and the supersession path all go through the
   one operation — assert it by patching `resolve.close` and watching all three reach it.
