Independent of Tasks 1 and 2 — a different module, and a status line that says `no tick yet` until
Task 1 has ticked is correct, not broken.

**Files**

- `asf/hooks.py` — `STATUSLINE_REFRESH_S`, `statusline_settings_path`, `statusline_command`,
  `is_statusline_ours`, `merge_statusline`, `_read_settings` / `_write_settings` split out of
  `_write_merged`, and the block in `install()`.
- `tests/test_hooks_recognise.py` — `StatusLineSettingTests`.
- `tests/test_install.py` — the two expected summary strings in `HooksTest` (PD6).

**Steps**

1. Beside `RUNTIME_SETTINGS_GLOBS` (`:45`), add `statusline_settings_path(product)` →
   `os.path.join(product.repo_dir, '.claude', 'settings.local.json')`, or `None` when there is no
   `repo_dir`. **Every `.claude` literal this card adds lives in this module and nowhere else**
   (PD4) — Task 4 calls this function rather than rebuilding the path.
2. `STATUSLINE_REFRESH_S = 60` and `statusline_command(asf_path, product_name)` per §5.
3. `is_statusline_ours(command, product_name)` per §5's snippet, using `_SUFFIX` in `_is_ours`'s own
   shape and not `_ENTRY_TOKEN` (PD3).
4. Split `_write_merged` (`:350-360`) into `_read_settings(path)` — the `os.path.isfile` guard and
   the `json.load`, unchanged and **still raising on malformed JSON** — and `_write_settings(path,
   merged)` — the `makedirs` and the `json.dumps(…, indent=2) + '\n'`. `_write_merged` keeps its
   signature, its `if merged == current: return` short circuit and its behaviour exactly (P10,
   PD7).
5. `merge_statusline(settings, asf_path, product_name)` → `(settings, refusal)` per §5: asf's own
   entry is replaced, a foreign one is left untouched and named in the refusal, every other key is
   kept because the merge is `dict(settings, statusLine=…)` and nothing else.
6. In `install()`, after the rule-hook block and before the summary (`:390-394`), add §5's block —
   so the accounts' approvals hook and `ensure_git_hooks` are already on disk whatever this decides
   (P9, D8) — with PD7's guard: `_read_settings` is called inside
   `try/except (OSError, ValueError)`, and an unparseable file appends
   `NEEDS OPERATOR: <path> is not readable JSON — add the command: "<statusline_command(…)>"` to
   `refusals`, writes nothing, and sets the summary clause to
   `statusLine: NEEDS OPERATOR (below)`. The three good outcomes are §5's: written, already there,
   or `not written (no repo_dir)`.
7. Append the clause to the summary line, `; {statusline}`.
8. **PD6:** update the two expected strings in `tests/test_install.py`'s `HooksTest` — `:1238-1241`
   and `:1251-1252` — by appending `; statusLine in {self.repo}/.claude/settings.local.json` to
   each. Change nothing else in that class.
9. `StatusLineSettingTests`, with `SecondInstallChangesNothingTests`' `setUp` copied in (see *The
   fences*): `install()` writes `.claude/settings.local.json` with `type`, the `--product` command
   and `refreshInterval: 60`, and leaves any other key in that file untouched; the bytes of every
   file it wrote — **that file included** — are identical after a second and a third `install()`;
   an `asf` path that moved is replaced in place, still one entry; a foreign `statusLine` comes back
   byte-for-byte unchanged with rc 2, a `NEEDS OPERATOR` message carrying the exact command, **and
   the approvals hook and the git hooks still written**; an unparseable `settings.local.json` does
   the same and is left byte-for-byte alone (PD7); `is_statusline_ours` accepts bare,
   path-qualified, `asf-live` and `-m asf.cli`, and refuses `asfmt`, another product's `--product`
   and any trailing text.
