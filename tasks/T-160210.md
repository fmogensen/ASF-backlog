**Steps**

1. `actions`: a new `@dataclasses.dataclass Retarget` with `pr: int` and `base: str` (`''`: the
   trunk), and its `describe` line `retarget #<pr> -> <base or the trunk>`. Put it in `ORDER`
   between `A.ClosePR` and `A.CancelRun` — a GitHub write ahead of `A.OpenPR` and the merges, so a
   PR is on the trunk before anything tries to land it.
2. `ports`: declare `retarget(self, pr, base) -> None` on the GitHub protocol beside
   `archive_and_reset`, and implement it as a `self._write` of
   `pr edit <n> --base <base or product.main>`. `apply.Retarget` calls it, and `apply.targets`
   lists `A.Retarget` with the other PR actions so the stale-view guard covers it.
3. `decide.unstack(facts, config, judged, states, parked)` → `(actions, notes)`, called from
   `decide` once `states` exist. For each visible item with `it.stack`, read
   `(base, fork) = stack_of(it)` and take the predecessor from the item's `after:` ids:
   - predecessor **Done** (`landed(pred, its prs)` and its state is `State.DONE`):
     `A.Retarget(pr.number, '')` for the item's own open PR when `pr.base` is not already the trunk
     — a PR GitHub already holds there is skipped **on the facts**, never on an error, so two ticks
     plan at most one (`D9`) — and `A.NoteStack(iid, '', '')`. Note line
     `STACK RETARGET <item> #<pr> -> <trunk>`.
   - predecessor archived, reset, reverted or parked, **or** `base` on no branch in
     `facts.branches` while the predecessor is not Done (`D10`): `A.NoteStack(iid, '', '')` and
     `A.ArchiveAndReset` for the item's own open PR, reason `its base <base> was rebuilt`. Nothing
     is merged and the card waits on its edge again.
4. `spawn`: the replay. `make_worktree(..., base='', fork='')` passes `fork` to
   `_rebase_onto_base`, which, when `fork` is given and is **not** an ancestor of `origin/<main>`,
   runs `git rebase -q --onto origin/<main> <fork>` in place of the plain rebase — the Task's own
   commits only, never the predecessor's, which the trunk now holds as that merge (`D4`). A fork
   already an ancestor does nothing. A conflict is aborted and returns, as the existing arm does
   (`:944-946`), so nothing is left mid-rebase and the item falls to the existing conflict path; a
   replay that moved the branch is published by `lifecycle.publish` as every launch-time rebase is.
   `ports._spawn` and `pool.Row` carry `fork` off the card's stack the way `base` is carried.
5. Extend `tests/kernel/test_stacked_builds.py` with `class Unstack`: one case per acceptance line
   on `S-135959`'s card, all 17, in three groups — the retarget (one per landing, the key cleared
   the same tick, none for a PR already on the trunk, idempotent over two ticks, the retargeted PR
   landed by the ordinary path with no hold left, since Task 4's hold is keyed on `pr.base`); the
   replay, in a scratch repository with the predecessor's commits merged into the trunk (own commits
   only, an ancestor fork a no-op, a conflict aborted and left nowhere, the existing conflict path,
   a moved branch published); and step 3's four teardowns.
