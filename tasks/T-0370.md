## Description
stories: S-33102
writes: asf/probe/journey.py, tests/test_probe_journey.py
after: Task 1, Task 2

§2.3 and §2.4: the list ASF hands the workflow, the five-step sign-in journey that is always first
and always ASF's, and the reader that turns a broken report into a reported absence rather than a
silent pass. This Task ships no io and no host — it is pure over a `Probe`, a list of `Owed` and a
string.

**Files**

- `asf/probe/journey.py` — `Journey`, `Result`, `SIGN_IN`, `journeys`, `try_it_path`,
  `parse_results`
- `tests/test_probe_journey.py` — T3

**Steps**

1. `Journey`: frozen, `name`, `kind` (`sign-in` | `standing` | `try-it`), `path`, `item`, `pr`.
   `Result`: frozen, `name`, `kind`, `verdict`, `step`, `seconds`, `screenshot`, `origins`,
   `item`, `pr`, `detail`.
2. `journeys(probe, owed)`, in order: the sign-in journey, always and first (D6); one per name in
   `probe.journeys`, in configuration order; one per `Owed` whose `customer_visible` is true and
   whose try-it line yields a path, named `<item> #<pr>`.
3. `try_it_path(line)`: the first `https://<origin>/…` on the line whose origin is in
   `probe.origins`, else the first bare `/path` token, else `''`. An off-origin URL yields `''`
   — it is not the product's host to probe.
4. `parse_results(text)`, total over garbage: invalid JSON, a `schema` that is not `1`, a missing
   `journeys` key, a journey with no `verdict`, a non-`pass` verdict with an empty `step` — each
   becomes one `Result` with verdict `unrunnable` and a `step` naming what was wrong with the
   report (D3, b103).
5. **The sign-in dependency, enforced by ASF and not trusted to the engine** (D6, and T3's named
   contract case): when the sign-in `Result` is not `pass`, every later `Result` is forced to
   `unrunnable` with a step naming the sign-in failure — whatever the report claimed. A run that
   reports five green journeys taken while signed out is exactly the false pass this exists for.
6. The five sign-in step names of §2.4 are module constants — `sign-in: request code`,
   `sign-in: code mail`, `sign-in: submit code`, `signed in` — so the Bug of §2.10 and the guide
   name the same strings the parser does.
7. `tests/test_probe_journey.py`: T3's ordering assertions; `try_it_path` over
   `Try it: open https://<origin>/settings/theme`, `- **Try it:** /settings/theme`,
   `Try it: toggle dark mode` (→ `''`) and an off-origin URL (→ `''`); §2.3's document read into
   two `Result`s; the five garbage cases; and the forced-`unrunnable` contract case.
