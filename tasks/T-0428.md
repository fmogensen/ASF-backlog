## Description
stories: S-32651

after: none

The spec's third **In** bullet and the `reading back what asf writes` block: a suffixed basename and
the two module forms join the forms both recognisers accept, so a second `hooks install` from a
suffixed install changes nothing, appends no second settings entry (P6), and leaves the doctor's
`approvals-hook` row green (P7). `hook_entry` arrives here, beside the expression it reads.

**Files**

- `asf/hooks.py` — `is_git_hook_ours`, `hook_entry` (new), `_is_ours`
- `tests/test_hooks_recognise.py` — new module: the form table, `SecondInstallChangesNothingTests`,
  `ApprovalsMissingReadsEveryFormTests`
- `docs/guide/product-config.md` — the accepted-spellings sentence at `:632-634`

**Steps**

1. `is_git_hook_ours(text, name)` becomes three alternatives, each anchored on the left at a word
   boundary so a longer command name cannot match a shorter one:
   - an entry-point basename — bare, quoted or path-qualified, matching `ENTRY_NAME_RE`'s shape —
     followed by `redact --<name>`;
   - `-m asf.redact --<name>`;
   - `-m asf.cli redact --<name>` (PD9: new acceptance, and a command that really runs).
   The forms it must accept and reject are §The design's table, and it is the test table in step 5.
   `exec /opt/p/bin/asfmt redact-all --pre-push` stays `False`, which today's expression gets right
   by accident and the left anchor now gets right on purpose.
2. `hook_entry(text, name)` — new, beside it: the command the matched line names, unquoted. The
   entry-point path for the first form, the interpreter for the two module forms, `None` when no line
   matches. **`None` for a bare name** — a command with no `/` in it (PD5): `asf init`'s hooks resolve
   at hook-run time by design and are never candidates for repair.
3. `_is_ours(command, name, product)` widens the same way: an entry-point basename (bare or after a
   `/`) or `-m asf.cli hook`, then `hook <name>`, keeping the existing optional `--product <p>` tail
   and its `$` anchor. P7 makes the doctor's `approvals-hook` row correct by this edit alone.
4. `merge` and `approvals_missing` are not touched in this Task — only what `_is_ours` answers
   changes. `merge`'s unconditional replace (P6) is Task 3's.
5. `tests/test_hooks_recognise.py`, the form table as a parametrised list over both hook names: bare
   (`exec asf redact --pre-push`), quoted absolute, unquoted absolute, quoted suffixed
   (`exec "/opt/p/bin/asf-live" redact --pre-push --product p`), unquoted suffixed, and both module
   forms — all ours; and the near misses — `exec /opt/p/bin/asfmt redact-all --pre-push`, a line
   inside a string (`echo "asf redact --pre-push"`), a `#` comment, and the other hook's name — none
   of them. The same table asserts `hook_entry`'s answer for each row, `None` for the bare form and
   for every near miss.
6. The settings table beside it: `<dir>/asf hook approvals`, `<dir>/asf-live hook approvals`,
   `asf hook approvals`, `<python> -m asf.cli hook approvals`, each with and without the
   `--product <p>` tail, all ours; and `<dir>/asfmt hook approvals`, `asf hook approvals --product q`
   against product `p`, and a trailing-text case, none of them.
7. `SecondInstallChangesNothingTests`: a product over a temp `ASF_HOME` with a git repo, installed
   once with `which` answering `<bin>/asf-live`, every file's bytes captured, installed again the
   same way — the git hooks and both settings files are byte-identical and the `PreToolUse` group
   holds exactly one entry. Run a third time with the entry point resolved as a bare `asf-live` name,
   to pin that no spelling asf writes makes a second entry appear.
8. `ApprovalsMissingReadsEveryFormTests`: `approvals_missing` over an account whose settings hold
   each recognised command form in turn answers empty, and over one holding a near miss answers the
   account — the doctor's `approvals-hook` row through the seam P7
