**Files**: `asf/env.py`, `docs/products.example.yaml`, `asf/groom/policy.py` (new: gate only),
`asf/feeder/rows.py`, `asf/tick/step_wave.py`, `tests/test_env.py`, `tests/test_feeder.py`,
`tests/test_tick_steps.py`, `tests/test_groom_policy.py` (new: `GateTests`).

**Steps**
1. `env.PRODUCT_FIELDS['groom'] = _MAP`; `Product.groom` property beside `approvals`, `{}` when absent.
2. `docs/products.example.yaml`: `approvals.groom`, the `groom:` block and `branch_prefixes.groom`, exactly §2.1.
3. `asf/groom/policy.py`: `groom_auto`, `open_questions`, and threshold readers with the D11
   defaults (`duplicate_overlap` 0.95, `recurring_bug_count` 2, `adjudicate_attempts` 2) plus
   `policy_on(product, name)`.
4. `rows.py`: `GROOM_ADJUDICATE`, the four Row fields, `groom_row(index, product, busy, groom_state, inflight)` per §2.5
   (tier 2, `brief_kind='groom'`, item = `oldest`, branch `branch_for(product, 'groom', date, default='groom/')`).
   It emits nothing when the gate is off, `open` is empty, an inflight entry has `job == f'groom-{date}'`,
   or `attempts >= adjudicate_attempts`. Thread an optional `groom_state=None` through `candidates`/`plan_rows`.
   It sorts in tier 2 after every STALEMATE/CONFLICT/STALE row and before the first new-work row.
5. `step_wave.py`: `groom_state(product, root)` reads the newest `groom/<date>.md` via
   `open_questions`, and counts attempts as ledger lines with `job == groom-<date>`
   (`lifecycle.read_lines`). Also `KIND_JOB_KEY`/`job_name(..., key=None)` (PD9), and passes `groom_state` to `plan_rows` only under the gate.
6. Tests: `GateTests` (groom_auto true/false/unset/`human-now`; a gate-off `cmd_groom` writes the
   same file as before), `GroomRowTests` (T8, every case), the `test_env` validation cases (T12's
   config half), and a wave test for `job_name('groom', 'F-0001', key='2026-09-22') == 'groom-2026-09-22'`.
