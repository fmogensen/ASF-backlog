The spec's fourth **In** bullet and the `repair without downgrade` block: `entry_point_source` reads
editability off files (D8), `prefer_entry` answers the one question (D6, D7), and `ensure_git_hooks`
and `merge` both ask it. The repair edits the line, never the file (PD4), and never the bare form
(PD5).

**Files**

- `asf/hooks.py` — `entry_point_source`, `prefer_entry`, `repair_entry` (the line substitution),
  `ensure_git_hooks`'s third upgrade, `merge`'s gated replacement
- `tests/test_hooks_entry.py` — `EntryPointSourceTests`, `HookRepairTests`, `NeverDowngradesTests`
- `tests/test_install.py` — `test_a_moved_asf_replaces_its_own_entry` restated (PD6)
- `tests/test_check_staged.py` — the record pre-commit's third line asserted to survive a repair

**Steps**

1. `entry_point_source(path)` → `('editable', <checkout>)` | `('installed', <site-packages>)` |
   `None`. It reads `path`'s first line for `#!<interpreter>`, takes that interpreter's prefix, and
   globs `lib/python*/site-packages/asf_factory-*.dist-info/direct_url.json` and
   `lib/*/site-packages/…`. `dir_info.editable` true → `('editable', <url path>)`; a dist-info
   without it → `('installed', <dir>)`. `None` for an unreadable or absent dist-info, a `#!/bin/sh`
   wrapper, a line that is not a shebang, and an unreadable `path`. It executes nothing (the spec's
   **Out**) and raises nothing: every failure is `None`.
2. `prefer_entry(written, running)` → `True` when `running` should replace `written` (D7): a
   `written` that is `None`, missing or not an executable file loses to any usable `running`; an
   `editable` `written` loses to a non-editable `running`; an unknown source on either side, or an
   equal pair, keeps `written`. `False` when `running` itself is not usable. `written is None`
   through PD5's bare-name rule reaches this as "no candidate", and the caller skips before asking —
   both paths agree, and the test pins it.
3. `repair_entry(text, name, entry)` — PD4's substitution: the matched line with its entry-point
   token replaced by `entry`, quoted the way `_git_hook_body` quotes it, and **every other byte of
   the file unchanged**. `None` when no line matches or the token is already `entry`. Built over the
   same match `hook_entry` returns, so the two cannot disagree about which line is the hook's.
4. `ensure_git_hooks` gains a third upgrade beside `init_hook_upgrade` and `staged_check_upgrade`
   (P8), in that order and after both: when the hook is ours, `written = hook_entry(text, name)` is
   not `None`, and `prefer_entry(written, asf_path)` is true, the file is written with
   `repair_entry(...)` and the summary adds `repaired <path>: <written> → <asf_path>`. A bare form
   gives `hook_entry` `None` and is skipped (PD5). Nothing else about the function changes — a
   foreign hook is still refused and never edited, and the other repo's hooks are still written.
5. `merge` stops replacing unconditionally (P6): a matching entry is replaced only when
   `prefer_entry(<the command's entry point>, asf_path)` is true, and otherwise left exactly as it
   is — **still counting as found**, so no second entry is appended. The entry point of a settings
   command is taken from its first word, with PD5's rule applied the same way: a bare name is never
   replaced. `_write_merged` already returns before opening the file when the merge is a no-op
   (`asf/hooks.py:288-291`), so a run that keeps every command writes nothing at all.
6. `EntryPointSourceTests`: three fixture venvs — one whose `direct_url.json` has
   `dir_info.editable` true and a `file://` url, one whose dist-info has no `direct_url.json`, and
   one with no dist-info — each with a real `asf` script whose shebang names its interpreter, giving
   `('editable', <checkout>)`, `('installed', <site-packages>)` and `None`. Plus: a `#!/bin/sh`
