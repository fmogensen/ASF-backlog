§2.1, §2.2, §2.3 and §2.7. A role becomes a file with a two-key frontmatter and five sections in
order; a loader reads it with `asf.record.frontmatter` and a validator returns one problem string
per breach, nine of them; one table binds every brief kind to a role and one names the reason of
every role no kind binds. Ten files ship. Nothing outside `asf/roles/` reads any of it yet — the
package is complete and inert until Task 2 renders it.

**Files**

- `asf/roles/__init__.py` — **new**: the package, and the module docstring saying what a role is
  (identity, doctrine with the incident behind each rule, the output contract, the economy, the
  boundary) and what it is not (a model, a backend, an effort, a tool list — those are the
  operator's config and the phase's).
- `asf/roles/roles.py` — **new**: §2.2's `ROLES_DIR`, `roles_dir()` (PD10), `RoleError`, the
  `Role` dataclass, `load`, `load_all`, `validate`, `for_kind`, `block`; the nine refusal
  constants `SECTIONS`, `MAX_LINES = 60`, `DOCTRINE_MIN = 4`, `DOCTRINE_MAX = 8`, `INCIDENT`
  (PD6), `ECONOMY_MAX_LINES = 6`, `FORBIDDEN`; `BINDINGS` and `UNBOUND` exactly as §2.3 fences
  them. `block(role, cap)` is written here and first called by Task 2.
- `asf/roles/writer.md`, `reviewer.md`, `coder.md`, `fixer.md`, `diagnostician.md`,
  `harvester.md`, `interrogator.md`, `prober.md`, `security.md`, `documenter.md` — **new**, ten
  files, the purposes of §2.7's table verbatim in `purpose:`.
- `pyproject.toml:27-28` — `"asf.roles" = ["*.md"]` beside `"asf.briefs" = ["templates/*.md"]`.
- `tests/test_roles.py` — **new**: `ShapeTests`, `ValidateTests`, `NoModelTests`, `GenericTests`,
  `BindingTests`.

**Steps**

1. `asf/roles/roles.py`: `Role` per §2.2 — `name`, `purpose`, `sections` (an ordered dict,
   heading → the section's text in file order), `text` (the body below the frontmatter,
   verbatim), `sha` (`hashlib.sha256(text)` first 12 hex), `lines`. `load(name)` reads
   `roles_dir()/<name>.md`, parses with `asf.record.frontmatter.parse` (`asf/record/frontmatter.py:184`)
   and raises `RoleError` on a missing file. `load_all()` returns `{name: Role}` over every
   `*.md` in `roles_dir()`, sorted. `sha` is over the body only, so the path and the mtime never
   move it and an edit to `purpose:` does (the purpose is identity).
2. `validate(role)` returns a list of problem strings, the nine of §2.1's table in that order,
   each naming itself: frontmatter keys not exactly `{name, purpose}` (two refusals — missing,
   and unknown); a missing section, a section out of order, or a heading that is not one of
   `SECTIONS = ('Identity', 'Doctrine', 'Output', 'Economy', 'Boundaries')`; over `MAX_LINES`;
   doctrine bullets outside `DOCTRINE_MIN..DOCTRINE_MAX`; a doctrine bullet with no `INCIDENT`
   match; `## Economy` over `ECONOMY_MAX_LINES`; a `FORBIDDEN` word case-insensitively anywhere
   in the **raw file text**, frontmatter included (PD8); a `## Output` carrying a line matching
   `^REPORT$` or a fenced block containing `status:`. An empty list is a valid role.
   `FORBIDDEN = ('model', 'backend', 'effort', 'tools', build.HEAVY, build.LIGHT)` with the two
   label constants imported from `asf.briefs.build` inside the function, so the roles package
   does not import the briefs package at module load.
3. `BINDINGS` and `UNBOUND` byte for byte from §2.3. `for_kind(kind)` returns `BINDINGS[kind]` and
   raises `RoleError` on a kind the table does not know. `block(role, cap)` renders
   `## Who you are — <name>` and the body, truncating by whole sections, last section first, and
   appending `… (role <name> truncated at <n> lines)` when it cut — the `fit` discipline of
   `asf/briefs/preamble.py:337-349`, written here over sections rather than over `Section`
   objects, and first called by Task 2.
