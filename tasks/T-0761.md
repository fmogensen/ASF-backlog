The spec's fourth In bullet and `## The design` §4 in full: `live` drops a card on `removed:` *or*
`moved_to:`, `retired_done` keeps the retired-and-done ones aside on the same test, both behind one
local `retired(entry)` predicate, and a fence test pins that predicate against
`asf.record.core.is_retired`. Four lines of product code, four docstrings, six tests.

This is the load-bearing half and it lands first. **Read PD3 before starting**: on a `lane: direct`
Feature the retirement label Task 2 writes is not inert — it launches a build session — so the
window in which that label exists without this drop must never open. Read **PD10** (widen both
halves of the rule in one edit, or land a measured regression), **PD7** (this module's test file
imports no `board`, and nothing in the tree tests `board.render`) and **PD12** (an absent stage
launches two different sessions, not one).

Nothing in `asf/feeder/rows.py`, `asf/views/board.py` or `asf/record/` is touched. `rows.items_of`
(`:228-239`) already reads whatever `index_reader.live` decides and copies `retired_done` across
(`:239`), so widening the rule in one function widens it for the board, the roadmap, the README's
counts, the status table and the feeder at once — which is what C2 means by *retirement is one rule
or it is not a rule*.

**Steps**

1. `retired(entry)` in `asf/views/index_reader.py`, module level, directly above `live`, exactly as
   the spec's §4 writes it:

   ```python
   def retired(entry):
       """True for an index entry the record retires: ``removed:`` or ``moved_to:``.

       The same rule as :func:`asf.record.core.is_retired`, spelled again here because this module
       is stdlib-only by contract and imports nothing from ``asf.record``. The two are pinned equal
       by ``tests.test_views``' fence: a card that ``is_retired`` and a card this drops must always
       be the same card. Before F-0172 they were not — this tested ``removed:`` alone, so a *moved*
       Feature stayed in the live set and the board and the feeder both read the stale ladder word
       on it.
       """
       return bool(entry.get('removed') or entry.get('moved_to'))
   ```

   The duplication is deliberate and C6 is the ruling: P14 measured that no module under
   `asf/views/` imports `asf.record.*` and the header promises "stdlib only", so the import is not
   taken; step 6's fence is the price of the copy.
2. `live` routed through it, and **its local variable renamed** — today `live` binds a local named
   `retired` at `:35`, which would shadow the new function on the very next line:

   ```python
   def live(raw):
       """``raw`` (``{id: card}``, retired cards included) as an :class:`Items`: the cards not
       retired (:func:`retired` — ``removed:`` or ``moved_to:``), with the retired ones that are
       done kept aside in ``retired_done`` (and any ``raw`` already carries)."""
       out = Items((k, v) for k, v in raw.items() if isinstance(v, dict) and not retired(v))
       kept = dict(getattr(raw, 'retired_done', {}))
       kept.update((k, v) for k, v in raw.items()
                   if isinstance(v, dict) and retired(v) and v.get('state') in DONE_STATES)
       out.retired_done = kept
       return out
   ```
