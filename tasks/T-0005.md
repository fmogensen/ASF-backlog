## Description
stories: S-7302, S-7303

**Files**
- `asf/tick/step_wave.py` — `capacity()`, `run()`, docstring; `DEFAULT_CAPACITY` moves out
- `asf/feeder/render.py` — `_default_capacity` (PD2)
- `tests/test_tick_steps.py` — new class `WaveStep`

**Steps**
1. `step_wave.capacity(product=None)` returns `asf.capacity.resolve(product or
   env.load_product()).sessions` (PD3). Delete `DEFAULT_CAPACITY` here; if anything still imports
   it, re-export `asf.capacity.DEFAULT_SESSIONS` under the old name.
2. Rewrite step 3 of the module docstring: `capacity` is the resolver's ceiling (spec §2.2's
   session law), the feeder still takes this product's in-flight sessions off it itself (P5).
3. `run(ctx)`: resolve once per tick (`r = capacity_mod.resolve(product)`), pass `r.sessions` to
   `plan_rows`, and write **one** `ctx.event('capacity', …)` every tick — before the
   `wave: nothing to launch` early return, so it is written bound or not — with the fields of
   §4.3: `sessions`, `sessions_inflight` (`len(running)`), `sessions_bound_by`, `ci`,
   `ci_inflight`, `ci_bound_by` (`ctx.event` adds `kind`, `product`, `ts`). `ctx.counts` gains no
   key.
4. `asf/feeder/render.py`: `_default_capacity(product)` returns
   `asf.capacity.resolve(product).sessions`; the `--capacity` help text names the resolver chain
   instead of `feeder.capacity`. `--capacity n` still wins.
5. `tests/test_tick_steps.py`: new class `WaveStep(StepsTestCase)` with the three tests of spec
   §3.3 — the resolver is what the feeder is handed (patch `asf.capacity.resolve`); a
   `capacity.total.sessions` with another product's live ledger rows cuts the wave; the event line
   in `metrics/events/<day>.jsonl` carries `sessions_bound_by`. `WaveStepTests` is not touched.
