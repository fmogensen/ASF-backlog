**Steps**

1. `asf/workers/stops.py`, ~60 lines, §2.6's docstring as it stands.
   `stop_path()` is `os.path.join(env.ASF_HOME, 'state', 'credential-stops.json')` — one file for
   the machine, beside `headroom.limits_path()` (`asf/workers/headroom.py:150`), whose read /
   atomic-tmp-and-replace write shape it copies exactly. `record(account, var, path, job='',
   product='', why='')` replaces any earlier record for the same account. `active(now=None)` →
   `{account: rec}` for every stop whose file still does not read non-empty, dropping the ones
   that now do **as it reads** and saving the table back; a stop whose `path` is `''` is always
   active (PD16). `clear(account=None)` drops one or all. An unreadable or unwritable state dir
   loses the memory and raises nothing, as `Failures` does.
2. `asf/workers/pool.py`: `lane_label(cfg, name)` → `f'lane-{i}'` for the account's 1-based place
   in `worker_pool.accounts`, `'lane-?'` for a name the config does not hold. Its docstring says
   it is the only form an account may take in anything printed into the record (§2.6).
3. `Pool.from_config` (`:441`): `credential_stops=stops.active()` beside
   `limits=headroom_mod.active_limits()` (PD13), and the field on `__init__`.
4. `Pool.credential_stop(account)` → `(var, why)` or None, and `band` gains §2.6's first branch,
   before `self.limit(account)`: a credential outranks a window, because no reset will help. The
   reason string is §2.6's, with `lane_label(self.cfg, account.name)` in it.
5. `asf/workers/runtime.py`: `AuthEnvError.__init__(msg, clear='', var='', path='', scope='')`,
   and the one raise site (`:335`–`:338`) passes all four —
   `scope='product' if var in product_auth_env else 'account'` (PD8). The message string is
   unchanged, byte for byte.
6. `asf/workers/spawn.py`: `SpawnError.__init__(msg, clear='', cls=None, why='')` defaulting
   `cls, why` to `failure.classify(text=msg)` when the raiser names none — so every existing
   raise site (a busy worktree, an external checkout, a dirty tree, a failed `worktree_setup`, a
   git failure at `:68`) is classified by its own text with no edit. `WorktreeBusy` and
   `WorktreeExternal` keep their present handling in `settle`: waits, not failures, and counted
   as neither.
