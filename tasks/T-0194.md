§2.1 whole, and the grammar of §2.2. One new top-level module and its test module — pure functions
over text, with `git` injected as a callable where a branch must be read (D11). Every later Task
imports it, so it lands alone and first. It touches nothing that exists: two new files, no
caller wired yet, and the suite is green the moment the module parses.

**Files**

- `asf/proves.py` — new. `CLAIM_RE`, `Claim`, `parse`, `bullets`, `card_bullets`, `validate`,
  `claims_on_branch`, `tick`, `render`, with §2.1's docstrings copied and a module docstring
  naming F-0040 and the four callers to come.
- `tests/test_proves.py` — new. `ParseTests`, `BulletsTests`, `ValidateTests`, `TickTests`,
  `BranchTests`, covering every case §3.1 lists.

**Steps**

1. `CLAIM_RE` as §2.1 fences it, with `\d{4,}` in place of `\d{4}` and its comment reading *"any
   prefix, four digits or more"* — **P3**, and the one correction this plan makes to the spec. The
   rest of the pattern is byte for byte: the `^[ \t>*-]*` lead that lets a claim be found under a
   `## Proves` bullet or a quoted body, `re.M | re.I`, and the three dashes of D12 with surrounding
   space optional.
2. `Claim`, a frozen dataclass: `story` upper-cased, `line` an `int`, `test` as written, `raw` the
   line as found for the refusal text.
3. `parse(text)` — every claim in first-seen order, duplicates collapsed on `(story, line, test)`.
   A line that says `Proves` but names no id, no number or no test yields nothing and raises
   nothing.
4. `bullets(body)` — the `## Acceptance` bullets of a card body, in order, counting checkbox
   bullets only (**P7**): `- [ ]`, `- [x]`, `- [X]`, leading whitespace tolerated, the checkbox
   stripped from the returned text. A section between two acceptance sections is not counted, and a
   body with no `## Acceptance` heading yields `[]`.
5. `card_bullets(root, item)` — `bullets` of `root/<folder>/<id>.md`, the `folder`/`id` pair
   `step_prs.card_relpath` uses (`asf/tick/step_prs.py:125-126`); `[]` for an unreadable or absent
   path, never an exception.
6. `validate(claims, task, items, root, tree=None)` → `(good, problems)`, the five problem kinds of
   §2.1 in the order found, each a one-line string naming `claim.raw` and what is wrong: `no
   claim`, `unknown story` (not in `items`, or its `type` is not `story`), `not this Task's`, `no
   such line`, `no such test` (only when `tree` is given; the path before `::` is what is looked
   up). A Task passes when `problems` is empty and `good` is non-empty — one malformed claim beside
   one good one is a rejection (D3).
7. `claims_on_branch(git, trunk, branch)` — exactly one call through the injected callable,
   `['log', '--format=%B', f'origin/{trunk}..origin/{branch}']`, its output parsed. No
   `subprocess` and no `os` in this function (D11).
8. `tick(body, line_no, note)` → `(new_body, changed)`. Flip the `line_no`-th acceptance bullet
   from `- [ ]` to `- [x]` and leave every other character of the body alone — the same leading
   whitespace, the same text, the same trailing newline. `changed` is False when the bullet does
   not exist or is already `- [x]`. `note` is the caller's History text and this function does not
   write it (D7).
9. `render(claims)` — the `## Proves` block's bullets, one per claim, the text the trailer had.
10. Tests, in the repo's `tests/` idiom (temp dirs, no network, no `~/.ASF`): the trailer parsed
