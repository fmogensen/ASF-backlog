§2.6's first half. Without this key the comparison the card's second acceptance names cannot be
computed from the record at all: the record carries the account as an index and nothing else
(`account_index`, B-0023), and which lane ran a session is nowhere on the line.

One schema key, one helper, one line in `session_event`. The discipline is D7's and it is the same
as D5's: a line written before this card does not know its lane and must not claim one, so the
default is `null` and every reader says `unknown` for it rather than `local`.

**Files**

- `asf/metrics/metrics.py` — `SCHEMAS['sessions']` gains `'lane'`; `record_lane`; `session_event`
  fills it
- `tests/test_quota_pressure.py` — `LaneTests`
- `tests/test_cloud.py` — a cloud-lane record's session event carries `lane: 'cloud'`

**Steps**

1. `asf/metrics/metrics.py`: `'lane': (('str', 'null'), None)` in `SCHEMAS['sessions']`, with a
   one-line comment naming the three values it takes — `local`, the cloud lane's own name, or a
   hosted runtime's own lane — and why the default is `null` rather than `'local'` (D7).
2. `record_lane(record)` with §2.6's docstring and body copied as they stand:
   `record.get('runtime_lane') or record.get('lane')`, and `str(got) if isinstance(got, str) and got
   else 'local'`. The `isinstance` is the whole point and the docstring says so: a non-cloud run's
   `lane` key is the **harvest** lane state machine's own map (`asf.workers.lifecycle.lane_of`
   returns `{}` for anything that is not a dict, `asf/workers/lifecycle.py:413-420`), so a dict
   there reads as `local`, and only the bare string an old cloud launch wrote is honoured.
   `pool.is_cloud_lane` (`asf/workers/pool.py:206-212`) stays the reader for the pool's own
   question; this is the record's.
3. `session_event` (`:1498-1534`): `'lane': record_lane(record)` in the `ev` dict beside the others
   it fills. One line, no branch — a record with neither key reads `'local'`, which is the honest
   answer for a launch this pool made, and only a line written before this card reads `None`,
   because it was never through `session_event` at all.
4. Nothing else writes a `sessions` line that needs the key: `asf/metrics/import_sessions.py` builds
   its events without it and `validate` fills `None` (P5), which is the right reading for a pre-asf
   runner's log. Do not touch that adapter.
5. `tests/test_quota_pressure.py`, `LaneTests`: `record_lane` over four records — `runtime_lane:
   'cloud'` → `'cloud'`; the bare `lane: 'cloud'` an old launch wrote → `'cloud'`; `lane` carrying
   the harvest lane state machine's **map** → `'local'`, and assert the returned value is a string
   and not the map; neither key → `'local'`. A fifth: `runtime_lane` carrying some third runtime's
   own name → that name, unchanged and unvalidated, which is what D7 bought by making it a free
   `str`. Then `session_event` over a record end to end, and
   `metrics.validate('sessions', {…}, {})` with no `lane` key → `None`.
6. `tests/test_cloud.py`: one case where a cloud-launched record's session event carries
   `lane: 'cloud'`, in the class that already builds cloud records. This is the join between the
   cloud runtime's marker and the stream, and it is the one assertion that would catch the marker
   being renamed.
