## Description
stories: S-16204, S-16205, S-16206
writes: asf/workers/stall.py, asf/workers/spawn.py, asf/harvest/pr_hygiene.py, tests/test_workers.py, tests/test_pr_hygiene.py, tests/test_session_identity.py
after: Task 1

Rows 2 and 3 of §2.4, and §2.5's launch record. The cold retry stops inheriting the dead run's
model id and resolves the original kind's need; the `CONFLICT → REBASE` line stops printing a
vendor name by hand; and both launch paths write `model_label` beside the runtime `model`, which is
what Task 5's metric reads.

**Files**

- `asf/workers/stall.py` — `correct_once` (`:101-141`): the `Job`'s model becomes
  `spawn.model_arg(build.model_for(product, session.get('kind')), _cfg())`, and the retry ledger
  line (`:129-136`) gains `model_label`. `_cfg()` (`:154`) is already the config reader it needs
  and `product` is already an argument — no new parameter.
- `asf/workers/spawn.py` — `record` gains `'model_label': row.model` (`:306-307`); `model_arg`'s
  docstring stops naming a vendor (`:252`, P8).
- `asf/harvest/pr_hygiene.py` — `render(row, conv=None, product=None)` (`:212-218`) prints
  `model_for(product, 'rebase')` in place of the literal; the module docstring's two vendor names
  (`:6`, `:9`) go with it.
- `tests/test_workers.py` — `ColdRetryModelTests` (new) and `LaunchRecordTests` (new).
- `tests/test_pr_hygiene.py` — `:62`'s expected line, and the no-vendor-name assertion of P8.
- `tests/test_session_identity.py` — the launch record's new key.

**Steps**

1. `correct_once` resolves fresh. The retry keeps the kind of the session it retries (§1.2 — a
   dead spec session's retry writes the spec), so the need is that kind's:
   `label = build.model_for(product, session.get('kind'))`, and the `Job`'s model is
   `spawn_mod.model_arg(label, _cfg())`. The recorded id on the dead session is never read. An
   unmapped label raises `SpawnError` with its existing `NEEDS OPERATOR` text — the same refusal
   the wave already gives, one tick earlier than a dead runtime would.
2. The retry's ledger line carries `'model': <the resolved id>` and `'model_label': label` — the
   same two keys `spawn.spawn` writes, so one reader serves both paths.
3. `spawn.spawn`'s `record` gains `'model_label': row.model` — `row.model` is the label it was
   handed, `job.model` the id it resolved. One line.
4. `model_arg`'s docstring example becomes `worker_pool.models: {heavy: <id>}` (P8). No behaviour.
5. `pr_hygiene.render(row, conv=None, product=None)`: the `REBASE` arm prints
   `f'… → launch rebase-{slug} ({model_for(product, "rebase")})'`. With no product it prints the
   default label, `light` — `model_for` already resolves against `Conventions()` through
   `preamble.conventions(None)`. The two docstring lines lose the vendor name and say "a light
   session merges the trunk into the branch" instead. `conv` keeps its place and meaning; callers
   that pass only `conv` are unchanged.
6. `ColdRetryModelTests`: a registry whose dead `spec` session records a bogus model id; the retry
   launches with the id `worker_pool.models['heavy']` maps and its ledger line reads
   `model_label: heavy`, and both differ from the bogus id; the same for a dead `coder` session
   and `light`; and a product whose `models: {spec: light}` moves the spec retry to `light` —
   which is what "resolved fresh" buys.
7. `LaunchRecordTests`: `spawn.spawn` writes `model_label` equal to the row's label and `model`
   equal to the id `model_arg` returned, and the two are different strings.
8. `tests/test_pr_hygiene.py`: the expected line becomes `… → launch rebase-<slug> (light)`, and a
   case asserts the rendered line matches no vendor-model pattern
   (`re.search(r'(?i)\b(sonnet|opus|haiku|claude-[\w.-]+)\b', line)` is None) — the honest
   enforcement of §1.2 (P8).
