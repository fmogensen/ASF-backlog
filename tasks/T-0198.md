## Description
stories: S-18754
writes: asf/evidence/evidence.py, tests/test_evidence.py
after: Task 1

§2.6. One new key on `discover()`, holding only claims that have **landed** — a claim is not
evidence until it is on the trunk. Both sources are already fetched or one cheap call away, and the
second is what makes the tick work for a product that lands by fast-forward and has no pull
requests at all: this one.

**Files**

- `asf/evidence/evidence.py` — `landed_proves(product, prs, ...)` beside `id_evidence`
  (`evidence.py:723`), and the `"proves"` key on `discover`'s returned dict; `import` of
  `asf.proves`.
- `tests/test_evidence.py` — `LandedProvesTests`.

**Steps**

1. `landed_proves` gathers from the two sources of §2.6, keyed by Story id, each entry
   `{line, test, task, pr, sha, source}`:
   - **merged pull requests.** `pr_list` already asks `gh` for `body`
     (`evidence.py:191-194`), so no new round-trip: a PR whose `state` is `MERGED`, whose
     `mergeCommit.oid` is set and whose oid `ancestry(product, [f"origin/{product.main}"])`
     (`evidence.py:900`) says is on the trunk contributes its body's claims, with `source: "pr"`,
     `pr` its number and `sha` the merge oid. `task` is the Task id among the PR's `id_tokens`
     (`evidence.py:683`).
   - **trailers on the trunk.** One `git log --format=%H%x1e%B --grep=^Proves: origin/<main>`,
     bounded by the same `--since=record_since(product)` window `main_commits` uses
     (`evidence.py:726-737`), with `source: "commit"`, `pr: null` and `sha` the commit. `task` is
     the id token in the commit's subject, which `commits_name_item`
     (`asf/harvest/harvest.py:669`) guarantees every landed lane commit has.
2. Duplicates across the two sources collapse on `(story, line, test)`, the pull-request source
   kept where both name the same claim — it carries the `pr` number, and the commit source carries
   no more than the same sha.
3. The entries of each Story sort by `(line, task)` so the evidence file is stable between passes
   and a diff of it means something.
4. `discover` gains `"proves": landed_proves(...)`, built from the `prs` list it already has in
   hand (`evidence.py:402`). A product with no pull-request host yields the commit-sourced claims
   alone; a `gh` that fails yields `[]` for that source and the other still lands, as every other
   input of `discover` already behaves.
5. Nothing about `id_tokens`, `ID_TOKEN` or `record_since` changes. Task ids in this record are four
   digits and `ID_TOKEN` reads them; the five-digit Story ids are read by `proves.CLAIM_RE`, which
   is Task 1's business and P3's.
6. `LandedProvesTests`: `discover()['proves']` keyed by Story id, from a merged pull request's body
   and from a `Proves:` trailer on a trunk commit; an **open** pull request's claim absent; a merged
   pull request whose merge commit is not an ancestor of the trunk absent; the `task` field taken
   from the id token in the commit subject; the same claim from both sources appearing once, with
   its `pr`; and a product with no pull-request host yielding the commit-sourced claims alone.
