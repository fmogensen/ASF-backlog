§2.9, and the card's "so `asf backlog` can sort by it". The board reads `cost.over_budget` off the
index entries it already loads and imports nothing of this Feature's — which is why it needs
nothing landed and goes in the first wave. Until Task 2 lands, no card carries the key and the
cell simply shows what it shows today.

**Files**

- `asf/views/board.py` — `render(root, product=None, sort=None)`, the Cost cell, the group sort,
  and `cmd_backlog` passing the flag (`:41-92`).
- `asf/cli.py` — one `--sort` argument on `p_backlog_view` (`:299-300`).
- `tests/test_views.py` — `BoardBudgetTests` (T9).
- `tests/test_cli.py` — only if the parser's surface is asserted there.

**Steps**

1. The Cost cell keeps `ix.money(ix.usd(ix.subtree(items, f)))` and appends the subtree's
   over-budget items: `· over: T-0021` for one id, `· over: 2` for more, nothing when there are
   none — read off each subtree item's `cost.over_budget`, which is the only new fact the view
   touches.
2. `render(root, product=None, sort=None)`; `sort='budget'` orders each Epic's group by
   over-budget items first, then subtree spend, both descending, in place of `(ix.rank, id)`;
   `sort='rank'` and `sort=None` are today's order, and the table they render must be
   byte-identical to today's.
3. `cmd_backlog` passes `getattr(args, 'sort', None)`; `p_backlog_view.add_argument('--sort',
   choices=('rank', 'budget'), default='rank')` in `asf/cli.py`.
4. `tests/test_views.BoardBudgetTests`: `· over: T-0021` in the Cost cell of the Feature whose
   subtree holds it, `· over: 2` for two, nothing in a Feature with none; `--sort budget` putting
   the Feature with over-budget items first within its Epic and then by spend; `--sort rank`
   byte-identical to today's table.
