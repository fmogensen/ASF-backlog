## Description
stories: S-37362
writes: asf/scorecard/score.py, asf/views/scorecard.py, tests/test_scorecard.py
after: none

The spec's §2.4's third part — the scorecard — and nothing else. After this lands the card's fourth
acceptance is *measurable*: the scorecard shows queue wait per Feature beside CI minutes per Feature,
and the value loop's weekly snapshot carries both, so *"queue wait and CI minutes per Feature fall"*
is a series somebody can read rather than a claim.

P10 is why this is a clean, independent Task: `grep -rn "queue_wait\|queue_min" asf` finds nothing
today — re-run in this worktree and it still finds nothing. The series starts at zero and nothing
has to be migrated. And it needs **no** other Task to land: `_num(r.get('queue_s'))` is 0 on an event
recorded without one, which is every event until Task 2 lands and then every event older than it. *A
stored weekly row from before this change reads `queue_min` as 0, so no historical row breaks and the
series simply starts.*

**Read PD12 before editing either table.** Each table is four lines, not one: a header, a
pipe-counted separator, a row f-string, and — in the Features table — a hand-counted filler,
`'| (none landed in these weeks) | | | | | | | | | | | | | |'` (`views/scorecard.py:97-98`). §3.7's
*"the golden text of a row with no queue figure still renders"* is that filler and nothing else. And
`score.py`'s `cell()` default dict (`:147-149`) is a fifth place: a `queue_min` missing from it makes
`per_item`'s new `+=` a `KeyError` on the first `ci` event.

One thing is load-bearing. **`ci_min` does not change** (D4, P10): `per_item` also folds
`facts.gates`' seconds into `ci_min` (`:162-165`), and nothing about that moves. The new figure is
accumulated beside it, from `queue_s` only, and `queue_s` has no gate equivalent — a gate reading is
not a queued CI run.

**Files**

- `asf/scorecard/score.py` — five edits. `cell()`'s default dict (`:147-149`) gains
  `'queue_min': 0.0` (PD12). `per_item`'s `facts.ci` loop (`:158-161`) gains §2.4's second line,
  byte for byte: `cell(i)['queue_min'] += _num(r.get('queue_s')) / 60 / len(ids)`. `feature_rows`
  carries `queue_min`; `window_row` its sum over the window's `ci` events, beside the `ci_min` sum at
  `:217-218`; `by_lane` a `queue_min_per_feature`; `PAIR_METRICS` it immediately after `ci_min`; and
  `TOTAL_SUMS` it as a summable. `per_item`'s docstring gains it. The `facts.gates` loop is
  untouched.
- `asf/views/scorecard.py` — eight edits, four per table (PD12). The weekly table (`:61-70`): header,
  separator, row. The Features table (`:87-98`): header, separator, row, **and the filler**. The
  column is headed `queue min` and formatted like `ci min` — `{…:,.0f}`.
- `tests/test_scorecard.py` — two new classes. `QueueMinutes`: `score.per_item` over a `ci` event
  with `queue_s: 300` and two `items` gives each card `queue_min == 2.5`; an event with no `queue_s`
  adds 0 (P10's default); `feature_rows` carries `queue_min`, `window_row` its sum, `by_lane` a
  `queue_min_per_feature`, `total_row` sums it; and a stored weekly row written **before** this
  change reads `queue_min` 0 with every other figure unchanged. `ScorecardColumns`:
  `views/scorecard.render` prints the `queue min` column in both tables; the golden text of a row
  with no queue figure still renders; and — the PD12 assertion — **every emitted line of both tables
  has the same cell count as its header**, the filler included.

**Steps**

1. **`cell()`'s default first.** One key, and it is what stops the `KeyError` PD12 names.
2. **`per_item`'s line**, §2.4's fence byte for byte. Then the four carriers: `feature_rows`,
   `window_row`, `by_lane`, and the two lists (`PAIR_METRICS` after `ci_min`, `TOTAL_SUMS` as a
   summable).
3. **The two tables, four lines each.** Count the pipes on every separator and on the filler. Then
   write the cell-count assertion (PD12) and let it find what the counting missed.
4. **The two test classes.** Neither subclasses another
