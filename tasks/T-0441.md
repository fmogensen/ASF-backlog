## Description
stories: S-32903
writes: asf/views/status.py, tests/test_views.py
after: Task 2

The spec's `asf/views/status.py` block, D10 and D15: the three feeder cells stop making three
independent plans and take one, a fourth cell prints the gate and disappears when nothing holds, and
the three existing cells print what they printed before.

**Files**

- `asf/views/status.py` — `_plan`, `s1_gate_cell`, and `ready_cell`, `build_cell`, `decisions_cell`
  taking the `Plan`
- `tests/test_views.py` — `StatusViewTests` gains the `S1 gate` row's two answers and the one-plan
  assertion; `DecisionsCellTests` follows the cell's new argument

**Steps**

1. `_plan(root, product)`: `step_wave.plan_now(product, root=step_wave.reader_root(product) or root)`
   — the record clone when the product has one, else its `backlog_dir`, else the table's own root
   (PD7). `None` when that root is falsy or holds no `index.json`, which is the condition the three
   cells test today, and `None` when the plan raises — one unreadable plan never loses the table, the
   rule `render`'s own `try` already keeps.
2. `render` makes the plan once, directly after the header rows, and hands it to the four cells that
   need it (D15). Every other cell keeps its current arguments; `root` still goes to `stale_cell`,
   `value_cell`, `ab_pairs_cell`, `release_cell`, `record_cell` and `groom_cell`, which are about the
   operator's checkout and are not feeder plans.
3. `ready_cell(plan)`, `build_cell(plan)` and `decisions_cell(plan)` keep their output to the
   character and keep `not_configured('backlog_dir (no index.json)')` for a `None` plan. `ready_cell`
   counts `plan.rows`; `build_cell` calls `build_load` with `plan.items`, `plan.capacity`,
   `plan.inflight` and `plan.inputs`' fields; `decisions_cell` takes `plan.inflight` and
   `plan.inputs['occupancy']` and keeps `undecided_rows(..., limit=0)` and its ranking. Their
   numbers move only where PD8 and PD9 say they move, and the suite's products have no cloud lane.
4. `s1_gate_cell(plan)` with the spec's docstring: `None` when `plan` is `None`, when `plan.gate` is
   `None`, or when `gate_line` returns `None` — a row that only speaks up when something is wrong,
   the `Stale` row's own pattern (P11). Otherwise `gate_line`'s string with its `S1 gate: ` head
   stripped (the row's own name says it), then one sentence per entry of `plan.gate.unworked`:
   `B-0061 S1, nothing working it (blocked by B-0041)`. No `skip` here — the status table has no
   `raise_holds` pass to duplicate (PD13).
5. The row is added to `render`'s list as `('S1 gate', lambda: s1_gate_cell(plan))`, between
   `Ready to launch` and `Decisions`, so the gate sits beside the count it explains. The existing
   `Gate` row — the product's own CI gate — keeps its name and its place (P11).
6. `StatusViewTests`: a record whose plan has an unseated S1 with tier-2 rows behind it renders an
   `| S1 gate | … |` row carrying the card's counts and kinds and a sentence per unworked S1; the
   default record renders **no** `S1 gate` row at all, and the table's other rows are unchanged
   line for line against what the class asserts today; `Ready to launch`, `Features in build` and
   `Decisions` print what they print today for the class's own product, which has no `backlog_dir`
   (PD7) — the case that would go `not configured` if the fallback were dropped. One case asserts
   the plan is made **once** per `render`: `step_wave.plan_now` patched to count its calls answers
   `1` for a render whose four feeder rows are all filled (D15).
7. `DecisionsCellTests` is updated to the cell's new argument and keeps every expectation it has.
