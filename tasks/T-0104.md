§2.7: a hole becomes visible the day it opens. `asf status` counts the items no rule sees;
`asf check` names each one, what is missing, and the spec section to read.

**Files**

- `asf/views/status.py` — `record_cell(root)` (new, P15) and its row in `render`'s table
  (`:202-221`), reading `index.json` through `asf.views.index_reader`.
- `asf/record/check.py` — the residue finding, one per item whose evidence carries
  `rule: no-rule`; the `landed:` sha shape check (P16).
- `tests/test_views.py` — beside `StatusViewTests` (`:85`) and `StatusRow` (`:190`).
- `tests/test_backlog.py` — beside `CheckCommandTests` (`:278`).

**Steps**

1. `record_cell(root)`: `<n> open · <n> Active · <n> blocked · <n> no rule`, counted from
   `index.json`'s items — `open` is a state that is not `Closed` and no `removed:`, `blocked` is
   the machine `blocked`, and `no rule` is an `evidence:` list whose last entry is `rule: no-rule`
   (the machine block reaches the index whole, P15). No index, or none readable → the
   `not_configured` cell the other rows use, so one missing file never loses the table.
2. The `Record` row in `render`'s tuple, above `Ready to launch` — the record's counts before the
   feeder's, which is the order an operator reads them in.
3. `asf check`: one finding per residue item, in the file's existing `(relpath, line, message)`
   shape —
   `no closing rule sees this item (type story, no Task, no matrix row, parent F-0021 is Active) — it can never close; see docs/specs/f-0080.md §2.1`
   — with the parenthetical built from the item's own type and what its evidence lines do not
   carry. A record with no residue produces no finding.
4. `landed:` shape: a typed value that is not 7–40 hex characters is a finding on its own line
   (P16). Presence on the trunk is not asked here and is named in the finding's text as what
   `ingest` decides.
