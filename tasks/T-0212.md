## Description
stories: S-18806
writes: asf/tick/step_train.py, asf/train.py, asf/cli.py, tests/test_tick_steps.py, tests/test_cli.py
after: Task 6

§2.6's second pass and the second half of §2.9. The train pays, once, for every Task on it: one
pull request for a product with a merge queue, or one `land_set` for one that fast-forwards. Both
paths are the code that already runs every gate — no second implementation (§1.2).

**Files**

- `asf/tick/step_train.py` — the cut pass replacing Task 6's stub.
- `asf/train.py` — the `cut` subcommand on the `train` parser (PD13).
- `asf/cli.py` — nothing beyond Task 4's registration; the subcommand hangs off it.
- `tests/test_tick_steps.py` — the cut cases of §3.5.
- `tests/test_cli.py` — `asf train cut --dry-run`.

**Steps**

1. A train is cut when `train.due(row, now, cfg)` says so — six Tasks, or a `first_commit` older
   than `max_age_s`, whichever comes first (D9). At tick resolution the real rule is "at the first
   tick after two hours", which is what the test asserts rather than a wall clock.
2. The registry row moves to `cut` before anything is called, so a step that dies between the two
   leaves a train nothing will append to rather than one that is cut twice.
3. `landing: pull-request` — `gh pr create -R <slug> --base <main> --head <train branch>`, titled
   `train <lane> — <n> Tasks`, its body one row per Task: id, title and card link. Every Task id
   appears in that body, which is what makes `asf/record/match.py` rule 1 attribute the run's
   minutes to all of them (§2.10) — so the body is not decoration, it is the measurement's input.
   That one pull request is the one CI run.
4. The CI class line is conditional (PD4): `asf/ci.py` is not in this tree, so the body carries
   F-0038's class for the union of the Tasks' footprints when the module imports and omits the
   line when it does not. One `try/except ImportError`, and a test for each branch.
5. `landing: fast-forward` — `harvest.land_set(repo, state_dir, [(train_branch, synthetic
   record)], conv, gate_conv, asf_repo, dry_run, out, items, touched)` with a single entry. Green:
   the push lands, every Task's session is marked `harvested: <sha>` and its `harvest: train` mark
   is cleared, so the next harvest closes each worker branch through `already_on_trunk` (D14,
   B-0057). Red: the registry row keeps its verdict for Task 8's pass.
6. `asf train cut [--product P] [--lane L] [--dry-run]`: without `--lane` it cuts every due train,
   which is exactly this pass; with `--lane` it cuts that lane's open train even when it is not
   due — the operator's escape hatch before a release. `--dry-run` prints what it would do and
   calls neither `gh` nor `land_set`.
7. `TrainStepTests` per §3.5's cut cases: the sixth append cutting the train — the registry row
   `cut`, `gh pr create` called once with the train branch and a body naming all six Tasks (the
   `gh` call stubbed, its argv asserted); a train whose first commit is two hours old cut at three
   Tasks; a fast-forward product's cut calling `land_set` once with one entry and, on green,
   clearing every mark and setting every `harvested`; and the body carrying no class line with
   `asf.ci` absent (PD4).
8. `tests/test_cli.py`: `asf train cut --dry-run` printing the due trains and calling nothing.
