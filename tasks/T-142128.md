**Steps**

1. In `launch`, immediately after the `gated_plan` call at `asf/tick/step_wave.py:1317`, add the
   single `invariants.flow_report(product, items, inputs, running, out=out)` call and the comment
   §2.3 writes, so every `INVARIANT` line of a wave prints together.
2. It is called **once per wave**, outside `gated_plan`'s replan loop (`REPLANS = 8`) — the
   feeder's own `feeder_gate` runs up to eight times inside it and `feeder_waits` swallows its
   lines (`out=lambda _l: None`, `:558`), which is half of why this is a fourth scope and not a
   feeder-scope check (§1.3 C3).
3. It reads the wave's own overlaid `items` (`index_reader.load` plus `overlay_blockers` plus
   `plan_order.overlay`, `:1301-1305`) and its `running`, the same facts `gated_plan` planned
   from — not a freshly loaded index — so the law and the plan cannot disagree about what was
   true this tick.
4. Over `candidates`, never `planned`: the capacity cut *removes* rows, so judging the cut plan
   would call every seat-starved row a sink (§1.2 P10, §1.3 C5).
5. Extend `tests/test_flow_conservation.py` with `TheWaveCallsIt`: drive `launch` through the
   existing wave harness with `invariants.flow_report` replaced by a recorder. Assert it is called
   exactly once per wave, with the wave's own item map and inflight sessions; that its output
   reaches the wave's `out` after the feeder's own `INVARIANT` lines; that a wave with a sink
   present still launches every row it would have launched without one; and that a check point
   which raises leaves the wave's launches and its remaining lines unchanged.
