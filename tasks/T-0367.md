**Steps**

1. `asf/security/doctor.py`: `doctor_findings(product)` → the five findings §2.10 names — a product
   with a `repo_slug` and no `security.paths` (nothing is read); a record with no rule card for a
   core check basename (P15/D14 — the check is not on the clock, named per basename); an alert feed
   older than `alerts.max_age_h`; a probe older than `ports.max_age_h`, absent, or missing a
   configured box; a box with no address. Clean, one green line with the counts:
   `6 class(es) · 14 box(es) · alerts 2h · probe 9h`. It reads the cache and `ports.latest` and
   makes no call of its own beyond them; a box's address is never printed (D11).
2. `asf/security/__init__.py` gains `from asf.security.doctor import doctor_findings` (PD9),
   placed so the package still imports with no optional dependency and no cycle.
3. `asf/doctor.py`, beside the `customer content` row: `from asf import security` and
   `for ok, detail in security.doctor_findings(product): rows.append(('security', False, ok,
   detail))` — the shape the row above it has (`:867-869`), not required, so a product that
   configures nothing is not red for having no security block it never asked for; the *repo and no
   paths* case is the one that goes red.
4. `docs/products.example.yaml`: §2.1's block byte for byte, with its comments — the six example
   class names (D3: this file is where every product-shaped default lives), `alerts.max_age_h`,
   and the `ports` block with `boxes`, `workflow`, `artifact`, `max_age_h` and the commented
   `ports:` line naming `DEFAULT_PROBE_PORTS`.
5. `docs/guide/security-checks.md`: the block key by key; the three cards and what each files
   (§4's signature table); the probe's workflow job of §2.9 to paste, and `gh secret set
   ASF_PORT_TARGETS` as the operator's one-time hold-and-approve step (D11, `touch_security`); the
   one-line `tools/checks/` shims and the three adoption cards a product's record needs (§4), with
   the doctor row named as the thing that stays red until they exist. No address, no account name,
   no machine path in the page; a lane is `lane-N`.
6. `docs/README.md` gains the page in the guide list, beside the CI runner pool's line (PD15).
7. `SecurityRowTests` per §3's T10: for this product as it stands (a repo, no `security.paths`, no
   `ci.pool`) the row is red and names the missing block; with the block set and no adoption card
   in the record it names the three basenames; with a stale feed, a stale probe and a box with no
   address it names each; with everything in place it is green and prints the counts. One
   assertion that no detail string contains a fixture address.
