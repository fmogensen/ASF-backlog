The spec's `## The design` §2 in full: `observe.liveness_for`, `identity_alive` re-expressed on top
of it, and `health.alive_for` supplying `is_ours`, `silent_min` and `silent_for`. **This is the Task
that pays.** After it lands, a worker whose `ps` line carried no readable env is judged again next
pass instead of being ended — and no cold retry is started in the worktree it is still writing
(P7) — while a worker that answers but has written nothing for longer than the product's
`silent_min` is ended exactly as today.

The wiring and the bound are one commit by construction, not by convenience: see **PD1**. Read
**PD2** (the two-call shape, and why the first call carries neither measurement), **PD3** (the cloud
branch stays first), **PD4** (`product` is None on three shipped call sites) and **PD5**
(`_observe`, so Task 3 costs no second `ps`) before starting.

Neither `asf/workers/stall.py` nor `asf/tick/step_health.py` is edited, and neither gains a
state-word literal — that is the point of fixing this at the callable (P6): `judge` reaches it
through `gather`, `stall.classify` calls it directly, and one line closes both.

**Files**

- `asf/workers/observe.py` — new `liveness_for(observed, runs, exists=None, is_ours=None,
  silent_min=None, silent_for=None)`; `identity_alive` re-expressed on top of it, keeping its
  signature, its docstring's D11 rule, its cloud-first line and its "a pid no run recorded" branch.
  `lifecycle` is already imported here.
- `asf/workers/health.py` — new private `_measurements(product, runs)` and `_observe(product, runs,
  session_source)`; `alive_for` rewritten on the latter with its own signature, callers and `why`
  fallback unchanged.
- `tests/test_workers.py` — new `class LivenessForTests(unittest.TestCase)` and
  `class LivenessSilenceBoundTests(unittest.TestCase)`, both plain `TestCase`s.

**Steps**

1. `observe.liveness_for` returns a `verdict(pid)` closure over `by_pid = {o.pid: o for o in
   observed}` and `run_by_pid` built the way `identity_alive` builds it today (first run wins for a
   repeated pid). `exists` defaults to `lifecycle.pid_alive`. Memoise `exists` per pid in the
   closure (PD2).
2. `verdict(pid)` is the two-call shape of **PD2**:
   `v = lifecycle.liveness(run, o, exists_memo)`; then `if v == lifecycle.UNKNOWN:` re-call with
   `is_ours=is_ours(pid) if is_ours else None`, `silent_min=silent_min`, and
   `silent_for=silent_for(pid) if silent_for else None`. The first call carries **neither**
   measurement — passing `silent_min` there would record a recycled pid as `gone` instead of
   `reused`.
3. `identity_alive(observed, runs, **kw)` keeps `if cloudpid.is_token(pid): return
   cloudpid.alive(pid)` as its **first** line (PD3), then `if pid not in run_pids: return pid in
   by_pid` unchanged, then `return verdict(pid) in lifecycle.LIVE_VERDICTS`. Build the `verdict`
   callable once, outside `alive`, not per call.
4. `health._measurements(product, runs)` returns the three-key dict:
   `is_ours=lambda pid: is_print_worker(command_line(pid))`;
   `silent_min=stall_mod.silent_minutes(product) if product is not None else
   stall_mod.DEFAULT_SILENT_MIN` (PD4);
   `silent_for=lambda pid: <minutes since the log's mtime for the run recorded at pid>`, built off a
   `{pid: log}` map from `runs`, returning `None` for a pid with no log or an unreadable mtime —
   `None` means "not measured", and `liveness` then answers `UNKNOWN` rather than `GONE` (Task 1,
   step 3's last row). Check `asf/workers/health.py`'s existing imports: `stall` is imported lazily
   in places here, so import it the way the module already does rather than adding a top-level
   import that could close a cycle.
5. `health._observe(product, runs, session_source)` does the `spawn_mod.load_cfg()` +
   `observe.read(...)` once and returns `(observed, why, _measurements(product, runs))`.
