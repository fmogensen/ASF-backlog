§2.1 whole. The stream becomes typed, keyed and single-product, `asf/metrics/log.py` is born owning
the vocabulary and the one append, and both hands that write `metrics/events` today start going
through it. Nothing about *what* is emitted changes here — that is Task 2 — so this Task's diff is
readable as one question: is an events line now a validated event like the other five.

**Files**

- `asf/metrics/metrics.py`:
  - `STREAMS` gains `'events'`; `SCHEMAS` gains §2.1's entry byte for byte **except** `item`,
    whose default is `None` and not `MATCH` (PD5).
  - `PRODUCT = object()`, a fourth sentinel beside `REQ`, `MATCH` and `TS`, and — the trap —
    `_apply`'s `elif default in (MATCH, TS)` becomes `elif default in (MATCH, TS, PRODUCT)`
    (`:179`, PD4). `validate` gains `product=None` and fills a `PRODUCT` field from it, leaving
    `None` when none was passed. `PRODUCT` is the default for `product` on `ci`, `sessions`,
    `ticks` (whose nullable `None` it replaces at `:139`), `landings` and `gates` too, so every
    event line of every stream carries its product.
  - The second trap: `validate`'s bare `else:` at `:263` becomes `elif stream == 'ticks':`
    (PD4). Add nothing to the `('ci', 'sessions', 'landings')` tuple at `:273`; the events
    branch does its own id check — `ID_RE` first, membership in `items` only then (PD5).
  - `natural_key` gains `if stream == 'events': return (ev['kind'], ev['key'])`, **above** the
    `(ev['tick'],)` fall-through, so `ticks` keeps its branch and `events` stops landing in it.
  - `append_event`'s existing single read of the day file (`:340`) also collects the distinct
    string `product` values; one that differs from `ev['product']` raises §2.1's `SchemaError`
    verbatim, with the path relative to `root`. A line whose `product` is `None` — every line
    written before this Feature — is ignored by the guard.
  - `intake_latency_rows` reads its three payload keys through one `_payload(ev, key)` helper —
    `fields` first, top level second (PD7) — at `:492`, `:495` and nowhere else.
- `asf/metrics/log.py` — **new**, first half only (the renderer is Task 4):
  - `KINDS` as §2.1 gives it, **plus `'groom_answer'` and `'intake'`** (PD6).
  - `emit(root, product, kind, key, *, tick=None, item=None, job=None, account=None, branch=None,
    text=None, items=None, **fields)`: builds the head, puts the rest under `fields`, calls
    `metrics.validate('events', ev, items, product=product)` then
    `metrics.append_event(root, 'events', ev)`, returns the stored event. A `SchemaError` is
    printed and returns `None` — an event that cannot be written never aborts the step that
    raised it. `text` is collapsed to single spaces and capped at 200 characters **here**, at the
    write, so the renderer never has to (§2.4 rule 4).
  - `TICK_KEYED = ('stall', 'refusal')` and a `keyed(kind, tick, key)` helper that prefixes the
    tick for those two (PD8). Task 2's call sites use it; it lives here because the rule belongs
    to the vocabulary, not to a step.
  - The module docstring states the head, the `fields` bag, the `(kind, key)` key and the two
    tick-keyed kinds, and names no path outside the record (PD25: `check_conventions.sh` scans
    this file).
- `asf/tick/tick.py` — `Context.event(kind, **fields)` becomes a call into `log.emit` with the
  tick's product, `self.record_root()` and the tick's `HHMM` as `tick`, and appends the stored
  event to a new `self.events = []`. `Context.counts` **stays** in this Task (Task 2 deletes it):
  one Task, one question. `key` defaults to the caller's `key=` when given, else to `kind` — a
  temporary that Task 2 replaces at every site, noted in a comment naming Task 2's subject rather
  than an id.
