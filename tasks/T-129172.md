Design §5, all five edits. It shares no path with Tasks 1 and 2 and is on nobody's `after:`: a
replan brief that names the Feature's Stories with their acceptance lines is right whether or not
the row that launches it has been fixed yet, so this runs in wave 1 beside Task 1 (**PD1**,
**PD11**). The claim it has to keep is D-0006's: every other brief kind stays byte-identical, and
**PD5** is why the fixture record is not edited to prove it.

  beside `proves_lines` (`:383-410`); `collect` gains the `'story_acceptance'` key beside its
  `'stories'` (`:516`, **not** the `:510` the spec cites — **PD3**); the preamble's Stories line

**Steps**

1. `STORY_KINDS` gains `'replan'`. Add `STORY_ACCEPTANCE_KINDS = ('replan',)` under it with one
   comment line: the kinds that get the fuller block, and why only this one — a spec session writes
   the Stories and a plan session reads the spec document, which carries the acceptance text; a
   replan session has neither (D-0006).
2. `feature_story_lines(product, items, feature)` beside `proves_lines`, in its shape and with the
   spec's docstring: `root = getattr(product, 'backlog_dir', None)`, then for each
   `ix.children(items, feature, 'story')` — the same reader `stories_of` uses (`:374-380`), so the
   two keys never disagree about which Stories the Feature has — render
   `f"{sid} {title}: "` as the lead, `' ' * (len(sid) + 1)` as the continuation pad, and
   `asf.proves.card_bullets(root, story_item)` numbered 1-based, starting over at each Story, `;`
   after every bullet but the last of its Story. Join with `'\n'` and return a string, as
   `proves_lines` does. **The one difference from `proves_lines` is D-0007**: where it `continue`s past a
   Story with no readable bullets, this one emits `f"{sid} {title}: (acceptance not readable)"`.
   Say so in the docstring, and say why: a Story silently missing from a replan brief is the failure
   this card reports, and nothing refuses it later.
3. `collect`: add `'story_acceptance': feature_story_lines(product, items, feature)` beside
   `'stories'` (`:516`). `product`, `items` and `feature` are all in scope there. The key renders
   for every brief and is `''` when the Feature holds no Story — it is a facts key, not a template
   placeholder, so `build.context` needs no change and `PlaceholderTest` (`tests/test_briefs.py:981`)
   stays green by construction.
4. The preamble line (`:652-653`): keep the outer `if facts['stories'] and kind in STORY_KINDS:`
   so a Feature with no Story still emits nothing, and split inside it exactly as §5 writes it —
   `Stories of the Feature, with their acceptance lines:` plus
   `facts['story_acceptance'].splitlines()` for a kind in `STORY_ACCEPTANCE_KINDS` that has the
   text, else the existing one-line form unchanged. The `else` branch must be the shipped f-string
   character for character; that is what keeps the six other goldens byte-identical.
5. `replan_context`'s task line: add `stories = ', '.join(t.get('stories') or ()) or 'none'` and
