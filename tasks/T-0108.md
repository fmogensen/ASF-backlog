§2.5. The mechanism is F-0031's and does not change; what changes is that the set is now non-empty
by default, so the gate finally fires, and that the held line says which proposal card answers the
branch — or does not, which is the operator looking at an amendment nobody proposed.

**Files**

- `asf/harvest/harvest.py` — the held line at `:1237-1239`'s block gains the trailing
  `— proposed in <id>` clause from `propose.open_proposal(record_root, matched_file)` when there is
  one. Nothing else in the gate moves: `merge_class` already reads the set through Task 1, and
  `is_granted` already releases one branch.
- `tests/test_amendable.py` — `MergeTests` (§3.5).
- `tests/test_harvest.py` — the held line's new clause where the existing gate cases assert on it.

**Steps**

1. `open_proposal` imported from `asf.propose` at the call site, read once per held branch.
2. The line becomes `held <branch>: merge_amendable_set (human-now) — <path> — proposed in <id>`,
   and keeps today's form exactly when no open item carries `source: amend:<path>`.
3. `MergeTests` over the git fixture, per §3.5: a branch touching `rules/R-0042.md` with
   `amendable_paths` **unset** is held as `merge_amendable_set (human-now)` — the default set is
   what catches it, which is the whole point of Task 1 — and the held line names the open proposal
   card for that path; a branch touching only `docs/` lands; after
   `asf approvals resolve <item>/merge_amendable_set granted` the held branch lands.
