## Description
stories: S-18755
writes: asf/record/ingest.py, tests/test_ingest.py
after: Task 1, Task 5

§2.7. The one pass that turns the claim into a fact on the card. It waits on Task 5 because the key
it reads is Task 5's: an ingest pass over an evidence key nobody fills ticks nothing and reads as a
feature that does not work.

**Files**

- `asf/record/ingest.py` — `tick_proven(canonical, ev, stamp)` and its call in `cmd_ingest`, between
  the write loop (`ingest.py:440-462`) and `do_index` (`:463`); `import` of `asf.proves`.
- `tests/test_ingest.py` — `ProvenAcceptanceTests`.

**Steps**

1. The pass runs after the write loop and before `do_index` (**P14**), over the Story cards only:

   ```python
   for iid, rec in canonical.items():
       if rec['meta'].get('type') != 'story':
           continue
       for claim in (ev.get('proves') or {}).get(iid) or []:
           body, changed = proves.tick(body, claim['line'], note)
   ```

   The card is re-read off `rec['path']` and parsed afresh, because that same loop may have just
   written a machine block and a History line into it. One `frontmatter.render` write per Story
   that changed, the shape `ingest.py:456-462` already uses.
2. For every line **newly** ticked, one History line through `append_history_lines`, in §2.7's
   exact shape:

   ```
   - 2026-09-24 12:30 ingest: proved line 1 — T-0123, PR #412 (tests/test_proves.py::ParseTests::test_trailer)
   ```

   The `PR #<n>` clause is omitted where the claim's `pr` is null — a fast-forward landing has no
   pull request to name, and the sha is already in the evidence.
3. The stamp is `cmd_ingest`'s own `now[:16].replace('T', ' ')` (`ingest.py:172`), not a second
   clock: two writes in one pass must not disagree about the minute.
4. Idempotent by construction (D7). A bullet already `- [x]` is left alone and writes no History
   line, so a second ingest in the same minute changes nothing. A claim whose line does not exist —
   the Story's acceptance list was rewritten after the Task landed — ticks nothing, raises nothing,
   and is what Task 7's rule check reports. Nothing here ever turns `- [x]` back into `- [ ]`.
5. No machine-block key is added, no typed field changes, and `index.json`'s shape is untouched.
6. `ProvenAcceptanceTests`, over a temp record and a stub evidence dict: line 2 of a Story's
   `## Acceptance` turned from `- [ ]` to `- [x]` with one History line naming the Task, the pull
   request and the test; the other bullets and the machine block byte-identical; a second ingest
   writing nothing; a claim for a line the Story does not have changing nothing and raising
   nothing; a claim with `pr: null` writing a History line with no `PR #` clause; a Story with no
   `## Acceptance` section changing nothing; and `asf check` clean on the record afterwards — a
   ticked box must still satisfy `ACCEPTANCE_ITEM_RE` (`asf/record/check.py:15`, which accepts
   `- [x]`).
