  `'precedent'` (PD3); `FIELD_RE`'s alternation (`:32`) gains `undelivers` in the same position;

- `tests/test_report.py` — `RulingFieldsTests` (`:172-211`): the three whole-dict literals at
  `:182`, `:186` and `:203` gain `'undelivers'` (PD2), plus the new cases for the fourth field and

**Steps**

1. `FIELDS`: `… 'ruling', 'blocked_on', 'writes', 'superseded_by', 'undelivers', 'precedent')`.
2. `FIELD_RE`: `…|blocked_on|writes|superseded_by|undelivers|precedent)` — the same slot.
3. `ruling_fields`: add, beside the existing `writes = _claim(rep.get('writes'))`,

   ```python
   undel = _claim(_first_line(rep.get('undelivers')))
   ```

   and the fourth key `'undelivers': undel.split() if undel else None`. **`_first_line` is PD1
   and is not optional**: without it the `NEEDS OPERATOR:` paragraph that the brief asks every
   session to print runs on into this field and every word of it becomes a claimed id (measured:
   eight ids for a one-id ruling). `undelivers` names ids on one line; a second line is never part
   of the claim.
4. Replace `ruling_fields`' docstring with the spec's §1 text, keeping its own sentence for why the
   field is read last and why that costs nothing.
5. `tests/test_report.py`: add `'undelivers'` to the three whole-dict literals (PD2) — `:182`
   (`None`, the ruling claims no strike), `:186` (`None`) and `:203` (`None`).
6. Add cases to `RulingFieldsTests`: `undelivers: T-0002 T-0003` → `['T-0002','T-0003']`; each of
   `none`, `None`, `n/a`, `-`, `—`, empty and absent → `None`; the stray-line arms of C2 both ways
   — above `superseded_by:` the line corrupts the field above it (`writes: none` reads
   `['none','undelivers:','T-0002','T-0003']` *before* this change, which is the measured reason
   for the placement) and placed last it claims nothing; and **PD1's case**: `undelivers: T-0002`
   followed by a `NEEDS OPERATOR:` paragraph reads exactly `['T-0002']`, the sibling of the
   bug-1377 case already pinned at `:194-205`.
7. Assert the two readers are unmoved: a ruling whose only mechanism is `undelivers:` still
   overrules a review (`lifecycle.overruling` refuses on `blocked_on`/`superseded_by` only) and
   `health.ready` still reads `blocked_on`.
