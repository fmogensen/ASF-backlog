§2.3. One more hold, chained where the other two are, so `asf next`, `asf status`, the shadow tick
and the wave all get the same answer from the one path. What it holds is `HELD_KINDS`' own union
and not a second list, which is what makes it impossible for `feeder.hold` and this hold to
disagree about what "new work" means (D1) — and also what leaves `DELIVERY → PLAN`,
`DELIVERY → CODE` and `RESHAPE → PLAN` uncaught, inherited rather than widened (P7). An S1/S2
Bug's `BUG → FIX` is exempt (D2), which today is every `BUG → FIX` row the feeder makes (P6).

- `asf/feeder/rows.py` — `from asf import budget` (`:72`); `WAITS_BUDGET` beside `WAITS_MERGE`
  (`:117`); `BUDGET` and `BUDGET_HELD_KINDS` under `HELD_KINDS` (`:1289-1292`); `epic_verdicts`,
  `epics_over_budget`, `over_budget_epics`; one line in `candidates()` after `hold_classes`
  (`:1355`).

**Steps**

1. `from asf import budget` at the top of `asf/feeder/rows.py`. `asf.budget` imports
   `asf.conventions`, which imports `re` and `dataclasses` and nothing of this package — so the
   leaf stays a leaf and there is no cycle. This is the import its own module docstring invites.
2. `WAITS_BUDGET = 'WAITS ON budget'` beside `WAITS_LANDING` (`:114`) and `WAITS_MERGE` (`:117`).
   P4: this module owns the action word, `asf.budget` owns the money in it.
3. `BUDGET = 'budget'` — the `waits_on` of a held row — and
   `BUDGET_HELD_KINDS = frozenset(k for ks in HELD_KINDS.values() for k in ks)`, both directly
   under `HELD_KINDS` (`:1289-1291`) with §2.3's comment, so a kind added to `HELD_KINDS` joins
   this hold in the same diff and the two can never drift.
4. `epic_verdicts(items)` exactly as §2.3 fences it: `{e['id']: budget.epic_spend(e['id'],

   subtree sum per Epic per pass, never per row.
5. `epics_over_budget(items)` → the `EpicSpend`s in `epic_id` order whose verdict is `over` and
   under which some *other* item is still open (`is_open`, `:405`, over `ix.subtree(items, e)`
   less the Epic itself) — D6: an Epic over budget whose work is all Closed holds nothing, so it
   raises nothing. Read from the index alone, never from a row: §1.1's cut is why (D5).
6. `over_budget_epics(rows, items, verdicts=None)` exactly as §2.3 fences it, with two

   (P4), and the action assembled as `f'{WAITS_BUDGET}: {budget.epic_over(s)}'`. The walk is
   `ix.epic_of(items, item)` — `items.get(r.item_id) or {}` is falsy and `ix.epic_of` answers
