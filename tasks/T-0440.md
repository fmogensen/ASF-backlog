The spec's `asf/feeder/render.py` block and the card's third acceptance: `cmd_next` loses its own
index load, its own overlay-less map and its own capacity default, and plans through `plan_now`; the
gate line goes under the load line; `--json`'s stdout does not move. The fixture in this Task's
`writes:` is there because it is the file a regeneration would touch — PD5 says it is not regenerated,
and the Task's own Gate proves it by leaving it byte-identical.

**Files**

- `asf/feeder/render.py` — `cmd_next` through `step_wave.plan_now`; `table()` takes the gate and the
  source note; `_default_capacity` retired
- `tests/test_feeder.py` — `CliTest` gains the gate cases; `TableTests` gains the gate argument's two
  answers; `NextAllTests` unchanged in expectation
- `tests/test_s1_gate.py` — `NextPlansTheWavesRows`
- `tests/fixtures/feeder/next-s1-held.md` — asserted unchanged (PD5)

**Steps**

1. `cmd_next(args, root=None)` keeps its signature and its `root` override — `tests/
   test_invariants_in_feeder.py:132` calls it with the tick's own `record_root()` and must keep
   working. Its body becomes the spec's: load the product, then
   `plan = step_wave.plan_now(product, root=root, inflight=load_inflight(inflight_path) if
   inflight_path else None, capacity=args.capacity, decision_limit=0 if args.all else None)`. `root`
   given wins, as today; `--inflight` still replaces the live sessions for a what-if and `None` still
   means the ledger's; `--capacity` `None` still means the wave's own seats, now including the cloud
   lane's (PD9).
2. `ix.load`, the bare `plan_rows` call, `step_wave.plan_inputs(product, root)` and
   `_default_capacity` all leave `cmd_next`; `_default_capacity` is deleted, having no other caller.
   `_hidden_undecided` stays and is fed `plan.items`, `plan.inflight` and
   `R.occupied(plan.inputs.get('occupancy'))`.
3. `build_load` is called with `plan.items`, `plan.capacity`, `plan.inflight` and `plan.inputs`'
   fields exactly as today — one substitution of source, no change of shape.
4. `table(rows, header=None, hidden=0, load=None, gate=None, note=None)`: `gate` is
   `tiers.gate_line(plan.gate)`'s string or `None` and is appended **directly under** the load line,
   no blank line between (the spec's `asf next` block); `note` is the source line, appended only when
   `plan.source` is not the clone —
   `— planned from the product's backlog_dir, which may be behind origin (asf tick makes the record
   clone)` — and byte for byte the spec's. Both are omitted when `None`, so every existing call of
   `table()` renders what it renders today.
5. Under `--json` the rows list on stdout is byte-identical to today's — `rows_json(plan.rows)`, same
   keys, same order — and `gate_line` and the source note go to **stderr** (the spec's **Out**: the
   stdout of `next` is a value a script reads, and `surface.py` calls `next` read-only).
6. `CliTest` gains two cases beside its existing ones: an index whose plan has an unseated S1 with
   tier-2 rows behind it prints the card's line under the `Features in build` line, as two lines of
   one block — asserted directly, not through the existing `rsplit` (PD6); and the same run under
   `--json` puts the line on **stderr** with stdout parsing as a JSON list whose keys are the set
   `test_json` already pins. A third case asserts the source note appears for a product planned from
   its `backlog_dir` and not for one planned from a clone. `test_next_table`'s existing load
   assertion is not touched.
7. `TableTests` gains one case for `table(..., gate=None)` — the golden output, unchanged — and one
   for `table(..., gate='S1 gate: …')`, where the line is the last line of the load block.
   `test_golden_s1_held` and `test_golden_s1_unheld` keep their current bodies and their current
   fixtures: PD5 reproduced that both plan
