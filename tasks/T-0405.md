## Description
stories: S-32356
writes: asf/plugin_build.py, tests/test_plugin.py
after: none

§2.5: a third action beside `build|check` that writes the whole tree under `<ASF_HOME>/plugin`
from the CLI's own parser, reading nothing from a checkout — so a `pipx` install has the `/asf:*`
skills (B-0047).

**Files**

- `asf/plugin_build.py` — `installed_plugin_dir()`, `install(dest, out)`, `install` as a third
  `choices` value, `--dir` documented for it
- `tests/test_plugin.py` — `PluginInstallTests`

**Steps**

1. `installed_plugin_dir()` returns `os.path.join(env.ASF_HOME, 'plugin')` (`asf/env.py:21`) —
   under `<ASF_HOME>`, never the runtime's own configuration directory (PD15, D7).
2. `install(dest=None, out=print)`: `dest or installed_plugin_dir()`, then
   `expected_files(os.path.join(dest, 'plugin'))` written relative to it —
   `.claude-plugin/marketplace.json` at the top, `plugin/.claude-plugin/plugin.json`,
   `plugin/skills/<name>/SKILL.md` per view and dialogue, `plugin/hooks/hooks.json`
   (`asf/plugin_build.py:130-138`). Directories are created; every file is written whether or not
   it differs, so the tree is regenerated byte-identical on a second run.
3. Strays under the destination's `plugin/skills` are **removed**, not merely reported: a skill
   dropped from the CLI must not linger in an installed tree. `build` keeps its report-only
   behaviour on a checkout; only `install` deletes.
4. `run_action` gains `install`, which never calls `default_plugin_dir` — the "no checkout here"
   refusal stays `build`'s and `check`'s alone (`asf/plugin_build.py:196-201`). The parser's
   `choices` becomes `['build', 'check', 'install']` and its help names the third action.
5. `PluginInstallTests`: with `ASF_HOME` pointed at a temp directory and the cwd somewhere with no
   `.claude-plugin/marketplace.json`, `asf plugin install` writes every path `expected_files`
   names, with the same bytes `build` would write; a second run changes no byte; a stray skill
   directory planted under the destination is removed; `--dir` overrides the destination; and
   `default_plugin_dir` is asserted never called on the `install` path.
6. `asf plugin check` against the checkout's own `plugin/` stays green (PD14) — the parser's help
   string is not rendered into any SKILL.md.

**Gate**

```sh
python3 -m unittest -v tests.test_plugin
python3 -m asf.cli plugin check
bash tools/check_conventions.sh && bash tools/check_generic.sh
python3 tools/run_tests.py 2>&1 | tail -3
```

**Acceptance**

```

```
