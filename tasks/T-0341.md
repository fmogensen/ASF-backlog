§2.1: the tick's launch path stops building its own four-key dict and calls the filler the contract
test covers, so every launched brief carries the `Head:` line, the `exists:` flag, the document
sizes, the named tests, "Where to look" and the last report — six facts that were already written
and never delivered (P3). A deletion plus an import; no behaviour is added.

**Files**

- `asf/tick/step_wave.py` — `-repo_facts`, `-_git`, `+_repo_facts`; the two call sites at `:623-624`
  and `:726-727`
- `tests/test_tick_steps.py` — `-test_unpushed_branch_facts`, `+WaveFactsTests`

**Steps**

1. Delete `repo_facts(product, branch)` (`:431-441`) and `_git(repo, args)` (`:426-428`, no other
   caller — verify with `grep -n '_git(' asf/tick/step_wave.py` before and after).
2. Add the late-import shim beside `_build` and `_wave`, keeping the step's import shape:

   ```python
   def _repo_facts(*a, **kw):
       from asf.briefs import facts
       return facts.repo_facts(*a, **kw)
   ```
3. Both call sites become
   `repo_facts=_repo_facts(product, row, <index>, running)` — `fresh` at `:624`, `items` at `:727`,
   each the same index that call already passes to `_build`.
4. If `subprocess` is left unused in the module after step 1, drop the import; if another function
   still uses it, leave it.
5. Delete `test_unpushed_branch_facts` (`tests/test_tick_steps.py:683-686`, P17) — it asserts the
   deleted dict — and add `WaveFactsTests` in its place: run the wave over the fixture product with
   a pushed branch, capture the `repo_facts` the patched `build` receives (the `built` list at
   `:319-320` is the shape to follow), and assert
   `set(facts) == set(preamble.REPO_FACT_KEYS)`, `facts['branch_exists'] is True`, that the brief's
   text carries a `Head:` line naming the branch's own short sha and `exists: yes`, that
   `hasattr(step_wave, 'repo_facts')` is False, and that `briefs.build(...)` over the same row with
   `facts.repo_facts(...)` yields the same text the wave produced.
