- `asf/rules/hooks/r0003.py` — `Bash` only (PD6). The complement of `touch_production` (D7):
  refuses bare `git push` from a checkout whose `HEAD` is the trunk or whose upstream
  (`branch.<name>.merge`) is the trunk; `git push origin HEAD` / `git push origin @` from the
  trunk; `git push --force`, `-f`, `--force-with-lease` and `--mirror` **to any branch**, because
  the standing rule is that a lane branch is never force-pushed and the lane rebases it (B-0056);
  and `git push --delete` / `:<branch>` of the trunk. Returns **None** for an explicit trunk
  refspec — `git push origin main` is the matrix's, and the refusal text for what this rule does
  catch names `touch_production` as the owner of the rest, so the model is never told two stories
  about one command (D7, P8). The branch and upstream are read with
  `git -C <cwd> rev-parse --abbrev-ref HEAD` and `git -C <cwd> config --get branch.<b>.merge`
  under `hermetic.git_env()`, so an inherited `GIT_DIR` from an enclosing git hook never answers
  for another repo — the same guard `hooks.git_hooks_dir` takes (`asf/hooks.py:73-78`). The trunk
  name is `ctx.product.conventions.main`, never a literal (PD15).
- `asf/rules/hooks/r0005.py` — `Bash` only. Two shapes, one card: a worker session whose job is
  not a lane job running `gh pr create`, `gh pr merge`, `gh pr ready`, or `git push` with
  `-o merge_request.*` → refused outright, with the standing rule ("the session pushes its branch
  and ends there; the lane opens and lands the PR") as the reason. A **lane** job running
  `gh pr create` whose body is missing a line its lane requires → refused, each missing line
  named. What a lane requires is `conventions.lane.pr_body_lines`: a list of literal lines or
  `/regex/` forms, empty by default, and an empty list means every body is allowed. `--body-file`
  is resolved against the call's `cwd` and read; `--body-file -` and a heredoc body are read from
  the command text; a `--body-file` that is not there yet (a body written by a later command of the
  same compound) **allows** and records one `rule-hook-error`. Whether a job is a lane job comes
  from `ASF_JOB`, by the same reading the rest of the tree uses — read it in the tree rather than
  inventing a prefix test.
- `asf/conventions.py` — `lane.pr_body_lines`: `'pr_body_lines': 'lane_pr_body_lines'` in
  `LANE_KEYS`, the `lane_pr_body_lines: list` field defaulting to `()`, and the lane-shape
  validator's refusal string at `:450` widened to name the third key. A non-list value is a shape
  finding, not a silent default.
- `docs/products.example.yaml` — `pr_body_lines` under the existing `lane:` block, with one
  comment line and one example line.
- `tests/test_conventions.py` — `lane.pr_body_lines` read, defaulted, and named by
  `shape_findings` when misshapen; and the widened refusal string naming all three lane keys.
- `tests/test_rule_hooks.py` — `PushRuleTests` and `PrRuleTests`.
