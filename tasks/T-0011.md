4. `templates/groom.md`: the house voice and §2.6's five points, in order. It gives the answer grammar
   (`yes`, `no`, `rank <n>`, `parent <id>`, `S1|S2|S3`, `unblock <id>`), each with one sentence of why,
   or `NEEDS OPERATOR: <the question> — <your recommendation>`. Every line goes in
   `- [ ] <id> <title> — <why> → answer: adjudicator: <word>` form into `{answers_file}` only.
   **The repository is not your work**: no commit, no push, no card edit. The four classes that are
   never the session's go to `NEEDS OPERATOR` (licence, money, security, customer-visible).
5. `tests/test_briefs.py`: a `ROWS['groom']` row, with the three attributes set on it. The
   existing golden, every-kind and placeholder tests then cover it. Add asserts that the text
   names the groom file, the answers file and `unblock <id>`, and that `model == 'heavy'` and
   `id_ranges_needed` hold.
