entry, one trivial `cloudpid.why`, two lines at health's one write site, a second axis on the
census and one column on the Dead rows. **Read PD2 before writing the column**: `dead_why` and the
Dead group are disjoint by construction, and the column as specified would read `—` for ever.

**Files**

- `asf/workers/lifecycle.py` — `dead_why` appended to `RUN_FIELDS` (`:114-116`). Nothing else:
  `end_reason` is untouched byte for byte and `is_dead_reason` (`:220`) keeps its exact equality
  (P3, the card's Out)
- `asf/workers/cloudpid.py` — `why(tok)`, the sibling of `status` (`:80`): `(load().get(tok) or
  {}).get('why') or ''`
- `asf/workers/health.py` — `dead_why` beside `dead_class` at the one write site (`:932-935`);
  `dead_census` (`:171`) gains a `by_refusal` axis; `dead_census_line` (`:199`) appends
  `; refusals: naming 3, pre-push 1`
- `asf/views/sessions.py` — a `Why` column on the Dead rows only: `DEAD_COLUMNS` and a per-group
  header in `render`'s loop (`:148-158`)
- `tests/test_workers.py` — one new class, `DeadWhyOnTheEndRecord`
- `tests/test_doctor.py` — one new class, `DeadCensusNamesTheRefusals`
- `tests/test_views.py` — one new class, `DeadRowsCarryTheirWhy`

**Steps**

1. `RUN_FIELDS` gains `'dead_why'`. It belongs to one launch and never folds into the next, which
   is the whole reason it is an entry there rather than text appended to `end_reason` (C13/P3).
2. `cloudpid.why(tok)` beside `status`, three lines with a docstring: the token's last recorded
   `why`, `''` when none. For a local run's pid it answers `''`, so `dead_why` is written only
   where there is something to write.
3. `health.py`, at `:932-935`: `dead_why = cloudpid.why(s.get('pid')) if dead_class else None`
   (`''` → None) and `dead_why=dead_why` added to the existing `pool_mod.update_session(...)` call.
   Measured: `dead_class` is non-None only when `reason == lifecycle.DEAD_PID`, so the field
   follows the class and is the class of a death only (the comment at `:930-931` already says so).
   `end_reason` and the `s.update(...)` beneath it are not touched.
4. `dead_census` gains `by_refusal`: for each counted death, `refusals.last(product, r.get('job'),
   r)` and its `kind`, folded `{kind: n}` and omitted when empty. **PD3** is what makes this
   honest — the window filter is in `last`, so a nine-day-old death does not inherit the live
   ledger. The returned dict keeps every key it has today and adds this one.
5. `dead_census_line` appends `; refusals: naming 3, pre-push 1` when any is known and nothing
   when none is, reading `data.get('by_refusal') or {}` — per **PD11**(b) this is required, not
   defensive: `tests/test_doctor.py:277`, `:285` and `tests/test_workers.py:3297` pass
   hand-written dicts with no such key. Its `ok` rule is untouched: an unexplained death is still
   the thing the line fails on. `asf/doctor.py` needs no edit (`:1811` calls it as it stands).
6. `refusals.dead_reason` is the only read of the composed sentence (C14) — written in Task 1,
   with **PD2**'s `cloudpid.why` fallback, and called here and in the view. No reader touches
   `run['dead_why']` directly.
7. `asf/views/sessions.py` — `DEAD_COLUMNS = LIVE_COLUMNS + ('why',)` beside `LIVE_COLUMNS`
   (`:94`), and `render`'s group loop picks `DEAD_COLUMNS` with `header + ('Why',)` for the `Dead`
   group and today's pair for every other. Set `why` on each dead row as `refusals.dead_reason(
   run, product)` cut to its first line; leave it `''` rather than `'-'` and let `_table`'s own
   `r.get(k, '—') or '—'` (`:100`) render the em dash every other empty cell in these tables
   already uses — the spec's `-` is that dash, not a second convention. P13's Ended t
