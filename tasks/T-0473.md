The spec's first, second and third **In** bullets and `## The design` §1's `by_pattern` and §3 whole.
One new module, one parser entry, one surface row. The lane keeps every registry write (D1, D14):
this command resolves a product, lists PRs once, attributes each to a card, prints a table and calls
`Lane.adopt`.

**Files**

- `asf/adoptpr.py` — new module: `by_pattern(conv, text)`, the selection, the attribution,
  `cmd_adopt_pr(args, root)`
- `asf/cli.py` — `adopt-pr` in `build_parser` and its dispatch
- `asf/surface.py` — the `adopt-pr` row
- `tests/test_adopt_pr.py` — `ItemDerivationTests`, `AdoptCommandTests`, `AllGlobTests`
- `tests/test_surface.py` — the count literal at `:49`, 49 → 50

**Steps**

1. `by_pattern(conv, text)` with the spec's docstring byte for byte (§1): the `(id, slug)` a
   `branch_patterns` entry captures in `text`, or `(None, None)`. Entries are tried in **name order**
   and the first that **fullmatches** answers. `<id>` compiles to `(?P<id>[A-Za-z]+-\d{4})`, `<slug>`
   to `(?P<slug>[A-Za-z0-9._-]+)`, every other character escaped. It never touches the record;
   turning a slug into a card is `match_event`'s job (P17).
2. **Resolve.** `env.load_product(args.product)`; its repo and `repo_slug`; a product with no PR host
   (`Lane(...).slug` is None, i.e. fast-forward landing) refuses with one line and exits 1 — there is
   no queue of pull requests to adopt. The record's `index.json` is loaded once for P17 and for the
   `--item` check.
3. **Select.** One `Lane(product, root=root).host.prs()` — the lane's own `gh pr list` (P5, PD8),
   keyed by head branch. Numbers as given are looked up by inverting that dict on `number`; `--all`
   matches the key with `fnmatch`. Either way a candidate must be `state == 'OPEN'` and
   `base in (None, trunk)`; anything else refuses **by name** with what it actually is (closed,
   merged, on another base, not a PR at all). `--all` and numbers together refuse; neither refuses;
   `--all` with no glob refuses (D10); `--item` with more than one PR refuses (D3). Each of these is a
   usage refusal, exit 2, before anything is read.
4. **Attribute** each selected PR, in the spec's order (D2), recording the rule that answered:
   `--item <id>` (which must be a card in the record — **PD9**: an id no card answers for refuses
   that PR rather than adopting under it); then `by_pattern(conv, branch)` and `by_pattern(conv,
   title)`, whose `<id>` must be a card and whose `<slug>` is handed to `match_event`, printed as
   `branch_patterns:<name>`; then `match.match_event(items, branch=…, pr=…, title=…,
   prefixes=match.branch_prefixes(product))`, accepted only when it returns exactly one id, printed
   as the rule `match_event` itself named — **PD6**: the string is printed unedited, since the rule
   that answered is the record's to name. Nothing, or more than one candidate, is refused.
5. **Drop what a run already owns** — **PD5**, D9's rule read as its own reason requires. A head
   branch `lifecycle.by_branch(lane.path)` already answers for is never written a second time: a run
   carrying `adopted_pr` or `adopted` prints `already adopted` and counts with the successes (the
   card's fourth named test, and the spec's Out line about a `merge: auto` adoption); any other run
   prints `a run already holds this branch (<job>)` and is **refused**, because a second line would
   outrank it in `by_branch` and reset a live lane record to PUSHED.
6. **Print the table** — §3's header, columns and summary line, byte for byte in shape:
   `product: / repo: / trunk:`, then `PR BRANCH ITEM BY ACTION`, then
   `<a> adopted, <b> already adopted, <c> refused`, then one `NEEDS OPERATOR:` line per refused PR
   naming its branch, its title and the exact `asf adopt-pr <n> --item <id> --product <p>` to run.
