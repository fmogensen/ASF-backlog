## Description
stories: S-30453
writes: asf/groom/inbox.py, asf/groom/groom.py, tests/test_groom.py
after: none

§2.4. The memory file was a workaround: *an `inbox:` answer with a trailing `— why` is silently
dropped*, so remember not to write one. The grammar does not widen — nothing is applied that was
not applied before — and the code stops needing to be worked around, because it says what it
refused and why (§1.2, §1.4).

**Files**

- `asf/groom/inbox.py` — `parse_answer` returns `(parsed, reason)`; `apply_answer` returns
  `(applied, reason)`
- `asf/groom/groom.py` — the inbox branch prints the refusal line
- `tests/test_groom.py` — `InboxAnswerGrammarTests`, and the existing callers of both functions

**Steps**

1. `asf/groom/inbox.py`: `parse_answer(answer)` returns `('close', None)`, `(headers, None)` or
   `(None, reason)`. The `None` at `:299` becomes a reason naming the first clause that failed,
   built from the clause text and the grammar: the clause in quotes, `is not a clause`, and the
   five forms `_CLAUSES` holds, listed from `_CLAUSES` itself rather than re-typed. When the
   failing clause carries an em dash — or ` - `, the same mistake in ASCII — the reason adds
   `an answer carries no why`, which is the sentence §3's T4 looks for and the one that makes the
   mistake fixable.
2. `apply_answer(root, name, answer, date, who, intake_dir=None)` returns `(applied, reason)`:
   the bool it returns today and the reason from `parse_answer`, `None` when it applied. Its
   docstring says the pair is the contract, so a caller cannot use the tuple's truthiness by
   accident — every call site is updated in this Task, and there are no others (`grep` for
   `apply_answer` finds `asf/groom/groom.py:310` and `tests/test_groom.py`).
3. `asf/groom/groom.py:309-315`: unpack the pair. On `applied`, everything is as it is today —
   the count, the `groom_answer` event, the fields. On a refusal, print
   `groom: answer not applied — inbox:<name>: <reason>` through the section's own `out` and
   `continue`. No event: a refused answer changes nothing, so there is nothing to record (§4,
   "Rows and events"). Every other answer on the page is applied exactly as before.
4. `tests/test_groom.py` gains `InboxAnswerGrammarTests`, §3's T4 case for case:
   `parse_answer('parent E-0001 — because the card changes the feeder')` returns `(None, reason)`
   with `an answer carries no why` in the reason; `parse_answer('feature')` and
   `parse_answer('close')` are unchanged; a groom page carrying one bad inbox answer and one good
   one applies the good one, counts 1, emits exactly one `groom_answer` event, and prints exactly
   one `groom: answer not applied —` line naming the bad clause.
5. Update the existing `AnswerParsingTests` and `GroomInboxIntegrationTests` cases that call
   either function for its old return shape. They are in the same file and the fence runs the
   whole module.
6. Run `tests/test_groom_every_tick.py` — it calls `process_inbox` directly
   (`tests/test_groom_every_tick.py:32`) and is the fence's second half: the every-tick invariant
   must not notice this change.
