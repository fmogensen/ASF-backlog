## Description
stories: S-33101
writes: asf/probe/scope.py, asf/views/prod.py, tests/test_probe_scope.py, tests/test_prod_view.py, tests/test_metrics.py
after: Task 1

§2.2 and PD6: `_is_customer`, `_glob_re` and `_changed` move out of the prod view into
`asf/probe/scope.py`, and the view imports them back. One classifier for "is this customer-facing",
because the whole close rule of §2.9 hangs off its answer. `owed` then reads a release through
`metrics.release_items` and `metrics.TRY_IT` — not a second try-it parser.

**Files**

- `asf/probe/scope.py` — `Owed`, `_glob_re`, `is_customer_visible`, `_changed`, `owed`
- `asf/views/prod.py` — the three definitions deleted, imported from `asf.probe.scope`; the one
  call site at l. 163 keeps its shape
- `tests/test_probe_scope.py` — T2
- `tests/test_prod_view.py` — the ON PROD table asserted byte-identical
- `tests/test_metrics.py` — `release_items` and `TRY_IT` unchanged

**Steps**

1. `is_customer_visible(paths, changed_files, within=None)` is `asf/views/prod.py:99`
   `_is_customer` verbatim, with its `non_customer_hint` parameter — which every caller passes
   empty — dropped, and `_glob_re` (l. 75) beside it.
2. `_changed(repo_dir, sha)` moves too (PD6). `asf/views/prod.py` imports all three and its l. 163
   becomes `if not is_customer_visible(cust, _changed(repo_dir, sha), within):`.
3. `Owed`: frozen, `item`, `pr`, `try_it`, `customer_visible`.
4. `owed(product, sha, previous_sha, items, repo=None)` (PD7): `metrics.release_items(items, sha,
   previous_sha)` gives the items whose merged pull request is inside `sha` and outside
   `previous_sha`, with the try-it line `metrics.TRY_IT` already parsed; `is_customer_visible(
   product.customer_paths, _changed(repo, merge_sha))` gives the flag. One row per
   (item, pull request) — an item with two pull requests is two rows. An item with no try-it line
   and no customer-visible landing still appears, with `try_it=None`.
5. `tests/test_probe_scope.py`: the identity assertion T2 asks for — the test imports
   `asf.probe.scope.is_customer_visible` and the name `asf.views.prod` now holds, and asserts they
   are the same object — then a git fixture with four merged pull requests (customer-visible with
   a try-it line; customer-visible without; test-only with a try-it line; under no `customer_paths`
   glob), asserting four rows with the right `try_it` and `customer_visible`, and that a pull
   request inside `previous_sha` is not among them.
6. `tests/test_prod_view.py`: the ON PROD table over the same fixture, byte-identical to before
   the move.
