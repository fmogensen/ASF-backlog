## Description
stories: S-32603
writes: asf/doctor.py, asf/feeder/render.py, asf/briefs/build.py, asf/views/capacity.py, tests/test_doctor.py, tests/test_feeder.py, tests/test_briefs.py, tests/test_capacity.py, tests/test_path_resolution.py

The spec's "four bypassing commands" table (P5, D5, D6, D7): the three views that print no first line
at all and the doctor that names a product without saying what chose it, all four through Task 2's
`product_line` and the same stdout/stderr rule.

**Files**

- `asf/feeder/render.py` — `cmd_next` resolves through `env.resolve_product` and prints the line
- `asf/briefs/build.py` — `cmd_brief` prints it to stderr
- `asf/views/capacity.py` — `cmd_capacity` prints the record-less form; `--all` prints its own line
- `asf/doctor.py` — `format_table`'s caption gains the source; `cmd_doctor` resolves through
  `env.resolve_product`
- `tests/test_feeder.py` — `NextNamesItsProductTests`
- `tests/test_briefs.py` — `BriefNamesItsProductOnStderrTests`
- `tests/test_capacity.py` — `CapacityNamesItsProductTests`
- `tests/test_doctor.py` — the caption's source, in the existing table tests' idiom
- `tests/test_path_resolution.py` — `capacity`'s row, and the exemption dropped for `next`, `brief`
  and `doctor`

**Steps**

1. `cmd_next` (`asf/feeder/render.py:102`) resolves `res = env.resolve_product(getattr(args,
   'product', None))`, loads that product by name, and prints `product_line(res.name, res.source,
   root)` as its first line — to stderr when `args.json` is set (`--json` is on its parser,
   `asf/feeder/render.py:150`), to stdout otherwise. `root` stays the caller's override when one is
   passed, so the tick's own use of `cmd_next(args, root)` is unchanged.
2. `cmd_brief` (`asf/briefs/build.py:521`) resolves the same way and prints the same line **to
   stderr always** (D7): its stdout is the brief a worker is handed, and `new` and `stale` already
   take that seam.
3. `cmd_capacity` (`asf/views/capacity.py:145`) prints the record-less form `product <p> (<source>)`
   — it reads `config.yaml` and the product files and never the record, so a record path there
   would be false (D5). With `--all` it prints `products: all — <n> declared` instead, `<n>` being
   the number of products `_products_for` resolved. Under `--json` the line goes to stderr, so the
   JSON on stdout is still parseable. `render` and `as_json` keep their signatures.
4. `format_table(product_name, rows)` (`asf/doctor.py:1055`) takes the source and its caption
   becomes `== DOCTOR <product_name> (<source>)` (D6) — one header, not two. `cmd_doctor`
   (`:1075`) replaces `args.product or env.default_product_name()` with
   `env.resolve_product(args.product)` and passes both fields through (PD6, PD7). Every other row
   of the doctor's table, its RED logic and its exit status are untouched.
5. `NextNamesItsProductTests`: two products over a temp `ASF_HOME`; `asf next --product bot` from
   nowhere opens on `record: <bot's record> · product bot (--product)`; bare from inside `bot`'s repo
   it says `(cwd)`; with `ASF_PRODUCT` set it says `($ASF_PRODUCT)`; under `--json` the line is on
   stderr and stdout parses as JSON.
6. `BriefNamesItsProductOnStderrTests`: the line is on stderr and stdout's first line is the brief,
   for a bare run from the product's repo and for `--product`; the source token matches the input.
7. `CapacityNamesItsProductTests`: the first line is `product <p> (<source>)` with no `record:`
   prefix and no path; the token follows the input for `--product`, `$ASF_PRODUCT` and a cwd inside
   the product's repo; `--all` prints `products: all — <n> declared`; under `--json` the line is on
   stderr and stdout parses.
8. `tests/test_doctor.py`: the caption carries `(<source>)` for each of the four inputs, and the
   existing table assertions are updated to the new caption where they match it exactly.
9. `tests/test_path_resolution.py`: `capacity` is added with PD9's `product` kind, `doctor` becomes
   the `caption`
