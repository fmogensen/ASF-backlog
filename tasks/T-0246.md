## Description
stories: S-0001
writes: tests/test_tick_steps.py, tests/test_tick.py, tests/test_groom_every_tick.py
after: Task 4, Task 7

§3.6 — S-0001's proof. The production side is already true (PD15): `step_daily.parts` is three
callables run through `run_part`'s `redirect_stdout`, `step_groom.run` calls
`apply_pending_answers` and `cmd_groom(apply=True)` directly, and `run_step0` calls
`cmd_file_bugs` then `cmd_rollup` then `do_index` in that order. What was missing is the
assertion, and the assertion was not *writable*: with `file_bugs` spawning the factory and
`step_wave` spawning git, a tick with `subprocess.run` patched to raise could not complete. Tasks
4 and 7 are what make it writable, and this Task writes it. Tests only — no production file
changes (§2.8: groom and stale are "nothing but S-0001's proof").

**Files**

- `tests/test_tick_steps.py` — the four parts named, each a callable, and the no-subprocess tick
- `tests/test_tick.py` — `DailyStepTests`
- `tests/test_groom_every_tick.py` — the groom step's two parts in process

**Steps**

1. `DailyStepTests` per §3.6: `step_daily.parts(product, root)` is `stale`, `rollup` **for
   yesterday** (`step_daily.yesterday()`, not today) and `scorecard`, in that order, each a
   callable — asserted by name and by `callable()`, and by calling each through
   `step_daily.run_part` with a thunk of its own.
2. `run_step0`'s order per §3.6: `file-bugs` and `rollup` run in process, in that order, before
   `do_index` — asserted by recording the calls the step makes over one fixture record, so the
   order is the assertion and not a reading of the source.
3. `step_groom.run` per §3.6: it applies the pending answers and runs `cmd_groom(apply=True)` in
   process, both over the record clone, and a non-zero `cmd_groom` raises `StepFailed` with the
   code in the message (`tests/test_groom_every_tick.py`).
4. The assertion the seam makes possible, and the centre of this Task: with
   `subprocess.run` patched to raise, a tick's `record`, `groom` and `daily` steps **all
   complete** — not one of the four parts the Story names starts a process. Patched at
   `subprocess.run`, `subprocess.Popen` and `subprocess.check_output`, so a spawn by any name
   fails loudly rather than passing unnoticed. A product with no `repo_dir` is the fixture, so
   `ctx.git` builds nothing (Task 4) and the record clone is a local path.
5. A part that fails does not stop the others and the step still fails, per §3.6: three parts, the
   middle one raising, and `run` prints `daily: <name> FAILED — <first line>` for it, `ok` for the
   other two, then raises. And the day is not stamped — the stamp the daily step writes is absent
   after a failing run and present after a clean one.
6. These are additions: no existing case in the three modules changes its assertion, and the
   private-name patches Task 4 removed are not reintroduced.
