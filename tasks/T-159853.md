land here. **Two are built** — Stories-first ordering and the pace cap, both one term in the
existing launch key or one stop in `_launches`. **Two are held, with no code at all** — the
non-strict landing path (`P14`) and per-account cloud environments (`P13`) are already in the
kernel, and this Task's job is the test that stops the release losing them. The fifth, the flake
quarantine with its defect check, is **F-0336**'s, under this card's own Epic (`D16`, `PC13`); the
sixth, batching green PRs behind a strict trunk, is the spec's `Out` row — wiring
`asf/merge_queue.py`'s 3,114 lines into `decide` is exactly the rewrite the card puts out of scope,
and Task 10 writes that into `docs/KNOWN-ISSUES.md` as the one configuration 0.3 does not serve.

**Files**

- `asf/kernel/decide.py` — two clauses, both flagged. **Stories-first** (S-131015): `_launches`'
  `first` key (**`:1663-1664`**) gains one term **between the relaunch term and the rank**, exactly
  as §7 fences it — `(0 if started_story(iid) else 1) if config.stories_first else 0`, where
  `started_story(iid)` is true when another Task of the same Story (through `parent`, **or** a
  `stories:` naming, which is `decide`'s own definition of a Story's children) is Building, in
  Review or in Landing. With `kernel.launch.stories_first` off the term is the constant `0` and the
  order is **byte-identical to today's** (`D20`, S-131015's sixth line) — that is the one line that
  makes this safe to ship on by default, so write it first. The breach term stays first, so an item
  over its wait target still launches before every Story term (S-131015's third line), and a
  relaunch still beats a fresh Task of a started Story (its fourth). A Bug has no Story and is
  ordered by rank as today (its last). **Pace** (S-131016): `_launches` stops at
  `config.launch_per_tick` new launches when the key is set, **after** the breach-first and relaunch
  classes have had their places — so a pace never delays work that is already late (S-131016's
  second line) — and with the default `0` it never stops (`D21`, its third). When the product has a
  CI read the cap is `min(launch_per_tick, capacity.bandwidth(product)['ci_free'])`
