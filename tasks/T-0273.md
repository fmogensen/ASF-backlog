## Description
stories: S-29404
writes: asf/briefs/build.py, asf/briefs/templates/precheck.md, asf/roles/roles.py, tests/fixtures/briefs/golden/precheck.md, tests/test_briefs.py, tests/test_roles.py
after: Task 2

§2.5: the fourth registration a brief kind needs, four times — `KINDS`, a template whose every
placeholder is a context key, `MODEL_TABLE`, `roles.BINDINGS` — plus the level's own model row.
The guarantee the card asks for is one line of it: no level of this kind resolves to `HEAVY`, so
the pass is always cheaper than the round it precedes.

**Files**

- `asf/briefs/build.py` — `'precheck'` in `KINDS`; `'pre-check'`/`'prereview'` in `KIND_ALIASES`;
  the three level names in `MODEL_CLASSES`; the `'precheck'` row of `MODEL_TABLE`;
  `model_for(product, kind, item=None, cls=None)`; `model_table` passing `cls=`; `_class_item`
  deleted with its last caller (PD11); `precheck_level`, `precheck_why`, `precheck_dimensions`,
  `precheck_path` and `precheck_table` in `context`
- `asf/briefs/templates/precheck.md` — §2.5's template
- `asf/roles/roles.py` — `BINDINGS['precheck'] = 'asf-reviewer'`
- `tests/fixtures/briefs/golden/precheck.md` — the new golden
- `tests/test_briefs.py` — `ROWS['precheck']`; `PrecheckBriefTests`
- `tests/test_roles.py` — `for_kind('precheck')`

**Steps**

1. `KINDS` gains `'precheck'`; `KIND_ALIASES` gains `'pre-check': 'precheck'` and
   `'prereview': 'precheck'`. `ID_RANGE_KINDS` is **not** touched (§2.5): the pass mints nothing.
2. `MODEL_CLASSES` gains `precheck_mod.LEVELS`' three names, and `MODEL_TABLE` gains
   `'precheck': {'default': CHEAP, LOW: CHEAP, HIGH: LIGHT, MAX: LIGHT}` with the comment saying
   `HEAVY` is deliberately absent and why. The level names are imported from `asf.precheck`, never
   re-typed.
3. `model_for(product, kind, item=None, cls=None)`: `cls = cls or item_class(item)`, the rest
   unchanged — the override read, the `str` form, `_pick`. `model_table` becomes
   `{kind: {cls: model_for(product, kind, cls=cls) for cls in MODEL_CLASSES} for kind in
   MODEL_TABLE}` and `_class_item` is deleted (PD11). The launcher passes `row.precheck_level` as
   `cls` for this kind — one line where it already picks the model for a row.
4. `context` gains the five keys of §2.5: `precheck_level` (`row.precheck_level` or `HIGH`),
   `precheck_why` (`row.precheck_why` or the row's reason), `precheck_dimensions` (the numbered
   list, one line per dimension of that level), `precheck_path`
   (`conventions.precheck_path(slug)`) and `precheck_table` (`render_table(level)`). All five are
   set for every kind, as every other key is, so no template can reach a missing name.
5. `templates/precheck.md` is §2.5's markdown byte for byte, its fenced `asf precheck …` command
   included. The template names no product path and no worker account: the path arrives as
   `{precheck_path}`.
6. `roles.BINDINGS['precheck'] = 'asf-reviewer'` (D12) — no new role file; the reviewer's doctrine
   is the doctrine this pass needs, and the scope is the brief's.
7. `tests/test_briefs.py`: `ROWS['precheck']` — a `PUSHED → PRECHECK` row over the fixture record
   with `precheck_level='high'` and a `precheck_why` — so
   `test_every_kind_has_a_template_and_a_golden` and the two forbidden-name tests cover the new
   kind. Regenerate with `ASF_UPDATE_GOLDEN=1 python3 -m unittest tests.test_briefs`.
8. `PrecheckBriefTests` per §3.5: `build.build` over that row carries the level, every dimension
   of that level and **none** of a deeper one, the `precheck_path` from
   `conventions.precheck_path`, the table skeleton (which `precheck.parse` finds with one row per
   dimension and no fault beyond *unfilled*), and the `asf precheck … --level high` command with
   the level filled in. `model_for` for `precheck` is `cheap` at `low`, `light` at `high` and
   `max`, and — asserted over all three levels and the default — never `heavy`;
   `conventions.models.precheck: {low: light}` overrides only `low`;
   `doctor.model_table_lines(product)`
