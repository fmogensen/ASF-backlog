The spec's §*The design* §5: `commits_note` builds a `## Not proved` block from the one `git log`
it already runs.

**Files**

- `asf/harvest/lane.py`:
  - `commits_note` (**:495-517**): its docstring gains the spec's third clause naming
    `## Not proved`; `claims = proves.parse(…)` becomes
    `claims, refused = proves.parse_all(text)` over the same `text = '\n'.join(messages)`, and
    `gaps = refused + proves.parse_not_proved(text)` — refusals **first**, then declared gaps, so
    the block opens with what the coder did not mean to say. The existing `if claims:` block is
    unchanged, and `if gaps:` adds `'\n## Not proved\n\n' + proves.render_not_proved(gaps) + '\n'`
    after it. The `## Items` block, the `return ''` on `r is None or not r.ok`, and the single
    `git log --reverse --no-merges --format=%B%x1e` read are all untouched — one log, one pass,
    as before (spec P11).
  - `Host.open`'s `body += commits_note(…)` (**:4275**) is **not** changed; the block arrives
    through the string the function already returns. The body is not refreshed on a later push
    (spec **Out**, P11) and nothing here tries to.
- `tests/test_lane.py`:
  - `ProvesNote(LaneFixture)` added, on the bare origin, product checkout and worker clone
    `LaneFixture` (**:374**) already builds, with **two** fixture needs of its own the spec names:
    a push helper that gives a commit a **body** (`git commit -m <subject> -m <trailers>`), because
    `push_lane` (**:417**) writes a subject only and a trailer in a subject is not a trailer; and a
    `git fetch -q origin` in the product checkout before each read, because `commits_note` reads
    `origin/<trunk>..origin/<branch>` and the product checkout's remote refs are otherwise stale.
  - exactly the spec's seven cases: a whole claim gives `## Items` + `## Proves` and **no**
    `## Not proved`, byte for byte today's output; the card's qualified claim gives `## Not proved`
    with `- S-0021 line 6 — partial claim: "only" (tests/guard.test.ts …)` and **no** `## Proves`
    block at all, because there is nothing counted to put in one; one of each gives both blocks,
    `## Proves` first; a `Not proved:` trailer with no `Proves:` anywhere gives `## Not proved` and
    no `## Proves`; refused claims come before declared gaps in the block; a branch with neither
    gives `''` and a repo whose range cannot be read gives `''`, both unchanged; and two commits
    on the branch with the trailer on the **older** one still produce the block — the `--reverse`
    single-log read (spec P11).
  - `tests/test_lane.py` is run **whole** in the Gate because `commits_note` sits in the module
    whose fixture builds the lane and `Host.open` composes the body from it.

**Steps**

1. Baseline: `python3 -m unittest -v tests.test_lane` green, unmodified. Record the last line.
2. Write `ProvesNote`'s first case — the whole claim, today's output byte for byte — against
   unmodified code, and get the fixture right before changing any product code: the body-carrying
   push helper and the `git fetch -q origin`. A first case that fails here is a fixture fault, not
   a code fault; a `''` note means the fetch is missing.
3. Add the `parse_all` / `gaps` / `## Not proved` lines to `commits_note`.
4. Write the remaining six cases; watch each fail for the right reason — a `## Proves` block
   appearing on the qualified-claim-only case means `parse_all`'s halves were read the wrong way
   round.
5. Run the Gate.
