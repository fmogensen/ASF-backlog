The spec's last two `## In` bullets and `## The design` §§7–8: the Runners and Prod cells read
`provides:` where their hand-set key is unset, and `credentials.for_product` returns a connector's
provider beside the named ones. Unchanged by the cut — both read `provides:` and `check:`.

Read **PD4** before writing the `for_product` half — **re-measured for this replan and still true**:
nothing outside `asf/env.py` and the tests imports `asf.credentials`, so there is no daily
credential pass, no `NEEDS OPERATOR` line and no doctor row on the other end of that call, and
**this Task builds none of them**. Also **RD5** (this Task closes the `tests/test_connectors.py`
chain) and **PD17**.

**Files**

- `asf/views/status.py` — `runners_cell` (`:99`) and `prod_cell` (`:119`), plus the two
  `not_configured` texts
- `asf/credentials.py` — `for_product` (`:189-199`) only
- `tests/test_connectors.py` — `StatusCapabilityTests`
- `tests/test_credentials.py` — the provider list, and the name it does not double

**Steps**

1. `runners_cell`: `org = ci.get('runner_org') or connectors.provided(product, 'ci')[1].get('org')`,
   byte for byte from the design. `prod_cell`:
   `workflow = product.conventions.get('deploy_workflow') or connectors.provided(product,
   'deploy')[1].get('workflow')`. The hand-set key is **first** in both, so it wins (D6), and
   `provided` returning `(None, {})` is what makes the `[1].get(...)` safe. Both imports are
   function-local (PD14).
2. The `not_configured(...)` answers change **only their text**, naming the connector line to add as
   well as the key — the key first, the connector second, because D6 keeps the key first.
   `DEPLOY_WORKFLOW_KEY` (`:115`) keeps its value: `not_configured('ci.runner_org')` and
   `not_configured(DEPLOY_WORKFLOW_KEY)` are still the answer for a product with neither.
3. **Everything after those two lines is untouched** (P10, and the `## Out` list's fifth entry): the
   live run listing, the `git rev-list --count`, `ci_queue.runners_text`, `ci_pool.load_pool`,
   `deploy.lines` and the `? (…)` unreadable answers. A disagreement between a hand-set key and a
   connector's settings is `connectors.findings`' to report (T-0553), never an error and never a
   refusal here.
4. `credentials.for_product(product, cfg)`: after the named providers it already resolves, append
   `connectors.as_provider(c)` for every connector with a non-empty `check:`, **skipping any whose
   name a `credentials.providers` entry already took** — so a login shared across products stays
   declared once in `config.yaml` and is not probed twice. The `ConfigError` for a `credentials:`
   name `config.yaml` does not define is unchanged. Its docstring gains the second source and
   **names PD4**: no pass in the package calls this function today, so this is the seam for the day
   one is built, and the observable coverage F-0185 ships is the doctor's `connector:` rows
   (T-0553) and `asf connect` (`new 1`). Say the same in the commit body.
5. `StatusCapabilityTests`: the Runners and Prod cells read the connector's settings when the
   hand-set key is unset; the hand-set key still wins when both are set and disagree; a product with
   neither still prints `not_configured` naming the key; and the connector-named clause is in the
   text. Stub the live reads — `runners_cell` takes a `source=` and `prod_cell` reads through `_sh`
   — so neither test needs a network. **There is no `tests/test_status.py`**: the existing cell tests
