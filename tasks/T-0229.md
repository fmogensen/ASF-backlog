## Description
stories: S-29057
writes: asf/tick/step_health.py, tests/test_tick_steps.py
after: Task 4

§2.8's last clause, and the reason the wall-clock cap is enforceable at all: nothing in the
package calls `capped()` today, so the token ceilings have never bound either. `capped` stops the
run and appends its result line synchronously, so calling it **before** `health(fix=True)` means
the same tick that stops the run also ends its session with the reason; after it, the reason would
land a tick late (§1.4).

**Files**

- `asf/tick/step_health.py` — one line at the top of `run()`, and the module docstring's sentence.
- `tests/test_tick_steps.py` — `HealthEndsACappedRunTests` (T8).

**Steps**

1. `stall_mod.capped(product, out=out)` as the first statement of `run()`, before
   `health_mod.health(product, fix=True, …)`, with §2.8's comment: a run over a cap is ended here,
   not left.
2. The module docstring's opening paragraph gains the sentence — the step now ends a run over its
   caps before it reconciles the sessions.
3. `capped()` never raises on a malformed `token_caps:` (it prints and returns `[]`), so the step
   needs no guard of its own; nothing else in `run()` moves.
4. `tests/test_tick_steps.HealthEndsACappedRunTests`: a recorded call order proving
   `stall.capped` runs before `health(fix=True)`; one tick over a live session past its wall clock
   printing the `CAP` line, then health's `ended` line for the same job with `end_reason: failed:
   run cap`, and the `sessions` stream carrying that `result`; a tick with nothing live printing
   `cap: none` and being otherwise unchanged.
