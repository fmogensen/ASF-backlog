## Description
stories: S-38352
writes: asf/approvals.py, tests/test_approvals.py
after: none

The spec's §4. One token into `_READ_ONLY_PROGRAMS`, and its cases. After this Task the approvals
hook stops reading `printenv | grep -iE 'backlog|ASF'` as a *run* of whatever its pattern names:
an item id or a rule name inside that grep pattern is text the session searched for, never a
command it ran — the same false refusal F-0042 fixed for `grep`.

This Task's footprint intersects nothing else in the card, and it needs no registry. It runs in the
first wave beside Task 1. It is not the whole of S-38352 — the two `SELF_DIAGNOSIS` rules are
Task 3's — and that is why the Story is on both `stories:` lines.

**Files**

- `asf/approvals.py` — `_READ_ONLY_PROGRAMS` (`:444-450`): `'printenv'` appended after `'jq'`,
  the spec's §4 diff byte for byte. **One line of this file.** The `#:` block above it
  (`:440-443`) is not edited: its contract — *"a simple command running one of these runs nothing
  else and writes no file but through a redirection"* — is exactly what `printenv` satisfies, and
  restating it for one name would invite a reader to look for a difference.
- `tests/test_approvals.py` — the cases below, in the class that already covers `_read_only` /
  `_run_text` (find it by `grep -n 'READ_ONLY\|_read_only\|written_words' tests/test_approvals.py`;
  do not add a class beside an existing one that covers the same function).

**Steps**

1. The one-token edit.
2. The cases. `printenv` is read-only and `env` is **not** — assert both, because the second is
   the whole of C8 and nothing else in the card tests it: `env NAME=value <program>` runs a
   program, so a single rule or a single register entry for `env` is a rule that allows
   everything, and the register's own docstring is the reason `sed` and `awk` are out for the
   same shape of argument.
3. The second-order case, which is what §4 is actually for: a command whose text is
   `printenv | grep -iE 'backlog|ASF'` is not a *run* in `_run_text`, so the words inside the grep
   pattern are searched-for text and not commands. Assert it on the card's own evidence string.
4. `printenv > /tmp/x` is still a write — the register's contract is *"writes no file but through
   a redirection"*, and the redirection is what `_REDIRECTS` (`:462`) catches. Assert it, so the
   next person to read `printenv` as unconditionally safe finds the line that says otherwise.

**Gate**

```bash
python3 -m unittest -v tests.test_approvals
python3 -m unittest -q tests.test_install tests.test_doctor

```

**Acceptance** (the spec's §*Stories*, S-38352's own acceptance line, byte for byte — its
`tests.test_worker_perms.SelfDiagnosis` half is Task 3's)

> - S: A session can read its own environment — `Bash(printenv:*)` and `Bash(grep:*)` in `SELF_DIAGNOSIS` with `env` deliberately absent, and `printenv` added to `approvals._READ_ONLY_PROGRAMS` so a `printenv | grep <pattern>` is no longer read by the hook as a run of whatever its pattern names — acceptance: `python3 -m unittest -v tests.test_worker_perms.SelfDiagnosis tests.test_approvals`
