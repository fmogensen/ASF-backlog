The spec's `## The design` §3 whole, in one commit — the module and all four registrations together,
because `header.TITLES['coverage']` is only legal once the parser is registered (P20) and
`RENAMED['parity'] = 'coverage'` is only legal once `'coverage'` is a declared command (P7). After
it lands, `asf coverage [--reference <id>]` prints one reference's rows with gaps first, a `%` per
section and a `MISMATCHES` block when there are any; `asf parity` prints the first declared
reference through the alias, and today's PARITY table byte for byte for a product that declares none.

**Read PD6 before touching `asf/views/parity.py` — the answer is that this Task does not.** The
alias is a new function in the new module; `parity.py` is in no `writes:` line, which is what makes
C7's "byte for byte" a property of the diff. Then **PD13** (no `E-nnnn` literal and no
`feature-matrix` anywhere in the new module — both fences scan it, and `tests/` is exempt), **PD11**
(`parse_rows` drops a nine-cell row; that is today's behaviour and is not widened here) and **PD12**
(an `epic:` naming nothing is an empty table, not a fourth mismatch class).

**Files**

  spec's docstring; the row builders for `source: stories` and `source: file`; the three states; the
  four blocks (header, `GAPS FIRST`, `BY SECTION`, `MISMATCHES`); `cmd_coverage(args, root)` in the
  `cmd_prod` idiom (`asf/views/prod.py:248-252`); and the `parity` alias (PD6). It imports
  `area_key` and `STATE_STATUS` from `asf.views.parity` rather than copying them (P6 — `area_key`
  already sorts `1.2.10` numerically), `ix.load` for `index.json`, and `evidence.parse_rows` for
  `source: file`. No git, no `gh`, no network, no clock (C12).
- `asf/cli.py` — `p_coverage = sub.add_parser('coverage', …)` beside `p_parity` (`:307-308`), with
