## Description
stories: S-8401, S-8402, S-8405

**Files**: `asf/groom/policy.py`, `asf/groom/groom.py`, `tests/test_groom_policy.py`.

**Steps**
1. `Answer(word, field, value, why)` and the four policies with the §2.2 table's conditions and reason
   lines. `ctx` carries date, `now`, thresholds and `undecided_close` (`stage_limits`, default
   `14d`), plus the ledger's item set for `close_on_starvation`. No policy reads the clock or the config.
2. `POLICIES` in the §2.2 order. A test asserts its names equal `groom.POLICY_NAMES`.
   `groom.policies.<name>: off` skips that policy.
3. `barred(answer, item, product)` with the one-row table of §2.8, kept as data. A barred question
   gets no policy answer and its slot is rendered per PD4.
4. `cmd_groom`, only under `groom_auto`: after `process_inbox`, build the sections, run the policies,
   and render each answer as `→ answer: controller: <policy> <word>`. Write the file, then apply it
   through `apply_groom_answers` against that file (D3). Rebuild `canonical`/`derived` before `do_index`.
   The printed line gains `by rule N` (PD10).
5. Tests: `PolicyTests` (T2), one answering and one nearest-miss case per policy. `PolicyPassTests`
   covers T3 and T4 (cards only; Task 6 adds the digest half of T4). `ApprovalBoundTests` covers
   the policy half: with `new_epic: human-now`, an Epic inbox card gets no answer and its line is not in `open_questions`.
