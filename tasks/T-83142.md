## Description
stories: S-73204
writes: asf/feeder/rows.py, tests/test_doc_lane_review.py
after: none

The spec's §1, whole, and nothing else. This Task is what the four PRs in the card are waiting
for: after it lands, a Feature whose `spec/`, `plan/` or direct branch the lane holds in `REVIEW`
draws the `PUSHED → REVIEW` row at the round the lane asks for, and exactly one row (**PD4**). It
adds no field to `Row` and touches no other module, so it is green and useful on its own
(**PD10**).

**Files**

- `asf/feeder/rows.py` — `FEATURE_LANES` beside `DIRECT`; the gate in `lane_rows`; `lane_speaks`;
  `direct_row`'s opening check; the filter in `_one_feature_rows`; `pushed_ids`; `_pushed_branch`
  and its use in `pushed_rows`.
- `tests/test_doc_lane_review.py` — new. `TheFeatureLaneRows` only; the other two classes are
  Tasks 2 and 3's (**PD7**).

**Steps**

1. `FEATURE_LANES = (DIRECT, 'spec', 'plan')`, beside `DIRECT`, with the spec's comment: the
   branch kinds a Feature's own lane branch carries. A Task's or Bug's branch is never one of
   these.
2. `lane_rows`' gate reads the branch, not the id — the spec's §1 replacement, byte for byte:
   `feature_lane = (item.get('type') == 'feature' and _conventions(product).branch_kind(h.get('branch') or '') in FEATURE_LANES)`,
   then `if item.get('type') not in ('task', 'bug') and not feature_lane: continue`. Everything
   after the gate is untouched: `REVIEW` still draws `PUSHED → REVIEW` at
   `int(h.get('round') or 1)` with `brief_kind='review'`, any other open state still draws
   `PUSHED → LAND` naming the state, and `docs_only_task` is left exactly as it is — its own type
   check refuses a Feature (`asf/harvest/lane.py:489`), so no clause is needed for the
   Feature case. `branch_kind` returns None for an unknown prefix and `'legacy'` for a retired
   one, neither of which is in `FEATURE_LANES`, which is the "no known prefix draws no row" line.
3. `lane_speaks(fid, occupancy)` — the spec's §1 function with its docstring verbatim: true while
   `fid` is in the occupancy's `review` or `landing`. One rule, one place.
4. `direct_row`'s opening check becomes `if lane_speaks(fid, occ): return None` — the same
   predicate it spells out today (`rows.py:1725`), now named.
5. In `_one_feature_rows`, after `out` is built and before it is returned,
   `if lane_speaks(fid, occupancy): out = [r for r in out if r.kind not in (PUSHED_LAND, APPROVED_LAND)]`,
   with the spec's comment and one line more recording **PD5**: every row of those two kinds
   reachable from here is the Feature's own (`_doc_row`, `replan_row`, `direct_row`,
   `spec_plan_row`, `land_doc_row`), and `task_rows` emits neither — which is why filtering by
   kind alone is enough to keep a `building` Feature's Task rows.
6. `pushed_ids` admits a Feature an occupancy key names, and nothing else about it changes — the
   spec's §1 comprehension, byte for byte. The open-PR clause stays Task/Bug only (C4): a
   Feature's evidence lines are `spec on …`/`plan on …` and never carry `PR #N OPEN`, so a clause
   for it could not fire.
7. `_pushed_branch(items, product, occupancy, iid)` with the spec's docstring: the branch the
   occupancy entry that named `iid` carries — `review`, `landing`, `back`, then the `lanes` map —
   else `_branch_of(item, product, kind)` as today. `pushed_rows` calls it instead of
   `_branch_of`, and **returns no row for a Feature no occupancy entry names a branch for**: its
   own document row already speaks for it. Nothing derives `spec/`, `plan/` or the direct prefix
   from the item's type (C5) — `_branch_of` maps any non-Task to the fix lane, which is the
   `fix/F-0280` of P9.
8. Write `TheFeatureLaneRows` to the ten acceptance lines of S-73204, one case each, over an
   occupancy built the way `asf.workers.lifecycle.occupancy` builds one for a document branch in
   lane `REVIEW` — the `review`, `lanes`, `waiting_landing`, `branches` and `docs` keys together,
