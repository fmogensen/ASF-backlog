What makes a whole tree fileable before a single id exists (D3), and the end-to-end test that the
front door's output is an Epic with Features, Stories and acceptance — the card's first acceptance
line. Runs after Task 2 (`tests/test_idea.py`).

**Files**

- `asf/groom/shape.py` — `Card` gains `assumptions` (`asf/groom/shape.py:11`).
- `asf/groom/inbox.py` — `parse_inbox_file` lifts `## Assumptions`; `process_inbox` resolves
  `parent: inbox:<file>` and passes the new section (`asf/groom/inbox.py:52-80,125-165`).
- `tests/test_inbox_shape.py` — new `ForwardReferenceTest`.
- `tests/test_groom.py` — `## Assumptions` surviving intake into the minted card.
- `tests/test_idea.py` — `IdeaToGroomTest`.

**Steps**

1. `Card = namedtuple('Card', 'title headers description features acceptance assumptions')`, and
   `parse_inbox_file` lifts `Assumptions` with the existing `_lift_section` beside `Features` and
   `Acceptance`. Every construction site of `Card` passes the sixth field.
2. `process_inbox` keeps a `minted = {}` map, file name → id, filled as it mints (it already walks
   `sorted(os.listdir(...))`, `asf/groom/inbox.py:125`, so a parent filed with a lower-sorting name
   is minted first).
3. Before `derive` is called on a card whose `parent:` starts with `inbox:` (PD9):
   - the named file is in `minted` → replace the header with that id and carry on;
   - the named file is still in the intake directory → `continue`: untouched, unquestioned, and
     picked up by a later pass once its parent is minted (D4);
   - neither → the existing Question path, `parent: names an intake card that is not there:
     <name>`.
4. `write_new_item(..., sections={'Features': card.features, 'Assumptions': card.assumptions})` —
   ordered, and rendered immediately above `## Acceptance` (`asf/record/ids.py:75-91`, PD10).
5. `IdeaToGroomTest` drives `asf idea … --no-interrogate` (Task 2's flag) against a fixture tree,
   then `asf groom`, then `asf index` and `asf check`.
