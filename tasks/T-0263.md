§2.2 whole: the page rewritten into the three parts `asf/views/readme.py` already enforces, with
every measurement in a span and the facts file committed beside it. This is the half of F-0030 that
never landed (P2), written once, here, by the card the page is *for* (D2).

Waits on Task 1 because `readme._commands_rows` reads the parser, so the `commands` block must be
refreshed after `asf pages` is registered (§2.6), and on Task 2 because T5 requires
`tools/quickstart.sh` to exist and be executable.

**Files**

- `README.md`
- `docs/readme-numbers.json`

**Steps**

1. Keep the page's title and its closing *Not "ASF" the Apache Software Foundation* line. Write the
   three `##` parts, exactly `readme.HEADINGS` and in that order: `## The argument`,
   `## The mental model`, `## The manual`.
2. `## The argument` — the four claims of §2.2's table, each standing on the span or the link that
   supports it and nothing else (D11): the `scoreboard` block, the two links to the public record's
   `ROADMAP.md` and `SCORECARD.md`, the `cost_per_feature` block and the `usd_per_feature` span, and
   `### Quick start`. A claim with neither a span nor a resolving link is not written.
3. `## The mental model` — the six sentences the page already carries as its opening paragraph (one
   record with typed intent and derived state; rules as checks; code decides what runs when, agents
   only write and judge; multi-product from day one; the factory builds itself through the same
   mechanism it offers you), and the `cost_per_feature` block.
4. `## The manual` — four `###` sections, four to eight lines each, which are what closes the release
   gate's docs criterion (D3, P7) and what a first-time reader looks for: `### Install` (the `pipx`
   and installer lines the page already carries), `### Quick start` (one fenced block, exactly
   `bash tools/quickstart.sh`, plus what the reader will see — D12), `### Configuration`
   (`~/.ASF/config.yaml` and `~/.ASF/products/<product>.yaml`, linking
   `docs/guide/product-config.md`), `### Upgrade` (the installer re-run at a new ref, linking
   `docs/guide/upgrading.md`). Then the `commands` block, the repository's layout, the license and
   the credit line.
5. The layout list names only directories that exist: `asf/`, `plugin/`, `docs/`, `sample/`,
   `tools/`, `tests/`. `rules/` and `evals/` are removed — neither exists in this checkout, and
   §1.2 is explicit that nothing is created to make a sentence true.
6. Every measurement goes in an `asf:n` or `asf:block` span. No digit run in prose outside a span,
   inline code, a link target or `LITERALS` (`0.1`, `2.0`): *twenty minutes*, *eight criteria*,
   *three parts*, in words (D4).
7. Run `asf readme --refresh` in this worktree — after Task 1 has landed, so the `commands` block
   holds the `pages` row — which writes `docs/readme-numbers.json` and renders every span's body from
   it. The page and the facts file are then byte-identical to what the renderer produces. No number
   is typed and none is carried over from the spec's §2.2 example. If the record does not resolve in
   the session's environment, the Task prints `NEEDS OPERATOR: the committed numbers need a refresh
   against the factory's own record — asf readme --refresh --product <the factory's product>` and
   hand-fills nothing.
8. The page fits 150 lines and 10,000 bytes. The `commands` block is one row per top-level
   subcommand plus two header lines and is the largest single block on the page; the Task measures it
   from the parser and cuts *prose* to fit. §2.4's rule stands: the budget is never met by moving
   prose into `docs/` and never by trimming a generated block. If the remaining budget cannot carry
   the three parts, the Task reports it rather than dropping a block or raising `MAX_LINES`.
