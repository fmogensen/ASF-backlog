## Description
stories: S-7306, S-7307
writes: asf/tick/steps.py, asf/tick/tick.py, tests/test_tick_steps.py

**Files**
- `asf/tick/steps.py` — `run_command(…, env=None)`
- `asf/tick/tick.py` — `_run_steps`: the CI hold on `batch`, the overlay on every command step
- `tests/test_tick_steps.py` — new classes `BatchStep`, `CommandStep`

**Steps**
1. `steps.run_command(step, command, timeout, emit=print, cwd=None, env=None)`: when `env` is
   given, `Popen(..., env={**os.environ, **env})`; otherwise unchanged (P3). Name the parameter
   so it does not shadow the module's `from asf import env` inside the function (e.g.
   `extra_env`), keeping the call sites readable.
2. `tick._run_steps`, for a command-owned step: resolve once per tick lazily (only when a command
   step runs), then
   - `step == 'batch'` and `r.ci is not None` and `r.ci_inflight is not None` and
     `r.ci_inflight >= r.ci` → print `waits    batch — at ci capacity (<inflight>/<ci>)`, skip
     the command, `step_rc = 0`, and record the step as ran-ok;
   - otherwise run the command with `extra_env=capacity.env_overlay(r, product)` — §2.6's tree,
     D8 (unknown runs), D9 (unconfigured runs, and no `gh` call because the resolver makes none).
   The overlay is passed to **every** command step, not only `batch`.
3. `tests/test_tick_steps.py`: `BatchStep(StepsTestCase)` with the four tests of §3.4 (stub
   `asf.capacity.resolve` / inject a CI source; `no_ci_capacity_configured_makes_no_gh_call`
   patches `subprocess.run` for `gh` and asserts it was never called); `CommandStep` with
   `test_the_capacity_overlay_is_in_the_command_environment` — a command step running a tiny
   script that prints `ASF_CAPACITY_SESSIONS`, asserted in the `[command:<step>]` output.
