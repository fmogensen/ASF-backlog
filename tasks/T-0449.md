after: Task 4

The spec's §5 steps 2, 6 and 7 plus D14's last piece: `--to` resolves both products the way
`resolve_product` owns (D16), writes `moved_to:` on the source cards, files each in the target's intake
dir with a `moved_from: <source>:<ID>` ref, skips one already there, and commits the target record on
its own (D15). Then `INBOX_KV_RE` learns `moved_from` so the ref lands on the minted card and the
dedupe outlives the intake file.

**Files**

- `asf/record/move.py` — `--to` in the required group, `resolve_target`, `intake_file`, `dedupe`, steps
  6-7 of `cmd_move`, the table's TARGET column
- `asf/groom/inbox.py` — `INBOX_KV_RE` gains `moved_from`; `process_inbox` carries it onto the card
- `tests/test_move.py` — `MoveToTargetTests`, `DedupeSurvivesMintingTests`, the `--to` case in
  `DryRunTests`
- `tests/test_inbox_shape.py` — an intake file with `moved_from:` types a card that carries it

**Steps**

1. `--to PRODUCT` joins Task 4's required mutually exclusive group, and `_published`'s message gains
   its half: `f"move: {n} cards moved to {args.to}"`.
2. `resolve_target(args, root)` (step 2, D16): `env.load_product(args.to)` — a `ConfigError` is one
   `cli.needs_operator_line` line and exit 2, never a traceback and never a guess. `--to` naming the
   source product refuses. The source name is `env.resolve_product(args.product).name`, and the product
   it names must be the one whose `backlog_dir` is `root` — compared by directory identity
   (`st_dev`/`st_ino`) as `product_of_dir` compares (`asf/env.py:445-460`), not by spelling — else
   `error: --to needs the source product's own record — <root> is not <name>'s backlog_dir`. The name
   is written into every `moved_from:` ref, so a wrong one makes every future dedupe on the target miss.
3. The source write (§5's table, `--to` row): `set_typed(rec, {'moved_to': args.to, 'belongs_to': None},
   writer='move')` — P5's product-only form, because the target's id does not exist until the target's
   groom mints the card — and the History line
   `- <date> move: moved to <p> — <p>:<intake file>`.
4. `intake_file(target, card, source_name)`: `<target backlog_dir>/<target conventions.intake_dir>/
   <slug>.md`, the slug named and `-2`/`-3`-suffixed exactly the way `cmd_inbox` names a taken one
   (`asf/groom/inbox.py:118-140`, P16). Contents are §5's markdown: the title through
   `inbox.scrub_title`'s redaction filter before it is written into another product's record, then
   `moved_from: <source>:<ID>`, `type:` from the source card, a Bug's `signature:`/`severity:` or a
   Task's `writes:`, the source card's `## Description` verbatim and its `## Acceptance` — and **never**
   `parent:` (D13): an id is meaningless in another record, and the target's intake asks its own parent
   question on its own groom day.
5. `dedupe(target_root, intake_dir, ref)` — one function, True when any `*.md` in the intake dir **or**
   its `done/` subdirectory carries the `moved_from: <ref>` line, **or** the target's `index.json` holds
   an item whose `moved_from` is `<ref>`, falling back to `load_items(target_root)` when the target has
   no `index.json` yet. A card that dedupes is skipped and counted for the table's
   `already there (<id>)` cell and the footer.
6. Step 7 (D15): `before = publish.snapshot(target_root)` taken before the first intake file is
   written, then `publish.publish_changes(target_root, before, f"move: {n} cards from {source} —
   inbox")` after the last — signed off and pushed, warning on stdout when the push is refused exactly
   as the source's does. Two records, two commits: one commit across two git repositories does not
   exist, and an intake file left uncommitted would never reach the target's tick, which resets its
   clone to origin.
