## Description
stories: S-8001, S-8003
writes: asf/evidence/evidence.py, asf/metrics/metrics.py, tests/test_evidence.py

**Files**
- `asf/evidence/evidence.py` — the purge and the rewiring.
- `asf/metrics/metrics.py` — `deploy_runs`, the release-note line.
- `tests/test_evidence.py` — three new classes, one restated assertion (PD4).

**Steps**
1. Module docstring: the three `~/.claude-workers/tools/*.py` provenance lines become "lifted from
   the first product's pre-asf board, parity and tick-table scripts" — no path, no file name. The
   sentence naming `deploy-prod.yml`, `ci.yml` and the `deploy-dev` job says instead: the newest
   successful run of `conventions.deploy_workflow` for `prod_sha`; the newest run of
   `conventions.ci_workflow` on the trunk whose `conventions.ci_dev_job` succeeded for `dev_sha`.
2. Delete `PR_CACHE`, `EVIDENCE_CACHE`, `PLANS_DIR`, `SPECS_DIR`, `BRIEFS_DIR`, `REVIEWS_DIR`,
   `MATRIX_PATH`, `SDD_DECISIONS`, `HOTFIX_RE`, `DESIGN_SPEC_NAME`, `DEFAULT_BRANCH_PREFIXES`,
   `conv_dir`. `PR_TTL` and `EVIDENCE_TTL` stay.
3. `_cache_file(name, product)` → `os.path.join(env.state_dir(product), 'cache-' + name)`; no
   product name → `ValueError`. `pr_list` passes `'prs.json'`, `load` passes `'evidence.json'`.
4. `branch_prefixes(product)` returns the same dict shape from the object: `conv.prefix(kind)`
   for `code`, `fix`, `spec`, `plan`, and `list(conv.legacy_prefixes())` for `legacy`.
5. `discover()` reads `conv = product.conventions` and takes `plans_dir`, `specs_dir`,
   `reviews_dir`, `briefs_dir`, `matrix_path` off it. `read_trees` lists `briefs_dir` only when
   it is not `None` (`main_briefs = {}` otherwise, `brief_dirs` stays empty); the parity-matrix
   block runs only when `matrix_path` is set, else `stories = {}`.
6. The deploy-sha block becomes two helpers taking the name as a parameter —
   `_newest_success(workflow)` and `_newest_with_job(workflow, job, branch)`, today's inline code
   unchanged otherwise — called only when the conventions carry the names:
   ```python
   prod = _newest_success(conv.deploy_workflow) if conv.deploy_workflow else None
   dev = _newest_with_job(conv.ci_workflow, conv.ci_dev_job, branch=product.main) \
         if conv.ci_workflow and conv.ci_dev_job else None
   ```
   `ci_green_runs` is untouched: it already asks for successful runs on the trunk without naming
   a workflow.
7. `migrate_sources(product, design_spec_name=None)`: `design_spec_name` falls back to
   `conv.design_spec_name`; the specs tree uses `conv.specs_dir`; the decisions text comes from
   `conv.decisions_file` (`None` → `None`, no ref read); hotfix reports come from
   `conv.reports_dir` (`None` → `{}`) with names matched by `re.compile(conv.report_pattern)`
   when set, else every `*.md`. The `design_spec_name=` parameter stays for `migrate`'s tests.
   The parsers (`parse_rows`, the D-row and hotfix shapes) are untouched — only their locations
   move (spec, Out).
8. `asf/metrics/metrics.py`: `deploy_runs(repo_slug=None, product=None)` takes the workflow from
   `_resolve_product(product).conventions.deploy_workflow` and returns `[]` when it is `None`;
   `render_release`'s line reads `Deployed sha … (deploy finished …)` with no workflow name.
   `tests/test_metrics.py` mocks `deploy_runs` at every call site, so it is not in this diff.
9. Tests: `SecondProductDiscoverTests`, `MigrateSourcesTests`, `CacheTests`, exactly the cases the
   spec names. Restate `tests/test_evidence.py:497` for `cache-evidence.json` (PD4). `FIRST_TOKEN`
   already builds from a `Product` and needs no change (PD11).
