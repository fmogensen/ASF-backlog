The spec's **In** 3 and its design §4: the one edge P10 says is missing, in the idiom P11 says the
repo already uses. `after: Task 2` is real — the job runs `asf rehearse`, and a job calling a
command that is not on the trunk is red on every push to `main`. `after: Task 5` is an ordering
edge and nothing more: it makes Task 6 the Task that completes the spec's S-79608 fence, so that
fence has one owner and is copied whole into one Acceptance block.

The job goes in `release.yml` and **not** into a new workflow file: `release.ci_runs` does not
filter by workflow, and a `needs:` cannot reach across workflows, so a second workflow would give
the gate neither of its two readers.

**PD15** binds this Task and reaches no card: `tests/test_version.py` is in its footprint because
that is where this repo pins `release.yml`'s shape, and because without it Task 7's
`(parent, stories, writes)` would equal this Task's and Task 7 would never be minted. The test
asserts the **permanent** half only — the job, the step name, the two `needs:` edges — and never
the `continue-on-error` line, so Task 7 removes that line and touches no test.

**Files**

- `.github/workflows/release.yml` — the `rehearsal` job of §4 verbatim in shape: `if:
  github.event_name != 'workflow_dispatch' || github.ref == 'refs/heads/main'`, `checkout` with
  `fetch-depth: 0`, `setup-python` 3.12, `pip install --quiet .`, then a step named exactly `release
  rehearsal` (the name `release.ci_steps.rehearsal` reads) setting a `git` identity and running `asf
  rehearse`. That step carries `continue-on-error: true` while the Bug cards the first red run files
  are open (C9) — Task 7 removes it, and nothing else about the job changes then. `release` (`:39`)
  and `preview` (`:93`) each gain `needs: [rehearsal]`, spelled exactly that way: the spec's fence
  counts the literal string and expects 2.
- `tests/test_version.py` — beside `test_the_release_workflow_runs_on_every_push_to_main_and_on_prs`
  (`:245`), which already reads the file through `_release_yml()` (`:254`): the `rehearsal` job
  exists, its step is named `release rehearsal` and runs `asf rehearse`, both `needs: [rehearsal]`
  edges are there, and the job's `if:` admits a push to `main` and a pull request while refusing a
  `workflow_dispatch` of another ref. Nothing about `continue-on-error` (PD15).

**Steps**

1. Add the job. Check the `if:` against the two jobs it gates: `preview`'s own `if` is
   `github.event_name == 'workflow_dispatch' && github.ref == 'refs/heads/main'`, so on a dispatch
   of `main` the rehearsal job runs and `preview` waits on it; on a dispatch of any other ref both
   are skipped; on a push to `main` the rehearsal job runs and `release` waits on it; on a pull
   request the rehearsal job runs and `notes`, which has no `needs:`, is unaffected.
2. `needs: [rehearsal]` on `release` and on `preview`, and nowhere else.
3. `continue-on-error: true` on the `release rehearsal` step, with a comment naming C9 and Task 7.

4. The assertions in `tests/test_version.py`, on the permanent half only.
5. Add **no second workflow file** and change `tests.yml` not at all.
