## Description
stories: S-30561
writes: asf/rules/rules.py, asf/cli.py, tests/test_rule_hooks.py
after: Task 6

§2.12's second half. One table, no new metrics stream: `metrics.STREAMS` is a closed set with a
validating schema, and the refusal rows already go to the product's existing `approvals.jsonl`
ledger (§1.2).

**Files**

- `asf/rules/rules.py` — `cmd_hooks(args, root)` and the reads it needs. The table of §2.12:
  a header `== RULE HOOKS  <n> declared, <n> installed in <n> accounts, <n> unresolved` and one
  row per rule with `rule`, `event`, `installed` (`<k>/<n accounts>`, from
  `hooks.rule_hooks_missing`), `refused(Nd)` (rows with `event == 'refused-rule'` and that `rule`
  in the window), `errors(Nd)` (`rule-hook-error`) and `violations(Nd)` (Bugs `asf file-bugs`
  opened for that rule id in the window). `refused` renders `—` for a rule that cannot refuse —
  R-0006, whose rc is always 0 (D9) — rather than `0`, which would read as "enforced and never
  triggered". `--days` narrows the window, `--json` carries the same numbers, and a product with
  nothing installed renders `0/<n>` in `installed` and does not render as healthy. The declared
  set is `hooks.declared_hooks()`; the ledger comes through `approvals.read(product)`; the counts
  are seven, not six (PD5).
- `asf/cli.py` — three changes (PD14): `choices=['check', 'hooks']` on `rules_command`, a
  `--days` argument, and a branch on `args.rules_command` at `:496-498` so `hooks` dispatches to
  `cmd_hooks` and `check` keeps dispatching to `cmd_check`. `asf/rules/rules.py`'s own
  `build_parser`/`main` gets the same `hooks` subparser, so `python3 -m asf.rules.rules hooks`
  works the way `check` does.
- `tests/test_rule_hooks.py` — `MeasureTests`.

**Steps**

1. `cmd_hooks` and its reads in `asf/rules/rules.py`, then the `build_parser` subparser.
2. `asf/cli.py`: the widened choices, `--days`, and the dispatch branch. Assert by hand that
   `asf rules check` still runs the check — the dispatch change is the one place this Task can
   break something that already works.
3. `MeasureTests`: the §2.12 table over a seeded ledger and a seeded Bug set with all columns;
   `--days` narrowing the window; `--json` carrying the same numbers; and `0/<n>` for a product
   with nothing installed, not rendering as healthy.
