## Description
stories: S-36851
writes: asf/workers/caches.py, asf/doctor.py, tests/test_cache_prune.py
after: Task 1

The spec's `asf doctor` row: `caches.doctor_line(product)` rendered off `caches.json` alone, and
`doctor.check_caches` appending one row after `branches`. The row measures nothing and touches
nothing — `worktrees.doctor_line`'s docstring is the contract this inherits, and its own
`pnpm store: <path>` clause is the precedent for naming an absolute path in a doctor detail
(`asf/workers/worktrees.py:371-402`; doctor output is printed to an operator, never committed —
`doctor.run` has exactly one caller in the package, `asf/install.py:314`).

Read **PD3** (an absent directory is green, a non-directory is red), **PD5** (`bytes`/`entries`
are what remains, so "still over its cap" means something), **PD9** (this Task fills
`doctor_line`'s body; `asf/doctor.py` is this Task's alone) and **PD11** (no `not_configured`
call, and the phrase *not configured: <key>* in no docstring) before starting.

**Files**

- `asf/workers/caches.py`
  - `doctor_line(product)` — the body: `(ok, detail)` off `read_state`, None before a pass has
    run. `detail` names the variable, the size, the entry count, what the last pass removed and
    when. `ok` is False exactly when a directory carries a `problem`, is still over its cap, or
    `failed` is non-empty — and True for an `absent` directory (**PD3**) and for a missing hit
    rate (`test_no_summaries_is_said_plainly_and_is_not_an_error` asserts it, in Task 3)
- `asf/doctor.py`
  - `check_caches(product)` — new, beside `check_branches` (`:1012-1020`), the same four-line
    shape: import inside the function, `return caches.doctor_line(product)`, `(OSError,
    ValueError)` → None
  - `run` (`:977-981`) — the row after `branches`' and before `return rows`, appended only when
    `check_caches` is not None, exactly as `branches` is
- `tests/test_cache_prune.py` — `class CacheDoctorRow(CacheFixture)` and its five tests, the
  spec's block byte for byte

**Steps**

1. `doctor_line`'s body. One clause per directory from the state file, joined — the variable, the
   `_gb` size, `N entries`, `pruned K (X GB)` and the pass's `at` stamp; a directory carrying a
   `problem` renders its reason verbatim, which is what `'not an absolute path'` in the fenced
   test reads. The detail for `test_the_row_carries_the_size_and_what_the_pass_did` must satisfy
   `assertRegex(detail, r'\d+\.\d GB')`, so the one-decimal GB of **PD6** is load-bearing here
   too, not cosmetic.
2. The `ok` rule, all three limbs. The over-cap limb is the one **PD5** pays for: compare the
   state's post-pass `bytes` against `max_size_gb`, so a pass that got the directory under its cap
   is green and one blocked by the floor is red with `over` in the detail — which is exactly
   `test_the_row_is_red_while_the_directory_is_still_over_its_cap`, where 8 MiB survives a
   1073-byte cap because it was written this second (C4's floor).
3. `check_caches`, then the row. Copy `check_branches`' four lines — including its `(OSError,
   ValueError)` catch, which is why an unreadable state file is a missing row rather than a
   traceback out of `asf doctor`. No `not_configured` (**PD11**).
4. `CacheDoctorRow`, byte for byte. `test_the_row_measures_nothing_itself` is the one that pins
   the contract: it grows the directory by 60 MiB after the pass, calls `check_caches`, and
   asserts the state file is unchanged *and* the new entry still exists — the row neither
   re-measures nor prunes.
