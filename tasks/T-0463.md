The spec's eleventh **In** bullet and its `### The guides` block. Three passages tell the operator to
hand-merge ASF's line into their hook (P14); after Tasks 1–3 that is only true under `--no-chain`.
Last in the wave, because the prose describes what `asf hooks uninstall` and the doctor's row say on
a terminal, and neither exists until Tasks 2 and 3 land.

**Files**

- `docs/guide/product-config.md` — the "Redaction hooks" section (`:622-668`)
- `docs/guide/troubleshooting.md` — the refusal row (`:45`) and the two paragraphs at `:78-84`
- `docs/guide/getting-started.md` — step 3's line (`:64`)
- `docs/guide/upgrading.md` — the idempotence row (`:114`)

**Steps**

1. `docs/guide/product-config.md:622-668` says the install **chains by default**: what `<hook>.local`
   is, that ASF's gate runs first and the renamed hook after it with the same arguments, that a
   `pre-push` gets the same refs because they are buffered once and read twice, that
   `asf hooks uninstall --product <p>` puts the original back, and that in a tracked `core.hooksPath`
   directory (`:643`) the rename is an ordinary working-tree change the operator commits — the
   install prints the two paths so there is nothing to discover, and stages nothing (Out). The
   refusal at `:637` becomes `--no-chain`'s, and the two hand-merge examples at `:655` and
   `:666-667` stay exactly where they are, under `--no-chain`, as what you do if you would rather
   merge by hand.
2. `docs/guide/troubleshooting.md:45` — the `is not asf's` row becomes `--no-chain`'s, and two rows
   join it: `NEEDS OPERATOR: <path>.local is already there — …` with "move it aside or merge the
   two, then rerun" as the remedy, and the doctor's `<path> chains <name>.local, which is not
   there` with "restore your own hook, or `asf hooks install --product <p>` to write ASF's alone".
3. `docs/guide/troubleshooting.md:78-84` — the `.githooks/pre-commit` paragraph points at the one
   command, and **"An existing `pre-push` stops receiving refs"** becomes one line saying it does
   not: the install chains and buffers, and only `--no-chain` leaves you the merge that
   product-config.md describes.
4. `docs/guide/getting-started.md:64` and `docs/guide/upgrading.md:114` — one clause each: step 3
   chains a hook already there rather than refusing it, and `asf hooks install` is still idempotent
   (a second run changes no file, not the hook and not the `.local`).
5. No example in any of the four is left claiming a behaviour Tasks 1–3 did not build: every command
   line quoted in the changed passages is run by hand against a scratch repo before the Task is
   done, and the `asf hooks uninstall` message quoted is the one `uninstall` prints.
