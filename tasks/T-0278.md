## Description
stories: S-29652
writes: asf/tick/step_wave.py, tests/test_tick_steps.py
after: Task 1, Task 2

§2.4. Two lines in `launch()`, placed so that the per-Epic line cannot go quiet on the tick where
it matters most: it is derived from the index, and the rows it explains are derived from the plan
(D5, P13). One `budget_hold` event per held Epic per wave, through `ctx.event` — a free-form JSON
line, no stream schema to extend (§1.1, §4).

**Files**

- `asf/tick/step_wave.py` — `budget` added to the module's `from asf import approvals, env`
  (`:66`); the two lines of §2.4 in `launch()`, directly after
  `planned, dropped = gated_plan(…)` (`:663`) and before the `share_held` loop (`:672`).
- `tests/test_tick_steps.py` — `EpicOverBudgetWaveTests` (new), on `StepsTestCase` — it already
  has `write_config`, a patchable plan and `self.events(ctx)` (`:307`, `:775`).

**Steps**

1. `from asf import approvals, budget, env` (`:66`). `asf.budget` is a leaf and `step_wave`
   already imports `asf.workers.lifecycle`, which imports it — no new edge in the graph.
2. In `launch()`, directly after the plan is made (`:663`) and before the first `waits` line,
   exactly §2.4's two statements over `feeder_rows.epics_over_budget(items)`:
   `ctx.event('budget_hold', item=s.epic_id, spend=s.usd, budget=s.budget)` then
   `out(budget.epic_line(s))`. `feeder_rows` is already imported at the top of the function
   (`:644`), and `items` at that point is the tick's own overlaid index (`:669-672`) — the same
   map the feeder gated on, so the Epic's line and its rows' lines can never name different
   figures. The comment says why the figures come from `items` and not from `planned` (D5).
3. Nothing else in `launch()` moves: no branch, no seat, no event order change beyond the new
   line, and the `capacity` event still leads the wave's own stream.
4. `EpicOverBudgetWaveTests` per §3.3, capturing `out`: over the feeder fixture with `E-0001`
   pushed past its budget, exactly one line starts `OVER BUDGET E-0001` whatever the number of
   held rows, and its index in the output precedes every `waits` line for those rows. With **zero
   free seats** — `capacity.resolve` patched to `sessions=0`, or `capacity:\n  total:\n
   sessions: 1` against one in-flight session, both of which `WaveStep` already does (`:793`,
   `:857`) — the `OVER BUDGET` line is still printed: the §1.1/D5 regression, and the reason P13
   put the call where it is. One `kind: budget_hold` object is appended to
   `metrics/events/<day>.jsonl` in the record clone with `item`, `spend`, `budget`, `product` and
   `ts` (the last two `ctx.event`'s own, `asf/tick/tick.py:182`), and every line of the file
   parses as one JSON object. An Epic under its budget prints no line and writes no event. Two
   Epics over budget print two lines in id order and write one event each.
