The spec's guide section: the paragraph F-0122's Task 6 leaves where the *pull before you read*
one was gains its last sentences, saying that the sha is an **identity** and not a freshness
check, and how the two shas on a fallback line are read. Prose about the exact string Task 1
makes `line` produce, so it lands after it and quotes it rather than paraphrasing.

**Files**

- `docs/guide/operating.md` — the paragraph F-0122's Task 6 leaves at the opening, gaining the
  spec's four sentences
- `tests/test_readme.py` — new `RecordShaProseTests`

**Steps**

1. Append the spec's diff (`docs/specs/f-0155.md:245-254`) to that paragraph, as a new paragraph
   under it: the `@ 9f8e7d6` after each path is that copy's HEAD; it is an identity, not a
   freshness check; quote it when you report what a table said; when the line names two copies the
   two shas are how far apart they are, and
   `git -C <checkout> log --oneline 9f8e7d6..a1b2c3d` is the difference; a record that is not a git
   work tree simply has no `@` clause.
2. Do not restate what F-0122's Task 6 already wrote there — which copy is read, the age, the
   fast-forward, the `git -C <path> pull` command. This Task adds the identity paragraph and
   nothing else; the surrounding text is F-0122's and stays as that Task left it.
3. Any example sha or `record:` line in the paragraph is the **exact** string `freshness.line`
   produces, checked against Task 1's `TheLineNamesTheCommit` rather than retyped. Illustrative
   paths are `/path/to/record` and `~/.ASF/state/<product>/record` — no worker account name and no
   machine path (spec P14).
4. `RecordShaProseTests` in `tests/test_readme.py`, reading the guide **from the checkout** as
   `ProductResolutionProseTests` and `WorktreeSetupProseTests` already do
   (`tests/test_readme.py:482` and `:507` are the precedent and the shape, including their `_read`
   helper). Each assertion names the clause it is pinning, so a later rewrite is told which
   sentence it broke: the paragraph carries the `@` clause and calls it the copy's HEAD; it says
   *identity* and denies that it is a freshness check; it gives the two-sha `git log --oneline
   <a>..<b>` comparison; and it says a record that is not a git work tree has no `@` clause.
5. `bash tools/check_generic.sh` before the push, over the guide and the test. This is the Task
   whose diff is prose a human reads, so the redaction check is part of its Gate and not an
   afterthought.
