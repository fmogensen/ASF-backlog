after: Task 1

Design §2 of the spec: `pushed_work_line` takes the second half as a second, defaulted argument
and keeps **one** row; the green text gains "and an owner"; the red text joins the two halves with
`; `; the call site passes `stalled_landings` over the plan it has already drawn. No new `asf
doctor` row, and no recomputation of the condition in `doctor.py` — the gate is applied once,
where the plan is drawn (`D7`, `D11`, `P10`).

**Files**

- `asf/doctor.py`
  - `pushed_work_line(orphans, stalled=None)` (`:1821`), with the spec's docstring. Green:
    `'pushed work: every open Task/Bug with an open PR has a NEXT row and an owner'`. Red: the two
    halves joined with `'; '`, so a product with both says both in one row; the first half's text
    is unchanged. The second half names each item as `<id> (PR #<pr>, <n> row[s] behind)` and the
    command `asf land <pr> --priority`, **pluralised the way §1's two cells are** — with
    `LANDING_MIN_DEPENDANTS = 1`, `n == 1` is the threshold case and therefore the common one, so
    `1 row behind` and never `1 rows behind`.
  - the call site (`:1848`): the existing `orphaned_pushed(…)` argument unchanged, and
    `feeder_rows.stalled_landings(plan)` added as the second — over the plan the function already
    built, which was drawn for the product and so already carries `D11`'s gate.
- `tests/test_pushed_work.py` — the class `DoctorSaysTheOwnerlessLanding` with the four cases of
  the third fenced block, appended after `DoctorSaysIt` (`:112-125`). `doctor` is imported **inside
  each case**, which is how `DoctorSaysIt` already does it: the module imports only `asf.env.Product`
  and `asf.feeder.rows`/`tiers` at the top (`:11-12`), so a bare `doctor.` would be a `NameError`.
  Nothing in the existing module is edited, and nothing in Task 1's additions is edited.

**Steps**

1. **Read `asf/doctor.py` first.** F-0274 is `spec-approved` and decides at its `C9` that
   `check_pushed_work` becomes `check_plan_silence(product)`. At the time this plan was written it
   had not landed — `check_pushed_work` is `:1832`, `check_plan_silence` is a free name, and
   `docs/plans/f-0274.md` is not in the tree (**PD7**) — but if it has landed by the time this Task
   runs, the one line of Step 3 goes into `check_plan_silence` instead. The spec forbids citing
   `check_pushed_work` without reading the file (`docs/specs/f-0326.md:336-337`). Nothing else in
   this Task depends on the order, because the new argument is defaulted.
2. Give `pushed_work_line` the `stalled=None` second argument and the two text changes. Keep one
   row and keep the label `pushed work`: `pushed work` is already the invariant for "pushed work
   nothing is acting on", and this is its second half, not a second invariant (`D7`). Write the
   singular/plural of `row[s] behind` explicitly — the threshold is one, so the singular is the
   common case, not the edge.
3. Add the one argument at the call site. It is `feeder_rows.stalled_landings(plan)` over the plan
   already in hand, so `asf doctor` makes no new read and no new host call.
4. Add `DoctorSaysTheOwnerlessLanding` and run the Gate. `DoctorSaysIt`'s two existing cases must
   stay green untouched: neither pins either text (**PD8**), which is the same fact that makes the
   defaulted argument safe for every other caller.
