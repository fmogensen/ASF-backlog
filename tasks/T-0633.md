## Description
stories: S-37754

after: Task 2

The spec's `## The design` §7 in full, and nothing else. After this lands, a week of gate ledger
lines becomes one table an operator can act on — median, worst and count per module, slowest first —
and the card's third acceptance clause is met end to end, on a product still gating locally.

One thing is load-bearing, and it is a **precondition made into an assertion**: `render_daily` must
not read the operator home (P15). `tests/test_metrics.py:422` compares
`metrics.render_daily(self.root, DAY, self.items)` byte for byte against `EXPECTED_DAILY`, and the
suite's `$ASF_HOME` is shared by every module. So `cmd_rollup` does the one read and passes the rows
in, the section renders **only when there are rows** (D12, `delivered_vs_single` at `:738-741` is the
in-tree precedent), and `EXPECTED_DAILY` is **not edited** — that it still matches, unchanged, is
what proves the change is inert for a product with no gate ledger.

Read **PD12 before writing `gate_modules`' first line** — `env.state_dir(None)` does not fail, it
resolves someone else's product and creates a directory.

**Files**

- `asf/metrics/metrics.py` — `gate_modules(product, week)` folding `<state dir>/gates.jsonl` into
  `[(module, median_s, worst_s, gates)]` slowest first, over the lines whose `at` is in `week`, with
  PD12's guard first and the same tolerant reading `gates_from_ledger` uses (`:1632-1654`: a line
  that is not JSON, or not a dict, is skipped, never raised on); `render_daily` gains
  `slow_modules=None` and renders §7's heading, sentence and table only when it is non-empty; and
  `cmd_rollup` (`:1448-1459`) computes `days_back(day, 7)` and passes
  `slow_modules=gate_modules(getattr(args, 'product', None), week)` into its one `render_daily`
  call. No other caller of `render_daily` exists (measured: `:1459` is the only one).
- `tests/test_metrics.py` — the fold over a hand-written `gates.jsonl` (median, worst, count, order,
  a line with no `modules` key ignored, a line outside the week ignored, no product → `[]`); the
  table rendered from `render_daily(root, day, items, slow_modules=[…])`; `cmd_rollup` as the one
  thing that reads the ledger; and `EXPECTED_DAILY` **unedited**, with the golden test untouched.

**Steps**

1. **`gate_modules`** — PD12's guard, then the read. Median over a module's readings, worst as the
   maximum, `gates` as how many gate lines carried that module; ties broken by module name so the
   order is deterministic. Seconds are floats in the ledger (`812.3`) and stay floats in the table.
2. **`render_daily`** — the keyword and the conditional block, in `delivered_vs_single`'s exact
   shape: build the rows, and append the heading only if there are any. Then run
   `python3 -m unittest -q tests.test_metrics` before writing a new test: `EXPECTED_DAILY` must
   already match, unedited, or the section is not conditional.
3. **`cmd_rollup`** — the one read and the one keyword. Nothing else in the command moves.
4. **The tests.**
5. Run the Gate.

**Not in this Task** — `record_gate`'s `modules` key and the `slowest modules:` line, which are Task
2's and are on the trunk before this starts (PD13); anything in `asf/ci_gate.py`; the scorecard's
`gates` stream and `gates_from_ledger`, which read the same file by key and are deliberately
unchanged (P14). And from the spec's `## Out`: an explicit "no readings" line — D12 chose the
conditional form so the golden proves the change is inert — and any edit to `EXPECTED_DAILY`.
