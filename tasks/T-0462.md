## Description
stories: S-32705
writes: asf/approvals.py, tests/test_approvals.py, tests/test_amendable.py
after: Task 1

The spec's tenth **In** bullet, its `asf/approvals.py` block and D9. Two edits to one table each:
`asf hooks uninstall` is held exactly as `install` is, and a session writing a real hook file —
the chained `<hook>`, or the `<hook>.local` behind it, which runs on every commit and was reachable
by no recogniser at all before this change — is refused as `touch_security`.

**Files**

- `asf/approvals.py` — `_PATH_GLOBS['touch_security']` gains `hooks.REAL_GIT_HOOK_GLOBS`;
  `_COMMAND_PATTERNS['touch_amendable_set']`'s `asf hooks install` pattern becomes `(?:un)?install`
- `tests/test_approvals.py` — the new glob's cases, and the `asf approvals` row
- `tests/test_amendable.py` — `asf hooks uninstall` held like `install`; the amendable set unchanged

**Steps**

1. `_PATH_GLOBS['touch_security']` (`asf/approvals.py:132-137`) becomes the secret shapes
   `+ hooks.GIT_HOOK_GLOBS + hooks.REAL_GIT_HOOK_GLOBS`. Neither `_classify_path` (`:260-276`) nor
   `path_class` (`:542-563`) needs another splice: unlike `RUNTIME_SETTINGS_GLOBS`, this constant is
   in the table itself, so both readers and `_builtin_recognisers` get it for free.
2. `r'\basf\s+hooks\s+install\b'` at `:152` becomes `r'\basf\s+hooks\s+(?:un)?install\b'`. Nothing
   else in that tuple moves.
3. **PD7 is this Task's one correction to the spec**: the constant Task 1 declares carries both
   `.git/hooks/*` and `*/.git/hooks/*`, because a session's repo-relative path to the real hooks
   directory is `../…/.git/hooks/<name>` from a linked worktree and `.git/hooks/<name>` from a
   plain checkout, and `_match_glob` matches exactly one of the two in each case. Both forms are
   asserted, with a real worktree, so the case the class exists for is the case that is tested.
4. `tests/test_approvals.py`: a `Write` to `<repo>/.git/hooks/pre-commit` is `touch_security`; so is
   one to `<repo>/.git/hooks/pre-commit.local`; so is a `Write` from inside a **linked worktree** of
   that repo to the same file (PD7), which is the shape every ASF session has; a write to
   `.githooks/pre-commit` is still `touch_security` through `GIT_HOOK_GLOBS`, as it was; and a read
   of any of them is not held, through the read-only rule the module already has. One case asserts
   the `asf approvals` row for `touch_security` prints the new glob (`.git/hooks/*`) — D9's "no
   further edit" — while `hooks.RUNTIME_SETTINGS_GLOBS` stays named and not spelled, which is what
   `tests/test_approvals.py:575-577` asserts today.
5. `tests/test_amendable.py`: `asf hooks uninstall --product p` is refused as `touch_amendable_set`
   with no `kind` (a command naming no file), beside the `asf hooks install` case at `:240`; a
   read-only command that merely quotes it — the shape of `:281`'s `rg "asf hooks install" docs` —
   is still not held; and the amendable set is **unchanged**: the `hooks` kind's globs are still
   exactly `RUNTIME_SETTINGS_GLOBS + GIT_HOOK_GLOBS` (`:43`), `REAL_GIT_HOOK_GLOBS` is asserted
   absent from every kind, and `format_set` still has six rows. `.git/` is never tracked, so it is
   never a path a pull request can touch (P11).
