## Description
stories: S-78055, S-78056
writes: asf/tick/step_wave.py, tests/test_rulepass.py
after: Task 1, Task 2

One kind, one check, one preview-safe write root, and one map. `screen()` is the only per-row
filter every launch path goes through (P9, C1), so one check here cannot be bypassed by a second
path — and the preview twin is what keeps `asf status`' "Ready to launch" from counting a row the
wave will rule (C10).

**Files**

- `asf/tick/step_wave.py` —
  - the kinds tuple (`:737-739`) gains `RULED = 'ruled'` and nothing else (**PD3**).
  - `screen(…, record_root=None)` — one kwarg, and the check between the `paused` branch
    (`:826-831`) and the host hold (`:832-837`) (C2).
  - `waivers(product, root, index)` — the one fact both feeder branches read, with the spec's
    docstring verbatim.
  - `plan_inputs` (`:298`) returns `'waived': waivers(product, root, index)`.
  - `launch` (`:1209`) passes `record_root=ctx.record_root`; `would_start` (`:890`) and
    `launch_now` (`:1303`) pass nothing (**PD5**).
- `tests/test_rulepass.py` — the S-78055 `screen` cases and the S-78056 `waivers` cases, added to
  the module Task 1 created.

**Steps**

1. Append the ninth name, leaving the eight landed values alone (**PD3**):

   ```python
   #: what :func:`screen` says of a row (``Screened.kind``): it starts, or why it does not
   STARTS, WAITS, HELD, CLOSED, PAUSED, HOST, NO_SEAT, CAPPED, RULED = (
       '', 'waits', 'held', 'closed', 'paused', 'host', 'no seat', 'relaunch cap', 'ruled')
   ```

2. `screen` takes `record_root=None` and the check goes in, after `paused` and before the host
   hold. It is reached only by an adjudicate row, and it takes no seat — `room` is untouched, so
   the seat goes to the next candidate, which is the point of putting it before the seat test
   (C2):

   ```python
           if row.brief_kind == 'adjudicate':
               ruled = rulepass.apply(product, row, items, say,
                                      root=record_root() if (act and record_root) else None,
                                      dry_run=not (act and record_root))
               if ruled:
                   if act and ctx is not None:
                       ctx.event('rule_pass', item=row.item_id, rule=','.join(ruled.rules),
                                 finding=' '.join(ruled.finding), where=ruled.where,
                                 cite=', '.join(ruled.cites))
                   say(f'ruled    {job:<24} {row.item_id:<10} — {ruled.why}')
                   result.append(Screened(row, ruled.why, RULED))
                   continue
   ```

   `say` is `out` under `act` and `_quiet` otherwise, so the preview prints nothing by
   construction. `record_root` is passed as the bound method, not its value, so no clone is made
   on a tick that rules nothing.

3. `would_start` and `launch_now` are left as they are — neither passes `record_root`, so
   neither writes (**PD5**). In `launch`, the one call site gains
   `record_root=ctx.record_root`. On the wave-clock path `apply` therefore runs with no root and
   `dry_run=True`, and its answer is discarded: the row starts, as today. One line says so, from
   `apply` itself.

4. `waivers(product, root, index)` — the spec's docstring verbatim, and the match made here
   because this is the only caller holding both the product and a filesystem (P19, C11). Per
   **PD10** the correction branch needs no review read:

   ```python
   def waivers(product, root, index):
       out = {}
       if not rulepass.enabled(product):
           return out
       items = feeder_rows.items_of(index) if index else {}
       for iid, item in items.items():
           try:
               d = rulepass.dispute(product, _bare_row(iid, item, product), items)
               at = rulepass.waived(product, iid, d.finding) if d else ''
               if at:
                   out[iid] = at
           except Exception:  # noqa: BLE001 — no waiver is no stand-down, never an error
               continue
       return
