**Steps**

1. In `asf/record/core.py`, add `PRIORITIES = ('need', 'nice', 'later')` beside
   `NO_PARENT_TYPES`/`PARENT_TYPES` (`core.py:28-34`) as the one definition, with a docstring
   naming it the word set the record enforces.
2. Make it the only definition, three readers. `asf/groom/inbox.py:25`'s own `PRIORITIES` becomes
   the import — the file already does `from asf.record.core import ID_DIGITS` at `:14`, so this is
   one word on an existing line. `asf/record/new.py:107`'s inline `('need', 'nice', 'later')` in
   the `--priority` check becomes `core.PRIORITIES`; leave that flag's own message as it is.
3. `new.FIELD_WORDS` (`:46-47`) gains `'priority': PRIORITIES`, so `asf set <id> priority=urgent`
   is refused by `_parse_sets` (`:73-75`, `priority='urgent' — one of need, nice, later`) at the
   command and not merely reported by the next check. Do not add it to `FIELD_UPPER`: the three
   words are lowercase and `severity` is the only field case-folded on the way in.
4. In `record_findings`, beside the milestone rule Task 2 added, the priority rule: a
   `meta.get('priority')` that is set must be in `core.PRIORITIES`, else
   `priority: 'urgent' is not one of need, nice, later`, at `find_line(rec, 'priority')`.
5. The blast radius is measured and empty: the live record holds `need` 110, `nice` 7, `later`
   193 and absent 2370, with no fourth word (P9), so the rule is green on it the day it lands —
   and by Precondition 4 `_report_staged` prints a finding `HEAD` already carries as a warning
   (`check.py:574-592`), so even a record that was not could never have an unrelated commit
   refused for it.
6. Extend `tests/test_work_item_model.py` with `PriorityWords`. First the two lines that pin what
   already holds (P5 R5): an Epic carrying `priority: need` passes `record_findings` with no
   finding, and an inbox note whose header declares `priority: need`, run through the groom's
   intake, mints a card that carries it into a record `record_findings` reports clean. Then:
   `nice` and `later` also pass; a card with no `priority:` is clean; a card carrying a word
   outside the three is one finding that names all three; `core.PRIORITIES` is the one definition
   and `inbox.PRIORITIES` and `new.FIELD_WORDS['priority']` are it; `asf set` refuses a priority
   outside the three words before it writes, leaving the card byte-identical, and writes one
   inside them; and answering an inbox note's open question leaves the note's own `priority:`
   header in place.
