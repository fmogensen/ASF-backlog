§2.8 — `mint_id`'s rule at the tool boundary, for the one path that never reaches `mint_id`: a
session writing the card file itself with `Write` (D8).

**Files**

- `rules/R-0004.md`, `rules/r0004.sh` — `title: a card is minted from the range the session was
  given`, `check: tools/checks/r0004.sh`, `hook: [PreToolUse]`; body naming the collision two
  worktrees minting from one counter produce.
- `asf/rules/hooks/r0004.py` — returns None unless `call['tool_name']` is one of `Write`, `Edit`,
  `MultiEdit` (PD6). Refuses when the call's `file_path` (or `notebook_path`) is a **new** file
  matching `<backlog_dir>/<folder>/<PREFIX>-<NNNN>.md` for a folder of `asf.record.core.TYPES`
  (`asf/record/core.py:15-23` — read `TYPES`, do not list the folders), the cwd is a worktree, and
  either `BACKLOG_ID_RANGE` names no range for that prefix while `BACKLOG_ALLOW_MINT` is unset, or
  the id is outside the range it names. The range is parsed by calling
  `asf.record.ids._id_range(prefix)`, not by a second regex — one parser for
  `BACKLOG_ID_RANGE`, which is the whole point of the rule. Allows: an `Edit`/`Write` of a file
  that already exists (not a mint), any write outside the card folders, and everything in a
  canonical clone (`.git` a directory) or a plain fixture directory. The refusal is §2.8's text,
  naming the range the session holds and `asf new --type <t> --title "…"` as the way that mints
  from it.

**Steps**

1. `asf/rules/hooks/r0004.py`, then its card and shim with the executable bit.
2. `MintRangeTests` over a real record fixture that is a linked worktree (`.git` a file): the seven
   rows T8 names, plus the wrong-tool allow (a `Bash` call at the same path) for PD6.
3. `asf doctor --product <p>` by hand: `rule-hooks` green for five scripts.
