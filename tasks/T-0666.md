The spec's `## The design` §1 and §2, plus §4's one change to `drift`. After this lands, the card's
own expression reads: `${{ fromJSON(format('["self-hosted","{0}"{1}]', vars.X || 'heavy',
github.event_name == 'pull_request' && ',"class-pr-heavy"' || '')) }}` becomes two `RunsOn` rows, one
per event class, and every consumer that asks a set question of one `ro.labels` gets the union across
events for free — `plan`'s `needed` is already `any(… for ro in jobs)`, so a label wanted only on PRs
is `blocked` with no new code (C5). `_EXPR_DEFAULT` goes, and with it the guess that a
`${{ anything || 'heavy' }}` means `heavy`: with no variables known, a `vars.*` is now unresolved
(C3) — which is safe to land only because Task 1's freeze is already in (**PD1**).

**S-36351 rides here and may not be split off** (**PD3**): the resolver is what first puts
`class-pr-heavy` into a judged label set, and `drift`'s provider-like flag would then tell the
operator to stop asking for the label `ci.reserve` exists to place. Three lines, same commit.

Read **PD6 before writing `_label_token`**: the spec says both that a token resolves to one label
and that a scalar may resolve to a list, and the card's own test only passes under the second — the
token resolver returns `None`, a string, or a **list**, and `parse_runs_on` flattens. Read **PD8**
for the three spellings GitHub accepts that the spec's grammar as written would refuse, and for the
one widening this plan declines. Read **PD9** for `event_classes`' dedup.
