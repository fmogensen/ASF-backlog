added, nothing else removed. After this lands, a run with one flaky module among 278 reads:

```

OK (skipped=18)

1 flaky
  tests/test_groom_publish.py:140:1 › GroomPublishTests.test_a_record_that_is_not_a_checkout_is_left_alone
```

measured here with the real identity shape, byte for byte (minus the real suite's own module
count and timings, which this worktree does not reproduce) — the fixture in
`RetryPassTests`/`FlakyBlockTests` plants exactly this failure and gets exactly this output.

Three things are load-bearing, each pinned by a Story. **The retry is a second pass over the
pool, never a loop inside a module's own process** (D-0001, D-0003): `run()` stays the one place both the
CI step and every local gate call (P1, P6), and the pool's own queue/`running` shape is reused for
the second pass rather than invented twice. **A module's second result replaces its first in
`results` by index, in place** (D-shape, S-67254): `finish` gains one keyword, `replace_at=None`
(PD3), so the module count, `Ran N tests`, the `red:` line and the exit status are all read off
the *final* attempt, with no second code path computing any of them. **The flake is read off the
*first* attempt's output, not a diff between the two** (S-67255): `flaky_rows(module, rc, output)`
is pure — three arguments in, rows out, no process, no file, no environment (measured: a direct
call surrounded by an environment snapshot, unchanged after).

Read **PD1** before trusting any substring match on `'tests/'` — the correct test is "this
module's own file," computed once as `own_file`. Read **PD4** before moving the red-set
computation earlier than "after the tail has drained" — nothing upstream of that point has every
result yet.
