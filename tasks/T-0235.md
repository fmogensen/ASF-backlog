§2.5: the immutable timestamp the incident clock needs, written once and never moved, seeded for the
existing record by one migration. Today `asf/feeder/render.py:43` runs the S1 clock off
`stage_since or created` while `asf/record/ingest.py:334` moves `stage_since` on every state change —
so launching a fix for an S1 Bug resets the clock that exists to catch a launch that failed, which
F-0071 D7 already ruled must not happen (`docs/specs/f-0071.md:82`).

**Files**

- `asf/record/ingest.py` — `MACHINE_KEY_ORDER` gains `'opened'` after `'stage_since'`;
  `_ingest_fields(..., typed=None)` writing it once (PD8)
- `asf/schema.py` — `_migrate_to_2`, `MIGRATIONS[2]`, `SCHEMA_VERSION = 2`
- `asf/feeder/render.py` — `incidents`' one line (§2.5)
- `sample/backlog/**` — the sample's committed record migrated to schema 2 (PD9)
- `tests/test_ingest.py` — `OpenedTests`
- `tests/test_schema_version.py` — the `MIGRATIONS[2]` cases
- `tests/test_feeder.py` — `IncidentClockTests`

**Steps**

1. `MACHINE_KEY_ORDER`: `'opened'` immediately after `'stage_since'` — the two read together on the
   card, and the order makes the difference between them visible.
2. `_ingest_fields` gains `typed=None` and §2.5's one line with its comment:
   `fields['opened'] = machine.get('opened') or (typed or {}).get('created') or fields['stage_since']`,
   after `stage_since` is computed. Never recomputed, never dropped, for any item type — an age is
   worth having on a Feature too, and a key that exists only for Bugs is a key every reader guards.
   The caller (`asf/record/ingest.py:822`) passes the `_typed` it already split at `:820`.
3. `_migrate_to_2(record_dir)`: for every card with a machine `stage_since` and no `opened`, write
   `opened = stage_since` through `frontmatter.merge_machine` in `MACHINE_KEY_ORDER` position,
   touching nothing else and appending no `## History` line — a migration is not a derivation (§4).
   `MIGRATIONS[2] = _migrate_to_2`, `SCHEMA_VERSION = 2`. `stamp_cards` already skips a card at or
   above the target (`asf/schema.py:88`), and `migrate_dir` already runs the entry then the stamp
   then the commit (`:196`).
4. `asf/feeder/render.py:43` becomes
   `since = ix.parse_ts(b.get('opened') or b.get('stage_since') or b.get('created') or '')` (D15) —
   a migrated record reads the immutable key, one not yet migrated keeps its present behaviour.
   `s1_hours`, `starved`, the `Incident` tuple and `asf status`'s `INCIDENTS` block are untouched.
5. The sample's record, per PD9: `asf schema-migrate` over `sample/backlog/` and commit its output —
   each card gains `opened` in position, `sample/backlog/index.json`'s stamp becomes 2. B-0001's
   `opened` is `2026-01-01T09:00:00Z`, its own `stage_since` (`sample/backlog/bugs/B-0001.md:11`).
6. `tests/test_ingest.py:OpenedTests`, per §3.5: `_ingest_fields` over a card with no `opened` writes
   it from the typed `created` when there is one, else from the `stage_since` the same call computes;
   over a card that has one, three ingests across a `New → Active → Resolved` walk leave `opened`
   byte-identical while `stage_since` moves each time.
7. `tests/test_schema_version.py`, per §3.5: `MIGRATIONS[2]` over a record of ten cards — every card
   with a `stage_since` gains `opened` equal to it, in position, with no `## History` line added and
   no other key touched; a card already at version 2 is not rewritten; running it twice is a no-op.
