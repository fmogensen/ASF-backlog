The spec's design §1 whole, and nothing else: one new module that reads the App's declaration,
signs a JWT with `openssl`, mints an installation token, caches it with its expiry and refreshes
it inside a 15-minute margin — plus `openssl` as a new kind in the client ratchet with
`asf/ghapp.py` as its only owner. It is the first wave by itself because every other Task imports
a name from it and it imports nothing from them: at this head `grep -rn 'app_id\|installation_id\|installations' asf | wc -l`
is `0` (`P8`), so no existing reader is extended and no existing test can go red from this Task —

**S-120855 — the module: declaration, JWT, mint, cache, refresh, and nothing secret in any output**

```bash
# S-120855 — the module: declaration, JWT, mint, cache, refresh, and nothing secret in any output
python3 -m unittest -q tests.test_ghapp
```

- [ ] a product declaring no github_app is unconfigured, and settings returns none
- [ ] a product declaring an app id and a key file gets both back, with the key path expanded from a leading tilde
- [ ] a declared installation id is read back as an integer, and an absent one leaves the field empty
- [ ] the signing input is two base64url segments joined by a dot, neither of them padded
- [ ] the claims carry the app id as the issuer, an issued-at one minute in the past and an expiry nine minutes in the future, measured off the clock passed in
- [ ] the signer is invoked as openssl, with the digest and the key file as arguments and the signing input on stdin
- [ ] a signer that fails returns no token and a reason that names the key path and carries no key material
- [ ] the minted token is the access token the mint response carried, and its expiry is the response's own
- [ ] the token file is written with mode 0600 and holds the token and nothing else
- [ ] the meta file holds the app id, the installation id, the slug, the mint time and the expiry, and no substring of the token or the key
- [ ] the installation id is discovered from the product's repo slug when the product declares none, and the discovered id is kept in the meta file
- [ ] a declared installation id is used as declared and no discovery call is made
- [ ] a refresh with a cached token further from expiry than the margin makes no call at all
- [ ] a refresh with a cached token inside the margin mints a new one
- [ ] a refresh with no cached token mints one
- [ ] a refresh on a product with no app configured makes no call, writes nothing and gives a reason
- [ ] a refresh while a dry run is active mints nothing, prints one would-mint line and gives the dry-run reason
- [ ] a mint that fails leaves the previous token file exactly as it was and records the reason in the meta file
- [ ] a mint answered with a rate-limit body latches the process the way a refused gh call does
- [ ] a mint answered with unparseable output is a reason, never a token
- [ ] no value the module returns, logs or writes contains the token or any line of the key file, over every failure path above
- [ ] the module holds the only urllib request site in the package
- [ ] the module holds the only openssl call site in the package, and the client ratchet names it as that kind's owner
