The spec's §2. The launch rebase — the site the card measured, 25 of 57 superseded runs
(`trunk_rebase_needed`'s own docstring, `asf/workers/spawn.py:618-619`) — asks the verdict before it
rebases, and `severity` is threaded from the feeder row to it. **This is the Task that fixes the
card's own incident**: the 18:23Z push that re-dated all five of PR #858's commits with no content
change does not happen while run `36262385912` is in flight.

**Read PD4 before writing the `CONFLICT` rows**: a conflicting rebase aborts and moves nothing, so
the head cannot tell an exception from a deferral — assert the line and the `needed=` argument.
**Read PD5 before adding the class**: the fixture lifts to `Home` first.

**What changes for the machine when this lands.** A held branch carrying trunk history whose PR has
a queued or running `ci.workflow` run keeps its head exactly as origin holds it — byte-identical,
un-re-dated — and the session starts on it (C6); one line goes to stderr. A branch that does not
merge cleanly into the trunk is still rebased at once, S1 or not. With nothing in flight — and for
every product with no `ci.workflow` or no `repo_slug`, which is every product in the suite (P8) —
the rebase and its publish are byte-for-byte what they are today.
