The spec's §6, plus the one token in `lifecycle.py` that keeps a sweep session from being held for a
push. The verdict *parser* is Task 1's — it is part of the pure module — so this Task is the brief
that asks for the block and the tests that pin both halves against each other: the brief quotes the
schema the parser reads (D-0001's "the grammar is shared, so there is still one block reader").

**Files**

- `asf/kernel/briefs.py` — `GROOM_SWEEP_TEXT` exactly as §6 writes it, beside `GROOM_FILL_TEXT`
  (`:123-154`); `_sweep_brief(product, launch, item, findings, model)` beside `_groom_brief`
  (`:382-396`) and in its shape — the body capped at `GROOM_BODY_MAX` (`:195`), `floor.Brief(kind=
  S.KIND, …, add_dirs=[], id_ranges_needed=False)`, no floor template and no git facts; and one
  dispatch branch in `build` beside the groom-fill's (`:434-436`), on
  `model_for(product, S.KIND)`. The three facts the template needs come off
  `launch.findings` through `S.read_facts` (**PC8**): `{class_phrase}` is `parked` or `New`,
  `{age}` the one-decimal day count, and `{parked_by}` either empty or the single line D-0008 names
  — *"`T-0123` is parked through `F-0045` (`priority: later`), not by its own priority, so it
  cannot be revived from here: choose `retire` or `keep`."*
- `asf/workers/lifecycle.py` — `'groom-sweep'` added to `NO_LANDING_KINDS` (`:2720`). One token.
  `lands` (`:2732`) reads the tuple and needs no change, and `OFF_BRANCH_KINDS` is **not** touched:
  a sweep's branch is its own worktree name, never the item's.
- `tests/kernel/test_sweep.py` — `VerdictTests` and `BriefTests`, one method per acceptance line of
  S-125157. `BriefTests` follows `tests/kernel/test_dor.py:440-450` byte for byte in shape:
  `env.Product('sample', {'main': 'main'})`, then a hand-built
  `A.Launch(sweep.KIND, iid, config.sweep_branch + iid, sweep.brief_facts(...))`, then
  `briefs.build(product, launch, item, launch.findings)` and assertions on `b.kind`, `b.model`,
  `b.text` and `len(b.text)`.

**Steps**

1. `NO_LANDING_KINDS` first — one token, and it is the Story's last acceptance line. Run
   `tests.kernel.test_push_rule` immediately: it is the module that pins which kinds are held for a
   push.
2. `GROOM_SWEEP_TEXT`, copied from §6. The spec fences that template with four backticks
   because it contains a fenced block of its own: the schema the session must end with. Keep that
   inner fence, and keep `{schema}` fed from `S.VERDICT_SCHEMA` rather than retyped, or the brief
   and the parser drift the first time a key is renamed.
3. `_sweep_brief` and `build`'s branch. The brief reads its facts through `S.read_facts(findings)`
   and **never** from `facts`, a port or the record (**PC8**) — it is handed one `Item`.
