The spec's `## The design` §4 in full, and nothing else. After this lands, three gaps the mint
check cannot cover are covered: a Task minted before any of this existed — every open Task in the
record today; a trunk that moved between the mint and the seat, a sibling having landed the surface
in the days between; and a Task whose **own id** a trunk commit already names, which is P6's row
that no production caller has ever been able to raise.

Two things are load-bearing. **The call site is not where the spec's sample puts it** — read
**PD3**; at `:682` the preflight makes `left_out` print a false `no seat left` line about the row
it just refused. And **nothing is written but the typed sha** (C12): `state`, `evidence:` and the
`ingest:` History line are the ingest's keys, written by the one pass that owns them, and the next
tick turns the sha into `Closed` by `reconciled` — the row does not launch this tick either way, so
nothing waits on the state landing.

Read **PD4 before wrapping `close_by_trunk`** (it guards itself; a second `stage.guarded` walks the
whole record twice per refusal), **PD1** for what the second of the preflight's two questions
inherits, and **PD13** for why this Task owns the fenced block that names both new test modules.

- `asf/tick/step_wave.py` — one new function, `trunk_preflight(ctx, planned, items, out=print)`,

  trunk_check`) are function-local, as §4 writes them and as `launch`'s own neighbours do. Nothing
  else in the file moves.
- `tests/test_trunk_check.py` — one class appended, `WavePreflight`, with the spec's four rows. The
  harness and Task 1's four classes are not edited; `WavePreflight` subclasses the file's harness
