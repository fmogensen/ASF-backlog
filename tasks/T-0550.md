## Description
stories: S-37102
writes: asf/groom/policy.py, tests/test_groom_policy.py
after: none

The spec's §*`asf/groom/policy.py`*: one guard, moved. Today `decide_or_close_ci_red`'s **failure**
branch is bounded by `ctx.ci_red_days` and its **closing** branch is bounded by nothing, so a
ten-day-old green closes a CI-red Bug under a seven-day window (P9, measured). The guard moves up
onto the job's newest fact and covers both.

This Task **removes** a branch rather than adding one, and it adds no key: `ci_red_days` keeps its
value and its name (D12). Deliberately free of `metrics.ci_facts` — the policy's window is a rule
about facts, not about how they are read — so it may land beside Task 1 in either order.

The other five policies `decide_or_close_ci_red` sits among, `_filed_at`, `ci_red_job`,
`_undecided`, `Ctx` and `policy.ci_red_days` are **not** touched. Nothing in `asf/groom/groom.py`
is touched — the tuple it hands the policy is Task 1's business.

**Files**

- `asf/groom/policy.py` — `decide_or_close_ci_red` (`:423-452`): the guard added immediately after
  `latest = runs[-1]` (`:439`), the failure-only check at `:440-441` **deleted**, and two
  docstrings widened. Nothing else in the module.
- `tests/test_groom_policy.py` — two cases added to the shipped `FactPolicyTests` (`:272`), in the
  `# -- decide_or_close_ci_red` block (`:369-427`). No new class; the six shipped cases are not
  edited.

**Steps**

1. After `latest = runs[-1]`:

   ```python
       if ctx.now - latest['ts'] > datetime.timedelta(days=ctx.ci_red_days):
           return None            # the job's newest fact is older than the window: no answer off it
   ```

   `latest` is the newest of the **filtered** runs — the job's own newest `success`/`failure` — not
   the newest of `ctx.ci_runs`. That distinction is what makes P11 hold case by case; a guard on the
   unfiltered newest run would turn `test_ci_red_decides_when_the_jobs_latest_trunk_run_failed` on
   its head, since that fixture's newest run names a different job.
2. Delete the `if ctx.now - latest['ts'] > …: return None` **inside** the failure branch. The guard
   **replaces** it (P11); leaving both is a dead second test and reads as if there were two windows.
3. `decide_or_close_ci_red`'s docstring: its last sentence becomes *"No trunk run of the job, or a
   newest run older than ``ctx.ci_red_days`` → no answer: a policy never answers off a fact older
   than its own window (F-0175)."* — and the clause "*its latest trunk run failed within
   ``ctx.ci_red_days``*" earlier in the same docstring now describes the guard rather than the
   branch, so re-read it whole before editing one line of it.
4. `policy.ci_red_days`'s own docstring (`:81-85`) gains the same reach: it is the policy's **fact**
   window, not only its redness window. `CI_RED_DAYS`'s value (7) does not change.
5. Two cases on `FactPolicyTests`, in the `decide_or_close_ci_red` block:
   - `test_ci_red_refuses_to_close_on_a_green_older_than_the_window` — the case measured in P9: a
     Bug last filed 2026-09-12, facts `[09-10 failure, 09-14 success]`, `NOW` 2026-09-24 12:00,
     `ci_red_days=7` → `None`. **Today this returns `Answer('no: green since bbbbbbbbb', 'removed',
     …)`** — write the test so that it fails before the guard and passes after it, or it proves
     nothing.
   - `test_ci_red_closes_on_a_green_inside_the_window` — the same fixture with the green at 09-22 →
     the `Answer` it gives today, unchanged. This is the row that stops the guard from being
     over-tightened into "never close".
6. Do **not** add a second key (`ci_facts_days`), do **not** bound the green **streak's start**
   instead of the newest fact (a trunk green for three months would then never close its Bug), and
   do **not** touch the branch P10 names — a Bug filed after the last recorded run already returns
   `None` correctly, and the fix for the card's five unanswered Bugs is Tasks 1 and 2, not this one.
