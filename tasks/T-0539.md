The spec's `## The design` §1 in full, and nothing else: `ALIVE`, `GONE`, `REUSED`, `UNKNOWN`,
`LIVENESS`, `LIVE_VERDICTS` and the pure `liveness(run, observed, exists, is_ours=None,
silent_min=None, silent_for=None)`, beside `pid_alive` in the one module the fence allows to name a
session state (C4, PD9).

**Nothing the factory does changes when this Task lands.** The function has no caller: `alive_for`
still returns `identity_alive`, `judge` still reads `ev.alive`, `stall.classify` still asks the same
bool. That is the point of cutting it here — the four words can be pinned one row at a time, against
a factory whose behaviour is provably identical, and Task 2 is then a wiring diff with no new logic
in it.

Write the signature **whole**, including `silent_min` and `silent_for`, even though no caller
supplies them until Task 2 (PD1): the bound is part of what `liveness` *means*, and a second Task
widening a signature is a second chance to get the argument order wrong — and the order is the
argument here (spec §1, closing paragraph: the OS is asked before the observation is believed).

Read **PD2** before writing the docstring: `is_ours` is a **bool**, not a callable, and the reason
it can be a bool without costing a `ps` per pid per tick lives in Task 2.

**Files**

- `asf/workers/lifecycle.py` — the six new module constants and `liveness`, placed immediately after
  `pid_alive` (`:580-595`) and before `occupies` (`:598`), carrying the spec's `#:` comments byte for
  byte. `cloudpid` is already imported in this module (`pid_alive` uses it). No existing line moves.
- `tests/test_lifecycle.py` — a new `class LivenessVerdictTests(unittest.TestCase)`, a plain
  `TestCase` and **never** a subclass of a harness in this module — subclassing one re-runs its
  host's whole suite under a second name.

**Steps**

1. Add the constants. `LIVENESS = (ALIVE, GONE, REUSED, UNKNOWN)` is the full vocabulary;
   `LIVE_VERDICTS = (ALIVE, UNKNOWN)` is the pair a run keeps running under, and is the single line
   Task 2's `identity_alive` will read. Keep the spec's `#:` comment on the block, including its
   `(F-0234)` tag.
2. Add `liveness` exactly as §1 writes it, in that order: cloud token → `exists` → observation →
   `is_ours is False` → the silence bound → `UNKNOWN`. Do not reorder to put the observation first;
   the whole defect is that the OS was never asked (P3).
3. `LivenessVerdictTests` — one test per row, each stating only the facts it means and leaving every
   other argument at its default, the way `Evidence`'s null defaults let a test state one fact
   (`:1049-1050`):
   - a pid the OS does not answer for is `GONE` **whatever the observation says** — pass an
     `Observed` at the pid carrying the run's own session and `exists=lambda p: False`, and assert
     `GONE`. This is the row that proves the order.
   - an observed session carrying the run's own id, with `exists` True, is `ALIVE`.
   - a run with no `session` of its own, observed at all, with `exists` True, is `ALIVE` — F-0076's
     rule for a run recorded before sessions existed, kept whole.
   - an observed session naming a **different** id is `REUSED`.
   - `exists` True, observation `None`, `is_ours=False` is `REUSED`.
   - `exists` True, observation `None`, `is_ours=True`, `silent_min=30`, `silent_for=5.0` is
