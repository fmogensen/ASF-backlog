The spec's *The design* §1, and nothing else. One new pure function beside `pr_of`, and
`queue_landed` becomes its two-line reading — same name, same one caller, same two landed
assertions (C3/P18). Nothing in this Task changes a derived state or a lane record: it puts the
fact where C1 says it must live, so Task 2 and Task 3 can both import it without importing each
other.

`landed_prs` is `{pr number: sha}`, not a set (C4): the sha is the Task's `merged_sha` and it is
in the same subject row, so a second lookup is a second chance to disagree. It reads all three
landing subjects through `pr_of` (C2) — `merge-queue: #<n> …`, `… (#n)`, `Merge pull request
#<n> …` — which is already the trio `asf/facts/landing.py:170-178` treats as one question, and
which is what closes P12's hole: a queue landing recorded by the queue's *trailer* rather than its
subject carries the `… (#n)` form and today's `queue_landed` misses it entirely.

It takes both row shapes, because its two callers produce different ones: `first_parent` yields
`{'sha', 'author', 'at', 'subject', 'body'}` dicts (`asf/trunk_watch.py:125-143`) and
`main_commits` yields `(sha, subject, [path, …])` tuples (`:1093-1102`). Both are newest first,
and the newest wins when two rows name one number.

**Files**

- `asf/trunk_watch.py` — new `landed_prs(commits)` beside `pr_of` (`:69-76`), with the spec's
  docstring verbatim. Reads `pr_of` and nothing else; no git, no product, no import.
- `asf/evidence/evidence.py` — `queue_landed` (`:1394-1404`) becomes the spec's two-line body;
  `_QUEUE_NUMBER_RE` (`:1390-1391`) and the `QUEUE_SUBJECT` import are deleted with it (PD5).
  `_commit_rows` (`:1303`) stays and is what normalises the tuples. Its one caller,
  `id_evidence`'s `queued = queue_landed(commits)` (`:1465`), is **not** touched.
- `tests/test_pr_cache_trunk.py` — new `class TrunkLandedRowTests` after
  `QueueLandedIsNotOpenTests` (`:92`), carrying this Task's cases from the spec's S-74154 block:
  the three subject forms, the subject naming no PR, both row shapes, and newest-row-wins. The
  two existing classes are not edited.

**Steps**

1. Write `landed_prs(commits)` in `asf/trunk_watch.py` under `pr_of`: iterate `commits`, take
   each row's subject from `row['subject']` for a dict and `row[1]` for a tuple/sequence, call
   `pr_of(subject)`, and record `number → sha` only when `pr_of` returns one. Rows are newest
   first and the newest wins, so a number already in the map is not overwritten. A row that is
   neither shape, or carries no sha, is skipped rather than raising — `main_commits` is parsed
   from `git log` output and `first_parent` from another, and neither promises well-formedness.
2. Replace `queue_landed`'s body with `set(trunk_watch.landed_prs(_commit_rows(commits)))` under
   a function-local `from asf import trunk_watch` (the module's existing style for this import,
   `:1398`), keeping the spec's one-line docstring. Delete `_QUEUE_NUMBER_RE` and the
   `QUEUE_SUBJECT` import (PD5).
3. Add `TrunkLandedRowTests` with this Task's cases. The two assertions `QueueLandedIsNotOpenTests`
   already makes — `queue_landed` is `{1046}` for the queue subject, and `#1047` stays in
   `open_prs` — must still pass untouched: the widening can only *add* a number the trunk's own
   subject names, which is C3's whole argument for keeping the name.
4. Run the Gate. `tests.test_pr_cache_trunk` was **7 OK** before this Task (PD7).
