## Description
stories: S-18803

after: Task 2

§2.4 and the first half of §2.9. One append-only file per product, folded the way
`sessions.jsonl` is, and a pure half — `open_train`, `due`, `tasks_of` — that takes plain dicts
and a clock so the cut rule is tested without a git repository. Nothing in this Task appends a
commit or cuts anything; it is the index the three Tasks after it write through.

**Files**

- `asf/train.py` — **new**: the module docstring, `STATES`, `trains_path(product)`,
  `load(product)` / `append(product, row)`, `fold(lines)`, `open_train(records, lane)`,
  `open_trains(product)`, `due(train, now, cfg)`, `tasks_of(train)`, `new_train(conv, lane, now)`,
  and `register(sub)` with the `train` parser and its `status` subcommand.
- `asf/cli.py:181` — `from asf.train import register as register_train; register_train(sub)`,
  beside `plugin_build.register(sub)` (PD13).
- `tests/test_train.py` — **new**: §3.4.
- `tests/test_cli.py` — `asf train status` over a product with no train, and with two.

**Steps**

1. `trains_path(product)` is `os.path.join(env.state_dir(product), 'trains.jsonl')` — the
   directory `pool.sessions_path` already uses (`asf/workers/pool.py:168`), so the registry sits
   beside the ledger and no new state root is invented.
2. The record is §2.4's JSON object exactly: `train`, `lane`, `branch`, `opened`, `first_commit`,
   `tasks` (a list of `{item, job, branch, sha, subject}`), `state`, `cut`, `pr`, `landed`.
   `STATES = ('open', 'cut', 'landed', 'abandoned')`, with the transitions in the docstring.
3. `fold(lines)` folds by `train` id, last line wins per id, the way `lifecycle.fold` folds a job
   (`asf/workers/lifecycle.py:24`) — so a Task's row written twice leaves one row, and a lost or
   truncated last line costs the open trains rather than the work (§4).
4. `open_train(records, lane)` → the one record for `lane` whose `state` is `open`, else `None`.
   Two open records for one lane is a registry error, not a second train: it returns the newest
   and the error is the caller's to print. `open_trains(product)` is `{lane: record}` over the
   folded file, and it is what `plan_inputs` hands the feeder (Task 5, PD11).
5. `due(train, now, cfg)` → `(True, why)` when `len(train['tasks']) >= cfg.max_tasks` or
   `first_commit` is older than `cfg.max_age_s`; `(False, '')` otherwise, and always `False` for a
   train with no `first_commit` — an opened branch nobody has committed to is not aging (D9). The
   clock is a parameter, never `now_utc()` inside.
6. `new_train(conv, lane, now)` builds the id `f'{lane}-{stamp}'` and the branch
   `conv.branch('train', id)`. The prefix is never written as a literal here (PD7) — this module
   is scanned by `check_conventions.sh` like every other.
7. `register(sub)` adds the `train` parser with a `status` subcommand taking `--product` and
   `--json`; `cmd_status` prints one block per train — the branch, the seat count, the age of the
   first commit, each Task and where its commit sits, and `due`'s reason when it is due — and
   exits 0 whether or not a train exists (§2.9). `--json` prints `{"trains": [...]}`, the shape
   §3.8's operator one-liner reads.
8. `tests/test_train.py` per §3.4, entirely on plain dicts and a fixed clock: `open_train`
   returning the one open record and `None` when the last is `cut`; two open records for one lane;
   `due` at five Tasks and one hour → False, at six → True, at two Tasks and two hours one second
   → True, and False with no `first_commit`; `fold` over a file where a Task's row is written
   twice; and `new_train(conv, 'code', …).branch` → `train/code-…` built from the product's
   prefix. Plus PD14: a train branch on origin with no session record is not a harvest entry.
9. `tests/test_cli.py`: `asf train status` exit 0 with no registry file at all, and its `--json`
   over a two-train registry.
