**Steps**

1. `register`: `asf propose [--from-hold <item>/<class>] [--path P]... [--why LINE]
   [--evidence LINE]... [--patch FILE] [--title T] [--parent ID] [--product P] [--dry-run]`,
   exactly §2.4's usage line.
2. `--from-hold`: the hold's latest `refused` record from `approvals.read(product)` fills `--path`
   from its `detail`, the title as `Amend <path> — <why>`, and the patch from its `patch`. A hold
   that is unknown or not open is an error naming `asf approvals list` and exits 2.
3. `--why` is required; without it the command exits 2 saying a proposal with no reason is not
   evidence.
4. The parent: `--parent`, else `conventions.default_bug_epic`, else no `parent:` line at all — the
   groom then asks its one question, as intake always does (P7).
5. The patch crosses into the record only when `redact.scan_text` (`asf/redact.py:180`) finds
   nothing in it; otherwise the fence holds `patch withheld — the redaction gate found N
   finding(s)` and the patch stays in the machine-local ledger (§1.2, F-0075).
6. The card at `<record>/<conv.intake_dir>/propose-<slug of the first path>.md` (PD10), the slug
   being the path lowercased with every non-alphanumeric run collapsed to `-`; an existing
   proposal for the same path is overwritten — one open proposal per file. The body is §2.4's
   template: the title, `parent:`, `source: amend:<path>`, `## Description` (the `--why` line and
   the fixed F-0024 sentence), `## Evidence` (the refusal line naming the timestamp, job, item,
   tool and attempt count, then each `--evidence` line verbatim), `## The change proposed` holding
   the diff fence, and `## Acceptance` with its one box.
