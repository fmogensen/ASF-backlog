The spec's §*The design* §2 and §3 in full: `DECIDED_BY_SEVERITY`, `SUPPLY_MAX`, the `Supplied`
namedtuple, `supplied`, `supply` (the 13-guard ladder, in `derive`'s own order and on `derive`'s
own conditions — spec §3's table, reproduced there verbatim), and the four resolution helpers
`nearest_parent`, `best_epic`, `supplied_parent`, `title_acceptance`. Read **PD5** before starting:
this Task is both Stories at once, because the spec's own design is one function, not two.

**Files**

- `asf/groom/inbox.py` — add, in this order, directly from the spec's §2/§3 (copy the bodies
  there verbatim; they are the design, not a sketch for the coder to reinterpret):
  - `DECIDED_BY_SEVERITY = ('S1', 'S2')`, `SUPPLY_MAX = 14`, the `Supplied` namedtuple — spec §2.
  - `nearest_parent(canonical, iid, types)` — the climb to the first open legal ancestor, through
    `parent:`, guarded by `core.is_open` (never `file_bugs.usable_bug_epic`: PD2's citation, P13 —
    `asf.groom` stays out of `asf.tick` at module level; the one existing function-local import in
    this file, `body_signature`'s `from asf.tick import flaky` at **:205**, is not touched or
    extended).
  - `best_epic(canonical)` — the open Epic the feeder would reach first: decided before undecided,
    then `shape._rank` (unranked last), then id — the same order as `feeder.rows.feature_order`'s
    first key and `views.index_reader.rank` (PD2's citations).
  - `supplied_parent(card, canonical, types, default_bug_parent=None)` — the five-tier ladder (spec
    §3, the five-item list under its docstring): `nearest_parent` first, then `default_bug_parent`
    (validated through `core.is_open`) for a signed card, then `shape.infer_parent_epic`, then
    `default_bug_parent` again if not yet tried, then `best_epic`. Tiers 2-5 need `'epic' in
    types`, so a Task (`types == PARENT_TYPES['task']`, no `'epic'`) is only ever supplied a parent
    by the climb.
  - `title_acceptance(title)` — one acceptance item, the card's title, whitespace-folded.
  - `supply(card, canonical, default_bug_parent=None)` — the 13-row table of spec §3, each row
    guarding on the same condition `shape.derive` guards the matching question with (never the
    question's text), in `derive`'s own order; a guard that would supply `None` falls through to
    row 13 (the declared-type residue).
  - `supplied(card, canonical, default_bug_parent=None)` — the re-derive loop: call `derive`, and
    while it returns a `Question`, call `supply` and re-derive, up to `SUPPLY_MAX` times; a `Shape`
    with any clauses gets its rule prefixed `BY_RULE + result.rule` (Task 1's constant); a
    `Question` reached with no clause yet taken is returned bare (a residue — C9).
