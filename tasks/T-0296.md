## Description
stories: S-30451
writes: rules/memory-pointer.sh, tests/test_memory.py, tests/test_rules.py
after: Task 1

§2.2. `rules.core_rules_dir()` has resolved `<checkout>/rules` since B-0021 and the directory has
never existed (§1.1; `docs/plans/f-0040.md:37` records the same absence and assigns its creation
to a Task that has not landed — either card may create it, both only add files). This Task creates
it with one file in it: the thin script `resolve_script` expects, which shells out to
`asf memory check` so that "a memory file with no card" has exactly one owner (§1.4).

**Files**

- `rules/memory-pointer.sh` — new, executable, §2.2's four lines
- `tests/test_memory.py` — `RuleScriptTests`
- `tests/test_rules.py` — `ResolveTests` (new: PD9)

**Steps**

1. `rules/memory-pointer.sh`, §2.2's body byte for byte: the shebang, the two comment lines
   naming R-0124 and stating that paths come from the environment, `set -euo pipefail`, and
   `exec python3 -m asf.cli memory check ${ASF_PRODUCT:+--product "$ASF_PRODUCT"}`. It names no
   directory, no account and no host — the whole point — and `chmod +x` it, which
   `resolve_script`'s caller needs and `RuleScriptTests` asserts.
2. `"$@"` is appended after the `--product` expansion so the script can be run with `--dir` at a
   fixture, which is what §3's T2 does. Nothing else is added: a rule check that grows logic
   grows a second definition of the rule.
3. `tests/test_memory.py` gains `RuleScriptTests`: the file exists and is executable
   (`os.access(path, os.X_OK)`); its text matches no pattern in `tools/forbidden-names.txt` and
   names no path outside `$ASF_PRODUCT`; run with `--dir` at a temp fixture of two unpointed
   files it exits 1 and prints both base names; at a fixture where both files carry ids it exits
   0. The subprocess gets `PYTHONPATH` the way `tests/test_rules.py`'s `_run` already does, so it
   finds `asf` without an install.
4. `tests/test_rules.py` gains `ResolveTests` (PD9): `resolve_script` returns the product's own
   script when the product has one; the core script of the same base name when it does not, with
   `$ASF_CORE_RULES_DIR` pointed at a temp directory; `None` when neither exists; and — over the
   real `rules/` directory this Task creates, with `$ASF_CORE_RULES_DIR` unset —
   `resolve_script(<a root with no rules dir>, 'rules/memory-pointer.sh')` finds the shipped
   script by base name. The existing `CoreRulesTests` is untouched; it exercises the same
   resolution through `asf.rules.rules check`, and this class is the unit test under it.
5. Do not touch R-0124's card: a rule's `check:` and its `enforced:` line are record writes,
   outside this repo, and the final message carries them as `NEEDS OPERATOR` (§4).
