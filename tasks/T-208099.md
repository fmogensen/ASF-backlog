   the resolver's business, not the classifier's (**PD3**, **PD15**).
3. `write_grant_by_rule(paths, it, items, test_paths, trunk_files)` → the granted paths or `[]`,
   **its one home** (D-0007): every requested path matches a `test_paths` glob, is **not** in
   `trunk_files` (so it is a file this item adds, not one it edits), and is in no other live
   item's `writes:`. Its docstring names both callers — this class, and F-0358 §2.3's by-rule
   grant for a finding outside the footprint — and says the rule is all-or-nothing: one path the
   rule does not cover grants none of them. `BY_RULE` is §2.4's string verbatim.

   three stay exactly as they are — one rule, two callers, no copy.

   lambda p, g: _overlap([p], g))` — the one parser the REPORT field already uses (P12), so one

   `write_grant_by_rule(paths, it, facts.items, tuple(config.test_paths),
