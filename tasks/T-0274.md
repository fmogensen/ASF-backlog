## Description
stories: S-29405
writes: asf/briefs/facts.py, asf/briefs/preamble.py, asf/briefs/build.py, asf/briefs/templates/review.md, tests/fixtures/briefs/golden/review.md, tests/test_briefs.py, tests/test_brief_facts.py
after: Task 4

§2.6: the half of the card that makes the saving real — the round opens with the precheck's table
and is told that a finding already in it is never a new C. `build` never runs git, so the text
arrives through `facts.repo_facts`, which is where every git-read fact of a brief comes from.

**Files**

- `asf/briefs/facts.py` — `repo_facts` gains `precheck`
- `asf/briefs/preamble.py` — `REPO_FACT_KEYS` gains `'precheck'`; `collect` passes it through
- `asf/briefs/build.py` — `precheck_block` in `context`
- `asf/briefs/templates/review.md` — §2.6's opening
- `tests/fixtures/briefs/golden/review.md` — regenerated
- `tests/test_briefs.py` — `ReviewStartsFromPrecheckTests`
- `tests/test_brief_facts.py` — the `precheck` key

**Steps**

1. `facts.repo_facts`: for a `review` row, `facts['precheck']` is the text of
   `conventions.precheck_path(slug)` at the branch's rev, or `''` — read with the same
   `_git_text`/`ls-tree` rev the other keys use, so no extra fetch and no failure on a branch that
   does not exist. Every other row kind gets `''`. The docstring's "the six keys" becomes seven,
   and `REPO_FACT_KEYS` (`asf/briefs/preamble.py:234`) gains `'precheck'` — the two must not
   drift.
2. `preamble.collect` returns `'precheck': (repo_facts or {}).get('precheck') or ''`, beside
   `'last_report'`.
3. `build.context` gains `precheck_block`: the file's text when there is one, else the one line
   saying no mechanical pass ran — never an empty placeholder (§2.6). `precheck_level` and
   `precheck_path` are already context keys from Task 4; for a review row the level comes from
   `precheck.level_of(text)` (PD7) and falls back to `'unknown'`, and the path from
   `conventions.precheck_path(slug)` whether the file is there or not.
4. `templates/review.md` opens with §2.6's markdown byte for byte — the level, the path, the
   sentence that a finding already in the table is the precheck's and **never** a new C, then
   `{precheck_block}`. Nothing else in the template moves: the round, the review path and the C/I
   instruction stay exactly where they are.
5. Regenerate `tests/fixtures/briefs/golden/review.md` with
   `ASF_UPDATE_GOLDEN=1 python3 -m unittest tests.test_briefs` and read the diff: the opening
   added and nothing else changed.
6. `tests/test_brief_facts.py` per §3.6: `repo_facts` for a `review` row over a branch carrying a
   precheck returns its text under `precheck`; `''` for a branch with none; `REPO_FACT_KEYS` and
   the returned keys are the same set.
7. `ReviewStartsFromPrecheckTests` per §3.6: `build.build` over that row → the review brief
   contains the precheck's table verbatim, the never-a-new-C sentence and the precheck's path;
   with no precheck it contains the one-line "no mechanical pass ran" and no empty placeholder;
   and in both cases it still contains everything it does today — the round, the review path, the
   C/I instruction — asserted against the golden, not just by substring.
