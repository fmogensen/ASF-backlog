## Description

§2.5: the page's quickstart is the test's script, so the page and the thing that works cannot
diverge. The lines are written from commands that exist and outputs they actually print (PD5).

**Files**

- `asf/views/readme.py` — `quickstart(text) -> [Step]`, the parser §2.5's contract describes, and
  that contract in the module docstring.
- `README.md` — the quickstart block's lines, corrected to what runs.
- `tests/test_readme.py` — `QuickstartTests`.

**Steps**

1. The contract in the module docstring and in the parser: every line is blank, a `#` comment, an
   expected-output line (`# → <text>`) or a command; exactly one line carries the trailing marker
   `# your product`; every other line runs verbatim, in order, in one shell, and must exit 0; each
   `# → <text>` asserts `<text>` appears in the preceding command's stdout. A block with no
   `# your product` line, or with two, is an error naming the line.
2. The lines themselves (PD5): `asf init --product …` exists (`asf/init.py:309-316`); `asf tick`
   exists and `--once` does not (`asf/tick/tick.py:434-445`); `asf next` and `asf doctor` exist.
   Write the block with those, run it under the fixture, and take each `# → ` expectation from what
   the command printed — never from the spec's sketch, never from memory.
3. The fixture is the one `tests/test_sample_product.py` already builds: `sample/` copied to a temp
   dir, bare origins for `repo/` and `backlog/`, a temp `ASF_HOME` with the `fake` worker runtime and
   no scheduler. `_publish`, `_fill` and `SAMPLE` are imported from that module the way it already
   imports `fake_clis` from `tests/test_scheduler.py` — no fixture is duplicated.
4. `QuickstartTests` per §3.6: parse the block out of the real `README.md`; replace the whole
   `# your product` line with the fixture's equivalent, and name the replaced line in any failure
   message; run every other line verbatim in one shell; assert each exit status is 0 and each `# → `
   text appears in its command's stdout.
5. The page stays inside Task 4's budget and its spans are untouched, so `OnePageTests` and
   `CommittedPageTests` stay green without a re-refresh. The Gate runs both to prove it.

**Gate**

```sh
python3 -m unittest -v tests.test_readme
python3 -m unittest -v tests.test_readme.OnePageTests tests.test_readme.CommittedPageTests
python3 -m asf.cli readme --check
python3 tools/run_tests.py 2>&1 | tail -3
bash tools/check_generic.sh && bash tools/check_conventions.sh && python3 -m asf.cli check
```
