## Description
stories: S-31110

§2.9 — the half of the card's part 4 that is testable end to end, and the honest half of the word
"redacts" (D8). A hook can refuse a call whose output would carry a secret; it cannot rewrite one.
What this Task does is make sure that nothing the factory *copies out of a log* carries one. The log
file itself is left exactly as the child wrote it (D9): it is the evidence, it lives under the
operator's own state directory, and rewriting evidence to make a check pass is what this factory
refuses everywhere else.

**Files**

- `asf/redact.py`:
  - `scrubbed_lines(log_path, repo=None)` — §2.9's one reader: every line of a job log with every
    protected name and secret replaced by `SCRUB_TOKEN`, through today's `scrub` and
    `default_patterns`. Each line stays valid JSON, because `scrub` replaces values inside the
    strings and never the structure.
  - `scrub_text(text, repo=None)` — the same for one string, so the three call sites below do not
    each build a pattern set.
  - `--log <job>` in `add_arguments`, and the branch in `cmd_redact` that prints a job's transcript
    scrubbed, for an operator who has to read one.
- `asf/workers/runtime.py` — one change, at the source: `ClaudeCodeRuntime.run`'s
  `text=(rec or {}).get('result', '')` becomes `text=redact.scrub_text(...)` (`:538-541`). Every
  durable copy downstream of a run — the session record's `result`, the console line, the harvest's
  read — is fed from `Result.text`, so scrubbing here covers them all with one call.
- `asf/workers/stall.py` — `correct_once` scrubs `error_text` before it writes it into the
  correction brief (`:237-247`): a token in a failure message was about to be written into a file
  and handed to another session.
- `asf/tick/step_health.py` — the `ruling` text read straight off a log record (`:137`) goes through
  `scrub_text`. This is the one of "every view that prints a report line" that ends up **durable**:
  a ruling is written into a record card. The two reads in `asf/tick/widen_footprint.py` (`:95`,
  `:283`) extract path globs, which cannot be a token, and are left alone rather than touched for
  symmetry — stated here so the omission is read as a decision.
- `tests/test_worker_deny.py` — `TranscriptScrubTests`: T11, every clause. A fixture job log
  carrying, on separate lines, a fixture `CLAUDE_CODE_OAUTH_TOKEN` value, a `GH_TOKEN` value, a
  `gh`-shaped literal, an Anthropic-key-shaped literal and a worker account name — every one built
  by concatenation (**PD10**). Then: `scrubbed_lines` contains none of the five and every line is
  still valid JSON; the session record written from that log carries none; the correction brief
  `correct_once` writes carries none; `asf redact --log <job>` prints none; `redact.scan_text` over
  all four outputs returns no finding; and the log file itself is asserted **unchanged**, byte for
  byte.

**Steps**

1. `scrubbed_lines` and `scrub_text`, and `TranscriptScrubTests`' first clause over a fixture log.
2. `redact --log` and its clause.
3. The three call sites, one at a time, each with its clause.
4. The log-unchanged assertion last — it is the one that fails if a well-meant filter was put in
   front of the child's fd.
