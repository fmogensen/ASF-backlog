§2.4: the three call sites that count a taken slot stop counting rows and start counting seats.
The wave's `already running` guard keeps reading the whole unrecorded list, so nothing is launched
twice and nothing about the *item* moves earlier than it does today (§1.2, §3.3).

**Files**

- `asf/workers/lifecycle.py` — `inflight(path, product=None, alive=None)` and
  `live_all(state_root, alive=None)` each gain `'state'` per row (`:272-276`, `:182-194`).
- `asf/capacity.py` — `inflight_sessions(name)` → `seats(inflight(...))`, with P12's product
  resolution (`:99-103`).
- `asf/feeder/tiers.py` — `free_slots(inflight, capacity)` → `max(capacity - lifecycle.seats(inflight), 0)`
  (`:22-23`).
- `asf/workers/pool.py` — `live_sessions(product, alive=None)` carries the state (`:191-192`);
  `Pool.load` and `Pool.lane_load` count only seat-holders (`:256-262`); `Pool.from_config` passes
  the `observe.identity_alive(observed, registered)` it already computes to `live_all`, and an
  observed extra is built carrying `state: working` (`:234-242`).
- `asf/tick/step_wave.py` — `inflight(product)` passes the product through (`:41`).
- `tests/test_lifecycle.py` — the `inflight`/`live_all` rows now carry `state` (P17, `:288`); the
  ratchet loses `asf/capacity.py` and `asf/feeder/tiers.py`.
- `tests/test_capacity.py`, `tests/test_feeder.py`, `tests/test_workers.py` — §3.2's cases.

**Steps**

1. `inflight(path, product=None, alive=None)`: each dict gains `'state'` from
   `state_of(product, run, alive=alive, path=path)`. The *list* is unchanged — every run the
   ledger has not closed — so `rows.inflight_ids`, `groom_row` and `groom.policy.suppress` keep
   holding their items busy, which is what §3.3 asserts.
2. `live_all(state_root, alive=None)`: same, per product registry, each row still carrying its
   `product` and `session`.
3. `tiers.free_slots` and `capacity.inflight_sessions` route through `lifecycle.seats`; through
   the second, `inflight_sessions_elsewhere` and the operator total follow with no further change
   (`asf/capacity.py:106-110`, `:215`).
4. `Pool.load`/`lane_load` filter on `lifecycle.holds_seat` — a row with no `state` (a hand-built
   pool in a test, an observed extra) holds a seat. `Pool.from_config` hands `live_all` the
   identity-liveness callable it builds for the extras, so the pool's load becomes "processes that
   answer" at no second `ps` (P5 of the spec's preconditions, `asf/workers/pool.py:234-239`).
5. `wave`'s `running` set is left exactly as it is (`asf/workers/wave.py:40`): it reads the whole
   `pool.live` list, seat-holding or not, so a job whose run the ledger has not closed still waits
   with `already running`. No change to `asf/workers/wave.py` — the spec's §2.4 last bullet is
   satisfied by not touching it, and Task 2's tests assert it.
6. `pool.live_sessions(product, alive=None)` carries the state for Task 3's views to split on.
7. The ratchet in `tests/test_lifecycle.py` loses this Task's two modules.
8. Tests per §3.2, in the repo's existing idiom (temp `ASF_HOME`, no network).
