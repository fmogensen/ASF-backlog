§2.1 and §2.2: the directory that is not the suite, and the one module that reads it. Nothing
scores anything yet — the roster is empty (PD5) — and that is the point: the loader and the hash
are the instrument's identity, and they are provable with no adapter in the tree.

**Files**

- `evals/README.md` — why this is not the suite; how to add a lever; why a task is never edited
  (§2.1's own list). The three sentences that must be in it: an eval is frozen and scored as a
  rate; a wrong task is **deleted and replaced**, never edited, and the hash records that as a new
  instrument; a lever with only one polarity measures half an instrument.
- `evals/manifest.json` — `{"levers": [], "min_tasks": 2, "require_both_polarities": true}`, with
  no comment key: JSON, stdlib, the precedent being `sample/fake_script.json`.
- `evals/exemptions.json` — `{"exemptions": []}`; an entry is
  `{"lever": "<id>", "reason": "<why there is no pair yet>", "card": "<id>"}`, both strings
  required and non-empty.
- `asf/evals/__init__.py` — the package docstring: what a lever is, what a task is, and the one
  rule that separates this package from `tests/` (an eval is never edited to make it pass).
- `asf/evals/set.py` — `EvalError`; `Task`, `Lever`, `Set` exactly as §2.2's three frozen
  dataclasses; `ADAPTERS = ('matcher', 'brief-kind', 'rule-check')`; `default_root()`;
  `load(root=None)`; `lever_hash(lever)`; `set_hash(levers)`.
- `tests/test_evals.py` — new module; `SetLoadTests`, `SetHashTests`.

**Steps**

1. `asf/evals/__init__.py` and `asf/evals/set.py`, stdlib only (`dataclasses`, `fnmatch` is Task
   7's, `glob`, `hashlib`, `json`, `os`). No product name, no branch prefix, no `tools/*.sh` path
   literal and no `E-nnnn` id: `tools/check_generic.sh` and `tools/check_conventions.sh` refuse all
   four, and the `tools/[A-Za-z0-9_-]+\.(py|sh|json)` pattern (`tools/forbidden-conventions.txt`)
   is why a check script's path lives in `evals/manifest.json` and never in this package.
2. `default_root()` — `$ASF_EVALS_DIR`, else `evals/` beside the package's parent, the shape
   `rules.core_rules_dir` already has (`asf/rules/rules.py:56`); `None` when neither is a
   directory, which the caller reports (PD10). A product's own set is not this function's: it is
   `os.path.join(record_root, conv.evals_dir)`, passed in by the caller, and `conventions.evals_dir`
   is read for it — never the literal (PD10).
3. `Task`, `Lever` and `Set` as §2.2 writes them, `frozen=True`, `Lever.tasks` and
   `Lever.implements` tuples, `Set.set_hash` twelve hex characters.
4. `load(root=None)`: the manifest first (`levers`, `min_tasks`, `require_both_polarities`), then
   every `*.json` under each lever's `tasks` directory in **sorted path order**, then
   `exemptions.json`. A family entry (`"family": true`) expands to one lever per subdirectory of
   its `tasks` template's parent, the id being `rule:<dir name>` — with an empty roster this is
   dead code until Task 4, so write it once and let Task 4's fixtures be its first exercise.
5. The refusals, each an `EvalError` naming **the file and the key** (§2.2's list, and §3.1 asserts
   every one): an unknown `adapter` (not in `ADAPTERS`); an `expect` that is neither `fire` nor
   `no-fire`; a missing or empty `why`, `given` or `want`; a `lever` field disagreeing with the
   directory; a `*.json` under no lever's directory; a duplicate task `id`; an exemption for a
   lever that has a pair; an exemption with no `reason` or no `card`.
6. `lever_hash(lever)` — `sha256` over, per task in path order, the task's repo-relative path and
