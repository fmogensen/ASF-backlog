§2.5. The brief becomes five parts, the new one second: the item line, the role block, the
preamble, the kind template, the tail. `Brief` gains `role` and `role_sha`. `build` gains a
`cfg` parameter it does not yet read (PD4), so Task 3 adds no signature change of its own. No
template line is deleted (In/out, PD14).

**Files**

- `asf/briefs/build.py` — the module docstring's "four parts" becomes five, with the new line in
  place (`:10-16`); `Brief` gains `role: str = ''` and `role_sha: str = ''` (`:113-122`);
  `role_block(product, kind)` returns `(block_text, role_name, role_sha)` — `''`/`''`/`''` for a
  kind whose role is in `UNBOUND` or whose roles dir is unreadable; `build` inserts it as the
  second part and fills the two new fields; `build(…, cfg=None)` and `cmd_brief` loading the
  operator config (PD4). `asf.roles` is imported inside `role_block`, not at module level.
- `asf/conventions.py` — `DEFAULT_ROLE_MAX_LINES = 60` beside `DEFAULT_PREAMBLE_MAX_LINES`
  (`:67`), and `role_max_lines: int = DEFAULT_ROLE_MAX_LINES` on `Conventions` beside
  `preamble_max_lines` (`:145`).
- `docs/products.example.yaml:52` — `# role_max_lines: 60` beside `# preamble_max_lines: 120`,
  with the one-line comment saying what it caps (PD5).
- `tests/test_briefs.py` — `RoleBlockTests` (new, §3/T4).
- `tests/fixtures/briefs/golden/*.md` — regenerated; every bound kind's golden grows by its
  role's block (PD16).

**Steps**

1. `asf.briefs.build.role_block(product, kind)`: `roles.for_kind(kind)` → the name, `None`/absent
   when the kind's role is in `UNBOUND`; `roles.load(name)`; `roles.block(role, cap)` with the cap
   from `preamble.conventions(product).get('role_max_lines')` when it is a positive int, else
   `DEFAULT_ROLE_MAX_LINES`. A `RoleError` — an unreadable dir, a file that is not there — returns
   the empty triple: an invalid role dir is a red gate and a red doctor row, never a dead wave
   (In/out, D12). Nothing is validated here; validation is `asf roles --check` and doctor's job.
2. `build`: the block goes between `item_line(...)` and `preamble_mod.build(...)` in `parts`
   (`build.py:294-298`), empty parts dropped by the existing `'\n\n'.join(p.strip() …)` — an
   unbound kind renders no heading and no blank run. `Brief(... role=…, role_sha=…)`.
3. `build(product, row, index, inflight=None, repo_facts=None, cfg=None)` (PD4) — unread this
   Task, threaded so Task 3 changes no caller. `cmd_brief` loads the config the same tolerant way
   `spawn.load_cfg` does and passes it. `asf/briefs/__init__.py`'s wrapper and
   `step_wave._build` pass through `*a, **kw` already and need no edit.
4. `asf/conventions.py` and `docs/products.example.yaml` per PD5.
5. `RoleBlockTests` per §3/T4: for every kind in `KINDS`, the built text contains
   `## Who you are — <role>` exactly once and at an index after the item line and before the
   preamble's first heading, and carries that role's Doctrine bullets; with
   `conventions={'role_max_lines': 12}` the block is cut on a section boundary and its last line
   is `… (role <name> truncated at <n> lines)`; a kind whose role is in `UNBOUND` renders no
   heading (asserted over a `BINDINGS`-less kind via a temporary roles dir, since every kind in
   `KINDS` is bound — §2.3).
6. Regenerate the goldens and read them back, as §3/T4 fences it. The diff is reviewed line by
   line: a golden that grew by anything other than its role's block is a bug in step 2.
