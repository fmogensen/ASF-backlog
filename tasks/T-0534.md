## Description
stories: S-35880, S-35881

after: none

The spec's first, second, fifth and sixth **In** bullets and `## The design` §§`_NWO`, `_out`,
`known_ref`, `resolve_target`. Four additions above `install`, and one two-line rewrite inside
`ci_red`. **`install()` is not touched in this Task** — `resolve_target` has no caller when this
lands, so the factory's behaviour is byte-identical and the whole Task is judged by its own two test
classes plus the regression fence.

That idleness is the reason it lands first: the gate in Task 2 is one call, and it should be a call
to something already proven three-valued rather than something being written in the same diff.

Read **PD1** (the `any_rc` case `FakeRun` cannot express), **PD3** (`ls-remote`'s default answer),
**PD7** (the regex lift is measured) and **PD8** (the three load-bearing details) before starting.

**Files**

- `asf/upgrade.py` — `_NWO` beside `HEX40` (`:350`); `_out` gains `any_rc` (`:323-329`); `ci_red`'s
  first two lines over `_NWO` (`:444-446`); `NO_COMMIT_STATUS`, `known_ref` and `resolve_target`,
  all three placed after `resolve_ref` (`:353-364`) and before `other_ticks`
- `tests/test_install.py` — `KnownRefTests` and `ResolveTargetTests`, beside `UpgradeToTests`
  (`:683-743`)

**Steps**

1. `_NWO` with the spec's `#:` comment and body byte for byte, beside `HEX40` at `:350`. Then
   `ci_red`'s `m = re.search(r'github\.com…', url)` (`:444`) becomes `m = _NWO.search(url)`, and
   `if not m: return False` stays as it is. Nothing else in `ci_red` moves and its behaviour does not
   change (PD7 — measured over five url shapes, including the ssh and the non-GitHub one).
2. `_out` gains `any_rc=False` as a fourth parameter and the spec's two-sentence docstring addition,
   and its return becomes
   `return p.stdout if (any_rc or p.returncode == 0) and isinstance(p.stdout, str) else None`.
   Default-off, so `repo_url`, `remote_head`, `resolve_ref` and `ci_red` are unchanged — do not add
   the keyword to any of them.
3. `NO_COMMIT_STATUS = '422'` with the spec's two-line `#:` comment byte for byte. It is D4's whole
   argument (a 404 is the repo, never the ref) and a bare `'422'` inline would lose it.
4. `known_ref(url, ref, run=subprocess.run)` with the spec's body and docstring byte for byte. The
   three details at PD8 — `.strip()` before the match, `or {}` before the `.get`, `str(...)` around
   the status — are each load-bearing and measured; keep `AttributeError` in the `except` clause
   beside `ValueError`, it is what catches a JSON scalar body.
5. `resolve_target(url, ref, run=subprocess.run)` with the spec's body and docstring byte for byte,
   directly below `known_ref`. Note that `resolve_ref` short-circuits on `HEX40` itself (`:358`), so
   the `ref if HEX40.match(ref) else …` guard is belt and braces rather than a behaviour — keep it as
   written, because it is what makes the *"a forty-hex sha is never `ls-remote`d"* rule readable at
   the gate rather than only inside the function it calls.
6. `KnownRefTests(unittest.TestCase)` in `tests/test_install.py`, below `UpgradeToTests`. Class
   fixtures: `URL = 'https://github.com/o/r.git'`, `GOOD = 'b' * 40`, `TYPO = '5304f6d16' + 'a' * 31`,
   `SHORT = '7a5881d'`, `EXPANDED = SHORT + 'e' * 33`, and `NO_COMMIT` / `NO_REPO` as the spec writes
   them. One case per clause of the spec's §S-35880 list:
   - `GOOD` confirmed → the full sha, and `run.calls == [['gh', 'api', '-H',
     'Accept: application/vnd.github.sha', 'repos/o/r/commits/' + GOOD]]` — the exact command, asked
     **once**;
   - `NO_COMMIT` → `assertIs(..., False)`, never `assertFalse` (`None` must not pass);
   - `NO_REPO` → `assertIsNone`;
   - empty stdout → `None`; a `run` raising `OSError` (no `gh`) → `None`; `URL` replaced by
     `'git@example.invalid:o/r'` → `None`, and **no** subprocess call at all (`run.calls == []`);
   - the source answering `'f' * 40` for `GOOD` — some other commit → `None`;
