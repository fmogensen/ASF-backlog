The spec's `## The design` §C in full: the `started` record carries what finds its run,
`Queue._placed` nets its claim against the runners it already holds from one lazy busy read, a
record with nothing left unplaced is dropped, and an unreadable host counts exactly as today. Plus
the `running=` fixture the fences need (PD11) and the guide's queue section for all three halves
(PD13). **The card's second defect closes here** — heavy reads 2 free where it read 0.

**Read PD8 before starting**: `_placed` must be memoised per pass and must never write
`Queue.busy`. `_broken_reserve` and `_busy_runs` read `q.busy or {}` and feed the relief pass's
cancel candidates; a pass that saw `{}` seeing a populated map changes which runs get cancelled,
which is not this card. Read **PD11** (`busy_runners()` returns None against the shipped `FakeGh`,
and the `total_count` digit line is what makes the status listing parse at all) and **C6** (the
claim is *netted*, not dropped whole — dropping whole replaces a 2× over-count with an under-count
of the same shape, and a seven-job run that has placed one would stop claiming the other six).

**Steps**

1. The `started` append (`:2267`) gains what identifies the run: `'branch'` (the entry's branch —
   `key.split(':', 1)[1]` where the key carries one, else `e['item']`, the same derivation the head
   guard's line already uses at `:2259`), `'sha'` (`e.get('sha')`) and `'workflow'`. A3's `start()`
   asserts `(rec['key'], rec['branch'], rec['workflow']) == ('pr:b', 'b', 'ci.yml')`.
2. `Queue._placed()` with the spec's docstring, memoised in `self._placed_map` for the pass
   (PD8). Per started record, the slots its run already holds: a busy runner is its run's when the
   run's `head_branch` is the record's `branch`, its workflow file
   (`os.path.basename(run['path'])`) is the record's `workflow`, and its `head_sha` is the record's
   `sha` **where the record carries one** — a start re-set by a new push keeps its place but takes
   the new head, and a record from before this Task carries no `sha` and matches on branch and
   workflow alone. The runner's slots count against **every** fit key it satisfies, because that is
   every key whose supply already counts it busy: for each key in the record's `needs`, add the
   runner's slots when its `norm_labels()` cover `fit_asks(key)[1]` and its class is the key's.
3. The busy read is lazy and taken at most once per pass (C7, PD8): `_placed` returns `{}` at once
   while `self.data['started']` is empty — **no host call**, which A3's
   `test_an_empty_ledger_asks_the_host_for_nothing` asserts. Otherwise it uses `self.busy` when
   that is not None (the relief pass has already read it, `:1497`), else calls
   `self.source.busy_runners()` once inside a `try` and caches the answer — `None` included — in
   `self._placed_busy`. `None` means `{}` placed, which leaves the pass counting as it does today:
   it over-holds, never over-starts.
4. `Queue.free` subtracts the residual: `max(0, need - placed)` per key, over the same
   `if c in free` guard it has today. The netting writes what it learned back into
   `self.data['started']` — each record keeps its `placed` map beside its `needs` — and a record
   whose every key is fully placed is taken out of the list. Both side effects belong to the
   memoised `_placed()` so they happen once however many times `free` is called in a pass
   (`live_line` calls it n+1 ti
