§2.1: one dict, one frozenset and two pure functions. Stdlib only — the module imports nothing
from `asf`, which is what D10 buys by taking the product as a string. Nothing calls it yet;
Task 2 is its first caller.

**Files**

- `asf/views/header.py` — new: `TITLES`, `STAMP_VERSION`, `head`, `command_key`
- `tests/test_views_header.py` — new: `HeaderTests`, `CommandKeyTests`, `RegistryTests`, `PENDING`

**Steps**

1. `asf/views/header.py`, with §2.1's code and its three doc comments copied as the spec writes
   them: `TITLES` with all twenty keys (`status`, `next`, `backlog`, `roadmap`, `parity`, `prod`,
   `sessions`, `scorecard`, `release-readiness`, `capacity`, `tokens`, `stale`, `doctor`,
   `rules check`, `ci`, `ci queue`, `ci reconcile`, `ci reserve`, `health`, `performance`),
   `STAMP_VERSION = frozenset({'doctor'})`, `head(command, product, clause='')` and
   `command_key(args)`.
2. `head()` exactly as §2.1 writes it: `f"**{TITLES[command]} {product}**"`, then
   `f"{title} — {clause}"` when `clause` is truthy and the bare title otherwise. The `KeyError`
   on an unregistered command is the documented behaviour, not a bug — no `.get`, no default.
3. `command_key(args)` exactly as §2.1 writes it: `args.command` with `-` mapped to `_`, plus
   `_command`, read off `args` with `getattr(…, None)`; the joined `f"{args.command} {sub}"` when
   that attribute is set, else `args.command`. `release-readiness` therefore probes
   `release_readiness_command`, finds nothing, and keys as itself.
4. `HeaderTests`: a clause appends ` — <clause>`; an empty clause and a `None`-ish clause append
   nothing; the product name sits inside the bold, before the closing `**`; every title is taken
   from `TITLES` and not retyped in the assertion; an unregistered command raises `KeyError`.
5. `CommandKeyTests`: over `build_parser().parse_args([...])`, not a stub —
   `['ci', 'queue', …]` → `'ci queue'`, `['ci', 'reconcile']` → `'ci reconcile'`,
   `['ci', 'reserve']` → `'ci reserve'`, `['rules', 'check']` → `'rules check'`,
   `['status']` → `'status'`, `['release-readiness']` → `'release-readiness'`.
6. `RegistryTests`, with PD10's escape: `PENDING = {'health', 'performance'}` and the comment
   naming Task 7 as what empties it. Two assertions —
   `set(plugin_build.VIEWS) <= set(header.TITLES)`, and every `TITLES` key's first word is either
   in `registered_commands()` (the helper `tests/test_plugin.py:23` already has, repeated here
   rather than imported across test modules) or in `PENDING`. `'ci'` is already registered
   (`asf/ci_pool.py:1218`), so only the two land in `PENDING`.
7. No `asf/views/__init__.py` change here — Task 2 owns that file's docstring.
