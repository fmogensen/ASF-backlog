- `asf/workers/stall.py` — `correct_once(product, session, error_text, runtime, mark='corrected',
  suffix='-correction')`
- `asf/workers/lifecycle.py` — `RUN_FIELDS` gains `transport_retry`
- `asf/tick/step_health.py` — the two `transport` branches and `transport_retry`
- `tests/test_failure.py` — `TransportTests`, `WorkTests`
- `tests/test_tick_steps.py`, `tests/test_dead_run_load.py` — the existing suites, green unchanged

**Steps**

1. `stall.correct_once` gains `mark='corrected'` and `suffix='-correction'` with §2.5's docstring.
   `error_text=None` writes **no** file and launches the original brief, unchanged, under
   `f"{session['job']}{suffix}"` — no `.correction.md`, no `CORRECTION_HEAD`, because that text
   tells a session its work was at fault (D8). Everything else is unchanged: its own job, its own
   log, its own ledger line, the `id_range` and `ASF_SESSION` handling (D-0048 part b).
2. The early return becomes `if session.get(mark): return False` (PD9), and the field it marks on
   the original run is `mark`, set through `pool_mod.update_session`.
3. `asf/workers/lifecycle.py`: `'transport_retry'` in `RUN_FIELDS` (`:108`), so it belongs to the
   launch that earned it and is never inherited by the next launch on the same job (B-0041).
4. `step_health.transport_retry(ctx, session, why, runtime_fn, out=print)` — §2.5's third bullet:
   `stall_mod.correct_once(product, session, None, runtime_fn(), mark='transport_retry',
   suffix='-retry')`, `transport_retry: 1` on the original and on the retry, one line, and
   `ctx.counts['relaunches'] += 1` — it *is* a relaunch. Returns `'retried'`.
5. The two `transport` branches in §2.5's block: the first when `not session.get('transport_retry')`,
   the second (D9) returning `operator(ctx, session, cls, why, out=out)` — one needs-operator line
   naming the product and the class through `failure.operator_text`, no second launch, no hold.
   Below them, `# work: exactly what this function does today` and not one changed line.
6. `handle_dead`'s docstring gains the three new returns beside today's six
   (`credential` | `quota` | `retried`), as §2.5 says. `hold_failed_corrections` keeps its
   `-correction` suffix test untouched: a `-retry` run is judged as an ordinary run, and a *work*
   failure on it is corrected the ordinary way. `ROLE_PREFIX` (`asf/record/match.py:30`) and
   `KIND_PREFIXES` (`asf/metrics/metrics.py:44`) match a job's *prefix*, so `-retry` needs no
   registration — assert that, register nothing.
