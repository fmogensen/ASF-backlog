The spec's `## The design` §3 in full, plus the two fences it does not name (PD3, PD5). After this
lands, `asf brief --kind epic-features` builds a brief that tells a session to draft an Epic's
Feature cards and file them with `asf inbox`, on the HEAVY model, under the interrogator's role,
with the record's intake directory on its `--add-dir` list — and the trunk carries no row kind yet,
so nothing launches it until Task 2 lands.

This is a `CONSOLE → AMEND` Task: `asf/briefs/templates/epic-features.md` is in the `role_agents`
amendable kind, so the operator's session writes it, never a coder's (P15, PD1).

Three things are load-bearing. **`KINDS` and everything else land in one commit** — the moment
`epic-features` is in `KINDS`, five whole-set fences iterate it, and a half-landed kind is a red
suite for a kind with no template (P14). **HEAVY is not a preference** (PD4): with the
`asf-interrogator` binding, LIGHT, CHEAP and a missing `MODEL_TABLE` row are each one red test.
And **the record grant is what makes `asf inbox` reachable at all** (PD5) — without it the
session's only write is outside every directory it can see.

Read **PD3 and PD4 before touching `KINDS`**, **PD5 before writing the `add_dirs_for` clause**,
**PD7 before wording the `{done_features}` heading**, **PD13 before writing the defect-word
sentence**, and **PD8 before the `ROWS` entry and the golden**.

- `asf/briefs/templates/epic-features.md` — **new**, the spec's §3 template, with PD7's and
  PD13's two corrections and nothing else changed: the heading reads *"Features already under this
  Epic — do not draft these again"*, and the defect-word sentence states the conjunction. The
  `asf inbox` line stays bare of `--product` (PD6). Placeholders used: `{item_id}`,
  `{item_title}`, `{description}`, `{done_features}` — the first three are existing `context()`
  keys, the fourth is this Task's.
- `asf/briefs/build.py` — four edits. `KINDS` gains `'epic-features'` at the end (19 → 20).
  `MODEL_TABLE` gains `'epic-features': {'default': HEAVY}` (PD4); `DEFAULT_MODELS` is derived and
  needs no edit. `context()` gains **one** key,
  `'done_features': facts['done_features'] or 'none — this Epic has never had a Feature',`.
  `add_dirs_for` gains the `epic-features` clause (PD5), keyed on `kind` alone, deriving
