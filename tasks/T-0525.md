§2.6 and §1.3's frozen string. Half of this Task is a test that asserts nothing changed: the class
string `not pushed`, `score.failure_class`, the cause key `failure:failed: not pushed`, its title
and `diagnose.metric`'s number. §1.3 is unusually emphatic about why — this card is verified by
reading that key over the two weeks after it lands against the two before, so any change to the
string, the classifier or the key would drive the reading to zero without a single session pushing
anything, *"a number that falls because the meter was replaced is a lie told to the loop that filed
this card"*. The other half is one line of evidence in the cause's detail, so whoever picks up a
reopen knows which sub-cause is left.

**Files**

- `asf/improve/measure.py` — two defaulted fields on `Run`, populated in `ended_runs` (PD1)
- `asf/scorecard/diagnose.py` — `NOT_PUSHED_SUBS`, `sub_cause`, `sub_cause_line`, the `sub` key in
  `rank`'s failure fold (`:87-95`), the detail line in `causes` (`:188-196`)
- `tests/test_scorecard.py` — `NotPushedCauseTests`

**Steps**

1. `asf/improve/measure.py`: `Run` gains `publish_refused: str = ''` and `worktree: str = ''` at the
   end of the field list, each with a one-line comment saying which registry key it is and that it
   is read by `diagnose`'s sub-causes and nothing else. `ended_runs` (`:120-124`) passes
   `publish_refused=r.get('publish_refused') or ''` and `worktree=r.get('worktree') or ''`. Defaults
   are mandatory: `tests/test_improve.py:215` constructs `Run` positionally with ten arguments and
   is outside this Task's `writes:`.
2. `asf/scorecard/diagnose.py`: `NOT_PUSHED_SUBS` — the sub-cause names in the order the line prints
   them, with a `#:` comment saying they are disjoint by construction and exhaustive (PD2), and that
   they are read off evidence already recorded and computed nowhere else.
3. `sub_cause(run)` — pure, one run to one name, in this precedence, which is what makes the buckets
   disjoint and the line sum to the count above it:
   1. `refused` — a non-empty `run.publish_refused`: the factory tried and was refused. Its own
      split comes from `asf.workers.lifecycle`'s pure text classifiers (local import, the idiom
      `asf/scorecard/facts.py:392-410` uses): `rebase_conflict` → `rebase conflict`, `stale_head` →
      `stale head`, else `push_failure` → `hook refused` / `network`, else `refused`.
   2. `no worktree` — a falsy `run.worktree`: nothing was left to publish, and `publish_gap` returns
      before writing any line for such a run (`asf/workers/health.py:341-342`), which is why this
      cannot be read off `publish_refused`. The never-pushed case leaves none either: `publish_gap`
      returns at `:350` with nothing attempted, because `ev.unpushed` is `0` and there is no
      `remote_sha`.
   3. `uncommitted` — the `end_reason`'s uncommitted count is above zero.
   4. `unpushed` — uncommitted zero, unpushed count above zero.
   5. `never pushed` — both counts zero: the branch origin never held (PD2).
   6. `other` — an `end_reason` the count regex cannot read. Present so the line always adds up and
      a future wording change is visible rather than silently swallowed.
   The counts come from one module-level regex over the frozen string
   (`(\d+) uncommitted file\(s\), (\d+) unpushed commit\(s\)`), with a `#:` comment naming §1.3: the
   string this reads is frozen for the length of this Feature, and the T6 fence is what says so.
4. `sub_cause_line(subs, total)` — §2.6's sentence from a `{name: int}` dict: `of the 23 runs: 9
