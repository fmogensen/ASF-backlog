The spec's §`asf/cli.py`, `asf/doctor.py`, `asf/upgrade.py` — the pointer — and its seventh **In**
bullet, the advisory `config keys` row. Three places a load failure surfaces, all naming the same
command, plus the row that says what is parked so a parked key is not a lost key with extra steps.
Independent of Task 3 in substance; queued behind it on `tests/test_install.py` (PD8).

**Files**

- `asf/cli.py` — `needs_operator_line` (`:362-363`)
- `asf/doctor.py` — `check_config`'s product branch (`:128-129`), `check_config_keys`, one row in
  `run` beside the `backlog` row (`:817-818`)
- `asf/upgrade.py` — `row`'s `ConfigError` branch (`:588`)
- `tests/test_cli.py` — `RefusedProductFileTests` (`:16`) extended
- `tests/test_doctor.py` — `ConfigRowPointsAtConfigCheck`, `ConfigKeysRow`
- `tests/test_install.py` — `UpgradeRowPointsAtConfigCheck`

**Steps**

1. `needs_operator_line(err, product=None)` — the spec's replacement, byte for byte. It stays **one
   line** and still carries `asf init --product {p}`, so `tests/test_cli.py:35-42`'s pin holds (P10):
   exactly one line on stdout, starting `NEEDS OPERATOR: `, containing `asf init --product sample`,
   exit 2, for `status` and for `tick`.
2. `doctor.check_config`'s product branch returns
   `False, f'products/{product_name}.yaml: {e} — asf config check --product {product_name}'`. The
   two-value shape of that return is unchanged; `run` reads `result[0], result[1]` and returns the
   row alone (P8, `:817-819`), so a refused file still renders as one row — now one with a route.
3. `check_config_keys(product)` → `(ok, detail)`: how many keys are parked under `x-unmapped:` and
   how many old-but-read spellings are in the file, with the command. `no unmapped or renamed keys`,
   or `2 keys parked under x-unmapped:, 1 old spelling still read — asf config check --product p`.
4. `run`: `rows.append(('config keys', False, ok, detail))` after the `backlog` row. **Not required**
   (D15) — a parked key is a decision owed, not a broken install, and a row that goes red on a state
   the operator cannot clear without a product decision teaches them to ignore the doctor.
5. `upgrade.row`'s `ConfigError` branch returns
   `(name, '?', str(schema.SCHEMA_VERSION), f'fix the config: {e} — asf config check --product {name}')`.
   The diagnosis is kept beside the command, not replaced by it (PD6).
6. `ConfigRowPointsAtConfigCheck`: a product file with an unknown key gives `config` RED and exactly
   one row, whose detail ends in `asf config check --product <p>`.
7. `ConfigKeysRow`: a loadable file carrying a hand-written `x-unmapped:` block with two keys and one
   old-but-read `conventions:` spelling gives a `config keys` row counting both, marked not required,
   and `asf doctor` still exits 0.
8. `RefusedProductFileTests`: the existing pin is untouched and one case is added — the same single
   line also contains `asf config check --product sample`.
9. `UpgradeRowPointsAtConfigCheck`: the per-product row for a refused file contains both the
   `ConfigError` text and `asf config check --product <p>`.
