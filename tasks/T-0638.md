The spec's `## The design` §3 in full: `asf init` writes `approvals:\n  groom: auto` with the three
comment lines that say what it turns on, and `asf doctor`'s `approvals` row leads its detail with
`groom off: inbox is not groomed — …` when the gate is not `auto`. The code default stays off
(C10): flipping `groom_auto` would turn the policy pass and adjudicate sessions on under every
existing product, silently, on upgrade. A new yaml is a file a person is about to read, with a line
they can delete.

The row stays **ok** (C12) and the note says what is off rather than only that it is off (C13):
intake still types inbox cards either way (P16), so *"the inbox is not groomed"* alone would read
as *"your cards are not being typed"*, which is false.

Read **PD5 before touching `docs/products.example.yaml`** — uncommenting the gate there fails
`tests/test_approvals.py::CatalogueTest`, measured, and `env.validate_product_text` will not catch
it. Read **PD6 before running the approvals suite**: one existing assertion breaks and the fix is
its fixture. **PD13** is the one place this plan writes the clause differently from the spec, with
its reason. **PD9** is why the comment block parses, measured on the text that will be written.
