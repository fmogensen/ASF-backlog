## Description
stories: S-36553

after: Task 3

The spec's §5 (D5): before the ladder's arms, a run whose `error_subtype` is in `RESUMABLE` and
whose row shows no resume yet is handed back to `runtime.continue_run` once, its row marked
`resumed: 1`, with **no `ended` written** — it continues and is judged on its next end like any
other run. Everything else falls through to Task 3's arm, which is the behaviour without this
Story: a second cut-off, a `continue_run` that returns None, a non-resumable subtype, a row with no
runtime session id, a spawn that raises `AuthEnvError`.

Read **PD5** (health has no runtime; `runtime_fn` is injected and the tick is the only caller wired),
**PD6** (what the Job is, field by field, and that the log is the row's own), **PD7** (the skip
guard, without which the hold fires on top of a live resume) and **PD14** (`RESUMABLE` is shipped
as the spec writes it and not tuned here) before starting.

**Files**

- `asf/workers/health.py` — `RESUMABLE`, `resume_cut_off(product, job, s, ev, runtime, now)`,
  `health`'s new `runtime_fn=None` keyword (`:630`), the call before the ladder's arms
  (`:723`-ish, after the publish/retry handling and before `update_session` writes `ended`), and
  PD7's skip guard in `steps` (`:665`).
- `asf/tick/step_health.py` — `health_mod.health(..., runtime_fn=_runtime)` at `:175`.
- `tests/test_continuation.py` — the resume, and each of the five fall-throughs.

**Steps**

1. `RESUMABLE = ('max turns',)` with the spec's `#:` comment byte for byte — *"The runtime's own
   errors that mean 'this session ran out of room', not 'this work failed'."* Members exactly as
   the spec states them (PD14). The tuple holds the **factory's** words (`ERROR_SUBTYPES`' values),
   never the runtime's raw subtypes, so `error_subtype` is the only reader of the raw field.
2. `health` gains `runtime_fn=None` as its last keyword, documented in the docstring as PD5 frames
   it: a callable returning a runtime, called only at the moment a resume is attempted; None means
   no resume is attempted at all, which is the behaviour without this Story. A resume is attempted
   only when `fix` and `runtime_fn` are both truthy.
3. `resume_cut_off(product, job, s, ev, runtime, now)` → `(True, word)` when the run was handed
   back, else `(False, '')`. It refuses, in this order and with a comment on each: a run already
   carrying `resumed`; an `error_subtype(ev.result)` that is falsy or not in `RESUMABLE`; a row
   with no `worktree` or no `branch`; an empty `runtime_mod.runtime_session(s.get('log'))`
   (nothing to resume — PD6). Then it builds the Job exactly as PD6 specifies, writes
   `<brief>.resume.md` with `lifecycle.died_text(word)` as its body, calls
   `runtime.continue_run(job)`, and on None returns `(False, '')`. `runtime_mod.AuthEnvError` is
   caught and returns `(False, '')` with one printed line, as `stall.correct_once` does
   (`asf/workers/stall.py:309-312`). On a Result: `pool_mod.update_session(product, job,
   pid=result.pid, resumed=1)` and nothing else — **no `ended`, no `end_reason`, no `rc`**.
4. The call site: inside `steps`, after the publish and the `push_retry` handling and **before**
   the `pool_mod.update_session(..., ended=now, ...)` at `:730-732`. On `(True, word)`:
   `found.append((job, 'resumed', word))` (Records) and `return` — the run is live again and this
   pass writes no transition for it. On `(False, …)`: fall straight through to the code that exists
   today, which is the whole of the fall-through requirement.
5. PD7's guard, beside the `if s.get('ended'):` branch (`:665`): a run that carries `resumed` and
   whose `pid` is alive returns from `steps` before `judge` is called, with a comment naming the
   window it covers — the spawn has returned, the child has not yet written its `init` line, and
   `read_result` still reads the cut-off result. No `found` row: nothing happened this pass.
