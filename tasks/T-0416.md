§2.1's fourth row and §2.2's check 3. `doctor.ROWS` exists (Task 2); this Task writes the 34
sections and then makes the check require them, so a new doctor row is red in CI until it has a
documented fix (D3).

**Files**

- `docs/troubleshooting.md` — 34 `###` sections over the moved page
- `asf/docs.py` — check 3
- `tests/test_docs.py` — `CoverageTests`'s doctor case

**Steps**

1. `docs/troubleshooting.md` gains a `### <name>` heading for each of `doctor.row_names()`'s 34
   names, each with what the red row means — the second column of `ROWS` is the one-line meaning,
   and the page says it in full — and the command that fixes it. The page has 7 `###` headings
   today, so 27 are new (PD17).
2. `cli:*` is one heading for the family, matching the name `ROWS` carries, and it says which
   probes fan out under it.
3. The moved page's existing content — the `NEEDS OPERATOR` lines and the common stalls — stays,
   under the row sections it belongs to or after them. Nothing the guide documented is dropped.
4. `asf/docs.py` check 3: every `doctor.row_names()` name has a `### <name>` heading in
   `docs/troubleshooting.md`. One complaint per missing name.
5. `CoverageTests` gains its doctor case: every `doctor.row_names()` name has a `###` heading in
   `docs/troubleshooting.md`, and the failure names what is missing.
6. `asf docs check` clean before the commit. With this Task all five checks are on and the tree
   satisfies all five — which is the state Task 10's CI step and the tag gate both assume.
