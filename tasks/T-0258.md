## Description
stories: S-19906

after: none

§2.9: `merge` appends to `## Source` as well as `## History`, and nothing in the present appender is
specific to History but the string `'## History'` (`asf/record/ingest.py:289-300` — `parse_sections`,
`_section_lines` + `section_content`, `render_sections`). The heading becomes a parameter and the old
name becomes the one-line wrapper. Task 6 is the first caller of the general form; every present
caller keeps the wrapper and must come out byte-identical.

**Files**

- `asf/record/ingest.py` — `append_section_lines(body, heading, new_lines)`; `append_history_lines`
  as its one-line wrapper
- `tests/test_ingest.py` — two cases for the parameter, beside the History cases already there

**Steps**

1. `append_section_lines(body, heading, new_lines)`, the body of today's `append_history_lines` with
   `'## History'` replaced by `heading` and the docstring §2.9 gives: a body with no such section
   comes back unchanged, which is what `append_history_lines` has always done for a body with no
   `## History`.
2. `def append_history_lines(body, new_lines): return append_section_lines(body, '## History', new_lines)`
   — the name every present caller keeps using (`asf/groom/groom.py:167`,
   `asf/record/ingest.py`'s own callers), so no other file changes in this Task.
3. Two cases in `tests/test_ingest.py`: `append_section_lines` appends inside a named non-last
   section (`## Source` with `## History` after it) and leaves every other section byte-identical;
   and it returns the body unchanged when the heading is absent (PD10's shape, pinned here and
   again in Task 6 where it matters).
4. One case that the wrapper did not change: an existing History case re-asserted through
   `append_history_lines`, so the Task's own test says the round trip is the same one.
