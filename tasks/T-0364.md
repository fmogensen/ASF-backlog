## Description
stories: S-32256
writes: asf/security/ports.py, asf/tick/step_daily.py, tests/test_security_ports.py
after: Task 1

§2.9: four functions and one new part of the daily step. The probe runs on a runner because a
connect from the tick host proves nothing about what the internet reaches (D12); an address is a
repository secret and never a line, an artifact or a commit (D11).

**Files**

- `asf/security/ports.py` — `TARGETS_ENV`, `targets`, `probe`, `dispatch`, `latest`, `violations`
- `asf/tick/step_daily.py` — one entry in `parts`
- `tests/test_security_ports.py` — `TargetTests`, `ProbeTests`, `DispatchTests`, `ViolationTests`

**Steps**

1. `targets(product)` → `[(box, address)]`: the union of the `ci.pool` boxes (`asf/ci_pool.py:57` —
   the entries carry no address of any kind, P16) and `security_ports()['boxes']`, each resolved
   against `$ASF_PORT_TARGETS`, a JSON `{box: address}` the job hands the probe. A box with no
   address comes back with an empty one — unprobed, never discovered, never guessed, never ranged
   (§1.2). `TARGETS_ENV` names the variable once.
2. `probe(targets, ports, connect=None, timeout=2.0)` → `{'ts', 'from', 'results': [{'box', 'port',
   'open'}]}`: one TCP connect per (box, port), `connect` injected in the tests, the address used
   and never returned. `from` is the runner's label, not an address. A box with no address yields
   no result rows, which is what makes it *unprobed* downstream.
3. `dispatch(product, run=None)`: `gh workflow run <security_ports()['workflow']>` on the trunk,
   with `security.gh_env` (PD7); a product with no `ports` block prints `no boxes configured` and
   returns 0 (P21 — this product configures none, so the part must be a clean no-op here).
4. `latest(product, run=None)`: `gh run list --workflow <w> --status success --limit 1 --json
   databaseId,createdAt`, then `gh run download <id> -n <artifact> -D <tmp>`, the JSON read out of
   the temp dir and the dir removed; `(None, why)` when there is no successful run or the artifact
   is unreadable.
5. `violations(product, now=None)`: §2.9's three line shapes byte for byte — `sev=S1
   sig=port-<box>-<port>` per open port, `sev=S1 sig=unprobed-<box>` per configured box the newest
   probe did not cover (D13: the line says `unprobed`, not `open`, and carries S1 because nobody
   knows either way), and one `sev=S2 sig=probe-stale` when the newest probe is older than
   `max_age_h`, absent, or unreadable, naming the reason. Nothing is closed and nothing is
   reconfigured (§1.2).
6. `step_daily.parts` gains `('security-ports', lambda: ports.dispatch(product))` after `stale`
   (`asf/tick/step_daily.py:32`), imported inside `parts` the way its three siblings are, so the
   tick log reads `daily: security-ports ok — dispatched <workflow>`. A failing dispatch does not
   stop the rollup or the scorecard (P18), and next tick's R-0010 turns a probe that stopped
   running into a violation by itself.
7. `TargetTests`/`ProbeTests` per §3's T7: `targets` unions the two sources, resolves each against
   `$ASF_PORT_TARGETS` and returns a configured box with no address as unprobed; `probe` against a
   **loopback listener the test opened itself** reports that port open and an unused one closed,
   honours the timeout, and its serialized result is searched for each fixture address and contains
   none.
8. `ViolationTests`/`DispatchTests`: an open port is one `sev=S1 sig=port-<box>-<port>` line, an
   unprobed box one `sev=S1 sig=unprobed-<box>`, a 40 h-old probe one `probe-stale` line, a clean
   fresh probe none; `dispatch` calls `gh workflow run` with the configured workflow through a fake
   runner and returns 0 with `no boxes configured` for a product with no block; `latest` reads the
   newest successful run's artifact through two fake `gh` calls and returns `(None, why)` when
   there is no successful run.
