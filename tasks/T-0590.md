The spec's §2: the landings read once for the pass, each tree's branch resolved before the
evidence is gathered, and that branch's landing passed into the verdict. The orphan's second
`gather` goes away because the branch it existed to find is now resolved up front. With it, the
squash shape of the landing — a tip the lane re-committed onto the trunk, so this HEAD is no
ancestor of it and `in_trunk` is `False` — is reaped on the ledger's word.

**What changes for the machine when this lands.** One further class of worktree is reaped: clean,
ended, with commits the trunk does not hold, whose *branch* the ledger says landed under another
run. And one `ls-remote`-shaped `gather` per orphan directory disappears from every pass. Every
other tree is listed exactly as before, with the reason that keeps it. `gone` stays the narrow
`landed(s) or detail == 'empty'` (C7); `prune_branches` is not touched (PD5); nothing is written to
the registry (C6); `asf/workers/worktrees.py` is not touched (C9).

**Files**

- `asf/workers/health.py` — inside `health`: `landings = lifecycle.branch_landings(registry)`
  beside `owners` and `heads`; the loop body's `branch`/`gather`/`reap_verdict` lines. The module
  docstring's "three rules" list becomes four. `remove_worktree`, `prune_branches`,
  `_lane_branches`, `_head_branch`, `gone`, `release_id_range` and the finding tuple are untouched.
- `tests/test_workers.py` — `LandedByAnotherRunReapTests(Home)` added after `TestHealth`. No

1. `landings = lifecycle.branch_landings(registry)` next to `owners = lifecycle.by_worktree(

2. The loop body's four lines become:

   ```python
           s = owners.get(lifecycle.path_key(path)) or sessions.get(name)

           branch = (s or {}).get('branch') or _head_branch(path) or ''
           ev = lifecycle.gather(product, s or {'branch': branch}, alive=alive, worktree=path,
   ```
