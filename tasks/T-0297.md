## Description
stories: S-30452
writes: asf/groom/shape.py, asf/groom/inbox.py, asf/groom/groom.py, tests/test_groom_shape.py
after: Task 1, Task 4

§2.3. The memory file held a better rule than the code has: parent by what the card changes, not
by how its title happens to read. The routes decide first, the shared title words stay as the
floor under them — a card with no `writes:`, which is most inbox cards, has nothing to route on
(§1.4). `after:` names Task 1 for `conventions.epic_routes` and Task 4 for the two groom modules
they share (PD11).

**Files**

- `asf/groom/shape.py` — `infer_parent_epic(canonical, tokens, writes=(), routes=())` and
  `derive`'s call
- `asf/groom/inbox.py` — `process_inbox`'s `routes=()` parameter, passed to `derive`
- `asf/groom/groom.py` — the one `process_inbox` call, passing the product's routes
- `tests/test_groom_shape.py` — `EpicRouteTests`

**Steps**

1. `asf/groom/shape.py`: `infer_parent_epic(canonical, tokens, writes=(), routes=())`. Before the
   word count, walk `routes` in order; a route is a mapping with `globs` and `epic`. The first
   route any glob of which overlaps any glob of `writes` wins — `footprint.globs_overlap`
   (`asf/feeder/footprint.py:26`) in both directions, the module's own import already at the top
   of the file, never a second matching rule — provided its `epic` is in `canonical`, is an
   `epic`, and `is_open`. A route naming an absent or closed Epic is skipped and the walk goes
   on: the groom is not where a config typo is discovered, and the fallback still answers (§2.3).
2. With no route matching, or an empty `writes`, return exactly what the function returns today.
   The two new parameters default to empty, so `infer_parent_epic(canonical, tokens)` is
   unchanged for every existing caller and for `tests/test_groom.py:91`'s case.
3. The docstring gains the ranking in one sentence and a route example written as
   `{globs: [<glob>, …], epic: <epic id>}` — a placeholder, never a real id: `\bE-[0-9]{4}\b` is
   forbidden anywhere under `asf/` (PD14). The worked example with ids is Task 1's, in
   `docs/products.example.yaml`.
4. `derive(card, canonical, default_bug_parent=None, routes=())`: at `:124` pass
   `infer_parent_epic(canonical, tokenize(card.title), writes=_route_globs(headers.get('writes')),
   routes=routes)`, where `_route_globs` splits the header on whitespace and commas and drops
   empties — `writes` is already read off the card at `:60`, so nothing new is parsed.
5. `asf/groom/inbox.py`: `process_inbox(root, canonical, date, default_bug_parent=None,
   intake_dir=None, asked=None, routes=())`, following `default_bug_parent`'s shape exactly, and
   pass it through at `:184`. Its docstring gains one sentence: the routes are the product's
   `conventions.epic_routes`, and with none the parenting is what it was.
6. `asf/groom/groom.py`: beside `default_bug_parent` at `:994-996`, read
   `routes = product.conventions.get('epic_routes') or () if product is not None else ()` — the
   mapping access the line above already uses — and pass `routes=routes` at `:999`. Nothing else
   in `cmd_groom` changes.
7. `tests/test_groom_shape.py` gains `EpicRouteTests`, §3's T3 case for case: with two open Epics
   and a route matching `docs/**`, a card whose `writes:` is `docs/guide/x.md` parents to the
   routed Epic even when every word of its title belongs to the other; a card with no `writes:`
   parents by shared words; a route naming a closed Epic and a route naming an absent one are
   both skipped and the words answer; `infer_parent_epic` called with no routes is unchanged.
   Add the end-to-end case too: `process_inbox` with `routes=` set files the card under the
   routed Epic, which is what proves the wiring rather than the function.
8. Run `tests/test_groom.py` whole — the fence names the module, and `:91`'s existing case is the
   guard that the fallback did not move.
