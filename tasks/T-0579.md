## Description
stories: S-36052

after: Task 2

The spec's §2. Six reads of `f['paths']`-as-a-flag move onto `filtered(f)`, two lines gain a
clause, and dev and prod start saying `relevant` when — and only when — they carry a filter. After
this Task the count and the words can no longer disagree about whether an environment is filtered
(C5).

**What changes for an operator when this lands.** A filtered environment at zero says *why* it is
at zero: `has every main commit touching apps/site/** outside its excludes`. A dev or prod that
carries a filter says `main is 3 relevant commits ahead of prod \`abc123def\` (9 in all)` instead
of a bare gap it then refuses to act on. The config summary says which filter produced a count:
`site manual (site-deploy.yml, apps/site/** less 7 excludes)`. An environment with **neither**
`paths:` nor `exclude:` — which is every dev and prod on the machine today (C2) — prints exactly
what it printed before, word for word.

**Files**

- `asf/harvest/deploy.py` — `_scope(f)`, new; `_lag`'s target branch (`:703-704`) and its dev/prod
  branch (`:700-702`); `_manual` (`:717`); `decide`'s zero branch (`:741-744`); the findings line
  (`:276-277`).
- `asf/views/prod.py` — `:226` becomes `rel = 'relevant ' if deploy.filtered(f) else ''`. `:239`
  keeps passing `f['paths']` as the ON PROD table's `within` (C4, PD8) — deliberately, and the
  reason goes in a comment there so the next reader does not "finish the job".
- `tests/test_deploy.py` — `RelevanceLines` added. `RelevanceFilter` and `RelevanceAgainstGit` are
  untouched.

**Steps**

1. `_scope(f)` exactly as the spec's design has it, with PD2's `.get`: the paths clause
   (`touching <', '.join>`) when there are paths, `'outside its excludes'` when there are excludes,
   joined by a space, either half absent when its list is empty. So an exclude-only environment
   says `has every main commit outside its excludes` and a paths-only one (impossible after Task 1
   unless `exclude_defaults: false` with an empty list) says today's sentence unchanged.
2. `_lag`, target branch: `rel = 'relevant ' if filtered(f) else ''` and the `N in all` clause on
   the same predicate — `f"{f['behind']} in all" if filtered(f) and f['behind'] is not None else
   None`. Nothing else in that branch moves.
3. `_lag`, dev/prod branch (C6): with a filter,
   `f"{trunk} is {_n(f['relevant'], 'relevant ')} ahead of {env} {_s(f['deployed'])}"` plus
   `f" ({f['behind']} in all)"` when `behind` reads, then the existing `({age})` clause — two
   parentheses, as the spec's example has them. With **no** filter the expression must be
   byte-identical to today's `f"{trunk} is {_n(f['behind'])} ahead of {env} {_s(f['deployed'])}"`
   plus the age clause; write it as an explicit `if filtered(f)` split rather than as a clever
   single f-string, and pin the no-filter form with an `assertEqual` on the whole line, not an
   `assertIn` — C2's promise is byte-for-byte and only an equality test measures it.
4. `_manual` (`:717`): `rel = 'relevant ' if filtered(f) else ''`. One line.
5. `decide`'s zero branch (`:741-744`): `if filtered(f) and f['relevant'] == 0:` and the line
   becomes `f"{head} {env} {_s(f['deployed'])} has every {trunk} commit {_scope(f)}"` plus today's
   `({f['behind']} other commits since; mode {f.get('mode')})` tail. The existing
   `assertIn('has every main commit touching apps/site/**')` at `tests/test_deploy.py:444` must
   still hold — it does, as a prefix of the new sentence.
6. The findings line (`:276-277`), C8 with PD6's plural: `scope` keeps
   `', '.join(paths(product, t)) or 'every commit'` and gains
   `f" less {n} exclude{'' if n == 1 else 's'}"` when `n = len(excludes(product, t))` is non-zero.
   The one shipped assertion at `tests/test_deploy.py:554-556` moves from
   `'site manual (site-deploy.yml, apps/site/**)'` to
   `'site manual (site-deploy.yml, apps/site/** less 7 excludes)'` — the price C8 name
