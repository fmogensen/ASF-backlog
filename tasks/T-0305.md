§2.5 and §2.6 — the first two live hooks, each with its card, its shim and its `decide` in one
commit (PD2). Also the `rules` conventions block, whose only consumer is R-0002 (PD13).

**Files**

- `rules/R-0001.md` — the card of §2.1, byte for byte for R-0001: `id: R-0001`, `type: rule`,
  `title: a stage names its files`, `check: tools/checks/r0001.sh`, `hook: [PreToolUse]`, and
  §2.1's body ("A blanket stage in a worktree commits whatever else is in the tree …").
- `rules/r0001.sh` — the shim (D4, PD8), `chmod +x`:
  ```bash
  #!/bin/bash
  # written by hand, shipped with asf — the hook half of R-0001 (F-0061)
  exec "${ASF_PYTHON:-python3}" -m asf.rules.hooks.r0001
  ```
- `rules/R-0002.md`, `rules/r0002.sh` — the same shape: `title: the stash stack is shared — never
  touch it`, `hook: [PreToolUse]`, and a body naming the common `.git` directory and the WIP-commit
  way out.
- `asf/rules/hooks/r0001.py` — `decide(call, ctx)` and a `hookcall.run('R-0001', decide)` under
  `__main__`. Returns None unless `call['tool_name'] == 'Bash'` (PD6) and unless
  `ctx.in_worktree or ctx.in_repo` — the rule binds a worktree or a repo checkout and not a
  `.git`-less fixture directory. Over each simple command of the compound
  (`approvals._simple_commands`, which strips heredocs and splits on `&&`, `;`, `|`, so `main` or
  `git add -A` inside a commit message never counts) it refuses: `git add` with `-A`, `--all`,
  `--no-ignore-removal`, or a path argument of `.`, `:/`, `*` or the repo toplevel; `git add -u`
  with no path; `git commit` with `-a`, `--all`, or a bundled short flag containing `a`; and
  `git stage` in the same shapes. Allows `git add <path>…`, `git add -p`, `git add -u <path>`. A
  `ValueError` out of `_simple_commands` (unbalanced quotes) is left to the exception path of
  `hookcall.run`, which refuses and says it was the hook — the safe side, and the same side
  `_pushes_trunk` picks.
- `asf/rules/hooks/r0002.py` — refuses `git stash` bare and
  `git stash push|save|pop|apply|drop|clear|branch|create|store` when `ctx.in_worktree`; allows the
  read-only `list` and `show`. `rules.r0002.allow_tagged` true in the product's conventions lets
  `git stash push -u -m <tag>` through (and only that form: `-m` with a tag, `push`, no `pop`).
  The refusal is §2.6's text, with the WIP-commit and the `apply <sha>` recovery as the two ways
  out. `conventions.map_of('rules')` is how the key is read, never `getattr` (PD13).
- `asf/conventions.py` — the `rules` field (`dict`, defaulting to a copy of a documented
  `DEFAULT_RULES`), `'rules'` in `MAP_CONVENTIONS` so a misshapen block is a red `conventions`
  doctor row rather than a silent default, and the field's `#:` comment naming
  `rules.r0002.allow_tagged` as the only key any rule in F-0061 reads.
- `docs/products.example.yaml` — the `rules:` block in the `conventions:` section, with
  `r0002: {allow_tagged: false}` and one comment line on what it buys.
- `tests/test_conventions.py` — `rules` read from a mapping, defaulted when absent, and read as
  the default (with a shape finding) when misshapen.
- `tests/test_rule_hooks.py` — `StageAndStashTests`, table-driven over each rule's real `decide`,
  each row a real call JSON.
