**Steps**

1. Create `asf/record/cards.v2.schema.json` as §2.1 outlines it: `$schema`, `$id`, `type: object`,
   `additionalProperties: false`, `required: [schema_version, id, type, title, state]`, and one
   property per key with its one type. Start from §2.1's fenced outline verbatim, then add one
   property per remaining key — §1.1's 63 on the live root plus the seventeen `kernel_*` keys of
   `ports.KERNEL_KEYS` (`asf/kernel/ports.py:80`), which the measured records do not carry (P17).
   Two are settled by the measurement: `removed` is `{"type": ["boolean", "string"]}` and
   `blockedBy` is an array only. `satisfied` is declared even though no card carries it — the
   schema is closed, so without it the first card Task 7 resolves would fail its own write gate.
2. Keep the two state fields apart, as §2.1 says: `state` is the record's four words
   (`asf/evidence/closing.py:53`), `kernel_state` the kernel's seven lowercase ones
   (`ports.STATE`). This file is the first place both vocabularies are written down together;
   merging them is a state-machine change and out of scope.
3. The two ASF keywords are annotations a JSON Schema reader ignores: `"owner": "machine"` (what
   Task 2's `card.split_machine` reads) and `"ref": "card"` (the fields Task 6 checks). Put
   `"owner": "machine"` on exactly the keys the old `# ---- machine ----` marker held — and
   settle `reshape_applied` and `reshape_applied_at` to one owner each, which is the measured bug
   D-0004 names.
4. Create `asf/record/validate.py`, stdlib only, around 150 lines: `errors(instance, schema)`
   returning `[(pointer, message)]` in document order, pointers in JSON Pointer form
   (`/acceptance/2/test`). Implement exactly the keywords D-0002 names — `type`, `enum`, `const`,
   `required`, `properties`, `additionalProperties`, `items`, `pattern`, `minLength`, `minimum`,
   `minItems`, `oneOf` for a nullable — and expose `UNSUPPORTED` as the list of keywords it does
   not implement. It must raise on no input, however malformed: catch nothing by guessing, return
   an error instead.
5. `pyproject.toml`: `[tool.setuptools.package-data]` (`:24`) gains `"asf.record" =
   ["*.schema.json"]`, so the file ships. Read it with the
   `os.path.dirname(os.path.abspath(__file__))` idiom (`asf/briefs/build.py:43`), never a cwd path.
6. Create `tests/test_card_schema.py` covering S-133155's twenty lines. The one that matters most
   is the closure: assert that every keyword the schema file uses is one `validate.py` implements,
   by walking the schema and comparing against `UNSUPPORTED` — and assert the test itself fails
   when a keyword is added to the schema that the validator lacks, so the schema can never promise
   more than it checks. Cover a valid card of each of the seven types, a missing required
   property, a bad `id` pattern, a `state` outside the enum, a non-string `writes` entry, an
   `acceptance` entry with no `text` and one with an undeclared property, an empty `gate` string,
   a `risk` outside the two words, a negative `rank` and a null one, document order, two faults
   giving two errors, and the schema being readable from an installed package.
