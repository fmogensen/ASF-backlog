## Description
stories: S-79607
writes: asf/rehearsal.py, tests/test_rehearsal_tags.py
after: Task 2

The spec's design §2, the `tags` row: `version.of_commit`, `version.label`, `version.plan`,
`version.tag_entries`, `version.health` and `install.newest_tag` over the laid-down repo, each
answer asserted against `manifest['refs']` so an answer carrying a **tag object's** sha rather than
its commit's is a failure named with both shas; then `version.cut` and `version.prerelease` into a
scratch clone, and `version.health` green after.

**PD7** binds it: `install.newest_tag`'s integer-tuple-and-stray rule is already proven at
`tests/test_install.py:2218`, and that test cannot see P8's defect because it reads only the name,
never the sha it came with. The new class is `NewestTagPairsTheCommitNotTheTagObject`.

**Files**

- `asf/rehearsal.py` — the `tags` act, appended to `ACTS` after `record`. The four correct readers
  are **not** changed (Out): `asf/version.py:455` and `asf/metrics/metrics.py:1499` ask for
  `refs/tags/<t>^{commit}`, `asf/version.py:335` and `:419` read `%(contents)` and
  `%(creatordate:unix)`, and `asf/workers/spawn.py:551` asks for both `refs/tags/<t>` and
  `refs/tags/<t>^{}`. `version.label(version, sha)` (`asf/version.py:91`) is a pure formatter, not
  a repo reader, so the act exercises it on values the repo answered rather than "over" the repo.
- `tests/test_rehearsal_tags.py` — **new**, with `NewestTagPairsTheCommitNotTheTagObject`: a real
  `git ls-remote --tags` listing of an annotated tag carries two lines, `<tag-object-sha>
  refs/tags/v0.1.0` and `<commit-sha> refs/tags/v0.1.0^{}`, and `cli.RELEASE_TAG.fullmatch` drops
  the second — so the surviving name is paired with the tag object's sha (`asf/install.py:45-63`,
  the `names.append(name)` at `:60` keeping no sha at all). A new class, subclassing
  `unittest.TestCase` and no existing harness.

**Steps**

1. Lay the snapshot's repo down and prove every `manifest['refs']` entry is there as the manifest
   says — annotated entries created with `git tag -a -m <its annotation>`, plus one pre-release tag
   and a `CHANGELOG.md` with their entries (S-79607's first line).
2. Each reader, each answer against the manifest. A tag-object sha where a commit sha belongs is a
   failure naming both shas.
3. `version.cut` and `version.prerelease` into a scratch clone; `version.health` green after.
4. Do **not** change `install.newest_tag`. Out, by C1: its Bug card comes from the red run.
