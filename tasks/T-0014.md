## Description

**Files**: `asf/groom/policy.py`, `asf/groom/groom.py`, `asf/tick/step_daily.py`,
`tests/test_groom_policy.py`, `tests/test_tick_steps.py`.

**Steps**
1. `suppress(sections, index, inflight, product)` per §2.3. A line whose item a live session holds,
   or for which `feeder.rows.candidates(index, product, inflight)` emits a launching row, becomes
   `- [x] <id> <title> — <why> → answer: (spoken for: <ROW KIND>)`. It runs before the policy pass.
   `cmd_groom` reads `inflight` via `lifecycle.inflight(pool.sessions_path(product))` and the index
   via `index_reader.load(root)`.
2. The answers file: `cmd_groom` applies `args.answers_file` (when it exists) after the previous
   groom file and before the policy pass, with `adjudicator_job=f'groom-{date of the file}'`. It
   then renames the file to `<date>.answers.done`.
3. Events: when `args.event` is set, one `groom_answer` per applied answer (`item, section, field,
   value, by`: `rule:<policy>` / `adjudicator:<job>`), and one `groom_open` (`count, barred`) per
   run. Their shapes are §4's.
4. `step_daily.parts(product, root, event=None)` passes `event` and the state dir's newest
   `groom/<date>.answers` into `cmd_groom`; `run` passes `ctx.event`.
5. The printed line gains `spoken for N, open N` (§4, PD10).
6. Tests: `SuppressionTests` (T6: a Feature with no Stories and a `CARD → SPEC` row becomes a `[x]`
   line, gets no policy answer, and is not in `open_questions`). `AnswersFileTests` (T10). A
   `DailyStepTests` case checks that `parts` hands the event sink to groom.
