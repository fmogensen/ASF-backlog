**Steps**

1. `normalise(text, tmp, day, ids)` — §2.4's six replacements, in an order that does not undo
   itself (the temp root before any sha inside a path, the stamp's `HH:MM` before the general ISO
   timestamp): a git sha → `<SHA>`, the temp root → `<TMP>`, today → `<DAY>` and the following day
   → `<DAY+1>`, an ISO timestamp → `<TS>`, the stamp line's `HH:MM` → `<HH:MM>`, the minted Task
   id → `<TASK>`. **Replace, never strip** — a stripped line cannot regress, and the goldens must
   still fail if a table loses its stamp line or grows a column.
2. One `_golden(name, text)` helper: under `ASF_UPDATE_GOLDEN=1` write the normalised text and
   return; otherwise read and `assertEqual`. Regenerating must produce a file identical to the one
   on disk — that is §3.2's whole point, and an un-normalised sha is what makes it fail.
3. `test_board_and_roadmap_match_the_goldens`: run `asf backlog --product sample` and
   `asf roadmap --product sample` through `cls.asf` (`asf/cli.py:146,149`), normalise each, and
   compare against `board.md` and `roadmap.md` (S-18055).
4. `test_scorecard_matches_the_golden`: read `<backlog>/metrics/daily/<day>.md`, which the tick's
   `record` step wrote — `sample/` declares `steps: {daily: off}`, so the `daily` step is not the
   source and must not be invoked (S-18056).
5. The following day's rollup, in `setUpClass` after tick 9, exactly as §2.5 specifies:
   `python3 -m asf.metrics.metrics --root <record> --product sample rollup <day+1>`. Both
   `--root` and `--product` are real arguments of that parser (`asf/metrics/metrics.py:1465-1466`),
   and the cap that makes the second run necessary is `_cut_trunk_release`'s
   `if prev and prev[-1][:10] >= day: return None` (`:1148-1150`) — one release note per day
   (PD12).
6. `test_release_notes_and_their_tags`: both `releases/<day>-<sha7>.md` and
   `releases/<day+1>-<sha7>.md` exist, both match their goldens normalised, and **both tags are
   present in the scenario's bare origin** — a release note whose tag was never pushed is a
   release that did not happen (S-18057).
7. Generate the five fixtures with `ASF_UPDATE_GOLDEN=1`, then read each one before committing:
   a golden holding a raw sha, a timestamp, a temp path or the minted id is a normaliser that is
   not finished (§2.4's last paragraph). Then run §3.2 and require `git diff --exit-code` to be
   clean (S-18054).
