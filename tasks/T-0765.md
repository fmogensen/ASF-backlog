The spec's `## The design` §1, §2, §3 and §5 in full, and nothing else. After this lands, the
Capacity row's queue clause names both clocks and the threshold for the entry the head guard
governs —

```
ci queue 1, head T-0500 waits 40 min (15 min at the head; admitted at 20) — heavy 1 free, needs 4 (Task unranked, 1st in line)
```

— and prints not one extra byte for an entry it does not:

```
ci queue 2, head batch waits 1 min — at the ci ceiling (4 runs in flight; batch starts below 4) (other, 1st in line)
```

Both of those are this session's measured output from the candidate, not a derivation. **No
admission changes.** If the diff reaches `decide`, `head_of`, `head_wait_s` or `_mark_head`, it has
left the card.

Three things are load-bearing. The whole clause is built **inside `_waits`** (C7), because `_waits`
is the one thing standing between the live renderer and the snapshot renderer, and this card exists
because two clocks diverged unnoticed — the callers decide *whether*, `_waits` decides *how it
reads*. The gate is **necessarily per call site**: the live path has a real `skip` to compare
against, the snapshot has only the `at_ceiling` flag the hold stored (C3). And the at-head age is
rendered `int(s // 60)` — the guard's own arithmetic (C4) — so the number an operator watches climb
is the number the admission line will print.

Read **PD1** before transcribing the second acceptance test, **PD4** for the six rewrites, and
**PD5** before changing a byte of the parenthesis.
