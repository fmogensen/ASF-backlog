## Description
stories: S-29557
writes: asf/credentials.py, asf/cli.py, tests/test_credentials.py
after: Task 3, Task 4

§2.8, and acceptance 1's mechanism. The two files this Feature cannot have a session write get an
installer instead, so the operator's part is one command and two commits rather than two
hand-written files. It comes last because its own test asserts that `credentials` is a part name
in `step_daily.parts` — which is Task 4's line — and because the card it writes carries
`owner: operator`, which is only settable after Task 3.

**Files**

- `asf/credentials.py`:
  - `CARD_BODY` and `SCRIPT_BODY` — the card of §2.8 and the six-line `rules/credentials.sh`,
    byte for byte as the spec writes them, with `R-nnnn` in the script's comment substituted for
    the minted id. The card's `title:` is `Every signed-in tool is valid for three more days`,
    `scope: factory`, `owner: operator`, `check: rules/credentials.sh`.
  - `install(record_root, repo_root, print_only=False, job=None)` → an rc.
    - `job` defaults to `os.environ.get('ASF_JOB')`. When it is set: print
      `NEEDS OPERATOR: asf credentials install writes the amendable set — run it yourself: asf credentials install --product <p>`
      and return 2. **Nothing is written** — the refusal is the first statement of the function, so
      there is no path on which a session creates either file (D9, PD15).
    - `print_only`: print both files to stdout and return 0, writing nothing.
    - Otherwise, in order: mint the card with `asf.record.new.cmd_new` for type `rule`; set
      `check: rules/credentials.sh` and `owner: operator` with `asf.record.setfield.cmd_set`;
      write `rules/credentials.sh` into `rules.core_rules_dir()` at mode `0o755` when it is not
      already there, creating the directory with `os.makedirs(..., exist_ok=True)` (PD14); then
      re-index with the record's own `do_index`. All four in process — never by shelling to `asf`
      on `PATH`, because the test runs with no `asf` binary installed and because the id must come
      from the record's own minter and never from this code.
    - Print the two lines §2.8 gives, each naming a path written and the commit the operator still
      owes:
      `wrote rules/R-nnnn.md (record) — commit it: git -C <record> commit -s rules/` and
      `wrote rules/credentials.sh (asf) — commit it: git -C <asf> commit -s rules/credentials.sh`.
- `asf/cli.py` — `credentials_command`'s `choices` widen to `['check', 'install']`, a `--print`
  flag, and the dispatch branch for `install` (PD12: the choice and its branch land together).
- `tests/test_credentials.py` — `InstallTest`, §3's four cases:
  - `test_install_writes_the_card_and_the_script`: a record laid down by `init.lay_down` in a
    tmpdir and an empty core `rules/` dir with `$ASF_CORE_RULES_DIR` pointed at it.
    `install(record, repo, job=None)` writes `rules/R-nnnn.md` with `check: rules/credentials.sh`
    and `owner: operator`, writes `rules/credentials.sh` mode `0o755`, and
    `rules.load_rules(record)` then returns that card.
  - `test_the_installed_card_runs_in_the_rules_row`: with the card installed and `asf` on `PATH`
    replaced by a stub that prints one `credential provider-c expires … — renew: …` line and exits
    1, `rules.run_check(record, card)` returns that one line as a violation and no check failure.
  - `test_install_refuses_inside_a_session`: `job='spec-f-0042'` writes nothing, returns 2, and
    its output carries `NEEDS OPERATOR:`.
  - `test_the_daily_step_names_credentials`: `credentials` is a part name in
    `step_daily.parts(product, root)`.
  - One the plan adds: `test_print_writes_nothing`, because `--print` is the only other path that
    must leave the amendable set alone.

**Steps**

1. `CARD_BODY`, `SCRIPT_BODY`, and `install`'s refusal branch first — the test that a session
   writes nothing goes green before any writing code exists.
2. `--print`.
3. The minting path, in process, against a `lay_down` record in a tmpdir.
