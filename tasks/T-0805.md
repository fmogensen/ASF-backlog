## Description
stories: S-59255
writes: asf/record/ingest.py, tests/test_no_test_no_done.py, tests/test_ingest.py
after: Task 1

The spec's §*The design* §4: `unproved_of` turns the refusal into the line's reason, the Story loop
says it out loud whatever state the Story is in, and `tick_proven` is not touched because a refused
claim never reaches it.

Read **PD7** (this Task's cases build `ev` by hand, so it does not wait on Task 3).

**Files**

- `asf/record/ingest.py`:
  - `unproved_of` (**:1358**) gains the spec's `refused` block, byte for byte: the Story's
    `ev['proves_refused']` entries become `{line: why}`, clamped to `1 <= n <= m` by the same
    bound the existing `pending` set uses, and are passed to `proves.unproved(..., refused=…)`.
    Its docstring gains the spec's sentence. The signature does **not** change — the refusal comes
    out of the `ev` the function already takes.
  - `refused_claim_line(entry)` added beside `unproved_line` (**:1370-1373**), exactly as the spec
    gives it: `claim refused, line <n> not proved — <why> — <task>[, PR #<n>] (<test>)`, with the
    `, PR #<n>` clause omitted where `pr` is null, matching `tick_proven`'s own `pr_clause`
    convention (**:1483**).
  - in the Story loop, **immediately before** the existing `open_lines` block (**:1073**), the
    spec's two lines: one `lines.append(refused_claim_line(entry))` per entry of
    `(ev.get('proves_refused') or {}).get(iid)`. **Unconditional** — outside the
    `closing._DONE` guard at **:1074** (spec D8, P8): that guard prints only where a done rule
    would have fired, which is never true at the moment a bad claim lands, because the Story is
    Active. A refusal routed through the guarded channel alone is a refusal nobody reads.
  - `ev_obj.unproved` (**:1077**) is left exactly as it is: it is set unconditionally already, and
    a line with a refused claim against it is unproved, so it appears there for free.
  - `tick_proven` (**:1452**) is **not touched**. It reads `(ev.get('proves') or {}).get(iid)`,
    which a refused claim never enters (spec P6, and Task 3's `add` is what keeps it out), so no
    bullet flips and no `proved line` History entry is written. A test says so rather than leaving
    it to be inferred.
- `tests/test_no_test_no_done.py` — `PartialClaimIsNotAProof(RecordCase)` added, driven through
  the record fixture that class already builds (a Story with two acceptance lines and a Task under
  it), with `ev` carrying `{'proves': {}, 'proves_refused': {sid: [{'line': 2, 'test': …, 'task':
  'T-0001', 'pr': 7, 'sha': …, 'source': 'pr', 'why': 'partial claim: "only"'}]}}` — built by hand,
  not through `evidence.discover` (**PD7**). Exactly the spec's six assertions:
  - after `ingest_into`, line 2's bullet is still `- [ ]` and `## History` holds no
    `proved line 2` entry — `proves.proved_lines(body)` does not contain `2`. **This is the
    defect, stated as an assertion**: it is the one case whose failure means the card's bug
    shipped under its own fix.
  - the Story's evidence carries the `claim refused, line 2 not proved — partial claim: "only" —
    T-0001, PR #7 (…)` line **while the Story is Active** (spec D8, P8) — the case that fails if
    the refusal is routed through the `unproved line` channel alone.
  - `unproved_of` gives line 2 the `why` `partial claim: "only"` and line 1 `no proof` (spec D9),
    and `ev_obj.unproved` is `(1, 2)`.
  - a Story whose **only** claim is refused does not close: the done rule does not fire, and the
    Feature above it does not either.
  - the same pass with the claim **counted** instead (no marker) ticks line 2, writes
    `proved line 2`, and emits no refusal line — so the two paths are proved to differ only in the
    marker.
  - `proves_refused` absent from `ev` altogether reads exactly as today, which is what keeps every
    other case of this module and of `tests/test_ingest.py` green.
- `tests/test_ingest.py` — run **whole** in the Gate because `unproved_of`, the Story
