## Description
stories: S-60908
writes: asf/tick/shadow.py, asf/tick/tick.py, tests/test_tick.py
after: Task 2

The spec's `## The design` §2's second half, and the last two cases of its A3 Acceptance block.
**PD2 is this Task's trap** — the new return value is falsy on success — and **PD3 its one open
choice, decided**. It adds no git call (PD4): `_stage` already reads all three stages, which is
P13.

**Files**

- `asf/tick/shadow.py` — `_resolve_by_ownership` (`:171-193`) gains the add/add branch and returns
  `list | None`; `push` (`:120-157`) reads it with an identity test (PD2), accumulates across
  rebase rounds, prints the one extra line when the list is non-empty, and takes PD3's optional
  `discarded` list
- `asf/tick/tick.py` — `commit_and_push` passes a `dropped = []` to `push` and raises one
  `NEEDS OPERATOR` naming the ids when it comes back non-empty
- `tests/test_tick.py` — A3's last two cases

**Steps**

1. `_resolve_by_ownership`: an `added_both = []` local, appended when `base is None and ours is
   not None and theirs is not None` — the spec's own four lines, and the branch the stages already
   tell apart (`:184-188`, P13). Return `None` wherever the function returns `False` today
   (`:179`, `:183`, `:186`, `:188`, `:190`, `:192`) and `added_both` where it returns `True`
   (`:193` — the final `git add -A` must still have succeeded, so a failing `add` is `None`, not
   an empty list).
2. `push`'s call site, **PD2**: `discarded_now = _resolve_by_ownership(path)` / `if discarded_now
   is None: <abort and return False, as today>` / `dropped.extend(discarded_now)`. An identity
   test, never `if not …` — `[]` is a successful modify/modify resolution and the landed truth
   test would abort the rebase on it, taking all four of P19's exact-output assertions red
   (`tests/test_tick.py:209`, `:247`, `:283`, `:325`, `:362`). The accumulator is a local of
   `push`, outside the `for _round` loop, because the inner `while` can resolve several times.
3. The one extra line, printed **only** when the accumulator is non-empty, after the existing
   `rederived` line so the order reads "what happened, then what it cost":
   `tick: <n> card(s) discarded by the rebase — origin already holds these ids: <ids>`, the ids
   from the basenames (PD3) and sorted. A resolution that discarded nothing prints exactly the one
   line it prints today, which is the contract D8 keeps and P19 pins.
4. PD3's `discarded=None` parameter on `push`, extended with the record-relative paths. A3's call
   omits it and must stay byte-for-byte unaffected, so the parameter is last and defaulted and the
   return stays `bool`.
5. `commit_and_push` passes `dropped = []` and, when it is non-empty, prints one
   `NEEDS OPERATOR:` naming the ids and that they must be re-filed — the content is in the
   operator's reflog and nowhere the factory can read (C7), so the line asks for a decision and
   carries no command. It sits beside the push's own line, after it. The ids are derived once, in
   one helper, so the push's line and this one cannot disagree.
6. A3's last two cases. `test_a_modify_modify_resolution_still_prints_exactly_one_line` is the
   **unchanged body** of the landed
   `test_f0087_typed_field_and_machine_block_on_one_card_resolve_by_ownership_under_the_race`, as
   the spec's comment says — copy it, do not rewrite it, because its value is that it is the
   landed assertion. `origin_adds_the_same_id('B-0268')` must make a real add/add: origin's own
   `bugs/B-0268.md` with **different content**, pushed between the clone's commit and its push, so
   the rebase sees stage 1 absent and stages 2 and 3 both present. A fixture where the two sides'
   content matches produces no conflict at all and the case passes vacuously.
