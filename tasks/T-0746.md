The spec's `evidence.merge_branch` and `asf/backfill/history.py` bullets, and `## The design` §§2–3.
This is the Task that lifts P1: `main_commits` reads the trunk only since the record's first commit,
so every pre-ASF merge is invisible *by construction*, and backfill's own walk drops the `--since`.

Still nothing is written. `landings` returns `({card: Landing}, [Unmatched])` and the reader is
injected, so the whole mapping is testable with no git and no host — which is the property the
fence's last sentence asks for.

Read **PD2** (`merge_branch` takes `main` too, or its own fence cannot pass), **PD3** (the fallback
goes through `_by_legacy`, and `_find_legacy` would silently resolve every Task to its Feature),
**PD4** (there is no batch to expand) and **PD14** (the reader parses its own log; `_parse_name_log`
has no date slot) before starting.

**Steps**

1. `merge_branch(subject, main=None)` in `asf/evidence/evidence.py`, beside `_MERGE_SUBJECT`, with
   the spec's §2 docstring byte for byte apart from the signature line (PD2). Body: the loop
   `naming_ids` runs today — for each `rx` in `_MERGE_SUBJECT`, on a match take `m['branch']`, strip
   a leading `refs/heads/` then `origin/`, return `''` when `main and b == main`, else return `b`.
   `''` when nothing matched. Pure: no record, no git, no product.
2. `naming_ids`'s merge clause (`:978-984`) becomes `b = merge_branch(s, main)` /
   `return branch_ids(b) if b else []`. Nothing else in `naming_ids` moves — not the stacked-scope
   loop, not `_LEAD_SUBJECT`, not the order. The `return []` for a trunk merge is now
   `merge_branch`'s `''`, which `branch_ids` never sees; the reading is the same.
3. `MergeBranchTests` in `tests/test_evidence.py`, one case per clause of the spec's fence:
   `feature/auth-flow-3` for `Merge pull request #820 from o/feature/auth-flow-3`; `x/y` for
   `Merge branch 'refs/heads/x/y'`; `worker/T-0001` for
   `merge-queue: #752 (worker/T-0001 @ abc1234)`; `''` for a squash subject with no merge shape; and
   `''` for a merge of the trunk into a branch — that last one passing `main=` (PD2), which is the
   case that pins why the argument exists.
4. Re-assert P2's three measurements as tests in the same class, before and after values identical:
   `naming_ids('Merge pull request #820 from o/feature/auth-flow-3')` is `[]`,
   `naming_ids('Add the auth flow (#820)')` is `[]`,
   `naming_ids('merge-queue: #752 (worker/T-0001 @ abc1234)')` is `['T-0001']`. The fence says
   `test_evidence` is *"asserted **green and unchanged**"*; these three make "unchanged" a test
   rather than a promise, which matters because the refactor moves code out from under them.
5. `asf/backfill/__init__.py`: the package docstring — what the pass is, that it reads by default,
   that it types the record's own existing answers and derives nothing, and that `asf ingest` owns
   every state. Name F-0130. No code, no imports, no re-exports (PD13).
6. `asf/backfill/read.py`, the only module that shells out. Three readers, each returning plain data:
   the trunk walk of PD14 — `git log --merges --first-parent --format=%x00%H%x09%cs%x09%s
   --name-only --diff-merges=first-parent origin/<main>`, with `--since <rev>` appended only when the
   caller passed o
