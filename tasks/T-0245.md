## Description
stories: S-29353, S-29354
writes: asf/rules/rules.py, asf/tick/file_bugs.py, tests/test_rules.py, tests/test_file_bugs.py
after: Task 1

§2.4 — a live silent failure. `file_bugs.rule_check_results` runs the factory's own rule pass as a
subprocess of itself with `timeout=60`, while inside it each check gets 60 s and eight run at a
time: a record with nine rule cards needs two batches, and `$ASF_RULE_CHECK_TIMEOUT` raises the
inner budget without touching the outer one. When the outer timeout fires, `rule_check_results`
returns `None`, `rule_violation_signatures` returns `{}`, and the tick files no Bug for any
violation, reports no broken check and prints nothing at all. The whole rule → Bug loop the
module's docstring describes is lost without a word. The fix is to stop spawning: `rules` is
already callable in process — `load_rules`, `partition` and `run_all` all take `root`, are
stdlib-only, and `asf.rules.rules` imports nothing from `asf`, so there is no cycle. Also §2.6's
two `file_bugs` numbers, since this is the Task that owns the file.

**Files**

- `asf/rules/rules.py` — `_check(root)` and `check_data(root)`; `cmd_check` rendering rather than
  building
- `asf/tick/file_bugs.py` — `rule_check_results` in process; `_ASF_REPO_ROOT`, the `env_vars`
  block, the `subprocess.run`, the `timeout=60`, the returncode check and the `json.loads` all
  gone; `CI_REFUSAL_WINDOW_H` and `CHECK_FAILURE_RUNS_TO_SURFACE` reading their fields
- `tests/test_rules.py` — `CheckDataTests`
- `tests/test_file_bugs.py` — `RuleCheckInProcessTests`

**Steps**

1. `asf/rules/rules.py`: a private `_check(root)` holding `cmd_check`'s present body down to the
   payload — `load_rules`, `partition`, `run_all`, the malformed-rule lines appended to
   `violations`, `violations.sort()`, `unenforced.sort(key=…)` — and returning
   `(payload, len(enforced))`, where `payload` is the three keys `--json` prints today
   (`violations` as `{rule, line}` dicts, `unenforced`, `broken`). `check_data(root)` is
   `_check(root)[0]`, with §2.4's docstring. PD7 is why the count rides beside the payload rather
   than in it: `cmd_check`'s human line needs `len(enforced)` and the `--json` bytes must not move.
2. `cmd_check` becomes its `try/except RulesError` around `_check`, then the two renderers it
   already has: `json.dumps(payload, indent=2, sort_keys=True)` for `--json`, byte-identical, and
   the `== RULES …` block plus `--verbose`'s unenforced list for the human path. Its return codes
   (`2` for a `RulesError`, `1` for violations or broken, else `0`) are unchanged.
3. `asf/tick/file_bugs.py`: `rule_check_results(root)` becomes §2.4's six lines — a local
   `from asf.rules import rules`, `return rules.check_data(root)` in a `try`, `except
   rules.RulesError: return None`. Its docstring says what None now means and what it no longer
   means: None when the rule set itself could not be read, and a rule pass that ran is never None,
   however many checks broke.
4. Deleted with it: `_ASF_REPO_ROOT` (`:132`) and its three `dirname`s, the `env_vars` block
   (`:138`–`:141`) with its `BACKLOG_ROOT` and `PYTHONPATH`, the `subprocess.run` (`:142`), the
   `timeout=60`, the `returncode not in (0, 1)` check and the `json.loads`. In process there is no
   second clock, no `PYTHONPATH` to compute, no `sys.executable` to find — a `pipx` install has no
   repo root to point at, and `_ASF_REPO_ROOT` computes one anyway — and no JSON to re-parse (D5).
   The module's `import subprocess` goes; `import sys` stays (`:482`, `:490` print to stderr) and
   `import json` stays (it reads `index.json`).
5. No outer timeout replaces it (§1.3): with the pass in process its clock is its own per-check
   budget, `asf/rules/rules.py:38`'s `TIMEOUT` over `MAX_WORKERS = 8`, which is the only budget
   that was ever correct. `rule_violation_signatures`' body is untouched, and
   `report_check_failures` starts seeing `broken` entries it could never see when the outer
   timeout ate the whole pass
