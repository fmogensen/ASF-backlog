## Description

after: Task 1, Task 2

The spec's §*The design* §3 in full: `bug_rows` takes `adjudicated`, `_candidates` passes it, and the
`n > limit` branch stops being a dead end.

This is the half the other two make possible. Today an over-limit Bug emits
`WAITS ON operator — adjudicated after N sessions (limit 3): a person decides` and **nothing** moves
it: no ruling, no card edit, no `asf unpark`, no `asf correct`, ever. A person is told to decide and
then handed nothing that acts on a decision.

Read **PD5** (the reason's `STALEMATE → ADJUDICATE` prefix is correct — do not special-case it),
**PD6** (`tiers._remedy` prints a different clause and `asf/feeder/tiers.py` is not in this
footprint) and **PD7** (the docstring clause this Task must fix) before starting.

**Files**

- `asf/feeder/rows.py`:
  - `bug_rows` (**:787**) takes one keyword argument, `adjudicated=None`, appended after `why`.
  - its `n > limit` and `n == limit` branches (**:833-842**) merge into one, exactly as the spec
    writes it: `if n >= limit:` builds the STALEMATE row the cap builds today — `tier=tier`
    (identical to today's `0 if sev == 'S1' else 1`), `kind=STALEMATE`, `action=LAUNCH`,
    `brief_kind='adjudicate'`, `branch=branch_for(product, 'fix', b['id'])`,
    `reason=f"{sev} open after {n} sessions: adjudicate, not another fix"` — then
    `out.append(row if n == limit else _capped(row, attempts, limit, product, adjudicated))`.
    At `n == limit` the appended row is **byte for byte** today's row; past it, `_capped` decides.
    The `waits('operator', …)` call the old branch made is gone, and `waits` keeps its other four
    callers.
  - its docstring's last clause (**:795**) is rewritten: past the attempt limit the row is one of
    `_capped`'s three outcomes — a ruling carried out by one `correct` session on the fix branch, a
    PARKED row when the card has not moved, or one adjudicate session on this card state (**PD7**).
  - `_candidates` (**:2430**) passes it: the call at **:2445** becomes
    `bug_rows(items, product, busy | spoken, attempts, held_by, adjudicated)`. Nothing else in
    `_candidates` changes — `rows += [r for r in bugs if r.launches]` (**:2446**) takes the
    launching outcomes (`ruling_row`'s and the relaunching STALEMATE row, both `action=LAUNCH`),
    `bug_waits` (**:2447**) takes the non-launching PARKED one (`Row.launches` is
    `action.startswith(LAUNCH)`), and the merge at **:2471** puts it exactly where
    `waits('operator', …)` used to sit, behind the `spoken_for` test. The second `_capped`
    application at **:2484-2485** never doubles up: `STALEMATE` is not in `CAPPED_KINDS`
    (**:203-204**).
- `tests/test_feeder.py` — `BugPastTheAttemptLimit`. For a decided, open S1 Bug with
  `attempts = limit + 1`: with no adjudicate run recorded, the row is `STALEMATE → ADJUDICATE`,
  `would launch`, `brief_kind == 'adjudicate'`, on the Bug's fix branch; with an ended adjudicate
  run on this same card, the row is `PARKED adjudicated, card unchanged`, does not launch, keeps
  `waits_on == 'operator'`, and its reason names `` `asf unpark B-0057` `` (Task 2's string — this
  is why this Task is third); with an operator ruling **or a release** since that run, it launches
