   `HOLDER_PR`, `HOLDER_STUCK`, `HOLDER_NONE`).
2. `predecessor_question(text)` → the one item id the question names, or `''`: `PREDECESSOR_RE`
   fires and `ITEM_TOKEN_RE` finds exactly one distinct token. Two tokens or none is `''` (D-0013).

   predecessor's change is still off the trunk; the holder clause is appended in order — a live
   `Session` for that item by branch, else an open `PR` by number and branch, else `dep`'s own
   `Stuck` by **owner role** and capped reason (**PD12**), else `HOLDER_NONE`. Both answers end
   with the holder, because "is it still open" and "who owns this" are one question in the ledger.

   item) and `facts.prs` (open). Returns `(answer, resolvers.PREDECESSOR, ())` or `None`. Called
   from `_auto_answer` after `_card_read`, last of the four.
