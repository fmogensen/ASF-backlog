## Description
stories: S-37800
writes: asf/harvest/lane.py, tests/test_lane.py
after: none

The spec's design §1: one `own` field on the lane record, and the `ON_TRUNK` constant that names the
one landing the DONE table may not credit. Nothing in `asf/tick/summary.py` is touched here — this
Task only makes the fact readable; Task 2 reads it.

Read **PD1** (every anchor in this file is stale), **PD7** (why the two-argument `.get` is exact)
and **PD5** (the fixture cannot push an empty branch; this Task adds the helper) before starting.

**Files**

- `asf/harvest/lane.py` — `ON_TRUNK` constant; `Lane.record` gains `own`; the three `on-trunk`
  literals re-spelled through the constant
- `tests/test_lane.py` — the new `OwnCommits` class; the `push_lane_empty` helper on `LaneFixture`

**Steps**

1. `ON_TRUNK = 'on-trunk'` in `asf/harvest/lane.py`, beside the other lane constants near
   `HEAVY_DROPS` (`:161`), with the `#:` comment **byte for byte** from the spec's §1 block:

   ```python
   #: `method` on a MERGED record whose sha is the trunk tip, not a merge of this branch: the
   #: branch's work was already there. The one landing the DONE table may not credit (F-0191).
   ON_TRUNK = 'on-trunk'
   ```

   It must be module-level and importable — Task 2 reads `lane.ON_TRUNK`.
2. `Lane.record` (**`:1811`**, not the spec's `:1736`) gains the `own` field exactly as the spec's
   §1 snippet has it: after `prev = f.get('prev') or {}` and **before** the `heavy` block, so it
   sits ahead of `rec.update(extra)` and any explicit `own=` passed by a caller would still win.

   ```python
   # what the branch carried of its own, counted while origin/<trunk>..origin/<b> still shows
   # it (PD6). A branch gone from origin cannot be counted: the last pass that could, stands.
   own = f.get('ahead', prev.get('own'))
   if own is not None:
       rec['own'] = own
   ```

   The two-argument `.get` is the whole of C3 and C4 and is **not** interchangeable with
   `f.get('ahead') or prev.get('own')`, which would carry a stale count forward over a real `0`
   and leave the defect in place (PD7). The `if own is not None` guard is what makes "absent"
   distinct from `0` — do not collapse it to a plain assignment.
3. Re-spell the three `'on-trunk'` literals through the constant: `_judge`'s two returns at
   **`:1203`** and **`:1208`** become `return MERGED, f'method={ON_TRUNK}'`, and `enter_merged`'s
   test at **`:1996`** becomes `method in (ON_TRUNK, 'ff')`. Nothing else changes in either
   function; `method` is still `reason.split('=', 1)[-1]` (`:1974`), so it still reads `'on-trunk'`
   for those reasons and every existing test of the reason string stays green. `'ff'` is left a
   literal — the spec mints one constant, not two.
4. `tests/test_lane.py`: add `push_lane_empty(self, branch)` to `LaneFixture`, beside `push_lane`
   (`:388`) — a fetch then `git push origin origin/main:refs/heads/<branch>`, per PD5. It pushes a
   ref at the trunk tip and makes no commit. Task 2 uses it too.
5. The new `OwnCommits` class over `LaneFixture`, with the spec's four cases from A1:
   a branch with one commit records `own: 1` on every lane record through to `MERGED method=ff`;
   a branch pushed at the trunk tip (step 4's helper) records `own: 0` on its
   `MERGED method=on-trunk`; a branch gone from origin carries the previous record's count forward;
   a record with neither has **no `own` key at all** — assert `'own' not in rec`, not
   `rec.get('own') is None`, since C3 turns on the key's absence. Read the record back through
   `self.lane_of(branch)` (`:415-417`), which is the fixture's own accessor. For the third case,
   drive a pass that reaches `gone_merged` (PD7): the branch deleted from origin with the previous
   record's `head` an ancestor of the trunk.
