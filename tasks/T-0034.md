**Files**: `asf/groom/inbox.py` (adds `cmd_inbox`), `asf/cli.py`, `tests/test_inbox_shape.py`
(adds `InboxCommandTest`), `tests/test_path_resolution.py` (the PD12 row).

**Steps**
1. `cli.py`:
   - Add the subparser `inbox` with
     `help="file an untyped card into the record's intake dir (the groom types it)"` and the
     arguments `--title` (required), `--body-file`, `--parent` and `--product`. There is no
     `--type`.
   - Dispatch with
     `cmd_inbox(args, resolve_record(args, announce=_announce_stderr))`.
2. `cmd_inbox(args, root)`:
   - `d = os.path.join(root, intake_dir(args))`, created if it is missing.
   - The slug is `re.sub(r'[^a-z0-9]+', '-', title.lower()).strip('-')`, or `card` if that is
     empty. If the name is taken, append `-2`, `-3`, and so on.
   - The text is `# {title}\n`, then `parent: {id}\n` if given, then `\n`, then the body file
     verbatim.
   - Print the path relative to `root` and return 0. It mints nothing and runs no groom.
3. `InboxCommandTest`: every case the spec lists. `test_writes_an_untyped_card` compares a
   before/after listing of every item folder. `test_inbox_then_groom` runs `asf inbox --title
   "Billing invoices" --parent E-0001` and then `asf groom`, and expects exactly one new file
   under `features/` whose `parent` is `E-0001`.
4. `tests/test_path_resolution.py`: add the PD12 row.
5. Nothing is added to `asf.plugin_build`, because `inbox` is neither a view nor a dialogue.
   `python3 -m asf.plugin_build check` must stay clean.
