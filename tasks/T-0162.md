§2.5. The filer belongs to the record, not to either pass that calls it, so F-0091's `improve` and
this pass file through one writer whichever lands first (§1.4). It is the `file_bugs` shape exactly
(P12), with `source` in place of `signature` — and a Feature may not carry `signature:` (P11), which
is why the key is a different one.

**Files**

- `asf/record/propose.py` — **new**: `propose(root, canonical, source, fields, body, date,
  level='auto', product=None, out=print)` and `find_open_by_source(canonical, source)`.
- `asf/approvals.py` — `CLASSES` (`:43`) gains §2.5's `ActionClass('propose_improvement', …)`.
- `asf/record/new.py` — `SETTABLE['feature'] |= {'source'}` (`:19`).
- `docs/products.example.yaml`, `sample/product.yaml` — `propose_improvement: groom` under
  `approvals:` (PD11).
- `tests/test_savings.py` — `ProposeTests` (new, §3.5).
- `tests/test_approvals.py` — `known_readers` gains `'savings'` (`:54`, PD11).

**Steps**

1. `find_open_by_source`: the item that `core.is_open` and whose typed `source:` matches.
2. `auto` — found and `last_seen` is today → `'skipped'`, nothing written; found → write typed
   `measured`, `last_seen`, `expected_pct` and `rank`, append one `## History` line
   `- <date> savings: <class> <before> → <reading> (<n> landings)` → `'bumped'`; not found →
   `ids.mint_id(root, canonical, 'feature')` and `ids.write_new_item(...)` with §4's typed fields
   and an `## Acceptance` of one line, the number that closes it → `'filed'`.
3. `groom` (the default) — one file per proposal in `conventions.intake_dir`, named
   `savings-<class>-<subject>.md`, same body, `parent:` carried. An intake file already there for
   that key is overwritten with the new number, so the groom never sees two. Nothing under
   `features/` is touched.
4. `human-now` — nothing written, one line per proposal:
   `NEEDS OPERATOR: savings proposes <class> (<sentence>) — widen approvals: propose_improvement in
   products/<p>.yaml`.
5. `do_index` is **not** called here — the caller calls it once at the end (P12), as `cmd_file_bugs`
   does (`file_bugs.py:258`).
6. `propose_improvement` joins `CLASSES` in §2.5's words, `'groom'` by default, `read_by
   ('savings',)`; `known_readers` in `tests/test_approvals.py` gains `'savings'`; both yamls gain
   the key — one diff, or `CatalogueTest` is red (PD11).
7. `SETTABLE['feature'] |= {'source'}`, so the same field can be written by hand with `asf new
   --set source=…`.
8. `ProposeTests` per §3.5: `auto` files one Feature per over-threshold class with §4's typed
   fields, and a second run the same day changes nothing; a run the next day with a new reading
   bumps `measured` and appends one `## History` line; two subjects of one class are two cards;
   `groom` writes the intake files and touches no Feature; `human-now` writes nothing and prints one
   `NEEDS OPERATOR:` line per proposal; `approvals.matrix` accepts `propose_improvement` (P13) and
   `asf check` is clean over everything filed — including that no filed Feature carries `writes:` or
   `signature:` (P11, `check.py:170`).
