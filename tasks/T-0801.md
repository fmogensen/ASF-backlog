**A. S-58804 — the failing test's own file is read out of the log.**

```bash
python3 -m unittest tests.test_merge_queue.TestPathsTests -v
```

`TestPathsTests` — over `failure_findings`' per-check item and the readers under it:

- a unittest log carrying `File "~/work/o/p/tests/test_audit.py", line 42, in t` gives
  `test_paths` containing `('~/work/o/p/tests/test_audit.py', 42, <the line>)`, and
  `paths` still `[]` (the direct reading is untouched, P4)
- a relative traceback frame `File "tests/test_audit.py", line 42` is read the same way
- `FAIL: test_x (tests.test_audit.AuditGap.test_x)` gives a `test_paths` entry for
  `tests/test_audit.py` at line `0`
- a check whose log does not read keeps both `paths` and `test_paths` empty and raises nothing
- the three shapes the direct reading already catches (`tests/test_audit.py:42: AssertionError`,
  `FAILED tests/test_audit.py::C::t`, `FAIL  src/audit.test.ts > name`) keep the exact `paths` they
  have today

and the one bullet of S-58804's own list that §2 owns:

- [ ] `repo_path` reduces an absolute runner path to the batch tree's own spelling, and gives
  `None` for a path the tree does not hold

**B. S-58805 — a test file no member changed names the member whose files it covers.**

```bash
python3 -m unittest tests.test_merge_queue.CoversTests -v
python3 -m unittest tests.test_merge_queue.CoverBlameTests -v
```

`CoversTests` — `covers` is pure and discriminates: a test whose text reads `from asf.audit import
rows` covers `asf/audit.py` and not `asf/release.py`; a test named `test_audit` covers `asf/audit.py`
with no import at all; `asf/a/b/__init__.py` is covered by a test naming `asf.a.b`; a changed
non-source file (`README.md`, `docs/x.md`) is covered by nothing.

`CoverBlameTests` — over a three-member batch whose log names only `tests/test_audit.py`:

- the member that changed `asf/audit.py` is named, the other two are not
- the recorded entry is `(asf/audit.py, 0, <the finding's line>)` — the member's own file, not the
  test's (D-0006)
- `blame` returns that map with `covered` true, and `_send_back` is called with
  `files == ['asf/audit.py']`
- a test path that **is** in a member's diff never reaches the hop: the direct reading's answer
  stands and `covered` is false (D-0004)
- a test that covers all three members returns `{}` — the batch splits, as it does today (P7)
- a log path that resolves to nothing in the tree (`/usr/lib/python3.12/unittest/case.py`) is
  skipped and names nobody
- `repo_path` reduces an absolute runner path to the tree's spelling and gives `None` for a path
  the tree does not hold

and the two bullets of S-58805's own list that the layer's gate proves:

- [ ] An unreadable test blob, and a log path that resolves to nothing in the tree, name nobody and
  raise nothing
- [ ] `tests.test_merge_queue.Culprit` is green and unchanged — the direct reading, the send-back
  and the blind split all behave exactly as before — proven by `tests/test_merge_queue.py`

**C. S-58806 — the drop reason names the culprit, and the weaker hop is not held.**

```bash
python3 -m unittest tests.test_merge_queue.DropReasonTests -v
python3 -m unittest tests.test_merge_queue.Culprit -v
```

`DropReasonTests`:

- the drop line of a batch whose log names one member's own file reads
  `… dropped — red on <why> — #1's (its files, named in the failing job's log)`
- the drop line of a batch blamed through the hop reads
  `… dropped — red on <why> — #1's (the failing test tests/test_audit.py covers its files)`
- the cancel claim written for a live run on the dropped ref carries the same text in its `why`
- with no culprit (the blind split) and with the check red on the trunk too, the drop line is
  **unchanged**: `… dropped — red on <why>`
- the gate ledger row is **unchanged** in every one of those cases: `merge queue <ref>: red: <why>`
  (D-0002, P11)
- `culprit_text`'s head says `the failing test <path> covers files only this PR changes` for a hop
  culprit and keeps today's wording for a direct one
- with `merge_queue.hold_culprit` on and a deterministic red, a direct culprit is written to
  `merge-queue-culprits.json` and a hop culprit is **not** (D-0007)

`Culprit` is asserted **green and unchanged** — the direct reading, the send-back, the innocent
members' re-cut and the blind split all read exactly as they read today (P3, P7).

and one bullet this plan adds, from PD2:

- [ ] a lone member whose log named no file keeps the unchanged drop line — the `len(members) == 1`
  culprit entry (`asf/merge_queue.py:825-826`) is a membership fact and claims no evidence
