**Files**

- `asf/improve/measure.py` — `table(runs)`: `landed` and `min_per_landing` on each `by_kind`,
  `by_model` and `by_kind_model` entry.
- `asf/improve/classes.py` — the fifth class, `kind_ratio_regression`.
- `asf/improve/improve.py` — one more block in part (a) of `improve/<date>.md`, and the same rows
  into the `history.jsonl` line under `by_kind_model`.
- `tests/test_improve.py` — `MinutesPerLandingTests`, `KindRatioRegressionTests`.

**Steps**

1. `by_kind[k]`, `by_model[m]` and `by_kind_model[(k, m)]` each gain `landed` (runs of that cell
   with `landed`) and `min_per_landing` (`Σ minutes of that cell / landed`, rounded as the
   neighbouring keys are), and `None` when `landed == 0` — an infinity is not a number to rank on.
   Pure arithmetic over the runs list: no clock, no file, as F-0091 §2.1 requires of everything in
   `table`.
2. `improve.py` renders one more table in part (a) — `| kind | model | runs | hours | landed |
   min/landing |`, one row per `(kind, model)` cell with at least one run, sorted by
   `min_per_landing` descending so the worst is first and the argument is at the top, `None`
   printed as `—`. The same rows go into the `history.jsonl` line under `by_kind_model`.
3. `classes.py` gains `kind_ratio_regression`: for each kind with ≥ 5 landings in **both** this
   run and `before`, `now.min_per_landing / before.min_per_landing`; default threshold 1.5;
   measured is the largest such ratio, over when any kind is at or above it. The sentence is
   §2.5.2's verbatim: `<kind> now takes <now> min per landing, up from <before> — <pct> % worse
   over one week (<landed> landings this week, <before_landed> last).`
4. `excess_usd = (now.min_per_landing - threshold × before.min_per_landing) × landed / 60 ×
   usd_per_hour` of that kind, never negative — a kind exactly at 1.5 is worth $0, is printed, and
   proposes nothing.
5. The card it proposes is F-0091's shape unchanged: a `feature` under `improve.epic` with
   `source: improve:kind_ratio_regression:<kind>` as the dedupe key, so a kind bad for three weeks
   bumps one card's rank instead of filing three.
6. Under the sample floor, or with no `before` (the first run), the class prints
   `not measurable — needs two runs with ≥ 5 landings` and proposes nothing.
7. `MinutesPerLandingTests` and `KindRatioRegressionTests` over frozen run lists and a frozen
   `before` line — no clock, no `~/.ASF`, no network, in F-0091's own test idiom.
