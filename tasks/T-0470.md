The spec's third and fourth **In** bullets and `## The design` §1's and §2's conventions halves. Two
keys move from "kept verbatim in `Conventions.extra`" to declared, documented, shape-checked fields,
and the operator's two config pages gain them. No reader changes in this Task: retention keeps
reading `branch_patterns` exactly as it does today, and nothing reads `legacy_review` yet.

**Files**

- `asf/conventions.py` — `DEFAULT_BRANCH_PATTERNS`, `PLACEHOLDER_RE`; the two dataclass fields
  `branch_patterns` and `legacy_review`; two blocks in `validate_mapping`
- `tests/test_conventions.py` — the shape cases for both keys
- `tests/test_retention.py` — one case pinning `owned_patterns` over a pattern carrying placeholders
- `docs/products.example.yaml` — the `legacy_review` block beside `review_pattern` (`:49`), and a
  `branch_patterns` block beside it
- `docs/guide/product-config.md` — both keys in the conventions table (`:71-72`) and a paragraph each

**Steps**

1. `DEFAULT_BRANCH_PATTERNS = {}` and `PLACEHOLDER_RE = re.compile(r'<(id|slug)>')` with the spec's
   comment byte for byte (`## The design` §1). The default is a **plain empty dict**, not a path
   string: `python3 -m asf.conventions --forbidden` generates one pattern per path-shaped default and
   a default that looked like a glob would forbid its own text across `asf/**/*.py` (PD15, D7).
2. `branch_patterns: dict = field(default_factory=lambda: dict(DEFAULT_BRANCH_PATTERNS))` beside
   `branch_prefixes` (`:630`), and `legacy_review: dict = None` beside `review_pattern` (`:634`) —
   `None`, no default, D7. Both are now in `field_names()`, so `Conventions.get` finds them on the
   dataclass before it looks in `extra` (`:1036-1040`) and `__contains__` is true for both.
3. `validate_mapping` (`:438`) gains `branch_patterns`: not a map → one problem; a value that is not
   a non-empty string → one problem naming the entry; a value carrying more than one `<id>` or more
   than one `<slug>` → one problem; a value that does not compile once its placeholders are replaced
   → one problem. The docstring's list of checked keys grows both new names.
4. `validate_mapping` gains `legacy_review`: not a map → one problem (today `{'legacy_review':
   'nope'}` returns `[]`, measured — P14); a key that is not `glob` or `verdict_regex` → one problem
   naming it; either value missing, not a string, or empty → one problem; `verdict_regex` that does
   not compile → one problem carrying the `re.error`; a `glob` with no `{slug}` → one problem, since
   a glob without it reads one item's review as every item's (§2).
5. Nothing is added to `asf/env.py`: `env.validate_product_text` already routes the whole
   `conventions:` map through `validate_mapping` and reports each problem as `conventions.<key>` with
   its line (`:684-687`, P15). Asserted, not assumed — one case in `tests/test_env.py`'s existing
   style is **not** added here; instead the Gate runs `tests.test_env` and `tests.test_sample_product`
   whole, which is what would catch a key the router does not reach.
6. `tests/test_conventions.py`: `branch_patterns` survives `from_mapping` as a declared field and not
   an extra (`'branch_patterns' not in conv.extra`), `conv.get('branch_patterns')` returns it, a
   product declaring none gets `{}`; then each of step 3's four problems, each asserted as exactly
   one `(key, why)` and the well-formed forms (`'hotfix/<slug>'`, `'feature/<id>-<slug>'`, a literal
   with no placeholder) asserted clean. Then step 4's five problems for `legacy_review`, the
   well-formed `{'glob': '{reviews_dir}/{slug}-r{n}.md', 'verdict_regex': r'\(APPROVED\)'}` clean, and
   the unset default `None`.
