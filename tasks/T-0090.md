**Steps**

1. `health.health`'s per-session arm: `status = lifecycle.classify(s, ev, path=registry)`; the
   reason written is `f'{DEAD}: {status.reason}'` for a `dead` status and `status.result`
   otherwise. `publish_gap` (B-0056), the unpushed hold (B-0051/B-0075) and the empty-branch hold
   (B-0076) key off the same reason text they do today — `judge` is unchanged and `status.result`
   is what it returned. Health still writes exactly one `ended` line per run, at the tick (§1.2).
2. The B-0028 re-judge arm reads `lifecycle.is_dead_reason(s.get('end_reason'))` instead of
   `== lifecycle.DEAD_PID`, so a run health closed under either text is re-judged when its result
   appears.
3. `stall.classify` takes the classifier's `Status` (resolved once per session by `stall.stall`,
   which already resolves one `alive` callable for the whole list — `asf/workers/stall.py:82-86`):
   `DEAD` only when the status is `dead`, nothing at all for an ended-awaiting-tick run, and
   `STALL` (alive but silent) unchanged. An ended session is not a stall and is not reported.
4. `harvest.reap_hold(record, alive=None, session_source=None, product=None)` becomes the one
   question of P9 — `lifecycle.is_live(record) or lifecycle.holds_seat(status)` — returning
   `status.label` as the why, and keeping `'no finished line in its record'` for `record is None`.
   `reap` and `run_harvest` pass the `alive` they already build (`asf/harvest/harvest.py:221`, `:556`).
   `is_eligible` is untouched.
5. `step_health.dead_jobs` per P8. `correct_once`'s own behaviour, the twice-dead flag and
   `handle_dead` are unchanged — only which jobs reach them, and that set is the same set as today
   plus nothing.
6. `tests/test_lifecycle.py`: `OneClassifierTest`'s `NOT_YET` is emptied and the ratchet's
   docstring replaced by §2.7's rule. From here the test is what §3.6 fences.
7. Every `dead pid` expectation in the four test files becomes the honest text, except where the
   fixture is a ledger line *on disk* — those keep `dead pid` on purpose, and assert it still
   classifies as `dead(no end-of-run record, nothing pushed)` (§4: nothing rewrites history).
