§2.5. One fact on one row, and one block in one brief. The row's own branch is unchanged —
`worker/<id>`, the prefix harvest scans for code (B-0067) — and only its *base* moves: a small
Task builds on the Tasks already on the train rather than on the trunk. The feeder runs no git and
opens no file; the tick reads the registry and passes it in (PD11).

**Files**

- `asf/feeder/rows.py` — `Row` gains `train: str = ''` and `base: str = ''` (`:66`);
  `task_rows` (`:350`), `candidates` and `plan_rows` (`:508`) gain `trains=None`; the launching
  PLAN → CODE row sets the two fields.
- `asf/tick/step_wave.py:117` — `plan_inputs` gains `'trains': train_mod.open_trains(product)`.
- `asf/workers/spawn.py:146` — `make_worktree(product, job, branch, base=None)` cuts a fresh
  branch from `origin/<base>` when one is given, `origin/<main>` otherwise; `spawn` passes
  `row.base`.
- `asf/briefs/build.py` — the coder context gains `train`, `base` and `train_max_tasks`.
- `asf/briefs/templates/coder.md` — §2.5's block, rendered only for a train row.
- `tests/test_feeder.py`, `tests/test_briefs.py` — §3.6.

**Steps**

1. The two `Row` fields default to `''`, so every existing construction and every existing golden
   row is unchanged.
2. In `task_rows`, on the row that launches (after the `after:`, reshape, split and footprint
   gates already there): when `t.get('size') == 'small'`, the Task's lane is in
   `product.conventions.train_lanes`, and `trains` holds an open train for that lane, the row
   carries `train=<id>` and `base=<train branch>`. Any one of the three missing leaves both
   empty — which is `train.lanes: []`, a medium Task, and a lane with no open train
   respectively, all three asserted.
3. `trains=None` threads through `plan_rows` → `candidates` → `task_rows` as a keyword with a
   `None` default, so `asf next` and the status cell keep working when the tick has not read the
   registry. `plan_inputs` is the one place that fills it (PD11).
4. `make_worktree` gains `base=None`. It changes exactly one branch of that function — the
   "otherwise a fresh branch off `origin/<main>`" path takes `origin/<base>` instead. A worktree
   that already holds the branch is still reused and rebased as it stands, a held branch still
   comes back to its session, and `may_launch` and `ensure_git_hooks` still run before any of it:
   a base is where a *new* branch starts, never a rebase target.
5. The coder brief gains §2.5's block, rendered under a `{% if train %}`-equivalent the template
   engine already uses for optional blocks, with `{train}`, `{branch}`, `{base}`, `{item_id}` and
   `{train_max_tasks}` substituted. A medium or large Task renders none of it and its brief is
   byte-identical to today's.
6. `tests/test_feeder.py` per §3.6: a small Task's PLAN → CODE row carrying `train` and `base` when
   a train is open for its lane; carrying neither when `train_lanes` is empty, when the size is
   `medium`, when the size key is absent entirely (a record ingested before Task 3), and when
   `trains` holds no open train for that lane; and the row's `branch` staying `worker/<id>` in
   every one of those cases.
7. `tests/test_briefs.py` per §3.6: the coder brief rendering the train block with the train id,
   the base branch and the seat count; rendering none of it for a medium Task; and the existing
   test that makes a template placeholder without a context key a test failure still passing over
   the edited template.
