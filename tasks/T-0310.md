## Description
stories: S-30550, S-30560
writes: rules/*.md, rules/*.sh, tests/test_rule_hooks.py
after: Task 7

§3's T1 and T11 — the two tests that can only be written once every card exists: the whole-set
assertion over `rules/`, and the end-to-end run of the installed commands. This is the card's
first and second acceptance, and T11 is the test that would have caught every wiring hole the
spec's opening names. The `rules/` globs are in this Task's footprint as the set-level owner: if
the band or shim assertion finds a card whose frontmatter diverges, this Task corrects that card
rather than filing against the Task that wrote it.

**Files**

- `tests/test_rule_hooks.py` — `CoreRulesDirTests` and `FixtureSessionTests`.
- `rules/*.md`, `rules/*.sh` — no new file; the footprint is here only so a divergence found by
  the set-level assertion is fixable in the Task that finds it.

**Steps**

1. `CoreRulesDirTests`: `rules/` holds `README.md`, seven `R-000N.md` and seven `r000N.sh` (PD5);
   every card parses as frontmatter with `id`, `type: rule`, `title`, `check` and `hook`; every
   `hook:` value is a subset of `hooks.EVENTS`; every id is in the band `R-0001`–`R-0099` (D11);
   every hooked card has a script at `rules/<id-form>.sh` that is executable and whose shim line
   names `asf.rules.hooks.<id-form>`; the `check:` line is asserted for its *shape* only and never
   that the path exists (PD11); and `declared_hooks(RULES_DIR)` returns exactly the seven
   `(event, name)` pairs the cards declare, in the order `sorted(os.listdir)` gives them.
2. `FixtureSessionTests`: a fixture product, a fixture worker account, a fixture worktree, all
   under a tmpdir `ASF_HOME`. `asf hooks install` runs **for real**; the account's settings file is
   read back and every hook command in it is **executed** as the runtime would execute it —
   `asf hook <name>` is not assumed, it is run, with the call JSON on stdin and the session
   environment set — for one refused call and one allowed call per rule. Asserted per rule: rc 2
   and the first line of the refusal for the refused call, rc 0 and empty stderr for the allowed
   one, and one `refused-rule` row per refusal in the product's `approvals.jsonl`. Add the two
   cases the wiring holes were: one call per rule with the *wrong* `tool_name`, which must be rc 0
   and silent (PD6); and one run with `ASF_JOB` unset, which must be rc 0 for every rule (D12).
   R-0006's refused case is its report — rc 0 with its lines on stdout — and R-0007's is a `Stop`
   over a dirty fixture worktree.
3. Then `asf rules hooks --json` over that ledger: `7 declared, 7 installed`, `0 unresolved`, and
   the per-rule refusal counts the run produced (PD5).
4. Read every file this Feature added against T13's two checks one last time — the cards and the
   shims are outside `tools/check_conventions.sh`'s scan but inside `tools/check_generic.sh`'s.
