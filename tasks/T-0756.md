The spec's first `## In` bullet and `## The design` §§1–2: `run_steps(..., clock=None)` returns
`[(job, seconds)]`, `publish_timing_line(timings, wall, workers)` says it in one line, `health`
measures its own wall clock around the `run_steps` call and carries the line as a single
`('health', 'publishes', line)` entry in `found`.

Nothing the factory *does* changes when this lands: no judgement, no hold, no ledger field, no
push. That is why it goes first and can be proven on its own — and why the five existing
`RunStepsTest` cases staying green is what proves the timing changed no behaviour (PD14).

Read **PD5** (the queues carry no job today), **PD6** (the row's first element is the job, and the
line is printed raw) and **D3**'s spacing fence before starting.

**Files**

- `asf/workers/health.py`
  - `run_steps` (`:460-495`) — the `clock` parameter, `queues` carrying `(job, generator)` pairs
    (`:470`), the `timed` helper, `asks` as `(job, qi, ask)` (`:479`), both publish branches
    (`:486-490`), and `return timings` in place of the bare `return` (`:485`)
  - `publish_timing_line(timings, wall, workers=PUBLISH_WORKERS)` — new, beside `run_steps`
  - `health` (`:802-806`) — the wall clock around the `run_steps` call, and the one appended entry
    after the per-run ones
  - the print loop (`:845-846`) — `elif what in ('published', 'publishes'):`
  - `time` and `PUBLISH_WORKERS` are already in the module (`:52`, `:425`): no new import
- `tests/test_health_publish_steps.py` — `PublishTimingTests`; `RunStepsTest`'s five cases untouched

**Steps**

1. `run_steps` gains `clock=None` and binds `clock = clock or time.monotonic` — a fake clock is how
   the acceptance scripts the seconds without sleeping.
2. `queues = [[(entries[i][0], entries[i][2]) for i in g] for g in _groups(entries)]` (PD5). The
   send site becomes `asks.append((queue[0][0], qi, queue[0][1].send(sends[qi])))`; the
   `StopIteration` branch (`queue.pop(0)`, `sends[qi] = None`) is unchanged, and `_groups` is not
   touched at all.
3. One local helper, no `try`/`finally` (PD5):

   ```python
       def timed(job, ask):
           started = clock()
           return publish(*ask), (job, clock() - started)
   ```

   The seconds are computed **inside** the worker and returned with the result, so no shared list is
   ever written from a thread (P3). A publish that raises propagates unwrapped and records no row.
4. Both branches keep their shape: `done = [timed(job, ask) for job, _qi, ask in asks]` when there
   is one ask or one worker, `done = list(pool.map(lambda a: timed(a[0], a[2]), asks))` otherwise.
   The resume loop becomes
   `for (_job, qi, _ask), (result, timing) in zip(asks, done): sends[qi] = result; timings.append(timing)`
   — so the rows are in the order the calls were made, and every resume still happens on this
   thread, one run at a time.
5. `timings = []` before the loop; `return timings` where the function returns today (`:485`), and
   the `finally` that shuts the pool down is unchanged. Extend the docstring with the spec's own
   sentence: *"Returns ``[(job, seconds)]``, one row per publish made, in the order they were made."*
6. `publish_timing_line(timings, wall, workers=PUBLISH_WORKERS)` — the spec's docstring byte for
   byte. One line:

   ```python
       total = sum(s for _job, s in timings)
       job, slow = max(timings, key=lambda t: t[1])
       return (f'publishes: {len(timings)} push(es), {total:.0f} s of pushing in {wall:.0f} s '
               f'({workers} at once); slowest {job} {slow:.0f} s')
   ```

   Whole seconds, each with its space (D3, PD6). The function assumes at least one row — say so in
   the docstring; `health` is what guards it.
