weighted Total, put above `## Waste`, with `cmd_rollup` resolving the record list once and printing
the same numbers to stdout. Everything below the new section is byte-identical to what the same
fixture renders today.

**Files**

- `asf/metrics/metrics.py` — `_delta_int`, `_money`, `_delta_money`, `throughput_total(rows)`,
  `throughput_rows(root, day, items, records)` and `throughput_block(day, rows, skipped)` after
  `throughput_records`; `render_daily` (`:552-566`) gains `records=None, skipped=(), rows=None`
  and the new first section; `cmd_rollup` (`:1203-1231`) resolves the list and prints its line.
- `tests/test_metrics.py` — `EXPECTED_DAILY` (`:289`) gains the `records=None` section (P4);
  `ScorecardFirstLineTests` (new) with the two-record fixture of §2.4.

**Steps**

1. The three formatters exactly as §2.4 fences them: `_delta_int(now_, then)` →
   `f"{now_ - then:+d}"` (so no change is `+0`, never `0`); `_money(v)` → `'—'` when None else
   `f"${v:,.2f}"`; `_delta_money(now_, then)` → `'—'` when either is None, else
   `f"{'+' if now_ >= then else '-'}${abs(now_ - then):,.2f}"`. Copied as written (P15).
2. `throughput_total(rows)` → the Total's `(week, prev)` pair: `features` and `priced` summed
   across the rows, `usd` summed over the priced (None when nothing was priced), `mean` the
   **weighted** mean — total priced USD over total priced count, never the mean of the per-product
   means (§1.4). Used by `throughput_block` for its Total row and its headline, and by `cmd_rollup`
   for its stdout line, so the three can never disagree.
3. `throughput_rows(root, day, items, records)` → `[(label, week, prev)]`: for each
   `(label, r)` in `records`, `record_throughput(r, items if os.path.realpath(r) ==
   os.path.realpath(root) else match.load_index(r), day)[:2]`. This record reuses the `items` map
   `cmd_rollup` already loaded; every other record's comes from `match.load_index` on its own path
   (§2.4). A record whose index will not load returns an empty map rather than raising — it was
   already checked for `index.json` in Task 3, and a rollup does not fail on another product.
4. `throughput_block(day, rows, skipped)` → the list of markdown lines, pure over its arguments:
   `## Features on production`, the headline sentence restating the Total row (count, mean, last
   week's pair, `Δ features`, `Δ cost`, then "Every section below is diagnostic."), the note line
   naming both windows, the `by the day each Feature's stage reached \`on-prod\`` clause and the
   whole-life-cost sentence, then `Not read: <names joined by ', '>.` **only when `skipped` is
   non-empty**, then the seven-column table and the `**Total**` row. The windows in the note are
   `days_back(day, 7)[0] … [-1]` and `days_back(day, 14)[:7][0] … [-1]`, so the printed
   `2026-09-15 … 2026-09-21 against 2026-09-08 … 2026-09-14` falls out of the same call
   `record_throughput` makes.
5. `render_daily(root, day, items, conv=None, records=None, skipped=(), rows=None)`: the two
   existing lines of `out` stay exactly as they are, then
   `out += throughput_block(day, rows if rows is not None else throughput_rows(root, day, items, records or [('this record', root)]), skipped)`
   and `out += ['## Waste', …]`. With `records` and `rows` both None the section is one row
   labelled `this record` whose Total equals it — printed all the same, so the section is never
   absent (§2.4). The `rows` keyword is P6; the docstring says it is the rollup's already-computed
   list and that None means "compute it here".
