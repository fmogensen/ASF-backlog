## Description
stories: S-15507

§2.7: the adjudicate job becomes `groom-<date>-<sig>`, `adjudicate_attempts` counts per question
set, `adjudicate_rounds_per_day` is the day's ceiling, and the answers file carries the signature.
Without this the loop stalls after two sessions a day and the tick cadence buys nothing. The
hotfix's `new`/`adjudicate_per_day` answer to the same question is removed here (PD6).

**Files**

- `asf/groom/policy.py` — `question_signature(ids)` and `adjudicate_rounds_per_day(product)` per
  §2.7; `adjudicate_per_day` deleted (`:75`, PD6).
- `asf/groom/answers.py` — `_ANSWERS_FILE_RE` per §2.7; `_newest_applied` returns the newest *date*
  (group 1); `apply_pending_answers` supersedes only across a strictly later date.
- `asf/groom/digest.py` — `render_digest`/`write_digest` take `queued: bool` in place of
  `(attempts, cap)` (`:78`, `:124`); the day's remaining open questions are **Spoken for** when
  true and `NEEDS OPERATOR` lines under **For you** when false.
- `asf/groom/groom.py` — the answers-file branch reads the date from group 1 for the file it
  attributes sections to and the whole stem for `adjudicator_job=f'groom-{stem}'` (`:697-710`);
  `write_digest` is given `queued`, computed from the same three tests `groom_row` applies (`:772`).
- `asf/tick/step_wave.py` — `groom_state`'s `sig`, `job`, per-set `attempts`, `rounds` and
  signature-bearing `answers` path (`:71-99`); `_not_yet_put` and `'new'` deleted.
- `asf/feeder/rows.py` — `groom_row`'s three hold-back tests (`:391-406`); `groom_date` carries
  `f'{date}-{sig}'`, so the job and `branch_for(product, 'groom', f'{date}-{sig}')` are the round's.
- `tests/test_feeder.py` — `GroomRoundTests` (new, §3/T8); `GroomRowTests:352` follows the new job.
- `tests/test_tick_steps.py` — `PendingAnswersTests` (new, §3/T8's second half).
- `tests/test_groom_every_tick.py` — `SameDayAdjudicateTests` re-expressed over the signature (PD7).

**Steps**

1. `policy.question_signature(ids)` — eight hex of sha1 over the sorted open-question ids, stdlib
   `hashlib`. `policy.adjudicate_rounds_per_day(product)` — `groom.adjudicate_rounds_per_day`,
   default 12.
2. `groom_state`: `sig` over the suppressed open ids, `job = f'groom-{date}-{sig}'`, `attempts`
   counted against that job alone, `rounds` the distinct `groom-<date>-*` jobs the ledger holds,
   `answers` at `<state dir>/groom/{date}-{sig}.answers`. `new` and `_not_yet_put` go (PD6).
3. `groom_row` holds back when any of: a session whose job starts with `groom-<date>` is in flight
   (one adjudicate session at a time, as today); `attempts >= adjudicate_attempts(product)`;
   `rounds >= adjudicate_rounds_per_day(product)`. The `elif` of PD6 is deleted with them.
4. `answers.py`: `_ANSWERS_FILE_RE` becomes
   `^(\d{4}-\d{2}-\d{2})(?:-[0-9a-f]{8})?\.answers$`, so the legacy `<date>.answers` is still read;
   `_newest_applied` reads group 1 off the `.answers.done` names; `apply_pending_answers` supersedes
   a pending file only when a **strictly later date** has been applied, so two signatures of one day
   are both applied. `carry_staged_answers` needs no change — its stem already comes from the job.
5. `cmd_groom`'s answers-file branch per §2.7's last paragraph.
6. `digest`: `queued` replaces `(attempts, cap)`; `cmd_groom` computes it from step 3's three tests.
7. `groom.adjudicate_per_day` is deleted and becomes an unread key; the Task's report carries
   `NEEDS OPERATOR: a product that set groom.adjudicate_per_day — replace it with
   groom.adjudicate_rounds_per_day (default 12); groom.adjudicate_attempts now counts per question
   set, not per day`.
8. `GroomRoundTests` and `PendingAnswersTests` per §3/T8.
