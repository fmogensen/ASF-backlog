§2.6's plugin half, and §3.1's assertions that could not be written until every command existed.
A skill is one `VIEWS` entry plus the command's own `help=` string (§1.1) — there is no
hand-written skill file, and nothing under `plugin/` is hand-edited.

**Files**

- `asf/plugin_build.py` — `VIEWS` gains `'ci'`, `'health'`, `'performance'`
- `plugin/skills/{ci,health,performance}/SKILL.md` — new, written by `asf plugin build`
- `plugin/.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json` — regenerated
- `tests/test_plugin.py` — the per-skill assertions now over fifteen
- `tests/test_views_header.py` — `PENDING` deleted; the completeness and source guards; the
  twenty-command round trip

**Steps**

1. Add the three names to `VIEWS` (`asf/plugin_build.py:34`), keeping the tuple in the order an
   operator reads the console: fourteen views plus the `groom` dialogue, fifteen skills.
2. Run `python3 -m asf.cli plugin build` and commit its output. No file under `plugin/` or
   `.claude-plugin/` is edited by hand; `python3 -m asf.cli plugin check` exiting 0 over the
   committed tree is the standing proof.
3. `PENDING_VIEWS` stays empty (§1.1): all three commands are registered by Task 5, so there is
   nothing to except.
4. Delete `PENDING` from `tests/test_views_header.py` (PD10) and assert §3.1's completeness rules
   in full: `set(plugin_build.VIEWS) <= set(header.TITLES)`, and every `header.TITLES` key's
   first word is a registered command of `build_parser()`.
5. The two source guards, as assertions rather than as review: `'== '` appears in no f-string or
   string literal under `asf/**/*.py` that opens an operator table, and `asf.cli.stamp` has
   exactly one caller under `asf/` outside `asf/groom/digest.py` — the dispatcher's
   `_stamp_tail`. Both are read off the tracked tree, so a nineteenth view cannot reintroduce
   either.
6. The round trip, §3.1: over a temp `ASF_HOME` and the tiny record `tests/test_views.py` already
   builds, each of the twenty commands in `header.TITLES` is run through `asf.cli.main` with
   stdout captured and `ASF_TABLES=md`; its output opens with exactly
   `header.head(key, <product>, …)`'s prefix — the title taken from the dict, never retyped — and
   its last line matches `^— generated by asf <key>@[0-9a-f]+ \d\d:\d\d$` (or `@<version>` for
   the keys in `STAMP_VERSION`). Under `--json`, every `TITLES` command whose parser carries the
   flag (PD9, derived from `build_parser()` and not a count) prints parseable JSON on stdout and
   neither line.
7. `tests/test_plugin.py`: the per-skill assertions the file already makes — exactly three
   frontmatter keys, `allowed-tools: Bash`, a body running `"$ASF_BIN" <name> $ARGUMENTS`, and no
   name matching `tools/forbidden-names.txt` — now cover fifteen skills, and `plugin.json` and
   `marketplace.json` name all fifteen.
