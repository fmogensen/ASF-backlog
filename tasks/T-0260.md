## Description
stories: S-19906
writes: asf/groom/groom.py, tests/test_groom.py
after: Task 1, Task 4, Task 5

§2.8: the applier's fourth arm. Every write goes through `_write_card` (`asf/groom/groom.py:160-171`),
so each card gets its typed field and one History line in one place and `rec['meta']` is updated in
memory for the rest of the run. Nothing is closed, removed or deleted (§1.3): the loser keeps its
state, its children and its backlinks, and only the rule run and tomorrow's pass treat it
differently.

**Files**

- `asf/groom/groom.py` — `apply_conflict`; the `conflicts.CONFLICT_RE` arm in
  `apply_groom_answers` (`:311`, after `_attribution` and before the `PROPOSAL_RE` arm); the
  `append_section_lines` import beside `append_history_lines` (`:11`)
- `tests/test_groom.py` — `ConflictApplyTests`, `ConflictIdempotencyTests`

**Steps**

1. The dispatch arm, immediately after `raw_answer, who, by = _attribution(...)` (`:311`) and
   before the `PROPOSAL_RE` arm, so a conflicts line never reaches `_parse_answer`: match
   `conflicts.CONFLICT_RE` on the line and `conflicts.CONFLICT_ANSWER_RE` on
   `split_why(raw_answer)[0]` (PD8), build the three-line `emit` closure over
   `(sections or {}).get(iid, '')` and `by` the way the proposal arm does (PD9), call
   `apply_conflict`, `continue`.
2. `apply_conflict(canonical, a, b, answer, date, who, emit=None)`, returning the number of cards
   written. It splits the why off its own answer (`apply_proposal:232` does the same) and reads the
   pair's survivor from `conflicts.precedence`, never from the answer — the line printed the
   survivor before it was answered.
3. `keep A` / `keep B`: the loser gains `superseded_by: <survivor>`, the survivor gains the loser in
   `supersedes:` (a sorted list, de-duplicated — the pair `asf check` demands after Task 2), one
   History line each in the grammar every other groom answer writes:
   `- <date> groom: superseded_by → D-0042 (operator)` and
   `- <date> groom: supersedes → D-0042, R-0007 (operator)`.
4. `both`: both cards gain `decline_key(a, b)` in `conflict_declined:`, one History line each
   (`- <date> groom: conflict declined D-0042+R-0007 (operator)`), and no supersession field. This
   is `apply_proposal`'s `reshape_declined` suppression copied field for field (`:249-262`), so the
   pair is never proposed again and the state survives a record re-clone.
5. `merge`: `keep <the precedence winner>`, and first the survivor's `## Source` gains every source
   line of the loser's it does not already carry and its `## History` gains the loser's History
   lines each suffixed `(from <loser>)`, both through Task 4's `append_section_lines` in one
   read-modify-write of the body before `_write_card` re-reads it for the typed field. One History
   line: `- <date> groom: merged R-0007's source and history, superseded_by → D-0042 (operator)`.
   Where the survivor has no `## Source` the body comes back unchanged and the supersession still
   lands (PD10).
6. Anything else, including a blank slot, writes nothing and returns 0. `unanswered` (`:84`) already
   answers for the blank and the `____` and the spoken-for cases; an answered-but-unrecognized word
   on a conflicts line is named by `_skipped` (`:268`) and not applied.
7. The two refusals, each one printed line and no write, in `merge_tasks`' own shape (`:211`):
   `groom: keep A D-0042+R-0007 skipped — R-0007 is already superseded by D-0051`, and
   `groom: keep B D-0042+R-0007 skipped — D-0042 would close a supersession cycle through R-0007`.
   The second is decided by `conflicts.cycles(supersession_edges(canonical) | {(loser, survivor)})`
   — refused where it is written, rather than caught by the next `asf check`.
8. Idempotence, which `--apply` requires of every answer: `keep`/`merge` return 0 when the loser
   already carries that `superseded_by` and the survivor already lists it; `both` returns 0 when
   both cards already carry the key; `merge` copies only source and History lines the survivor
