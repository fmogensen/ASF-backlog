**Steps**

1. Create `tests/test_work_item_model.py` with `class ParentRules`. No production file is
   touched: all four rules already fire with the right message and the live record violates none
   of them (D-0012; P1 and P5 R1–R4, both re-measured at `2dac706fa`). This Task pins behaviour, and
   it is what makes the other six safe to build on.
2. Give the module one card-writing helper and one case runner, built from the spec's
   `## Acceptance tests` → "today's check, case by case" script, which is this module's fixture:
   a scratch record of the seven item folders, a `card(root, iid, type_, title, parent, typed)`
   writing frontmatter plus the `# ---- machine ----` block, and `record_findings(root,
   layout=False)` read for its findings. Keep `index.json`/`stale` findings filtered out of the
   assertion as that script does — the scratch record has no index. The other six Tasks extend
   this module, so put the helpers where they can reuse them.
3. Six cases, one per rule, each asserting the one finding, its message, and the card and line it
   is reported at: an Epic with `parent: E-1000` → `epic must not have a parent`, at its `parent`
   line; a Feature under a Feature → `parent F-1000 has wrong type feature`; a Story under an
   Epic → `parent E-1000 has wrong type epic`; a Task under an Epic → the same message; a Feature
   with no parent → `feature is missing a parent`, at its **`id`** line (`check.py:296` reports it
   there, not on a `parent` line it has not got); a Story whose `parent` names an id the record
   does not hold → `parent <id> does not exist`.
4. Two clean cases, so a rule firing on the wrong card fails the test: a Task under a Story and a
   Task under a Feature are both clean, and a record whose parents are all correct has no parent
   finding at all.
5. Each case asserts the record is *otherwise* clean — the one finding and nothing else — and the
   allowed parent types each case relies on are read from `core.PARENT_TYPES` and
   `core.NO_PARENT_TYPES`, never respelled in the test (the Story's last line). Both are **sets**
   on the trunk, not lists, so compare as sets or sort.
6. `must not have a parent` is asserted by no module in the tree today, and the one wrong-type
   case that exists is written at the Story (`tests/test_backlog.py:942`), so the Epic's rule is
   unheld and the Feature's and the Task's ride on a case that never names them (P2). Do not
   touch `tests/test_backlog.py` or `tests/test_check_staged.py`: their cases stay exactly as
   they are, and this module is the per-rule cover beside them.
