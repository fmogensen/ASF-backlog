The spec's design §5: the only surfaces a person touches. Half of this Story is a proof about where
the key is **not** — a product file carrying the App must load under the oldest pinned reader,
which is the whole reason the declaration is a convention and not a top-level key (`D1`, `P5`) —
and that half is already measured green before a line is written (`PD10`). The other half is one
`asf doctor` row, which is this feature's entire operator interface: there is no new `asf` command
(`D10`) and no new `config.yaml` key (`D12`).

**Read this Task from `docs/plans/f-0333.md`, not from this card.** The record cuts a Task card's
description at 4000 characters (`PD16`), so the card stops inside the Steps and neither the
**Gate** nor the **Acceptance** below reaches it; the card's `links.plan` is this file. Three
decision rows bind this Task and are on no card: `PD9` (`app_id` parses as an **int** — a
`isinstance(v, str)` check refuses the natural product file, measured), `PD10` (`D1` measured both
ways, including the pinned loader's `rc 0` and the top-level key's `ConfigError`) and `PD11`
(`token_path` must not make a directory — the row reads paths, it does not create them).

**Files**

- `asf/conventions.py` — one block in `validate_mapping` (`:580-666`), beside the `auth_env` block
  it sits next to in the product file (`:656-666`, whose shape it should mirror): `github_app` must
  be a map; `app_id` a **non-empty scalar** (`PD9` — an `int` is the normal case, so test for
  emptiness and not for `str`); `key_file` a non-empty string; `installation_id`, when set, a
  positive integer that is not a `bool`. The docstring's list of checked keys (`:582-586`) goes
  from fifteen to sixteen. **Nothing** is added to `env.PRODUCT_FIELDS` (`asf/env.py:569-575`) or
  `env.NESTED_FIELDS` (`:613-617`) — `D1`, `P5`, and the ruling at `asf/env.py:577-579`.
- `docs/products.example.yaml` — a commented `github_app:` block under `conventions:`, beside
  `auth_env` (`:309-315`), naming the five repository permissions an installation needs: contents,
  pull requests, checks, actions and metadata — read/write but for metadata.
- `asf/doctor.py` — one row, `github identity`, appended after `worker secrets` (`:1710-1711`).
  `not configured` and a **skip** with no App — the existing idiom is
  `return None, f'{NOT_CONFIGURED}: …'` (`:266`, and `:321`/`:444` for its shape); red when the key
  file is missing or unreadable, or the meta file's last mint recorded an `error`, or the cached
  token expired; green naming the app id, the installation id and the expiry, and — when the App
  shadows a declared `conventions.auth_env.GH_TOKEN` — the file that is no longer read (`D4`).
  Never the token, and never a line of the key (`D11`).
- `docs/guide/product-config.md` and `docs/guide/operating.md` — how an operator creates the App,
  which permissions to give it, where to save the key, and that the factory's quota is then the
  App's and no longer theirs. Keep every example generic: `check_generic.sh` refuses a product,
  company or person name anywhere in this repo, and a machine path is refused by the brief's own
  standing rule — use the example file's `acme/sample` and `~/.ASF/secrets/`.
- `tests/test_conventions.py` — the five shape cases and the checked-keys list.
- `tests/test_env.py` — the `github_app` block added to the `PLANNED_PRODUCT` fixture, which is
  what makes the existing `PinnedReader` (`:859`) and `TestExampleConfigsParse` (`:13`) cover it.
- `tests/test_doctor.py` — the new class `GitHubIdentityRow`, for the row's seven lines.
