## Description
stories: S-36450

after: none

The spec's `## The design` §2 in full, and nothing else. After this lands, one function can answer
*what is this job's limit* — its declared `timeout-minutes`, else the host's own 360 — for every job
of every workflow on the product's trunk, read once with the product's own login. Nothing calls it
yet; Task 2 is its only caller.

Read **PD5 first.** The parser is `parse_runs_on`'s loop plus one variable, and the variable is the
whole point: without it a step's `timeout-minutes` becomes the job's on the commonest workflow
shape there is. Read **PD12** before the test: `GitHubBackend.runs_on()` has no test today, so the
new one is the only net under the `_workflow_texts` refactor and must drive `runs_on()` through the
same fake.

**Files**

- `asf/ci_pool.py` — `DEFAULT_JOB_TIMEOUT_MIN = 360` with the spec's two-line comment; a new
  `parse_timeouts(text)` beside `parse_runs_on`; `Backend.timeouts()` as the third read-only stub
  and the one-sentence docstring change to the class's own (PD13); `GitHubBackend._workflow_texts()`
  carrying the walk and the `no repo_slug` guard out of `runs_on`; `GitHubBackend.runs_on()`
  rewritten as the four lines the spec prints; `GitHubBackend.timeouts()` with the
  larger-limit-wins comment.
- `tests/test_ci_pool.py` — a new `JobTimeouts(unittest.TestCase)` beside `RunsOnParser`.

**Steps**

1. `DEFAULT_JOB_TIMEOUT_MIN = 360` next to `FAIL` and `GH_TIMEOUT_S` (`asf/ci_pool.py:67-68`), with
   the spec's comment: the host's own limit, named by the annotation on a job that hit it, and a job
   always has a limit — the workflow only chooses whether to say so.
2. `parse_timeouts(text)` → `{job or display name: minutes}`, the spec's docstring verbatim. The
   loop is `parse_runs_on`'s (`:563-585`) — `_strip_comment`, the `indent == 0` / `jobs:` reset, the
   `^([A-Za-z0-9_.-]+|"[^"]+"|'[^']+'):(\s|$)` job-key match at `indent == job_indent` — plus
   **PD5's `key_indent`**: reset it to `None` on entering a job, set it from the first non-blank line
   at `indent > job_indent`, and read `timeout-minutes:` and `name:` only at `indent == key_indent`.
   A value that is not a base-10 integer, or that contains `${{`, is skipped. A job that declares
   none is **absent** from the map — the default is not this parser's to invent. A declared `name:`
   maps to the same minutes as the key, so both spellings are lookups (P3).
3. `Backend.timeouts()` as a `NotImplementedError` stub with the spec's two-line docstring, after
   `runs_on`, and the class docstring's list of the read-only half gains it (PD13). `FakeBackend` in
   the suite is **not** touched: `timeouts` has no caller in `drift`, `plan`, `check_trials` or the
   tick, so nothing reaches the stub.
4. `GitHubBackend._workflow_texts()` → `[(basename, text)]`: the `if not self.slug: raise
   BackendError('the product has no repo_slug')` guard, the `main = getattr(self.product, 'main',
   'main')` line, the contents listing, the `.yml`/`.yaml` filter and the raw fetch — moved out of
   `runs_on` byte for byte, not rewritten. `runs_on()` becomes the spec's four lines over it.
5. `GitHubBackend.timeouts()` over the same walk, merging each file's `parse_timeouts` with
   `out[job] = max(minutes, out.get(job, 0))` and the spec's comment on why the larger limit wins.
6. `JobTimeouts(unittest.TestCase)`: `parse_timeouts` over the eight shapes the Acceptance names,
   `DEFAULT_JOB_TIMEOUT_MIN == 360`, this repo's own `.github/workflows/tests.yml` read from disk
   (it declares none, so the map is empty), and `GitHubBackend` against a fake `run` — the
   `tests/test_ci_phantom.py:219` pattern, an object with `returncode` and `stdout` — asserting the
   merged map, the collision rule, **`runs_on()` through the same fake** (PD12) and `BackendError`
   on a product with no `repo_slug`.
