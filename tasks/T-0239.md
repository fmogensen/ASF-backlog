## Description

§2.6 and §2.7 as declarations only: every policy number the feeder and the tick read becomes a
field with one documented default, and `stage_limits` becomes one shaped block with one grammar,
one key set, one reader and one doctor finding. Nothing reads any of them yet — Tasks 3, 4, 6 and
7 are the readers. `forbidden_patterns()` is unchanged (§2.6): these are numbers, and the guard
against a second copy of them is a unit test, not a grep (D13).

**Files**

- `asf/conventions.py` — `DEFAULT_DECISION_ROWS`, `DEFAULT_ATTEMPT_LIMIT`,
  `DEFAULT_STALEMATE_ROUND`, `DEFAULT_CORRECTION_ROUNDS`, `DEFAULT_MAX_SPECS_IN_FLIGHT`,
  `DEFAULT_CI_REFUSAL_WINDOW_H`, `DEFAULT_CHECK_FAILURE_RUNS`, `DEFAULT_READ_TIMEOUT_S`,
  `DEFAULT_STAGE_LIMITS`, `STAGE_LIMIT_INT_UNITS`; the eight fields plus `read_timeout_s`; the
  `GIT_KEYS` and `FEEDER_KEYS` rows; `Conventions.stage_limit`; `validate_mapping`'s
  `stage_limits` row; the module docstring's `conventions:` example
- `asf/doctor.py` — `stage_limit_findings(product)`, appended to the `conventions` row
- `docs/config.example.yaml`, `docs/products.example.yaml` — the new keys beside their neighbours
- `tests/test_conventions.py` — `FeederPolicyFieldTests`, `StageLimitTests`
- `tests/test_doctor.py` — `ConventionsRowTests`

**Steps**

1. Eight `DEFAULT_*` constants — 5, 3, 4, 3, 2, 24, 3, 120 — each with the `#:` line §2.6's table
   gives, naming *what reads it*, not that it is a number.
2. Eight fields on `Conventions` beside `prs_per_tick` (`asf/conventions.py:469`):
   `decision_rows`, `attempt_limit`, `stalemate_round`, `correction_rounds`,
   `max_specs_in_flight`, `ci_refusal_window_h`, `check_failure_runs`, each `int`, each
   defaulting to its constant. `max_specs_in_flight` is read out of the `feeder:` block, which
   `validate_mapping` already shapes (`:394`): it joins the block's key map the way
   `push_timeout_s` joins `GIT_KEYS`, so `feeder: {max_specs_in_flight: 4}` resolves to the field
   and the block keeps its shape finding.
3. `read_timeout_s: int = DEFAULT_READ_TIMEOUT_S` beside `push_timeout_s` (`:483`), and
   `'read_timeout_s': 'read_timeout_s'` in `GIT_KEYS` (`:162`) — PD16.
4. `DEFAULT_STAGE_LIMITS` exactly as §2.7 prints it, fifteen keys, and `STAGE_LIMIT_INT_UNITS`
   its three. The eleven durations are `stale.DEFAULT_LIMITS`' present values byte for byte; the
   four new ones are the other readers' own defaults (PD14).
5. `Conventions.stage_limit(key)` → seconds: the product's `stage_limits` entry for `key` when it
   has one, else `DEFAULT_STAGE_LIMITS`' — merged per key, in `savings_for`'s shape (PD9).
   A duration string goes through the module's own `duration_seconds` (`:308`); an integer under a
   key in `STAGE_LIMIT_INT_UNITS` is that many of its unit; an integer anywhere else, and anything
   that parses as neither, is the default (and a `validate_mapping` problem, step 7). A `key` not
   in `DEFAULT_STAGE_LIMITS` raises `KeyError` — a reader asking for a limit that does not exist is
   a bug in the reader, not a product's misconfiguration.
6. Resolution order, one line, copying `asf/env.py:697`'s: `env.Product.conventions` already
   does `data.setdefault('stage_limits', self._get('stage_limits'))`, so a `conventions:` key of
   the same name already wins and the top-level block is already honoured — D11 needs no new code,
   and Task 1 asserts it rather than writing it. Nothing about `env.Product.stage_limits` changes
   (§1.3).
7. `validate_mapping` gains a `stage_limits` row, after `feeder`'s: not a map → one problem naming
   the key; a value that is neither a duration nor a permitted integer → one problem per key
   naming the key and the value; a key not in `DEFAULT_STAGE_LIMITS` → one problem worded as
   `asf/doctor.py:580`'s is, `stage_limits.tsak_active is not a known limit`.
