which names no documentation. It is here because Tasks 1 and 2 leave three shipped guide statements
**false** and one materially incomplete, and because the spec already rewrites the same fact in the
`asf/tick/steps.py` docstring — this is that sentence's operator-facing copy. The `NEEDS OPERATOR`
line at the foot of this plan offers to strike this Task; coverage survives without it, because both
Stories are on Tasks 1 and 2. If it is struck, nothing else changes.

It is `after: Task 1, Task 2` because it describes the finished state of both: the paragraph that
tells an operator they may now leave `batch:` out is the same paragraph that must send them to
`conventions.landing` first, and neither half is true until both Tasks have landed.

**Files**

- `docs/guide/product-config.md` — four edits and no others.
  (a) `:262-267`, the refusal paragraph: `batch` stops being *"the one ASF has no implementation
  for"* whose absence *"is a refusal"*. It becomes: an absent `batch` is `off`; `batch: asf` is
  still refused, because `asf` for a step ASF cannot run is a request for something that does not
  exist; and the refusal still exits 2 before anything runs, for that spelling. Keep the exact
  refusal line as it is quoted — it has not changed (PD4).
  (b) `:287-300`, *"The batch step"*: *"most products declare `batch: off`"* becomes *most products
  leave it out*, with `off` kept as the valid, tested spelling for *"another job still runs it"*
  (`asf/tick/steps.py:10`, and D7's reason the shipped yamls keep it). The closing sentence,
  *"Declaring `batch` as a command also switches the default landing to `pull-request`"*, gains what
  Task 2 built: with `conventions.landing` unset that inference is what `asf doctor`'s `landing`
  row goes **red** about, because deleting the line would move the product to `fast-forward`.
  (c) `:150-151`, the landing-inference paragraph: still true (D3), and it gains the same sentence —
  declare `conventions.landing` and the inference never applies. This is the paragraph an operator
  reads when choosing a landing mode, and it currently invites them to leave it unset.
  (d) Nothing else. Do not touch `:252` — PD11.
- `docs/guide/troubleshooting.md` — one edit. `:158-159`, *"A step has no owner."*: *"typically
  `batch`. Add `batch: off` (or its command) under `steps:`"* becomes the surviving case — `batch:
  asf`, which asks for an implementation that does not exist; remove the line to leave the step off,
  or give it a command. It must no longer tell an operator to write the `off` this card exists to
  make unnecessary.

  and the landing paragraph names `conventions.landing` together with the doctor row. Assert on
  short needles, as the existing classes do — three or four words, never a whole sentence — so the
  guide can be reworded without a red test.
