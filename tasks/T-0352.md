reason this waits on it.

**Files**

- `asf/metrics/metrics.py` — the `sessions` schema's `progress` key; `session_event`'s one field
- `docs/products.example.yaml` — `stage_limits.progress_min`, documented
- `sample/product.yaml` — a `stage_limits:` block carrying `progress_min` (PD11)
- `tests/test_metrics.py` — `SessionProgressClassTests`

**Steps**

1. `SCHEMAS['sessions']` (`asf/metrics/metrics.py:124-133`) gains `'progress': (('str', 'null'),
   None)` with §2.7's comment. Nullable with a declared default, so every row already on disk still
   loads and every writer that does not set it still validates (P11): `_apply` fills the default
   and rejects only *unknown* keys.
2. `session_event` (`:1522-1529`) gains `'progress': record.get('progress') or None` to the `ev`
   dict. The class the run was judged at is copied off the registry record and never recomputed
   from the progress file, which is a ring that may have rolled (D13). A run that ended before its
   first judgement carries `null`.
3. `docs/products.example.yaml`: `progress_min: 20m` in `stage_limits:` (`:314-325`), with the
   comment that says what it measures and that `0` turns the row off — read by the same duration
   grammar `silent_min` uses, so an int is minutes and `20m`/`1h` work too.
4. `sample/product.yaml`: a new `stage_limits:` block carrying `progress_min: 20m` and nothing else
   (PD11 — the file has no such block today, and the sample product restates none of the example's
   other defaults).
5. `SessionProgressClassTests`: `session_event` copies `progress` off the registry record; a record
   with no `progress` gives `None`; `validate('sessions', …)` accepts the key, fills `None` when it
   is absent, and still rejects an unknown one; and a `sessions` row written without it loads with
   `None` — the card's third acceptance, one session at a time.
