## Description
stories: S-31204

after: Task 3, Task 4

§2.5: the three new keys, the one section that carries the card's four items, and the trim rule that
keeps the last report on a relaunch (D10). This is the Task that makes the block appear; the two
before it only made its facts available. A first-launch brief is byte-identical to today's.

**Files**

- `asf/briefs/preamble.py` — `REPO_FACT_KEYS` (nine), `collect` (three keys), `relaunch_lines`, the
  `Section('relaunch', …)` in `build`, `trimmable=not facts['relaunch']` on `last_report`
- `asf/briefs/facts.py` — `repo_facts` fills `commits`, `progress`, `relaunch` and passes `review=`
- `tests/test_brief_facts.py` — `ContractTests` at nine keys
- `tests/test_briefs.py` — `RelaunchBlockTests`

**Steps**

1. `REPO_FACT_KEYS` becomes
   `('head', 'branch_exists', 'files', 'tests', 'last_report', 'outlines', 'commits', 'progress', 'relaunch')`.
2. `collect` carries the three, in §2.5's exact form:

   ```python
   'commits': dict((repo_facts or {}).get('commits') or {}),
   'progress': (repo_facts or {}).get('progress') or '',
   'relaunch': dict((repo_facts or {}).get('relaunch') or {}),
   ```
3. `facts.repo_facts` fills them: `relaunch = predecessor(product, row.item_id, plain['branch'],
   getattr(row, 'kind', ''))` (PD6); `progress = last_progress(relaunch_run['log'])` only when there
   is one, so a first launch pays neither read; `commits = commits_on(repo, rev, main)` whenever
   `rev` is truthy (PD5 — the trunk fallback yields zero by construction). When `relaunch` is
   non-empty, compute the `branch_review` triple and pass it as `review=` to `last_report` (PD8).
   All nine keys are present on every return, including the no-repo path, or `ContractTests` fails.
4. `relaunch_lines(facts, main)` renders §2.5's block, and its text is that block byte for byte:

   ```
   This item has run before: <job> ended <ended> — <end_reason> (attempt <n>).
   Its work is on `<branch>` and is yours to continue. <total> commits above origin/<main>, newest first:
   - <short sha> <subject>
   (<k> more — `git log --oneline origin/<main>..origin/<branch>`)
   Where it stopped: <progress>
   Your worktree was rebased onto origin/<main> before you started, so its shas are not the ones
   above; the subjects are. Continue from that head: never recut the branch, never open another,
   never redo what those subjects already did — read them first and pick up after the last one.
   Commit and push within fifteen minutes, then keep pushing: what is not on origin is what the
   next relaunch loses.
   ```

   The `(<k> more …)` line appears only when `commits['total'] > len(commits['lines'])`, with `k`
   the difference. `Where it stopped:` is dropped when `progress` is empty.
5. The `commits['total'] == 0` branch (D15): the commit list, the `(<k> more …)` line and the whole
   rebase-and-never-redo paragraph are replaced by the one line

   ```
   Nothing was pushed: the previous run left no commit on the branch, so there is nothing to continue from — start the work, and commit and push within fifteen minutes so this does not repeat.
   ```

   The two lead lines above it keep their wording except that `<total> commits above …, newest first:`
   is not printed.
6. In `build`, insert `Section('relaunch', '### The branch already holds your work',
   relaunch_lines(facts, main) if facts['relaunch'] else [])` between `state` and `conventions`
   (PD15: the name is absent from `TRIM_ORDER`, so it is never cut), and change the `last_report`
   section to `trimmable=not facts['relaunch']`. `TRIM_ORDER` itself is untouched.
7. `RelaunchBlockTests`: a relaunch brief carries the `Head:` line (C1), the commit list with its
   subjects and its cut count (C2), the `### The last report for this item` section (C3), the
   `Where it stopped:` line (C4) and the instruction — `never recut`, `never redo`, `fifteen minutes`
   —
