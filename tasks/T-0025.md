## Description

**Files**

- `asf/doctor.py` — `check_redaction_hooks`, one row in `run`
- `tests/test_install.py`, `tests/test_doctor.py`

**Steps**

1. `asf/hooks.py` gains the git-hook half: the two hook names, `git_hooks_dir(repo)` from
   `git rev-parse --git-path hooks` in that repo (so `core.hooksPath` is honoured and every
   worktree of the repo shares the hooks), the hook body, an "is it ours" test, and
   `ensure_git_hooks(product)`.
2. The body is §2.4's, and it is four lines — shebang, the comment naming the command and the
   Feature, and `exec "<absolute asf>" redact --pre-commit --product <p>` (the `pre-push` file
   `exec`s `redact --pre-push`, which gets git's stdin through `exec`). It does **not** unset
   `GIT_DIR`, `GIT_WORK_TREE` or `GIT_INDEX_FILE` (D12): those three name the very repo and index
   being committed, and a scanner that cleared `GIT_INDEX_FILE` would scan the wrong index — and
   clear the real one — under `git commit --only <path>`.
3. `ensure_git_hooks(product)` runs over each of `product.repo_dir` and `product.backlog_dir`
   (when set). A hook whose file contains `asf redact --pre-commit` (resp. `--pre-push`) or
   `asf.redact --pre-commit` (resp. `--pre-push`), in any form, is *installed* and is left alone.
   Absent → written, mode 0755. Present and not installed → **not touched**; the caller gets
   `NEEDS OPERATOR: <path> is not asf's — add the line: "<asf>" redact --pre-push --product <p>`.
   Running it twice changes nothing.
4. `install(product, …)` calls `ensure_git_hooks` **before** the `'hooks: 0 rules declare a hook'`
   early return (P2), folds both results into the message it returns, and exits 2 on a foreign
   hook with that `NEEDS OPERATOR` line.
5. `asf/doctor.py`: `check_redaction_hooks(product)` → `(ok, detail)` — ok with
   `pre-commit, pre-push in <n> repos`; not ok naming each missing or foreign hook and the command
   `asf hooks install --product <p>`. `run` appends `('redaction-hooks', True, ok, detail)`
   alongside the others.
6. `tests/test_install.py` gains `GitHookTests` and `tests/test_doctor.py` gains
   `RedactionHooksTests`, per §3.4. The two worktree tests run a **real** `git commit` and
   `git push` (to a bare temporary origin) in a worktree added off a repo where `install` ran, and
   assert the refusal and an unchanged origin.
   `test_a_commit_only_path_is_scanned_against_the_index_git_is_committing` runs a real
   `git commit --only <clean path>` in a repo whose working tree holds an unstaged secret
   elsewhere, and asserts the commit is allowed (the temporary index is what was scanned) and that
   the same secret staged into that path is refused (D12).
