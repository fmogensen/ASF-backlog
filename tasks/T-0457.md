## Description
stories: S-32357
writes: tools/upgrade_matrix.py, .github/workflows/tests.yml, tests/test_upgrade_matrix.py
after: Task 4, Task 5

The spec's §6: a standard-library script that runs beside two different installs and therefore may
not import `asf`, a computed tag selection that stays right as tags accumulate (D6), and a job inside
`tests.yml` rather than a second workflow — because a second workflow on `push: main` becomes
`runs[0]` half the time and turns the release gate's `install_from_zero` and `generic` "absent" for
a reason that is not true (P13, D5). Sixty-five releases have been cut and nothing has ever installed
one; this is the Task that makes "does v0.1.7 → HEAD still work" a question CI answers.

**Files**

- `tools/upgrade_matrix.py` — new; `--plan`, `--tag`, `--mixed`, `KEEP_RECENT`, `PINNED`, the fixture
  builder, the leg and the mixed leg
- `.github/workflows/tests.yml` — the `plan` job (PD9) and the `upgrade-matrix` job
- `tests/test_upgrade_matrix.py` — new; `PlanTests`, `MixedVersionTests`

**Steps**

1. `tools/upgrade_matrix.py`: Python 3 standard library only, no import of `asf` — it must run beside
   two different installs, and one of them is the *old* package, which cannot import HEAD's test
   helpers (D-out names the duplication with `tests/test_sample_product.py` and bounds it to the
   fixture). It is never named inside any `asf/**/*.py` (P20: `tools/[A-Za-z0-9_-]+\.(py|sh|json)` is
   forbidden there); a workflow yaml may name it, and does.
2. `--plan` (D6): read `git tag`, keep the oldest and newest of every `major.minor` line, both sides
   of every tag at which `<tag>:asf/schema.py`'s `SCHEMA_VERSION` or `CONFIG_VERSION` changed —
   a name absent from that file reads as `0` (PD10) — the newest `KEEP_RECENT = 3`, and everything in
   `PINNED` (a hand list: a tag known to have broken something goes in and never drops out). Sorted
   oldest first, de-duplicated, printed as a JSON list for `fromJSON()`.
3. One leg (`--tag <tag>`), all under one temp `HOME` and one temp `ASF_HOME`, following P17's shape
   but built by the script:
   1. `git archive <tag> sample | tar -x` — the tag's own fixture (D7), because the point of the leg
      is what that release's users had on disk. No `sample/config.yaml` in the archive:
      `skipped: <tag> carries no sample/`, exit 0, counted in the summary — never silently.
   2. bare origins for `sample/repo` and `sample/backlog`, `@REPO@`/`@BACKLOG@`/`@SAMPLE@` filled in
      from the tag's `config.yaml` and `product.yaml`, and a PATH whose `gh` is an offline stub that
      exits 1 — so every probe answers at once instead of asking the network.
   3. `python -m venv old && old/bin/pip install git+file://$PWD@<tag>` (D8: pipx is one install per
      machine, and the mixed leg needs two versions at once; the pipx path itself is already covered
      by `tests.yml`'s `install with pipx` step).
   4. `old/bin/asf init --product sample` then `old/bin/asf tick --product sample`; both must exit 0.
      A tag that cannot do either is a **failure**, not a skip — that is a release nobody could run.
   5. `new/bin/asf upgrade --skip-pipx` from HEAD's venv, built once and reused across legs; the
      table is recorded before and after.
   6. `new/bin/asf tick --product sample` — the assertion of the card's first acceptance: the tick
      migrates itself.
   7. Assert: that tick exited 0; `new/bin/asf doctor --product sample` exits 0; `index.json`'s
      `schema_version` equals HEAD's `SCHEMA_VERSION`; and, when a migration was due, the tick's
      output carried `migrate: schema a → b` and the record clone carries that commit.
4. `--mixed <tag>`: one `config.yaml` with `default_product: sample`, two products `sample` and
   `sample2` (a copy with origins of its own), the old venv ticking `sample2` and HEAD ticking
   `sample`, each after the other. Assert both doctors exit 0 and neither `config.yaml` load raises —
   the version-skew case the card names as gap 3, and t
