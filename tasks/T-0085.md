**Files**

  `NEEDS OPERATOR` line.

**Steps**

1. `TRUNK_SCAN = 2000` and `_ITEM_TOKEN = re.compile(r'(?<![\w-])([EFSTBDR]-\d{4})(?![\w])', re.I)`
   at module scope, with the comment §2.1 fences. `re` is already imported.
2. `trunk_items(product, limit=None)` with §2.1's docstring verbatim. `limit` falls back to
   `conventions.trunk_scan` through `Conventions.get`, then to `TRUNK_SCAN` — read once, at this
   one call site, never spelled again (P9, and §3.7's reason for naming `check_conventions.sh`).
   It runs `git fetch -q origin <main>` itself and then
   `git log -n<limit> --no-merges --format=%H %s origin/<main>`, walks newest-first and keeps the
   first sha per id, so the newest commit wins.
3. It fails open and silent: no `repo_dir`, a fetch that fails, a `git log` that returns non-zero
   → `{}`, no raise. Say why in the docstring — an absent fact must leave the gate exactly as it
   is today, which is the only safe direction for a check that suppresses work.
4. `plan_inputs` grows `'landed_shas': trunk_items(product)`, exactly as §2.1 fences it. Its three
   callers (`step_wave.run`, `feeder/render.cmd_next`, `views/status.py`) spread it into
   `plan_rows` and need no edit — Task 1 made the keyword legal (P6).
5. `health.empty_cap(product)` over `product.conventions.get('empty_cap')`, falling back to
   `lifecycle.EMPTY_CAP` when it is absent or not a positive int — the shape `feeder.rows.attempt_limit`
   already has.
6. The empty-branch arm of `health()` (`health.py:314-320`) passes `lifecycle.EMPTY` in place of
   `lifecycle.UNPUSHED` and `empty_cap=empty_cap(product)`, and appends
   `(job, 'parked' if fields['correction'].get('parked') else 'held', line.split(': ', 1)[1])`.
   The hold is written where it already is — at the moment the run is ended — so it happens once
   however many ticks later see the park. The `not pushed` arm above it is untouched.
7. `step_health.run` walks `found` for `what == 'parked'` and raises, per park,
   `ctx.event('parked', item=…, job=job, kind_of_hold='empty', reason=detail)` — **not**
   `kind='empty'` (P7) — and prints the one `NEEDS OPERATOR` line naming the item and the reason.
   `dead_jobs` filters on `what == 'ended'` and is unaffected by the new verb.
8. `TrunkItemsTests` against a real git fixture (`tests/gitfixture.py`, a `Template` as this module
   already builds them), covering every case §3.1 names, and the `plan_inputs` key.
9. `TestEmptyPark` in `tests/test_workers.py`, in `TestHealth`'s idiom: `feature_row` gives both
   spawns the same item (`F-0001`, P11), each pushes an empty branch, `health()` runs after each.
10. `ParkedEventTests` in `tests/test_tick_steps.py`: the health step twice over the parked ledger
    → exactly one `parked` line in `metrics/events/<day>.jsonl` and one `NEEDS OPERATOR` line;
    the wave step on both ticks → the `PARKED` waits line both times.

    classes: a class
