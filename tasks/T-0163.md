## Description
stories: S-17403, S-17408
writes: asf/metrics/metrics.py, tests/test_metrics.py
after: Task 1, Task 5

§2.8. Two new sections and one waste row, all three rendered from what the rollup already reads: the
streams for the window, and `items` — `match.load_index(root)`, already `render_daily`'s third
argument, and an index entry carries every typed and machine field of its card (P2), so the savings
block costs no new read. Runs before Task 8 and carries its two Stories' own acceptance (PD15).

**Files**

- `asf/metrics/metrics.py` — `landed_table(...)` and `savings_block(...)` (new); `scorecard_rows`
  (`:452`) gains the `landing cost` row; `render_daily` (`:550`) reads the `landings` and `gates`
  streams for the same 7-day window it already reads the others for, and appends the two sections.
  The `asf.savings` import is **inside** `render_daily` (PD12).
- `tests/test_metrics.py` — `SavingsScorecardTests` (new, §3.6's third class); `Rollup:367` for the
  rendered sections.

**Steps**

1. `render_daily` reads `read_stream(root, 'landings', week)` and `read_stream(root, 'gates', week)`
   and builds `per_kind(landed_changes(...))` once, for all three renderings.
2. `## Cost per landed change (7 days)` after the cost table, in §2.8's exact column order —
   Kind, Landed, Sessions, Rounds, Minutes, Gate min, USD — one row per kind and a bold `all` row,
   each cell the median over that kind's landed changes and `—` where there is nothing.
3. The `landing cost` waste row: `<n> landed in 7 days — median <m> min, $<u>`, note
   `gate <g> min per landing (threshold <t>)`. `scorecard_rows` keeps its positional signature and
   appends the row, so every existing caller and test is unaffected.
4. `## Savings` from `items`: every entry whose `source:` starts `savings:`, as §2.8's table — Card,
   Class, Expected, Baseline → now, Target, Verdict. `now` is the card's own detector, looked up by
   its typed `measurement:` in `signals.DETECTORS` and re-read this run; a class the code no longer
   has reads `unmeasurable` rather than silently green (§1.4).
5. `verdict` is `open` while the card is open, and once it is closed `kept` when `now <= target` and
   `reverted` when it is not. A closed card is never re-opened by the rollup — the verdict is a
   reading, not a state change. No savings card at all renders `No savings card has been filed yet.`
6. `SavingsScorecardTests`: the landed-change table, the `landing cost` waste row and the savings
   block are all in the rendered page; a card closed with its reading under target renders `kept`
   and over target `reverted`; an open card renders `open`; a card whose `measurement:` names no
   detector renders `unmeasurable`; a record with no landing renders the table's header and `—`
   cells rather than failing.
