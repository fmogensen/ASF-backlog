§2.4.1: one regex, in one place, imported by both readers — and the two functions that build a
file name instead of matching one. Independent of every other Task: the widened name is correct
whether or not a clerk session ever writes one.

**Files**

- `asf/groom/groom.py` — `ANSWERS_FILE_RE` widened to §2.4.1's named-group form
  (`groom.py:616`); its one caller at `groom.py:699` reads `m.group('date')`.
- `asf/tick/step_daily.py` — `_ANSWERS_FILE_RE` deleted and `groom.ANSWERS_FILE_RE` imported
  (`step_daily.py:27`); `pending_answers_files` sorts on `(date, half or '')`
  (`step_daily.py:44-52`); `_newest_answers_file` returns the newest *file*
  (`step_daily.py:30-42`); `carry_staged_answers` stops rebuilding `f'{date}.answers'` and carries
  any basename in the ended session's worktree that matches (`step_daily.py:73-96`, P7).
- `asf/workers/lifecycle.py` — `NO_LANDING_KINDS = ('groom', 'groom-clerk')` (`lifecycle.py:465`,
  P8).
- `tests/test_groom.py` — `TwoAnswersFilesTests`.
- `tests/test_tick_steps.py` — `CarryClerkAnswersTests`.

**Steps**

1. `ANSWERS_FILE_RE = re.compile(r'^(?P<date>\d{4}-\d{2}-\d{2})(?:\.(?P<half>[a-z]+))?\.answers$')`
   with §2.4.1's docstring, in `asf/groom/groom.py` and nowhere else. `groom.py:699`'s
   `m.group(1)` becomes `m.group('date')`.
2. `step_daily` imports it. `pending_answers_files` returns every unapplied match, sorted on
   `(date, half or '')` so `<date>.answers` precedes `<date>.clerk.answers` and a day's two files
   apply in a stable order. An applied file is `.answers.done` and no longer matches, so nothing
   about "unapplied" changes.
3. `_newest_answers_file` returns the newest matching **path** off `os.listdir`, not
   `os.path.join(d, f'{date}.answers')` — with two files a day the rebuilt name is the wrong one
   half the time.
4. `carry_staged_answers`: for each ended run of a `NO_LANDING_KINDS` kind whose worktree is not
   live, list the worktree and carry every basename that `ANSWERS_FILE_RE` matches to the same
   basename in the state dir, keeping the existing two guards — a target the state dir already
   holds is left alone, and so is one whose `.done` twin is byte-identical. The `job.rsplit` date
   derivation goes away with the name it built (P7).
5. `NO_LANDING_KINDS` gains `'groom-clerk'` (P8).
6. `apply_groom_answers` is not touched: a clerk's line is in the same grammar.
7. `TwoAnswersFilesTests`: both files in the state dir; `pending_answers_files` returns both with
   `<date>.answers` first; `groom --apply` applies both in one run, renames both `.done`, and
   every answer lands on its card; `<date>.answers.done` and a malformed `<date>.answers.bak` are
   not picked up. `CarryClerkAnswersTests`: a `<date>.clerk.answers` left in an ended
   `groom-clerk-<date>` session's worktree is carried to the state dir, and a live session's
   worktree is not touched.
