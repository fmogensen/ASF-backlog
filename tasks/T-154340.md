**Steps**

1. `asf/record/index.py`: `refresh` (`:22`) learns to write the views. It already returns the
   relpaths it wrote (`:27`, `:33`, `:41`) and `publish.commit_paths` (`asf/record/publish.py:75`)
   already commits a card with everything its derivation implies, so adding each view's relpath to
   `written` is what carries it into the same record commit as the card. Regenerating the views of
   a record whose cards are unchanged must change no byte.
2. `## Children` and `## Backlinks` stop being card content: they are derived into the view only
   (D-0009). So `expected_body`'s rewrite of those sections applies to the view, and the whole
   `section is stale (run asf index)` finding class disappears for a JSON card rather than being
   ported.
3. `asf/record/check.py`: one new finding class, `view is stale (run asf index)` — a `.md` beside
   a `.json` whose bytes differ from `card.render` — in the shape `index.json is stale`
   (`check.INDEX_STALE`) already has. And remove the stale-children/backlinks finding for a JSON
   card, which Step 2 makes unreachable. Leave every other finding class alone, including the
   protected-name ones (§1.3).
4. `asf/cli.py`: `asf show <id>` — a new subcommand printing `card.render`'s text for a person at
   a terminal (§2.9). An unknown id says so and exits non-zero; an **invalid** card prints the
   schema error, not a traceback. Register it beside `asf check` (`:329`); resolve the record with
   `cli.resolve_record` like every other record command (K7).
5. Create `tools/check_card_readers.sh`, the second lint, in the same shape as
   `check_record_writers.sh`: refuse a card `.md` *read* outside `asf/record/card.py`, the
   migration, and `proves.bullets`' schema-1 fallback. This is what keeps D-0001's view from quietly
   becoming a parsed format again. It must pass on the tree as this Task leaves it and fail on a
   module that reads a card markdown file.
6. Create `tests/test_card_json.py` for S-133158's eighteen lines. Beyond the view and lint cases:
   a card id still equals its file name and its type still equals its folder; the prose sections
   survive a load and a write unchanged; and `history` is a list of lines where appending one
   appends exactly one entry.
