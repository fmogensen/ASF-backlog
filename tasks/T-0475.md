The spec's sixth and seventh **In** bullets and `## The design` §5 and §6. Two cells that only speak
when there is something to say (P21, P22), both folding the registry and nothing else. It needs
Task 3's `adopted_pr` marker and nothing above it; it is queued behind Tasks 4 and 5 only because all
three write `tests/test_adopt_pr.py` (PD4).

**Files**

- `asf/views/status.py` — `adopted_cell(product)` and its row between `Merge` and `Capacity`
- `asf/doctor.py` — `check_adopted(product)` and its conditional append in `run()`
- `tests/test_views.py` — the cell's cases
- `tests/test_doctor.py` — the row's cases and its absence
- `tests/test_adopt_pr.py` — `StatusAndDoctorTests`

**Steps**

1. `adopted_cell(product)` with the spec's docstring byte for byte (§5). It folds
   `lifecycle.by_branch(H.sessions_path(env.state_dir(product)))` and nothing else — no `gh`, no git,
   no record, because `asf status` is read in a terminal on a clock. **Open** is a run carrying
   `adopted_pr`, not landed (`lifecycle.landed`), whose lane state is neither `MERGED` nor `STALE`;
   **landed** is one carrying `adopted_pr` that is not open. `N open (M landed)` while any is open,
   `None` — no row at all — at zero (D11, P21). An unreadable or missing sessions file is `None` too,
   which the row list's own `except` already tolerates but which should not print a `?` row for a
   product that never adopted anything.
2. The row goes in `render`'s list between `('Merge', …)` and `('Capacity', …)` (`:479-510`), as
   `('Adopted', lambda: adopted_cell(product))`.
3. `check_adopted(product)` with the spec's docstring byte for byte (§6): `(ok, detail)` or `None`.
   `None` when the registry holds no `adopted_pr` run at all (D12) — a product that never adopted a
   PR has no old queue to retire. Otherwise `steps.batch` is read through `tick.steps.resolve(product,
   ['batch'])` (P23), and the three rows are §6's table byte for byte: open PRs with `batch` a command
   → `<k> of <n> adopted PRs still open — keep steps.batch (<command>) until it is 0`; none open with
   `batch` a command → `<n> adopted PRs, all landed — steps.batch can be retired: steps: {batch: off}
   in products/<p>.yaml`; none open with `batch` off or undeclared → `<n> adopted PRs, all landed —
   steps.batch is already off`. The counting is `adopted_cell`'s, shared rather than restated so the
   two rows cannot disagree.
4. `ok` is True in every case: this row never says the install is wrong, only what may now be turned
   off. It is appended in `run()` beside the other conditional rows (`:879-893`) as
   `('adopted', False, ok, detail)` — `required=False`, so it never turns the exit code red (P22).
5. Retiring the step is **not** done here: the doctor says it may go, the operator edits the product
   file (the Out section). No product yaml is written by this Task.
6. `tests/test_views.py`: the cell over a registry with three open adopted runs and two landed →
   `3 open (2 landed)`; with all five landed → `None`; with none adopted at all → `None`; with a
   `merge: auto` `PR-nnnn` adoption (an `adopted:` run with no `adopted_pr`) → `None`, PD2's
   separation asserted in the view too; with an adopted run whose lane is `STALE` → not counted open;
   a missing sessions file → `None`. One case renders the whole table and asserts the row sits
   between `Merge` and `Capacity`, and one that a product with nothing adopted grows no row.

   row present and not ok-shaped, and `doctor.run` puts `adopted` in the table exactly once.
