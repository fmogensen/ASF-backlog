§2.5: the same two counts as deltas, printed above `IN FLIGHT` in the summary that already owns the
window and the stamp (P12). Reads Task 2's `digest`; writes neither `work.py` nor `status.py`, so it
runs beside Task 3.

**Files**

- `asf/tick/summary.py` — `render` takes `work_lines=()` last (PD14) and emits the block ahead of its
  existing loop, as §2.5's fence has it; `work_lines(product, since, now)` added beside `titles`,
  with the same narrow `except (OSError, ValueError, KeyError, TypeError)` and `()` on failure;
  `run` passes it by keyword. The module docstring names the third block.
- `tests/test_tick_summary.py` — `WorkDigestTests` (new, §3.4) over the existing `SummaryTestCase`
  fixture, whose `INDEX` gains the Bugs and Features the deltas count.

**Steps**

1. Add `work_lines(product, since, now)` — `index_reader.load(shadow.record_dir(product))` and
   `lifecycle.runs(pool.sessions_path(product))` inside one try, then `work.digest(...)`. The
   `from asf.views import work` import sits with the module's other imports; `asf.views.work`
   reaches nothing in `asf.tick`, so no cycle closes.
2. Give `render` the parameter and the block: `''`, `f'WORK since {since}'` with
   `' (first tick on this clock)'` when `first`, then the lines — before the `IN FLIGHT` / `DONE`
   loop, so the tick prints §2.5's three blocks in that order.
3. `run` calls `work_lines(product, since, now)` and passes the result to `render` by keyword.
4. Extend `SummaryTestCase`'s `INDEX` with the cards `WorkDigestTests` counts, and write the class:
   the title and its position, the two lines, both window edges, the quiet tick, `first`, and the two
   unreadable-source cases.
5. Run the Gate.

**Acceptance** (§3.4, §3.6 — the spec's fences)

```bash
python3 -m unittest tests.test_tick_summary.WorkDigestTests -v
```

Covers, over the existing `SummaryTestCase` fixture:

- the block's title is `WORK since <the same since the DONE block names>`, and it is printed
  **above** `IN FLIGHT`;
- `bugs      +1 filed, 2 fixed` for a Bug created inside the window (`New`, `stage_since` in it) and
  two Closed in it; a Bug filed *before* the window is not counted, nor is one that is no longer
  `New`;
- `features  1 landed (F-0095), 3 started` — one Feature at `landed` in the window (named), three
  distinct Features with a run launched in it; a fourth run on a Feature already counted does not
  make it four, and a run launched before the window is not counted;
- the window is half-open on both counts: `since` exclusive, `now` inclusive, asserted at both
  edges;
- a quiet tick still prints the block, as `bugs      +0 filed, 0 fixed` /
  `features  0 landed, 0 started`;
- `first` (no stamp — the 24h fallback window) is marked on this block as it is on `DONE`;
- an unreadable record clone and an unreadable ledger each drop the block and leave `IN FLIGHT` and
  `DONE` intact; `tests.test_tick_summary.FailureTests` is the regression that a failure past that
  is still one line and the stamp is still written.
