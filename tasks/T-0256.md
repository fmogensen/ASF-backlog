## Description
stories: S-19900
writes: asf/record/check.py, asf/record/new.py, tests/test_backlog.py
after: Task 1

§2.3 and §2.1's `SETTABLE` lines: the record refuses to hold a supersession it cannot resolve, and
the two fields become writable by hand — which is what makes the fix the finding *names* runnable.

**Files**

- `asf/record/check.py` — `from asf.groom import conflicts` beside the `shape` import (`:10`);
  one `findings.extend(conflicts.supersession_findings(canonical, find_line))` at the end of
  `record_findings`
- `asf/record/new.py` — `SETTABLE['rule']` and `SETTABLE['decision']` gain `supersedes` and
  `superseded_by` (`:20-21`)
- `tests/test_backlog.py` — `SupersessionCheckTests`

**Steps**

1. `asf/record/check.py` imports `conflicts` from `asf.groom` beside the `shape` import it already
   has — the import `asf/groom/policy.py:9-14` names as the one that must not be made is
   `asf.groom.policy`'s, not the package's, and `conflicts` imports nothing `check` does not
   already import itself.
2. One block at the end of `record_findings`, after the per-card loop and before the `index.json`
   staleness block (`asf/record/check.py:373`): `findings.extend(conflicts.supersession_findings(
   canonical, find_line))`, with the one-line comment saying the messages are `conflicts`' and
   the sort and the exit code are `cmd_check`'s (PD5). Nothing else in the file moves.
3. `SETTABLE['rule'] |= {'scope', 'enforced', 'reason', 'check', 'supersedes', 'superseded_by'}`
   and `SETTABLE['decision'] |= {'decided_by', 'date', 'supersedes', 'superseded_by'}`, exactly as
   §2.1 shows. `conflict_declined` is **not** added: the applier writes it and no hand does, the
   way `reshape_declined` is written only by `apply_proposal` (`asf/groom/groom.py:257`) and is in
   no `SETTABLE` either.
4. `SupersessionCheckTests` per §3.2, each case a record built with the module's own `write_item`,
   then `asf index`, then `asf check`: the dangling `supersedes:`; the dangling `superseded_by:`;
   the half-written pair, whose finding is on the *other* card and names the `asf set` command;
   its mirror; the three-card ring as one finding, not three, on `D-0001`'s card; the self-ring;
   the correctly written pair and the five-card chain both at exit 0 with no supersession finding
   at all; the cross-type `R-0007 superseded_by: D-0051`, checked the same way and not a finding.
5. The ordering case §3.2 ends on: a record carrying both a dangling parent and a dangling
   successor prints both findings, ordered by path then line — the assertion that the new block's
   tuples are the same shape `cmd_check` sorts (`:148`).
6. The fix the message names is run, not just printed: after the half-written-pair case, the test
   runs the `asf set <id> superseded_by=<id>` the finding quotes and asserts the next `asf index`
   + `asf check` exits 0. That is what step 3 is for, and it is the only test that proves the two
   `SETTABLE` lines.
