Five expressions stop spelling their own digit count and start importing the one that exists. The
defect is that the minter has issued five-digit ids for a while and five readers were still built
for exactly four, so each fails silently rather than loudly: a lane cannot name the card behind a
branch it created, a Feature closes over scope a removed Task carried, a scripted write leaves its
placeholders unfilled, and the pattern file that exists to refuse a hardcoded Epic id cannot see a
five-digit one. The last edit is what keeps it fixed: the ratchet's allow list loses its product
half, and its scan learns to read the one guard that is not a Python file.

**Files**

- `asf/harvest/lane.py` — one import line in its alphabetical place between `:157` and `:158`, and
  `ITEM_ID_RE` at `:275`. Nothing else in the module: `branch_facts` and `resolve_item`
  (`:1965-1980`, `:2014-2019`) keep their fallbacks and are not touched — they simply stop needing
  them — and the downstream handling of a branch whose name only looks like an id
  (`:1816-1819`) is left exactly as it is.
