The spec's §1 and §2. When this lands, `~/.ASF/state/<product>/checked.txt` is where the ticks
live, `asf/evidence/checked.py` is the only module that knows it, the legacy `~/.ASF/checked.txt` is
still read and never written, and `ev['checked']` is a set of strings on the wire and in memory.
Nothing yet writes a tick and nothing yet reads the set differently — the gate is Task 2's. This
Task is the foundation the other four stand on, which is why it is alone in wave 1.

Read **PD7** (what `checked_file=` means now), **PD12** (`add`'s argument shape), **PD14** (the
command's code lands in this module in Task 3 — leave room for it, write nothing of it here) and
**PD16** (`feature_state` is not a reader and is not touched) before starting.

**Files**

- `asf/evidence/checked.py` — **new**. `LEGACY_PATH`, `path`, `read`, `matches`, `add`, `remove`,
  `WAITING_PREFIX`, `waiting_line`, `held`.
- `asf/evidence/evidence.py` — `CHECKED_FILE` and its `TODO(config)` deleted; `discover`
  delegating; `load` and `main` normalising and serialising strings.
- `tests/test_checked.py` — **new file**, **new class** `TheList`.
- `tests/test_evidence.py` — **new class** `CheckedIsStringsOnTheWire`.

`asf/record/ingest.py` is **not** on this list: `_in_prod` still compares `pr in checked` after this
Task, which under a string set means a `manual` product's items stay exactly as stuck as they are
today. That is deliberate — it is one landing, not a regression — and Task 2 closes it.

**Steps**

1. `asf/evidence/checked.py`, new module, docstring naming it the one owner of the operator's
   checked list. Imports `os`, `re` and `asf.env` only — nothing from `asf.evidence.evidence`, so
   `evidence.py` can import it without a cycle.
   - `LEGACY_PATH = os.path.join(env.ASF_HOME, 'checked.txt')` with the spec's comment
     `# read, never written`.
   - `path(product)` → `os.path.join(env.state_dir(product), 'checked.txt')`, the shape
     `approvals.ledger_path` uses (`asf/approvals.py:598-599`, D14). It creates the state directory,
     as `env.state_dir` always has; that is the precedent and is not worked around.
   - `HEADER = '# asf checked — landings verified on production by hand. `asf checked --help`\n'`,
     the spec's first line byte for byte, written by `add` when it creates the file and never
     otherwise.
2. `_tokens(path)` → `set[str]`: read the file, take each line's **first non-blank token**, and keep
   it when it is `#<digits>`, bare `<digits>` or `[0-9a-f]{7,40}` — a PR tick normalised to its
   decimal digits with the `#` stripped, a sha tick lowercased. Anything else, **including a `#` not
   followed by a digit**, is a comment and yields nothing (D8). A hex string under 7 characters is a
   typo, not a sha, and yields nothing. Everything after the first token is never parsed. A missing
   file, and an `OSError` reading one, are the empty set.
3. `read(product=None, checked_file=None)` → `set[str]`. With `checked_file` given, `_tokens` of
   that path and **nothing else** (PD7). Otherwise `_tokens(path(product)) | _tokens(LEGACY_PATH)`
   (D3). The docstring says both, and says the tokens are PR numbers as decimal strings and landing
   shas as lowercase hex.
4. `matches(checked, pr, sha)` → bool: True when `pr` is not None and `str(pr)` is in `checked`
   (D4), or when some token in `checked` is at least 7 characters, is all lowercase hex, and is a
   prefix of `(sha or '').lower()` (D7). An empty `sha` matches nothing; a `pr` of `None` contributes
   nothing rather than matching the string `'None'`.
