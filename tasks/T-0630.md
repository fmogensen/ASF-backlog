The spec's `## The design` §§4, 5 and 6 — the target set, `--suffix=`, the per-venv url and
verification, the per-clock "this install is not the one that ticks" lines with their
`NEEDS OPERATOR` repair, `previous` and `venvs` in the record, the `rollback:` line, and the guide.
This is the half that changes what actually installs, which is why it lands last.

**A single-install machine must come out byte for byte where it is today** but for the ` in <venv>`
tail: one `pipx install --force git+…@<ref>` with **no** `--suffix`, one verification, one
`upgrade: installed <sha> in asf-factory`. That is the whole of C10's safety argument and the
existing `UpgradeTest` is its pin.

The park, the drain, the pending marker and F-0207's debt are **untouched** (C16, spec `## Out`
(a)) — and so are the schema table, `--skip-pipx`, the CI guard and `--to`'s tag resolution, all
used unchanged (`## Out` (f)). An **editable** venv is never reinstalled (C11): `pipx install
--force git+…` over one silently destroys a development install the operator is using from their
own shell, and `install.sh` already owns replacing it, under a tick lock and by explicit
invocation.

Read **PD1** (`record_last`'s `venvs` has no source — `_install` knows and `install()` records,
with an `int` between them), **PD2** (where the `rollback:` line can be printed at all, and why not
on `--skip-pipx`), **PD3** (the `NEEDS OPERATOR` line's path is a forbidden token in `asf/`),
**PD8(a)** (two `run_upgrade` helpers must patch `launch_agents_dir` or three suites read the
operator's real home), **PD10** (`clockinstall` is imported lazily here) and **PD11** (`--suffix=`
is one argv entry, and the test asserts the entry, not the joined string) before starting.
