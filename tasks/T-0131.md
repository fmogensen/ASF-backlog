§2.4. `model_for` gains D5's four-step order with the product's per-kind table still first, so no
product file changes meaning and every kind keeps the label it resolves to today. `effort_for`
reads `roles.<role>.effort`; `spawn.effort_args` maps a label through
`worker_pool.effort_args` and refuses an unmapped one in `model_arg`'s exact shape;
`add_dirs_for` appends `roles.<role>.grants`. The `roles:` block and the `effort_args` line are
documented in `docs/config.example.yaml`, or the feature ships undocumented (Preconditions).

**Files**

- `asf/briefs/build.py` — `model_for(product, kind, cfg=None)` per D5; `effort_for(role, cfg)` →
  `roles.<role>.effort`, else `roles.defaults.effort`, else `None`; `add_dirs_for(product,
  row=None, kind=None, cfg=None)` appending the role's expanded `grants` after the product's
  `job_grants` and the row's own, de-duplicated, order preserved; `Brief` gains `effort: str = ''`;
  `build` passes `cfg` into all three. `asf.roles.for_kind` is what maps a kind to the role these
  three take.
- `asf/workers/spawn.py` — `effort_args(effort, cfg)`: `[]` for a falsy label, the mapped list for
  a known one, `SpawnError(f'NEEDS OPERATOR: worker_pool.effort_args has no entry for {effort} — add it to config.yaml')`
  for an unknown one — `model_arg`'s shape (`:251-260`), one function below it.
- `asf/workers/runtime.py` — `Job.__init__` gains `extra_args=()` (`:30-32`), stored as a list;
  `build_command` appends them after the `--model` pair and before `--settings` (`:82-86`). An
  empty `extra_args` leaves the command line byte for byte what it is today.
- `docs/config.example.yaml` — §2.4's `roles:` block verbatim, including its two comment lines,
  and `worker_pool.effort_args: {<label>: [<arg>, …]}` as a commented line under `worker_pool`
  (`:19-28`) beside where `models` is read.
- `tests/test_briefs.py` — `RoleModelTests` (new, §3/T5), `RoleGrantTests` (new, §3/T6's second
  half); `KindModelGrantTest:558-570`'s existing label assertions kept and extended.
- `tests/test_workers.py` — `EffortArgTests` (new, §3/T6's first half); `build_command`'s golden
  at `:108-116` extended with an `extra_args` case.

**Steps**

1. `model_for(product, kind, cfg=None)`: `conventions.models.<kind>` → `roles.<role>.model` →
   `roles.defaults.model` → `DEFAULT_MODELS[kind]` → `LIGHT`, where `<role>` is
   `roles.for_kind(kind)` and a `RoleError` short-circuits to the last two steps. The product's
   per-kind override stays first (D5): putting the global role entry ahead of it would silently
   re-point a product that already set one. A role named in `roles:` with no file changes no
   label — nothing in this path reads the filesystem.
2. `effort_for(role, cfg)` and `add_dirs_for`'s role grants per §2.4. A role grant only ever adds;
   the permission fence (`permission_mode`, `settings_file`) is not touched.
3. `Brief.effort`, filled in `build` from `effort_for(roles.for_kind(kind), cfg)` — read by
   Task 4, unread here.
4. `spawn.effort_args` and the `runtime` wiring. `spawn.spawn` does not call it yet: the row has
   no `effort` until Task 4. This Task delivers the mapping and the refusal, which is what §3/T6
   asserts.
5. `docs/config.example.yaml` per §2.4, with the block's own comment — "the role files
   (`asf roles`) carry identity and doctrine and name none of this — the assignment is operator
   configuration" — kept, since it is the sentence the card's second acceptance line is about.
6. `RoleModelTests` per §3/T5: for every kind in `KINDS`, `model_for(product, kind, cfg={})` is
   the label it returns today — `heavy` for `spec`, `plan`, `reshape`, `review`, `groom`,
   `adjudicate`, `light` for the rest (D6: this change moves identity, not cost);
   `cfg={'roles': {'reviewer': {'model': 'light'}}}` makes `review` li
