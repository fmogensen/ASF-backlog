The spec's `## The design` §2.1, §2.2 and §2.3 in full, and nothing else. After this lands, a
branch that adds a focused test, a disabled test, a breakpoint or a debug flag left `True` to any
file that is not documentation is handed back to its session with every `file:line` — before
review, and again at the gate — and one line is made legal by `debug-ok: <why it stays>`.

**Read PD4 before writing a single fixture.** The waiver and §2.1's defaults must be in place
before any marker-bearing line is, or this branch is refused by the gate it adds. **PD3 before
touching `lane_refusal`** — four callers, none of which changes. **PD5** names the whole-tree AST
fence the new module sits inside.

Three things are load-bearing. **Nothing is re-implemented**: `matches`, `scan_line`,
`added_lines`, `describe`, `SHOW_HITS` and the new `diff` are imported from
`asf.customer_content` (P5, D10), and `asf/security/paths.py:6` is the precedent that this is the
established way, not a new one. **`is_doc` is split, not copied** (D2, P7): `landing_class` keeps
its name, its signature and its meaning, and its per-path half becomes the one docs-vs-code rule
both readers call — the spec's two functions in §2.3 are behaviour-identical to today's
`landing_class` over every path measured in PD1, including `docs/other.md` → `code`. And **the
chain's order is customer content first**, because it is the product's own declared scope; §3.1's
`Gate` class pins it.

  `DEFAULT_DEBUG_TOGGLE_WAIVER`, `DEFAULT_DEBUG_TOGGLES`, placed between
  `DEFAULT_FORBIDDEN_MARKERS`'s closing `)` (`:235`) and the `security:` comment block (`:237`),

  `validate_mapping`, beside the `customer_content` one (`:494-513`), emitting the four problem
  shapes §2.1 lists and reusing `_path_list_problem` (`:431`) for `paths` — a string where a list
  belongs char-splits into one matcher per character, one of them `*`. And `debug_toggles` added
  to the **docstring's own list of checked keys** (`:453-457`, P10): a checked key missing from
  that list makes the docstring false.
- `asf/customer_content.py` — `diff(repo, base, head)` promoted to a public function (P6, D10):
  the one `-U0` read, keeping the three-dot `f'{base}...{head}'` range exactly (a marker already

  `added_hits` (`:140`) rewritten to call it. Nothing else in the module changes; its 19 tests
  pin `added_hits` and therefore pin `diff`.
