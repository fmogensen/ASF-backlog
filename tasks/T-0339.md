## Description
stories: S-31462
writes: asf/workers/spawn.py, asf/console_perms.py, asf/approvals.py, asf/redact.py, tests/test_events_stream.py, tests/test_workers.py, tests/test_redact.py, tests/test_console_perms.py
after: Task 3

§2.8 whole. Three sites, one kind, `fields.what` distinguishing them, and not one machine path or
account name in the record (B-0023).

**Files**

- `asf/workers/spawn.py` — one `grant` event per entry of the final `add_dirs` list (`:703-709`),
  `fields.what = 'add-dir'`, `key=f"{job}:{label}"`, `item=row.item`,
  `account=metrics.account_index(account)`, `text` as §2.8's table gives it. `label` is the
  granted directory relative to `ASF_HOME` (rendered `<home>/…`) or to the product repo
  (`<repo>/…`), else its basename — never the absolute path the session was handed. The event is
  raised after the grant list is final and before the runtime is asked for anything, so a refused
  launch still records what it was about to grant.
- `asf/console_perms.py` — one `grant` event per rule added to or removed from `allow`/`deny`, at
  the **write** site (`cmd_console_permissions:143-148`) and not in `merge`, which is pure and
  holds no product. `fields.what = 'deny-rule'`, `key=f"{scope}:{rule}"`, `account=None` with
  `fields.actor = 'console'`. With no `--product` there is no record to write to (PD15): the
  grant line is printed and one note says the write was not recorded because no product was
  named.
- `asf/approvals.py` — the `secrets` human-now class, on **both** the refusal and the grant of a
  `gh secret` / `gh auth` / `auth_env` file write: `fields.what = 'secret'`,
  `key=f"{item}/{target}"`, `text` as the table gives it. `target` is a variable name or a
  command verb and **never a value** — `asf.redact` already owns the shapes.
- `asf/redact.py` — the one helper the three sites share: `grant_label(path, repo=None)`,
  returning `<home>/…`, `<repo>/…` or the basename. It belongs here because this module already
  owns what may appear in the record, and one helper is the only way three call sites cannot
  disagree.
- `tests/test_events_stream.py` — `GrantAuditTests`. `tests/test_workers.py` —
  `SpawnGrantEventTests`. `tests/test_redact.py` — `GrantPathsAreRelativeTests`.
  `tests/test_console_perms.py` — the deny-rule event and the no-product note.

**Steps**

1. `redact.grant_label` and `GrantPathsAreRelativeTests`: a path under `ASF_HOME` rendering
   `<home>/…`; one under the product repo rendering `<repo>/…`; one under neither rendering its
   basename alone; a path containing a worker account name rendering neither the name nor the
   machine path; and — the case that matters — the rendered label surviving
   `redact.scrub(label, redact.default_patterns(repo))` unchanged, because a label that the
   scrubber has to fix is a label that should not have been written.
2. `asf/workers/spawn.py`'s event and `SpawnGrantEventTests`: one event per granted directory,
   with `fields.what`, the item, the account as `a<n>`, and the label relative; a launch with no
   grants raising none; a refused launch still recording; and `assertNotIn` over the whole event
   for the account's name and for the absolute path.
3. `asf/console_perms.py`'s event and its two tests, including the no-product note (PD15).
4. `asf/approvals.py`'s `secret` event on both the refusal and the grant, with the target a name
   or a verb and never a value.
5. `GrantAuditTests`: all three `fields.what` values over one day file; every event carrying
   `item` and either an `a<n>` account or `fields.actor: 'console'`; the keys distinct so three
   grants are three lines; a repeat of the same grant in the same day leaving one line.
6. `bash tools/check_generic.sh` and `python3 -m unittest tests.test_redact` by hand before the
   push — the redaction check is the standing rule for anything that writes into the record.
