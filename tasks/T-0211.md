stories: S-18805

§2.6's first pass, and D14. A new step between `wave` and `prs` puts each finished small Task's
commit on its lane's train and marks the session so neither `prs` nor `harvest` touches its branch
again. The cut is Task 7's; this Task appends and stops.

**Files**

- `asf/tick/step_train.py` — **new**: the module docstring and `run(ctx, out=print)` with the
  append pass; the cut and red passes are stubs that print nothing and return 0 until Tasks 7
  and 8.
- `asf/tick/steps.py:24` — `STEPS` gains `'train'` between `wave` and `prs`; `ASF_CALLABLES`
  gains `'train': 'asf.tick.step_train:run'` (`:27`).
- `asf/tick/step_prs.py:98` — `candidates` skips a session whose `harvest` is `train` (PD8).
- `asf/harvest/harvest.py:193` and `:1296` — `record.get('harvest') != 'pr'` becomes
  `record.get('harvest') not in ('pr', 'train')`, the two places D14 names.
- `tests/test_tick_steps.py` — `TrainStepTests`, the append cases of §3.5.

**Steps**

1. `run(ctx, out)` returns 0 immediately with one line — `train: no lanes configured` — when
   `conventions.train_lanes` is empty (D15), which is every product until an operator names one.
2. One throwaway worktree for the whole step, `tempfile.mkdtemp(prefix='train-')`, removed in a
   `finally` — the shape `land_set` already uses (`asf/harvest/harvest.py:1193`), so a crashed
   step leaves no worktree behind.
3. The append pass, per lane, oldest session first: every session that is `finished`, not landed,
   not already marked, whose item's `size` is `small`, whose branch is on origin and ahead of the
   train head. No open train for the lane → open one:
   `git push origin origin/<main>:refs/heads/<branch>` with the branch from
   `train.new_train(conv, lane, now)`, and a registry row in state `open`.
4. `git cherry-pick` the branch's commits past the train head onto it — a fast-forward when the
   head has not moved. More than one commit is squashed into one, the Task id kept in the subject.
   A conflict, or a commit whose subject does not name the Task, **demotes** (D5): the cherry-pick
   is aborted, no registry row is written, no mark is set, and the session is left exactly as it
   is, so `prs` opens its ordinary pull request in the same tick.
5. On success: push the train, append the `tasks` row (`item`, `job`, `branch`, `sha`, `subject`),
   set `first_commit` on the registry row if it is still null, and mark the session
   `harvest: train` with the appended sha through the same session writer harvest uses.
6. One line per append, §2.6's: `train: T-0101 → train/code-20260924-0930 (3/6)`. One line per
   demotion naming why. The tick log says what the trains did without anyone opening the registry.
7. PD8, in this same diff, because the mark is worth nothing without it: `step_prs.candidates`
   skips `harvest: train`, and harvest's two conditions become `not in ('pr', 'train')`. Three
   call sites, one condition. The step sits before `prs` in `STEPS` so the mark is set before
   `prs` reads it in the same tick (D13).
8. `TrainStepTests` per §3.5's append cases, over `tests/gitfixture.py` with a product repo, a
   record and a session ledger: a finished small Task's single commit appended to a new train, the
   train pushed, the registry row written, the session marked `harvest: train`, and the worker
   branch still on origin (D14); a second small Task appended onto the moved head by cherry-pick,
   in session order; a medium Task in the same tick left completely alone — branch untouched, no
   registry row; a conflicting cherry-pick demoted with no registry row, no mark, and
   `step_prs.candidates` still offering it (D5); an appended Task **not** offered by
   `step_prs.candidates` and not eligible for harvest (PD8); `train.lanes: []` doing nothing and
   printing one line; and the step declared nowhere still resolving to `asf`
