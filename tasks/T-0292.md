## Description
stories: S-30306
writes: tests/test_evals.py, asf/evals/adapters.py
after: Task 3, Task 4

§1.4's purity row, over all three adapters at once — which is why it is last of the scoring Tasks
and not part of any of them. A task whose answer changes with the tree is not an instrument, and
this is the only place that is asserted about the *whole* set.

**Files**

- `tests/test_evals.py` — `DeterminismTests`.
- `asf/evals/adapters.py` — only if the assertions below find a read of the clock, the network or
  the working tree. A change here is a defect fixed, not a new feature.

**Steps**

1. `DeterminismTests`, §3.6: score the whole shipped set twice in one process; assert identical
   per-task outcomes, identical per-lever hashes and an identical set hash.
2. The purity assertion: for the second run, replace `socket.socket` and `time.time` with raisers
   for the duration, and assert the reading is unchanged. The wall clock the reading itself records
   (`LeverReading.seconds`, the `ts` of the event) is taken **outside** the adapters, which is what
   makes this possible — if it is not, that is the defect this Task fixes.
3. The one honest exemption to name in the test's docstring: the rule adapter runs a subprocess, so
   it takes real time; what is asserted is that no *outcome* depends on it, and that the only path
   it writes is under the temp root Task 4's step 7 already proves it removes.
