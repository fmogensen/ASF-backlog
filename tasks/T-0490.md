## Description
stories: S-34250, S-34253
writes: asf/product_config.py, asf/init.py, tests/test_product_config.py, tests/test_install.py
after: Task 1

The spec's `## The design` §`asf/product_config.py` down to `findings`, its §`asf config check` and
its §Registration's `check` half. The module is created here with its docstring, its three tables and
everything read-only; nothing writes a file in this Task. `register()` declares the `config` noun and
its `check` verb only — a `migrate` subparser pointing at a handler Task 3 has not written yet would
be red on arrival.

**Files**

- `asf/product_config.py` — the module docstring; `RENAMES`, `RETIRED`, `HOMELESS`; `Finding`;
  `current_keys`, `suggestion`, `findings`; `register`, `cmd_config_check`
- `asf/init.py` — `product_config` in `register_commands`' import and one `register` call
  (`:337-346`), and the docstring's command list
- `tests/test_product_config.py` — the module docstring, the shared fixtures, and
  `CurrentKeysComeFromTheSchema`, `CheckNamesEveryKeyAndItsHome`, `CheckExitCodes`
- `tests/test_install.py` — one `argv → handler` row for `config check` in `PackageTest`

**Steps**

1. The module docstring, byte for byte from the spec's §`asf/product_config.py`.
2. `RENAMES` (8 rows), `RETIRED` (1 row) and `HOMELESS = {}`, with the spec's comments — including
   the one that says the card slot ships empty and an id comes from `asf new`, never from this table
   (D10, P20). **No card id is written into this file.**
3. `Finding = collections.namedtuple('Finding', 'line key kind now detail fixable')`.
4. `current_keys()` — derived from `env.PRODUCT_FIELDS` and `env.NESTED_FIELDS` at call time (D2),
   never a copy: the top-level names, plus `f'{section}.{key}'` for each `NESTED_FIELDS` section.
5. `suggestion(key)` — `difflib.get_close_matches` over `current_keys()` first, then the dotted
   reading of an underscored key (`ci_budgets` → `ci.budgets`, `release_window_days` →
   `release.window_days`), `''` when neither answers. Probed: `difflib` alone answers
   `customer_path` and cannot answer `ci_budgets`, which is why there are two halves (P17, D9).
6. `findings(text)` — the unknown and wrong-shaped keys come from `env.validate_product_text`, the
   same list that refuses the load, so `check` can never disagree with the loader about whether the
   file is loadable; the renames and retirements are read off the text's own key lines with `env`'s
   `_match_key` and `_strip_comment`; a duplicate top-level key is a `duplicate` row (P18). Sorted by
   line.
7. `cmd_config_check` — the spec's table, byte for byte in its columns and its two closing lines.
   Exit **1 only when `env.validate_product_text` is non-empty**, never when `findings` is (PD13).
   `--json` prints the findings as a list of objects and nothing else.
8. `register(subparsers)` — the `config` parser, `sub.add_subparsers(dest='config_command',
   required=True)`, the `check` parser with `env.add_product_arg` and `--json`, and
   `set_defaults(run=cmd_config_check)` (P14). No `migrate` parser yet. Nothing is added to
   `asf/surface.py` (PD4).
9. `asf/init.py`: `product_config` into the `from asf import …` line and `product_config.register(subparsers)`
   after `schema.register`, and the docstring's list gains `config`.
10. `tests/test_product_config.py`: the module docstring and the fixtures every later class reuses —
    a product text carrying a rename, a retirement, a homeless scalar, a homeless block list, a
    homeless nested map, a wrong-shaped `customer_paths` and a duplicate key (PD9).
11. `CurrentKeysComeFromTheSchema`: every declared field and nested field appears; a field added to
    `env.PRODUCT_FIELDS` inside the test is understood with no edit to the module.
12. `CheckNamesEveryKeyAndItsHome`: one row per key, with its line, its kind and the current key it
    maps to or the note; `ci_budgets` prints the *did you mean* and is still classed `no home`.
13. `CheckExitCodes`: 1 for a file that does not load
