The spec's §4 — `rows()`, `render()`, `cmd_cancels()`, the `sub.add_parser('cancels', …)` in
`ci_pool.register` and the one `header.TITLES` key. This is the surface: an operator who sees a cancel
storm runs one command and gets the answer the card had to guess at.

It waits on Task 2 because it renders Task 2's classification, and because it writes the same module
(PD9). It is the only Task that touches a file outside the new module and its suite, and both of those
edits are one line each (P11).

Read **PD4** (`--days` past two finds no claims — the help text says so), **PD6** (`ci_pool.register`
imports this module *locally*, or the CLI's first import closes a cycle) and **PD7** (neither
`ci_from_api`'s jq nor `metrics.pr_info` answers §1's rules; this pass builds its own listing) before
starting.

**Files**

- `asf/ci_cancels.py` — the API reads (the run listing, the per-run jobs, the PR `merged_at` cache),
  `rows(...)`, `render(...)`, `cmd_cancels(args, out=print)`
- `asf/ci_pool.py` — one `sub.add_parser('cancels', …)` in `register` (`:1304-1321`), its flags, its
  `set_defaults(run=…)`, and the local `from asf import ci_cancels` beside `:1319`
- `asf/views/header.py` — one key in `TITLES` (`:7-19`): `'ci cancels': 'CI CANCELS'`
- `tests/test_ci_cancels.py` — the `Table` class

**Steps**

1. The run listing: `metrics.gh_lines(['api', f'repos/{slug}/actions/runs?created=%3E%3D{since}&
   status=completed&per_page=100', '--paginate', '--jq', …])` with the jq of P7 **plus `event`**
   (PD7), filtered to the product's CI workflow (`product.ci['workflow']`, P14). `updated_at` is when
   the run reached its conclusion — the moment it was cancelled — and is what §1's supersede test and
   the inferred-`merged` rule both read. Import `metrics` inside the function (PD6).
2. Jobs are read **for cancelled runs only** (C8): one paginated
   `repos/<slug>/actions/runs/<id>/jobs` call per cancelled run, giving each job's `name`,
   `conclusion`, `started_at` and `completed_at`. Nothing in this table needs the jobs of a run that
   concluded `success`, and over the card's own window that is 74 calls instead of 125. The run's
   cancelled minutes are summed over its jobs that concluded `cancelled`, the same arithmetic
   `ci_from_api` does at `asf/metrics/metrics.py:1722` — read it, do not import it (Out (d)).
3. The PR `merged_at` cache: `repos/<slug>/pulls/<n>` once per PR number in the cancelled population,
   keeping `merged_at`. **Not** `metrics.pr_info`, which returns `merged` as a bool and cannot answer
   the rule (PD7).
4. The timeouts dict: `ci_pool.parse_timeouts` over the workflow file, else
   `ci_pool.DEFAULT_JOB_TIMEOUT_MIN` for a job that declares none (P10, §1). Import `ci_pool` inside
   the function (PD6). An unreadable workflow file is an empty dict, which leaves every job on the
   host's default limit — under-claiming timeouts rather than over-claiming them, the direction
   `GitHubBackend.timeouts` already takes at `asf/ci_pool.py:765-768`.
5. `rows(classification)` — one row per cause in `CAUSES` order, **always, zeros included**: cause,
   group, run count, minutes, and the share of minutes. A cause that never appears is a cause the
   operator can see is zero, and `unclaimed` at zero is this card's own success condition. The share
   is of **runner-minutes, not of runs**, because runners are what the card is spending.
6. `render(...)` — the spec's §4 output exactly: the `header.head('ci cancels', product, clause)`
   first line with the clause naming the window, the cancelled-of-total run counts and the
   runner-minutes thrown away; the nine-row markdown table with the numeric columns right-aligned as
   §4 shows; then the footer. `from asf.views import header` — note `asf/ci_queue.py:3592` defines its
   own unrelated `header(name, m, waiting)` helper, so import the module, never the name.
