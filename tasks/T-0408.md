## Description
stories: S-32359
writes: asf/upgrade.py, tests/test_install.py
after: none

§2.7 and D11: `--to` is the documented name for the existing `--ref`, which stays an accepted
alias, and a tag is resolved to its commit before the CI-red guard reads CI. The clock reload and
the doctor's drift row already exist; this Task proves them, it does not rebuild them.

**Files**

- `asf/upgrade.py` — `--to` with `dest='ref'`, the tag resolution in `install()`
- `tests/test_install.py` — `UpgradeToTests`

**Steps**

1. `register`: `--to` added with `dest='ref'` and help naming a sha **or a tag**; `--ref` kept,
   same `dest`, help marking it the accepted older spelling (`asf/upgrade.py:622-630`). An
   operator's existing command line does not break for a word.
2. In `install()`, before line 507's `refuses(url, ref, run)`: a `ref` that is not 40 hex is
   resolved with `git ls-remote <url> <ref>` to its commit, and that commit is what `refuses`,
   `write_pending` and the marker see (PD12). The value the operator gave is kept and is what
   `pipx` receives, so `direct_url.json` records the tag and `version_string` reports the release
   (`asf/cli.py:91-104`).
3. A ref that resolves to nothing is one refusal line naming it and a non-zero exit — never a
   silent fall-through to `main`'s head.
4. `asf.tick` and `asf.drift` keep calling `install(ref=…)` unchanged (D11); the reload
   (`asf/upgrade.py:463-489`) and the drift row (`asf/doctor.py:481-490`) are untouched.
5. `UpgradeToTests`: `--to v0.1.1` and `--ref v0.1.1` reach the same `dest`; a tag is resolved
   before CI is read, and the guard refuses on a red run at the **resolved** sha; the resolved sha
   is what the pending marker holds; `pipx` receives the tag as given; a 40-hex sha is not
   ls-remoted at all; an unresolvable ref is the refusal line and a non-zero exit; and the clock
   reload is still called with the product names after a successful install.
