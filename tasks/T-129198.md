## Description
stories: S-104406
writes: asf/scheduler.py, tests/test_scheduler.py
after: Task 1

The spec's design §2's `_bootstrap_with_one_retry` (D-0003). The wait closes the race; the retry covers
the refusal the wait cannot explain, and it is the shape the installer already uses one level up for
this same failure (`asf/install.py:422-427`, B-0136).

**The wording is not cosmetic and is the whole of this Task's risk.** `_cmd_host` decides its own
exit status by looking for `failed` in these lines — `'failed' in line and 'bootout' not in line`
(`asf/scheduler.py:1504`) — so the **first** attempt's line must say `refused (…) — retrying once`
and must not carry the token `failed`, or a `--host` install whose retry *succeeded* exits 1, which
is the very shape this card is fixing. Only the terminal `failed again` line sets that 1. Nothing
in the suite or the guide pins today's first-attempt string: `grep -rn "bootstrap .*failed"` over
`tests/`, `tools/` and `docs/guide/` → no match.

**Files**

- `asf/scheduler.py` — `_bootstrap_with_one_retry(label, path)` exactly as §2 writes it, and
  `_launchd_install`'s tail becomes `lines.extend(_bootstrap_with_one_retry(label, path))`. Nothing
  else in the module moves: `bootstrap()`, `resume()`, `pause()` and `uninstall()` are untouched —
  none of them is a bootout immediately followed by a bootstrap of the same label, and
  `pause`/`resume` reach `bootstrap()` (`:956-970`) and never `_launchd_install`, so
  `_cmd_pause_resume`'s sniff (`:1473`) never sees these lines at all.
- `tests/test_scheduler.py` — `InstallRetryTest`, new, for S-104406's ten checklist lines, driving
  Task 1's `fake_refuse` helper.

**Steps**

1. Extract today's two bootstrap lines into `_bootstrap_with_one_retry` and add the one new
   branch: on a refusal, the `refused (…) — retrying once` line, a second `wait_unloaded(label)`,
   a second `_launchctl(['bootstrap', …])`, then `bootstrapped <label> (retried)` or
   `bootstrap <label> failed again (<why>)`. One retry, not a loop to the bound: two independent
   causes are in play and the wait only closes the first, so a second failure is a fact for the
   operator rather than something to keep hammering.
2. Keep the §2 comment that says *why* the word is `refused` — the next reader of `:1504` needs it.
3. Write `InstallRetryTest`: a once-refused bootstrap tried again and the clock loaded, with
   `refused … — retrying once` then `bootstrapped … (retried)` in that order; the first line
   asserted **not** to contain `failed` and the terminal one asserted to; a bootstrap refused both
   times printing `failed again` with launchd's own message and the clock not loaded; the retry
   waiting before it tries; exactly **two** bootstraps in `stub_argv` for one clock, never three;
   and a clock whose first bootstrap succeeds reaching `launchctl` once with neither retry line.
4. `tests.test_host_clock` is in the acceptance for the exit status the wording protects, not for
   a new case: `asf scheduler install --host` must exit 0 when the retry succeeded and 1 when it
   was refused twice. Add those two cases there if the module does not already reach them.
