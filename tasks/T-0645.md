The spec's `## The design` §1 and §3. After this lands, every job row the importer writes carries
its `limit` and, when it ended `cancelled`, the cause of that cancel — `timeout`, `runner-loss` or
`failure` — decided from the run and its jobs alone, on the tick's own daily step, with no operator
command. Nothing reads the new fields yet; Tasks 3 and 4 do.

Read **PD4 before touching `tests/test_metrics.py`**: the test that reaches the real host is
`Backfill.test_ci_backfill_and_idempotence` (`:1139`), not the one the spec names. Read **PD16**
before writing arms 4 and 5 — they are one predicate, and the live 19-second job is `started` with
`minutes: 0`. **PD8** is the one line of the spec's code this plan changes. **PD11** says why the two
new schema keys need no ordering work, and **PD18** why C15's cited precedent is beside the point.

**Files**

- `asf/ci_jobs.py` — **new.** The module docstring the spec prints verbatim; `RED = ci_pool.FAIL`;
  `TIMEOUT`, `RUNNER_LOSS`, `FAILURE`, `CAUSES`, `CANCELLED`, `TIMEOUT_SLACK_MIN`; `cancel_cause`.
  The three `NEAR_LIMIT_*` constants and `p90`/`near_limit` are **Task 3's** — this Task lands no
  function without a caller.
- `asf/metrics/metrics.py` — `from asf import ci_jobs, ci_pool` in the import block (`:33-34`);
  `JOB_SCHEMA`'s `limit` and `cause`; `MATRIX_SUFFIX`; `_limit_of`; `job_limits`; `ci_from_api`'s
  `limits=None` parameter, its one `job_limits` call, the `limit` field on each job row and the
  second pass that fills `cause`.
- `tests/test_ci_jobs.py` — **new.** `CancelCauseTests(unittest.TestCase)`, a plain `TestCase` with
  no harness to subclass.
- `tests/test_metrics.py` — a new `JobCauseImport(Base)`; the one added patch line in
  `Backfill.test_ci_backfill_and_idempotence` (PD4).

**Steps**

1. `asf/ci_jobs.py` with the spec's docstring and constants exactly as printed, `from asf import
   ci_pool` at module level (P20 — `ci_pool` imports `env` and stdlib only) and `RED = ci_pool.FAIL`
   as an alias, not a copy (C15).
2. `cancel_cause(job, jobs, conclusion, superseded=False)`: `None` unless `job['conclusion'] ==
   CANCELLED`, then the seven arms **in the spec's order**, first match wins — (1) a known
   `job['limit']` with `job['minutes'] + TIMEOUT_SLACK_MIN >= job['limit']` → `TIMEOUT`; (2) any row
   of `jobs` concluded in `RED`, or `conclusion` in `RED` → `FAILURE`; (3) `superseded` → `FAILURE`;
   (4) this job never started → `FAILURE`; (5) every started row of `jobs` concluded `cancelled` →
   `FAILURE`; (6) a known `job['limit']` → `RUNNER_LOSS`; (7) → `FAILURE`. `_started` is PD16's one
   predicate, used by arms 4 and 5. Arm 1 leading is the design (C3): a job that ran to its limit hit
   its limit, whatever else was true of its run.
3. `JOB_SCHEMA` gains `'limit': (('num', 'null'), None)` and `'cause': (('str', 'null'), None)`, with
   the spec's two comments. Both default `None`, so every event already being written still validates
   and a stored row that predates the change simply has no key (P7, P8).
