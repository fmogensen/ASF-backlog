## Description
stories: S-31456, S-31457
writes: asf/metrics/log.py, asf/cli.py, tests/test_log_render.py, tests/fixtures/log/**
after: Task 3

§2.4 whole. The log stops being a thing tools write and becomes a thing one function renders, and
the fixture day pins its bytes under two time zones.

**Files**

- `asf/metrics/log.py`, second half:
  - `RENDER` — `{kind: formatter}`. A kind in the stream and not in the map is not in the log.
    The `WAVE` line comes from the `ticks` stream at its own `ts`, and is the one line the map
    does not own.
  - `render(root, product, days) -> str`, the pure function: `# <day>` header; every line
    `HH:MM <text>` with the `HH:MM` taken from `ts` in **UTC** and no local clock read anywhere;
    the day's lines sorted by `(ts, kind, key)` — a total order, so two runs give the same bytes;
    `text` as the emitter wrote it, never re-derived from `fields` (`emit` already collapsed and
    capped it, Task 1); no machine path, no account name, every float `{:.1f}`; exactly one `\n`
    per line, no trailing spaces, output ending in `\n`; `--days N` as N blocks oldest first,
    one blank line between.
  - The footer (§2.4 rule 6): a blank line, then one `NEEDS OPERATOR:` line per
    `needs-operator` event of the window whose `key` has no later `hold-resolved` or
    `needs-operator-cleared` event, oldest first. No events, no footer and no blank line.
  - `cmd_log(args, root)` prints it, and a `main()` / `__main__` entry so
    `python3 -m asf.metrics.log` is the fence's command.
  - Read-only, and it says so: never a clone, fetch, reset or commit — the discipline
    `asf/tick/watch.py` keeps.
- `asf/cli.py` — `asf log [--product P] [--day YYYY-MM-DD | --days N] [--root DIR]`, `--root`
  defaulting to `shadow.record_dir(product)` (`asf/tick/shadow.py:44`). **Not** added to
  `asf.views.header.TITLES` (PD21) — byte-stability is an acceptance and a clock in a title line
  would break it.
- `tests/fixtures/log/record/metrics/{events,ticks}/2026-09-25.jsonl` — the fixture day: one
  `WAVE` tick line with all five counters non-zero, and the `launch`, `grant`, `merge`,
  `refusal`, `relaunch` and `needs-operator` events §2.4's sample renders, plus one event of a
  kind `RENDER` does not name, one event with `tick: null`, one `needs-operator` with a later
  `hold-resolved` (which the footer must omit) and one legacy line with no `key` and no `product`.
- `tests/fixtures/log/2026-09-25.expected.log` — the bytes, exactly §2.4's sample plus the
  footer.
- `tests/test_log_render.py` — `FixtureDayTests` and `NeedsOperatorFooterTests` beside Task 3's
  `NoOtherWriterTests`.

**Steps**

1. The fixture record and the expected log, written by hand from §2.4's sample. Every `ts` UTC,
   every line's `product` the same, keys sorted.
2. `RENDER` and `render`, then `FixtureDayTests`: the rendered bytes equal the file; a second
   render equals the first; the sort is total (shuffle the day file's lines and re-render — the
   bytes are unchanged); `TZ=Asia/Tokyo` changes nothing; the kind `RENDER` does not name is
   absent; the `tick: null` event still renders; the legacy line does not crash the renderer.
3. The footer, then `NeedsOperatorFooterTests`: one line per open `needs-operator`, oldest first;
   the resolved one absent; no events at all giving no footer and no trailing blank line; the
   window honoured by `--days`.
4. `cmd_log`, the `--root` default, the `main()` entry, and the two by-hand fences below.
5. `python3 -m unittest tests.test_views_header` in the Gate, to prove registering `log` without a
   `TITLES` entry left that contract intact (PD21).
