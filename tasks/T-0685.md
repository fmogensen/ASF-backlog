The spec's I1, I2, I3, I4 and I7's guide half, and `## The design` §§1, 2, 4 and the
`tests/test_readme.py` part of §5. This is the Task the customer reported against: the setting exists
and works, and the guide still says there are two labels and one per kind.

Its load-bearing piece is D1 — the built-in table is not restated in prose, it is a fenced block
holding `asf doctor`'s own `model table` lines, and the test asserts **equality** against
`doctor.model_table_lines`. The coupling is deliberate and it bites: a new brief kind, or a moved row
in `MODEL_TABLE`, reddens this module until the block is regenerated. The one-liner that regenerates
it is in Steps and in Acceptance.

Read **PD3** (the section slicer stops on `####` and raises with no following `###`), **PD4** (two
fences, and which one the test takes) and **PD9** (the 19 lines, and why they are safe in CI) before
writing a line.

Nothing the factory *does* changes when this Task lands. Three documents and one test module; no
session's model moves.

**Steps**

1. `docs/guide/product-config.md:81` becomes the spec's §1 row, byte for byte — the escaped pipes
   are the markdown table's and stay:

   ```markdown
   | `models:` → `<kind>: heavy\|light\|cheap`, or a map of those by item class | per kind × class | which model label a job kind runs on, and which label each item class within that kind runs on — below |
   ```

   The default cell is `per kind × class`, not `per kind`: unset does not mean one label per kind any
   more, and that is the sentence the row got wrong. Verified there is exactly one line in the file
   starting `| \`models:\`` — the test reads it by that prefix, the way
   `test_conventions_table_names_worktree_setup` (`:521-524`) reads its own.
2. The new subsection, inserted before `:223`. The prose is the author's; the clauses are the spec's
   §2 and are fixed — three labels and what each is for; `worker_pool.models` in `~/.ASF/config.yaml`
   as where labels become model ids; that a label the pool has no entry for refuses the launch
   **except `cheap`, which falls back to `light`** (measured: `MODEL_FALLBACK = {'cheap': 'light'}`,
   `asf/workers/spawn.py:725`, read by `model_arg` `:736-742`); that the built-in default is per
   brief kind **and** per item class; what a class is — a Bug's severity `S1`/`S2`/`S3`, else its
   type `task`/`story`/`feature`/`epic`; **I3's clause, which doctor's table cannot show** — that the
   seven rows are the seven *item* classes and a brief with **no item at all** (a groom day, a rebase
   of a branch whose card has gone) takes the kind's own `default:`; that `asf doctor` prints the
   resolved table for the operator's own product, one `model table` row per kind; the two yaml forms;
   D5's `default:` trap in its own paragraph; and that a value of any other shape is a red
   `conventions` row in doctor, not a silent default. No `####` anywhere in it (PD3).
