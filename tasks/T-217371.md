**Files**

asf/record/archive.py, asf/groom/inbox.py, tests/test_record_archive_inbox.py

**Steps**

1. `asf/record/archive.py`: `plan_notes(root, product, canonical, manifest)` — the second pass over
   `<intake_dir>/done/`, §2.8's three cases. A note whose `card:` id is on the record (in the
   working set **or** in the manifest) moves to `archived_folder(product.conventions.intake_dir)`
   byte for byte; a note `asf retire` moved there — its first block starts with
   `inbox._RETIRED_NOTE` — moves too, with `retired` set in its manifest entry; a note whose card
   exists nowhere **stays**, and the dry run says why: that is a note the groom has not finished
   with, whatever `done/` says. The folder is read from the product, never spelled (**PD12**).
2. `asf/record/archive.py`: the `notes` block Task 1's `move` already writes through —
   `{title, signature, card, retired, archived}` per §4 — filled from `plan_notes`, and
   `render_plan` gaining the notes count and the stayed-behind rows. Nothing about the cards' half
   changes.
3. `asf/groom/inbox.py`: `retired_keys(canonical, inbox_dir)` gains the manifest as its third
   source, and folds **only** an entry whose `retired` is set (**PD8**, block M3). The comment says
   why in one line: a note the groom filed successfully is not a retired note, and folding it would
   make the next note with that title drop as already retired — the opposite of the dedupe's job.
   `add(title, signature, ref)` is called with `ref = archive/<intake_dir>/<name>`, the path the
   note is at now, so the answer still names a file a person can open. The `done/` read stays,
   unchanged, for whatever has not moved yet, so a record mid-migration dedupes exactly as it did
   before. The manifest is read through `archive.read_manifest`, so `inbox.py` gains no second
   reader of the file.
4. `tests/test_record_archive_inbox.py`: S-211575's eight lines. A processed note whose card is on
   the record moves byte for byte; one whose card is only in the manifest moves too; a retired note
   moves with its retired reference recorded; a note whose card exists nowhere stays and the dry run
   says why; the dedupe folds a title key and a signature key for every **retired** archived note
   from the manifest alone — and, the measured correction, folds **neither** key for an archived
   note that is not retired (block M3), with the ordinary-note case asserted by name so a later
   reading of S-211575's line does not widen it back; the dedupe still reads `done/` for a note that
   has not moved; a note already archived is not filed again as a new card; and the groom opens no
   archived note file (patched `builtins.open`).
