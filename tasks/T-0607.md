The spec's §4 (D4): a bare-`failed` run with a branch takes the `UNPUSHED` hold — the same
correction kind, the same rounds counter, the same `same_head_loop`, the same cap-to-adjudicate
escalation — with `lifecycle.died_text` naming the runtime's word. A run with **no** branch keeps
today's behaviour exactly: nothing to publish, nothing to hand back.

Read **PD3** (the question arm does not cover bare `failed` today — "still parked" is a change this
Task makes), **PD4** (the arm carries the rebase-conflict and stale-head refinements, copied not
refactored) and **PD12** (the name `died_text` is already taken elsewhere and means something
else) before starting.

**Files**

- `asf/workers/lifecycle.py` — `died_text(word)` beside `unpushed_text` and `empty_branch_text`
  (`:2555-2566`).
- `asf/workers/health.py` — the parked-question arm's third clause (`:753-755`), and the new arm
  after the `UNPUSHED_REASON_PREFIXES` arm and before the `EMPTY_BRANCH` one (`:766-786`).
- `tests/test_dead_run_load.py` — the hand-back, the branchless run, the park's precedence.
- `tests/test_lifecycle.py` — `died_text`'s words, and the hold's own fields for this kind.

**Steps**

1. `lifecycle.died_text(word)` — pure, one expression, the spec's sentence: `the session was cut
   off mid-flight (max turns) — its branch holds what it had done; pick the work up from there,
   finish it, and push; if it cannot be finished, say why in the report`. The parenthesis is
   present only when `word` is non-empty, and the sentence reads without it otherwise — a run
   recorded before Task 1 landed, or one whose runtime named nothing, must still get a text that
   parses as English. Docstring per PD12: it names `asf.tick.step_health.died_text` as the
   *other* one and says which is which. It appends `ALREADY_LANDED` exactly as `unpushed_text` and
   `empty_branch_text` do (`:2555-2566`) — the loop it enters is theirs, so the way out of it is
   theirs too.
2. `health.py`, the parked-question arm (`:753-755`): its third clause gains
   `or reason == lifecycle.FAILED_BARE`, and one comment line says why — a cut-off session that
   declared a question for a person is parked, not handed back, and F-0126 is the card that
   settled it (PD3). This arm stays **above** the new one and keeps its precedence by position.
3. The new arm, after the `UNPUSHED_REASON_PREFIXES` arm and before the `EMPTY_BRANCH` one, with
   the spec's two comment lines byte for byte:
   `elif reason == lifecycle.FAILED_BARE and s.get('branch'):` → `text =
   lifecycle.died_text(s.get('runtime_error'))`, then PD4's two refinements in the order the arm
   above uses them (`lifecycle.rebase_conflict(line)` → `rebase_conflict_hold` and return;
   `lifecycle.stale_head(line)` → `stale_head_text`), then `fields, line = lifecycle.hold(registry,
   s, lifecycle.UNPUSHED, text, now, main=product.main)`, `pool_mod.update_session(product, job,
   **fields)`, `found.append((job, 'held', line.split(': ', 1)[1]))` — the same five lines the
   `UNPUSHED` arm ends with.
4. `s.get('runtime_error')` is the key Task 1 writes, read off the run dict the ladder already
   holds. It is `''` for a run recorded before Task 1 landed and `died_text` handles that (step 1);
   no fallback read of the log, no second call to `error_subtype` here.
5. Nothing about the `EMPTY_BRANCH` arm, the `delivered_off_branch` arm, the quota arm, the
   `closed` return or the hook-refusal arm moves. A run with no branch falls off the end of the
   `elif` chain exactly as it does today, and the fence's second assertion is what pins that.
