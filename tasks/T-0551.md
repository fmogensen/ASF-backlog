The spec's first three `## In` bullets and `## The design` §§1–2 in full: the `Connector` dataclass and
its four vocabularies, `load`, `catalogue_entry`, `product_problems`, the six shipped catalogue
files, and the `env.validate_product_text` call-out that makes a malformed block refuse the product
file.

This Task also lands **every reader in the module** — `provided`, `approval_signals`,
`session_auth_env`, `session_home_paths`, `as_provider`, `rows` and `findings` — because the spec
puts them in one module and splitting them across five Tasks would make all five write the same
file. Each is a pure function over `load(product)`, each lands with its own test in the same commit,
and **none of them has a caller yet**: the factory's behaviour after this Task is unchanged except
that a product file carrying a malformed `connectors:` block is refused with a key and a line. That
is what makes the five reader Tasks a one-file edit each.

Read **PD1** (the file is `asf/connectors/__init__.py`, not `asf/connectors.py` — and why the
alternative is silently dead), **PD9** (the yaml subset was measured; `catalogue_entry` must test
`os.path.isfile` first), **PD10** (the three shipped product files, and the example as the pin),
**PD14** (every cross-module import is function-local) and **PD17** (both fences) before starting.

**Files**

- `asf/connectors/__init__.py` — **new package** (PD1): `CAPABILITIES`, `KINDS`,
  `SESSION_POLICIES`, `SECRET_SCHEMES`, the `Connector` dataclass, `catalogue_dir`,
  `catalogue_entry`, `load`, `product_problems`, and the seven readers
- `asf/connectors/catalogue/*.yaml` — **six new files** (PD6), one per non-`git` entry of
  `_CLI_TOOLS` (`asf/doctor.py:370-378`)
- `asf/env.py` — `PRODUCT_FIELDS` (`:516-522`) gains `'connectors': _MAP` (PD10); one call-out at
  the end of `validate_product_text` (`:664-686`), beside `credentials_mod.product_problems`
  (`:681-683`)
- `pyproject.toml` — `[tool.setuptools.package-data]` (`:27-30`) gains
  `"asf.connectors" = ["catalogue/*.yaml"]`
- `docs/products.example.yaml` — the documented block, **uncommented** (PD10)
- `tests/test_connectors.py` — **new module**: `ConnectorModelTests`, `ConnectorValidationTests`,
  `OneProviderPerCapabilityTests`, `InheritRequiresFileSecretTests`, `CatalogueTests`,
  `LegacyParityTests`, and one test per reader
- `tests/test_env.py` — a case in `ProductValidation` (`:288`) that a malformed `connectors:` block
  is refused with its dotted key and its line

**Steps**

1. Create `asf/connectors/__init__.py` with the spec's four module constants byte for byte, each
   with its `#:` comment: `CAPABILITIES = ('ci', 'deploy', 'db', 'preview', 'secrets', 'code')`,
   `KINDS = ('cli', 'token', 'oauth')`, `SESSION_POLICIES = ('none', 'inherit')` (*"the default is
   the first"*), `SECRET_SCHEMES = ('env', 'file', 'keychain')`. The module docstring names no
   vendor and no product (PD17), says that every service word in it is a value read from data, and
   records PD9's two consequences: the catalogue is read by `env.load_file` because the package is
   stdlib-only, and a `#` in a regex must be quoted.
2. The `Connector` frozen dataclass with the spec's eleven fields and its comments byte for byte.
   `provides` and `actions` default to empty dicts through `dataclasses.field(default_factory=dict)`
   — the spec writes `...` for both, which is a placeholder, not a value.
3. `catalogue_dir()` → `$ASF_CONNECTOR_CATALOGUE_DIR` when set, else `catalogue/` beside
   `__file__`, shaped exactly on `rules.core_rules_dir` (`asf/rules/rules.py:56-63`).
   `catalogue_entry(name)` → `~/.ASF/connectors/<name>.yaml` first, then
