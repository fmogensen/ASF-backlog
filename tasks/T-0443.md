The spec's remaining **In** bullets and both the `main` and the `asf/cli.py` design blocks: the flag
prints one JSON object per line and nothing else on stdout, it exits 2 — with the reason on stderr
and stdout empty — when the product or its state cannot be read, every other argv keeps the exit 0
it has today, and `asf pr-hygiene --lanes` stops being refused by argparse.

**Files**

- `asf/harvest/pr_hygiene.py` — `import json`, the module docstring's `--lanes` line, `main`
- `asf/cli.py` — `p_pr_hygiene`'s new flag and the dispatch that forwards it
- `tests/test_pr_hygiene.py` — `LanesOnStdout`, `LanesExitCodes`, `LanesThroughTheCli` (new);
  `HygieneView`'s one `--lanes` expectation rewritten

**Steps**

1. `import json` above `import sys` (PD7), and the module docstring's usage line becomes the new
   shape — `pr_hygiene.py --lanes    one JSON object per PR in a lane: {pr, branch, lane, since,
   action}`. The other three usage lines and the two rendered-row lines above them are untouched.
2. `main` takes `listing = '--lanes' in argv` before the `try`, so the error path can see it.
3. The `except` keeps its four exception types, keeps printing `pr_hygiene: <e>` on **stderr**, and
   returns `2 if listing else 0`, with the spec's comment byte for byte: a listing's caller must be
   able to tell "ASF owns nothing" from "ASF could not be read", and 2 is a *check failure* to the
   rule contract, never a pass (D7, D8, P14). Every other argv keeps exit 0 exactly as it has it
   (D9, P7) — a session or an operator reading the rows is not a rule check.
4. The `--lanes` branch becomes `for entry in _entries(found): print(json.dumps(entry,
   sort_keys=True))`, **inside the `try`** and over the rows already read (PD4) — one read of the
   lane registry per invocation, and no exception from a second one escaping to `cli.main` to print
   a `NEEDS OPERATOR` sentence into the middle of a listing (P8). `sort_keys=True` and no `indent`
   make the line byte-stable (D10). Nothing else reaches stdout on this path: no header, no count,
   no trailing blank. No row prints nothing and returns 0.
5. `--close` and the default rendering keep every line and every exit code they have (§What stays
   exactly as it is).
6. `asf/cli.py:262`: `p_pr_hygiene.add_argument('--lanes', action='store_true', help=…)` with the
   spec's help string. `asf/cli.py:522`: `if args.lanes: pr_hygiene_args.append('--lanes')` before
   the call, so the module's rc is the command's rc. `asf/surface.py` is not touched — `pr-hygiene`
   stays read-only and `flag` names what makes a command *write* (P9, D1's §Out); `tests/test_surface.py`
   reads the table with no reach into the parser (PD10), so a new argparse flag moves no row and the
   plugin, which names `pr-hygiene` nowhere (P10), is not regenerated.
7. `LanesOnStdout` — the card's own test, through `main` with `env.load_product` and `env.state_dir`
   patched to the fixture the way `HygieneView` already patches them: a cached state with two PRs in
   two lanes prints exactly two lines, each parses with `json.loads`, each has exactly the five keys,
   and the two carry the two lanes; and stdout is byte-equal to
   `''.join(json.dumps(e, sort_keys=True) + '\n' for e in pr_hygiene.lanes(product))`, which pins
   the encoding rather than re-describing it. An empty cache prints nothing — `''`, not a blank
   line — and returns 0.
8. `LanesExitCodes` — `env.load_product` patched to raise `env.ConfigError`: with `--lanes` the rc is
   **2**, stdout is `''` and the reason is on **stderr**; the same failure with no flag is rc **0**
   (D9); an `OSError` from the state read takes the same two paths. And no network call on any of
   them: every case runs with `asf.harvest.lane`'s host reader patched to raise if it is touched, so
   a listing that reached for `gh` would fail the test rather than merely be slow (P5).
