**Steps**

1. `conventions.feedback`: `repo` (unset ⇒ the product's own `repo_slug`), `label`, `types`
   (issue label → card type), `max_per_tick`, `max_body_lines`, merged per key over
   `DEFAULT_FEEDBACK`. `'feedback'` joins `MAP_CONVENTIONS` so a misshapen block is a red doctor
   row rather than a silent default (PD14), and `docs/products.example.yaml` documents every key.
2. `pull` asks `gh issue list -R <feedback.repo or repo_slug> --state open --label <label>
   --limit N --json number,title,labels,body,url` through `metrics.gh_json`
   (`asf/metrics/metrics.py:817`), which returns `None` rather than raising. `None` — offline, no
   `gh`, a refused scope — is one line on stderr and an empty return, exactly as
   `publish_github_release` degrades. Number, title, labels, body and URL, and **nothing else**:
   the author, assignees, reactions and comments are never read (§1.2, D5).
3. An issue is skipped when any item's `links.issues` holds its number, when
   `<intake_dir>/issue-<n>.md` exists, or when `<intake_dir>/done/` holds a file whose `issue:`
   header is that number. The first is the steady state; the second and third close the window
   between the file being written and the item existing.
4. The card written is the shape `asf inbox` writes plus one header, exactly as §2.5's example
   block gives it: `issue: <n>`, `type:` from `feedback.types[label]`, `severity:`, the
   `Reported on issue #<n> — <url>` line, and the body quoted under `## Reported`. An `idea`
   writes **no** `type:` header, so `asf.groom.shape.derive` shapes it or asks its question and a
   human answers.
5. Title and body both go through `redact.scrub(text, redact.default_patterns(root))`
   (`asf/redact.py:235,248`); `@mention`s are replaced with the same token; the body is cut to
   `max_body_lines` with a `> … (<k> more lines on the issue)` last line. At most `max_per_tick`
   cards per run, lowest issue number first, so a flood arrives over several ticks in the order it
   was reported.
6. Each file is written and `publish`ed the way `cmd_inbox` publishes (`asf/groom/inbox.py:150`),
   so the record's clone and the trunk both carry it.
7. `INBOX_KV_RE` gains `issue` beside `type|parent|signature|severity|writes|stories`, and
   `process_inbox` puts it into the minted item's typed fields as `links: {issues: [<n>]}` — the
   one level of nesting `asf/record/frontmatter.py:158` already writes for `links.prs` and
   `links.branches` (P5). `## Reported` is body like any other section; the existing
   `_lift_section` calls are untouched.
8. The card is **undecided**: `process_inbox` mints with `decided: False` and this Task changes
   nothing abou
