## Description
stories: S-31108

after: Task 1

§2.7 and §2.12's doctor half. The generated settings file is what `spawn` will pass as `--settings`
in Task 4, so it lands first; all three doctor rows land here too, ahead of the fixture sessions,
because T6's last clause asserts a doctor row names a flag the installed runtime lacks and T9's
asserts the `worker-deny` row goes red on a deleted rule. Nothing here is passed to a launch yet.

**Files**

- `asf/workers/worker_settings.py` — **new**, built on `console_perms`'s shape (P17):
  - `FIXED_DENY` — §2.7's tuple verbatim: the secret-file reads, the environment printers, the
    unverified commit and push, the force push, `WebFetch` and `WebSearch`. The one comment that
    matters is §2.7's first note: `hermetic.build` in worker mode strips the environment to the
    allow-list and then `build_env` puts the live credentials back (`asf/workers/runtime.py:390`),
    so a session that prints its environment prints a usable token today.
  - `deny_rules(product, launch)` — `FIXED_DENY`, plus `Bash(git push origin <trunk>:*)` from
    `product.conventions.main` (never the literal — the conventions lint generates an anchored
    pattern for the default trunk name), plus one entry per tool in `launch.deny_tools`, plus one
    `Read` rule per secret directory the product's config names.
  - `allow_rules(product, launch)` — the role's own tools as `allow` entries, so the file states
    what the role *is* for as well as what it is not.
  - `settings(product, launch, operator_path=None)` — the operator's own
    `worker_pool.settings_file` read first (`spawn.settings_file(wp)`'s path, which already refuses
    a path that does not exist), then this role's rules merged **over** it with
    `console_perms.merge`'s discipline: append what is missing, keep order, touch no other key. A
    second call over the written file changes no byte.
  - `missing(settings, product, launch)` — the rules absent from a settings object, in order, for
    the doctor row, in `console_perms.missing`'s shape.
  - `path(product, launch, wp)` → `<state>/<product>/worker-settings/<role>.json`, written only
    when it differs from what is there.
  - `offer_text(product)` — every rule, per role, in full, in `console_perms.offer_text`'s shape.
  - `cmd_worker_permissions(args)` — `offer` prints; `install` writes every role's file and prints
    what it wrote.
- `asf/cli.py` — one parser: `worker-permissions` with a positional `worker_permissions_command`
  of `choices=['offer', 'install']` and `--product`, in `console_perms.register`'s shape
  (`asf/console_perms.py:154-163`), registered beside it.
- `asf/doctor.py` — three rows, each a `check_*` returning `(ok, detail)` and one `rows.append`
  beside the existing `worker secrets` and `worker push auth` rows (`:840-845`):
  - `role-launch` — red when a role file in `roles.roles_dir()` has no `TABLE` row or a row names
    no role file; red when `worker_pool.permission_mode` is set and differs from the table's mode
    for any kind, naming the kinds it flattens and, per **PD8**, that a pool-wide
    `bypassPermissions` also switches off the prober's `--restricted`. The detail always ends with
    `capability.missing()`'s list, which is what T6's last clause reads.
  - `worker-deny` — red when a role's settings file is missing a rule of `deny_rules`, naming the
    rule and the one command that fixes it (`asf worker-permissions install --product <p>`), in
    `console_perms.check_doctor`'s shape (`asf/console_perms.py:108-124`).
  - `worker-redaction` — red when a live session's log carries a `redact` match. Built on today's
    API only: `redact.default_patterns(repo)` and `redact.scan_text` over the log's lines, live
    sessions from `pool`. A finding never carries the matched text (`asf/redact.py:6-8`), so the
    row is safe to print.
- `tests/test_worker_deny.py`
