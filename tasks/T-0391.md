§2.3. Two `int` keys with a `0` default join the `ticks` schema and the non-negative check, `quota_held`
joins `ctx.counts` and `quota_seats` becomes an attribute of the tick context, and `tick_line` folds
both in beside `quota` and `refused_files`. After this Task every live tick line carries both, at
zero, and nothing yet writes anything else: Task 3 is what makes them non-zero.

The two keys and `tick_line` cannot be split across Tasks — `tests/test_tick.py:893` asserts every
key `tick_line` writes is a key of the schema (PD9).

**Files**

- `asf/metrics/metrics.py` — `SCHEMAS['ticks']` gains `quota_held` and `quota_seats`; the
  non-negative loop at `:264` gains both
- `asf/tick/tick.py` — `Context.counts` gains `quota_held`, `Context.quota_seats` is new,
  `tick_line` writes `quota_seats=ctx.quota_seats`
- `asf/tick/watch.py` — `COUNTER_KEYS` gains `'quota_held'` and not `'quota_seats'`
- `asf/tick/summary.py` — `digest`'s docstring names the sixth counter
- `tests/test_quota_pressure.py` — `TickLineTests`

**Steps**

1. `asf/metrics/metrics.py`: in `SCHEMAS['ticks']`, after `'refused_files'`, the two keys exactly as
   §2.3 writes them — `'quota_held': (('int',), 0), 'quota_seats': (('int',), 0)` — under §2.3's
   two-line `#:` comment, which is copied as it stands: the ready rows the quota guard's seats would
   have taken this tick, and the seats it was holding when the wave read the pool.
2. The non-negative loop at `:264` gains `'quota_held', 'quota_seats'`, in §2.3's own order. Its
   message is already `f"ticks: {k!r} must be >= 0"`, so the §3.4 fence's expected line needs no
   formatting change.
3. `asf/tick/tick.py`: `self.counts` at `:165` gains `'quota_held': 0`, and `self.quota_seats = 0`
   goes on the line after it, with a one-line comment saying why it is an attribute and not a
   counter — the digest prints every non-zero member of `counts`, and a denominator that is
   non-zero whenever one account cools would print on most ticks and say nothing (D14).
4. `tick_line` at `:611-616`: `quota_seats=ctx.quota_seats` beside `quota={}` and
   `refused_files={}`. `quota_held` needs no mention there: it rides in through `dict(ctx.counts, …)`
   (P3). Do not touch `quota={}` — it stays empty on every live tick, and D's own reason is that
   filling it would put an account name in a record that carries only an index (B-0023).
5. `asf/tick/watch.py`: `COUNTER_KEYS` becomes the six-tuple ending `'quota_held'`. `quota_seats`
   stays off it, and a short comment on the line says so with D14's reason, so the next reader does
   not "complete" the tuple.
6. `asf/tick/summary.py`: `digest`'s docstring at `:177-179` names the counters it prints; add
   `quota_held` to that list. No code changes — `digest` already prints every non-zero key of
   `counts`, which is how `quota_held` reaches the `TICK —` line (PD10).
7. `tests/test_quota_pressure.py`, `TickLineTests`: (a) a fresh `tick.Context(env.Product('sample',
   {}))` with no step having run produces a `tick_line` carrying `quota_held: 0` and
   `quota_seats: 0`, and `metrics.validate('ticks', line, {})` accepts it; (b) `set(line)` is a
   subset of `SCHEMAS['ticks']` — the same assertion `tests/test_tick.py:893` makes, restated here
   so this module fails for its own reason; (c) `ctx.counts['quota_held'] += 2` and
   `ctx.quota_seats = 3` reach the line as `2` and `3`; (d) `validate` refuses `quota_held: -1` and
   `quota_seats: -1` with the exact message the §3.4 fence prints; (e) a tick line with **neither**
   key — the shape every line already on disk has — is read back by `metrics.read_file` unchanged
   and still lacks them, and `validate` over that same dict fills `0`. (e) is P5, and it is what
   Task 4's `measured` list depends on.
