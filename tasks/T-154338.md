**Steps**

1. Create `asf/record/card.py` with the nine names §2.2 tables: `SCHEMA` (the parsed schema,
   loaded once, from Task 1's file), `path(root, folder, iid)`, `view_path(card_path)`,
   `load(path)`, `loads(text, path)`, `validate(meta, root=None)`, `dumps(meta)`,
   `render(meta, derived)`, `split_machine(meta)` and `refs(meta)`. In this Task `validate`
   implements the **shape** half only and ignores `root`; Task 6 adds the reference half behind
   the same signature, so no caller changes twice.
2. `path` returns `<root>/<folder>/<iid>.json` when that file exists, else the `.md` — a schema-1
   record. `load` returns `(meta, body)` where `meta` is the **flat** dict every existing reader
   already indexes (D-0004) and `body` is the prose rendered as markdown, so `rec['body']` keeps
   working for every reader that only displays it.
3. `dumps` is one canonical form: 2-space indent, keys in the order the schema declares them,
   exactly one trailing newline. Writing an unchanged card must change no byte, and
   `load(dumps(meta))` must give back the same field map — those two are what make a card's diff
   only what changed.
4. `split_machine` reads the schema's `"owner"` annotation instead of the `# ---- machine ----`
   marker, and keeps `frontmatter.split_machine`'s signature and return shape exactly, so the
   hundreds of readers that call it are unchanged. `refs` reads the `"ref": "card"` annotation and
   returns `[(field, index, id)]` — the reference fields come from the schema, never from a list
   in code.
5. `render(meta, derived)` writes the `.md` view: the frontmatter block as today for continuity of
   the eye, then `## Description`, `## Acceptance` as `- [ ]` lines, `## Gate` as a fenced block,
   `## History`, and the derived `## Children` / `## Backlinks`. Rendering twice must give the
   same bytes, and the view must carry no machine field the schema does not declare.
6. `core.load_items` (`asf/record/core.py:109`) gains the one branch that makes the migration
   survivable: in each item folder a `*.json` is a card read by `card.load`; a `*.md` **with** a
   sibling `.json` is that card's view and is skipped; a `*.md` **without** one is read by
   `frontmatter.parse` exactly as today, including the `FrontmatterError` path that appends to
   `parse_errors` and drops the card (`:130-134`). A card with both files present is counted
   exactly once. Leave `frontmatter.py` whole: it is the schema-1 reader Task 10 converts with and
   the renderer of the view's frontmatter block.
7. Create `tests/test_card_api.py` covering S-133156's twenty lines, including the three scan
   cases over a scratch record holding a JSON card, a markdown card, and one of each with a view.
