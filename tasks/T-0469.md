## Description
stories: S-33454

after: Task 4, Task 5

The spec's guide section: the three passages that today make the manual pull a step, rewritten to
say what the factory does, what the first line says when it could not, and what the operator's own
writes still need. Prose about what Tasks 4 and 5 print on a terminal, so it lands after both and
quotes them rather than paraphrasing.

**Files**

- `docs/guide/operating.md` — the opening (`:7-9`) and the groom's step 1 (`:292`)
- `docs/guide/product-config.md` — *The two copies of the record* (`:45-62`)
- `tests/test_readme.py` — new `RecordCopiesProseTests`

**Steps**

1. `operating.md`'s opening loses the manual step and gains the spec's replacement paragraph: the
   tick fast-forwards the checkout after every run; when it cannot — local changes, or a branch —
   the tables read the tick's own clone and their first line says so, with the age and the one
   command; `asf doctor`'s `record` row says the same thing standing still. The link to
   [the two copies](product-config.md#the-two-copies-of-the-record) is kept: the section it points
   at is where an operator goes next, and Task 6 rewrites that too.
2. `operating.md`'s groom step 1 (`:292`) becomes *your checkout is already current (see above);
   commit and push what you write there*. The section's closing sentence keeps the part that is
   still true and is the reason the step existed: the tick never *reads* the checkout, so an
   answer written there reaches it only when it is pushed.
3. `product-config.md`'s *The two copies of the record* keeps its table and rewrites its last
   paragraph to the spec's text, including both example `record:` lines in a fenced block — the
   plain one and the fallback one — the sentence that no table reads a card, so the fallback can
   never hide an edit, and `ASF_RECORD=checkout` as the way to pin the read and compare the two.
4. **And the one sentence above it that a landed commit already made false (PD11).** The paragraph
   at `:55-57` ends *"It reads your checkout once, for the `origin` URL, and never writes it."* —
   untrue since `47c3e9d11`, and it would otherwise sit three lines above a paragraph saying every
   tick ends by fast-forwarding that checkout. It becomes: the tick reads the checkout for the
   `origin` URL, and the one write it ever makes there is the `--ff-only` fast-forward at the end
   of the run — which can create no commit and lose no work. One clause, in the section the spec's
   `## Records` already names.
5. The two example lines are the **exact** strings `freshness.line` produces, checked against
   Task 3's `TheRecordLine` rather than retyped, with the machine-specific path written as
   `/path/to/record` and the state path as `~/.ASF/state/<product>/record` — no worker account
   name and no real machine path anywhere in either file.
6. `RecordCopiesProseTests` in `tests/test_readme.py`, reading both guides **from the checkout** as
   `ProductResolutionProseTests` already does (`tests/test_readme.py:399-421` is the precedent and
   the shape): `operating.md` no longer carries `Before you read a table, `git pull`` nor a groom
   step that opens `Pull your record checkout`; both files name the fast-forward; `product-config.md`
   carries both example `record:` lines, `ASF_RECORD`, and the sentence that no table reads a card;
   and `product-config.md` no longer carries `and never writes it` (PD11). Each assertion names the
   clause it is pinning, so a later rewrite is told which sentence it broke.
7. `bash tools/check_generic.sh` before the push, over both guides: no product, company, person or
   worker account name, and no machine path. The redaction check is part of this Task's Gate and
   not an afterthought, because this is the only Task whose diff is prose an operator wrote.
