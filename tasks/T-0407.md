§2.6: `asf uninstall --product <p> [--dry-run]` takes away what the install put on the machine and
leaves the record, the repos and the operator's config exactly where they were.

**Files**

- `asf/install.py` — `cmd_uninstall`, `register_uninstall`, the target table
- `asf/init.py` — `register_commands` also registers `asf uninstall`
- `asf/release.py` — `install_log` skips the uninstall rows (PD8)
- `tests/test_install.py` — `UninstallTests`

**Steps**

1. The clocks: every loaded job labelled `<label_prefix>.<p>.*` is booted out and its plist
   removed through `scheduler.uninstall(label)` (`asf/scheduler.py:477`), found through
   `scheduler.loaded_jobs` (`:614`) so the never-declared `ci-queue` clock is included. Another
   product's jobs and a legacy label the operator still declares are left alone.
2. The runtime hook entries: the entries `hooks._is_ours` recognises are dropped from every
   account settings file (`asf/hooks.py:246`, `:276`); every other key in that file is kept.
3. The git hooks: the `pre-commit` / `pre-push` files ASF wrote in `repo_dir` and `backlog_dir` are
   removed when `hooks.is_git_hook_ours` says they are ours (`asf/hooks.py:92`); a foreign hook is
   reported `left (not ours)` and kept.
4. The plugin tree: `<ASF_HOME>/plugin` is removed; the checkout's own `plugin/` is never touched.
5. Untouched, and asserted so: the record, both repos, `<ASF_HOME>/config.yaml`, `products/`,
   `state/` and `logs/`. An uninstall is not a wipe (D9).
6. One row per target — `removed`, `absent`, or `left (not ours)` — then the one command it will
   not run itself: `asf uninstall: the package itself: pipx uninstall asf-factory`.
7. `--dry-run` prints the same table and removes nothing.
8. The log: one `<utc>\t<product>\tuninstall` line appended to `<ASF_HOME>/logs/install.log`, and
   `release.install_log` skips rows whose ref is `uninstall` so the readiness view keeps counting
   installs by hand and not teardowns (PD8).
9. `register_commands` gains `asf uninstall` beside `asf install` (PD13).
10. `UninstallTests`: a fixture `<ASF_HOME>` with two products' plists, one legacy label, an
    account settings file carrying one ASF entry and two foreign keys, an ASF `pre-commit` and a
    foreign `pre-push`, and a generated plugin tree. The table names each row's verdict; only this
    product's jobs go; the foreign hook and the foreign settings keys survive; the plugin tree is
    gone and the checkout's `plugin/` is untouched; `config.yaml`, `products/`, `state/`, `logs/`
    and both repos are byte-identical afterwards; `--dry-run` changes nothing on disk; the last
    line names `pipx uninstall asf-factory`; the log row is written, and
    `release.install_log` over that same file returns the install rows and not the uninstall one.
