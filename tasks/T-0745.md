The spec's `## In` bullet for `conventions.legacy_branch` / `conventions.legacy_review` and
`## The design` §1 in full. Two fields of `Conventions`, two checks in `validate_mapping`, and
`branch_prefixes.legacy` documented as the one place a pre-ASF prefix is named.

Nothing reads either field when this lands, and that is why it can land first: the declarations are
the vocabulary the next five Tasks speak. What changes today is only that a misshapen one stops
being silent — P15 measures `legacy_branch: 12` kept verbatim and reported nowhere.

`asf/env.py:684-687` already turns each `(key, why)` `validate_mapping` returns into a dotted config
problem, so **no new call site is written** and `tests/test_env` needs no edit: it is asserted green
as the proof that the new problems reach the operator through the path the others already take.

**Files**

- `asf/conventions.py` — `legacy_branch` and `legacy_review` as fields of `Conventions`, beside
  `reports_dir`/`report_pattern` (`:694-695`), each with the spec's `#:` comment; `validate_mapping`
  (`:466-…`) gains both checks and its docstring's list of checked keys goes from ten to twelve
- `tests/test_conventions.py` — `LegacyBackfillKeys`

**Steps**

1. `legacy_branch: str = None` and `legacy_review: dict = None` as fields of `Conventions`, with the
   spec's `#:` comments byte for byte (§1's fenced block). Place them beside `reports_dir` /
   `report_pattern` at `:694-695`: those two are the other pre-ASF-migration conventions, and
   `report_pattern` is a regex-valued field with a `None` default, the exact precedent for both
   shapes. Declaring them as fields moves them out of `from_mapping`'s `extra` — measured,
   `'legacy_branch' in Conventions.field_names()` is `False` today and must be `True` after — which
   is what makes `conv.legacy_branch` an attribute rather than a `.get` and is the whole of P15's fix
   on the read side.
2. `validate_mapping` (`:466`) gains `legacy_branch`: one problem naming the key when it is not a
   string, when it is empty after `strip()`, when `re.compile` raises, or when `'slug'` is not in the
   compiled pattern's `groupindex`. Shape it on `full_suite_commands` (`:484-497`) — the existing
   *"a regex that must compile"* check — and reuse its `except re.error as e` wording so two regex
   problems read alike. One problem per key, never two: the checks are `elif`-chained after the type
   test, because `re.compile(12)` raises `TypeError`, not `re.error`.
3. `validate_mapping` gains `legacy_review`: one problem when it is not a mapping; then one when
   `glob` is missing, not a string, or empty after `strip()`; then one when `verdict_regex` is
   present and either not a string or not compilable. `verdict_regex` absent is **not** a problem —
   D14 makes the declaration only ever able to *skip* a review, so a glob with no verdict pattern
   degrades to honouring nothing, which is today's behaviour.
4. `validate_mapping`'s docstring (`:467-471`) names its checked keys — *"Only `doc_paths`,
   `shared_paths`, `lane`, `worktree_setup`, `pre_push_check`, `auth_env`, `full_suite_commands`,
   `customer_content`, `security` and `feeder` are checked"* — and gains both new keys in the same
   commit. A stale list there is the drift the docstring exists to prevent.
5. Document `branch_prefixes.legacy` as the one place a product names a pre-ASF prefix (D8), in the
   `#:` comment of the new `legacy_branch` field: the key is not new and gets no code, but a reader
   arriving at `legacy_branch` must be told that the *prefixes* go elsewhere and that `branch_kind`,
   `orphan_claims`, `unclaimed_legacy` and `retention.legacy_prefixes` already read them. Name F-0130
   and D8.
