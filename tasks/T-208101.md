**Steps**

1. `asf/kernel/resolvers.py`: §2.6's `NO_CI_JOB_RE` verbatim, and one more alternative in `match`'s
   `gate` branch (`:203-205`): a question is `gate` when today's `NOT_RUN_RE`/`HOST_RE` pair fires
   **or** `NO_CI_JOB_RE` does. The existing pair is untouched, and as today exactly one backticked
   command and a known `branch` are required — otherwise no match. This is the only change this
   Feature makes to `match` (**PD3**), and `gate` stays in `PROBED` and in `CODED`, widened in
   place and not renamed (D-0001).
2. `asf/kernel/trunk.py`: `TrunkProbe.__init__` gains `read_only=False` and `declared=()`, held as
   `self.read_only` and `self.declared`; `enabled[R.GATE]` becomes
   `bool(self.gates) or bool(read_only)` — without that the class is off for any product with no
   `pre_push_check` and the widening is unreachable (**PD7**, measured).
3. `for_product` passes `read_only=bool(k['resolve']['gate_read_only'])` and
   `declared=readonly.declared_commands(product)` — computed once per tick, not once per command
   (**PD9**). The import is local to the method, as `gitops`' and `hermetic`'s are in this module.
4. `_gate` (`:163-180`) keeps its shape. Rule 1 stands exactly where it is and returns today's
   refusal **when `self.read_only` is false**; when it is true, a command rule 1 misses goes on to
   the fetch, the sha and the cache key unchanged, and rule 2 is judged **inside** the worktree
   callback, where the path exists (**PD8**): `_gate_in(wt, cmd)` returns `self._shell(wt, cmd)`
   when `readonly.grant(cmd, wt, [wt], self.declared)` grants it, else
   `{'error': REFUSED % cmd, 'refused': True}` with `REFUSED = '`%s` is neither a pre_push_check
   step nor read-only'`. `_gate` returns a `refused` result with `ran = 0` and **does not cache
   it**. The refusal rule 1 gives when `read_only` is off keeps today's wording for a product that
   has not turned the widening on, and takes the widened wording when it has.
5. Nothing else about the probe changes: the same fetch, the same fresh detached worktree of
   `origin/<branch>`'s head, the same clean floor, the same `gate:<cmd>@<sha>` cache key, the same
   `test_runs_per_tick` charge, and the same `{sha, rc, last}` result through `answer()`'s existing
   `GATE_GREEN`/`GATE_RED`. `read_roots` is the worktree **alone**, so a command naming any path
   outside it is refused — that is the whole safety argument, and **PD9** measures it.
