§2.10: a sixth signature source beside the five `asf/tick/file_bugs.py` already has, needing no new
machinery — a function and one call in `cmd_file_bugs`. It reads `metrics/probes/*.jsonl` by glob,
so it needs only Task 4's line shape and runs beside Tasks 5 and 7.

**Files**

- `asf/tick/file_bugs.py` — `PROBE_TITLE`, `probe_signatures(root, now, conv=None)`, one call in
  `cmd_file_bugs` (l. 521-524)
- `tests/test_file_bugs.py` — T7, and a `metrics/probes` fixture beside the module's existing ones

**Steps**

1. `probe_signatures(root, now, conv=None)`: one entry per **failed** journey in
   `metrics/probes/*.jsonl` inside the last 24 h, the window and glob shape `ci_signatures`
   already uses (`asf/tick/file_bugs.py:61`).
2. Signature `probe: <journey>: <step>` — the same journey failing at the same step after the next
   deploy bumps the existing Bug rather than filing a second, which is what the typed `signature`
   field is for. A *different* step on the same journey is a second Bug.
3. `severity: 'S1'`, always. The card says severity one, and a customer journey that does not work
   on production is the definition of it.
4. `title: truncate(f"{PROBE_TITLE}{journey} — {step}", 120)`.
5. `evidence`: one line per occurrence — `run <id> at <sha7> <ts>: <journey> stopped at <step>
   (<detail>)` — capped at the module's evidence cap, keeping the newest (PD15).
6. `runs`: the probe run ids, which `_file_or_bump_bug` merges into `links.runs` (l. 339-343);
   `places`: the item the journey belongs to, when it has one. `runs` is always present, `[]`
   included (PD15), and no `links` key is written.
7. An `unrunnable` journey and a `pass` file nothing: nothing in production failed.
8. `cmd_file_bugs` calls it as it calls the other four (l. 521-524), under the same
   `approvals.level_of(product, 'file_bug')` gate — no special case.
9. `tests/test_file_bugs.py`: T7 — one entry over a stream with one failed journey, with its
   severity, signature, title prefix, evidence and `places`; filed under `default_bug_epic`; a
   second run the same day a no-op; the same journey failing again after the next deploy bumping
   `count` and merging `links.runs`; a different step a second Bug; `unrunnable` and `pass` filing
   nothing; and the `file_bug`-at-`groom` hold the filer already prints. The fixture gains a
   `metrics/probes` directory and a `write_probe_line` helper beside the existing writers.
