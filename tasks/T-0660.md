## Description
stories: S-36751
writes: asf/workers/lifecycle.py, asf/workers/health.py, tests/test_lifecycle.py
after: none

The spec's `## The design` §2 in full, and nothing else. After this lands, a health pass runs one
`git status --porcelain` per worktree per *version* of that worktree instead of one per question,
and the commit, reset, cherry-pick and push the factory makes inside the pass are still seen,
because every one of them moves the key.

**Read PD2 before touching `asf/workers/health.py`.** The spec says to build the snapshot *"beside
the `RemoteHeads` it already builds at `:810`"*. Seven of the nine `gather` sites run before that
line, inside `run_steps` at `:795`. Built at `:810` the snapshot serves two sites out of nine and
§3.2's load-bearing test is not even exercising it. It goes in `health`'s body **above** `run_steps`
— and PD2 is also why that is safe for this snapshot and would not be for `RemoteHeads`, which
stays exactly where it is.

**Read PD3 before threading anything into `publish_gap`** — the seam is the lambda at `:795-796`,
not the generators' yielded tuple. **PD4** for why no lock. **PD10** for `unpublished` and for the
`push_gap` name collision. **PD11** for the six dead helpers that are named and left alone.

Two things are load-bearing. **`--untracked-files` is not passed** (D8): an untracked file is a
porcelain line, so `ev.uncommitted > 0`, so `Evidence.pushed` is False and B-0051 holds the run.
`-uno` would silently pass a session that wrote a new file and never added it — turning a held run
into a finished one, which is the exact failure B-0051 exists to catch, and it is the card's own
first suggestion, refused. **The key is what a mutation moves** (D7): `(realpath(wt), HEAD sha,
index mtime_ns, index size)`. A memo keyed on the worktree path alone would answer `publish_gap`'s
re-gather with the pre-commit status and call a just-published run unpushed.

**Files**

- `asf/workers/lifecycle.py` — `class WorktreeStatus` beside `RemoteHeads` (`:1750-1779`) and
  following it exactly, with §2's docstring and PD4's sentence about why it holds no lock. Its key
  is read off the files the way `_common_git_dir` (`:1726`) already does but **stopping at the
  worktree's own git dir rather than following `commondir`** — a linked worktree's index lives in
  its own git dir, not the common one — so the key costs no subprocess. `lines(wt)` returns the
  **non-blank** porcelain lines, so `len(lines)` is today's `ev.uncommitted` exactly (`:1796`), and
  returns None only when `git status` itself exited non-zero. A worktree whose git dir cannot be
  read still gets its status run and is simply not cached (§2) — `None` means *the status failed*,
  not *the key was unavailable*; do not collapse the two, because `gather` returns early on the
  first and must not on the second. Then the keyword: `gather(product, run, alive=None,
  worktree=None, heads=None, status=None)` and `unpublished(wt, branch, main='main', status=None)`,
  each defaulting to *ask*, so a caller that passes none is byte-for-byte unchanged. Mind that the
  two read a failed status differently and keep it that way: `gather` returns `ev` early
  (`:1792-1794`), `unpublished` treats it as `n = 0` (`:1847-1848`).
- `asf/workers/health.py` — the snapshot built once in `health`'s body after the `alive` resolution
  (`:652`) and above the `steps` closure, so the closure captures it (PD2); `status=` passed at
  `:689`, `:699`, `:715` from the closure, at `:816` and `:819` in the reap loop beside the `heads=`
  they already pass, and into `publish_gap` through the lambda at `:795-796` (PD3). `file_review`
  (`:363`) and `republish_steps` (`:510`) each gain a `status=None` keyword and are handed the
  closure's snapshot at their call sites, so `:385` and `:528` are covered. `run_steps` (`:459`),
  its docstring, and the five-long yielded tuple at `:719` and `:529` are **not** touched (PD3).
  The `heads=` gap at the seven per-run sites is **not** closed — O4.
