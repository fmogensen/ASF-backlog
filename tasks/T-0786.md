## Description
stories: S-37256
writes: asf/workers/spawn.py, asf/workers/runtime.py, tests/test_connectors.py, tests/test_worker_env.py
after: new 2

The spec's seventh `## In` bullet and `## The design` §6, **through the one carrier the one kind
has**: `home:`. The variable carrier, `env.product_auth_env`'s merge, `asf/redact.py`'s pattern
question and `tests/test_redact.py` all leave with `secret:` (**RD2**) — which is why this Task
touches two modules instead of three and no longer carries the card's one real hazard.

What stays is **PD3**, in full: the spec puts the `extra=` argument at the wrong call site, and the
one it names fires on a minority of launches.

Read **RD2** and **PD3** before writing anything.

**Files**

- `asf/workers/runtime.py` — `Job.__init__` (`:33-36`) gains `home_seed=()`; `seed_home` (`:204`)
  and `_seed_home` (`:216`) gain `extra=()`; `ClaudeCodeRuntime.run`'s call (`:523`) passes it
- `asf/workers/spawn.py` — `connectors.session_home_paths(product)` computed once and passed into
  the `seed_home` call (`:911`) and the `Job` (`:1014`)
- `tests/test_connectors.py` — `SessionInheritTests`
- `tests/test_worker_env.py` — the seeded home, and the environment that does not change

**Steps**

1. **PD3 first, re-measured at this checkout (RD6):** `seed_home` has two callers —
   `asf/workers/spawn.py:911`, inside the worktree-setup path that runs only when the product
   declares `conventions.worktree_setup` and the tree has not already run it, and
   `asf/workers/runtime.py:523`, inside `ClaudeCodeRuntime.run`, which runs at **every** launch.
   `job.product` is a **string** (`spawn` passes `product.name`), so the runtime call site cannot
   load the product. Editing only the spawn site would seed a connector's login for the subset of
   launches that happen to run a setup command, and never for the rest.
2. `Job.__init__` gains `home_seed=()` beside `product_auth_env`, stored as a list, with a comment
   naming it as the product's connector-declared seed paths and F-0185. A keyword with a default
   changes no existing caller — do not make it positional.
3. `seed_home(acct, operator_home=None, extra=())` and `_seed_home` append `extra` to
   `acct.home_seed` before the copy loop. The docstring's *"Nothing but the listed paths ever enters
   that home"* stays true and gains *"and the paths its product's `sessions: inherit` connectors
   declare"*.
4. `ClaudeCodeRuntime.run` becomes `seed_home(job.account, extra=job.home_seed)` — the call that
   runs at every launch, and the whole reason PD3 exists. `spawn` computes
   `home_seed = connectors.session_home_paths(product)` once and passes it into the `seed_home` call
   at `:911` and into the `Job` at `:1014`, through a function-local import (PD14). **Do not load
   the product from `job.product` inside the runtime**: that puts a product-file read on every
   launch inside the one class that must stay a thin process wrapper.
5. `asf/env.py` is **not** edited and `asf/redact.py` is **not** in this footprint (RD2). A
   `home:`-seeded login is a file copy, exactly as `account.home_seed` has always been — asf reads
   no byte of it, so there is no value to scrub and no pattern to add. Say this in the commit body,
   with RD2 named, so the next reader of the spec's D8 does not re-derive it.
6. `sessions: none` — the default (D7) — seeds nothing, and a connector declaring no `home:` cannot
   be `inherit` at all (RD3's refusal). A product with no connectors gets a **byte-identical** seeded
   home and a byte-identical environment, which is the spec's own acceptance and is what
   `session_home_paths` returning `[]` buys.
7. `SessionInheritTests`: a `sessions: inherit` connector's `home:` paths are in the seeded home
   after a launch through the runtime's own call path (not by calling `_seed_home` directly);
   `sessions: none` puts them nowhere; a product with no connectors seeds a home equal to today's
   path for path and builds an environment equal to today's key for k
