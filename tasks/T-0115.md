## Description
stories: S-14857
writes: asf/metrics/metrics.py, asf/tick/step_health.py, tests/test_metrics.py, tests/test_tick_steps.py
after: Task 5

The spec's `asf/tick/step_health.py` and `asf/metrics/metrics.py` sections — the three readers
that file what a report says. `file_rulings` keeps its shape (`report_mod.ruling` was retyped in
Task 1) and gains nothing; the step emits one event per `bad-report` entry Task 5 puts in `found`;
the session's `reason` becomes the typed one-line summary where there is one, and the result's
text where there is not, so an ended run from before this change still reads.

**Files**

- `asf/tick/step_health.py` — `run(ctx, …)` emits `ctx.event('bad-report', job=…, item=…,
  kind=…, why=…)` for each `(job, 'bad-report', why)` in `found`; `file_rulings`'s docstring
  updated to say the ruling is the typed `ruling` field, its body unchanged (`:117`).
- `asf/metrics/metrics.py` — `session_event`'s `reason` (`:927-929`) becomes `report.summary(obj)`
  when the result carries a readable typed report, else today's first-line-of-the-text. The
  `sessions` schema (`:123`) is unchanged: no new key, no migration.
- `tests/test_tick_steps.py` — the two ruling cases and `test_the_bad_report_event_is_written`.
- `tests/test_metrics.py` — `test_the_session_reason_is_the_typed_summary`.

**Steps**

1. `session_event`: read the typed object through `report.typed(text)` (kind-less) inside a
   `ReportError` guard; on success `report.summary(obj)`, on failure the text as today. The import
   is local to the function if a module-level one would cycle.
2. `step_health.run`'s event, keyed off `found` so no second read of the registry is needed.
3. The four tests, then the suite and both checks.

**Gate**

```sh
python3 -m unittest tests.test_tick_steps tests.test_metrics -v
python3 -m unittest discover -s tests -t . 2>&1 | tail -3
bash tools/check_generic.sh

```

**Acceptance**

```sh
python3 -m unittest tests.test_tick_steps tests.test_metrics -v
```

- `test_a_ruling_is_filed_from_the_typed_report`: an ended `adjudicate` run whose result carries
  `report.render('adjudicate', ruling='the hold was an add/add conflict; the fix stands')` → the
  item's card gains that `## History` line, the run is marked `adjudicated`, and the `ruling`
  event carries the same text.
- `test_a_run_whose_typed_report_has_no_ruling_is_marked_not_filed`: `ruling: ''` →
  `adjudicated: 'none'`, no history line.
- `test_the_bad_report_event_is_written`: one tick over the twice-bad run →
  `metrics/events/<day>.jsonl` in the record clone has one `kind: bad-report` line naming the
  job, the item, the kind and the why.
- `test_the_session_reason_is_the_typed_summary`: a session whose result carries a
  `status: partial`, `pushed: no` report → the `sessions` event's `reason` is
  `report.summary(obj)`, one line; and a result with no typed report still records its text.
