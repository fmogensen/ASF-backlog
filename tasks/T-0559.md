## Description
stories: S-37152
writes: asf/workers/lifecycle.py, tests/test_lifecycle.py
after: none

The spec's `## Decisions → In` bullet 3 and `## The design` §3 in full: `git_error`, and the two
refusal sites that stop returning the last non-empty output line. git prints its fast-forward hint
**last** and its `failed to push some refs` summary second-last, so "the last line" is reliably the
one line that carries no information — which is how `hook_refusal_hold` came to hold sessions on a
message with nothing in it to act on.

Read **PD8** (no existing assertion pins `why[-1]` — the two lines are untested today, which is why
the text survived), **PD9** (both streams, and the redaction branch that must still win) and
**PD10** (`push_failure`'s classification, the one thing this can silently break).

**Files**

- `asf/workers/lifecycle.py` — `GIT_ERROR_RE`, `GIT_PUSH_SUMMARY_RE`, `GIT_ERROR_LINES` and
  `git_error`, new; `publish`'s refusal (`:1643-1644`) and `commit_leftovers`' refusal
  (`:1274-1275`) rewritten through it
- `tests/test_lifecycle.py` — `GitErrorTests`, a new class

**Steps**

1. The three module constants and `git_error(output, limit=GIT_ERROR_LINES)`, the spec's bodies and
   `#:` comments byte for byte. Place them near `push_failure` (`:1859`) or above `commit_leftovers`
   (`:1261`) — either reads, but both refusal sites must be *below* the definition. Keep the
   docstring's last sentence about the unprefixed local-hook line: it is the whole reason for the
   fallback branch and row three of the spec's table.
2. `publish`'s refusal (`:1643-1644`): delete the `why = [...]` line and return
   `f'publish {branch} refused: {git_error((p.stderr or "") + chr(10) + (p.stdout or ""))}'` —
   written with a real newline in the source, as the spec writes it. The redaction branch above it
   (`:1640-1642`) is **not** touched: it already reads both streams and it must still win (PD9).
3. `commit_leftovers`' refusal (`:1274-1275`): the same, with the `commit {branch} refused: ` prefix.
   Its `git add` refusal at `:1270` is unchanged — no git output is captured there.
4. `GitErrorTests` in `tests/test_lifecycle.py`, pure over `git_error` for the spec's three real
   outputs plus the empty one. Row one: a `! [rejected] …` line plus `error: failed to push some
   refs to '…'` → the `! [rejected]` line, the summary dropped. Row two: `remote: Permission to
   …/asf.git denied to lane-2.` plus `fatal: unable to access '…': … 403` → **both**, joined with
   `; `, in git's own order. Row three: `pre-push: lint failed on x.py:12` plus the summary → the
   hook's line. Empty and whitespace-only output → `push failed`. Add a hint case: output that is
   the summary plus a `hint:` block and nothing else falls back past both. Add a `limit` case: more
   than `GIT_ERROR_LINES` named lines are cut to three. Write `lane-2`, never a real account name
   (PD13).
5. In the same class, assert `push_failure`'s verdict on each row's new text (PD10): row two is
   `lifecycle.NETWORK_ERROR`, row three is `lifecycle.HOOK_REFUSED`, row one is None — the same way
   `tests/test_lifecycle.py:1538` already asserts it, through
   `push_failure(line.split('refused: ', 1)[1])`.
6. The live case the spec names: a real refused publish — a worktree whose `remote_sha` lease has
   moved under it — whose returned line now names git's own rejection rather than its summary.
   Build it from the git fixtures `tests/test_lifecycle.py` already uses for `publish`; assert on
   the substring git actually printed, not on a whole line, so the test does not pin a git version's
   punctuation.
7. One case for `commit_leftovers`' side: a commit the repo's hook refuses, whose refusal line now
   carries the hook's own message rather than the last line of its output.
