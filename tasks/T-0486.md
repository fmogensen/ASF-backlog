F-0031 extends as data. The settled ruling of `3cc3741b8` stays settled: a title that reads as money
bars nothing, and `test_deciding_a_card_crosses_no_approval_class` passes beside the new cases.

**Files**

- `asf/groom/policy.py` — `barred()` (`:520-532`), one clause after the `BARRED` loop
- `tests/test_groom_policy.py` — the bound's cases beside `test_deciding_a_card_crosses_no_approval_class`

**Steps**

1. The clause, exactly as the spec writes it, after the `BARRED` loop and before the final `return
   None`: when `answer.field == 'decided' and answer.value is True and typed.get('area')`, import
   `asf.approvals` **inside the function body** (`from asf import approvals`) — the module-level rule
   this module's docstring states (`:9-14`), and the reason `groom.py:748` does the same — call
   `approvals.area_class(product, str(typed['area']))`, and return `hit[0]` when it is not `None`.
   The `level_of` inside `area_class` is what applies the "not `auto`" half, so a product that maps
   its own declared class to `auto` is not barred by its own declaration.
2. `barred()`'s docstring gains the second sentence: the `approvals.<key>` a decide crosses is
   either `new_epic` (a new Epic) or a class the product declared this card's `area:` for. `BARRED`'s
   comment is left as it is — it is still true of `BARRED`, and the area bound is not a `BARRED` row
   (D6: changing the probe would let `close_exact_duplicate` close an Epic by rule).
3. `product is None` and a product with no `approval_signals` both reach the clause and both return
   `None` — `area_class`'s soft failure covers the first through `signals()` returning `{}`. A card
   whose `area:` is not a string (a list, from a hand-edited card) is `str()`-ed, never raised on.
4. Nothing else in the module changes. `DECIDE_CLASSES`, `decide_by_approval`, `POLICIES`,
   `DECISION_SECTIONS` and `PER_LINE_POLICIES` are untouched: the card's first two bullets are
   already on the trunk (D1) and this Task does not re-specify them.
5. `tests/test_groom_policy.py`, the unit half, against `policy.barred` directly: a Feature with
   `area: billing` under a product declaring `spend_money.areas: ['billing']` at `human-now` is
   barred as `spend_money`; the same Feature with no declaration is not; the same declaration with
   `spend_money: auto` does not bar; a Feature with **no** `area:` is never barred, whatever is
   declared; a Feature whose `area:` is `Billing` is barred (case, D8); a Feature whose `area:` is
   `billing/invoices` is barred by `billing/*` and not by `billing`; and an Epic with `area: billing`
   is barred under **`new_epic`** rather than `spend_money`, because `BARRED` runs first and
   catalogue order is not the loop order.
6. The type-agnostic half (PD5), asserted on purpose: a Story and a Task with `area: billing` are
   barred too; an auto-filed Bug — `signature:`, `count:`, `last_filed:`, no `area:` — is **not**,
   which is what exempts it without a special case; and a Bug that does carry `area: billing` is.
   `decide_feature.areas`/`decide_bug.areas` bar nothing (D5), asserted through `barred` and not
   only through `area_class`.
