## Description
stories: S-80807
writes: asf/flake.py, tests/test_flake_triage.py
after: Task 1

A re-run the factory makes is invisible where the operator looks (P10): the `infra` claim is
written to a ledger that partitions *cancelled* runs, and a phantom or lost-runner run concluded
`failure`, so `asf ci cancels` is right to skip it (C9). The flake triage's row already exists,
already reads `flake-triage.json`, and the infra re-run is the same file's third block.

**Files**

- `asf/flake.py` — `status_cell` (`:713-727`) only. `load` (`:154`) is not touched: its
  `fresh('infra')` (`:176-183`) already prunes the block by `RERUN_TTL_S`, so "a pruned record
  leaves no row" needs no code and is a test over `load`'s own window.
- `tests/test_flake_triage.py` — the status cases, beside `test_status_row_shows_a_live_entry`
  (`:320`).

**Steps**

1. Build the `infra` list from `sorted(data['infra'].items())` — sorted, because two heads in one
   row must have a stable order — and append its part last, immediately before the `return`, after
   the `held` part (**PD3**).
2. Skip three kinds of key in that loop: one starting `probe|` (bookkeeping, never a row — Task
   1 writes one per run id, so a head with four workflows would otherwise show four), a record
   that is not a dict, and a record with no `count`.
3. Each entry reads `{class} @ {head[:9]} re-run once`, with ` — BREACH, not re-run again`
   appended when the record carries `breach`.
4. The part reads `{N} infra re-run(s): ` and the entries joined by `; `, so one re-run with no
   quarantine renders `1 infra re-run(s): phantom @ 47be7bdd1 re-run once` and the row is that
   alone.
5. The quarantine loop (`:718-724`) and the `held` part (`:725-727`) keep their text and their
   order, and `status_cell` still answers None when no quarantine entry, no triage re-run and no
   infra re-run is live — two of S-80807's proven lines.
6. `asf/views/status.py`'s `quarantine_cell` (`:204-209`) is not touched: it is
   `flake.status_cell(product)` with no logic of its own, which is one of S-80807's lines and a
   test over that delegation, not a change.
7. `asf.ci_cancels`' `CAUSES` and `GROUPS` are not touched and `asf ci cancels` gains no row: the
   two remaining lines of S-80807 assert exactly that, from `tests/test_ci_cancels.py`'s side
   (C9, P10).
