§2.9. The field becomes writable by every writer of a card — the CLI, the plan parser — and the law
becomes checkable: a grant never leaves its Task's footprint, and two Active grants never overlap.
No card is edited and no card is invalidated: absent still means the footprint (§1.4).

**Files**

- `asf/record/new.py` — `--grant GLOB` (`action='append'`, optional, repeatable) beside `--writes`
  (`:45`); `grant = getattr(args, 'grant', None)` and `meta['grant'] = grant` beside `:129`. A
  `--grant` on a non-Task is refused with the message that shape already uses. `--writes` stays
  required for a Task; `--grant` is never required (§1.2, "making `grant:` required" is out).
- `asf/tick/migrate.py` — `writes_lines(body, key=None)`: `key=None` keeps today's
  `WRITES_RE` (`Files|Writes`, `:205`) byte for byte; a named key builds (and caches) one
  `^\s*<key>\s*:\s*(.+)$` regex and reuses the same list-splitting tail. No caller changes meaning.
- `asf/record/plan_tasks.py` — `grant = writes_lines(t['body'], 'grant')` beside the `writes` read
  (`:75-78`), written into the card's typed block as `typed['grant']` when present.
- `asf/record/check.py` — two findings after the Active-overlap block (`:196-207`): a Task whose
  `grant:` leaves its `writes:` (`boundary.within`, reported at `find_line(rec, 'grant')`), and two
  Active Tasks whose grants overlap (`footprint.overlaps`, PD6). `import fnmatch` stays; the
  existing footprint finding is untouched.
- `asf/init.py` — the README's typed-fields sentence (`:88`) names `grant` beside `writes`, in one
  clause saying which sizes the wave and which is enforced.
- `tests/test_backlog.py` — `NewGrantTests` and `GrantBoundaryCheckTests` (new).
- `tests/test_plan_tasks.py` — `GrantLineTests` (new).
- `tests/test_migrate.py` — one case that `writes_lines` with no key still reads `Files:` and
  `Writes:` exactly as before.

**Steps**

1. `writes_lines` generalised (PD11 needs nothing more — the field parses and indexes for free).
2. The plan parser reads the optional fourth line; a Task block without one produces a card with no
   `grant:` key at all, not an empty list.
3. `asf new task --writes … --grant …` writing both typed fields in the order the card template has.
4. `check.py`'s first new finding: for every open Task carrying both fields,
   `boundary.within(grant, writes)` — a returned glob is
   `f"{iid}: grant: {glob!r} is outside its writes: footprint"` at the `grant` line.
5. The second: Active Tasks carrying `grant:`, pairwise, through `footprint.overlaps`; the message
   is `f"{iid}: grant: {g1!r} intersects Active task {other}'s grant {g2!r}"`. One comment says why
   this one is the footprint matcher and the screen's is not (PD6).
6. The README sentence.
7. `NewGrantTests`: both fields written; `--grant` alone on a Task still refused for want of
   `--writes`; a card with no `--grant` has no `grant:` key.
8. `GrantBoundaryCheckTests`: a Task whose grant leaves its footprint is one finding at the `grant`
   line; two Active Tasks with overlapping grants are one finding; a lawful pair is silent; a card
   with no `grant:` at all produces no new finding.
9. `GrantLineTests`: a plan Task block carrying a `grant:` line reaches the minted card; one without
   mints a card with no such field.
