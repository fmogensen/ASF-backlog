§2.7: the third gate in this repo's `pre-commit`, and the same line in a product's. The card's
third acceptance line, and the only part of this Feature that refuses anything.

**Files**

- `asf/evals/freeze.py` — `staged_paths(repo)`, `refusals(staged, eval_set)`,
  `cmd_pre_commit(...)`.
- `asf/cli.py` — `--pre-commit` on the `evals` subparser and its dispatch (PD14).
- `.githooks/pre-commit` — the third gate.
- `asf/hooks.py` — `_git_hook_body`'s two commands for `pre-commit`, `evals_gate_upgrade`, and the
  composed `hook_upgrade` (PD11).
- `asf/init.py` — `PRE_COMMIT` gains the line and loses its `exec` (PD12).
- `tests/test_evals.py` — `FreezeTests`.
- `tests/test_install.py` — `EvalsHookTests`.

**Steps**

1. `staged_paths(repo)` — `git diff --cached --name-only --diff-filter=ACMRD -z`, repo-relative,
   the pattern `redact.scan_staged` follows (`asf/redact.py:330`). `D` is in the filter because
   deleting the task a change would have failed is the cheapest way to bend the set (§2.7).
2. `refusals(staged, eval_set)` — one refusal per lever whose tasks **and** whose own source are
   both in `staged`. A lever's task paths are the files under its tasks directory; its tool paths
   are its `implements` globs, matched with `ci.matches` (`asf/ci.py:38`), whose `*` crosses a `/`
   — the behaviour, not §2.7's sentence about it (PD16). `evals/manifest.json` and
   `evals/exemptions.json` are in neither set, so a lever rename travels with the tool it renames
   (§1.4).
3. `cmd_pre_commit` — the refusal of §2.7 on stderr, byte for byte: the header line, the lever, the
   task and the tool, the paragraph on why, and the four commands (`git reset`, `git commit -s`,
   `git add`, `git commit -s`). Exit 1. It returns 0 at once when `ASF_HOOK_RUNNING` is set (P9) and
   when the set's `manifest.json` is absent, so a checkout without the set is never blocked. It
   reads the index and never the working tree, and runs no task: the freeze is a path question, and
   a pre-commit that scored the set would put a rule check's subprocess in front of every commit.
4. `asf/cli.py`: `--pre-commit` on the `evals` subparser; with it, `evals_command` must be absent
   (PD14). Two lines of dispatch into `asf.evals.freeze`.
5. `.githooks/pre-commit`: `python3 -m asf.evals --pre-commit`'s CLI equivalent as the third gate,
   after the redaction gate, in the same shape as the two lines above it (an `echo` naming what it
   checks, then the command). The `ASF_HOOK_RUNNING` guard at the top already covers it.
6. `asf/hooks.py`: `_git_hook_body(name, asf_path, product_name)` (`:86`) returns two commands for
   `pre-commit` — `redact --pre-commit` then `evals --pre-commit` — and loses its `exec`;
   `pre-push` is byte-identical to today's. `is_git_hook_ours` (`:92`) is unchanged and still
   matches on the `redact` line (P11, D10). `evals_gate_upgrade(text, name)` beside
   `staged_check_upgrade` (`:118`) appends the evals line to a `pre-commit` that is ours and lacks
   it, and returns None otherwise. `hook_upgrade(text, name)` composes the three in order —
   `init_hook_upgrade`, `staged_check_upgrade`, `evals_gate_upgrade`, each applied to the previous
   result — and `ensure_git_hooks` (`:196`) calls it instead of the `or` chain (PD11). A hook that
   is not asf's is still left untouched, and its `NEEDS OPERATOR` line names both commands.
7. `asf/init.py`: `PRE_COMMIT` gains the evals line and its `exec asf redact --pre-commit` becomes
   two plain commands (PD12).
