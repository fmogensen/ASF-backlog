§2.1: the one thing in the factory that parses a `| check | result | evidence |` table, the one
thing that knows which checks a kind of review must cover, and the one thing that turns rows into a
verdict. Pure, stdlib, no path literal, no product name — a peer of `asf/tokens.py` and
`asf/approvals.py` (D1). Nothing imports it yet; Tasks 2, 3, 4 and 5 are its four callers.

**Files**

- `asf/reviews.py` — the module docstring, `MECHANICAL`/`STANDARD`, `PASS`/`FAIL`/`NA`,
  `APPROVED`/`CHANGES`/`BOUNCE`, `RESULTS`, `HEADERS`, `KINDS`, `Check`, `CHECKLIST`, and
  `cells`, `parse`, `normalize`, `required`, `missing`, `verdict`, `typed_verdict`, `faults`,
  `render_table`, `passed`
- `tests/test_reviews.py` — `TableTests`, `NormalizeTests`, `VerdictTests`

**Steps**

1. The module, with §2.1's docstring byte-for-byte — including "Nothing here opens a file, runs git
   or knows a path", which PD11 keeps true — and §2.1's constants, `Check` namedtuple and
   `CHECKLIST` exactly as the spec's fenced block spells them: two tuples per kind, mechanical
   first, standard second.
2. `cells(line)` — the splitter as `asf/evidence/evidence.py:356` has it: split on `(?<!\\)\|`,
   drop an empty leading and trailing cell, unescape `\|` to a literal pipe, strip each cell. This
   is the copy that becomes the original; Task 4 makes `evidence.cells` delegate to it.
3. `parse(text)` → `([Check, …], [fault, …])`. A table begins at a line whose cells, lower-cased
   and stripped of `*` and backticks, are one of `HEADERS`; the **next** line must be a separator
   (`| --- | --- | --- |`) or no table is found there at all — no rows, no fault. Rows run until
   the first line that does not start with `|`. Blocks number from 1 in order of appearance, so the
   order of the two passes is the order of the file (D3). A row whose cell count is not 3 is a
   fault naming its line, not a row. A result cell not in `RESULTS` is a fault naming its line —
   and a cell still carrying the skeleton (`<pass|fail>`, or anything holding `|` or `<`) is
   reported as **unfilled**, never as a pass. An empty evidence cell makes the row `fail` (D9).
4. `normalize(name)` — lower-case, collapse whitespace, strip backticks, `*`, a leading `-` and
   trailing `.,;:`. The one comparison used for coverage and, in Task 5, for acceptance matching.
5. `required(kind)` → the normalized mechanical names of `CHECKLIST[kind]`, in checklist order and
   none of the standard ones. `missing(checks, required)` → the required names no row covers, in
   checklist order.
6. `verdict(text, required=())` per D4: `''` when no table is present at all; `BOUNCE` when `parse`
   returned a fault or `missing` is non-empty; `CHANGES` when any row is `fail`; else `APPROVED`.
   An `n/a` row is neither a fail nor a missing check. `typed_verdict(text)` → the legacy word, a
   `verdict`-prefixed line preferred, as the shipped readers read it today.
7. `faults(text, required)` → the parse faults in line order, then one
   `required check missing: "<name>"` per missing name. `passed(checks)` → the normalized names of
   every `PASS` row. `render_table(rows)` → `| check | result | evidence |`, the separator, and one
   `| <name> | <pass\|fail> | ` per row — the escaped pipe, so the skeleton re-parses as one cell.
8. `TableTests` per §3.1: one table → three `Check`s with `block == 1`, the `\|`-escaped pipe in a
   check name unescaped, no fault; two tables under two headings → six rows, blocks `1,1,1,2,2,2`,
   file order; `| check | ok | evidence |` parses the same (D2). Then the faults, each naming its
   line number: a row of two cells; a result of `approved`; a result still reading `<pass|fail>`
   asserted as *unfilled* and asserted **not** a pass; a header with no separator under it → no
   table, no rows, no fault. A row with an empty evidence cell parses as `fail`.
