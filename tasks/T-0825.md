The spec's `## The design` §1 in full, and the first and third Acceptance blocks whole. One new
module, two new test classes in a new test file, one new class in `tests/test_lane.py`, and **not
one line changed anywhere else in the tree** — S-64356's whole claim is that `lifecycle.publish`
and `asf/harvest/lane.py` keep writing no ledger line (C5), which is proven by a test, not by an
edit. This is the Task every other Task waits for: all four read this module.

**Files**

- `asf/workers/refusals.py` — new. §1's module docstring byte for byte; `NAMING`, `PRE_PUSH`,
  `REFGUARD`, `PUSH_ALLOW`, `REDACTION`, `KINDS`, `CORRECTION_KINDS` (with `'gate'`, per
  **PD6**), `CLAUSE_MAX = 200`; the `Refusal` NamedTuple (`kind`, `line`, `at=''`, `where=''`)
  with **PD6**'s widened `kind` docstring; `path`, `env_for`, `clear`, `ledger`, `from_record`,
  `recognise`, `last`, `clause`, `dead_reason`
- `tests/test_refusals.py` — new. Two classes, `TheRefusalModule` and `TheRecordsOwnRefusals`
- `tests/test_lane.py` — one new class, `ANamingRefusalIsReadableAfterwards`

**Steps**

1. `asf/workers/refusals.py`, module docstring from §1 byte for byte, then `import json`,
   `import os`, `from asf import env`, `from asf.workers import lifecycle` — module level, per
   **PD11**(a): `cloud → refusals → lifecycle` closes no cycle and the coder must not hedge with
   a local import. Nothing of `cloud`, `health` or `harvest` is imported, ever (C1).
2. The constants, each aliased to the constant that already owns its string (C2): `NAMING =
   lifecycle.NAMING`, `PRE_PUSH = lifecycle.HOOK_REFUSED`, and `REFGUARD = 'refguard'`,
   `PUSH_ALLOW = 'push-allow'`, `REDACTION = 'redaction'` as their own — measured, no constant
   elsewhere owns those three. `CORRECTION_KINDS = (lifecycle.NAMING, lifecycle.COPIES, 'merge',
   'conflict', 'gate', lifecycle.HOOK_REFUSED, lifecycle.INCOMPLETE)` per **PD6**(a), with a
   comment naming `lane.py:3145` as `gate`'s site and `:1098` as `merge`'s. `CLAUSE_MAX = 200`.
3. `class Refusal(NamedTuple)` with the four fields in §1's order and its `kind` docstring per
   **PD6**(b) — "one of :data:`KINDS`, or a correction's own kind (:data:`CORRECTION_KINDS`)".
4. `path(product, job)`, `env_for(product, job)`, `clear(product, job)` — `pushlog`'s three,
   copied in shape (P14): `os.path.join(env.state_dir(product), 'gates', f'{os.path.basename(job
   or "")}.refusals')`; `env_for` makes the directory and returns `{'ASF_REFUSAL_LOG': path(...)}`
   and takes **two** arguments where `pushlog.env_for` takes three (**PD11**); `clear` swallows
   `OSError`. Reuse `pushlog.PUSHES_DIR` rather than a second `'gates'` literal.
5. `ledger(product, job)` — every line of the file as a `Refusal(where='ledger')`, oldest first,
   `[]` for no file, and a line that is not a JSON object with a `kind` and a `line` is **dropped**
   rather than raised on: a hook's output is not a contract (§2). Swallow `OSError` and
   `ValueError`.
6. `from_record(run)` — the Refusals on a registry line, in no particular order, both halves
   per-run and so needing no window (**PD3**). From `run['publish_refused']`: take the text after
   the first `'refused: '` the way `health.republish_steps` does (`health.py:686`), then the kind
   — `REFGUARD` when it matches **PD5**'s pattern, `REDACTION` on the redaction patterns, else
