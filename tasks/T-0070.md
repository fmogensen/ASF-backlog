## Description
stories: S-14307
writes: asf/doctor.py, docs/products.example.yaml, sample/product.yaml, tests/test_env.py, tests/test_doctor.py, tests/test_sample_product.py

Depends on T-14650 (`PRODUCT_FIELDS` learns the key, and `tokens.caps` is what the row calls). It is
disjoint from T-14651 and T-14652 and runs beside them. It does **not** write `asf/env.py` (PD6).

**Files**

- `asf/doctor.py`: `check_token_caps(cfg, product)` beside `check_capacity`, and one row block in
  `run()`.
- `docs/products.example.yaml`: the `token_caps:` block with the spec's comment, between
  `capacity:` and `deploy_sha:`.
- `sample/product.yaml`: the same block with the `default` row only.
- `tests/test_env.py`, `tests/test_doctor.py`, `tests/test_sample_product.py`: the four tests below.

**Steps**

1. `check_token_caps(cfg, product) -> [(ok, detail)]`, the shape `check_capacity` already returns
   (PD12): a `TokenCapError` gives one `(False, f'token_caps: {why}')` per refused entry; otherwise
   one `(True, 'default: in 8.0 M / out 1.0 M / cache rd 400.0 M / cache wr 40.0 M; <n> kind(s)
   overridden')` using `tokens`' own formatting, plus one `(False, …)` per dimension an operator set
   to `off`, naming it `<kind>.<dimension>` — an uncapped dimension is a decision that should be
   visible every time doctor runs.
2. `run()` appends each as `('token-caps', False, ok, detail)` after the capacity rows
   (`doctor.py:448-449`). `required=False`, so no finding here ever turns doctor red, and
   `format_table` prints a not-ok one as `skip`.
3. `docs/products.example.yaml`: the spec's block, comment included, after the `capacity:` block and
   before `deploy_sha:`. Nothing else in the file moves.
4. `sample/product.yaml`: the same block with the `default` row only, so `test_sample_product`
   exercises the real parse and the real resolve.
5. The four tests below. `test_sample_product`'s existing `test_doctor_is_clean` now also sees the
   new row: it stays green because the row is `required=False` and the sample's block is valid.

**Acceptance**

- `test_token_caps_is_accepted`: a product file with a `token_caps:` block loads and
  `validate_product_text` returns `[]`.
- `test_doctor_prints_the_resolved_caps`: a product with no block → one `token-caps` row, ok,
  naming the four default numbers.
- `test_doctor_names_a_bad_block`: a malformed block → a not-ok `token-caps` row naming the bad
  entry, and `doctor.is_red(rows)` is still `False` (the row is `required=False`).
- `test_doctor_names_an_off_dimension`: `spec: {cache_read: off}` → a not-ok row naming
  `spec.cache_read`.
- `test_sample_declares_token_caps`: `tokens.caps(Product('sample', loads(sample/product.yaml)))`
  returns without raising and `cap_for(p, 'spec')` has all four dimensions.
