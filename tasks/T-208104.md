**Steps**

1. `asf/kernel/questions.py`: `CLAIMED = CODED | {PUSHED} | {R.FINDING_HEAD, R.WRITE_GRANT,
   R.CARD_READ, R.PREDECESSOR}`, with §2.9's comment and its reason: `CODED` stands as it is (so
   the widened `gate` is already in the set, widened in place and not renamed, D-0001), and `PUSHED`
   has to be added **by name** because `classify` buckets a pushed-shaped question as `PUSHED`,
   which is `OWNED`, not `CODED` — a claimed set reading `CODED` alone would count the ledger's
   largest class as console and S-205275's per-class line could not be met for kind 1 however well
   Task 1's resolver worked. `OWNED`'s other member, `trunk-base`, is not a kind this Feature
   codes and stays out.
2. `read_answers(state_dir, path=None)`: `path` reads that file instead of the state directory's
   `ANSWERS_FILE`, everything else unchanged — one reader for the unit test and for a person's
   shell (**PD14**). Every existing caller passes `state_dir` positionally and is untouched.
3. `replay(records, resolving=None)` → `{'n', 'claimed', 'console', 'share', 'by'}`: every record
   run through `classify`, counted into the classes `CLAIMED` holds and the classes it does not,
   `share` claimed over `n`. With `resolving` given, a class the product has switched off is not
   counted as claimed, so the number a person reads is the number their own product would get.
   Pure, offline and deterministic (D-0011): no probe, no git, no network, no `Facts`, and the same
   result twice over the same records.
4. `render_replay(result)` → §2.9's line and its table, one row per class with its count and
   whether code claims it, ordered by count.
5. `asf/cli.py`: `--replay` and `--answers <path>` on `p_kquestions` (`:702-709`), passed through
   `questions(args.product, …, replay=args.replay, answers=args.answers)`; `questions()` prints
   `render_replay(replay(read_answers(sd, args.answers)))` when `--replay` is given, and its own
   share and tables otherwise. `--answers` without `--replay` is a usage error, named as such.
