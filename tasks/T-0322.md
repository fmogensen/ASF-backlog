## Description
stories: S-31106
writes: asf/budget.py, asf/workers/stall.py, tests/test_launch.py, tests/test_budget.py
after: Task 1, Task 5

§2.5's turn half. There is no turn-limit flag on the installed runtime (P6, re-read at this head),
so the cap stays where it already bites and becomes per kind. The stop, the cap result line, the
`capped` mark and the `CAP` console line are exactly what they are today (P8); what this Task fixes
is that a `close` job reached 600 turns before anyone noticed.

**Files**

- `asf/budget.py`:
  - `RUN_TURNS` — §2.5's table verbatim, with §2.5's comment: a kind with no entry takes `default`,
    which is `conventions.budget.run_turns`, so a product that set that number keeps it.
  - `run_caps(conv, kind=None)` — `(minutes, turns)`, the existing signature widened by a
    defaulted argument so `budget.run_caps(Conventions()) == (180, 600)` still holds
    (`tests/test_budget.py:148`). `conventions.budget.run_turns` is the `default` entry;
    `run_turns_by_kind` (Task 1's convention, read through `budget_for` — PD13) overrides any row;
    a non-dict value there is ignored and named in the returned detail rather than raised.
- `asf/workers/stall.py` — `cap` gains one local and passes it (**PD5**): `row_kind = s.get('kind')`,
  the feeder row kind `spawn` writes verbatim, used for `budget.run_caps(conv, row_kind)` and for
  `budget.run_cap_result(row_kind, …)`; `kind = metrics_mod.session_kind(s)` stays exactly where it
  is, for `tokens.caps` and `tokens.cap_result`, because that table is keyed by `tokens.KINDS` and
  validated to refuse anything else. A comment names both vocabularies and why there are two. The
  `CAP` console line keeps printing `kind`, so no existing assertion moves. Nothing else in the
  function changes.
- `tests/test_launch.py` — `RunCapTests`: T7 over a fixture ledger and a fixture log. A `close` job
  at 61 turns is over, is stopped, and its log's last record is
  `budget.run_cap_result('close', 'run_turns', 61, 60, at)` — the structured `asf.run_cap` object
  and the text both; `runtime.failure_reason` reads it back as `budget.RUN_CAP`; the same 61 turns
  on a `spec` job is not over; a measure set to `off` caps nothing. The first case is the one that
  fails without PD5's fix, and it is written first.
- `tests/test_budget.py` — `RunTurnsByKindTests`: `run_caps(conv, kind)` per row;
  `conventions.budget.run_turns` set to 900 raises every kind the table does not narrow and leaves
  `close` at 60; `run_turns_by_kind` overrides a row; `run_caps(conv)` with no kind is still
  `(180, 600)`. The existing `RunCapTests` in this module is untouched.

**Steps**

1. `RUN_TURNS` and `run_caps(conv, kind=None)`; run `tests.test_budget` — every existing case first.
2. `RunTurnsByKindTests`.
3. `stall.cap`'s one local and two call sites, with the comment; run `tests.test_workers.TestStall`.
4. `RunCapTests` in `tests/test_launch.py`, the `close` case first.
