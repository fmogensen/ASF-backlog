The spec's §2.3. After this Task `render_workflow` substitutes `@IDENT_NAME@`/`@IDENT_EMAIL@` from
`identity.agent_identity(acct)` the same way it already substitutes `@RUNS_ON@`, `@TIMEOUT@` and
`@SECRET@`, so a commit made on a runner and a commit made on this host are authored by the same
agent — and an operator who wants the code host's `noreply` form gets it from the account's
`identity:` instead of from a literal in this repo.

The two lines it replaces are `git config user.name "asf worker"` and
`git config user.email "asf-worker@users.noreply.github.com"` (`asf/workers/actions.py:91-92`).
Note what changes: the *name* is already the agent's and stays; the *e-mail* moves from the code
host's `noreply` form to D2's `@localhost`. That is deliberate and D2 argues it — and the account
override is how an operator who needs the `noreply` form keeps it, which is why
`docs/config.example.yaml` uses exactly that as its worked example (Task 3).

Read **PD7** before writing the signature: the override cannot reach a static file through a row,
and PD7 says what it reaches it through instead. Read **PD6** before believing the doctor will
catch a stale workflow — it will not, and §5's second operator line is the whole mitigation.

**Files**

- `asf/workers/actions.py`
  - `WORKFLOW`'s two lines (`:91-92`) → `git config user.name "@IDENT_NAME@"` and
    `git config user.email "@IDENT_EMAIL@"`, §2.3's block byte for byte.
  - `render_workflow(s, acct=None)` (`:123-128`) — two more `.replace` calls off
    `identity.agent_identity(acct)`, in the chain's existing shape. The docstring gains the
    identity beside the runs-on labels, the timeout and the token secret.
  - `install(product, s, out=print, acct=None)` (`:135-155`) — passes `acct` through; the printed
    block gains one line naming the identity it wrote (not a secret, and the operator needs to know
    which of two it got).
  - `cmd_install` (`:160-164`) — resolves the lane account per PD7 off the `env.load_config()` it
    already loads, and prints PD7's one line when the lane's accounts do not agree on one identity.
  - the module docstring's *"Reinstall after changing cloud.runs_on, cloud.token_secret or
    cloud.timeout_min"* (`:47`) gains the identity, and — since PD6 means nothing else will say
    so — the sentence that a workflow already on the trunk keeps its old identity until
    `asf cloud install` is re-run and committed.
- `tests/test_session_identity.py` — `class LaneIdentityTest`, §3.2's three tests.

**Steps**

1. The two template lines, then `render_workflow`'s parameter and the two `.replace` calls.
   `identity` is imported at module level here: `asf.workers.actions` already imports `asf.env` and
   `asf.workers.cloud`, and `asf.identity` imports neither, so there is no cycle.
2. `install` and `cmd_install`, then the docstring lines.
3. `tests/test_session_identity.py::LaneIdentityTest`. The second test
   (`test_both_lanes_name_the_same_identity`) is the one that earns the Task: take the pair out of
   the rendered YAML by parsing the two `git config user.…` lines, take the pair out of
   `build_env`'s `GIT_CONFIG_*` with `hermetic.git_config_pairs`, and assert equality for the *same*
   account — the defaults and an overriding one.
4. Print §5's second operator line in the report, as `NEEDS OPERATOR`, naming the product: the
   rendered change reaches no runner until an operator re-installs and commits the workflow, and by
   PD6 no doctor row will say so.
