§2.1 and §2.6: `UNDECIDED → DECIDE` joins the row kinds, `conventions.decision_rows` (default 5) is
the one knob for how many get one, and `candidates()`/`plan_rows()` take `decision_limit` so a
caller can ask for all of them. Nothing launches: the row is the sentence *this card is what a free
slot is waiting for*, in the one table that says what the tick would start (P2, P3).

**Steps**

1. The three constants, and `decision_rows(product)` — `_conventions(product).get('decision_rows')`,
   falling back to `DECISION_ROWS` when the value is not an `int >= 0`, the shape `attempt_limit`
   has (PD4). `0` means *every one*.
2. `undecided_rows(items, product, busy, limit=None)`: the roots are every open Feature and every
   open S1/S2 Bug (`ix.of_type`, `is_open`) whose `decided` is not `True` and whose id is not in
   `busy`; a `blocked:` one is skipped — it is the accounting's `blocked` bucket, and two rows for
   one card would be two answers to one question (§2.1). Tier is `0` for an S1 Bug, `1` for an S2,
   `2` for a Feature (D10). Order: tier, then `ix.rank`, then id — an unranked card last (P7). The
   cut is `limit` when given, else `decision_rows(product)`; `0` returns all.
3. Each row: `kind=UNDECIDED`, `action=NEEDS_DECISION`, `waits_on='decision'`,
   `brief_kind='spec'` for a Feature and `'fix-bug'` for a Bug, `branch` the one that kind's session
   would use (`branch_for(product, 'spec'|'fix', id)`), `feature_id` the Feature above a Bug or the
   card itself, and
   `reason=f"undecided {ix.age(v.get('stage_since'))} — {CARD_SPEC if … else BUG_FIX} waits for decided: true"`.
   No new `Row` field is added: the dataclass already carries every one of these.
4. `hold_unlanded`: `keeps` grows `NEEDS_DECISION` beside `ON_TRUNK` and `PARKED` (D11) — an

   exists to print.
