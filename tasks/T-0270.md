## Description
stories: S-29400, S-29401
writes: asf/precheck.py, tests/test_precheck.py
after: none

§2.1: the one module that says what level a branch is read at, which dimensions that level owes,
and which rows of the answer send the branch back. Pure and stdlib-only: no file is opened, no git
is run, no path is spelled (`check_conventions.sh` would fail on the pattern). Nothing imports it
yet — Task 2 is its first caller.

**Files**

- `asf/precheck.py` — the module docstring §2.1 gives; `LOW`/`HIGH`/`MAX`, `LEVELS`, `PASS`/`FAIL`/
  `NA`, `RESULTS`, `CONF_HIGH`/`CONF_MED`/`CONF_LOW`, `CONFIDENCES`, `HEADER`, `KIND`, `Row`,
  `DIMENSIONS`; `dimensions`, `level_for`, `parse`, `covered`, `findings`, `blocking`, `keys`,
  `faults`, `render_table`, `head_of`, `level_of`
- `tests/test_precheck.py` — `LevelTests`, `TableTests`

**Steps**

1. The module docstring of §2.1, verbatim, with "Nothing here opens a file, runs git or knows a
   path" scoped to the grammar (PD5 puts the command below a divider in Task 6).
2. The constants of §2.1 in its order, each with its doc comment: `LOW, HIGH, MAX = 'low', 'high',
   'max'`; `LEVELS = (LOW, HIGH, MAX)`; `PASS, FAIL, NA = 'pass', 'fail', 'n/a'`;
   `RESULTS = {PASS, FAIL, NA}`; `CONF_HIGH, CONF_MED, CONF_LOW = 'high', 'medium', 'low'`;
   `CONFIDENCES = {CONF_HIGH, CONF_MED, CONF_LOW, NA}`;
   `HEADER = ('check', 'result', 'confidence', 'evidence')`;
   `Row = collections.namedtuple('Row', 'check result confidence evidence line')`. Plus
   `KIND = 'precheck'` — the correction kind and the brief kind have one owner, so Task 2's lane
   and Task 4's brief spell neither.
3. `DIMENSIONS`, the three-key dict of §2.1 byte for byte, with its `#:` comment saying it is
   cumulative. `dimensions(level)` returns `LOW`'s, then `HIGH`'s, then `MAX`'s, in that order, up
   to and including `level`; an unknown level is `HIGH`'s (D4's rule for an unknown class, read the
   same way), never empty.
4. `level_for(size_class, changed_lines, max_lines)` exactly as §2.1's four-line body, importing
   `asf.size` for `SMALL`. `why` names the number that decided it:
   `f'{changed_lines} changed lines > {max_lines}'`, `f'size class {size.SMALL}'`,
   `f'size class {size_class or "unknown"}'`.
5. `_cells(line)`: split a `|`-delimited row on unescaped `|`, drop the leading and trailing empty
   cells, unescape `\|`, strip. `_norm(text)`: lowercase, collapse whitespace, strip `*`, backticks
   and trailing punctuation — the one normalizer `parse`'s header match and `covered` both use.
6. `parse(text)` → `([Row, …], [fault, …])`:
   - find the first line whose `_norm`'d four cells equal `HEADER`; with none, `([], [])` — no
     table found is not a fault (§3.2);
   - the next line must be a separator (every cell only `-` and `:`); without one, `([], [])`;
   - rows run from there to the first line not starting with `|`; each row's `line` is its
     1-based line number in `text`;
   - a row whose cell count is not 4 is a fault naming the line, and no `Row`;
   - a cell still carrying the skeleton — holding `<` or an inner `|` — is a fault reading
     `row <i>: <column> is unfilled (<the cell>)`, and the row is kept with that cell's value as
     it stands, so it can never satisfy `covered` or read as a `pass`;
   - a `result` outside `RESULTS`, or a `confidence` outside `CONFIDENCES`, is a fault naming the
     line and the value — *unfilled* is reported as unfilled and not as either;
   - a `FAIL` row whose evidence cell is empty is a fault: a finding with no `file:line` is not a
     finding.
7. `covered(rows, level)`: the dimensions of `dimensions(level)` no row's `_norm`'d `check`
   matches, in level order. `findings(rows)`: the `FAIL` rows in file order. `blocking(rows)`: the
   `FAIL` rows at `CONF_HIGH` (D6). `keys(rows)`: the sorted unique leading `file:line` token of
   each blocking row's evidence — `c_items`' shape (`asf/evidence/review.py:180`), read the same
   way, so `same_finding` compares like with like.
