The spec's `## The design` §B in full: `peak_concurrent` gains the split map, `run_peaks` derives it
from the live runners it already takes, `fit_caps` caps each key, `EXPECT_VERSION` goes to **7**
(PD2), `Queue.needs` collapses a class override (C8), `entry_needs` caps a PR start per key, and
`admit` and `live_line` pass the keys the line's needs mention. **The card's first defect closes
here**: the run whose seven heavy jobs cannot run on the free heavies is held, and the hold line
names the label it lacks.

**Read PD6 before starting** — `estimate`, `_by_type`, `needs_from_history` and `needs_by_type` all
cap through `_caps(pool)` and the caps have to be threaded as an argument; `fit_caps` cannot simply
be swapped in. Read **PD7** (a per-run cache record measured during a runner outage is reused for
ever and reads as "no strict requirement" — store the split it was measured under), **PD5** (a
second copy of the override logic lives in `_snapshot_clause`), **PD4** (the keys handed to `free`
are the union over *every* entry in line, and a key `free` cannot see fails open) and **PD2(b)**
(`hold` stays class-keyed — do not thread `split` into `_run_hold`).

   existing rule untouched — the runner test, the `skipped` test, the id dedupe, the

   `norm(job['labels']) & split.get(its class, frozenset())`, and the key set a job contributes to
   is every key whose labels are a **subset** of its asks — the bare class key always, plus one per
   distinct asks-set seen for that class. Take the peak per key over the jobs asking for **at
