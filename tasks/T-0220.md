## Description
stories: S-18900
writes: asf/record/ingest.py, tests/test_ingest.py
after: none

§2.1. `ingest` already has the old stage, the new stage and `now` in one loop; it writes none of it
anywhere a report can read. This Task adds the kind, the writer and the one condition that fires on
the transition into `on-prod`. Nothing reads the stream yet — Task 2 does.

**Files**

- `asf/record/ingest.py` — `ON_PROD_EVENT = 'feature-on-prod'` and `write_on_prod_event(root, iid,
  from_stage, now)` beside `MACHINE_KEY_ORDER` (`:19-21`); the transition test inside the write
  loop (`:440-462`), after `frontmatter.write_machine`; `import json` and `import os` at the top
  (the module has neither today, `:8-16`).
- `tests/test_ingest.py` — `FeatureOnProdEventTests` (new), built on the fixture shape of
  `ProductionIsTheProductsOwn` (`:63-125`), which already drives `ingest` with a mocked
  `evidence.load` carrying `prod_sha` and merged shas.

**Steps**

1. `ON_PROD_EVENT = 'feature-on-prod'` beside `MACHINE_KEY_ORDER`, with §2.1's comment: the
   `metrics/events` kind written when a Feature's stage enters `on-prod`, the durable record read
   by the rollup's first line (F-0044).
2. `write_on_prod_event(root, iid, from_stage, now)`: the path is
   `<root>/metrics/events/<now[:10]>.jsonl`. Read the file if it exists and return False when any
   line already has `kind == ON_PROD_EVENT` and `item == iid` — that is the idempotence the record
   clone needs, since it is reset and re-derived every cycle. Otherwise `os.makedirs(dirname,
   exist_ok=True)`, append `json.dumps({'from': from_stage or '', 'item': iid, 'kind':
   ON_PROD_EVENT, 'ts': now}, sort_keys=True, ensure_ascii=False) + '\n'`, return True. A line that
   will not parse as JSON is skipped, not raised on — the stream is unvalidated (§1.1) and a
   rollup must not be the thing that fails.
3. In the write loop, `old = machine.get('stage')` is read from the `machine` dict
   `frontmatter.split_machine` already returns (`:446`), **before** `_ingest_fields` is called, and
   after the `write_machine` / History block:

   ```python
   if type_ == 'feature' and stage_val.get(iid) == 'on-prod' and old != 'on-prod':
       write_on_prod_event(root, iid, old, now)
   ```

   It sits inside the `if ordered is None: continue` guard, which is correct: a Feature already at
   `on-prod` changes nothing and `_ingest_fields` returns `None` for it anyway. `'on-prod'` is
   written as the literal the ladder returns (`asf/evidence/evidence.py`'s `feature_stage`); the
   card's prose says "on-production" and the record says `on-prod` (§1.1).
4. The docstring of `write_on_prod_event` says why it does not go through `append_event`: P7 —
   `natural_key` has no `events` branch and raises `KeyError` on any line without a `tick`.
5. Nothing else in the loop moves. `_ingest_fields`, `append_history_lines`, the `## History` line
   and `stage_since` are untouched, so the event is purely additive.
6. `FeatureOnProdEventTests`: a record whose `F-0001` has every Task Closed and an `ev` carrying
   `prod_sha` plus the merged shas — one `asf ingest` writes exactly one line to
   `metrics/events/<today>.jsonl`, `{"from": "landed", "item": "F-0001", "kind":
   "feature-on-prod", "ts": …}` with `list(obj) == sorted(obj)` and `ts` matching `TS_RE`. A second
   `ingest` the same day adds none. A Feature reaching only `landed` (`prod_sha` absent) writes
   none. A Feature whose machine block already reads `stage: on-prod` writes none. A Task and a Bug
   that reach prod write none. The Feature's `## History` lines and its `stage_since` equal what
   the same fixture produces on `main` today.
7. The last clause of §3.1 in the same class (P9): build a list of `intake` / `groom_answer` /
   `launch` events, assert `metrics.intake_latency_rows(evs)`, then append the
   `feature-on-prod` lines and assert the two rows — values and notes — are equal.
