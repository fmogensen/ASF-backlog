## Description
stories: S-18753
writes: asf/tick/step_prs.py, tests/test_tick_steps.py
after: Task 1

§2.4. The card names this half literally — *the pull-request body carries `Proves: …` for every
acceptance line its tests prove* — and D1 is why the tick generates it from the branch instead of
asking the coder for it: a coder may never open a pull request, so the only text it controls is its
commit messages.

**Files**

- `asf/tick/step_prs.py` — `title_and_body`'s signature and the `## Proves` block
  (`step_prs.py:158-170`); the call in `run()` (`step_prs.py:205`); `import` of `asf.proves`.
- `tests/test_tick_steps.py` — `ProvesBlockTests`.

**Steps**

1. `title_and_body(item_id, item, root, branch, repo=None, trunk=None)` — `root` stays the record
   root that `card_link` reads, and the lane branch is read from `repo` instead (**P8**). With
   `repo` or `trunk` None the block is absent, which is the same shape a branch with no claim gets.
2. The block goes between the card's `## Acceptance` checkboxes and the closing
   `Opened by the tick from …` line, exactly as §2.4 lays it out: `## Proves`, then
   `proves.render(claims)`' bullets. Built from
   `proves.claims_on_branch(lambda *a: _git(repo, list(a)), trunk, branch)` — the step's own `_git`
   (`step_prs.py:45`), which already returns `''` on a non-zero exit, so an unreadable branch
   yields no claims rather than an exception in the middle of a tick.
3. `run()` passes `product.repo_dir` and `product.main`. No other call site exists.
4. A branch with no claim still gets its pull request opened, and the block is simply **absent** —
   no empty heading, no placeholder. The refusal is harvest's, in one place (§2.5); a pull request
   nobody opened is a Task nobody can correct.
5. `ProvesBlockTests`: `title_and_body` carrying a `## Proves` block with one bullet per claim on
   the branch, below the card's `## Acceptance` checkboxes and above the closing line; the block
   absent with no stray heading when the branch has no claim; the block absent when `repo` is not
   passed; the `gh pr create` argv from `pr_create_argv` unchanged otherwise; and the git callable
   asked for exactly the one `log` range `claims_on_branch` documents.
