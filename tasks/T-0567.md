## Description
stories: `asf doctor` lists a product's declared doc paths (spec `docs/specs/f-0186.md` § Stories, second bullet)
writes: asf/doctor.py, tests/test_doctor.py
after: none

The spec's §2.2 whole: `check_doc_paths` and the two lines that wire it into `doctor.run`. It is
the card's first-customer story in one row — an operator installing a product can read which
folders that product counts as documents, without reading its yaml.

The row is **always green and never required** (D6, and PD3 for why that is safer than the spec's
own argument for it): a `doc_paths` of the wrong shape never loads at all, and a glob that matches
nothing today is not a fault — a product may declare a folder before it has one.

This Task compiles and passes against the trunk as it stands; it does not wait for Task 1 (PD1).
Read **PD4** before deciding the row should call `lane.doc_matchers` — it should not — and **PD3**
before writing the third test.

**Files**

- `asf/doctor.py` — `check_doc_paths(product)` exactly as §2.2 writes it, placed beside
  `check_convention_shapes` (`:593-607`); and the two-line `for ok, detail in check_doc_paths(product):`
  block in `doctor.run` immediately after the `conventions` rows (`:870-871`). No other function
  is edited, and no import is added (PD4).
- `tests/test_doctor.py` — `class DocPathsRowTests(unittest.TestCase)` as §3.4 fences it, a plain
  `TestCase` and never a subclass of a harness in this module. `env`, `doctor`, `unittest` and
  `mock` are all already imported at `:1-11`.

**Steps**

1. `check_doc_paths` — the spec's body verbatim. It returns a one-element list, like
   `check_savings` and unlike `check_convention_shapes`, so the caller's `for` loop reads the same
   as its neighbours.
2. The wiring in `doctor.run`: `rows.append(('doc paths', False, ok, detail))` — `required=False`
   is what keeps it out of `install._doctor_red_keys`, which selects `required and ok is False`
   (`asf/install.py:314`), so a fresh install's red set does not change (P9, and nothing asserts a
   row count).
3. `DocPathsRowTests`, the spec's four methods byte for byte. The third,
   `test_a_misshapen_value_is_the_conventions_row_not_this_one`, gains one docstring line and no
   change to its body:

   ```python
           """A product file whose `doc_paths` is not a list never loads — `env.load_product`
           raises on `validate_mapping`'s problem — so this row is green because it is never
           reached, not because another row went red (PD3: `shape_findings` has no `doc_paths`)."""
   ```

4. Do not make the row red for a glob that matches nothing on disk, do not fold the listing into
   the `conventions` row's detail, and do not add a `doc_paths` key — all three are the spec's
   `## Out` or D6/D7.

**Gate**

```bash
python3 -m unittest -v tests.test_doctor.DocPathsRowTests
python3 -m unittest tests.test_doctor tests.test_conventions tests.test_contracts
python3 -m unittest tests.test_approvals tests.test_worker_isolation
bash tools/check_conventions.sh
bash tools/check_generic.sh
```

`tests.test_approvals` and `tests.test_worker_isolation` are the two other modules that call
`doctor.run` (`tests/test_approvals.py:703`, `tests/test_worker_isolation.py:406`) and are the
proof that one more always-green row breaks no caller. Neither is in this Task's `writes:`.
`tools/check_conventions.sh` matters here in particular: the row's detail string is built from
`conv.get(...)` at run time and must contain **no** path literal — a hard-coded `docs/specs` in
`asf/doctor.py` is a forbidden convention and fails the scan.

**Acceptance**

```bash

```
