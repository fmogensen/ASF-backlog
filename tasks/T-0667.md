The spec's `## The design` §3 and §6. After this lands the card is whole: `runs_on()` asks the repo
what its Actions variables are, hands the answer to every `parse_runs_on`, and the only time this
reader answers `heavy` to `${{ vars.X || 'heavy' }}` is when it asked and the repo said nothing.
A read it could not make is `None`, not a `BackendError` — the set is unknown, every `vars.*` job
goes unresolved, the pool's other rows survive, and Task 1's freeze makes that safe and loud (C9).
The guide is rewritten for all three Tasks at once (**PD14**).

Read **PD5 first.** `runs_on()` is not the function the spec read: `ee3ae8de6` split it into
`_workflow_texts()` plus two walkers, and `timeouts()` walks it too. The variables read goes in
`runs_on()`, **never** in `_workflow_texts()` — a shipped test added since the spec was written
counts the calls that walk the workflow files, and a read made from `_workflow_texts()` is made by
`timeouts()`, lands in that count and turns its 2 into a 3. And `variables()` returns `None` without
a `repo_slug`, so it can never build `repos/None/actions/variables`.
