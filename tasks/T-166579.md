**Files**

asf/kernel/host.py, asf/kernel/loop.py, asf/cli.py, asf/doctor.py, tests/kernel/test_kernel_beat.py

**Steps**

1. `asf/kernel/host.py`: `BEAT_FILE = 'kernel-beat.json'` and the writer that renders
   `{at, sha, tick_s, sessions, beats: {alive, frozen, looping, unknown}, rc}` atomically, the way
   `save_plan` writes its own file.
2. `asf/kernel/loop.py`: the tick calls that writer from a `finally` around its decide/apply
   block, after `save_plan`'s position and before `summarize`/`print_summary`, so a tick that
   fails after deciding still leaves a beat with its exit code in it. The `Locked` return writes
   no beat (`K8`). The tick line gains the `beats:` counts.
3. `asf/kernel/host.py`: `watch`'s logged line gains `kernel_beat=<age>s` beside `plan_age`, so
   the keep-alive reports it too while it is loaded.
4. A reader that survives both jobs being unloaded: `asf/cli.py` gains `kernel beat --product P`
   under the existing `kernel` subparser, printing one line — the age, the tick time, the session
   count and the verdict counts — and exiting 1 when the age is over
   `kernel.heartbeat.kernel_stale_after_s` or the file is missing, naming the age, the limit and
   the exact command that starts the tick. It reads state only: no lock, no launchd, no git, no
   GitHub.
5. `asf/doctor.py`: `check_kernel_beat(product)` → `[(required, ok, detail)]`, registered as a
   `kernel beat` row beside the `ci heartbeat` rows at `:1949-1950`, in the shape
   `check_ci_heartbeat` already returns. A product with no beat file and no kernel jobs yields no
   row rather than a red one.
6. Create `tests/kernel/test_kernel_beat.py` with one case per acceptance line, launchd patched
   through `scheduler._launchd_status` and the no-launchd/no-git/no-GitHub claim asserted by
   running the command with those paths patched to raise.
