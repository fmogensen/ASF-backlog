## Description
stories: S-8155
writes: asf/workers/health.py, asf/workers/stall.py, asf/views/sessions.py, asf/harvest/harvest.py, tests/test_session_identity.py, tests/test_harvest.py, tests/test_views.py

Depends on T-9451 (`identity_alive`). It queues behind T-9452 on the shared test file.

**Files**

- `asf/workers/health.py`: `health(..., alive=None, session_source=None)`, plus one helper
  `alive_for(product, runs, session_source=None)` that the other three call. It lives here
  because harvest and stall already import `health`.
- `asf/workers/stall.py`: `stall(..., alive=None, session_source=None)`.
- `asf/views/sessions.py`: `live_rows(product, alive=None, session_source=None)`. `render` gains
  `alive=None` for now (T-9454 adds `cfg` and the Other group).
- `asf/harvest/harvest.py`: `reap_hold(record, alive=None, session_source=None)`, and the one
  `alive` passed from `reap` and the `run_harvest` loop (D7).
- `tests/test_harvest.py`, `tests/test_views.py`: the D4 fixture patch, in the two fixtures only.
- `tests/test_session_identity.py`: `AliveIsIdentityTest`.

**Steps**

1. `health.alive_for(product_or_name, runs, session_source=None) -> callable(pid)`: `cfg =
   spawn.load_cfg()`, `observed, why = observe.read(cfg, pool.accounts_from_config(cfg),
   source=session_source)`. `why` → return `pid_alive`. Otherwise return
   `observe.identity_alive(observed, runs)`. `pid_alive` stays and is still the D10 fallback.
2. `health()`: when `alive` is None, `alive = alive_for(product, sessions.values(), session_source)`
   after `load_sessions`. It is built once and handed to every `gather`, `publish_gap` and
   `reap_verdict` as today. `stall()`: the same over `pool_mod.live_sessions(product)`.
   `live_rows()`: the same. `sessions.pid_alive` stays, because `test_pid_alive` calls it.
3. `reap_hold` as D7. `reap(...)` and the `run_harvest` loop build one `alive` over
   `read_sessions(state_dir).values()` and pass it.
4. Nothing here reads an observed session that no run of this product owns. `identity_alive` is only
   ever asked about a run's pid, so a foreign session is invisible to health and stall (spec Out).
5. D4: in `tests/test_harvest.py`'s case at `:411` and in `ViewsTestCase.setUp`, patch
   `asf.workers.observe.source_from_config` to return `observe.FakeSource([{'pid': os.getpid(),
   'ppid': 1, 'env': {}}])`. Scope the harvest patch to the one test method that uses
   `os.getpid()`. No assertion changes.
6. Run the whole suite. Anything red *only* because it now observes the real table gets the D6
   fixture treatment, and the report names it.
7. `AliveIsIdentityTest` as below.

**Acceptance**

- `AliveIsIdentityTest(Home)`
  - `test_reused_pid_is_dead`: a live run with pid 4242 and `session X`, and the source shows pid
    4242 with `session Y` → `health` writes `ended … dead pid` for the run.
  - `test_reused_pid_by_a_foreign_session_is_not_stalled`: the same with a foreign session at the
    pid → `stall` reports `DEAD`, not `STALL`.
  - `test_legacy_run_without_session_uses_the_pid`: a run with no recorded `session`, and pid
    observed → still live.
  - `test_foreign_sessions_are_never_judged`: the source shows two foreign sessions → `health`
    writes no line and `stall` reports none for them.
  - `test_reap_hold_uses_identity`: `harvest.reap_hold` on an ended run whose pid now belongs to
    another session → no hold.
