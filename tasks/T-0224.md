**Steps**

1. `render_daily(root, day, items)` with no `records`: the section is present, one row labelled
   `this record`, the `Total` row equal to it, the headline exactly
   `0 features on production this week, — per feature — last week 0, — · Δ features +0 · Δ cost —`,
   and no `Not read:` text. The em dashes are §2.4's and are asserted as written (P15).

   line is before the `cost:` line in its stdout (§4). Driven through the module's own CLI the way
   `run_cli` already does in this file.
4. A record whose only Feature shipped in both windows' worth of history — an event in each week —
   is counted in exactly one: the newer event wins (`shipped`'s "newest wins"), so this week has it
   and the previous does not.

   `throughput_records` is the only function that touches the operator home.
