## Description
stories: S-33603
writes: asf/record/ingest.py, tests/test_ingest.py
after: none

The spec's sixth **In** bullet (D6) and its `## The design` §3. Today a plan reached only by a typed
`links.plan` — a card the `asf migrate` pass wrote from a pre-ASF plan on a pre-lane branch — produces
**no** `plan on …` evidence line at all, so there is nothing for Task 3's gate to read. `_spec_home`
already solves exactly this for the spec; `_plan_home` is that function with `plan` for `spec`.

**Files**

- `asf/record/ingest.py` — `_plan_home` (new, beside `_spec_home` at `:488-505`); the Feature block's
  `plan_on_main` / `plan_branch` locals and the two `lines.append` branches (`:826,848-852`)
- `tests/test_ingest.py` — `APlanReachedOnlyByItsLink` (new class)

**Steps**

1. `_plan_home(meta, fev, ev, product)` → `(on_trunk, carrier_branch)`, immediately below `_spec_home`,
   mirroring it line for line: `fev['plan_on_main']` answers first; else the carrier is
   `fev['plan_branch']`, or the `origin/`-stripped revision of `fev['plan']` when that key carries a
   `<rev>:<path>` reference; else the typed `links.plan`, looked up through
   `evidence.doc_carriers(_path_only(link), ev.get('branches') or (), product)` — the trunk first,
   then every remote branch, in one `cat-file` (P10). `product is None` or no link returns
   `(False, '')`, as `_spec_home` does. Its docstring says what it is for in the same words the
   spec's D6 uses.
2. The Feature block reads it: `plan_on_main, plan_branch = _plan_home(rec['meta'], fev, ev, product)`
   beside the existing `spec_on_main, spec_carrier = _spec_home(...)` at `:824`.
3. `plan_approved` at `:826` becomes `bool(plan_review and plan_review[1] == 'APPROVED') or plan_on_main`
   — the bare `bool(fev.get('plan_on_main'))` replaced, so a plan the trunk really holds counts
   however it was matched (D6). This is the **only** stage input that changes: `plan_dict['exists']`
   at `:837` keeps reading `fev.get('plan')` (PD8), and the identically-shaped `plan_approved` computed
   for the earlier, non-Feature block at `:752` is left alone, exactly as the spec says.
4. The two evidence branches at `:848-852` read the new locals — `if plan_on_main:` →
   `plan_on_trunk(product)`, `elif plan_branch:` → `f"plan on {plan_branch}{r}"` with the review round
   appended as today. The line's **shape** does not change; only how far the search reached.
5. `APlanReachedOnlyByItsLink` (new class): a migrated Feature whose `links.plan` names
   `docs/plans/f-0xxx.md`, absent from the trunk and present on one pre-lane remote branch, with the
   lane's own discovery finding nothing, gets the evidence line `plan on <that branch>` and no
   `plan on origin/<trunk>`. Cases: the **same** link found on the trunk gives `plan on origin/<trunk>`
   and makes the Feature read `plan_approved` with no review row (the D6 half); a link on **two**
   branches takes `doc_carriers`' first, deterministically; a Feature the lane did discover keeps
   today's answer byte for byte and never reaches the link lookup; a Feature with no `links.plan`
   and no discovery gets **no** `plan on …` line, unchanged (the Out bullet — the gate needs a named
   carrier and the absence of evidence refuses nothing); a product whose trunk is not `main` renders
   `plan on origin/<its trunk>` through `plan_on_trunk`; and `product=None` returns `(False, '')`
   without touching git.
6. The existing spec-side assertions in `tests/test_ingest.py` are re-run unchanged, and
   `LandingOutranksThePlan` (`:209`) is asserted still green — it is the one class in that file whose
   subject is the plan's own evidence.
