## Description
stories: S-33603
writes: asf/feeder/rows.py, tests/test_feeder.py
after: Task 1

The spec's fifth **In** bullet (D5) and its `## The design` §2. A coder reads the plan from the trunk;
a Feature whose plan is on a branch is landed first, exactly as its spec already is. `land_spec_row`
becomes the `doc='spec'` case of one function, so every existing caller, row and golden of it is
unchanged byte for byte.

**Files**

- `asf/feeder/rows.py` — `PLAN_ON_BRANCH_RE`, `plan_carrier`, `land_doc_row`, `land_spec_row`
  (now a two-line delegate), `land_plan_row`; the `plan-approved`/`building` arm of `_one_feature_rows`
- `tests/test_feeder.py` — `APlanOffTheTrunkFeedsNoCoder` (new class)

**Steps**

1. `PLAN_ON_BRANCH_RE = re.compile(r'^plan on (?!origin/)(\S+)')` beside `SPEC_ON_BRANCH_RE` at
   `:170-171`, with the same one-line comment naming ingest's line. The `(?!origin/)` is what makes
   `plan on origin/<trunk>` — which Task 2 still writes for a landed plan — read as no carrier.
2. `plan_carrier(feature)` beside `spec_carrier` (`:292-299`), the same six lines against the new
   regex, returning `''` when no line matches.
3. `land_spec_row` (`:1069-1086`) is renamed `land_doc_row(feature, product, occupancy, doc)`: the
   carrier comes from `spec_carrier(feature) if doc == 'spec' else plan_carrier(feature)`, and every
   literal `'spec'` in its `brief_kind`, its `_waiting_doc` call and its reason becomes `doc`. The
   APPROVED → LAND reason is the spec's: `f'{doc} approved on {carrier}, not on the trunk: the lane '`
   `f'adopts it and lands it — no coder starts before it is on the trunk'`. Its docstring gains the
   plan half of what it already says about the spec.
4. `land_spec_row(feature, product, occupancy)` stays, as
   `return land_doc_row(feature, product, occupancy, 'spec')`, and `land_plan_row` is the same with
   `'plan'`. The spec's row is therefore byte-identical to today's and `tests/test_feeder.py`'s
   existing spec-landing assertions are re-run untouched — asserted, not assumed.
5. `_one_feature_rows` (`:1032-1033`) gains one arm above the existing one, exactly as the spec writes
   it: `elif word in ('plan-approved', 'building') and plan_carrier(f): out.append(land_plan_row(f, product, *waits))`,
   then today's `elif word in ('plan-approved', 'building'): out.extend(task_rows(...))`. `*waits` is
   the same `(occupancy,)` tuple the spec arm above it already passes, so the PUSHED → LAND case
   (the plan branch pushed and waiting on the lane) comes from `_waiting_doc` for free.
6. Nothing else in the feeder is touched. Active Tasks get their rows from `branch_rows`, which this
   arm never reaches (D5), and `delivery_rows` runs before `feature_rows` in `plan_rows` (`:1472-1474`)
   and is not gated on the carrier — both are asserted in step 7 rather than left to the reader.
7. `APlanOffTheTrunkFeedsNoCoder` (new class): a Feature at `plan-approved` with the evidence line
   `plan on plan/f-0001` and two New Tasks with real `writes:` gives one
   `APPROVED → LAND  WAITS ON landing: plan approved on plan/f-0001` row that launches nothing, and
   **no** PLAN → CODE row for either Task; the same fixture at `building 1/3` gives the same.
   Cases: with `plan on origin/main` instead, both Tasks launch coders as they do today; with **no**
   `plan on …` line at all, both Tasks launch (the Out bullet — absence refuses nothing); a Feature
   at `spec-approved` with a `plan on <branch>` line is untouched by the new arm and still takes the
   spec arm above it; an **Active** Task of a gated Feature still gets its `branch_rows` row, so a
   coder already on a branch is not stopped mid-flight; a gated Feature's plan branch that the
   occupancy says is pushed and waiting gives PUSHED → LAND, not APPROVED → LAND; and every existing
   `land_spec_row` assertion in the file is re-run green, which is what proves step 4's delegate.
