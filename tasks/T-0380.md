**Steps**

1. The constants: `MAX_STALL_RERUNS = 2` and `STALL_HISTORY_TTL_S = 48 * 60 * 60`, with §2.7's
   reason on the second — two days, so a backfill on either side of midnight still joins.
2. `load` (`:1160`): `'stalls'` joins the key tuple, in the **list** branch beside `started` and
   `relief` (PD11).
3. `prune` (`:1198`): `data['stalls']` is filtered to the records whose `at` is within
   `STALL_HISTORY_TTL_S` (PD10).
4. `update_stalls`' cancel (Task 3's step 4) gains the count and the cap, §2.4:
   - `prior` is the number of `stalls` recorded for the same `(branch, sha)` across the `relief`
     records and the `stalls` history, so it survives the relief record leaving the file.
   - The successful cancel appends `{'run': rid, 'branch': branch, 'sha': sha, 'step': step,
     'at': _iso(now), 'job': job_name}` to `data['stalls']` — §4.1's shape — always, cap or no cap:
     the history is what the stream joins (§2.7) and what the next `prior` counts.
   - `prior + 1 <= MAX_STALL_RERUNS` → the relief record as Task 3 writes it, now carrying
     `'stalls': prior + 1`.
   - `prior + 1 > MAX_STALL_RERUNS` → the run is cancelled and **no** relief record is written
     (D8), with §2.4's loud line: `ci queue: NOT re-running {kind} run {rid} ({item}) — step
     "{step}" has stalled {n} times on {branch} at {sha[:9]}; the step is the defect, not the run`.
5. `_rerun_cancelled` (`:1998`): the re-run line for a record carrying `stall` is §2.4's, because
   the existing one reads `trunk run None at ? started after waiting …` for a record with no
   `trunk_id` — `ci queue: re-ran {kind} run {rid} ({item}, {label}) — cancelled {n} min ago,
   stalled in step "{stall_step}"`. One branch on `rec.get('stall')` where `what` is built; the
   dry-run, the refused re-run, the TTL drop and the stale-workflow refusal are untouched and apply
   as they do to a relief cancel (P12).
6. `ReRunTests` in `tests/test_ci_step_silence.py`, named exactly as §3.4 names them:
   - `test_the_cancel_writes_a_relief_record_carrying_the_class_and_the_step`
   - `test_rerun_ids_carries_the_cancelled_run_so_the_lane_waits` — `ci_queue.rerun_ids(state_dir)`
     (`:1186`) holds the id while the record lives.
   - `test_the_record_is_re_run_on_the_next_pass_with_nothing_to_wait_for` — the `started` clause
     of Task 3: `gh run rerun` in the argv log on the pass after the cancel.
   - `test_the_re_run_line_names_the_step_it_was_cancelled_for`
   - `test_a_stale_workflow_still_refuses_the_re_run` — `_workflow_change` (`:2052`) is consulted
     for a stall record as for any other.
   - `test_the_third_stall_on_one_sha_is_cancelled_and_not_re_run` — the loud line, no relief
     record, and no `gh run rerun` on any later pass.
   - `test_the_cap_is_counted_per_branch_and_sha_not_per_run` — three different run ids on one
     `(branch, sha)` hit the cap; the same branch at a new sha starts again at zero.
   - `test_the_history_record_is_written_even_at_the_cap` — the `stalls` list carries all three.
   - `test_the_history_is_pruned_at_forty_eight_hours` — over `prune` directly.
7. `tests/test_ci_queue.py`: one case added — `test_a_queue_file_from_before_the_stall_watch_loads`
   — `load` over a file with neither key gives `stalled == {}` and `stalls == []`, and `prune` over
   it raises nothing (P9). No existing assertion changes.
