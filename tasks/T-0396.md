§2.6's second half and §2.7. Throwaway code under `tools/spike/f-0068/`, exactly as F-0065's probe
harness is (D11, P21): committed so it can be re-run, named for deletion in the document it
produces, and importing nothing from `asf/` (PD13).

Both Stories are here because they are one file and one fixture directory. §3.8's three refusals are
assertions about the same code path §3.7's arithmetic runs, and the fixture has to be designed as a
whole: F-9001 is the good comparison, F-9002 the lane that landed nothing, F-9003 the rows that
carry no lane. A Task that shipped the arithmetic against a one-Feature fixture would have its
fixture rewritten by the next one.

The fixture is **three** files, not two (PD12): a Feature's Tasks are resolved through the items map,
and neither stream carries a parent.

**Files**

- `tools/spike/f-0068/compare.py` — the instrument, stdlib only, read-only, no `asf` import
- `tools/spike/f-0068/fixture/index.json` — `{id: {type, parent}}` for F-9001, F-9002, F-9003 and
  their Tasks
- `tools/spike/f-0068/fixture/sessions.jsonl` — two lanes with known totals, and F-9003's
  lane-less rows
- `tools/spike/f-0068/fixture/landings.jsonl` — the landings those sessions earned
- `tests/test_quota_pressure.py` — `InstrumentTests`

**Steps**

1. `tools/spike/f-0068/compare.py`, opening with the docstring F-0065's precedent sets: what it is,
   that it is throwaway under F-0068 D11, that it is named for deletion in
   `docs/research/hosted-runtime-vs-the-local-pool.md`, and that nothing under `asf/` imports it.
   `argparse`, `json`, `os`, `glob`, `statistics` and `sys` — nothing else, and no `asf` import
   (PD13).
2. The reader: `streams(root, name)` globs `<root>/metrics/<name>/*.jsonl` and falls back to
   `<root>/<name>.jsonl`, so the same `--root` serves a real backlog checkout and the flat fixture
   the spec names (PD13). `items(root)` reads `<root>/index.json`. `subtree(items, fid)` walks
   `parent` upward from every item and yields the Feature and its descendants — the five lines that
   replace `metrics.descendants`.
3. The grouping: every session whose `item` is in the Feature's subtree, keyed by
   `lane = s.get('lane') or 'unknown'` (PD15). One row per lane present, `unknown` among them.
4. The columns, §2.6's table exactly: `sessions`; `tasks landed` — the subtree's Tasks with a
   `landings` event whose `(job, branch)` matches one of this lane's sessions' `(task, branch)`
   (PD14); `tasks open` — the subtree's Tasks with none; `USD (metered)` — `Σ usd`, `—` when no
   session of the lane reported one; `cost per Task` — `USD ÷ tasks landed`, `—` when either is
   missing or zero; `in / out / cache rd / cache wr` — the four dimensions, each summed on its own
   and never added together (P20, D8); `branches` — distinct non-null `branch`; `rounds per PR` —
   the mean of `max(round)` per branch, with the median beside it (PD17); `minutes` — `Σ minutes`.
5. The USD heading is `USD (metered)` and nothing shortens it (D8). Under the table, one sentence of
   the document's stamp: which lane's figure is money that moved and which is a price list applied
   to a subscription. The tokens are printed beside it because they are the one term both lanes
   measure the same way.
