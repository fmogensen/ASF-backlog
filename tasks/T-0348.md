§2.6. One regex and one function over text the session wrote, in the grammar every brief hands it
(P8). Independent of the leaf by construction: it reads a string and returns a string or None.

**Files**

- `asf/workers/report.py` — `OPERATOR_RE`, `BLOCKED`, `needs_input`; the module docstring gains the
  sentence naming the second thing a report declares
- `tests/test_report.py` — `NeedsInputTests`

**Steps**

1. Beside `NO_RE` and `UNPUSHED` (`asf/workers/report.py:31-33`): `OPERATOR_RE` and
   `BLOCKED = 'blocked'` exactly as §2.6 types them. `BLOCKED` is then the one owner of the word,
   and `UNFINISHED` (`:104`) is recomposed as `(PARTIAL_or_literal, BLOCKED)` so the two cannot
   drift — `UNFINISHED`'s value is unchanged and `footprint_claim` (`:109-133`), its only reader
   today, is untouched.
2. `needs_input(text)`: the first `OPERATOR_RE` match's `what`, stripped, else — when
   `parse(text).get('status')` is `BLOCKED` — that report's own words: its `left out:` if it has
   one, else the first line of the whole text. None otherwise, and None for empty / `None` text.
   `parse` is the existing reader (`:35-58`), so "the last REPORT block wins" is inherited, not
   restated.
3. Nothing else: no phrase list, no tool-error read, no "waiting for CI" (D5, D11).
4. `NeedsInputTests`: the first `NEEDS OPERATOR:` line of a text carrying two; the words of a
   `status: blocked` report when there is no such line (its `left out:`, and its first line when
   there is no `left out:`); None for a `status: done` report, for a report whose prose mentions
   waiting for CI, for text with no REPORT at all, for `''` and for `None`. Plus: a `NEEDS
   OPERATOR:` line **outside** any REPORT block is still found (the brief tells a session to print
   it "on its own line", not inside the block), and `UNFINISHED` still equals `('partial',
   'blocked')`.
