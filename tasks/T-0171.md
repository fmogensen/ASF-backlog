## Description
stories: S-16210
writes: asf/doctor.py, tests/test_doctor.py
after: Task 1

§2.8. One more row, appended like `capacity`'s with `required=False`: a wrong table is not a reason
to call the whole factory red, and the launch itself already refuses an unmapped label
(`spawn.model_arg`, `asf/workers/spawn.py:251-260`).

**Files**

- `asf/doctor.py` — `check_models(cfg, product)`; `run()` appends its findings as
  `('models', False, ok, detail)` after the `capacity` rows (`:478-480`); the module docstring's
  row list (`:3-4`).
- `tests/test_doctor.py` — the three details of §2.8 and the `required=False` assertion.

**Steps**

1. `check_models(cfg, product)` → `[(ok, detail)]`, the same shape `check_capacity` returns.
   The valid need keys are `set(briefs.build.KINDS) | set(conventions.DEFAULT_MODELS)` (P11), and
   the valid labels are the keys of `worker_pool.models` in `cfg`.
2. An unknown key → `models: 'corect' is not a job need (have: spec, plan, …, correct/judgement)`,
   the have-list sorted.
3. A value no `worker_pool.models` maps →
   `models: 'medium' for 'plan' is not in worker_pool.models (have: heavy, light)`.
4. No `worker_pool.models` configured at all → one skip-shaped ok detail saying so, not a finding
   per key: a checkout with no operator config must not print thirteen reds.
5. Clean → one row, `models: <n> needs, <m> labels — heavy: spec, plan, adjudicate, review, groom,
   reshape, correct/judgement`, with both counts computed from the table it was handed (P11).
6. `run()` appends each finding as `('models', False, ok, detail)` directly after the `capacity`
   rows, so `is_red` is unmoved and `format_table`'s column widths absorb the new name.
7. `tests/test_doctor.py`: the three details, that the row's `required` is `False`, and that a
   product with a bad table does not make `is_red(rows)` true.

**Gate**

