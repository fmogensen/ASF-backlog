The spec's `asf/workers/runtime.py — FakeRuntime` section and D12. Every scripted result gains a
schema-valid report before anything demands one, so that Task 4's clause lands on a suite that is
already telling the truth. `failure_reason` keeps its shape — the typed body arrived with Task 1.

**Files**

- `asf/workers/runtime.py` — `FakeRuntime.run` writes
  `step.get('result', '') + '\n\n' + report.render(kind, …)` into the log's result line, with
  `kind = step.get('kind') or 'coder'`; `step.get('report')` false writes no report at all.
  `Result(text=…)` stays the step's own string, so every existing assertion on `Result.text`
  holds. The class docstring gains the two new step keys. `failure_reason` is unchanged.
- `tests/test_workers.py`, `tests/test_lifecycle.py`, `tests/test_tick_steps.py`,
  `tests/test_session_identity.py`, `tests/test_sample_product.py` — the scripted results that
  assert on the *log's* result text (rather than `Result.text`) updated to expect the appended
  block; any fixture that needs a particular kind gains `'kind': …` on its step.
- `tests/test_workers.py` — `FakeRuntimeReportTest` (new, the spec's two cases).

**Steps**

1. `FakeRuntime.run` per the spec, `report` imported at module scope (it already is, `:21`).
2. Run the five files and fix what the appended block moved, one file at a time; a test that
   asserted on the log's result string asserts on its first line or on `report.check` being
   `None`, never on the absence of a report.
3. `FakeRuntimeReportTest`.
4. The whole suite, because `FakeRuntime` is what most of it runs on.
