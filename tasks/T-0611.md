The spec's §3, plus the one tuple entry without which the row it adds is dropped by the feeder's
own gate on every tick (PD5). A code branch asking for round `stalemate_round` or higher gets the
adjudicate row the document lane has had since F-0080, not another round — and the ceiling is tested
**before** Task 2's floor, because a branch that reached the ceiling has had real reviews with real
verdicts and there is something for an adjudicator to rule on, where the floor's case is that there
is not (D4).

Read **PD5** first — it is the whole reason this Task writes `asf/invariants.py` — then **PD4** (why
this Task is second and what the window between the two landings costs).

`after:` names Task 1 as well as Task 2 only so the wave is unambiguous; the binding constraint is
Task 2, whose `writes:` this Task intersects on two files.

**Files**

- `asf/feeder/rows.py` — the ceiling guard inside `lane_rows`' `if review:` branch, **above** Task
  2's floor guard.
- `asf/invariants.py` — `'STALEMATE → ADJUDICATE'` joins `LANE_LAUNCH_KINDS['REVIEW']` (`:472-476`).
- `tests/test_feeder.py` — **new class** `ReviewRoundCeilingTests`.
- `tests/test_invariants.py` — the case beside `test_r10_the_review_launch_on_a_review_branch_is_legal`
  (`:59-62`).

   `limit = stalemate_round(product)`; when `rnd >= limit`, append the spec's row — `kind=STALEMATE`,
   `action=LAUNCH`, `brief_kind='adjudicate'`, `branch=branch`,
   `reason=f'review round {rnd} >= r{limit}: adjudicate, no further round'` — and `continue`. The
   reason line mirrors the document rule's at `:1086-1091`; keep the two readable as the siblings
   they are.
2. `asf/invariants.py`: add `'STALEMATE → ADJUDICATE'` to `LANE_LAUNCH_KINDS['REVIEW']` (PD5) and
   extend `check_i4`'s docstring clause from *"REVIEW takes the review session"* to name the
   adjudicate the ceiling sends. Change nothing else in the map — `BACK`'s tuple, `_FREE_STATES` and
   `OCCUPANCY_LAUNCH_KINDS` are untouched, and `OCCUPANCY_LAUNCH_KINDS['busy']` /
   `['waiting_landing']` alias `LANE_LAUNCH_KINDS['REVIEW']`, so they widen with it by construction:
   a branch the lane has no record of but whose item is busy or pushed accepts the same adjudicate,
   which is the same row for the same reason.
3. `tests/test_feeder.py` `ReviewRoundCeilingTests`: a review round below `stalemate_round` emits
   `PUSHED → REVIEW` as today; at it and above, one `STALEMATE → ADJUDICATE` row on the same branch
   with `brief_kind='adjudicate'` and no review row beside it; the limit is read from
   `conventions.stalemate_round` and a product that sets it takes effect; the ceiling is tested

   a review row beside it is the second-launching-row finding, not a kind finding.
