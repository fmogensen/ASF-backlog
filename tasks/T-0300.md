## Description
stories: S-30455
writes: asf/record/spec_check.py, asf/cli.py, tests/test_spec_check.py
after: Task 5

§2.6. The memory file said: an approved spec goes stale, so grep every symbol it names before
planning. Nothing in the tree does that — `asf/drift.py` is version drift and `asf/precheck.py`
is the pass over a code branch, and neither reads a spec (§1.1). `after:` names Task 5 for
`asf/cli.py`, which the two registrations share (PD11).

**Files**

- `asf/record/spec_check.py` — new; `tokens(text)`, `absent(tokens, repo)`, `cmd_check`,
  `register`
- `asf/cli.py` — the `spec-check` registration
- `tests/test_spec_check.py` — new module; `SpecCheckTests`

**Steps**

1. `asf/record/spec_check.py`, docstring first: why it exists (a spec is a set of claims about a
   checkout, and the checkout moves), and what it deliberately does not read. No document
   directory in a string literal (PD14).
2. `tokens(text)` — inline backticked tokens only. Strip fenced blocks first, then match
   `` `([^`\n]+)` ``. §2.6's reason is exact: a fence is an example, and a spec that shows what an
   absent path looks like must not be a finding about itself — §3's T6 asserts that directly.
3. Classify each token in one pass: a **repo path** when it matches `[\w./-]+\.\w+(:\d+)?` and its
   first segment is a directory of the repo or the token contains a `/`; a **dotted symbol** when
   it matches `[A-Za-z_][\w.]*\.[A-Za-z_]\w*` with no `/` and no space; **anything else** — a
   shell word, a yaml key, a phrase — which is not checked and not reported. The third class is
   most of what a spec writes and is why this check works on the specs already in the tree rather
   than only on ones written after it (§1.4).
4. A path is present when the file is in the checkout. With a `:<line>` suffix, a file shorter
   than that line is one row reading `file has <n> lines` — the drift PD16 is made of, and the
   one class of finding that is a stale citation rather than an absent thing.
5. A dotted symbol is present when its last segment is defined in the module its dots resolve to
   — `def `, `class `, or an assignment at column 0 — and, when the dots resolve to no file,
   anywhere under `asf/`. Text search, not import: a spec names symbols that do not exist yet,
   and importing a module to find out would run it.
6. Output is §2.6's PD-shaped table, a plan session pastes it into its drift list: the
   `spec-check <path> against <repo> — <n> tokens read, <m> absent` header, the
   `| token | kind | what the checkout says |` table with one row per absent token, and
   `== <m> absent`. Exit 1 when the table has rows, 0 when it does not. `--repo R` points at
   another checkout; the default is the cwd's toplevel, found with `git rev-parse`.
7. `register(sub)`: `asf spec-check <spec> [--repo R] [--json]`; `asf/cli.py` gains
   `from asf.record import spec_check` / `spec_check.register(sub)` beside Task 5's. Not a view,
   so the plugin is unchanged.
8. `tests/test_spec_check.py` with `SpecCheckTests`, §3's T6 case for case over a temp repo: a
   present path reports nothing; an absent one is one row; a `:900` on a 40-line file is one row
   naming the length; a defined dotted symbol reports nothing and an undefined one is one row;
   backticked prose, a shell word and a yaml key are read and not reported; a token inside a
   fenced block is not read at all, so a spec whose fence shows an absent path reports nothing
   for it. Exit 1 with rows.
9. The case that matters most, and the reason this Story exists: run it over
   `docs/specs/f-0056.md` in this checkout and assert the only rows are citations this plan
   already recorded as drift (PD16). A spec checker that cannot read its own spec is not one.
