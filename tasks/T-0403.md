§2.2 steps 1–6, §2.3 and §2.4: the new module, the command surface, the step framework every
later Task hangs a step on, and the six steps whose failure ends the run — the host, this `asf`,
the config, the repos, the adopt, the account.

**Files**

- `asf/install.py` — new: `CONFIG_TEMPLATE`, `detect_accounts`, `account_stanza`, the step
  framework (`Step`, `run_steps`, the summary table, the exit status), `cmd_install`, `register`,
  and steps 1–6
- `asf/init.py` — `register_commands` also registers `asf install`
- `tests/test_install.py` — `InstallCommandTests`, `InstallConfigTemplateTests`,
  `InstallAccountsTests`, `InstallStepsTests` (its steps 1–6 methods)

**Steps**

1. The module docstring names what it is and what it is not: it configures, it never installs the
   package (D2), and the bootstrap it is `exec`ed by is named
   `os.path.join('tools', 'install' + '.sh')` (PD15).
2. The step framework: one `Step` record of `(label, fn, abort)`, a runner that prints one line
   per step — `ok` / `wrote …` / `already in place` / `repaired …` / `FAILED … (exit N)` — stops
   on a failed `abort=True` step, records and continues past the rest, and ends with the summary
   table and `0` only when every step passed. This is the shell's own discipline
   (`tools/install.sh:141-147`), moved without change.
3. `register`: `asf install` with `--product` (required), `--repo DIR`, `--repo-url URL`,
   `--record DIR`, `--record-url URL`, `--scheduler {launchd,cron,none}`,
   `--account NAME[:CONFIG_DIR]` (`action='append'`), `--fake-workers`,
   `--console-permissions {user,repo}`, `--allow-checkout`, `--yes`. Added to
   `asf.init.register_commands` beside `upgrade` and `hooks` (PD13).
4. The missing-flag rule, before anything is written: on a tty a missing `--repo`, `--record` or
   `--scheduler` is asked for once each with its default in the prompt; with `--yes`, or off a
   tty, one with no default is one `NEEDS OPERATOR` line and a non-zero exit. `--record` has no
   default unless the product file already carries `backlog_dir` (PD9).
5. Step 1 — the host: `git` on `PATH`, and `gh` unless the product has no PR host. Each missing
   one is a `NEEDS OPERATOR` line naming it; nothing is installed (the spec's Out).
6. Step 2 — this `asf`: print `cli.version_string()`. A checkout or editable install refuses with
   one `NEEDS OPERATOR` line unless `--allow-checkout` is given (D2). A checkout is what
   `cli._checkout_root()` finds.
7. Step 3 — `CONFIG_TEMPLATE`: one `str` with slots for `default_product`, `scheduler.kind`,
   `capacity.total.sessions` and the account block, a header pointing at
   `docs/config.example.yaml` for every key it does not write, and `# TODO` on the three
   `worker_pool.models` ids and nothing else. Written to `env.config_path()` only when absent,
   with `<ASF_HOME>/products/` created beside it; an existing file is never rewritten — the keys
   it lacks are printed as the diff that was not made, the way `cmd_init` prints its product diff
   (`asf/init.py:277-280`).
8. Step 4 — the repos: `--repo-url` / `--record-url` are cloned into `--repo` / `--record` only
   when that directory does not exist. An existing directory is read and never written to.
9. Step 5 — the adopt: `asf init --product <p> [--repo DIR] [--backlog DIR]`, called in-process
   through `init.cmd_init` so its exit status is the step's (D3: one writer for
   `products/<p>.yaml`).
