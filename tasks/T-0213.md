## Description
stories: S-18807
writes: asf/tick/step_train.py, tests/test_tick_steps.py
after: Task 7

§2.7, and the promise the whole card rests on: one red Task never holds the other five. The
narrowing is the attribution harvest already makes, the hand-back is the correction loop that
already exists, and the only new thing is a revert commit somebody can read.

**Files**

- `asf/tick/step_train.py` — the red pass replacing Task 6's stub.
- `tests/test_tick_steps.py` — the red cases of §3.5.

**Steps**

1. The verdict is the gate's own for a fast-forward product and `gh run view` on the train head
   for a pull-request one. A green train is nothing to do.
2. Narrowing, in order (D11): `harvest.red_modules(text)` first, then `harvest.gate_files(text)`,
   each intersected with each Task's `writes:` through `footprint.overlaps`. Exactly one Task
   matches → it is the culprit. More than one, or none → the newest Task on the train, then the
   next newest. Falling back to newest-first is what makes this terminate.
3. `git revert --no-edit <its commit>` on the train branch, pushed, its subject naming the Task
   and the run: `revert: T-0101 — red on train/code-20260924-0930 (run 41)`. The branch name comes
   from the registry row, never from a literal (PD7). CI re-runs on the new head; for a
   fast-forward product the cutter re-runs `land_set` once in the same tick.
4. The registry row for that Task moves to `reverted` and the seat count drops. A train whose
   Tasks are all reverted becomes `abandoned`, not merged as a no-op.
5. The Task goes back through the path that already exists:
   `hold_with_correction(state_dir, branch, record, 'gate', line, out, files, item_writes,
   touched, conv)` — the same call `land_set` makes for a red branch, with the same foreign-red,
   inert-diff and round-cap rules (`asf/harvest/harvest.py:985`). Its branch still exists (D14),
   so the FIX → CORRECT row the feeder raises next tick lands the correction on the work already
   there.
6. `size_floor: medium` is written on the Task's card in the record clone through
   `asf.record.setfield.set_typed` (PD15). The corrected Task gets its own branch off the trunk
   and its own pull request, and never rejoins a train.
7. A train that goes red twice in a row with no Task attributable is `abandoned`: every remaining
   Task is demoted the same way and the lane opens a fresh train on the next tick. That is the
   terminating case, and it is why step 2 falls back to newest-first rather than to nothing.
8. `TrainStepTests` per §3.5's red cases: a red train narrowing to the Task whose `writes:` the
   failing output names, reverting exactly that commit, leaving the other five on the train, and
   holding that Task with a correction and `size_floor: medium` on its card; a red train naming no
   Task's files reverting the newest Task first; and a second red with nothing attributable
   abandoning the train and demoting the rest. Plus one the spec implies and the test makes
   explicit: the demoted Task's worker branch is still on origin and `step_prs.candidates` offers
   it once its mark is cleared.
