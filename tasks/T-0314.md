the whole path exists from a probe to a line an operator reads, and every artefact on that path
has been opened by a test and searched for a secret.

**Files**

- `asf/credentials.py`:
  - `rule_id(root)` → the id of the live rule card whose `check:` basename is `credentials.sh`,
    from `rules.load_rules(root)`; `'credentials'` when there is none, or when the record cannot
    be read. This is D11's shared ledger key (PD10), and the fallback is what makes the day's line
    correct before the operator has installed the card.
  - `daily(product, root, event=None, now=None)` → always `0` (D12). In order:
    1. `results = check(product, cfg, fresh=True, now=now)` — the daily run always probes (D6).
    2. One `credentials` event per provider through `event` when it is given:
       `{provider, state, verdict, expires, days_left}` and **no `detail`** (§4).
    3. One summary line — `<n> providers: <n> ok, 1 EXPIRING provider-c (2d)` — which `run_part`
       turns into `daily: credentials ok — …`. A product with no providers prints
       `no providers configured`.
    4. The once-a-day operator line, raised by calling
       `file_bugs.report_operator_rules([{ 'rule': rule_id(root), 'line': <the quiet line>,
       'owner': 'operator' }, …], ledger, day)` over the ledger at
       `file_bugs.ledger_path(product.name)`, written back with the same module's writer — one
       function, one key, no duplicate on a tick that carries both (PD10). When it printed, one
       `needs-operator` event with the same message, the kind `tick.py:385-388` already writes.
    5. Every exception caught: printed as `credentials: <ExceptionName>: <msg>` (and, for a broken
       probe, `credentials: probe broken for <name>: <detail>`, the line §3's second
       `DailyStepTests` case asserts) and still `0`. A broken credential check never fails the day.
- `asf/tick/step_daily.py` — one entry in `parts`, after `scorecard` at `:36`:
  `('credentials', lambda: credentials_daily(product, root, event=event))`, with the local import
  beside the other three at `:28-30`.
- `tests/test_credentials.py` — `OperatorLineTest` and `NoTokenTest`:
  - `OperatorLineTest`: `daily()` over a product with an expiring provider raises exactly one
    `NEEDS OPERATOR` line ending in the renew command, keyed under the ledger's `operator` entry;
    a second call the same UTC day raises none; the key is the installed card's id when one is
    installed and `credentials` when none is.
  - `NoTokenTest`, §3's two cases: a probe that exits 0 printing
    `expires 2026-12-01T00:00:00Z token=<a value the test builds at run time from one of
    redact.SECRET_RULES, so no token shape is written into the test file itself>`. The test then
    reads the **whole text** of each artefact — `Result.detail`, the rendered table, the `--json`
    payload, the cache file on disk, and every event line the fake `event` collected — and asserts
    `redact.SCRUB_TOKEN` is in it and the literal value is not, while `expires` is still parsed to
    the timestamp. Second case: a probe whose stdout is 20 kB; `detail` is at most `DETAIL_MAX`
    characters.
- `tests/test_tick_steps.py` — two cases in the existing `DailyStepTests` at `:1447`:
  `test_credentials_never_fails_the_day` (a provider whose probe exits 1: `step_daily.run` returns
  0, prints `daily: credentials ok — …`, does not raise) and
  `test_an_exploding_probe_still_stamps_the_day` (the probe command does not exist: the part
  prints `credentials: probe broken for provider-a: …` and the day is stamped).
