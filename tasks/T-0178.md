## Description
stories: S-17456
writes: asf/record/check.py, tests/test_backlog.py
after: none

The spec's `### asf/record` second bullet. Four rules, one line per violation, in the shape
`cmd_check` already uses.

**Files**

- `asf/record/check.py` — `check_deliveries(canonical, add, find_line)`, called from the per-card
  loop of `cmd_check` (`:56`) or once after it: for each card with `delivers:` — every id exists
  in `canonical` and is not `removed`; each non-lead id carries `delivered_by:` equal to this
  lead; `delivers[0]` is the lead itself; no card carries both fields; no id appears in two
  `delivers:` lists. Each violation is one `add(rec, find_line(rec, 'delivers'), …)`.
- `tests/test_backlog.py` — `DeliveryFieldTests`.

**Steps**

1. `check_deliveries` and its call.
2. `DeliveryFieldTests`.
3. Run `python3 -m unittest tests.test_backlog -v` whole — `cmd_check`'s output is asserted
   line-for-line in places, and a new check must add lines only for a malformed delivery.

**Gate**

```sh
python3 -m unittest tests.test_backlog -v
python3 tools/run_tests.py
bash tools/check_generic.sh
bash tools/check_conventions.sh
```

**Acceptance**

```sh
python3 -m unittest tests.test_backlog.DeliveryFieldTests -v
```

- `test_member_must_point_back`: a member without `delivered_by:` → `asf check` names it.
- `test_no_item_in_two_deliveries`: the same id in two `delivers:` lists → one violation.
- `test_both_fields_on_one_card` → one violation.
- `test_a_well_formed_delivery_is_clean` → `asf check` is silent about it.
