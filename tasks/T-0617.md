The spec's §1, §2, §3 and §4 whole. When this lands, `MERGING` is never written without a number a
merge can use: the number is read once through `pr_number` (the facts' live PR, then the lane
record, then the host's own open PR for the branch at this head, written back onto the facts), a
branch that has none anywhere goes back to `PUSHED` to be given one, and the `PR_OPEN → PUSHED` row
stops an unnamed branch reaching the gate at all.

Read **PD4** first — the bounce has to terminate, and the trace is the thing this Task is judged on
— then **PD5** (no state filter on the first two terms), **PD6** (what the lookup costs and why the
guard sits above the room check), **PD7** (the forward references, and why `merge_prs` needs no host
test) and **PD8** (the incident's own branch needs no migration).

**Files**

- `asf/harvest/lane.py` — `NO_PR`, `pr_number` and `back_to_pushed` beside `merge_prs` (`:2968`);
  the guard at the head of `merge_prs`' loop (`:2973-2975`); the guard in `precheck` (`:2491-2496`);
  one new row in `next_state` inserted at `:1142`; the two new rows of the module docstring's
  transition table (`:28-75`).
- `tests/test_lane.py` — one method joining the existing `Transitions` class, and a **new plain
  `unittest.TestCase` class** `AMergeNeedsAPRNumber`.

`asf/invariants.py` is **not** on this list and must not change (PD9). Neither is
`asf/merge_queue.py` (C8).

**Steps**

1. `asf/harvest/lane.py`, beside `merge_prs`: `NO_PR = 'no PR number: nothing can merge it'` with
   the spec's comment, then `pr_number(lane, f)` and `back_to_pushed(lane, f, why)` — §1 and §2
   byte for byte, docstrings included. `pr_number`'s first two terms carry **no** state filter
   (PD5); the host arm accepts the answer only when `state` is `OPEN` and
   `not (head and f.get('head') and head != f['head'])`, so a head the host does not report is
   accepted and a head that disagrees is not. The write-back is
   `f['pr'] = dict(f.get('pr') or {}, number=number, state='OPEN', head=head or f.get('head'))`:
   filling `head` from the lane's own head when the host gave none changes nothing downstream —
   `next_state`'s T11 and CLOSED tests both read `pr.get('head') in (None, '', head)`
   (`:1074`, `:1105`), which our own head satisfies exactly as `None` did.
2. `merge_prs`, at the head of its loop: §3's five lines, replacing
   `b, number = f['branch'], (f.get('prev') or {}).get('pr')` with `b = f['branch']` /
   `number = pr_number(lane, f)` / `if not number: back_to_pushed(lane, f, NO_PR); continue`.
   **Above** the `room` test (PD6). No host test (PD7). Everything below the guard is unchanged —
   the budget wait, `dry_run`, `ci_admits`, `recheck`, the `MERGING` set, the merge, the queue arm
   and the whole conflict path keep reading the local `number`.
3. `precheck`, at `:2491-2493`: §3's second block — `f['how'] = 'gate'` /
   `number = pr_number(lane, f)` / `if isinstance(lane.host, GitHubHost):` /
   `if not number: back_to_pushed(lane, f, NO_PR); continue` / then the existing `check_gate` three
   lines, now inside that `if`. The `isinstance` test stays, and the `and number` comes off it: the
   whole point is that the falsy case is no longer a silent fall-through to `f['how'] = 'gate'`
   (P9). The `skip_regate` block and everything after it are untouched.
4. `next_state`, immediately after the `no PR host` keep at `:1140-1141` and **before** the
   `if s in (PR_OPEN, REVIEW)` row at `:1142`: §4's comment and its two lines,
   `if s == PR_OPEN and f.get('mode') == 'pr' and not n and not rec.get('pr'): return PUSHED, 'no PR
   number: a PR is opened again'`. Both halves of the test are required (C5) — the facts' `n` and
   the record's `pr` — so a pass whose `gh pr list` came back empty does not bounce a branch whose
   number the record knows, which is exactly the case `Lane.gather(prs=False)` produces
