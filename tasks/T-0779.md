The spec's `## The design` §A in full, plus the three fixture additions A1 needs: `split_labels`,
`fit_key`/`fit_asks`, `load_by_fit`/`free_by_fit`, and `Queue.free` gaining the keys it is being
asked about. No caller passes any key yet — **this Task is deliberately inert** (PD4), and the
proof of that is every shipped assertion in three suites reading unchanged.

**Read PD3 before starting**: `split_labels` must iterate the live runners alone. Building it the
way `label_classes` is built — declared labels folded in — makes A1's first assertion fail on this
fleet, because `fit_pool()` declares `b1`/`b2` as provider `beta`. Read **PD4** (a key `free` cannot
see is a key `shortfall` ignores, which is what makes this half safe alone and what makes Task 2's
union of keys load-bearing) and **PD11** (the three fixture parameters and what each must emit).

**Files**

- `asf/ci_queue.py` — five new module-level functions after `free_by_class` (`:1376-1378`);
  `Queue.free` (`:2181-2197`) gaining `keys=()`; the module doc's *free runners* paragraph

  `FakeGh` taking `pool=` and `labels=` (`:42-88`); `fit_pool`, `FIT_LABELS`, `ASKS`, `fit_history`
  and `class TestFitSupply(Base)`

**Steps**

1. `split_labels(runners, pool)` in `asf/ci_queue.py`, module level, directly after
   `free_by_class`, with the spec's docstring verbatim. Bucket each **online** runner's
   `norm_labels()` by its class — `class_key(by_name[r.name])` for a pool runner,
   `_label_key(r.labels, roles)` for one outside it, exactly as `load_by_class` (`:1363-1366`)
   decides a class — and per class keep the labels that at least one but not every bucketed runner
   carries, less `ci_pool.DEFAULT_LABELS`. A class the pool declares with no online runner gets
   `frozenset()`, never a missing entry. **Live labels only** (PD3): `pool` names the class and
   nothing else.
2. `fit_key(cls, asks)` and `fit_asks(key)`, the pair from the spec's §A. `fit_key('heavy', set())`
   is `'heavy'`; with labels it is the class, `'['`, the labels sorted and `'+'`-joined, `']'`.
   `fit_asks` inverts it and returns `(class, frozenset(labels))` — `fit_asks('heavy')` is
   `('heavy', frozenset())`. They must round-trip for every value either produces; C2 is why the key
   is a string at all (it is a JSON key in `expect`, in `started` and in a held entry's `free`, and
   a token in a line a person reads).
3. `load_by_fit(runners, pool, keys)` — `load_by_class` with one predicate added: for each key,
   count the online runners of `fit_asks(key)[0]` whose `norm_labels()` are a superset of the key's
   labels, at their `slots`, a busy runner holding all of them. A bare class key counts the whole
   class, so `load_by_fit(r, p, ['heavy'])['heavy']` and `load_by_class(r, p)['heavy']` must be
   equal on every fleet — assert that in step 8. Do not refactor `load_by_class` to call it: C5 is
   explicit that the class-keyed functions are left as they are, and `asf/capacity.py:325` and the
   status Runners row read that one.
4. `free_by_fit(runners, pool, keys)` — `{key: online - busy}` over step 3, the same one-line shape
   `free_by_class` has.
