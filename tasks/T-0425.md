## Description
stories: S-32604

after: none

The spec's `tools/install.sh` bullet and D8: the closing heredoc's last line is an instruction to
export a variable the resolution no longer needs; it becomes a statement of the rule and a
conditional, naming no path of its own (P10).

**Files**

- `tools/install.sh` — the closing heredoc at `:196-204`
- `tests/test_install.py` — `InstallScriptTest` gains the closing-line assertions (PD15)

**Steps**

1. The heredoc's `install: and start that session with ASF_PRODUCT=$PRODUCT so /asf:* reads this
   product.` (`tools/install.sh:203`) is replaced by the spec's three lines, byte for byte, with
   `$PRODUCT` substituted for `<product>`:

   ```
   install: /asf:* resolves the product from the working directory — a session started in
   install: <product>'s repo or its record needs no ASF_PRODUCT.
   install: set ASF_PRODUCT=<product> only for a session that runs outside both.
   ```

2. The two `/plugin` lines above it are unchanged — they are F-0107's, not this card's.
3. No path is printed. The installer knows only `$PRODUCT`; it never reads the product file, and the
   `asf` it installed is in a `pipx` venv so `python3 -c 'import asf'` is not available to it (P10,
   D8). A new `asf where` is the spec's **Out**.
4. `InstallScriptTest` (`tests/test_install.py:1669`) gains assertions on the closing output, on the
   stubbed PATH it already builds: the three lines are present with `$PRODUCT` substituted; no line
   of the output tells the operator to *start* a session with `ASF_PRODUCT` set; the word
   `ASF_PRODUCT` appears only in the conditional sentence; and no directory path appears in those
   three lines. The class's existing cases — the failing hooks step, the not-loaded clock, the exit
   status — are untouched.
