## Description
stories: S-32254
writes: asf/security/alerts.py, tests/test_security_alerts.py
after: Task 1

§2.6: one reader for two feeds, a cache that exists only so staleness is detectable, and
`violations()` in which an unreadable feed is a violation and never a pass (D9). No alert *value*
is read or printed, ever (P20).

**Files**

- `asf/security/alerts.py` — `Host`, `GitHubHost`, `read`, `violations`, `cache_path`
- `tests/test_security_alerts.py` — `FeedTests`, `CacheTests`, `ViolationTests`

**Steps**

1. `Host` with `secrets()` and `dependencies()` raising `NotImplementedError`, and the two field
   sets of §2.6 as their documented shapes — `{number, state, kind, url, created_at,
   locations_count}` and `{number, state, severity, package, ecosystem, url, created_at}`. The
   injection seam is the class, the way `ci_pool.Backend` is (P17).
2. `GitHubHost(product, run=None)`: `gh api repos/<slug>/secret-scanning/alerts?state=open&per_page=100`
   and `…/dependabot/alerts?state=open&per_page=100`, the environment from `security.gh_env`
   (PD7), 30 s each, `--jq` naming the fields it keeps — and **never** the `secret` field, with the
   comment saying that is F-0075's rule applied to someone else's API. A failure raises one error
   type the way `ci_pool.BackendError` does; `read` catches it.
3. `cache_path(product)` → `state/<product>/security/alerts.json` under `asf.env.state_dir`
   (`asf/env.py:849`) — the directory comes from the environment, no path literal beyond the two
   segments the spec names.
4. `read(product, host=None, now=None)` → `(feeds, age_h, why)`: the live feeds when both can be
   read, and then the cache is rewritten `{ts, secrets, dependencies}` through a temp file and one
   `os.replace`, the way `file_bugs._write_ledger` does (`:267`) because eight rule checks run in
   parallel; otherwise the cache with its age in hours and the reason the live read failed. No
   cache and no live read is `age_h = None` with the reason.
5. `violations(product, host=None, now=None)`: §2.6's three line shapes byte for byte — one per
   open secret alert with `sev=S1 sig=secret-<slug>-<n>`, one per open dependency alert with
   `sev=S2 sig=dep-<slug>-<n>`, and one `sev=S2 sig=feed-stale` naming the reason when the feeds
   could not be read and the last good read is older than `security_alerts()['max_age_h']`. A read
   that failed with a *fresh* cache prints nothing: the alerts it knows about are the cache's, and
   they are already filed.
6. `FeedTests`/`ViolationTests` per §3's T5: a fake host with one open secret and two open
   dependency alerts gives three lines with the right `sev=`/`sig=`; no line carries a secret
   value, and the fake asserts the `--jq` selection never names the `secret` field; a host that
   raises with a 2 h-old cache gives no line, with a 30 h-old cache one `feed-stale` line naming
   the reason; an empty feed is zero lines.
7. `CacheTests`: the cache is written through a temp file and exactly one `replace`, asserted on a
   fake; a malformed cache file reads as no cache and not as an exception; the cache never holds a
   field the `--jq` did not select.
