The spec's `## The design` §3 in full, and nothing else. After this lands, `T-14651` — an id from a
session's reserved five-digit block that was never minted — reaches T-0071's card instead of
vanishing at `asf/record/plan_order.py:226`, the wave holds the Task rather than launching it into
a gap, and one `RESHAPE → PLAN` row per Feature carries a sentence that tells the plan session
exactly which line to re-cut. No coder, no `empty branch`, no operator in the loop.

Two things are load-bearing. **`known` keeps its one remaining job** — deciding whether the
plan's-own-id mapping is even *tried* — so both callers (`backfill` with `known=set(metas)`,
`overlay` with `known=set(items)`, P2) pass it unchanged and an id the record **does** hold is
never remapped. And **the reshape row must survive `hold_unlanded`**: without the `keeps`
exemption, the pass that turns `after:`-blocked rows into `WAITS ON` rewrites the row that fixes
the plan into a restatement of the symptom, and the Feature waits for ever on an id nobody will
ever mint (P15).

Read **PD9 before writing `UNMINTED_AFTER_RECUT`'s sentence** — nothing downstream reads it as a
mode, so the sentence is the entire message and every clause in the spec's wording is load-bearing.
**PD11 before restructuring `derived_after`'s loop**, and **PD12 before writing
`test_an_unminted_id_is_kept_not_dropped`**.

  above `derived_after`; and `derived_after`'s loop rewritten as §3 writes it, including the
  `(cid, parent)` drop lifted out of the `elif` (PD11). The docstring is replaced with §3's, which
  states the keep and names the defect. `task_order`, `_card_ids`, `_explicit`, `task_ids`,

  (`:1299-1307`) replaced by §3's version, which splits off the unminted case and appends one
