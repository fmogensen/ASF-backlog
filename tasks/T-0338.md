§2.7 whole. What this Task promises is a byte-identical prefix per brief kind and a measurement,
not a hit rate: whether a prefix is cached is the runtime's and the provider's business.

**Files**

- `asf/briefs/build.py`:
  - `ROW_MARKER = '<!-- row -->'`. `load_template` (`:175`) splits on it and raises `BriefError`
    when the marker is missing **or** the stable half holds a `{placeholder}` — the check runs at
    load, so a template reordered wrongly fails the first brief of that kind rather than shipping
    a literal `{branch}` to a session.
  - `TAIL` (`:97`) splits into `TAIL_STABLE` — the heartbeat and standing-rules prose, verified
    here to hold no placeholder — and `TAIL_ROW`, the branch paragraph and the REPORT block,
    which need `{branch}`, `{main}`, `{item_id}` and `{kind}`.
  - `stable_text(kind)` — template head + `TAIL_STABLE`, a pure function of the kind,
    `functools.lru_cache`d.
  - `build()` (`:499`) composes §2.7's five parts in §2.7's order. The consequence is that the
    brief's first line stops being `Backlog item: <id> — <title>`; the docstring at `:12` that
    calls it "the line every session registry reads" is corrected in the same edit, because no
    reader in the tree reads it (PD19).
- `asf/briefs/templates/*.md` — all eighteen gain `<!-- row -->` exactly once, and each one's
  placeholder-bearing prose moves below it. This is the Task's real work: a careful content move
  per template, with the reading order preserved inside each half.
- `asf/views/tokens.py` — a **cache read** column (`tokens_cache_read`, the same median-per-kind
  treatment `in_tokens` gets) and the footer line
  `cache-read: <n>/<m> sessions (<pct> %)`. `_cell` and `render` grow one entry each; the
  `--json` rows carry the same numbers.
- `asf/metrics/metrics.py` — `scorecard_rows` gains a `prompt cache` row: the share of the week's
  sessions carrying a non-null `tokens_cache_read`.
- `tests/test_briefs.py` — `StablePrefixTests`, and `GoldenBriefTest` **renamed** to
  `GoldenBriefTests` (PD17 — §3's fence names the plural and `unittest` exits non-zero on the
  singular).
- `tests/fixtures/briefs/golden/*.md` — all eighteen regenerated (`ASF_UPDATE_GOLDEN=1`), then
  **read** before committing: a golden is a review artefact, not a blob, and the reordered brief
  is the thing this Task is judged on.
- `tests/test_views.py` — `TokensCacheColumnTests`. `tests/test_scorecard.py` —
  `PromptCacheRowTests`. `tests/test_sample_product.py` — `:197`'s `body.startswith` updated to
  the new first line.

**Steps**

1. `ROW_MARKER`, `load_template`'s split and its two refusals, `TAIL_STABLE` / `TAIL_ROW`,
   `stable_text`, and `build()`'s new order.
2. The eighteen templates, one at a time, running
   `python3 -m unittest tests.test_briefs.StablePrefixTests` after each: the marker present once,
   the stable half holding no `{`, the brief still reading in an order a session can follow.
3. `StablePrefixTests` (PD18): two briefs of each kind for two different items;
   `a.startswith(stable_text(kind))` and `b.startswith(...)`; `'{' not in stable_text(kind)`;
   `stable_text(kind)` unchanged when the two briefs are built in the other order (the
   `lru_cache` is not carrying an item's data); and `stable_text` non-empty for every one of the
   eighteen kinds. **Not** `commonprefix((a, b)) == stable_text(kind)`: the part following the
   stable half begins with the same bytes for two items of one kind, so the common prefix is
   always longer, and the equality the spec writes can never hold.
4. Regenerate and read the eighteen goldens; rename `GoldenBriefTest`; update
   `tests/test_sample_product.py:197`.
