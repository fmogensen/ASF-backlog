The spec's design §5 and `loops.replay`'s new parameter from the caller's side. A pin is how this
rule is defended against the next cap that resets it, so the numbers are stated rather than
described. Nothing in `asf/` is touched: this Task is one new fixture and one new test class.

**Files**

- `tests/fixtures/replay/loop_total.jsonl` — **new file.** An anonymised slice of the loop this card
  measured, in the existing fixture's own shape (**PD5**): the eight keys
  `item`, `kind`, `started`, `launch_head`, `card_digest`, `cause`, `report_key`, `ended`, with
  `unparked` added on the one line that resets. Job one is `c-0042`, 12 launches, a different
  `report_key` on each and a `card_digest` that changes twice, spread over eight days so no six fall
  inside one 24 h window. Job two is `d-0042`, 9 launches, with the `unparked` line after the sixth.
  No worker account name, no host name and no filesystem path — the ids are `c-0042`/`d-0042` as the
  existing fixture's are `a-0042`/`b-0042`.
- `tests/test_loops.py` — `TotalReplayPinTests` added beside `ReplayPinTests` (`:116`), with a second
  fixture path constant beside `REPLAY_SESSIONS` (`:13`) and `_load_sessions(path)` (`:16`) reused as
  it stands — it already takes a path.

**Steps**

1. Write the fixture. Pick the timestamps so the daily cap provably refuses nothing: 12 launches
   over eight days with gaps wide enough that no 24 h window holds six. Give every line of `c-0042` a
   distinct `report_key` so the same-report rule refuses none of them either — the fixture's purpose
   is a loop **both** live rules miss and the ceiling catches.
2. Write `TotalReplayPinTests`: the fixture's shape (12 + 9 lines, the two item ids); neither live
   rule refusing any launch of `c-0042` (`replay(sessions, total_cap=None)` is `[]` for that job);
   the total cap at its default refusing its **last six**, each named `loops.TOTAL_RULE`; the second
   job's `unparked` line resetting the count, so the launches after it are judged from zero; a cap of
   4 refusing strictly more than a cap of 6; the cap off refusing nothing; and the anonymity
   assertion — no line of the file matches a worker account name, a host name or a path separator.
3. Leave `ReplayPinTests` exactly as Task 2 left it. Its four unedited numbers are S-99859's first
   acceptance line and they are measured to hold at the default: with the rule at 6, the existing
   fixture still gives 11 same-report refusals, 3 daily-cap refusals and 14 in all — confirmed in
   this session, where those four cases passed with §1 applied and only the fifth (all rules off)
   moved. The fifth is Task 2's step 7, not this Task's.
