The spec's fourth, fifth and sixth **In** bullets and `## The design` §`asf/doctor.py` whole, with
PD5's correction to `_log_lines`. One bounded tail reader that `_log_tail` is rewritten over, one
backwards scan for a dangling start line, one field between `last-run=` and `log:`, and one
`OK → YELLOW` transition. Every other field, level and ordering of every doctor row is untouched, and
a log with no per-step line in its tail produces a row byte-for-byte identical to today's.

**Files**

- `asf/doctor.py` — `import re`, `from asf.workers import lifecycle`; `LOG_TAIL_BYTES`,
  `_STEP_START_RE`, `_STEP_END_RE`; `_log_lines`; `_log_tail` rewritten; `_since`; `current_step`;
  `step_detail`; the two additions in `scheduler_rows`' job loop
- `tests/test_doctor.py` — `SchedulerSectionFixture` extracted from `TestSchedulerSection` (PD10);

**Steps**

1. Two imports (P12, re-verified in PD12): `re` in the stdlib block at `:52-55`, and
   `from asf.workers import lifecycle` beside `from asf.workers import pool` at `:58`. `pool` already
   imports `lifecycle`, so no cycle is opened and nothing new is pulled into the doctor's import
   graph.
2. `LOG_TAIL_BYTES = 1024 * 1024`, `_STEP_START_RE` and `_STEP_END_RE`, all three with the spec's
   comments byte for byte, beside `NEVER_EXITED_INTERVALS` (`:657`).
   `_STEP_END_RE = r'^\[step:([a-z-]+)\] \d+\.\ds'` matches the pre-F-0142 line as well as the new
   one — that is deliberate and is what makes a log written by an older install read as "no step
   running" rather than as a running one — and `[step:<name>] FAILED …` matches neither pattern,
   verified against `asf/tick/tick.py:601`. `[a-z-]+` covers every name in `steps.STEPS` (PD12).
3. `_log_lines(path, limit=LOG_TAIL_BYTES)` with the spec's docstring byte for byte, and **PD5's
   exact semantics**: `[]` for a falsy path, a path that does not exist, or an `OSError`; else
   `os.path.getsize`, `open(path, 'rb')`, `seek(max(0, size - limit))`, read, decode `utf-8` with
   `errors='replace'`, split on `'\n'`; if `size > limit` **and** the window holds at least one
   `'\n'`, drop element 0 — the fragment the seek cut in half; then return the `rstrip()`ped
   non-empty lines, oldest first. The conditional drop is the one thing D15's named behaviour change
   requires and the unconditional drop would break (PD5).
4. `_log_tail(path)` is rewritten over it, with the spec's docstring and body: `None` when there is no
   log (`os.path.exists(path or '')` is False — `os.path.exists('')` is False, so a `None` path still
   answers `None`, matching today's `if not path or not os.path.exists(path)`), else the last line or
   `''`. Today's `OSError → None` becomes `OSError → ''` here, which the one caller cannot tell apart:
   both are falsy and both render `log: (empty)` (`:763`). The whole-file read at `:664` is gone —
   that is D7's cost being paid back, not spent.
5. `_since(at, now=None)`: `datetime.datetime.strptime(at, '%Y-%m-%dT%H:%M:%SZ')` read as UTC, then
   `max(0.0, (now or time.time()) - its epoch seconds)`; `None` on `ValueError`/`TypeError`. The
   format is `tick._stamp`'s, verified at `asf/tick/tick.py:152-153`; the doctor parses it rather than
   importing it, because the string is the record and `asf/doctor.py` imports nothing from
   `asf.tick.tick` today. `import datetime` is added if the module has none.
6. `current_step(path, alive=None, now=None)` with the spec's docstring and body byte for byte (D14):
   one backwards scan of `_log_lines(path)`, `None` the moment it meets `_STEP_END_RE`, and on
   `_STEP_START_RE` the dict `{step, owner, pid, alive, seconds}` with
   `alive=(alive or lifecycle.pid_alive)(int(pid))` and `seconds=_since(at, now)`; `None` when the
   scan runs out. The `alive` and `now` arguments are injection points for the tests; `scheduler_rows`
