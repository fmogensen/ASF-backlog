The spec's §2.6 in full — its three changes, all in `ci_pool` — and nothing else. After this lands,
the card's third acceptance is a thing the doctor asserts on every tick rather than a thing somebody
remembers: a product file cannot declare a role, a class or a reserve label in ASF's own namespace, a
reservation's label is generated rather than typed, and a self-hosted `runs-on` asking for a label
that is neither a tier ASF places nor a reservation is a required red row naming the workflow, the
job and the label.

D20 is the argument and it is short: *"an acceptance nothing checks is a sentence."* A refusal at
product load and a red doctor row are the two places this codebase already enforces config rules
(P1, P12).

**Read PD9 before making `label` optional.** `load_reserve` indexes `r['label']`
(`ci_pool.py:304`), so the moment `reserve_problems` stops requiring the key this raises `KeyError`
on the first reserve that omits it — and `reserve_problems`' duplicate-label check only runs for an
explicit label, so two reserves that both default would collide silently. **Read PD18** for why
`ci.labels` is left alone: it names host defaults, not routing, and it is the one label block that
must survive. **PD22** for why this Task shares a file with Task 3 and is a chain.

Two things are load-bearing. **The default strips a leading `asf-` from `of`** (§2.6): a reserve of
`asf-fast` would otherwise get `asf-pr-asf-fast`, so the rule is
`ASF_PREFIX + 'pr-' + of.removeprefix(ASF_PREFIX)` and `of: asf-fast` → `asf-pr-fast`. **A
hand-written label outside the namespace is still accepted, unchanged** (§3.5): this card refuses
ASF's own prefix, not every declared label — a product that names its runners keeps naming them
(O9), and every existing reserve keeps working.

**Files**

- `asf/ci_pool.py` — four edits. `_pool_problems` refuses a declared `role` or `class` beginning
  `ASF_PREFIX`, with §2.6's message: `ci.pool[0].role: 'asf-fast' is ASF's own namespace — a tier is
  placed, never declared`. `RESERVE_REQUIRED` becomes `('of', 'keep_free')`, and `reserve_problems`
  refuses a hand-written `label` in the namespace **other than** the default it would generate,
  moving its duplicate-label check to the **resolved** label (PD9). A new
  `default_reserve_label(of)` → `ASF_PREFIX + 'pr-' + of.removeprefix(ASF_PREFIX)`, used by both
  `reserve_problems` and `load_reserve`, so the rule has one home and Task 9 can document it.
  `load_reserve`'s `label=_norm(r['label'])` becomes `label=_norm(r.get('label') or
  default_reserve_label(r.get('of') or ''))` (PD9). `drift` gains one required row per offending
  label **on a discovered pool** — a self-hosted `runs-on` asking for a non-default label that is
  neither a tier nor a reserve label — with §2.6's text: `runs-on: tests.yml:gate asks for 'heavy' —
  no tier ASF places (asf-fast, asf-bulk) and no reservation; ASF cannot route it`. On a **declared**
  pool `drift` produces exactly today's `provider-like label in runs-on` row and nothing new; the new
  row is behind `pool_mode(product) == DISCOVER`, which means `drift` needs the product, so pass it
  as a keyword defaulting to `None` and leave every existing call site working unchanged.
- `tests/test_ci_pool.py` — two new classes. `Namespace`: `pool_problems` refuses `role: asf-fast`
  and `class: asf-x` in a declared entry, each naming the namespace, and a product file carrying one
  fails `env.validate_product_text` (P1). `RunsOnRouting`: `drift` over a discovered pool and a
  `runs-on: [self-hosted, heavy]` produces the required red row naming the workflow, the job and the
  label; over `runs-on: [self-hosted, asf-fast]` it produces none; over a reserve label it produces
  none; and over a **declared** pool it produces exactly today's `provider-like label in runs-on` row
  (O9). `doctor_rows` marks the new row **required**.
