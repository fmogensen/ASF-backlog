The spec's design §6, §5's registration triple, §1 and §2's install rewrite — in that order inside
the Task, because each is green alone and the next one needs it (**PD1**, **PD4**, **PD5**). This is
the card's cause: `bootout` returns when launchd has *signalled* the job, the `bootstrap` on the
next line is refused while the service is still in the domain, and the clock the command was run to
install is gone (`asf/scheduler.py:926-927`). The condition the bootstrap was missing is one the
product's own `status` reader already answers.

The retry is **not** here. Task 1 leaves `_launchd_install`'s bootstrap block exactly as it is
today — `rc == 0` → `bootstrapped <label>`, else `bootstrap <label> failed (<why>)` — and Task 2
extracts it into `_bootstrap_with_one_retry`. §2's sketch shows the finished shape; the coder
should write the wait around today's bootstrap and let Task 2 replace the last two lines.

**Files**

- `tests/test_scheduler.py` — §6's four changes to `_STUB` (`:27-65`), plus the three helpers and
  `InstallRaceTest`, and the one amended pin.
  - `bootstrap` (`:49-62`): where no `print-template.txt` exists, write
    `print-$label.txt` with `<label> = {` / a tab and `state = waiting` / `}`. The
    `print-template.txt` branch (`:54-57`) **keeps precedence** so `tests/test_cutover.py:127`
    and `:206` still see the body they wrote, and the `on-bootstrap.sh` hook at `:58-60` must
    survive the edit — `tests/test_cutover.py:205` is its only caller and §6's sketch elides it
    behind a `...`. `state = waiting` and not `running` is deliberate (D-0012): a bootstrapped job is
    loaded and idle, which is what keeps D-0006's running-now line out of every install that
    interrupted nothing.
  - `bootstrap`: a `refuse-$label` file makes **one** attempt exit 37 with launchd's own
    `Bootstrap failed: 37: Operation already in progress` on stderr, then removes itself. Set
    `label="$(basename "$3" .plist)"` **before** this branch — §6's sketch hides that line behind
    a `...` and the refusal path reads `$label`.
  - `bootout` (`:43-48`): of a label `print` answers for, remove `print-$label.txt` and exit 0; a
    `linger-$label` file holding a count keeps `print` answering for that many more calls first
    (the service still being reaped — the race itself). Nothing held it → `exit 3`, the ordinary
    first install, unchanged.
  - helpers beside `fake_print` (`:109-111`): `fake_linger(statedir, label, n)`,
    `fake_refuse(statedir, label)` and, if the linger needs it, a reader — so no test writes stub
    plumbing by hand.
  - `test_install_writes_the_plist_and_boots_out_before_bootstrap` (`:467-479`): the argv pin at
    `:473-478` becomes **three** entries — `argv[0]` the `print`, `argv[1]` the `bootout`,
    `argv[2]` the `bootstrap`. Measured red exactly here and nowhere else (**PD5**). No assertion
