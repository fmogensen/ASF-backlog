## Description
stories: S-30551, S-30552

after: Task 1

§2.2, §2.3 and §2.12's doctor half — the two wiring changes without which an installed rule hook
binds the operator's console and no worker session at all, plus the row that makes an unresolved
one visible instead of silent. All three tests in this Task use fixture rules directories, so
nothing here needs the real `rules/` cards.

**Files**

- `asf/hooks.py` — three changes and one addition:
  1. `install`: the per-account write becomes
     `_write_merged(account_settings_path(account), [('PreToolUse', 'approvals')] + rule_hooks,
     asf_path, None)` — product-less, each hook resolving its product from `ASF_PRODUCT` at run
     time (D1). The existing `_write_merged(repo_settings, rule_hooks, asf_path, product.name)`
     stays exactly as it is (D2). The account loop already runs before the `repo_dir` refusal
     (`:317-319` before `:328-330`), so a product with no `repo_dir` still leaves every worker
     session hooked and the refusal is now about the repo copy only — the "every hook that can be
     written is written before anything is refused" rule the docstring already states. The summary
     gains the count: `f'hooks: {written} rule hooks in {repo_settings}; approvals + '
     f'{len(rule_hooks)} rule hooks in {len(accounts)} worker accounts; {git_detail}'`.
  2. `check_script` gains a fourth root after the record's and the cwd's: `core =
     os.path.join(rules.core_rules_dir(), f'{name}.sh')`, returned when it is a file, `None`
     otherwise (D3, §2.3's body). Order does not change — a product's own record
     `tools/checks/<name>.sh` still wins, the same override `resolve_script` gives the check half
     — and the `asf.rules.rules` import is local to the function. The docstring says all four.
  3. `cmd_hook` runs the resolved script with an environment, not the bare inherited one:
     `env = dict(os.environ, ASF_PYTHON=sys.executable)` and `PYTHONPATH` prepended from
     `hermetic.package_parent()`, passed to `subprocess.run(['bash', script], env=env)`. Stdin is
     still inherited by the child and the script's rc is still the rc the runtime reads (PD8).
  4. `rule_hooks_missing(accounts, declared, repo_dir=None)` → `[(account, [name…])]`, beside
     `approvals_missing` and in its shape: the names in `declared` whose command is in neither the
     account's settings nor, when `repo_dir` is set, the repo's; an unreadable settings file counts
     as missing, exactly as `approvals_missing` treats it. It refactors `approvals_missing`'s inner
     `has(path)` into a shared `_installed_names(path, event)` rather than copying it.
- `asf/doctor.py` — the `rule-hooks` row beside `approvals-hook`: `check_rule_hooks(cfg, product)`
  → `(ok, detail)`, red when `hooks.rule_hooks_missing(accounts, [n for _e, n in
  hooks.declared_hooks()], product.repo_dir)` is non-empty (naming each account and the hooks it
  lacks) **or** when a declared hook's `hooks.check_script(name, product.name)` is `None`
  (naming each unresolved hook — the silent-exit-0 state §2.3 exists to prevent). One fix line:
  `asf hooks install --product <p>`. The row is appended after `approvals-hook` at `:835-836`,
  and the module docstring gains a paragraph naming it beside the ninth row without renumbering
  the ones after it. The account settings path is never built here — that is
  `hooks.account_settings_path`, in the one file `tools/check_conventions.sh` exempts for exactly
  this reason (PD15).
- `tests/test_rule_hooks.py` — `InstallTargetTests` and `ResolutionTests`.
- `tests/test_install.py` — the install-target change in `HookInstallTests`.
- `tests/test_doctor.py` — `RuleHooksRowTests`.
