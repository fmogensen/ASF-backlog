## Description
stories: S-34255

after: none

The spec's `## The design` §`asf/env.py` — three things the schema owes — and the fifth and sixth
**In** bullets. Nothing new reads anything here: `x-unmapped:` is declared precisely so that nothing
reads it, and the two shapes turn a block that used to load and be ignored into a finding at load
with its line. This Task must land first, because until `x-unmapped:` is a field, a parked key writes
a file that refuses to load (PD12).

**Files**

- `asf/env.py` — `_MAP_OR_NONE`; `'ci'` and `'deploy_sha'` in `PRODUCT_FIELDS` (`:514-522`) move off
  `None` onto it; one branch in `_shape_ok` (`:554-561`); the `'x-unmapped': _MAP` row with the
  comment naming F-0129
- `docs/products.example.yaml` — the commented `x-unmapped:` block
- `tests/test_env.py` — `ProductFieldShapes` and `ProductFileTests`

**Steps**

1. `_MAP_OR_NONE = 'a map (or the word none)'`, with the spec's comment: a list- or scalar-shaped
   `ci:` used to load and then be ignored by every reader, so the product ran with no gate, no
   provider and no deploy, and nothing said so (F-0129, D13).
2. `PRODUCT_FIELDS['ci'] = _MAP_OR_NONE` and `PRODUCT_FIELDS['deploy_sha'] = _MAP_OR_NONE`. **Not**
   `_MAP` for `deploy_sha` — PD2: `sample/product.yaml:39` and `tests/e2e/product/product.yaml:37`
   both write `deploy_sha: none`, and `_MAP` refuses both.
3. In `_shape_ok`, after the `value is None or shape is None` guard and before the `_MAP` branch:
   `if shape == _MAP_OR_NONE: return isinstance(value, dict) or (isinstance(value, str) and value.strip() == 'none')`.
4. `PRODUCT_FIELDS['x-unmapped'] = _MAP`, with the comment: what `asf config migrate` parks — a key
   with no home in the schema, kept rather than dropped (F-0129); its contents are not checked and
   nothing reads them. It nests under `NESTED_FIELDS` nowhere, which is what leaves its contents
   unchecked (P2).
5. `docs/products.example.yaml`: the spec's commented block, byte for byte — a `# x-unmapped:` /
   `#   secrets_store: vault` pair behind the three explanatory comment lines. Commented, so
   `TestProductSchema.test_the_documented_example_validates` (`:283-285`) is unaffected either way.
6. `tests/test_env.ProductFieldShapes`: `ci: {}` and `ci: none` and `deploy_sha: {}` and
   `deploy_sha: none` all validate `[]`; `ci:\n  - a` and `deploy_sha:\n  - a` and `ci: 3` each give
   one problem naming the key, its line and `a map (or the word none)`; `x-unmapped:` with a scalar,
   a list and a nested map under it validates `[]`, and `x-unmapped: 3` gives one problem.
7. `tests/test_env.ProductFileTests`: `docs/products.example.yaml`, `sample/product.yaml` and
   `tests/e2e/product/product.yaml` each `validate_product_text` to `[]` — the three files this
   repo ships, pinned together, so PD2's defect cannot come back by another route.
