§2.5: the immutable timestamp the incident clock needs, written once and never moved, seeded for
the existing record by one migration. Today `asf/feeder/render.py:45` runs the S1 clock off
`stage_since or created` while `asf/record/ingest.py`'s `tracked_changed` (`:429`) moves
`stage_since` on every state change — so launching a fix for an S1 Bug resets the clock that
exists to catch a launch that failed, which F-0071 D7 already ruled must not happen. `render.py`'s
own `s1_hours(product)`/`S1_HOURS` (landed separately, `:16-29`, reading `product.stage_limits`)
is the *limit* the clock compares against and is untouched by this Task — only the *timestamp*
`incidents()` reads at `:45` changes.

**Files**

- `asf/record/ingest.py` — `MACHINE_KEY_ORDER` (`:32`) gains `'opened'` after `'stage_since'`;
  `_ingest_fields` (`:403`) gains `typed=None`, writing it once (PD8)
- `asf/schema.py` — `_migrate_to_2`, `MIGRATIONS[2]`, `SCHEMA_VERSION = 2`
- `asf/feeder/render.py` — `incidents`'s one line (`:45`)
- `sample/backlog/**` — the sample's committed record migrated to schema 2 (PD9)
- `tests/test_ingest.py` — `OpenedTests`
- `tests/test_schema_version.py` — the `MIGRATIONS[2]` cases
- `tests/test_feeder.py` — `IncidentClockTests`
