**Steps**

1. `asf/connectors/__init__.py`: `KINDS` gains `'identity'` last, `DEFAULTS` gains
   `'identity': 'none'`, `BUILTIN` gains `{'none': 'asf.connectors.identity:none', 'fake':
   'asf.connectors.fakes:FakeIdentity'}`, and the module docstring's list of kinds names it. The
   entry-point group follows from `ENTRY_POINT_GROUP` with no new line.
2. `asf/connectors/protocols.py`: a `runtime_checkable` `Identity` Protocol with §2.7's docstring
   and its two methods — `at_launch(job) -> str` (the identity this launch used, `''` when there
   is one) and `status(identity, job) -> tuple` (`(alive, why)` read from the runtime, `(None, why)`
   when it cannot be read — never a stall).
3. Create `asf/connectors/identity.py` with the `none` factory, the no-op: an empty identity and
   an unreadable status, so one login behaves exactly as today. `asf/connectors/fakes.py` gains
   `FakeIdentity` for the tests.
4. `asf/kernel/ports.py`: `_spawn` records `at_launch`'s string on the session's ledger row, and
   `sessions()` carries it back on `Session.identity` unchanged — the kernel never parses it,
   never splits it and never compares it to a name.
5. A configured adapter whose `status` reports a session not running is a `FROZEN` **confirmation**
   on a session the beat already judged frozen, never a stall of its own; `None` changes no
   verdict. An `identity` name that resolves to no implementation is a `ConnectorError`, never a
   silent fall back to `none`, exactly as every other kind behaves.
6. Create `tests/test_identity_connector.py` with one case per acceptance line, including the scan
   that asserts no module under `asf/kernel/` names a runtime, a login, a credential directory or
   a tool, over the connector registry's own names (`K9`), and the case that the forbidden-name
   check stays clean with an adapter naming its tool inside `asf/connectors/`.
