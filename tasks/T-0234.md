**Steps**

1. `rec()` (`asf/evidence/evidence.py:1014`) gains `"mergeable": None` and `"conflicting": []`.
2. In the `for iid in ids:` loop (`:1044`), inside the `state == "OPEN"` branch: when
   `p.get("mergeable")` is `CONFLICTING` or `MERGEABLE` — never `UNKNOWN`, never a missing field
   (D12) — set `rec(iid)["mergeable"]`, with `CONFLICTING` winning over `MERGEABLE` whichever PR is
   seen first, and append the PR's number to `conflicting` when it is `CONFLICTING`. Module-level
   `CONFLICTING`/`MERGEABLE` constants, read from `asf/feeder/rows.py`'s own vocabulary so the two
   modules cannot drift.
3. `id_state` (`:1157`): the `open_prs` branch renders `f"PR #{n} OPEN (CONFLICTING)"` for a number
   in `iev['conflicting']` and `f"PR #{n} OPEN"` otherwise. Its return shape, its vocabulary and
   every other evidence line stay byte-identical (§1.3), and the fallback clause at
   `asf/feeder/rows.py:337` keeps matching for a record ingest has not yet rewritten.
4. `MACHINE_KEY_ORDER`: `'mergeable'` immediately after `'evidence'` — a key ingest derives that is
   not listed there is dropped on the next write (§1.1).
5. `_ingest_fields` gains `mergeable=None` (PD8) and §2.4's two lines: set it when truthy, `pop` it
   otherwise — a merged or closed PR has no mergeable state (§1.3), and `_ingest_fields`'s
   `new_cmp == old_cmp` check (`:337`) already makes an absent key cost no write. The caller
   (`:822`) passes `(ev.get('ids') or {}).get(iid, {}).get('mergeable')`.
6. `tests/test_evidence.py:MergeableTests`, per §3.4: `id_evidence` over a PR list — an `OPEN` PR
   with `mergeable: CONFLICTING` naming `T-0007` gives that id `mergeable == 'CONFLICTING'` and the
   line `PR #41 OPEN (CONFLICTING)`; `MERGEABLE` gives `'MERGEABLE'` and no extra line; `UNKNOWN`, a
   missing field, and a `MERGED` or `CLOSED` PR each give `None`; two open PRs on one id, one
   `CONFLICTING`, gives `CONFLICTING` and the suffix on that number alone.
7. `tests/test_ingest.py:MergeableTests`, per §3.4: the key lands in the machine block in
   `MACHINE_KEY_ORDER` position, and is popped when the PR later merges — with the `## History` line
   the existing `_phrase` path writes (§4).
8. `tests/test_feeder.py:ConflictRowTests`, per §3.4: an `Active` Task carrying
   `mergeable: CONFLICTING` and no session raises exactly one `CONFLICT → REBASE` row with
   `brief_kind='rebase'`; the same Task with `MERGEABLE` raises none — both asserted with the
   evidence-line fallback removed from the item, so the typed key alone is what fires it.
