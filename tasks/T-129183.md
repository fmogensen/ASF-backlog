The operator's ruling of 2026-10-10, which the spec carries as **D-0010** and as the last bullet of its
`## Records`. It is in this plan because that ruling put it here, and it carries **no Story**
deliberately: the spec is explicit that no Story's footprint reaches that product (**PD12**).

**Its diff is on the reporting product's repository, not this one.** The two globs on the `writes:`
line are paths in that product's tree. Whoever launches this Task launches it against that product;
the `.gitignore` it names is that product's, and its intersection with Task 1's `.gitignore` costs
nothing, because `after: Task 5` already puts this Task behind every other one in the plan
(**PD12**).

The ordering is the substance, not bookkeeping. Re-confirmed in the ruling on 2026-10-10: the path
is still tracked on that product's `origin/main` and still being rewritten by session commits — the
newest `9381a60ee` at 2026-10-09 09:34Z, six before it a review session's own end-marker commits,
the oldest `ef2566bf4`. A removal landed before Tasks 1–3 have stopped the committers is simply
re-added by the next auto-commit, which is why this Task waits for them and why nothing was removed
when the spec was written.

**Files**

- `NOTES.asf.md` — untracked, by `git rm --cached NOTES.asf.md`. The file is **not deleted from any
  worktree**: a continuation still reads it, and the whole point of the card is that it stays where
  it is and stops being staged.
- `.gitignore` — `NOTES.asf.md` added, so a human running `git add -A` by hand in a checkout of that
  product does not put it back (the same entry D-0008 adds here, for the same reason). The
  `info/exclude` half is written by `scratch.exclude()` from Task 1 on every worktree the factory
  makes from then on.

**Steps**

1. Confirm the state first, from inside that product's own checkout, and keep the output:
   `git ls-tree origin/main --name-only -- NOTES.asf.md`, and
   `git log --oneline --reverse origin/main -- NOTES.asf.md | head -3`. If the path is already gone
   from that trunk, this Task is done and lands nothing — say so and stop.
2. Confirm Tasks 1–3 are on that product's trunk, not merely on this repo's. The removal is only
   durable once the committers that re-add it are the fixed ones; `asf doctor`'s new
   **tracked-scratch** row from Task 5 is the read that says so, and it should be red on that
   product before this Task and green after.
3. On a branch off that product's trunk: `git rm --cached NOTES.asf.md`, add the `.gitignore` line,
   commit signed off, push the branch, open an ordinary pull request. No history is rewritten, no
   trunk is pushed, and nothing is force-pushed.
4. Let the factory merge it on green, like any other pull request. The 173 refs that already carry
   the file are **not** rewritten: each branch meets the lane's existing conflict → `BACK` →
   mechanical correction path as it comes up, and `lifecycle._resolved_to_trunk` already accounts
   for an add/add a rebase resolved in the trunk's favour, so no lost-work alarm fires on it.
5. Re-run the doctor row as the check that it is done.
