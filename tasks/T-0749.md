## Description
stories: S-39154
writes: asf/backfill/prs.py, tests/test_backfill.py
after: Task 4

The spec's `asf/backfill/prs.py` bullet and `## The design` §6. Roughly 140 pre-ASF pull requests are
open on the first adopting product and nothing in the factory will ever land or close one. This is
the Task that gives each exactly one answer.

`disposition` is **pure over gathered facts**, so the whole table is testable with no git and no
host — the facts are gathered by Task 2's reader and the predicates that decide them already exist:
`already_on_trunk` and `review.same_code` for *the trunk already holds this* (D11, P10), `docs_only`
for report-only (D10, P11). A third implementation of either question would be a third answer.

**Backfill decides; the lane lands** (D7). P8 and P9 are a complete implementation of the adopt path
already — the archive pushes, the PR closes, the stale rules and the conflict handling that took
B-0057, B-0065 and B-0066 to get right. Nothing in this file merges, gates, pushes to the trunk or
launches a review session. Read **PD10** (`close_pr` takes a facts dict and does **not** honour
`dry_run`) and **PD12** (`stale_after` arrives as seconds on the gathered facts) before starting.

**Files**

- `asf/backfill/prs.py` — **new**: the five disposition constants, `OpenPr`, `disposition(pr)`, the
  three reason lines, and the two lane hand-offs
- `tests/test_backfill.py` — `OpenPrDisposition`

**Steps**

1. The five constants with the spec's `#:` comments byte for byte: `ON_TRUNK`, `ADOPT`,
   `REPORT_ONLY`, `CONFLICTING_STALE`, `RESIDUE`. The docstring above them says what the spec's says
   — *"The disposition of one open pre-ASF pull request. Total: every PR gets exactly one."*
2. `OpenPr`, a frozen dataclass of the gathered facts and nothing derived: the number, the head
   branch, the head's date, the paths it touched (and whether they could be **read**, which is not
   the same as empty), the card a matcher claimed for it and whether that card is open, `merges_clean`,
   `on_trunk` (the `already_on_trunk` / `same_code` answer, gathered), and `stale_after` **in
   seconds** (PD12). No `Conventions`, no `product`, no git in this module — which is also how it
   stays clear of P16's fence.
3. `disposition(pr)` with the spec's §6 docstring byte for byte, the five rules in the spec's order,
   first match wins, `RESIDUE` the total fallback. The order is load-bearing and is a test: a PR whose
   files are identical on the trunk is `on_trunk` **even when it also conflicts**, because the trunk
   already has the work and a conflict is then irrelevant.
4. `report_only` is `docs_only(paths, doc_dirs + reports_dir)` with the tuple built as **PD11**
   requires, and it is **never** returned for a PR whose paths could not be read — `docs_only` already
   refuses to judge those (`bool(paths) and all(...)`, `asf/evidence/evidence.py:1076-1077`), and the
   gathered `paths_read` flag is the second guard so an unread PR is `residue`, not a close. A PR
   closed in error is the one outcome this pass cannot undo.
5. `adopt` requires all three: a card claims it, that card is **open**, and `merges_clean`.
   `conflicting_stale` requires `merges_clean` false **and** the head older than `stale_after`
   seconds. A PR that conflicts with a *fresh* head is `residue` — not closed — because its session
   may still be rebasing it.
6. A lane pull request is **not in this table at all**: one whose head branch's
   `conventions.branch_kind` is a *current* kind rather than `'legacy'`, or one a run already holds.
   The lane owns those (P8, P9). Filter them in the gatherer, and test that a lane-prefixed PR is
   absent from the table rather than given `RESIDUE`.
7. The two closing dispositions are one `Lane.close_pr(f, why)` each, with `f` the minimal facts dict
   of **PD10** — `{'branch': …, 'item': …, 'pr': {'state': 'OPEN', 'number': n}}` — and `why` the
   spec's §6 reason line for that rule, byte for byte, with its evidence interpolated
