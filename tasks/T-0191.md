The spec's §2.8 and §2.9. One bash script, thin enough to read in one screen, and the tests that
say the existing filing path needs nothing. `asf/tick/file_bugs.py` is **not** in this Task's
footprint and is not edited: §2.9 is "nothing new", and the Task's job is to prove it.

**Files**

- `rules/controller-chores.sh` — **new**, and the directory with it (PD11). The script of §2.8:
  `set -uo pipefail`, `asf chores --json --days 1` into a heredoc'd `python3`, exit 0 clean, 1 with
  one violation line each on stdout, 2 when the check could not run. Executable (`chmod +x`). It
  names no path, no id and no product: the thresholds and the paths come from `asf` (T11).
- `tests/test_rules.py` — `ControllerChoresCheckTests`, built on `CoreRulesTests`' shape
  (`:389-400`): a fixture record carrying the rule card through `write_rule` with
  `check: tools/checks/controller-chores.sh`, `ASF_CORE_RULES_DIR` pointed at this repo's own
  `rules/`, and a stub `asf` on `PATH` printing the `--json` payload each case needs — the script
  shells out to `asf`, and a test that relied on the installed one would not be hermetic.
- `tests/test_file_bugs.py` — `RuleViolationSignatureTests`: `rule_violation_signatures` over the
  violating record gives one signature `R-<id>: rule violated`, one evidence line per command, and
  `places` equal to their number (`asf/tick/file_bugs.py:114-149`).
- `tests/test_chores.py` — `FilingTests`: `cmd_file_bugs` over that record files one S2 Bug under
  the default Epic, a second run the same day files nothing, and a run the next day bumps the same
  Bug rather than filing a second; the body quotes the commands and carries no secret.

   `None` `cap` — `window_cap` is Task 2's (PD17) — and that the `null` case prints its reason on
   stderr and exits 0 (PD16).
