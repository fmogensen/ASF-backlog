## Description

§2.5 — the one defect in this spec that changes a launch. `asf/feeder/rows.py:127`
`PLAN_ON_TRUNK = 'plan on origin/main'` is the trunk's name inside a string
`tools/check_conventions.sh`'s anchored pattern cannot see, and for a product whose `main:` is not
`main` the sentence never matches: the STARVED → SPEC row loses both its reason and its
`branch=carrier` override, so instead of landing the spec that already exists on its own branch
the feeder launches a spec session to write it again. The producer changes with the consumer (D8):
a reader-only fix would leave the record carrying a sentence naming a branch the product does not
have, for every other reader of `evidence` to read.

**Files**

- `asf/record/ingest.py` — the two `origin/main` literals (`:783`, `:788`) become the product's trunk
- `asf/feeder/rows.py` — `trunk_of(product)`, `plan_on_trunk(product)`; `PLAN_ON_TRUNK` kept as
  the module constant; `:703`'s comparison
- `tests/test_ingest.py` — `EvidenceVocabularyTests`
- `tests/test_feeder.py` — `TrunkNameTests`

**Steps**

1. `asf/feeder/rows.py`: `trunk_of(product)` is `_conventions(product).main` — the existing
   `_conventions` read (`:222`), which already answers `Conventions()` for `product=None`, so
   `conventions.DEFAULT_MAIN` is the fallback with no new code (PD11). `plan_on_trunk(product)`
   returns `f'plan on origin/{trunk_of(product)}'`, with §2.5's docstring.
2. `PLAN_ON_TRUNK = 'plan on origin/main'` (`:127`) **stays** as the module constant for a product
   that names no trunk, so the four fixtures that spell the sentence keep working and nothing that
   reads the constant breaks. `:703`'s `PLAN_ON_TRUNK in (f.get('evidence') or [])` becomes
   `plan_on_trunk(product) in (f.get('evidence') or [])` — `product` is in scope there.
3. `SPEC_ON_BRANCH_RE` (`:126`) is unchanged: its `(?!origin/)` excludes *any* remote-qualified
   ref, which is already trunk-agnostic. No regex is widened to accept any trunk name — that would
   also match `plan on origin/some-other-branch` and turn a plan on a feature branch into "on the
   trunk", the opposite of what the row means (D8).
4. `asf/record/ingest.py`: in `derive` (`:536`), `trunk = (product.conventions.main if product is
   not None else conventions.DEFAULT_MAIN)` — one local, PD11 — and `:783`/`:788`'s two literals
   become `f'spec on origin/{trunk}'` and `f'plan on origin/{trunk}'`. Nothing else on either
   branch of those two `if`s changes: the `spec_carrier` and `plan_branch` arms, the review
   suffixes and the tasks-Closed line are byte-identical.
5. No migration (§4): `MACHINE_KEY_ORDER` is untouched, `schema.SCHEMA_VERSION` does not move. A
   record written before this change carries `plan on origin/main` for a product whose trunk is
   `master`; the row simply keeps not firing for it, exactly as today, until the next ingest
   rewrites the line — which is one tick, through the existing `_ingest_fields` comparison and the
   `## History` line that path already writes. For every product in the tree, whose trunk *is*
   `main`, not one byte of the record changes.
6. `EvidenceVocabularyTests` per §3.7: a fixture product with `main: trunk` — ingest writes
   `spec on origin/trunk` and `plan on origin/trunk`; the same record under `main: main` writes
   the two sentences byte for byte as today; `derive` with `product=None` writes
   `origin/main` (PD11).
7. `TrunkNameTests` per §3.7: `rows.plan_on_trunk(product)` is `plan on origin/trunk` for that
   product and `plan on origin/main` for `product=None`; a Feature at `spec-review` whose spec
   sits on `spec/F-0001` and whose plan is on the trunk raises **exactly one** STARVED → SPEC row
   **with `branch='spec/F-0001'`** and the "land the existing spec from that branch, don't rewrite
   it" reason — where today that product gets a plain STARVED → SPEC on `spec/F-0001`'s minted
