The spec's §1 reader half, and nothing else — `DEFAULT_EXCLUDES`, `_globs`, `excludes()` and
`filtered()`. No caller exists when this lands, so the factory's behaviour is byte-identical. This
Task exists so that the two rules an operator will argue about — *the defaults are added, not
substituted* and *the defaults never create a filter where none was asked for* — are written once,
before two call sites start asking them.

**What changes for the machine when this lands.** Nothing observable. No count moves, no line
moves, no config key is read that was not read before: `excludes()` is called by nobody until Task
2 and `filtered()` by nobody until Task 2's `_set_behind`.

**Files**

- `asf/harvest/deploy.py` — `DEFAULT_EXCLUDES` as a module constant beside the other module
  constants; `_globs(v)` lifted out of today's `paths()` body; `paths()` rewritten to call it,
  behaviour unchanged; new `excludes(product, env)`; new `filtered(f)`. `pathspecs`, `_behind`,
  `_blank`, `_done`, `_set_behind` and every renderer are untouched.
- `tests/test_deploy.py` — `RelevanceFilter(unittest.TestCase)` added, beside `NamedTargets` which
  owns this code today. No existing class is touched.

**Steps**

1. `DEFAULT_EXCLUDES` is the card's seven globs, **in the card's order**, as a tuple:
   `('**/*.test.*', '**/*.spec.*', '**/e2e/**', '**/playwright.config.*', '**/vitest.config.*',
   '**/__tests__/**', '**/*.md')`. A tuple, not a list, so no caller can mutate the default set for
   every product in the process. Its `#:` docstring says what the spec's design says: paths a
   deploy never ships, added to an environment's own `exclude` list unless `exclude_defaults:
   false`, and engaged only where the environment already has a filter — never on its own. C3 fixes
   this list; it is not per-product config and no card has asked for `*.stories.*` or
   `cypress.config.*`.
2. `_globs(v)` is today's `paths()` body verbatim — a bare string becomes a one-element list, a
   list keeps its non-empty string members, anything else is `[]` — and `paths()` becomes
   `return _globs(env_cfg(product, env).get('paths'))`. This is a refactor with no behaviour
   change; the lenient coercion is what the validator's strictness is deliberately at odds with
   (C9), and neither half moves here.
3. `excludes(product, env)`, the spec's snippet with PD5's dedupe:
   - `own = _globs(cfg.get('exclude'))`.
   - **The C2 guard first**: `if not own and not paths(product, env): return []`. This is the line
     that stops the defaults from silently making prod `0 relevant` on a docs-only trunk commit for
     every product on the machine. Write the reason into the docstring, not only into the code — it
     is the decision a later reader is most likely to undo.
   - `if cfg.get('exclude_defaults') is False: return list(dict.fromkeys(own))`. Identity against
     `False`, never truthiness: `exclude_defaults: 0` is not `false`, and a missing key must not
     read as one.
   - otherwise `list(DEFAULT_EXCLUDES) + [g for g in dict.fromkeys(own) if g not in
     DEFAULT_EXCLUDES]` — defaults first, in their own order, the environment's own globs after
     them, each once (PD5).
4. `filtered(f)` is `bool(f.get('paths') or f.get('exclude'))` — **`.get`, not subscription**
   (PD2). Its docstring names it as the one predicate every line and every count asks, so the two
   can never disagree about whether an environment is filtered.
