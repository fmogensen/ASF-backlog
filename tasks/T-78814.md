recognises git's own two lines, `refusals.describes_the_ask`, and `cloud.sync`'s dead-reason step
widened by that predicate so a run whose record holds only a rewrite correction has its own log read
as well. After Task 1 this is only ever a run the trunk moved under mid-flight (C6) — the name was
what was missing, and it costs one regex, one `KINDS` entry and a read the lane already makes when
nothing answers.

**Read this Task from `docs/plans/f-0289.md`, not from this card.** The record cuts a Task card's
description at 4000 characters and this section is longer, so the card stops inside the Steps and
carries neither the **Gate** nor the **Acceptance** copied from the approved spec; the card's
`links.plan` is this file. Three decisions bind this Task and are on no card at all. **PD5 is the
one that must be read before Step 5 is written**: the spec's own fence for the dead-reason step
re-calls `classify(view, …)`, and `view` is unbound on the `claude-remote` path, so the fence as
fenced crashes `sync` on exactly the shape this card sighted — the Step below lands the corrected
form, which produces the same sentence on both runtimes. **PD6** names the one landed assertion that
flips (`tests/test_cloud.py:1396`, 0 log reads → 1, because `naming` is a rewrite kind). **PD7**
settles an acceptance bullet that contradicts itself read literally: the `refusals.KINDS` sweep is
off the ledger.
