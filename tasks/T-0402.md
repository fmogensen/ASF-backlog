## Description
stories: S-33750
writes: asf/cli.py, asf/init.py, asf/schema.py, asf/upgrade.py, asf/hooks.py, asf/console_perms.py, asf/approvals.py, asf/scheduler.py, asf/ci_pool.py, asf/redact.py, asf/metrics/import_sessions.py, asf/plugin_build.py, asf/feeder/render.py, asf/harvest/deploy.py, asf/workers/__init__.py, asf/workers/unpark.py, asf/workers/actions.py, asf/briefs/build.py, asf/tick/shadow_diff.py, asf/tick/tick.py, asf/tick/watch.py, tests/test_surface.py
after: Task 5

§4's first Record: *nothing in the repo describes a command anywhere else after this lands*. Once
`apply` runs, the 49 strings at the `add_parser` calls are dead text that still reads like the
truth — which is exactly how `TITLES` and `add_parser` drifted into `backlog`/`BOARD` in the first
place (D2). This Task empties them and puts a test on the emptiness.

It carries S-33750 with Task 1 because it is the second half of one Story: the table declares every
command only once nothing else does.

**Files**

- `asf/cli.py` — the 28 top-level `add_parser` calls in `build_parser`
- `asf/init.py`, `asf/schema.py`, `asf/upgrade.py`, `asf/hooks.py`, `asf/console_perms.py` — the six
  `register` functions `init.register_commands` calls (`init`, `schema-migrate`, `upgrade`, `hooks`,
  `hook`, `console-permissions`)
- `asf/approvals.py`, `asf/scheduler.py`, `asf/ci_pool.py`, `asf/redact.py`,
  `asf/metrics/import_sessions.py`, `asf/plugin_build.py`, `asf/feeder/render.py`,
  `asf/harvest/deploy.py`, `asf/workers/__init__.py`, `asf/workers/unpark.py`,
  `asf/workers/actions.py`, `asf/briefs/build.py`, `asf/tick/shadow_diff.py`, `asf/tick/tick.py`,
  `asf/tick/watch.py` — one top-level registration each (`approvals`, `scheduler`, `ci`, `redact`,
  `import-sessions`, `plugin`, `next`, `deploy`, `workers`, `unpark`, `cloud`, `brief`,
  `shadow-diff`, `tick`, `watch`)
- `tests/test_surface.py` — `CoverageTests` gains the sixth check

**Steps**

1. Every top-level `sub.add_parser(...)` keeps its `help=` keyword and takes `help=''` — **never**
   drops the keyword. PD4: argparse records a subcommand in `_choices_actions` only when
   `'help' in kwargs`, verified here on Python 3.14.7, so a dropped keyword deletes the command from
   `--help`, from `surface.apply` and from `plugin_build.command_help()` in one edit.
2. The 49 sites, all found by `git grep -n "add_parser(" asf/`: 28 in `asf/cli.py`, and one each in
   `asf/init.py`, `asf/schema.py`, `asf/upgrade.py`, `asf/console_perms.py`, `asf/approvals.py`,
   `asf/scheduler.py`, `asf/ci_pool.py`, `asf/redact.py`, `asf/metrics/import_sessions.py`,
   `asf/plugin_build.py`, `asf/feeder/render.py`, `asf/harvest/deploy.py`,
   `asf/workers/__init__.py`, `asf/workers/unpark.py`, `asf/workers/actions.py`,
   `asf/briefs/build.py`, `asf/tick/shadow_diff.py`, `asf/tick/tick.py`, `asf/tick/watch.py`, and
   two in `asf/hooks.py` (`hooks` and `hook`).
3. **Second-level subcommands keep their own `help=` strings** — `ci reconcile`, `ci queue`,
   `ci reserve`, `cloud install`, `cloud doctor`, `deploy record`, `plugin build`/`check`,
   `rules check`, the seven under `workers`, the three under `metrics`. §1.3 puts them out of scope,
   `apply` never sees them, and emptying them would blank a page with no table behind it.
4. Where a registration's `help=` string was the only sentence saying what the command is, and the
   module has no docstring saying it, move the sentence into the module or function docstring rather
   than deleting it. A description is being moved to `asf/surface.py`, not thrown away, and the
   module that implements a command should still say what it implements.
5. `tests/test_surface.py` gains the sixth check, in `CoverageTests`: build the parser with
   `surface.apply` patched to a no-op (`unittest.mock.patch.object`) and assert every top-level
   choice action's `help` is `''`. That is D2 made mechanical — from here, a description typed at an
   `add_parser` is a red test rather than a review note — and it is scoped
