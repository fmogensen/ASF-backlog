## Description
stories: S-76254
writes: asf/hooks.py, tests/test_pin_defects.py
after: none

The spec's `## The design` §1, as printed (PD7 measured every line of it green), with the fifth
parameter threaded through the two functions §1 names. This Task adds no reader and no row: the
recognisers are untouched because they already read the new body correctly (P11, re-measured).

**Files**

- `asf/hooks.py` — `_git_hook_body` (`:124`) gains a fourth parameter `pin_required` and renders
  §1's three extra lines plus the `asf_pinned` function; `stale_own_hook` (`:165`) and
  `_own_upgrade` (`:176`) each gain a fifth parameter `pin_required`, passed through;
  `ensure_git_hooks` (`:341`) computes `pin_required` once and passes it to all three (`:371`,
  `:383`); `plan`'s chain (`:478`) passes it too, so `plan` and `install` keep deciding
  identically.
- `tests/test_pin_defects.py` — a new class beside `CloudSafeHooksTest` (`:274`), reusing its
  fixture: a throwaway repo with a tracked `.githooks` as `core.hooksPath`, a fake `HOME`, a real
  `git commit` and a real `git push` to a local clone.

**Steps**

1. `_git_hook_body(name, asf_path, product_name, pin_required)`. Between the `GIT_HOOK_MARKER`
   comment and the first `exec` line, render exactly §1's lines: the `# the asf a hook runs must
   be the dispatcher while <p> is pinned (F-0283)` comment, `pin_marker=` with
   `shlex.quote(dispatch.MARKER)` when `pin_required` and `''` when not (C5), `warned=`, and the
   `asf_pinned()` function. Then the two candidate lines become
   `if asf_pinned "<asf_path>"; then exec "<asf_path>" redact --<name> --product <p>; fi` and the
   same for `$HOME/.local/bin/asf`. The import is local (`from asf import dispatch`), as every
   other `dispatch` use in this module already is.
2. The refusal line's wording becomes §1's: `no asf that is <p>'s build and no
   {CHECKS_DIR}/redact.sh here: …`. Nothing goes red for it — the only assertions over that line
   are `tests/test_pin_defects.py:308,318,326` and they match the `REDACTION REFUSED (<name>)`
   prefix alone (PD7). Keep `CHECKS_DIR` as the interpolated constant, not the literal
   `tools/checks` the spec prints.
3. `stale_own_hook(text, name, asf_path, product_name, pin_required)` and
   `_own_upgrade(text, name, asf_path, product_name, pin_required)`: one parameter each, passed
   straight down to `_git_hook_body`. `_own_upgrade`'s `dispatch.is_ours(asf_path)` guard is
   unchanged (C15).
4. `ensure_git_hooks`: one `pin_required = os.path.isfile(dispatch.record_path(product.name))`
   before the repo loop — the same reading `_pinned` (`:733`) already does — threaded into the
   chain at `:371` and the write at `:383`. Nothing else about the write changes: a foreign hook
   is still left alone and still refused, a withheld path is still skipped, `_pin_refusal` still
   stands beside it (C6).
5. `plan` (`:478`): the same `pin_required`, so its `upgrade` verdict cannot disagree with what
   `ensure_git_hooks` writes.
6. Do **not** touch `is_git_hook_ours`, `hook_entry`, `init_hook_upgrade`, `staged_check_upgrade`
   or `add_staged_flag`: measured, all five read the new body as they read the old one, for both
   names and both pin states (P11, PD7).
7. `tests/test_pin_defects.py`: the four host states of P12, by running the written hook file
   directly under `/bin/sh` — a dispatcher at the path runs (exit 0, argv
   `redact --<name> --product <p>`); a non-dispatcher with the repo's `tools/checks/redact.sh`
   present warns once and runs `redact.sh` (exit 0); a non-dispatcher with no `redact.sh` warns
   then refuses (exit 1); no asf at all refuses (exit 1). Build the "dispatcher" fixture from
   `dispatch.render(...)`'s own first three lines, never a hand-copied marker string — measured,
   `MARKER` lands on line 2 and `head -n 3` is what the guard reads (PD7).
8. C4: exactly **one** warning line when both candidates resolve to the same non-dispatcher file.
