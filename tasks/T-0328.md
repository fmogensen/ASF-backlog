## Description
stories: S-31354, S-31355, S-31356

after: Task 3

§3.4, §3.5, §3.9 — in that order, which is D7's order and the only cheap one. Three questions, and
the first two can each void everything after them. Is the fence on at all, and does the collector
refuse a leg where it was not? Does the fence survive `bypassPermissions`, the launch path's own
default (`asf/workers/runtime.py:27`)? And does a proxied egress need the names
`hermetic.WORKER_ALLOW` strips? This Task also opens the document: the stamp and §2.7's second
section, so that every later Task appends rather than creates.

**Files**

- `docs/research/sandboxed-worker-shell.md` — **new**. §2.7's items 1 and 2 only: **the stamp** (the
  host OS and version, the runtime version, the date, the commit of this branch, the number of
  sessions launched, the count of unpaired rows) and **what the fence is** — the settings surface as
  Task 2 read it, with the one sentence about P11 that explains why every row below it is a pair.
  The document is one platform, stamped, and says so in as many words (D9): the cloud lane
  (`asf/workers/cloud.py`) runs inside a fence this factory does not own and is not measured (§1.2).
  The permission-mode finding and the environment-hole finding go in as prose here, each with its
  pair, because neither is a row of a role's table.
- `tools/spike/f-0065/**` — no new file. The footprint is here for PD12: a probe that comes back
  `error` is fixed and its leg re-run in the Task that found it.

**Steps**

1. `session.sh prober bare`, then `collect.py --role prober --require-control`. The two control
   rows must read `refused`. If they read `ok`, the settings file was ignored (P11) and the surface
   reading is wrong — that is a Task 2 defect found here, fixed here, and the leg re-run.
2. Then the inverse, which is the real assertion: `collect.py --role prober --leg off
   --require-control` must exit 1. A collector that accepts an unsandboxed leg's table is a
   collector that would have accepted every silently-ignored settings file in the spike.
3. The permission-mode pair, before any role table (D7): `session.sh coder mode-bypass` and
   `session.sh coder mode-default`, then `collect.py --pair coder.mode-bypass coder.mode-default
   --probe P00`. **If both legs read `ok`, `bypassPermissions` dissolves the fence** — write that
   finding into the document in the plainest sentence available, note that every row of every table
   must then be measured under the other mode, and add the §2.8 row that says the adopting card
   changes `permission_mode` (`asf/workers/runtime.py:27`, `asf/workers/spawn.py:715-716`) before it
   changes anything else. Tasks 5 and 6 then use the mode this pair proved keeps the fence.
4. The environment's own hole (§3.9): `session.sh coder grant-net` and `session.sh coder
   grant-net-passthrough`, then the four-probe pair. A probe `refused` in the first leg and `ok` in
   the second is a hole in `hermetic.WORKER_ALLOW` (`asf/hermetic.py:63-66`), and its row names the
   variable the operator must add to `worker_pool.env_passthrough`.
5. Write the stamp and §2.7's item 2. The unpaired count in the stamp comes from
   `collect.py --all --unpaired` and is updated by every later Task; it is never written by hand.
6. `bash tools/check_generic.sh` and `python3 -m asf.redact --tree` over the new document before
   the commit: the stamp names a host OS and a runtime version, and neither may carry an account
   name or a machine path (PD4, §3.8).
