Design §1's refusals, as batch-level cases on the class Task 2 created: a required job a runner
judged inside a cancelled run, one leg judged beside a skipped sibling leg of the same job, and a
path-filtered skip on a healthy run — each still red, and the runner-loss path still re-run by job.
Tests only; no product file changes. This is the fence the rule must build around itself, and it is
also where the rule is proved to have *declined*: a cut-short batch never reaches the flake triage
at all, so a shape that reaches the triage is a shape `run_cut_short` said no to.

**Acceptance**

**S-91808 — a job a runner judged, a leg a runner judged, and a path-filtered skip on a healthy
run, are still red**

The reds that must stay red, and the orderings that must not move (`D3`, `D9`):

```bash
python3 -m unittest -v \
  tests.test_mq_batch_survival.HostCancelIsNoVerdict.test_a_required_job_a_runner_judged_inside_a_cancelled_run_is_still_red \
  tests.test_mq_batch_survival.HostCancelIsNoVerdict.test_one_leg_judged_beside_a_skipped_leg_of_the_same_job_is_still_red \
  tests.test_mq_batch_survival.HostCancelIsNoVerdict.test_a_path_filtered_skip_on_a_healthy_run_is_still_red \
  tests.test_mq_batch_survival.SkippedBehindUnrequired
```

Green with these cases:

- a required job that failed on a runner inside a cancelled run is not read as a non-verdict: its first pass is held by the flake triage, pending, with no whole-run re-run asked and no member sent back
- the same job, with the triage's one re-run already spent, drops the batch as red and sends its culprit back, exactly as it does today
- a required job with one leg a runner judged and a sibling leg skipped on a cancelled run is not read as a non-verdict either: its first pass is held by the flake triage on the judged leg, and no whole-run re-run is asked
- the same leg, with the triage's one re-run already spent, drops the batch as red and sends its culprit back
- a required job skipped by its own path filter on a run that completed successfully drops the batch as red, which is the rule a skipped required check is not green
- a required job skipped behind an unrequired upstream that failed on a healthy run is still named as the real cause and still read by the triage and the blame
- a required job lost with its runner is still re-run by job, not by run, so the existing runner-loss path is unchanged
- the merge queue module's existing suites pass whole, with no assertion relaxed

**The regression surface** — the two suites the last bullet names, each whole:
