The spec's `## The design` §3: `doctor.clockless_steps` splits the step **names** out of
`check_clock_steps`' **lines**, so a caller that needs the names does not read them back out of a
sentence, and `asf/install.py`'s step 8 fails when it has just installed clocks that leave an
`asf`-owned step unreachable (C7).

Independent of Tasks 1 and 2 in every way — no shared file, no shared concept, no order — and in
wave 1 for that reason.

**Read PD6 before placing the call.** The spec's snippet, dropped in at the one place it names,
lets the `repaired (clock retried)` path — B-0136's own shape, with its own test — report success
while a step sits on no clock. Three success returns need the guard, two must not have it.

**PD7: there is no live symptom left.** The operator's `products/asf.yaml` already carries `groom`
on `record-health-wave-prs-harvest`, so `doctor.check_clock_steps` returns `[]` today and no
`NEEDS OPERATOR` line is owed by anyone. This Task builds the guard that would have caught it; its
acceptance is entirely its own tests.

`asf doctor`'s own row must come out **byte-identical** — `TestCheckClockSteps`' four existing
cases are the proof, and they are not edited, only added to.

**Files**

- `asf/doctor.py` — `clockless_steps(product)` with the spec's docstring, placed immediately above
  `check_clock_steps` (`:790`); `check_clock_steps` becomes one `NEEDS OPERATOR` line per
  `clockless_steps` entry, its message string unchanged. Both share the **one** loop over
  `tick_steps.resolve(product)` — `resolve`'s order is what the docstring's *"manifest order"*
  means (PD11/P10), and the `owner == 'asf' and step not in ticked` test and the
  `except scheduler.SchedulerError: return []` soft path move down into `clockless_steps`.
- `asf/install.py` — `_clockless_row(args, note)` on the module, returning `(0, note)` when there
  is nothing to report and `(1, 'step(s) on no clock: ' + ', '.join(clockless))` when there is,
  printing one `install: {line}` per `check_clock_steps` line to **stderr** first; called at
  `_step_scheduler`'s three post-install success returns (PD6). `doctor` is already imported
  (`:27`) — no new import, no new module, no new command, no new config key.
- `tests/test_doctor.py` — four new cases on the existing `TestCheckClockSteps` (`:111`), against
  `clockless_steps`. Its four existing cases against `check_clock_steps` are **not** edited.
- `tests/test_install.py` — new cases in the existing `InstallStepsTests`, beside the five step-8
  cases at `:2511-2560`. Those five are **not** edited (PD6: they pass `product='demo'`, which
  does not load, so the soft path keeps them green).
