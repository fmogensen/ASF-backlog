## Description
stories: S-29401
writes: asf/cli.py, asf/doctor.py, tests/test_views_header.py, tests/test_doctor.py, tests/test_cli.py
after: Task 2

§2.2: one tail, twenty commands, and `asf/doctor.py`'s hand-rolled `print(stamp(…))` deleted so
the stamp has exactly one caller under `asf/` outside `asf/groom/digest.py`. PD4 is why `_main`
is split first.

**Files**

- `asf/cli.py` — `_dispatch`, the reshaped `_main`, `_stamp_tail`, `_repo_of`; and the stale
  module docstring paragraph (`:11`)
- `asf/doctor.py` — `cmd_doctor`'s last `print(stamp('doctor', version=version_string()))`
  (`:1061`) and its two now-unused imports
- `tests/test_views_header.py` — `StampTests`
- `tests/test_doctor.py`, `tests/test_cli.py` — the stamp now comes from the dispatcher

**Steps**

1. Rename `_main`'s body to `_dispatch(args, parser, root)` with no other change — every
   `if args.command == …` branch and every `return` moves verbatim. `root = os.getcwd()` and the
   `parser.print_help(); return 2` fallback move with it.
2. `_main(argv=None)` becomes: build the parser, `args = parser.parse_args(argv)`,
   `rc = _dispatch(args, parser, os.getcwd())`, `return _stamp_tail(args, rc)`. `env.ConfigError`
   raised inside `_dispatch` propagates past the tail to `main`'s handler (`:446`), which is what
   makes the `NEEDS OPERATOR` path stampless (§2.2).
3. `_stamp_tail(args, rc)` exactly as §2.2 writes it, docstring included: resolve
   `header.command_key(args)`; return `rc` untouched when the key is not in `header.TITLES` or
   when `getattr(args, 'json', False)`; otherwise `version = version_string()` when the key is in
   `header.STAMP_VERSION` and `None` otherwise, then `print(stamp(key, repo=_repo_of(args),
   version=version))` and `return rc`. It prints on any `rc` (PD14).
4. `_repo_of(args)`: the product's `repo_dir`, resolved through `env` from
   `getattr(args, 'product', None) or env.default_product_name()`, returning `None` when there is
   no product (`capacity --all`), when the name resolves to nothing, or when loading raises —
   `stamp` then falls back to the cwd's sha exactly as it does today (`asf/cli.py:162`). It
   swallows `env.ConfigError` rather than raising a second one after the command already
   succeeded.
5. Delete the two lines at `asf/doctor.py:1060`–`:1061` (the comment and the `print`), and the
   `from asf.cli import stamp, version_string` at the head of `cmd_doctor` if nothing else in the
   function uses it. `doctor` is in `STAMP_VERSION`, so its stamp keeps naming asf's release and
   `tests/test_doctor.py`'s existing `generated by asf doctor@…` assertion keeps passing — it now
   proves the dispatcher, not the command.
6. Correct `asf/cli.py:11`'s paragraph: the "week-1 fast-path set … the fuller set lands with the
   0.1 spec" sentence describes a parser that no longer exists (`init`, `roadmap`, `backlog`,
   `product` and the rest are all registered in `build_parser`). Replace it with what the parser
   holds, and with the sentence that every table in `header.TITLES` ends with a stamp the
   dispatcher prints.
7. `StampTests`, §3.2: a command run with a `cwd` that is not the product's repo stamps the
   *product's* HEAD, asserted against `git -C <repo_dir> rev-parse` and not a retyped sha
   (B-0050); a product whose `repo_dir` does not resolve stamps `@unknown` and does not raise;
   `asf doctor` stamps `@<version_string()>` and `asf status` stamps a sha, the one difference
   `STAMP_VERSION` exists for; a command that returns 1 still prints its stamp; a command that
   dies on `env.ConfigError` prints the `NEEDS OPERATOR` line and no `— generated by asf` line;
   and `--json` on each `TITLES` command whose parser carries the flag (PD9, derived from
   `build_parser()`) prints parseable JSON on stdout with no stamp line in it.
