## Description
stories: S-32900, S-32905
writes: asf/feeder/tiers.py, tests/test_feeder.py, tests/test_s1_gate.py
after: none

The spec's first **In** bullet and its `asf/feeder/tiers.py` design block: a `Gate` record built by a
pure function that diffs the cut plan against the same plan at `s1_first=False`, one formatter that
owns the card's line, and one that writes a `NEEDS OPERATOR` line per S1 nothing is working. `select`
is not touched (D1, D2); nothing in this Task has a caller yet.

**Files**

- `asf/feeder/tiers.py` — `WORKED`, `Gate`, `gate`, `gate_line`, `needs_operator`
- `tests/test_feeder.py` — `S1GateTests` (new); `TiersTest` untouched
- `tests/test_s1_gate.py` — new module, `AnUnworkedS1HoldsNothing`

**Steps**

1. `WORKED = ('session', 'landing', 'branch', 'merge')` with the spec's comment: a tier-0 `WAITS` row
   whose `waits_on` is one of these is being worked; every other reason is a person's (D5). The four
   are `bug_rows`' own strings (`asf/feeder/rows.py:579-592`) plus the merge wait at `:704`.
2. `Gate = collections.namedtuple('Gate', 'holders held behind by_kind unworked')` with the field
   comments the spec's design block gives, byte for byte.
3. `gate(cut, uncut, held=())` — pure, over two row lists, no product and no I/O. `holders`: the ids
   of `cut`'s tier-0 rows with `action == NO_SLOT` that are not in `held`, in `cut`'s order, deduped
   (`dict.fromkeys`) — the same expression `left_out` already uses (`asf/tick/step_wave.py:371-372`).
   `behind`: the tier-2 launching rows of `uncut` not in `held`. `held` (the count): those of them
   whose `(item_id, kind)` is not among `cut`'s. `by_kind`: `[(kind, n)]` over the held rows in
   `uncut`'s order (D3) — feeder order, never sorted by count. `unworked`: `[(id, waits_on, reason)]`
   for each tier-0 row of `uncut` that does not launch and whose `waits_on` is not in `WORKED`, plus
   each tier-0 launching row whose `item_id` is in `held` (parked by an approval hold), in `uncut`'s
   order. Returns `None` when `holders` is empty and `unworked` is empty.
4. `gate_line(g)` — the card's line and the only place that string exists:
   `S1 gate: B-0057 holds 94 rows (PLAN → CODE 47, CARD → SPEC 27, STARVED → PLAN 12, STARVED → SPEC 8)`.
   Two or more holders read `B-0057, B-0061 hold 94 rows`. `None` when `g` is `None` or `g.held` is 0
   — a gate with nothing behind it is not news. The kinds are the row kinds as the feeder writes them
   (`asf.feeder.rows.BUG_FIX` and its siblings), never re-spelled here.
5. `needs_operator(g, product, skip=())` — `[]` when `g` is `None`; otherwise one line per entry of
   `g.unworked` whose id is not in `skip` (D8, PD13), in `unworked`'s order:
   `NEEDS OPERATOR: <id> is S1 and nothing is working it — <reason> — the S1 lane holds <g.held> of
   <g.behind> tier-2 rows behind it — <command>`. The count is always `held of behind` (D7), so a
   not-launchable S1 reads `0 of 94` and not `0 rows`. The reason and the command come from the
   spec's remedy table, switched on `waits_on`: `decision` → `undecided <age>` and
   `asf set <id> decided=true --product <p>`; `operator` → `adjudicated after <n> sessions` and
   `asf set <id> severity=S2 --product <p>` — or close it; a blocker id or `blocked` →
   `blocked by <ids>` and `asf set <id> blockedBy= --product <p>` — or close the blocker; a parked
   item → `held <class>` and `asf approvals resolve <id>/<class> granted|done|dropped`; anything else
   → the row's own `reason` and `asf set <id> severity=S2 --product <p>`. The `<age>` and the `<n>`
   are read off the row's `reason`, which already carries both (`asf/feeder/rows.py:595`, `:1201`),
   never off the item — `gate` takes no index and this function takes none either beyond `product`
   for the `--product` token.
6. `TIER_S1`, `TIER_S2`, `TIER_REST`, `NO_SLOT`, `free_slots` and `select` keep their meaning and
   their bodies exactly. `gate` reads them; nothing writes them.
7. `S1GateTests` in `tests/test_feeder.py`, over `plan_rows`
