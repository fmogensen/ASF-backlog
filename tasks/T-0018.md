## Description
stories: S-7452
writes: asf/hooks.py, tests/test_install.py, tests/test_approvals.py

**Files**
- `asf/hooks.py` — `hook_command`/`_is_ours` product-less form, `account_settings_path`,
  `install` writing the worker accounts.
- `tests/test_install.py` — `HooksTest` updated to the new message and the always-present
  approvals entry (PD6).
- `tests/test_approvals.py` — `HookTest.test_install_writes_the_entry_into_every_worker_account`.

**Steps**
1. PD2: `git show origin/main:asf/hooks.py | grep -q "BUILTIN"`; else the NEEDS OPERATOR line
   and stop.
2. `hook_command(asf_path, name, product)`: `product is None` → `<asf> hook <name>`.
   `_is_ours(command, name, product)`: `product is None` → `(^|/)asf hook <name>$`. `merge`
   passes `product` through unchanged.
3. `account_settings_path(account, home=None)` (PD4): `<expanduser(config_dir)>/settings.json`
   when set, else the runtime's user settings file under `account.home`, else under
   `home or os.path.expanduser('~')`.
4. `install(product, rules_dir, which, cfg=None)`: rule hooks go to the product repo exactly as
   today when any rule declares one (PD5); then `('PreToolUse', 'approvals')` is merged,
   product-less, into `account_settings_path(a)` for every `pool.accounts_from_config(cfg or
   env.load_config())`, creating the directory, idempotent through `merge`. Message:
   `hooks: <n> rule hooks in <repo settings>; approvals in <k> worker accounts`.
5. `tests/test_install.py` `HooksTest`: write an empty `config.yaml` in the temp home so no real
   account is touched; replace the `0 rules declare a hook` and `already installed` assertions
   with the new message and file-content idempotence (PD6); keep every other assertion.
6. The install test (§3 A2): two accounts with `config_dir` in a temp `config.yaml`, one settings
   file with an unrelated key that survives, a second install leaves both files byte-identical,
   and the entry is `{"matcher": "*", "hooks": [{"type": "command", "command": "<asf> hook approvals"}]}`.
