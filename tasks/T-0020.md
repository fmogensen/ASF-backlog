## Description
stories: S-7453

**Files**
- `asf/approvals.py` — `raise_holds(ctx, out)`, the `announced`/`closed` markers.
- `asf/tick/step_wave.py` — the raise at the top of `run`, the parking in the row loop.
- `tests/test_approvals.py` — `TickRaiseTest` on `tests.test_tick.TickTestCase`.

**Steps**
1. PD2: `git show origin/main:asf/approvals.py | grep -q "def cmd_approvals"`; else the NEEDS
   OPERATOR line and stop.
2. `raise_holds(ctx, out)` → `{item: (class, level)}` of every open hold (first in catalogue
   order per item). For each open `human-now` hold, oldest first, print
   `NEEDS OPERATOR: held <class> on <item> — <detail> — asf approvals resolve <item>/<class> granted|done|dropped`;
   when any `groom` hold is open, print once `approvals: <n> held for groom — asf approvals list`.
   For each open hold with no `announced` marker since its first `refused`:
   `ctx.event('held', hold=…, item=…, level=…, count=…, **{'class': cls})` (PD9), then append
   `announced`. For each resolved hold that was announced and has no `closed` marker:
   `ctx.event('hold-resolved', hold=…, item=…, resolution=…, **{'class': cls})`, then append
   `closed`. Each event exactly once across ticks (§4).
3. `step_wave.run`: call `raise_holds` first; in the row loop, a launching row whose `item_id` is
   held prints `waits    <job> <item> — held <class> (<level>)` (job = `job_name(row.brief_kind,
   row.item_id)`) and is not briefed or launched. The other rows are unchanged.
4. `TickRaiseTest` with the four §3 A3 methods; the NEEDS OPERATOR regex of A3 is asserted
   verbatim; `test_events_are_written_once` reads the record clone's `metrics/events/<day>.jsonl`.
