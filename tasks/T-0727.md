The spec's §2.7. P10 says no template or preamble does this today, so what lands is the regression
guard over a clean surface: every kind in `asf.briefs.build.KINDS` rendered, and a failure on any
rendered line matching *author/commit/sign* near *operator*, naming the kind and the line. The rule
itself — the three sentences §2.7 quotes — enters the *record*, not this repository; §5's first
operator line mints it.

This Task depends on nothing the other three land, and its `after: none` says so. It shares only
the test file, which is why it still runs on its own (PD14).

Read **PD16** before choosing the window: it is measured, it is six words either side, and the
measurement is the reason the guard can be tight enough to be worth having.

**Files**

- `tests/test_session_identity.py` — `class BriefIdentityRuleTest`, §3.4's three tests, and the
  module-level scanner they share. The rule's three sentences go in the class docstring, verbatim
  from §2.7, so the test says what it is guarding and not only how.

**Steps**

1. The scanner: over one rendered text, line by line, words lower-cased
   (`re.findall(r'[A-Za-z_-]+', line.lower())`); for each word starting `operator`, the ±6-word
   window; a hit when any word in it starts `author`, `commit` or `sign`. Returns
   `[(line number, line)]`, so the failure message can name both.
2. `test_no_brief_kind_tells_a_session_to_author_or_sign_as_the_operator` — every kind in
   `briefs.KINDS`, rendered through the synthetic-row shape `doctor.check_briefs` uses
   (`asf/doctor.py:1088-1094`: a `Row(action=LAUNCH, brief_kind=kind)`, no card, no git), scanning
   `Brief.text`. The failure message names the kind, the line number and the line. Nineteen kinds
   render for this product today and all nineteen are clean (PD16) — assert the count is not zero
   too, or a `KINDS` that came back empty would pass the guard silently.
3. `test_the_guard_catches_a_planted_line` — the guard proved to bite: patch a template in the test
   to say *"sign off as the operator"*, render, and assert the guard fails and names that kind.
   Patch it in the test's own tree or by monkeypatching the loader — never by editing a tracked
   template.
4. `test_git_commit_dash_s_is_not_a_violation` — `preamble.py`'s two lines (`:42`, `:666`) pass.
   They name a flag, not a person, and this is the test that keeps someone from "fixing" the guard
   by widening it until they do not.

**Gate**

```bash
python3 -m unittest -v tests.test_session_identity.BriefIdentityRuleTest
python3 -m unittest -q tests.test_session_identity tests.test_briefs tests.test_doctor
tools/check_generic.sh
```
