## Description
stories: S-59255
writes: asf/evidence/evidence.py, tests/test_evidence.py
after: Task 1

The spec's §*The design* §3: `landed_proves` fills a caller-supplied dict with what it refused,
over the same single pass, and `discover()` publishes it.

Read **PD7** (this Task carries the whole S-59255 fence, which spans it and Task 4).

**Files**

- `asf/evidence/evidence.py`:
  - `landed_proves(product, prs)` (**:1508**) becomes `landed_proves(product, prs, refused=None)`
    — one optional parameter, last, defaulting to `None`. Its docstring gains the spec's
    paragraph: a refused claim is **never** in the returned dict, because everything that reads
    that dict ticks (spec P6), and the parameter is filled in place rather than returned so the
    one production caller and the whole of `LandedProvesTests` keep their shape (spec D7).
  - the `add` closure gains the spec's refusal branch, written exactly as the spec gives it:
    after the existing `seen` dedupe, a claim with a `refusal` goes to `refused` with
    `entry["why"] = claim.refusal` beside the same `line`/`test`/`task`/`pr`/`sha`/`source` keys a
    counted entry carries — and **returns** without touching `per_story`. With `refused is None`
    it returns having recorded nothing, which is what keeps today's behaviour exactly.
  - both `for claim in proves.parse(…)` loops — the merged-PR body loop and the trunk-commit loop
    — read `parse_all` instead, counted first then refused, so `add`'s existing first-seen-wins
    dedupe is unchanged in meaning: the same claim seen from both sources is recorded once, from
    the pull request, which is read first. The `seen` set stays **one** set across both dicts, so
    a claim refused from a PR body is not re-reported from the trunk commit that carried it.
  - the final sort: `refused`'s lists sort by `(line, task or "")` at the end, exactly as
    `per_story`'s already do.
  - `discover()` (**:951**) declares `proves_refused = {}` before the evidence dict, passes
    `refused=proves_refused` to `landed_proves`, and publishes `"proves_refused": proves_refused`
    beside `"proves"`. The dict is filled by the time it is read, because `landed_proves` runs
    while the dict literal is being built.
- `tests/test_evidence.py`:
  - `LandedProvesTests` (**:1238**) is **not edited** — every existing case calls
    `landed_proves(product, prs)` with no `refused` and indexes the returned dict (spec P7), and
    all of them are asserted unchanged and green.
  - `RefusedProvesTests` added beside it, on the same fixture, exactly the spec's list: a merged
    PR whose body carries one whole and one qualified claim puts exactly the whole one in the
    returned dict and exactly the qualified one in `refused`, with `why == 'partial claim:
    "only"'` and the same six keys a counted entry has; a `Proves:` trailer on a trunk commit does
    the same with `source == 'commit'` and `pr is None`; the same claim seen from **both** sources
    appears once, in `refused`, and never in both; `refused=None` (the default) drops the refusals
    and returns exactly what it returns today; and both dicts sort by `(line, task)`.
  - one case on `discover()`'s own output: `ev['proves_refused']` carries the refusal and
    `ev['proves']` does not — the assertion that the dict reached the evidence and not just the
    function.

**Steps**

1. Baseline: `python3 -m unittest -v tests.test_evidence` green, unmodified. Record the last line.

   `tests.test_evidence`: green and unchanged — with `parse` still filtering, nothing refused ever
   reaches `add`, so this step is a no-op by construction. That is the point: it proves the
   parameter is inert before the loops move.
