## Description

The spec's I5 and I7's example half, and `## The design` §3 and the `tests/test_env.py` part of §5.
`docs/products.example.yaml:116-125` is worse than silent: its three per-kind label lists describe
the routing as it was *before* `f5816335c`, and its only worked example is `review: light` — a string
override, the one form that cannot express what this card is about.

D2 is why the lists are **deleted** rather than corrected. Correcting them buys one release;
deleting them removes the thing that rots. And a per-kind claim cannot express a per-class table, so
`review: heavy` would pass any per-kind assertion while still telling the customer the opposite of
the truth — the deletion is the fix, the assertion is the guard against putting it back.

Read **PD5** (the guard must skip a token that is not a kind, or the block you are landing turns it
red), **PD2** (`from asf.briefs import build` gets a function) and **PD8** (the whole replacement was
pre-verified; every existing assertion survives it) before starting.

`models:` stays **commented** (D3). Uncommenting it would change what `conventions` the documented
Product actually holds, for every test that loads that file — a routing change smuggled in as
documentation. The proof that the reader accepts the map shape is Task 3, on text it owns.

**Files**

- `docs/products.example.yaml` — the `models:` comment block (`:116-125`)
- `tests/test_env.py` — two new methods on the existing `DocumentedModelsTests` (`:31-49`), and one
  module-scope import

**Steps**

1. Replace `docs/products.example.yaml:116-125` with this block. It was applied in memory in this
   worktree and every existing assertion survives it (PD8) — the three `label — kind, kind, kind`
   lists are gone, `conventions.models` and all three label words stay, and `models:` stays
   commented:

   ```yaml
     # read as conventions.models.<kind> — the operator's override of the model label a kind runs
     # on. Three labels, mapped to real model ids in ~/.ASF/config.yaml under worker_pool.models:
     #   heavy  judgement
     #   light  code
     #   cheap  clerical work with a right answer
     # The built-in default is per kind AND per item class (a Bug's severity; else task/story/
     # feature/epic): an S2 or S3 Bug's review, correction and adjudication run light where an S1's
     # run heavy. `asf doctor` prints the resolved table for this product, one `model table` row per
     # kind — read it there rather than here, so what you read is what runs.
     # Unset for a kind means that built-in row. A string covers every class; a map picks by class,
     # and its `default:` covers every class it does not name — including ones the built-in routes
     # to heavy. Argue a change against the numbers, not taste: `asf improve` prints
     # minutes-per-landing per kind and per model every week, and the table in
     # docs/config.example.yaml is the measurement this routing was chosen from.
     # models:
     #   coder: heavy
     #   review: {S1: heavy, S2: light, S3: light, feature: heavy, default: light}
   ```

   The `cheap` line deliberately carries no em dash, so it names no kinds and the guard of step 3 has
   nothing to read on it (PD5). If the author prefers the spec's §3 wording
   (`#   cheap  clerical — no judgement, a right answer`), the guard's skip-non-kinds semantics make
   that green too — but do not write both and do not write a per-kind list on any label line.
   Keep the two-space yaml indent: these lines sit inside the `conventions:` block.
2. The worked example is the **flow form** `review: {S1: heavy, S2: light, S3: light, feature: heavy,
   default: light}` — the card's own line, and therefore the line a customer copies — plus
   `coder: heavy` as the one-label form beside it. `review: light` as the block's only example is
   what goes.
3. `tests/test_env.py`: add `from asf.briefs.build import DEFAULT_MODELS`
