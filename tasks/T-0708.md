The spec's §1 in full: the new module's config half, the three keys `CI_FIELDS` gains, and the
fifth delegation in `validate_product_text`. After this Task a product file can say
`ci.provider: vm` with hosts and jobs, and every unknown field, missing `ssh`, missing `command`,
duplicate name, non-positive `slots`/`timeout_min`, unsatisfiable job label and empty-block
provider is refused by dotted key with a sentence — and a product that says nothing new cannot
tell this landed.

Nothing that talks to a machine lands here: no `ssh`, no `subprocess`, no store. The module ends
at `required_names`.

Read **PD12** (the three fences and the `/tmp/` trap) before naming `DEFAULT_ROOT`, and **PD11**
(no module-level `lane` import) before writing the import block.

**Files**

- `asf/ci_vm.py` — new. The module docstring, then the spec's §1 surface in its own order:
  `PROVIDER`, `HOST_FIELDS`, `HOST_REQUIRED`, `JOB_FIELDS`, `JOB_REQUIRED`, `DEFAULT_ROOT`,
  `DEFAULT_SLOTS`, `DEFAULT_TIMEOUT_MIN`, `DEFAULT_RETENTION_DAYS`, `CONNECT_TIMEOUT_S`,
  `RED_LOG_TAIL_BYTES`, `VmHost`, `VmJob`, `enabled`, `config_problems`, `hosts`, `jobs`,
  `required_names`. Module-level imports: the standard library and `asf.env` only (PD11).
- `asf/env.py`
  - `CI_FIELDS` (`:527-531`) — `'hosts': _LIST, 'jobs': _MAP, 'artifacts': _MAP,
    'post_status': None`, the spec's §1 block byte for byte, with the comment naming F-0178 as
    `artifacts`' co-owner (P13/C12: identical declaration, whichever lands first owns the line)
  - `validate_product_text` — one delegation after `ci_queue.config_problems`'s (`:678-680`),
    the spec's §1 snippet byte for byte, line-anchored
    `lines.get('ci.hosts', lines.get('ci', 0))`
- `tests/test_ci_vm.py` — new: `class Config`, the spec's §*The config* list in full.

**Steps**

1. `asf/ci_vm.py`'s docstring first — one paragraph saying what the module is (the `vm` CI
   provider: machines, commands, a store and a pass), what it is not (no runner registration, no
   queue, no workflow — C's out-of-scope list), and that `<root>` is the only place on a host
   ASF writes.
2. The eleven constants and the two frozen dataclasses, the spec's §1 byte for byte.
   `DEFAULT_ROOT = '.asf-ci'` is relative to the ssh user's home and is not negotiable (PD12).
3. `enabled(product)` — `evidence.ci_provider`-shaped but local and cheap: the product's `ci`
   is a dict whose `provider`, lower-cased and stripped, is `PROVIDER`. False for a `ci` that is
   a bare string, for `none`/`off`, and for a product with no `ci` at all. Every branch this card
   adds is behind this one function, so it never raises: a product object missing `ci` is False.
4. `hosts(product)` / `jobs(product)` — declaration order kept (`jobs` returns a `dict`, which
   preserves insertion order; the spec's `ci.jobs` is a map of name → entry, so the job's `name`
   comes from the key). Unknown fields are ignored here and reported by `config_problems`: a
   parser that raised would make one bad key unreadable rather than refused. `labels` become
   `frozenset`, `artifacts` a `tuple`, `slots`/`timeout_min` ints with their defaults.
5. `config_problems(ci)` — `[]` for a `ci` that is not a dict. Then, in one pass and always as
   `(dotted, why)` with the dotted key naming the offender exactly (`ci.hosts[1].ssh`,
   `ci.jobs.e2e.timeout_min`): an unknown host or job field against `HOST_FIELDS`/`JOB_FIELDS`;
   a missing `HOST_REQUIRED`/`JOB_REQUIRED`; a duplicate host name or job name; `slots` or
   `timeout_min` not a positive int (and not a bool); a `ci.jobs` entry whose `labels` no
   declared host's labels are a superset of; and — only when the provider is `vm` — no hosts at
   all, or no jobs at all. The label check is the one that needs care: it is *satisfiability*,
   `job.labels <= host.labels` for at least one host, and a job with no labels is satisfied by
   any host.
