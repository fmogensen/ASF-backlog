§2.5. This is the measurement half of the card and it is independent of the gate: it lands whether
or not the gate is armed, and until it lands every run F-0094 successfully rescued is still counted
against this card's own number. `sessions_from_registry` folds the registry and yields each run's
*current* verdict every tick; `append_event` throws it away every tick because the corrected event
carries the same natural key `(task, ts)` and a run's `ended` does not move when the factory
re-judges it.

**Files**

- `asf/metrics/metrics.py` — `SESSION_OWNED`, `append_event` (`:336-350`), a rewrite helper, and
  `cmd_append`'s status branch (`:377-380`)
- `tests/test_metrics.py` — `SessionUpdateTests`

**Steps**

1. `SESSION_OWNED = ('result',)` directly above `append_event`, with §2.5's `#:` comment byte for
   byte — including why it is a tuple, and why `reason`, `usd`, `minutes` and the token dimensions
   are **not** in it (an ended run's log does not grow, so none of them is the registry's to
   correct).
2. `append_event(root, stream, ev)` keeps its signature and gains §2.5's third status. Read the
   day's file once into a list (`read_file`, `:313-321`), find the first stored line whose
   `natural_key` equals the event's, and:
   - no hit → the current append path, unchanged byte for byte, including the trailing-newline
     probe (`:344-348`) and `'appended'`;
   - a hit and `stream != 'sessions'` → `'exists'`, not a byte written;
   - a hit on `sessions` whose `SESSION_OWNED` fields all match the event's → `'exists'`, not a byte
     written;
   - a hit on `sessions` with a differing owned field → set **only** those fields on the stored
     line, rewrite the file from the parsed lines in their own order, return `'updated'`.
   Every other field of the stored line is left as it was: §1.4's reason is that the stream carries
   item joins and token dimensions that a backfill with a different `items` index enriched, and a
   blanket overwrite would silently drop them.
3. The rewrite is its own small function: every line through `dumps` into a
   `tempfile.NamedTemporaryFile(dir=os.path.dirname(path), delete=False)`, flushed, then
   `os.replace` onto the path — same directory, so the replace is atomic and a reader never sees a
   half-written stream (§2.5). PD9 says what this does to the other lines and why it is right.
4. `cmd_append`'s status branch becomes three-way (PD8): `'exists'` keeps today's `no-op: already
   in <rel> (natural key …)`, `'updated'` prints `updated <rel> (natural key …)`, `'appended'` keeps
   `appended to <rel>`. `cmd_backfill`'s `put` (`:1725-1732`) and `import_sessions`' `put`
   (`asf/metrics/import_sessions.py:233-241`) both count by status and need no change — the tick's
   output gains `sessions updated: N`, which is §2.5's whole point for the operator.
5. `SessionUpdateTests(Base)` in `tests/test_metrics.py` — `Base` (`:125`) already gives the root
   and the `put` helper — one case per clause of the T5 fence: a first `sessions` event returns
   `'appended'`; the same key with an unchanged `result` returns `'exists'` and leaves the file
   **byte-identical** (read the bytes before and after, do not compare parsed lines); the same key
   with `result` moved from `failed: not pushed: 3 uncommitted file(s), 0 unpushed commit(s)` to
   `finished` returns `'updated'`, leaves exactly one line for that key, carries the new `result`,
   and keeps the stored line's `reason`, `usd`, `minutes` and all four token dimensions as they
   were — build the first event with values in each of those fields and a second event with them
   absent or different, so the test would fail if the line were overwritten wholesale.
