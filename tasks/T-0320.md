## Description
stories: S-31102, S-31107

§2.3, §2.5's dollar half and §2.6's application. The Task that stops launching every role as root.
`build_command` stays a pure function of the job and of the flags the installed binary accepts;
`spawn` fills the new fields from one `launch_for` call, and the session record finally answers what
a session was launched with.

**Files**

- `asf/workers/runtime.py`:
  - `Job.__init__` gains `effort=''`, `tools=()`, `deny_tools=()`, `agents_file=None`, `agent=''`,
    `plugin_dirs=()`, `max_budget_usd=None`, `strict_mcp=False`, `restricted=False`, each
    defaulting to the empty value, so every existing caller and every existing test constructs the
    same job it does today.
  - `build_command(job, binary=DEFAULT_BINARY, caps=None)` — §2.3's body, in §2.3's order, with
    **PD6**'s one change: `have` is `caps` when given, else `capability.flags(binary)` only when
    `_gated(job)` finds a non-empty gated field, else `set()`. `_gated` is a module-level helper
    with a docstring saying why. The docstring of `build_command` is §2.3's, plus the sentence that
    a job with no gated field runs no subprocess at all.
  - `flags_skipped(job, caps)` → the gated flags this launch left out, in order, for the session
    record and the doctor row. One function, read by both, so the ledger and the reading never
    disagree.
- `asf/workers/spawn.py`:
  - One `launch_for(row.kind, product)` call, one `write_agents_file`, and the `Job` construction
    of §2.3 — `permission_mode` the launch row's, overridden by `wp.get('permission_mode')` when an
    operator set one (unchanged precedence); `effort=roles_launch.effort_for(row.kind)`;
    `tools`/`deny_tools` the row's; `agents_file` the written path and `agent=launch.role`;
    `plugin_dirs=[procedures.plugin_dir()]`; `strict_mcp=True` for every role (D13);
    `restricted=launch.restricted`, **dropped when the resolved mode is `bypassPermissions`**
    (PD8), with the drop recorded; `max_budget_usd=budget.of(conv, item).usd`, `None` passing no
    flag; `settings_file=worker_settings.path(product, launch, wp)`.
  - The session record gains `role`, `effort`, `permission_mode` and `flags_skipped`.
- `tests/test_launch.py` — `CommandLineTests`, `BudgetFlagTests`, `EffortTests`, and a `SpawnLaunchTests`
  for the record's four new fields and the `--restricted` drop.
- `tests/test_workers.py` — `RuntimeCommandTests` (**PD11**), new: a reviewer job with a full
  capability set produces §2.3's exact argv in §2.3's order; the same job against an empty
  capability set produces **today's** argv unchanged (P1); `--agent` is never passed without
  `--agents`; `max_budget_usd=None` passes no flag; no subprocess runs in either case. The existing
  `TestRuntime.test_command_line_golden` is left exactly as it is and must stay green — it is the
  regression that says an old job still builds an old command line.

**Steps**

1. `Job`'s nine new keyword parameters, defaults first, and run `tests.test_workers` — every
   existing case must pass before a flag is added.
2. `_gated`, then `build_command`'s gated additions one flag at a time in §2.3's order, running
   `TestRuntime.test_command_line_golden` after each.
3. `RuntimeCommandTests`, including the empty-capability-set case.
4. `flags_skipped`.
5. `spawn`: the `launch_for` call, the agents file, the settings file, the two caps, the
   `--restricted` drop, the record's four fields.
6. `CommandLineTests`, `BudgetFlagTests`, `EffortTests`, `SpawnLaunchTests`.
