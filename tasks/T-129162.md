## Description
stories: S-80305

after: none

The spec's **In** 3 and its design §3: `stability` joins `SETTABLE['feature']`, `SETTABLE['epic']`
and `BOOL_FIELDS`. That is the whole change, and it is deliberately the whole change — the
`true`/`false` refusal before the card is touched (`asf/record/new.py:69-70`, `_parse_sets`), the
`asf set` path (`asf/record/setfield.py:148`, through the same `_parse_sets`) and `asf check`'s
per-card type validation (`asf/record/check.py:312-316`, which already loops over `BOOL_FIELDS`)
all come from machinery that exists, with no edit outside this file (PD9). The field reaches the
feeder with no index change (PD8), and what it *means* is Task 2's.

This Task delivers S-80305's last bullet — `stability` is settable on both types, parses `true`
and `false` as a boolean, and `asf new --set stability=yes` is refused before the card is written.
S-80305's other four bullets are the exemption's behaviour under a freeze and are **Task 2's**.

**Read this Task from `docs/plans/f-0307.md`, not from this card.** Measured, not assumed: this
section is **5469 characters** and the record cuts a Task card's description at 4000 (PD6), so the
card stops inside the sentence that introduces the **Acceptance** and the five S-80305 bullets
never reach it. The card's `links.plan` is this file.

**Files**

- `asf/record/new.py` — two `SETTABLE` lines with the spec's §3 doc comment above them, placed
  beside the existing `SETTABLE['feature'] |= {'lane', 'size', 'ab_pair'}` (`:33`) and its
  `reshape_applied` sibling (`:36-37`), each of which carries exactly such a comment; and
  `stability` appended to `BOOL_FIELDS` (`:49`). `SETTABLE[t]` is a `set` (`:20`), so `|=` is the
  landed idiom. Nothing else in the file moves — in particular **not** `FIELD_WORDS`: a boolean
  field is checked by the `BOOL_FIELDS` branch (`:69-70`), not the word branch.
- `tests/test_backlog.py` — the round-trip, the refusal and the `asf check` finding, beside the
  `local_only` cases at `:250-282` and in their shape (PD14), for a **Feature** and for an
  **Epic**.
- `tests/test_new_publish.py` — `asf new --set stability=true` on a Feature and on an Epic, and
  `--set stability=yes` refused before the card is written.

**Steps**

1. `asf/record/new.py`: the doc comment the spec fences, then
   `SETTABLE['feature'] |= {'stability'}` and `SETTABLE['epic'] |= {'stability'}`. Keep them
   together, beside the Feature block at `:30-33`, so the two types read as one declaration.
2. `BOOL_FIELDS = ('local_only', 'stability')`. Leave `asf/record/check.py` alone — its loop is
   already over `BOOL_FIELDS` and widening the footprint for its comment is not this Task (PD9).
3. `tests/test_backlog.py`: `asf set F-xxxx stability=true` and `=false` round-trip to a Python
   `bool` in the card's frontmatter (assert with `assertIs`, as `:258` does — `1` and `'true'`
   must not pass); the same on an **Epic** card; `asf set … stability=maybe` is refused and the
   card is unchanged on disk; and a hand-edited `stability: maybe` is named by `asf check` as
   `stability must be true or false` (the `:263-273` shape — write the bad value into the file,
   then run `check`).
4. `tests/test_new_publish.py`: `asf new --type feature --set stability=true` and
   `--type epic --set stability=true` land the field; `--set stability=yes` exits non-zero with
   `one of true, false` and writes **no** card. Assert the no-card half: `_parse_sets` runs before
   the file is written, and that ordering is what the bullet claims.
5. Do **not** add a `stability` reader to the feeder, a `conventions` key, a migration or a
   backfill: the spec's **Out** rules out all four, and absent reads as not-stability.
