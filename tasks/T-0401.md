stories: S-33751, S-33752, S-33753, S-33754

§2.3 and §2.6. Four Stories on one Task because they are one call: `apply` is what makes the table
binding, and coverage, voice, internals and the markers are four assertions about the same 49 rows
seen through the same parser. Split apart, three of them would assert over a table nothing reads.

This is the Task where the descriptions actually change, so it is also where the plugin's twelve
skills are regenerated (PD6) — the same sentence a stranger reads in `--help` is the sentence an
assistant reads before deciding to run something.

**Files**

- `asf/cli.py` — the three lines at the end of `build_parser` (§2.3), and the `surface` import
- `asf/surface.py` — `apply`'s docstring, if Task 1's needs a word about the epilog; the epilog text
  itself lives in `asf/cli.py` where §2.3 puts it
- `tests/test_surface.py` — `CoverageTests`, `VoiceTests`, `NoInternalsTests`, `MarkerTests`
- `plugin/skills/**` — regenerated: twelve descriptions, markers included
- `tests/test_plugin.py` — only if an assertion names a description

**Steps**

1. `asf/cli.py`, at the end of `build_parser`, §2.3's three lines byte for byte: `surface.apply(sub)`,
   the epilog, `p.formatter_class = argparse.RawDescriptionHelpFormatter`, then `return p`. The call
   sits after every `register(sub)`, which is what makes one post-pass see all 49 (§1.1).
2. The epilog's first line is §2.3's, unchanged — `A command with no [writes …] marker only reads:
   it prints and exits.` The second line is PD8's, because §2.3's is untrue of two commands:
   `Every command but upgrade and plugin takes --product, on the command or on its subcommand;`
   `without it, the record is the current directory when that is a record, else the default product's.`
3. `CoverageTests`, §2.6 check 1, both directions over the live parser: every `action.dest` in
   `sub._choices_actions` is a key of `surface.COMMANDS`, and every key of `COMMANDS` is registered.
   Plus the failure path stated as a test: a parser with one extra `add_parser('not-declared',
   help='x')` makes `surface.apply` raise `SurfaceError` naming that command. That is the check a
   new command trips, and it is worth asserting that it trips rather than only that it passes today.
4. `VoiceTests`, §2.6 check 2, over every row: the first word — punctuation stripped, so
   `render,` is `render` — is in `VERBS`; the description starts lowercase; it does not end in `.`;
   it contains no `?`; it is at most 100 characters. `VERBS` is §2.1's list plus `derive`, `install`
   and `rebuild` (PD10) — if a row's verb is missing, the list gains it in a visible line, and the
   check is never loosened.
5. `NoInternalsTests`, §2.6 checks 3 and 4. No description contains `/`; none matches
   `\.(json|ya?ml|sh|py|md)\b` or `<[a-z]+>`; none contains a field name of
   `asf.conventions.Conventions` as a word, **case-sensitively** (PD11 — `stage_limits` is the
   defect, `README` is not). And nothing explains itself: no description matches
   `\b<name>\b\s+(table|pass|view|report|command)\b`, case-insensitively (PD9). Assert the check
   against the three strings the card filed, so the test proves it would have caught them:
   `the evidence pass (git/gh derived state)`, `the PARITY table: one row per Story` and
   `items over their stage limit (the product's stage_limits)` each fail it.
6. `MarkerTests`, §2.6 check 5 and S-33751's whole Story: for every command, the `help` argparse
   holds equals `text + surface.marker(effect, flag)` for that row; no description in the table
   contains `[writes`; the parser's epilog carries both lines; and — PD8 made mechanical — the set
   of commands taking `--product` nowhere (neither on the command nor on each of its subcommands) is
   exactly `{'upgrade', 'plugin'}`, the two the epilog names.
