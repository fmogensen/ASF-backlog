**Steps**

1. `asf/record/ids.py`: `record_top` (`:40-52`) and `mint_id`'s `taken` (`:126-136`) list
   `core.archived_folder(folder)` beside `folder`. The archive listing matches
   `^<prefix>-(\d+)\.(json|md)$`; the item folder's own `^<prefix>-(\d+)\.md$` is left exactly as it
   is (**PD10**, block M2). The one-line comment says why the two differ: an archived card is the
   one card no reader will ever rewrite, so its number must hold whether or not a view sits beside
   it, while changing the item folder's regex would change which ids a live record calls taken —
   which this card does not ask about. Names only: no file is opened, no card is parsed (D-0014).
2. `asf/record/ids.py`: `origin_top` (`:74-105`) runs one more
   `ls-tree -r --name-only <remote>/<trunk> -- archive/<folder>` per prefix, folded into the same
   `top`. A pathspec is rooted, so today's `-- <folder>` reaches no archive path and the two
   listings never double-count. No API call, no second fetch.
3. `asf/record/check.py`: the new finding, beside the duplicate-id rule at `:337-343` and **in both
   modes** for the reason that rule's own comment gives (**PD11**) —
   `T-0123 is also in archive/tasks/ (one of the two is stale)`, on the working-set card's relpath
   at its `id` line. The archive's names are read once per `record_findings` call, `os.listdir` per
   archive folder **that exists** — at most seven — and no card is opened, so `asf check` still
   loads the working set only (D-0013).
4. `tests/test_record_archive_ids.py`: S-211573's eight lines. `record_top` counts the archive;
   minting inside a claimed range steps over a number the archive holds (the measured `T:0090-0120`
   case of block M2, asserted as the fix); minting with no claimed range clears both tops; the
   origin-side top reads the archive's folder on the trunk (a real temp repo with a commit, not a
   stub); the gate opens no archived card file (counted by patching `builtins.open`);
   `asf check` reports an id both places hold and reports nothing when an id is in exactly one of
   them, in both `--schema-only` and the full mode; and the rule costs at most one directory listing
   per archive folder (counted by patching `os.listdir`).
