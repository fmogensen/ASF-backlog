## Description
stories: S-15554, S-15555
writes: asf/record/ingest.py, tests/test_ingest.py

§2.2 and §2.4: the five per-type blocks keep every line that *matches* an item to evidence and
every line that builds the `evidence:` prose, and lose their state choice to `closing.state_of`.
The pass gains one step — descent — between features and epics.

**Files**

- `asf/record/ingest.py` — the module docstring's "derives its machine block" sentence; `_ev_of`
  helpers per type filling a `closing.Ev`; the five blocks calling `closing.state_of` +
  `closing.sticky`; `_in_prod(child_ids, task_ev, ev)` (P9); `descend(...)` (§2.4); the `rule:`
  line appended to every item's `ev_lines`; `_ingest_fields`' History phrase quoting the rule.
- `tests/test_ingest.py` — `DescentTests` (new), `IngestDerivesNothing` (new, the structural
  test), and the new cases of §3.2 beside `CmdIngestEndToEndTests` (`:359`),
  `ProductionIsTheProductsOwn` (`:63`), `LandingOutranksThePlan` (`:126`), `RemovedTaskTests`
  (`:564`), which are unchanged and are the regression net.

**Steps**

1. Per type, build a `closing.Ev` from what the block already matched: the Task block from `tev`
   plus `match_ids`; the Story block from its matrix row, the Tasks whose `stories:` name it, and
   `_in_prod` over those Tasks (P9); the Bug block from `bev`, `merged_in_prod`, the typed
   `signature`, and `quiet_for`/`quiet_limit` computed here from `last_filed` and
   `stale.load_limits(product).get('bug_quiet')` (P6, P7, P8); the Feature block from its children's
   derived states, `_in_prod`, `spec_on_main`/`plan_approved` and `match_ids`; the Epic block from
   its children's derived states and the typed `closed`.
2. Each block's state line becomes
   `closing.sticky(old_state, closing.state_of(type_, ev_obj, old_state))`, and `new_state[iid]`
   is that `Closing.state`. No `evidence.*_state` call remains (P5). B-0074's early `continue` in
   the Task block becomes rule order, not control flow: `landed-green`/`landed` are read before
   `in-flight`, so a trunk landing still outranks a plan's task table.
3. `stage_val` is untouched: `evidence.feature_stage` is a stage function, not a state function,
   and the `landed`/`card` assignments of the Feature block stay exactly where they are.
4. Every item's `ev_lines` gains one last entry, `rule: <name>` (§2.3), and `_ingest_fields`'
   History phrase becomes `rule: <name>; <the other lines>` so the line reads
   `state Resolved → Closed (rule: landed-green; commit 9f2ac41 names T-0052; …)`.
5. `descend(canonical, new_state, closings, derived)` per §2.4, run after the Feature pass and
   before the Epic pass: a Feature that came out `Closed` closes the children beneath it whose own
   `Closing.rule` is `NO_RULE`, or whose state is `New` with no branch, no PR and no commit. A
   child with evidence of its own — Active, an open PR, a branch — keeps its own rule's state. One
   level at a time, to a fixed point inside the subtree (Feature → Story → Task). A Bug is never
   descended onto. The rule name is `parent-closed` and the evidence lines name the parent and the
   sha that closed it.
6. `IngestDerivesNothing`: an AST walk over `asf/record/ingest.py` asserting no `Attribute` call
   of the form `evidence.<x>_state`, so a sixth state choice cannot grow back into the module.
7. The rest of §3.2's new cases: every closed item's `evidence:` ends with `rule: <name>`; the
   History line quotes it; a second `asf ingest` over the same evidence writes nothing (P10 of the
   spec — `_ingest_fields` returns `None` when the block is unchanged).
