The spec's `## The design` §2's first half and §3 in full, the whole of its A2 Acceptance block,
and the first three cases of its A3 block. **PD1 is this Task's shape** — the reporting moves to
the top of `commit_and_push`, before the commit, because that is the only place an event survives
— and **PD4 is its hardest constraint**: not one new `['git'` line in `asf/tick/shadow.py`.

**Files**

- `asf/tick/shadow.py` — the `Sync` namedtuple; `probe_operator_checkout(product, out=print)`,
  built by **moving** `sync_operator_checkout`'s four read-only git calls into it (`:211`, `:214`,
  `:217`, `:221` — PD4); `sync_operator_checkout(product, out=print, probe=None)` keeps the
  `merge --ff-only` (`:225`) and nothing else, and returns a `Sync`; the three refusal lines lose
  `{repo}` and gain the drift (`:219`, `:223`, `:228` — D10)
- `asf/tick/tick.py` — `commit_and_push` (`:294-311`): the probe, the line, the `NEEDS OPERATOR`,
  the event and the health write at the top; the merge, handed the probe, where the sync is today
  (`:310`); `ctx.checkout_sync` kept on the context
- `asf/tick/record_health.py` — `record` takes and carries `checkout` (`:33`); `update` is new;
  `line` restructured so the checkout sits outside the `ok` gate (`:57-67`) — all three PD7
- `asf/views/status.py` — `stale_cell`'s docstring only (`:300-314`, PD8). No code change
- `tests/test_operator_checkout_sync.py` — the A2 block: the landed local-edit case gains the two
  new assertions, five new cases join it
- `tests/test_tick.py` — the A3 block's first three cases. Task 4 writes the other two, which is
  why that Task is `after: Task 2`

**Steps**

1. `Sync = namedtuple('Sync', 'moved why behind paths detail')`, the spec's docstring byte for
   byte. `SYNC_PATHS_MAX` beside it, the cap the docstring names — the spec gives no number; use
   **3**, the cap `parked_cell` already uses for the same job (`asf/views/status.py:480`), and say
   in the comment that the line is for a person, not a manifest.
2. `probe_operator_checkout(product, out=print)`: the three opening guards unchanged
   (`:206-210`), then the four moved calls. `why` is a property of the **tree**, not of the drift
   (PD15): `'off-trunk'` when `symbolic-ref` is not the trunk, `'local-changes'` when
   `status --porcelain --untracked-files=no` is non-empty, `None` otherwise — each answered
   whatever `behind` is, and `behind` reported as the number `rev-list --count` gave (0 included).
   `paths` is that same `status` output's path column, which is already record-relative, sorted and
   capped. It prints the matching refusal line when `why` is set, and returns
   `Sync(moved=False, why=…, behind=…, paths=…, detail=…)`.
3. The three refusal lines, byte for byte from §2, each keeping the literal `not fast-forwarded`
   (`tests/test_operator_checkout_sync.py:81`, P18) and **naming no filesystem path** (D10): the
   old `{repo}` becomes `the record checkout`, and the drift and the paths go in. Nothing in this
   module may print `product.backlog_dir` again — the line goes into the tick log and its fields
   into a tracked, published event.
4. `sync_operator_checkout(product, out=print, probe=None)` keeps **only** the merge. Its body is:
   take the probe it was given when that probe already refused — there is nothing to merge and the
   line was already said, so return it untouched (PD15) — otherwise probe again with `out=None`
   (the push has moved origin since, so `behind` must be re-read), return that probe when it
   refuses or when `behind` is 0, and otherwise run the `--ff-only` merge and answer
   `Sync(moved=True, why=None, …)` or the merge's own refusal. The `behind == 0 → nothing to do`
   short-circuit lives **here** now, not in the probe (PD15). Net `['git'` lines in the file after
   this step:
