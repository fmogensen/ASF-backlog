## Description
stories: S-32560
writes: asf/metrics/metrics.py, .github/workflows/tests.yml, tests/test_metrics.py
after: Task 6

§2.7 and §2.8, D7. Two reads in front of `cut_tag`, and the two CI steps — one that runs
`asf docs check`, one whose *name* is what the gate looks for. It lands last of the docs chain
because both of its CI steps must be green on arrival: `asf docs check` is clean only once Task 6
has turned on the fifth check and satisfied it (PD9).

**Files**

- `asf/metrics/metrics.py` — `release_gate(product, sha, root)` and its call in
  `_cut_trunk_release` (`:1382`)
- `.github/workflows/tests.yml` — two steps after `check generic`
- `tests/test_metrics.py` — `ReleaseGateTests`

**Steps**

1. `release_gate(product, sha, root)` → `(bool, reason)`, called in `_cut_trunk_release` between
   `found = commit_items(...)` (`asf/metrics/metrics.py:999`) and `tag = tags_at(...)` (`:1086`).
   On a refusal it prints `release: not cutting a tag at <sha7> — <why>` to stderr and returns
   `None` — which the rollup already treats as "nothing new", so the next one retries.
2. The install half: `release.ci_runs(slug, product.main, 1, gh_json)` for the finished run at
   `sha` (`asf/release.py:220`), then `release.ci_steps` (`:231`) and
   `release.step_state(steps, cfg['ci_steps']['install_from_zero'])` (`:240`, default `'install.sh'`
   at `:43`). Not found ⇒ refuse, `"the install-from-zero step did not run"`. Found and not green
   ⇒ refuse, naming it. A product with no CI provider, or an empty `ci_steps.install_from_zero`,
   skips this half — it has no forge to ask, and nothing about its release path changes.
3. The docs half: `docs.check_at(product.repo_dir, sha, conv)`; any complaint ⇒ refuse with the
   first three and the count.
4. The forge not answering at all is **not** a refusal to cut — it is `"could not read CI"`, the
   same `None` return, and the same retry next rollup. A tag is never cut on an unread gate, and a
   network blip never fails a release permanently. `check_at` returning `None` (an unreadable
   tree) is read the same way.
5. An already-tagged sha (`tags_at(repo, new)[0]`) is not re-gated: the tag exists, and the gate's
   job is to stop a new one.
6. Nothing downstream of `cut_tag` changes — the note, the tag, the GitHub Release with its pinned
   install line and `sync_changelog` are untouched (§1.2, P1).
7. `.github/workflows/tests.yml`, after the `check generic` step (`:31-32`):
   `- name: the docs check (pages, links, anchors, doctor rows, commands, config keys)` /
   `run: asf docs check`; and
   `- name: install.sh into a temp HOME against the sample product` /
   `run: python3 -m unittest -v tests.test_quickstart`. The second exists because P3 does not hold
   — the workflow has no step matching `install_from_zero` today (PD16) — and when F-0107's Story
   11 lands `tests/test_install_e2e.InstallFromZeroTests` that step's **body** becomes it and its
   name does not change. The gate reads the name, so the swap is invisible to this card.
8. `ReleaseGateTests` as §3 gives it, including the `ci: {provider: none}` case and the
   already-tagged case.

**Gate**

```sh
python3 -m unittest -v tests.test_metrics tests.test_release
asf docs check
bash tools/check_conventions.sh && bash tools/check_generic.sh
python3 tools/run_tests.py 2>&1 | tail -3
```

**Acceptance**

```bash
python3 -m unittest -v tests.test_metrics.ReleaseGateTests
```

```bash
python3 tools/run_tests.py
```
