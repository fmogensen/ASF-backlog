## Description
stories: S-15605
writes: asf/workers/lifecycle.py, tests/test_lifecycle.py

§2.3's first half. Triage's third cause and the tick's `between` pair both read facts that exist
only on the runs; this Task is where they become readable.

**Files**

- `asf/workers/lifecycle.py` — `Round`, `round_log(path)`, and `hold(path, run, kind, text, now,
  files=())`.
- `tests/test_lifecycle.py` — `RoundLogTests`.

**Steps**

1. `Round = collections.namedtuple('Round', 'n kind text files at job brief_kind')`.
2. `round_log(path)` → `{item: [Round, ...]}` in `started` order over every run of the item
   (`runs(path)` flattened, never `latest`): each run's `correction` is one Round, `n` its position
   in the item's list from 1, `kind`/`text`/`at` off the correction, `files` off
   `correction.get('files') or ()`, `job` and `brief_kind` off the run. A run with no correction
   contributes none. Reads the ledger and nothing else — no clock, no git.
3. `hold(..., files=())` puts `files` on the correction dict (both branches: the ordinary round and
   the `at_cap` one), as a list, and changes not one word of the two lines it returns. Every
   existing caller passes no `files` and gets today's behaviour byte for byte.
4. `corrections(path)` needs no change — it already passes the whole correction dict through
   (`dict(corr, rounds=…, branch=…)`, `lifecycle.py:301-313`), so `files` reaches the feeder.
   Assert that in the test rather than trusting the read.
5. Tests: three holds on one item across two jobs → three `Round`s in `started` order with their
   kinds, texts and files; `hold(..., files=['a.py'])` puts them on the correction; `corrections()`
   carries them through; an item with no correction is absent from `round_log`.
