**S-92305 — a ruling's `superseded_by:` retires the item, and only against a closed successor.**

```bash
python3 -m unittest tests.test_apply_rulings.SupersedeTests tests.test_retire -v
```

Asserts, on the `WidenStepBase`-shaped record fixture: an ended `adjudicate` run whose REPORT
carries `superseded_by: T-0002` where `T-0002` is `Closed` leaves `T-0001` carrying `removed:`
(opening with `retired: `, as `retire.removal` builds it) and `superseded_by: T-0002`, both written
in one commit whose subject names the item and whose `--name-only` is that one card; that `T-0002`
gains `supersedes: [T-0001]` in a second commit of that card alone, and that an existing
`supersedes:` entry on it is kept and the new id merged in sorted order
(`sorted(set(existing) | {item})`, D-0002); that `conflicts.supersession_findings` over the record
afterwards is **empty**, where it reports one finding when only the item's half is written (P13);
that **two rulings in one pass against one successor** — two runs, each declaring
`superseded_by: T-0002` for a different item — leave `T-0002` carrying *both* ids in `supersedes:`
and `supersession_findings` empty over both pairs, the case C2 found the once-loaded `canonical`
dropping the first id of; that a third ruling in that same pass declaring the reciprocal edge
(`T-0002 superseded_by T-0001`, after `T-0001` was retired against `T-0002`) is **refused** by the
cycle clause, which can only see that edge because the item's half was mirrored into `canonical`
too — and that it is refused **also when the successor's own write failed**, which is the case that
pins the mirror to the line after the item's write rather than to the end of the pair;
that **a second ruling declaring a pair the record already carries** — a different job naming the
same successor for the same item, the T-0353 shape of one decision ruled three times — writes
**nothing**: no card write, no commit, no History line, both cards byte-identical, the run still
marked `outcome_read`, and one line naming the already-applied clause, so the `removed:` reason the
card keeps is the deciding ruling's words and not the last session's; that **a second ruling naming
a different closed successor** (`T-0003`, also `Closed`) is **refused** with both cards
byte-identical, one line naming the successor the item already carries, and
`conflicts.supersession_findings` **empty** afterwards — asserted as a pair with the un-gated
behaviour it replaces, since the cycle clause cannot see this case (two distinct successors close no
ring) and the un-gated applier files exactly the finding D-0002 exists to prevent, on a card it has
already retired; that a successor present in `items` but absent from `canonical` — the two shapes
disagreeing, a card renamed or unparseable since the index was built — refuses **that one ruling**
with a line, and the pass still applies the next ruling in the same tick rather than losing them
all to the `apply()` wrapper's `except`;
that `apply()` with `items=None` (no index to read, `health.record_items`' own return)
applies nothing, prints one line, raises no `TypeError`, and leaves every run unmarked so the next
tick retries (I2);
that one History line was appended to each card and it names the field, the counterpart and the
job; that `feeder_rows.candidates` then returns **no** row for the item where it returned one
before (P4); that the same run is not read a second time (`outcome_read`, D-0009) and a second tick
writes nothing; that a successor which is `Resolved` or `removed:` passes the gate too and one
which is `Active`, absent from the index, or the item's own id does **not**; that a `superseded_by:`
whose edge would close a supersession ring — `T-0002` already `superseded_by: T-0001` — is refused
with both cards byte-identical and the ring named in the line (D-0001, the clause `groom.py:368-371`
applies to the same write); in each refused case the card is byte-identical afterwards, the run is
marked, the item keeps its row, and one line names the clause that failed; that a `superseded_by:`
of `none` is no claim at all; that the `items` dict the pass was handed carries the item's
`removed:` and `superseded_by:` **after** `apply()` returns, and that
`widen_footprint.report_facts` run over that same dict in the same step then builds nothing for the
retired item — no `writes:` update and no relaunch correction on a removed card (C5, the
write-back `rejudge.take_no_split:144-145` makes for the same reason); that an I3 refusal of an
applied ruling prints `INVARIANT I3: ruling refused …` and not `widen refused …`, so the Bug the
tick files names the applier (D-0008); and that `tests/test_retire.py` passes unchanged —
`retire.removal` is called, not altered.

**S-92306 — a ruling's `blocked_on:` becomes a visible wait.**

```bash
python3 -m unittest tests.test_apply_rulings.BlockedOnTests -v
```

Asserts: an `adjudicate` run declaring `blocked_on: T-0002` gives `T-0001` `after: [T-0002]` with
one History line and one commit; that `feeder_rows.candidates` then shows `WAITS ON T-0002` for it
rather than a launch, and **not** zero rows (D-0003, P4 — the assertion is on the row being present
and waiting, which is what distinguishes `after:` from `blockedBy:`); that an existing `after:`
entry is kept and the new id appended once, idempotently; that `blocked_on:` naming the item
itself, an id the index does not hold, or an id that already reaches the item through `after:` is
refused with the card unchanged and the cycle named; and that a `blocked_on:` on a `coder` or
`correct` run is ignored (D-0005).

**S-92307 — a ruling's `writes:` replaces the footprint, or is refused by the record.**

```bash
python3 -m unittest tests.test_apply_rulings.FootprintTests tests.test_widen -v
```

Asserts: an `adjudicate` run declaring `writes: src/a.py lib/shared.py` writes exactly that list
onto the card, in that order, with one History line and one commit; that a `writes:` the record
stage's I3 refuses leaves the card byte-identical and prints the owner `refused_by` names, the run
marked so it is not retried blind; that a `writes:` of `none` is no claim; that the globs are taken
from `ruling_fields` (whitespace-split, as the parser gives them) and not re-parsed; that the field
is ignored on a non-`adjudicate` run (D-0005); and that `tests/test_widen.py` passes whole — the
widening rule's own writes are untouched by the new writer sharing `write_card` with it.
