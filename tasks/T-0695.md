The spec's §1 and §2: a `STUCK` class in `push_cause`'s vocabulary, and the leased tip carried across
`_repair_naming`'s two attempts so the second push is never made over a sha the pass has just proved
unmoved. Two pushes become one; two lines that state false things become none.

This Task lands no memo and no routing. A `'stuck'` falls to the existing `else` at `:2051-2053` and
logs `deferred — the push was refused (stuck: <why>); trees identical, no session — the next pass
tries again`, which is still one line a pass — Task 2 is what stops the repetition. That is
deliberate: this Task is the half that can be proved by counting pushes, and it is provable alone.

**PD8** (both lease-race tests survive, and why) and the shared fence block above.
