## Description
stories: S-33750
writes: asf/surface.py, tests/test_surface.py
after: none

§2.1 and §2.2, and nothing else. A pure data module with no caller: `build_parser` does not read it
until Task 5, so this Task cannot break a single command, and the whole of it is a dict in and a
`self.assert*` out.

The table is written here with the **new** names — `import-items`, `board`, `stories` — which is
why it must not be wired up yet (PD5). Until Task 5 it is a document with a test; from Task 5 it is
the surface.

**Files**

- `asf/surface.py` — new: the module docstring §2.1 writes, `RECORD`, `REPO`, `HOST`, `PRS`,
  `VERBS`, `COMMANDS` (49 rows), `RENAMED`, `SurfaceError`, `marker`, `apply`
- `tests/test_surface.py` — new module; `TableTests`

**Steps**

1. `asf/surface.py`, opening with §2.1's docstring copied as it stands. No import from the rest of
   `asf` — not `env`, not `conventions`, not `cli` — so `build_parser` can import it with no cycle;
   `TableTests` asserts that with `ast.parse` over the module's own source.
2. The four effect constants with §2.1's inline comments byte for byte, `PRS` included even though
   no row uses it today (PD12b): it is one of D9's four targets, and a target a row can reach for is
   cheaper than a fifth constant invented later.
3. `VERBS`: §2.1's 25 words plus `derive`, `install` and `rebuild` (PD10), one alphabetical
   frozenset, with a comment saying a verb enters by editing this line and never by loosening the
   check.
4. `COMMANDS`: all 49 rows of §2.2, in §2.2's order, as `(description, effect, flag)` — the
   description byte for byte from the table's middle column, the effect and the flag read off its
   right column (`—` → `(None, None)`, `[writes X]` → `(X, None)`, `[writes X with Y]` →
   `(X, 'Y')`). No row carries a `[writes` substring: the marker is rendered, never typed (§2.6
   check 5).
5. `marker(effect, flag)` copied from §2.1 byte for byte, docstring included.
6. `RENAMED = {'migrate': 'import-items', 'backlog': 'board', 'parity': 'stories'}`, with the
   comment §2.1 writes. Nothing reads it until Task 4.
7. `SurfaceError(Exception)` and `apply(sub)` exactly as §2.3 writes them — the function lands here,
   with its docstring, and stays uncalled until Task 5. Landing it now keeps §2.3's seam in one
   module and keeps Task 5 to its own file's one call.
8. `tests/test_surface.py`, new, with `TableTests` (PD13): 49 rows; every value a 3-tuple; every
   effect `None` or one of the four constants; every flag `None` or a non-empty string; no
   duplicate key; no description containing `[writes`; `VERBS` a frozenset of lowercase alphabetic
   words; every `RENAMED` value a key of `COMMANDS` and no `RENAMED` key one; `marker` rendering
   each of the three shapes (`''`, `' [writes the record]'`, `' [writes this host with --write]'`);
   and the module importing nothing from `asf`.
9. No test in this Task touches `build_parser`. Coverage, voice and internals are Task 5's, and a
   test of them here would be red until the renames land.
