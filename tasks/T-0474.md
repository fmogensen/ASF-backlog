## Description
stories: S-33654
writes: tests/test_adopt_pr.py
after: Task 4

The card's second named test, both halves, and the spec's Out line that `adopt-pr` merges nothing:
every check, approval, order and cap is the ordinary lane's (P19, P20). **This Task writes no
production code, and that is the Story** (PD7) — if it needed any, the claim that native landing
drains the queue unchanged would be false. It is the one place the whole chain runs end to end: the
command writes the line, the lane takes the branch up under a foreign name, the product's own review
form approves it, the product's own checks go green, and a real merge lands on origin's main.

**Files**

- `tests/test_adopt_pr.py` — `AdoptedQueueDrainsTests`

**Steps**

1. The fixture is `ProductHarvestTests`' (P25, D15): a real bare origin and worker clone, `pr_product`
   (already `reviews_dir: .in/reviews` and `steps: {batch: 'bash q.sh'}`, so landing is
   pull-request), and `fake_gh` / `fake_gh_prs` patching `harvest._gh` so `pr list`, `pr checks` and
   `pr merge` are answered and the merge really lands on origin's main. The product also declares the
   card's `legacy_review`: `{glob: '{reviews_dir}/{slug}-r{n}.md', verdict_regex: '\(APPROVED\)'}`.
2. **The card's second test, first half.** A branch under a foreign name (`bugfix/inv-77-pdf`), whose
   commits name no card, with an open PR and a `.in/reviews/b-0044-r1.md` on it reading
   `Looks fine (APPROVED)`. `asf adopt-pr <n> --product sample` writes the line; one harvest pass with
   green checks merges it, and the assertions are: the PR was merged through the host, origin's main
   carries the branch's commit, the run's lane state is `MERGED`, and `harvested` names the sha.
3. **The card's second test, second half.** The same branch with **no** review file waits: the lane
   is `REVIEW` or `WAITING` and never `BACK`, nothing is merged, no correction is written, and a
   later pass after the review file appears merges it — the same run, no new line.
4. A review file present but **not matching** `verdict_regex` waits too, with `changes` as its
   verdict and a `WAITING` reason ending `no session — the PR author answers on the PR` (D8 + D6),
   and still merges once the marker is added.
5. **The product's own gate is unchanged**, asserted rather than assumed: a red required check holds
   the PR at `WAITING_CI`/`GATE` exactly as it holds an ASF branch; `pr_order` and
   `conventions.branches_per_tick` cap an adopted queue the same way — five adopted PRs with
   `branches_per_tick: 2` land two, then two, then one, each in `pr_order`'s order, with the visit
   stamp so none starves (P19); and under `conventions.merge: manual` with an approval level set, an
   approved green adopted PR is `WAITING` for the person and not merged (P20).
6. **Costs nothing**: across all of the above, `occupancy` counts no seat for an adopted run and the
   feeder's capacity is unchanged (P4) — one case asserts it directly, since that is what lets an
   operator adopt twenty PRs without stalling the factory.
7. One case walks the operator's own sequence in order, as the guide will describe it (Task 7):
   `--all '<glob>' --dry-run`, then without it, then two harvest passes, then the queue is empty —
   so the page Task 7 writes is describing a sequence this suite actually runs.
