§2.1 and §2.2. The module and its two data classes, the config readers and their problem lists,
the one function that runs a probe, and the arithmetic that turns a result into a verdict. No CLI,
no cache, no table, no tick wiring — nothing in this Task has a caller outside its own tests, and
that is intentional: it is the surface Tasks 2, 4, 5 and 6 are written against.

**Files**

- `asf/credentials.py` — **new**. Module docstring: what a provider is, that a probe is read-only
  and never prints a token, and that its contract is the rule contract. Then:
  - `PROBE_TIMEOUT_S = 20`, read through a `_timeout()` helper so `$ASF_CREDENTIAL_PROBE_TIMEOUT`
    overrides it, in the shape `asf/rules/rules.py:28-38` already uses (a bad value falls back to
    the default rather than raising at import). `DEFAULT_WINDOW_DAYS = 3`,
    `DEFAULT_PROBE_EVERY = '1h'`, `DETAIL_MAX = 160`.
  - `Provider` and `Result`, frozen dataclasses, exactly the fields §2.1 gives them —
    `Provider(name, probe, renew, account='', window_days=DEFAULT_WINDOW_DAYS)` and
    `Result(provider, state, expires='', detail='', probed_at='')`. `Result.state` is one of
    `'valid' | 'invalid' | 'broken'`; a `STATES` tuple names them so no string is typed twice.
  - `providers(cfg)` → `{name: Provider}` from `cfg`'s `credentials.providers` map, each provider
    taking `window_days` from its own entry else `credentials.window_days` else
    `DEFAULT_WINDOW_DAYS`. A missing or misshapen `credentials:` section is `{}`, never a raise:
    the problem list is where a bad section is reported, and the doctor is what reports it.
  - `probe_every(cfg)` → seconds, from `credentials.probe_every` through `_seconds('<n>s|m|h|d')`;
    an unparseable value falls back to `DEFAULT_PROBE_EVERY` and is named by `config_problems`.
  - `config_problems(cfg)` → `[(dotted key, problem)]`, every problem §2.1 lists: a provider with
    no `probe:`, one with no `renew:`, a `window_days` that is not a positive integer, a
    `probe_every` that is not `<n>s|m|h|d`, an `account:` that `pool.accounts_from_config(cfg)`
    does not name, and a `renew:` that `redact.default_patterns(None)` matches, reported as
    `credentials.providers.<name>.renew: carries a secret-shaped value — put the secret in a file`
    (§2.4's last bullet, byte for byte). Sorted by dotted key, so the doctor's row is stable.
  - `product_problems(value)` → `[(dotted key, problem)]` for a product file's `credentials:`
    value: not a list, an entry that is not a non-empty string, or a duplicate name. `None` is no
    problem — a product that names none is a product with nothing to check.
  - `for_product(product, cfg)` → the `Provider`s the product names, in the product's own order.
    A name `credentials.providers` does not define raises `env.ConfigError` with exactly
    `product.yaml credentials: <name> is not a provider in config.yaml credentials.providers`.
  - `probe_env(provider, cfg, product)` → the environment the probe runs under (D5, PD13). With
    `provider.account`: the account of that name out of `pool.accounts_from_config(cfg)` and a
    synthetic `runtime.Job(product.name, 'credential-probe', product.repo_dir, None, None,
    account=acct, product_auth_env=env.product_auth_env(product))` through `runtime.build_env`.
    Without one: `hermetic.worker_base()`. Either way `GIT_TERMINAL_PROMPT=0` is set last, so a
    credential the session cannot reach fails at once instead of hanging on a prompt.
    `runtime.AuthEnvError` propagates — `run_probe` is what turns it into a `broken` result.
  - `run_probe(provider, env_map, now, run=subprocess.run)` → `Result`. The command is
    `shlex.split(provider.probe)`, run with `env=env_map`, `capture_output=True`, `text=True`,
