**Steps**

1. `asf/record/check.py`: one finding class per schema error, reported at the card and the field's
   line, and one for a card whose JSON does not parse. `record_findings` (`:206`) already exits
   non-zero through `cmd_check`'s `return 1 if findings else 0` (`:196`), so the exit codes come
   free: non-zero when any card is invalid, zero when they are all valid.
2. `--schema-only`: a new flag on the existing `check` parser (`asf/cli.py:329-338`, which has
   `paths`, `--product`, `--staged`, `--invariants` and `--deep` and no such flag) reporting the
   schema and reference findings and nothing else. It is a **flag**, not a root argument: the root
   is `cli.resolve_record`'s and the positional paths are a filter inside it (K7).
3. The record pre-commit needs **nothing**: it runs `asf check --staged` already
   (`asf/hooks.py:308`'s `STAGED_CHECK_LINE`, written by `asf/init.py:268` and kept current by
   `hooks.ensure_git_hooks`), over the staged tree — so a hand edit and another tool are refused
   the day this finding class lands (P6, D-0016). Assert it rather than change it: the staged check
   judges the cards as the commit stages them and not the working tree, refuses a commit staging an
   invalid card, **passes** a commit staging a valid card beside an invalid one already on the
   record, and still derives the index and the views as it does today.
4. `asf/init.py`: `put('.github/workflows/record-check.yml', …)` beside the hooks it already
   writes (`:267-270`) — install the pinned `asf`, run the schema-only check, write nothing.
   Idempotence and "never overwrite a person's edit" are free: `put` returns early when the path
   exists (`:254-257`). So writing it twice leaves one file, unchanged.
5. `asf/doctor.py`: one row saying whether the record's CI workflow is in place, in the shape the
   other rows have.
6. Create `tests/test_card_enforcement.py` for S-133163's fifteen lines, and extend
   `tests/test_check_staged.py` — green at this base but **slow** (over ten minutes), which is why
   this Gate runs it alone in its own process (K5). The CI workflow case asserts the file runs the
   schema-only check and nothing that writes.
