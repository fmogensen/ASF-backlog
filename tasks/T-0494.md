**Steps**

1. `step_start_line(step, owner, pid=None, at=None)` beside `step_end_line`, with the spec's
   docstring and body byte for byte (`## The design` §`asf/tick/tick.py`):
   `f'[step:{step}] start owner={owner} pid={pid or os.getpid()} at={at or _stamp()}'`. `os` is
   already imported (`:35`) and `_stamp()` (`:152-153`) is the tick's own UTC stamp,
   `%Y-%m-%dT%H:%M:%SZ` — the format Task 2 parses. The `pid=` and `at=` arguments exist so a test
   can pin the whole line (D2, D4).
2. `step_timing_line` → `step_end_line(step, seconds, ok=True, owner='asf', pid=None, at=None)`
   (D12), with the spec's docstring byte for byte, returning
   `f'[step:{step}] {seconds:.1f}s ok={"yes" if ok else "no"} owner={owner} pid={pid or os.getpid()} at={at or _stamp()}'`.
   The `[step:<name>] <seconds>s` prefix is unchanged to the byte — that is D1, and it is what keeps
   the blast radius at three lines instead of twelve. The rename is safe: the whole tree holds exactly
   two references, `asf/tick/tick.py:476` and `tests/test_tick.py:772` (PD12), and no compatibility
   alias is left behind.
3. In `_run_steps`, the start line at the **two** points a step actually begins (D11, P3), never one
   above the guards:
   - the `asf` branch — `print(step_start_line(step, owner), flush=True)` as its first statement,
     before `run_asf_step(step, ctx)` (`:443-444`);
   - the command branch — inside `with locks.command(step) as free:` **after** the
     `if not free: … continue` guard (`:466-469`), with the spec's two comment lines byte for byte.
     A start line above the guard would name a step the tick then skipped, and Task 2 would report it
     as running.
4. The end-line print becomes
   `print(step_end_line(step, ran[-1]['seconds'], ok=not step_rc, owner=owner), flush=True)` (`:476`).
   `flush=True` is new on this line (PD9) and `owner` is the loop variable, which `resolve` has
   already narrowed to `asf` or `command` by the time the body runs (P2, verified: `off` is
   `continue`d at `:436-438`).
5. Nothing else in the loop moves: the `off` line, `tick: step daily already ran today`, the

   are. `timed()` and every `[record:<part>]` line are untouched (P15), and so are `run_shadow` and
   `dry_run.run`, which never enter `_run_steps` (P17).
