§2.4. The gate exists after Task 2 and nothing calls it; this Task is the four edits that make the
runtime call it, and the doctor row that notices when an account's settings file lost it. §1.4's
row is the whole argument for the shape: a rule card's `hook: [Stop]` lands in a product repo's
`.claude/settings.json` and so binds only sessions in a product repo that carries the card, where
the gate binds every factory session — which is exactly the case F-0031 §2.3 PD5 made for
`approvals`, so it rides the same line in `install`.

**Files**

- `asf/hooks.py` — `BUILTIN` (`:59`), `cmd_hook` (`:448-455`), `install`'s per-account write
  (`:378-380`) and its summary line (`:396-397`), `gate_missing`, and the module docstring
- `asf/doctor.py` — `check_unpushed_gate`, the `unpushed-gate` row beside `approvals-hook`
  (`:835-836`), and the docstring's row inventory (`:21-22`)
- `tests/test_install.py` — `StopGateInstallTests`
- `tests/test_doctor.py` — `UnpushedGateRowTests`

**Steps**

1. `asf/hooks.py`: `BUILTIN = {'approvals': ('PreToolUse',), 'unpushed': ('Stop',)}`, byte for byte
   as §2.4 writes it. The `#:` comment above it (`:57-58`) already says a built-in name shadows a
   script of the same name and needs no change.
2. `cmd_hook` dispatches on the name, §2.4's body byte for byte: `approvals` →
   `approvals.run_hook(sys.stdin.read(), os.environ, product=args.product)`, `unpushed` →
   `stopgate.run_hook(sys.stdin.read(), os.environ, product=args.product)`, then the check-script
   fallback unchanged. Both imports stay local, for the reason the current comment gives
   (`:450`) and because `asf.workers.stopgate` must not be imported to run an unrelated hook.
   Update the `hook` subparser's help (`:463-464`) to name both built-ins, and the module
   docstring's last paragraph (`:25-27`) likewise.
3. `install`'s per-account loop becomes
   `_write_merged(account_settings_path(account), [('PreToolUse', 'approvals'), ('Stop', 'unpushed')], asf_path, None)`
   — one call, both entries, product-less. `merge` needs no change: `if event != 'Stop'` (`:328`)
   already omits `matcher` for a `Stop` entry, and `_is_ours` with `product=None` (`:309`) already
   matches a command with no `--product` tail. The summary line (`:396-397`) becomes
   `approvals and the unpushed gate in {len(accounts)} worker accounts`. Everything else in
   `install` — the refusal ordering that writes every hook it can before refusing anything, the
   git hooks, the rule hooks — is untouched: §1.3 and F-0031 §2.4's rule that one refusal never
   skips another hook is load-bearing here, because the gate must reach the accounts even when a
   foreign git hook refuses the call.
4. `gate_missing(accounts, repo_dir=None)`, modelled on `approvals_missing` (`:403-419`) line for
   line, with `'Stop'` for `'PreToolUse'` and `'unpushed'` for `'approvals'`: the accounts whose
   sessions would run with no gate, an unreadable settings file counting as one without it. Write it
   as its own function rather than parameterising `approvals_missing` — the doctor rows read
   differently, the two hooks' events differ, and a shared helper with two flags would be harder to
   read than fifteen duplicated lines. Place it directly below `approvals_missing`.
5. `asf/doctor.py`: `check_unpushed_gate(cfg, product)` built the way `check_approvals_hook` is

   (`asf hooks install --product <p>`). Green reads
   `unpushed gate in <n> worker accounts`.
