**Steps**

1. `questions.record(plan, now, intake=None)` keeps every key it writes and gains `left_by`, a
   `{class: n}` map folded off **the same comprehension** `console` is built from, so
   `sum(left_by.values()) == left` is a property of the code (**PD13**):
   `collections.Counter(classify(st.reason) for iid, (s, st) in plan.states.items() if s is
   State.STUCK and st is not None and st.owner == 'operator')`. A tick that leaves nothing writes
   no `left_by` and no record at all, exactly as today.
2. `share(records, since)` gains `left_by` to its return, folded the way `by` already is — a
   `Counter` updated over the window's rows. A record written before this release has no
   `left_by`, and `r.get('left_by') or {}` folds it as none: the fold is additive and an old
   ledger is not a crash, the rule `intake` already follows.
3. `render_left(win)` → the second table, ordered by count with the most frequent first and the
   class's share of what was left, in the shape §2.8 prints:
   `| left to the console | n | share of left |`. A window that left nothing returns `''` and
   `questions()` prints the share line alone.
4. `questions(product, …)` prints `render_left(win)` under `render_share(win)` when the window
   left anything. `--classify`'s existing table is untouched, and so is `render_share`'s one line.
5. Nothing touches `gate.console_row`, `questions.share`'s `resolved`/`left`/`share` keys,
   `CONSOLE_SHARE_MIN` or the window: the `console share` row is this Feature's measure, not part
   of its build (§1.1 Out), and the test asserts the figure the row reads is unchanged by all of
   the above.
6. Create `tests/kernel/test_question_kinds_left.py`, one case per acceptance line of S-205274,
   and beyond them: the identity `sum(left_by.values()) == left` over a tick leaving three Stucks
   of two classes (step 1); a ledger of mixed old and new records folded without error (step 2);
   and the table's order for a tie on count (by count, then by class name, as `classes()` already
   orders).
