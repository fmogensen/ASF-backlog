## Description
stories: S-32703, S-32702
writes: asf/hooks.py, asf/init.py, tests/test_hook_chain.py
after: Task 1

The spec's fourth, seventh and eighth **In** bullets and its `## The design`'s parser block: the
command the operator types. `uninstall` puts a chained hook's original back and refuses to touch
anything this installer did not write; the parser gains a second `hooks_command` and the
`--chain` / `--no-chain` pair, chaining by default; `asf init` chains, and the spawn gate does not.

**Files**

- `asf/hooks.py` — `uninstall(product, cfg=None)`; `install(…, chain=True)`; `cmd_hooks` dispatch;
  `register`'s `hooks_command` choices and mutually exclusive group
- `asf/init.py` — one line: `ensure_git_hooks(product, chain=True)` at `:317`
- `tests/test_hook_chain.py` — `UninstallRestoresTests` (new class), and the CLI case appended to
  `ChainingIsNeverUnattendedTests` (PD3)

**Steps**

1. `uninstall(product, cfg=None)` → `(rc, message)`, with the spec's docstring. Per repo in
   `[r for r in (product.repo_dir, product.backlog_dir) if r]`, per name in `GIT_HOOK_NAMES`,
   against `git_hooks_dir(repo)`: a hook file carrying `HOOK_MARKER` is this installer's — when
   `chained_local(text, name)` names a `.local` that is there, `os.replace` moves it back over the
   hook (the original's own bytes and mode, one atomic call, counted `restored`); otherwise the
   hook is removed (counted `removed`). Anything else is left **byte for byte** and named in the
   message. `cfg` exists only so the account count is real in a test (PD8).
2. What "anything else" covers, each with its own case: the operator's own hook, an `asf init` hook
   (`asf.init.INIT_MARKER`), and a hand-merged hook carrying the gate line but not the marker. The
   marker and not `is_git_hook_ours` is the test (D6) — the loose recogniser is true of the last
   two, and removing either would delete work ASF did not write.
3. The message: `hooks uninstall: <n> restored, <m> removed in <k> repos`, then the line saying the
   worker accounts' `approvals` hook is deliberately left in place — it is the guard over human-now
   actions and this command never removes it (Out) — with the account count from
   `pool.accounts_from_config(cfg or env.load_config())`, then one `<path> is not asf hooks
   install's — left as it is` line per hook left alone. `rc` is 0 whenever every hook this
   installer wrote is gone, which includes having had nothing to do; a hook left alone is reported,
   not a failure, and is never a `NEEDS OPERATOR` — there is nothing for a human to decide.
4. A missing hooks directory, a `repo` that is not a git repo, and a hooks directory with no hooks
   at all are each `rc` 0 with nothing done; the not-a-git-repo case says so in one line, as
   `ensure_git_hooks` does.
5. `install(product, rules_dir=RULES_DIR, which=shutil.which, cfg=None, chain=True)` passes `chain`
   straight to `ensure_git_hooks` at `asf/hooks.py:382`. The CLI default and the function default
   agree, so `tools/install.sh:146` chains with no edit (PD14). Nothing else in `install` moves —
   the approvals hook is still written before anything is refused.
6. The parser (`asf/hooks.py:459-463`): `choices=['install', 'uninstall']`, and the mutually
   exclusive group the spec writes, `--chain` storing true by default and `--no-chain` storing
   false, with the spec's two help strings. `--chain` is a no-op the card names so the operator can
   write what they mean.
7. `cmd_hooks` stops ignoring `args.hooks_command` (P5): `uninstall` dispatches to `uninstall(product)`,
   anything else to `install(product, chain=args.chain)`; the print and the return are as they are.
8. `asf/init.py:317` becomes `hooks_mod.ensure_git_hooks(product, chain=True)` (D5). Its printed
   line — `init: git hooks in place | NOT installed — <detail>` — now carries the `chained <path> →
   <path>.local` clause Task 1's detail adds, which is the whole of the Records table's `asf init`
   row. `asf/workers/spawn.py` is not touche
