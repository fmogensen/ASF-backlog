The spec's eighth and ninth **In** bullets (D8, D9) and its `## The design` §5. The report already
declares the question (P13) and the feeder already has a park (P14); what is missing is the one
branch in health that reads the first and writes the second, and the one that lets it go.

**Files**

- `asf/workers/lifecycle.py` — `BLOCKED`, `card_fingerprint`, `blocked_park_text`, `blocked_park`
- `asf/workers/health.py` — the park branch in `ended`'s `steps`, and the release beside the
  closed-state release at `:597-601`
- `tests/test_lifecycle.py` — `blocked_park` and `card_fingerprint`'s own cases
- `tests/test_workers.py` — `ABlockedRunIsParkedUntilTheCardChanges` (new class)

**Steps**

1. `BLOCKED = 'blocked'` beside `UNPUSHED`, `EMPTY`, `NAMING`, `COPIES` and `INCOMPLETE`
   (`asf/workers/lifecycle.py:1859-1877`), with the spec's comment. It is **not** added to
   `MECHANICAL`: a mechanical hold goes back to a session with no round, and the whole point of this
   kind is that no session is launched.
2. `card_fingerprint(product, item_id, items)` — the spec's `card_fingerprint`, implemented as a
   delegate to `asf.briefs.build.card_digest` (PD4): `''` for a falsy `item_id` or a `None` `items`,
   else `build.card_digest(product, item_id, items)`. The import is inside the function, as
   `step_wave.stale_briefs` does it (`asf/tick/step_wave.py:233`), because `asf.briefs.build` imports
   `asf.feeder.rows` and lifecycle is below both. Its docstring says what PD4 says: the digest is the
   one a brief is already cut from, `## History`, the machine block, `state`, `evidence`, `stage_since`
   and `updated` are outside it by `DIGEST_FIELDS`' own rule, and a park that lifted on those would be
   no park at all (D9). `card_digest` passes `items` through `feeder_rows.items_of`, which accepts a
   loaded `{id: card}` map as well as an `index.json` dict (`asf/feeder/rows.py:209-215`) — so
   health's `record_items` output is a valid argument — and drops removed cards, which is harmless
   here because a removed card is released a step earlier by `closed_state` (P15).
3. `blocked_park_text(question, item)` and `blocked_park(question, item, card, now)` exactly as the
   spec writes them: the text quotes the question, names the RESHAPE → PLAN session as the re-cut
   that lifts it, and names `asf unpark <item>`; the fields are
   `{'correction': {'kind': BLOCKED, 'text': question, 'at': now, 'parked': True, 'reason': blocked_park_text(...), 'card': card}, 'operator_flagged': 1}`
   and the line is `f'parked {branch}: {reason}'`, the shape every other park in `hold` prints
   (`:1961,1967,1988`). `blocked_park` is a function of its own and not a branch of `hold`, because
   `hold` spends a round and counts findings and this spends neither.
4. `health.ended`'s `steps`: after `reason` is settled and `found.append((job, 'ended', reason))`,
   compute `question = report_mod.needs_input(str((ev.result or {}).get('result') or ''))` once, and
   add the park as a **fourth** branch of the existing chain — after `if retry:` and after
   `elif reason == f'failed: {lifecycle.EMPTY_BRANCH}' and lifecycle.landed_earlier(registry, s):`,
   in front of the `UNPUSHED` hold and the bare empty-branch hold, guarded by
   `question and (reason.startswith(UNPUSHED_REASON_PREFIXES) or reason == f'failed: {lifecycle.EMPTY_BRANCH}')`
   (PD6). It calls `lifecycle.blocked_park(question, s.get('item'), lifecycle.card_fingerprint(product, s.get('item'), items), now)`,
   `pool_mod.update_session(product, job, **fields)` and `found.append((job, 'parked', line))`.
   The `closed` early return above it (`:659-660`) still wins: a closed item's run is never parked.
