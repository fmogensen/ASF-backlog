## Description

The spec's **In** 3 and the `edge_candidate`/`publish` half of design §1 (D-0001, D-0004; P1, P7, P8, P9,
P10, P19). edge is an admission rule, not a promotion: the newest tag whose every landing check
succeeded, no ceremony and no wait. The whole weight of this Task is on what is **not** a
candidate — `clear` is not green, Unknown is not green, and a red tag is skipped rather than
stopping the scan.

**Read this Task from `docs/plans/f-0308.md`, not from this card** — the record cuts a Task card's
description at 4000 characters and this section is longer, so the card stops before the Acceptance.

**PD10** binds this Task: `upgrade.ci_verdict` already takes a `checks` argument and already
answers Unknown for a sha with no run, a pending check, an unreadable `gh` and a repo whose
product names no `landing_checks` — so this Task calls it and asserts its answers, and writes no
verdict logic of its own. **PD12** is the live-host consequence of that last case and is asked of
an operator below; it changes nothing this Task builds.

**Files**

- `asf/channels.py` — `edge_candidate(product, url, tags, run=subprocess.run, limit=None)` exactly
  as §1 gives it: `tags` newest-first, at most `limit or DEFAULTS['lookback_tags']` examined,
  `upgrade.ci_verdict` asked one tag at a time, returning at the **first** green with its detail,
  else `(None, None, '; '.join(seen))` so the report says what it is waiting for. And
  `publish(product, name, commit, run=subprocess.run, out=print)`: one
  `<commit>:refs/heads/releases/<name>` through `gitpush.push` (`:66`) with
  `guard=refguard.Guard(main=product.main, protected=refguard.listed(product.conventions))` and
  `refs_only=True` — the push carries no new code. A guard refusal, a dry run
  (`mutation_guard.is_active()`, `asf/gitpush.py:89`) and a non-fast-forward are each returned as
  `(False, detail)`, never raised. The non-fast-forward is left as git's refusal on purpose: it is
  the backstop for a candidate chosen from a stale log, and it is what keeps a head from moving
  backwards (D-0001).
- `tests/test_channels.py` — `FakeGh`, the `ci_verdict` answers per sha and per check name: green,
  red, pending, a `gh` failure, and a repo whose product names no landing checks. Then `EdgeTest`
  and `PublishTest`, one case per checkbox line of S-81205 — including the two the fence calls out
  by name, a tag with no run at all never reaching edge, and the dry run publishing nothing while
  saying what it would have pushed. The backwards case is asserted against a published head: a
  candidate older than it is not published, and the log is left as it was.

**Steps**

1. `edge_candidate` against `FakeGh`: the newest green first, then red-skips-to-older, then the
   three Unknown shapes, then the `lookback_tags` bound and the stop-at-first-green.
2. `publish` against an injected `run`: assert the refspec and `refs_only=True` on the call, not
   only the return.
3. The guard refusal and the dry run, each asserting that `git` never ran.
4. The backwards case and the log-unchanged-after-a-refused-push case.
5. The Gate, in the foreground.
