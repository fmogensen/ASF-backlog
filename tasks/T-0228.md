## Description
stories: S-29056
writes: asf/tokens.py, asf/workers/stall.py, asf/workers/runtime.py, asf/workers/lifecycle.py, tests/test_tokens.py, tests/test_lifecycle.py, tests/test_budget.py

§2.8's first half: there is no cap of any kind on a single run today, and `stall.capped` — the
only code in the package that ends a live run cleanly — has never had a caller. This Task gives it
the two run measures to judge beside the four token dimensions, and makes the record say which
cap ended the run. Task 5 gives it the caller.

**Files**

- `asf/tokens.py` — `Meter.turns`, counted and reset in `meter()` (`:77-130`); `TOKEN_CAP =
  'token cap'` beside `cap_text` (`:191`).
- `asf/workers/stall.py` — `elapsed_min(session, now)` and `capped()` judging the run measures
  (`:162-204`); the module docstring's sentence about what a capped run is recorded with (`:24`).
- `asf/workers/runtime.py` — `failure_reason` telling the two structured records apart
  (`:474-493`).
- `asf/workers/lifecycle.py` — `OUTCOME_CLASSES` gains both constants, before `OTHER` (P9).
- `tests/test_tokens.py` — the turn counter, the run-capped session, the `CAP` line.
- `tests/test_lifecycle.py` — `OutcomeClassTests`.
- `tests/test_budget.py` — `RunCapTests`' wired half, beside Task 1's pure half (P4).

**Steps**

1. `Meter.turns: int = 0`; `meter()` increments it on every `assistant` record and resets it to 0
   at each `system`/`init` boundary beside `result` and `by_dim` — the pass it already makes, one
   more counter. `DIMENSIONS` does not grow: `run_turns` is not a token dimension (§1.3).
2. `TOKEN_CAP = 'token cap'` in `asf/tokens.py`, beside `cap_text`; `runtime.failure_reason`'s
   literal at `:484` becomes that constant.
3. `stall.elapsed_min(session, now)` — the run's `started` to `now` in minutes, `None` when the
   ledger has no usable `started`.
4. `capped()`: `run_verdict = None if verdict else budget.run_over(elapsed_min(s, now), m.turns,
   budget.run_caps(conv))`, computed inside the existing guard, and `continue` when neither
   verdict holds or the pid is not this run's (P10). `conv` comes off the product's conventions,
   read once outside the loop.
5. The result line and the registry mark branch on which verdict fired: `tokens.cap_result(…)` and
   `capped={'dimension', 'tokens', 'limit', 'at'}` for a token dimension, `budget.run_cap_result(…)`
   and `capped={'measure', 'value', 'limit', 'at'}` for a run measure. `found.append((s['job'],
   measure, value, limit))` and the `CAP   <job>  <measure> <value> over <limit> (<kind>)<detail>`
   line are one shape for both.
6. Everything §2.8 says is unchanged stays so: a run that already has a result is never touched
   (`detail = ' finished first'`), a foreign pid is never signalled, `stop=False` judges only, a
   malformed `token_caps:` block still stops nothing, and `cap: none` still prints when nothing
   fired.
7. `runtime.failure_reason`: `asf.cap` → `tokens.TOKEN_CAP`, `asf.run_cap` → `budget.RUN_CAP`,
   both before any text is read — a session's own prose is forgeable and the factory's field is
   not (F-0028 D9). The docstring's first sentence names both.
8. `lifecycle.OUTCOME_CLASSES` gains `tokens.TOKEN_CAP` and `budget.RUN_CAP` **inserted before
   `OTHER`** (P9), so `outcome_class('failed: run cap')` is `run cap` and `outcome_class('failed:
   token cap')` is `token cap`, neither `other`. `FAILING_CLASSES` follows from the tuple and
   needs no change.
9. `tests/test_tokens.py`: `meter` counting turns per run and resetting them at an `init`
   boundary; `stall.capped` over a live session whose `started` is 4 hours ago stopping it,
   appending a result whose `asf.run_cap` names `run_minutes`, marking the registry line, and
   printing `CAP   <job>  run_minutes 240 over 180 (code)`; a run with a result untouched;
   `stop=False` judging only.
10. `tests/test_lifecycle.OutcomeClassTests`: both classes in `OUTCOME_CLASSES`, and
    `outcome_class` naming each rather than `other`.
