## Description
stories: S-18150
writes: asf/ci.py, tests/test_ci_class.py
after: none

§2.1, plus the reader PD4 gives a home to. Pure functions over plain lists: no filesystem, no
configuration, no product convention, and — PD8 — not one path literal, in code or in a docstring.

**Files**

- `asf/ci.py` — **new**: the module docstring (what a class is and what it is not: what a push
  *owes CI*, never what may *land* — §1.2's boundary against harvest's gate, named so the next
  reader does not fold the two), `FACTORY_ONLY`, `FULL`, `CLASSES`, `matches`, `classify`,
  `unmatched`, `globs_from_workflow`.
- `tests/test_ci_class.py` — **new**: §3.1's cases and `globs_from_workflow`'s.

**Steps**

1. `FACTORY_ONLY = 'FACTORY_ONLY'`, `FULL = 'FULL'`, `CLASSES = (FACTORY_ONLY, FULL)` — the two
   names in the order §2.1 fences them, and `CLASSES` as the tuple the mirror and any future
   caller read rather than writing the strings again.
2. `matches(path, globs)` — D6's rule, `fnmatch.fnmatchcase` over the repo-relative path, the
   base name when the glob carries no `/`. This is `asf/approvals.py:158`'s `_match_glob` by
   another name and deliberately so: one matching rule per repository. Do not import it from
   `approvals` — that module is the approval matrix's, and a classifier that imports it inherits
   its configuration reach; the four lines are copied with a comment naming the original as the
   rule's home.
3. `classify(paths, factory_only_globs)` — `FACTORY_ONLY` when `paths` is non-empty **and** every
   path matches; `FULL` for everything else, including an empty `paths` and an empty glob list
   (D5). No normalisation of `paths` beyond stripping a leading `./`: the caller passes
   repo-relative, forward-slash paths, which is what `git diff --name-only` prints.
4. `unmatched(paths, factory_only_globs)` — the paths that forced `FULL`, first-seen order, no
   de-duplication beyond first-seen.
5. `globs_from_workflow(text)` (PD4) — the lines of the `FACTORY_ONLY_PATHS:` block scalar in a
   workflow's text, stripped, comments and blanks dropped, in file order. It reads the block by
   its key and the indentation of the line after it, and returns `[]` when the key is absent —
   a workflow without the block is a workflow with no class, not an error. The key name is a
   module constant so the workflow, the doctor row and the mirror all spell it once.
6. `tests/test_ci_class.py` per §3.1: every path matched → `FACTORY_ONLY`; one unmatched among
   ten matched → `FULL`; empty paths → `FULL`; empty globs → `FULL`; `unmatched()` returning
   exactly the forcing paths in first-seen order; the glob rule over a bare name, a directory
   glob, a nested one and a path matching none; `CLASSES` holding exactly the two names.
7. The same module covers `globs_from_workflow`: a block read back as a list, a workflow with no
   block → `[]`, a comment line inside the block dropped, and the block read out of the real
   `.github/workflows/tests.yml` — which at this Task returns `[]`, and after Task 4 returns the
   list. Write that last assertion as "whatever the file holds, every line of it is a non-empty
   string with no leading dash", so it is true before and after Task 4 and never needs editing.
