## Description
stories: S-15353
writes: asf/workers/continuation.py, tests/test_continuation.py
after: Task 2

§2.4. A review file becomes a message: the check table, the verdict and the C/I lists, and not
one line of the brief. The session holds the card, the spec, the plan and its own diff; what it
does not hold is the findings, and a path would only make it read the file again — which is the
cost this Feature exists to remove.

**Files**

- `asf/workers/continuation.py` — `findings(text)` and `prompt(product, run, row, round_n,
  review_path, text)` per §2.4's two docstrings.
- `tests/test_continuation.py` — `PromptTests` (§3.3).

**Steps**

1. `findings(text)` → `{'verdict', 'table', 'criticals', 'improvements', 'missed'}` over the
   shape `asf/briefs/templates/review.md` asks a reviewer for. `verdict` is
   `harvest.pr_hygiene.parse_verdict(text)` — the one parser, never a second one (P8).
2. `table` is the contiguous block of `|` lines under the check header, verbatim, rows and
   separator as written: a reviewer's own evidence column is the finding, and re-rendering it
   would lose the `\|` the template asks for.
3. `criticals` and `improvements` are the `C`/`I` items, each kept **whole** — a C is
   `file:line` plus the exact fix, and half of one is not actionable. A `### Missed in round 1`
   section is read into `missed`.
4. `prompt(...)` renders §2.4's message: the `CORRECTION — round N of the review of <item> is
   in. verdict: <verdict>` head; the three sentences naming the session's own worktree and
   branch and telling it not to re-read what it wrote; the review path; the table; the C list;
   the I list; and the closing instruction — fix every C exactly, apply the I's it agrees with,
   widen nothing, re-run the acceptance tests and the Gate, `git commit -s`, push, finish with
   the typed REPORT, one line per C.
5. A `correct` row whose branch carries no review file sends the same shape with the harvest's
   correction text under `stall.CORRECTION_HEAD` (`asf/workers/stall.py:32`) in place of the
   review block — the red gate's own output is the finding, and `briefs.build.correction_text`
   already puts it under that head for a cold fixer.
6. The whole message is capped at `conventions.preamble_max_lines` (`asf/conventions.py:145`),
   the cap a brief already runs under. The table and the C list are kept whole; the I list is
   trimmed first, worst last.
7. `PromptTests` per §3.3: `findings` over a review file written to `templates/review.md`'s own
   shape — the verdict line, the six-row check table verbatim, three C items and two I items
   kept whole, a `### Missed in round 1` section read into `missed`; over a file with a verdict
   and no table; over one with a table and no verdict (`parse_verdict`'s fallback, P8). Then
   `prompt`: it contains the check table and every C, it names the branch and the review path,
   and it contains **none** of the brief's preamble — asserted by `'Backlog item:' not in text`
   and `TAIL` absent; a `correct` row with no review file carrying the harvest's correction text
   under `CORRECTION_HEAD` instead; the cap trimming the I list before the C list. And `target`
   refusing, by kind: `adjudicate`, `review`, `fix-bug` and `task` each → `kind <k> never
   continues`; a `spec` row on a Feature at stage `card` → `no review round`; a `spec` row at
   `spec-review r2` → round **2** and round 2's review path, not round 3 (§1.4, PD13) —
   asserted against `conv.review_path(slug, 2)`, never a literal (PD12).
