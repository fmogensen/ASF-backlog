## Description
stories: S-33053, S-33054
writes: asf/product_loop/loop.py, asf/scorecard/loop.py, tests/test_product_loop.py, tests/test_scorecard.py
after: Task 2

§2.4 and §2.5: the loop's first half, and the one keyword argument plus one entry kind the shared
queue needs to carry it (D11, P1). Two Stories because §2.5 *is* how §2.4's step 5 files — the
`met_before` split and the `propose_product_change` level are the same branch read twice.

The two acceptances this Task makes mechanical: *"the loop reads only the product's own
measurements and writes only to that product's record"* and *"a proposed product change arrives as
a card, never as a merge"*. The first is D10 — the target is `product.name`, hard-coded, with no
scope argument and no `file_to` — and the second is that the only thing this module ever writes into
a record is an item file and a History line, through a queue.

**Files**

- `asf/product_loop/loop.py` — `PRODUCT_QUEUE`, `READINGS`, `STATE`, `MARKER`, `daily`,
  `_readings_path`/`_state_path` through `facts.state_file`, `record_readings`, `history`,
  `met_before`, `propose`, `card_text`, `intake_text`
- `asf/scorecard/loop.py` — `queue=` on `enqueue` and `drain`; `drain`'s third entry kind
- `tests/test_product_loop.py` — `ProposeTests`, `TargetTests`
- `tests/test_scorecard.py` — `RecordTests` gains the `card` kind and the second-queue case

**Steps**

1. `asf/scorecard/loop.py`: `enqueue(target, entry, state_dir=None, queue=QUEUE)` and
   `drain(product, root, out=print, state_dir=None, queue=QUEUE)` — one keyword each, defaulted to
   the constant already there (`:42`), so every existing caller is unchanged. `drain`'s summary line
   names the queue it drained, so two loops' lines are told apart in the tick log.
2. `drain` gains §2.5's third branch beside `inbox` (`:192`) and `history` (`:201`):
   `elif e.get('kind') == 'card':` — dedupe on the same marker through `_find_marker(by_id, …)` and
   `_inbox_has(root, intake, …)`, then `ids.mint_id(root, canonical, 'feature')` and
   `ids.write_new_item(root, canonical, 'feature', new_id, e['typed'], e['body'], today(), e['why'])`
   (PD12, PD13). `canonical` comes from `core.load_items` + `core.canonicalize`, which is what
   `mint_id` and `write_new_item` take — `load_cards` gives the scorecard's flat card dicts and is
   the wrong shape for a writer, so read it once, lazily, the way the `by_id` cache already is.
   Count it into `n_cards`. When any card was minted, call `index.do_index(root)` once at the end.
   Nothing else about `drain` changes: the queue read, the marker dedupe, and a History line whose
   card is not minted yet staying queued are all untouched.
3. `tests/test_scorecard.py::RecordTests`: two cases. A `card` entry is minted once into
   `features/` with its typed fields, and a queue drained twice writes one card (the marker
   dedupe). A second queue name is a second file: `enqueue('p', …, queue='other.jsonl')` then
   `drain(p, root, queue=QUEUE)` leaves the other queue untouched, which is D11's whole purpose.
4. `asf/product_loop/loop.py`: `PRODUCT_QUEUE = 'product-loop-queue.jsonl'`,
   `READINGS = 'product-loop.jsonl'`, `STATE = 'product-loop-state.json'`,
   `MARKER = 'product-loop:'`. Paths come from `facts.state_file(product, …)`
   (`asf/scorecard/facts.py:456`), so the three files are under `env.state_dir(product)` and nowhere
   else (§4) and no path literal beyond the file names appears in the module (PD20).
5. `record_readings(product, readings, now, path=None)`: append one JSON line per run in §4's shape
   — `date`, `as_of`, `product`, and one entry per reading carrying `name` and `state` always, plus
   `value`, `unit`, `guardrail`, `direction`, `breach` and `breached` for an `ok` one and `detail`
   for a `broken` one. **`value` is absent from every broken reading** — there is no field for a
   number nobody took (§4), so build the dict by state rather than writing `None`. Reuse
   `loop._read_lines`/`_write_lines`' shape for reading
