   `load_items` and never after a `None` from `canonical.get` (**PD5**, D-0017):
   `reopen._canonical` (`reopen.py:56-62`) for the id its caller named; `setfield.cmd_set`
   (`setfield.py:299`, and the two re-loads at `:410` and `:436` — one call at the top covers all
   three, since the card is in the working set by the time they run); `undeliver` (`:85`) for the
   member and its lead; `resolve.resolve_edges` (`:205`) for `iid`. Each passes its own `why`: the
   reason the operator gave for `reopen`, the field and value for `set`, `undeliver`'s own, and the
   resolution's for `resolve`. `asf untick` is `setfield`'s path and needs no fifth site.
2. `asf/record/archive.py` is **not** in this Task's footprint: `bring_back` landed whole in Task 1
   (**PD5**), so this Task adds call sites and tests only. If a coder finds `bring_back` short of
   what a site needs, that is a `needs writes:` on `asf/record/archive.py` in the REPORT, not a
   quiet widening.
3. `resolve.resolve_edges`: the docstring gains the one sentence that says why the call is there
   even though no edge onto an archived id can exist — the closure holds a referenced card in the
   working set (D-0004), so what the call is for is `target_rec = canonical.get(iid)` at `:229`, the
   target's own relpath that must ride in the same commit as the edges it resolves.
4. `tests/test_record_archive_reopen.py`: S-211571's eleven lines. `asf reopen` on an archived id
   moves the card and its view back **before** it derives anything (assert the order by reading the
   card's bytes at the moment the reopen's own derivation runs); the card is byte-identical to what

   is there; exactly one `unarchived: <why>` History line; `asf set`, `asf untick` and
   `asf undeliver` each on an archived id; the resolver on an archived target; an id in neither
   place still `not found`, unchanged; a card brought back, closed and aged again archived by a
   later pass; and a card whose shape is below the record's converted as it comes back.
