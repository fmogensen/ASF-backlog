The spec's fourth and fifth **In** bullets and `## The design` §`asf/scorecard/loop.py`,
§`asf/views/scorecard.py` (all but the `_delta_cell` line Task 1 took) and §`asf/cli.py`, plus PD1's
five-line dispatch. This is the Task that turns Task 1's pure functions into a command. It waits on
Task 1 because `loop.totals` calls `score.total_row` and `score.delta_row`, and `render_all`'s last
line is `score.total_line`.

**Files**

- `asf/scorecard/loop.py` — `totals(as_of=None, products=None, read=snapshots)`, beside
  `snapshot`/`snapshots` (`:141-155`)
- `asf/views/scorecard.py` — the module docstring's first paragraph (`:1-3`); `compute_all`,
  `render_all`; the `--all` branch at the head of `cmd_scorecard` (`:216`)
- `asf/cli.py` — `p_scorecard.add_argument('--all', …)` (after `:333`); PD1's early dispatch
  (above `:539`)
- `tests/test_scorecard.py` — `AllProductsReaderTests`, `AllProductsCommandTests`

**Steps**

1. `asf/scorecard/loop.py`: `totals(as_of=None, products=None, read=snapshots)` with the spec's
   docstring byte for byte, placed directly after `snapshots` (`:155`) under the existing
   `# --- snapshots --` banner, which it is the third of. The signature is the design block's three
   parameters, not the `## In` bullet's two (PD11).
2. Its body, exactly the envelope the design block prints:
   - `as_of` defaults to `facts.now_iso()` — already imported? No: `loop.py` imports
     `iso, load, load_cards, state_file, to_dt` from `asf.scorecard.facts` at `:38`. Add `now_iso`
     to that import list rather than importing the module.
   - `week = score.week_start(to_dt(as_of)).date().isoformat()` — the same key the rows carry (P4,
     verified at `asf/scorecard/score.py:228`); `prev_week` is that Monday minus seven days;
     `day = 1 + (to_dt(as_of).date() - <that Monday>).days`, so a Monday reads `day 1/7` and a Sunday
     `day 7/7`; `days` is `7`.
   - `products` defaults to `configured_products()` (`:64-70`) and is otherwise the names given, in
     the order given. For each name, `rows = read(name)` once, then `row` is the row whose `week` is
     `week` and `prev` the one whose `week` is `prev_week`, either or both `None`. A name with no
     rows at all still gets an entry with both `None` — that is what lets the table print
     `never measured` rather than dropping the product (D8).
   - `total = score.total_row([p['row'] for p in products if p['row']])`, `prev_total` the same over
     `prev`, `delta = score.delta_row(total, prev_total)`, and each product's own
     `delta = score.delta_row(row, prev)`.
   - Reads `state/<product>/scorecard.jsonl` through `read` and **nothing else** (D2): no
     `facts.load`, no record, no repo, no registry, no forge, and no clock but `as_of`. The S-34951
     fence patches `asf.scorecard.facts.load` to raise, so a stray call is a failure, not a slowdown.
3. `asf/views/scorecard.py`: `compute_all(as_of=None, products=None)` with the spec's docstring byte
   for byte — one line, `return loop.totals(as_of=as_of, products=products)`. It takes no `root` and
   no `Product` (PD1).
4. `render_all(d)`, printing the spec's table exactly: the header
   `**SCORECARD — ALL PRODUCTS** — week of <week> (day <n>/<days>) vs <prev_week>`, the ten columns
   in the spec's order (`Product`, `Landed`, `On prod`, `$ all-in`, `$/feature all-in`,
   `$/feature own`, `Repair sessions`, `Repair/feature`, `Median lead`, `Read at`), one row per
   product in `configured_products()` order, then the **total** row with every cell bolded and
   `Product` as `**total**`. Every measured cell is `<this week> (last <last week>, <Δ>)` — the
   acceptance's *"each with last week's value and the delta"* — rendered through the existing `_m`,
   `_n` (`:17-23`) and Task 1's `score.delta`. `Median lead` carries **no** delta (D4) and the
   total's is `—`. A product with no row for this week
