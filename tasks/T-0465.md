## Description
stories: S-33450
writes: asf/tick/tick.py, tests/test_tick.py
after: Task 1

The spec's `asf/tick/tick.py` design section, whole, and the card's P4: three tick exits reach no
`commit_and_push` and therefore never fast-forward the checkout, and every one of them is a tick
after which origin may have moved. One function with a flag on the context, called from the
places that actually end a tick, and removed from the commit path where a raising commit skipped
it.

**Files**

- `asf/tick/tick.py` — `sync_checkout(ctx)`; `Context.__init__` gains `checkout_synced`; the call
  removed from `commit_and_push`; two calls in `run_record_step`; one at `run`'s end
- `tests/test_tick.py` — new `CheckoutSyncOnEveryExit`

**Steps**

1. `sync_checkout(ctx)`, with the spec's docstring: return False at once when
   `getattr(ctx, 'checkout_synced', False)`, set the flag, import `shadow` inside the function as
   the module already does at its other call sites, and return
   `shadow.sync_operator_checkout(ctx.product, out=print)`. The `getattr` guard, not a bare
   attribute read — a `Context` built by an older path, or a stand-in in a test, must not raise
   here (D12).
2. `Context.__init__` gains `self.checkout_synced = False`, so the attribute is real on every
   context and the `getattr` default is a belt, not the mechanism.
3. Remove the two-line comment and the `shadow.sync_operator_checkout(...)` call from the end of
   `commit_and_push` (`asf/tick/tick.py:232-233`), leaving `return rc`. The `from asf.tick import
   shadow` at the top of that function stays — `commit_local` and `push` still need it. This is
   D13: a sync at the end of the commit path is skipped whenever the commit raises (P4c), and its
   position implied the fast-forward was about *this* tick's push when it is about the checkout
   being current at all.
4. `run`'s end (`asf/tick/tick.py:489-492`): `sync_checkout(ctx)` on its own line after the
   `if ran and ctx.has_record:` block and **before** `print(total_line(...))`, outside the record
   lock — it touches the operator's checkout, never the clone, so it must not hold a lock taken
   for the clone's commit. This closes P4a (a `--steps prs,health` tick) and P4c (a commit that
   raised inside `finish`, which is caught at `tick.py:521-527` and returns normally).
5. `run_record_step`'s two standalone exits (`asf/tick/tick.py:206-214`): in the `except`, after
   `ctx.stale_reason = _reason(detail)`, `if alone: sync_checkout(ctx)` with the spec's comment —
   *origin may have moved before this tick broke* — then `return 1`. And the tail becomes
   `if not alone: return 0` / `rc = commit_and_push(ctx)` / `sync_checkout(ctx)` / `return rc`.
   The non-standalone path still returns 0 without syncing: it is inside a tick, and step 4 syncs
   at that tick's end. This closes P4b.
6. `CheckoutSyncOnEveryExit` in `tests/test_tick.py`, one case per hole plus the idempotence,
   asserting on what reached the tick log and on how many times `sync_operator_checkout` was
   called (patched, so no git and no network in this module): a tick with **no record step**
   (`--steps` of command steps only, `has_record` false) still syncs; a **record step that
   failed** syncs; a **refused push** syncs; a **commit that raised** inside `finish` syncs; and a
   full tick that reaches both `run`'s end and a standalone path calls it **exactly once**. Each
   case also asserts the tick's exit code is what it was before this change — the sync reports,
   it never decides a tick's result.
7. One case asserts the negative that the old position hid: with `commit_and_push` raising
   `subprocess.CalledProcessError`, the sync still happens. That is P4c stated as a test, and it
   is the one that fails against `main`.
