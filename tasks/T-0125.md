## Description
stories: S-17803, S-17804, S-17809

§2.4. One call in `run_product_harvest`'s eligible loop, after the lane refusal and before the
approvals class, the rebase and the gate. The branch is held with a `boundary` correction naming
the extra paths; it never enters the combined head, so it can never land inside somebody else's
push (B-0040). Nothing on origin is touched — that is Task 4's proof, and this Task's discipline.

**Files**

- `asf/harvest/harvest.py` — `touched_files(repo, trunk, branch, renames=True)` (`:818`) passing
  `--no-renames` when False (P5); the screen in the second loop, between `lane_refusal` (`:1297`)
  and `approvals.merge_class` (`:1301`); `hold_with_correction` (`:958`) gaining `outside=()` and
  passing it to `lifecycle.hold` as `extra`; `mode_warning` printed once per product harvest before
  the loop; `off` skipping the diff read entirely.
- `asf/workers/lifecycle.py` — `hold(path, run, kind, text, now, empty_cap=EMPTY_CAP, extra=None)`
  (`:626`): `extra` is merged into the correction dict on all three return paths and nowhere else.
  `kind` is already free-form, so `boundary` needs no registration.
- `tests/test_harvest.py` — `BoundaryHoldTests` (new, in the shape of `ForeignRedTests:1321`), and
  the lane half as `ProductHarvestTests` methods whose names carry `f0026`.
- `tests/test_lifecycle.py` — one case that `extra` reaches the correction and that a hold without
  it is byte-identical to today's.

**Steps**

1. `touched_files` grows the keyword; every existing caller is unchanged and still gets git's
   default rename detection.
2. `lifecycle.hold`'s `extra`, and `hold_with_correction`'s `outside=()` threaded to it. The
   red-test attribution arms above it (`foreign`, the docs-only arm) are untouched — attribution is
   a question about blame, not permission (§2.10).
3. The screen, exactly §2.4's shape: `card = (items or {}).get(item) or {}`,
   `edge = boundary.refusal(conv, branch, item, card, touched_files(repo, trunk, branch, renames=False))`;
   on `hold` it holds with `outside=boundary.outside_of(edge)` and `continue`s; on `warn` it prints
   `boundary {branch}: {edge[1]}` and falls through; on `off` the diff is never read.
4. `mode_warning` (PD7) printed once, before the loop, when the product's value is not one of the
   three.
5. `BoundaryHoldTests` (§3.3, the unit half): a diff inside the grant → None; one file outside →
   the text names it and `kind` is `boundary`; five and six files outside → the `(+N more)` form
   and the full list on `.outside`; a file **deleted** outside the grant is a violation like any
   other; a file renamed out of the grant with both paths judged (`--no-renames`); `warn` and `off`.
6. The lane half, `-k f0026`, on the product fixture: a `worker/T-0080` whose diff leaves its grant
   is `held` with one line, gets a `boundary` correction carrying `outside`, is **not** gated (the
   gate's timing line never appears), leaves `origin/main` where it was and `origin/worker/T-0080`
   at the same sha; a green branch inside its grant still lands unchanged; an out-of-grant branch in
   a combined set is held while its lawful sibling lands at the pushed sha; a `spec/F-0001` branch
   carrying its document **and** `asf/harvest/harvest.py` is held, and one carrying only its
   document and a review file lands; a card with no grant and no footprint is gated as today.
7. The re-admission case of §3.3's last clause belongs to Task 4, which writes it in the same class.
