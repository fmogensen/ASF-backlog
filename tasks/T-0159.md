## Description
stories: S-17409
writes: asf/conventions.py, asf/doctor.py, docs/products.example.yaml, tests/test_conventions.py, tests/test_doctor.py
after: none

§2.9 and §4's config block. Every threshold the pass reads is a typed convention with a documented
default, and a product that misspells one is told so by the doctor rather than silently read as the
default. Independent of every other Task's writes, so it runs in wave 1 beside Task 1; Task 5 is its
first reader.

**Files**

- `asf/conventions.py` — `DEFAULT_SAVINGS` (new, with §2.9's comment); `Conventions.savings:
  dict = field(default_factory=lambda: dict(DEFAULT_SAVINGS))` beside `stage_limits` (`:163`);
  `savings_for(conv, key)` (new). `forbidden_patterns` (`:110`) is not touched — it walks *string*
  defaults containing `/`, `{` or `#`, so a dict default adds no pattern (P14).
- `asf/doctor.py` — `check_savings(product)` (new, beside `check_capacity:269`), one row in `run`
  (`:452`) after `capacity`, not required.
- `docs/products.example.yaml` — §4's `conventions: savings:` block, its eight keys each with the
  one-line comment §4 gives it.
- `tests/test_conventions.py` — `SavingsDefaultsTests` (new); `ModuleConstantsTests:255` gains the
  `DEFAULT_SAVINGS`/`Conventions().savings` pair; `ForbiddenPatternsTests:136` asserts the dict
  default adds no pattern.
- `tests/test_doctor.py` — `TestCheckSavings` (new), beside `Capacity:304`.

**Steps**

1. `DEFAULT_SAVINGS` exactly as §2.9 fences it: `window_days` 7, `min_landings` 5,
   `preamble_ratio` 2.0, `gate_minutes_max` 20.0, `rounds_per_landing` 1.3,
   `step_duration_ratio` 1.5, `spend_ratio` 1.5, `failure_class_count` 3.
2. The `savings` field on `Conventions`, and `savings_for(conv, key)` returning the product's value
   for a key it names and `DEFAULT_SAVINGS[key]` for one it left out — a product overriding one
   threshold keeps the other seven.
3. `from_mapping` needs no change: `savings` becomes a declared field, so a product's block is read
   into it rather than kept in `extra` (PD13).
4. `check_savings(product)`: every key of the product's `savings:` is a key of `DEFAULT_SAVINGS`
   and every value is a number greater than zero. Green is
   `savings: 8 thresholds, <n> overridden`; red names the bad key and the values it may take.
5. The example yaml's block, under `conventions:`, in §4's words.
6. `SavingsDefaultsTests`: the defaults are what §2.9 says; a product overriding one key keeps the
   other seven through `savings_for`; a product naming none gets all eight; `forbidden_patterns()`
   is unchanged by the new default. `TestCheckSavings`: an unknown key is red and named, a zero or
   negative value is red and named, a clean product is green, and the row appears in
   `doctor.run(...)`'s output in table order.
