## Description
stories: S-31100, S-31101, S-31103
writes: asf/roles/launch.py, asf/workers/capability.py, asf/roles/roles.py, asf/conventions.py, tests/test_launch.py, tests/test_roles.py, tests/test_conventions.py
after: none

§2.1, §2.2, §2.4 and §2.6's `effort_for`. Three new readable things and one deletion: the table
that says what each role is launched with, the probe that says which of those the installed binary
will accept, the writer that turns a role file into a runtime agent definition, and `asf-locator`'s
`UNBOUND` reason, which this Feature makes untrue. Nothing in this Task is wired into a launch —
`build_command` and `spawn` are Task 4 — so `main` after it launches exactly as it does today.

**Files**

- `asf/roles/launch.py` — **new**. Imports `asf.roles.roles`, `asf.conventions` and the stdlib,
  nothing else, so the launcher, the doctor and the table view all read one module.
  - `PERMISSION_MODES = ('acceptEdits', 'auto', 'bypassPermissions', 'manual', 'dontAsk', 'plan')`
    and `EFFORTS = ('low', 'medium', 'high', 'xhigh', 'max')` — the runtime's own six and five,
    written down because T1 validates every row against them (P5, re-read at this head).
  - `READ_TOOLS = ('Read', 'Grep', 'Glob')`, `EDIT_TOOLS = ('Edit', 'MultiEdit', 'NotebookEdit')`
    and `WRITE_TOOLS = ('Write',) + EDIT_TOOLS`. **PD4**: `EDIT_TOOLS` is what a role that writes
    one named file is denied, `WRITE_TOOLS` is the set whose *path argument* `roleguard` checks. A
    comment says so, and names T5's first clause as the reason.
  - `Launch`, frozen, with §2.1's eight fields and §2.1's docstring.
  - `TABLE` — §2.1's twelve rows, with two corrections from PD4: `asf-reviewer` takes
    `deny_tools=EDIT_TOOLS`, and `asf-prober` takes `tools=READ_TOOLS + ('Write',)`. `asf-security`
    and `asf-locator`, which write no named file, keep `deny_tools=WRITE_TOOLS` and `tools=READ_TOOLS`
    respectively. `connections=()` on every row.
  - `resolve_writes(launch, product)` — the row's `writes` patterns with `{reviews_dir}`,
    `{specs_dir}`, `{plans_dir}`, `{reports_dir}` filled from the product's `Conventions` fields
    (`asf/conventions.py:498-531`) and `<record>` from `product.backlog_dir`. No literal path is
    ever written in this module: `tools/check_conventions.sh` generates an anchored pattern per
    path-shaped default, so `docs/reviews` here would fail the lint — the placeholder form is the
    only form that passes.
  - `launch_for(kind, product=None)` — `roles.for_kind(kind)`, the table row, then the product's
    `conventions.roles.<role>` override for `effort` and `permission_mode` **only**. An override of
    `tools`, `writes` or `connections` raises, naming the key and the amendable set: widening a
    boundary is an operator action (`asf/amendable.py:53`), not a product setting. A non-empty
    `connections` raises for the same reason (§2.1's third fact).
  - `MECHANICAL = ('rebase', 'close', 'groom-clerk')` and `effort_for(kind, binary=None, caps=None)`
    — §2.6, verbatim in intent: the lowest level `capability.effort_levels` reports for a mechanical
    kind, the row's own otherwise, `''` when the runtime has no `--effort`. `caps` is injectable so
    every test runs without a binary.
  - `agents_path(product, job)` → `<state>/<product>/agents/<job>.json`, under
    `env.state_dir(product)` beside the briefs directory (PD14), and `write_agents_file(product,
    job, launch)` → §2.4's one-key JSON object: `description` the role's `purpose` verbatim,
    `prompt` `roles.block(role, roles.MAX_LINES)` — the full text, since `validate` refuses a file
    over `MAX_LINES`, so `block` never truncates a valid role — and `tools` the row's set minus
    `deny_tools`. `json.dumps(..., indent=2, sort_keys=True)` so the same role and row give the same
    bytes. A role whose file fails `roles.validate` raises before anything is written, naming the
    role and the problem.
  - `table_rows(product, caps=None)` is declared here as a stub raisin
