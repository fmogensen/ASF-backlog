## Description
stories: S-32350
writes: tools/install.sh, asf/install.py, tests/test_install.py
after: Task 1

§2.1 and D5/D6: steps 2–6 leave the shell, the default ref becomes the newest release tag, and
after `pipx` the script `exec`s `asf install` with the flags it was handed.

**Files**

- `tools/install.sh` — the usage line, the `--` terminator, the release-tag default, the `exec`;
  steps 2–6 removed
- `asf/install.py` — `newest_tag(refs)` (PD6)
- `tests/test_install.py` — `ReleaseRefTests`, `InstallScriptTest` extended

**Steps**

1. `newest_tag(refs)` in `asf/install.py`: pure over ref names or `refs/tags/<name>` lines, keeps
   only what `cli.RELEASE_TAG` fullmatches (PD7), orders by the integer tuple of the name's
   digits, returns the newest or `None`.
2. `tools/install.sh` keeps: the `pipx` / `git` prerequisite check; resolving `ref`; the
   `pipx install --force git+<url>@<ref>` made while holding `<ASF_HOME>/state/<product>/tick.lock`
   bounded by `ASF_INSTALL_LOCK_WAIT_S`; the `<ASF_HOME>/logs/install.log` line; the
   `pipx ensurepath` check; and the whole-script `{ … }` wrapper.
3. Argument parsing: `<product> [ref] [-- <asf install flags>]`, with `--` terminating the
   positionals (PD11). `ASF_REF=main` or a second argument still pins a branch head or a sha.
4. With no `ref`: `git ls-remote --tags --refs <url> 'v*'`, the inline `python3` applying step 1's
   rule, and the chosen tag said out loud —
   `install: product <p>, release v0.1.1 from <url>`. No tag on the remote is one `NEEDS OPERATOR`
   line, not a silent fall back to `main`.
5. Steps 2–6 are deleted, and after `command -v "$BIN"` the script `exec`s
   `asf install --product <product> [the flags after --]`. One implementation of every step, one
   exit status. The doctor baseline reader, the clock retry and the console offer are Task 2's,
   already in Python; nothing of them is left behind in the shell.
6. The header comment is rewritten to describe the two things the script still does, so it does
   not go on claiming six steps it no longer runs.
7. `ReleaseRefTests`: one fixture bare remote carrying `v0.1.0`, `v0.2.0`, `v0.10.0` and the stray
   `v0.2.0-rc1`. `newest_tag` answers `v0.10.0`; the bootstrap's inline `python3`, run against the
   same `ls-remote` output, answers the same string; the stray is rejected by
   `cli.RELEASE_TAG.fullmatch` in both; an empty ref list is `None` and the `NEEDS OPERATOR` line.
8. `InstallScriptTest` extended on its existing stubbed PATH (`tests/test_install.py:1669`): the
   four call shapes of PD11; `pipx` is called once with `git+<url>@<the resolved tag>`; the
   `install.log` line carries that ref; the script `exec`s `asf install --product <p>` with the
   flags after `--` in order and nothing else; and `asf install`'s exit status is the script's.
   The cases that drove steps 3–6 (a failing hooks step, the not-loaded clock, the doctor
   baseline) move out with the code they tested — they are Task 2's `InstallStepsTests` now.
