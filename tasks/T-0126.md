## Description
stories: S-17805, S-17807
writes: asf/harvest/harvest.py, tests/test_harvest.py
after: Task 3

§2.5 and §2.7 — the card's second acceptance line, and the hold that costs no second session. The
one path in this factory that discards content today (`land_already`'s `dropped with the branch`)
stops doing so, and a hold whose question the record has answered is cleared by harvest itself.

**Files**

- `asf/harvest/harvest.py` — `land_already` (`:878-890`): with `extras`, `archive_commit` +
  fast-forward push to `refs/heads/archive/<branch>` before the lane branch is deleted, and the
  line naming where the extras went; with no extras the path is byte-for-byte what it is today.
  The re-admission block in the first loop, immediately above the `is_eligible` screen (`:1282`,
  PD9), as §2.7 fences it.
- `tests/test_harvest.py` — `ProductHarvestTests` methods carrying `discard` in their names, and
  the re-admission case in the `f0026` set Task 3 started.

**Steps**

1. `land_already`: when `extras`, `sha = archive_commit(repo, branch, f'archive({item}): {branch} —
   its deliverable is on {trunk}; kept for …  [skip ci]')`; an empty sha or a refused push leaves
   the lane branch in place and prints one line — the branch is never deleted before its archive
   exists. Only then `mark_session`, the delete, and
   `landed {branch}: already on {trunk} at {tip}; not its deliverable — {files} kept on
   archive/{branch}`. `dry_run` prints and writes nothing, as it does today.
2. `land_already` needs the item id for the archive message; it is already computed at the call
   site (`:1272`) and is passed in rather than re-derived.
3. The re-admission: read `lifecycle.pending_correction(record, sessions_path(state_dir))`; when its
   `kind` is `boundary.BOUNDARY_KIND` and `boundary.refusal(...)` over the current diff is None,
   `mark_session(..., correction=None)` (P3), update the in-memory record so the `is_eligible` call
   below sees the cleared state, and print `re-admitted {branch}: its grant now covers the diff`.
   `rounds` is left as it stands — the round already spent is not refunded (§1.4). A dry run prints
   the line and writes nothing.
4. `-k discard` (§3.4): for a held branch, `git rev-parse origin/<branch>` and
   `git rev-list --count origin/main..origin/<branch>` are identical before and after the tick, and
   every file the session wrote is readable at that sha; a branch held at the boundary in three
   consecutive harvests still has all of its commits; `land_already` with extras pushes
   `archive/<branch>` whose tree contains the extra file, deletes the lane branch only after that
   push succeeds, keeps the lane branch when the archive push is refused, and prints the line naming
   where the extras went.
5. The re-admission case in the `f0026` set: the same held branch, with the card's `grant:` widened
   between two harvests, lands in the second with no new session, printing `re-admitted`, its
   correction cleared and its `rounds` unchanged.
