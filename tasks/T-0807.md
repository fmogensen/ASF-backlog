## Description
stories: S-59304, S-59306, S-59307
writes: asf/reservations.py, tests/test_reservations.py
after: none

The spec's `## The design` §1 in full, and A1 whole. No caller changes and nothing in the factory
behaves differently when this lands — `declared` is `writes_bookings`' own inner loop with a name,
`booked`/`pending_added` are `added_files`' command pointed at a revision instead of a remote ref,
and `unhonoured`/`honour_refusal` have no caller until Task 2. That is exactly why it goes first:
D10's argument is that the brief that states a reservation and the check that enforces it read one
function, and a function Tasks 2 and 3 each wrote for themselves is the defect this card closes.

Read **PD2** (A1's fixture declares a sequence A1's own paths do not belong to — the one byte of the
block the Task changes), **PD4** (`NO_COMMAND`, so an unconfigured product is not a standing
warning), **PD9** (the three fixture methods A1 calls do not exist) and **PD14** (the forbidden
tokens, in a module that is not one of the three exceptions) before starting. **PD1** names the
`extra=()` keyword this Task adds to `snapshot`; Task 2 is its only caller, and it is here because
`snapshot` is in this Task's footprint and not in Task 2's reach without it.

**Files**

- `asf/reservations.py` — `declared`, `_added`, `added_files` (refactored onto `_added`, signature
  and docstring unchanged), `booked`, `pending_added`, `_numbers_under`, `unhonoured`,
  `honour_refusal`, `NO_COMMAND`; `writes_bookings` and `added_bookings` re-pointed at the lifted
  readers; `snapshot` gains `extra=()`
- `tests/test_reservations.py` — the A1 cases: four into `class Bookings`, four into a new
  `class Honour`, and the two git cases into a new `class PrePushRev` (PD9)

**Steps**

1. `declared(item, seqs)` exactly as the spec's §1 writes it, docstring included — the `set` and the
   `sorted` return are load-bearing: `writes_bookings` appends per glob and could append the same
   `(sequence, number)` twice from two globs, and the brief's line must be stable.
2. `writes_bookings`' inner loop (`:132-138`) becomes
   `for name, n in declared(item, seqs): out.append(Booking(name, n, branch, WRITES))`. Everything
   above it — `is_open`, `feature_of`, `plan_carrier`, the `kind`/`branch` choice — is untouched. The
   output is now deduplicated and sorted within a card, which is what
   `test_writes_bookings_reads_the_same_numbers_as_declared` asserts; the nine landed `Bookings`
   cases each declare at most one numbered glob per card, so none of them moves.
3. `_added(repo, trunk, rev)` and `added_files(repo, trunk, ref)` exactly as the spec writes them:
   `added_files` keeps its signature, its one caller and its docstring byte for byte, and becomes
   `return _added(repo, trunk, f'origin/{ref}')`.
4. `_numbers_under(paths, seqs)` — for each sequence, the basenames of `paths` whose `os.path.dirname`
   equals that sequence's directory, through `reserve.numbers_in` against its regex; return
   `sorted(set((name, n)))`. Lift it from `added_bookings`' **per-ref** loop (`:107-110`, PD13) and
   have that loop call it. The trunk half above it (`:104-106`) reads a tree *listing* of bare
   filenames, not paths, so it is not a caller and does not change.
5. `booked(repo, trunk, rev, seqs)` → `_numbers_under(_added(repo, trunk, rev), seqs)`, with the
   spec's docstring: `rev` is any revision, `HEAD` in a session's own worktree for a branch not yet
   on origin, `origin/<ref>` for one that is. Pure and rev-only — that is the half T-0600's lane
   reuses (`## Out`).
6. `pending_added(repo, seqs)` — one `git status --porcelain --untracked-files=all` through `H.sh`
   in `repo`; keep a line whose first two characters are an addition (`A` in either column, or
   `??`), take its path as `line[3:]`, and return `_numbers_under(paths, seqs)`. A rename (`R`) and
   a modification (`M`) are not additions and are skipped, for `added_files`' own reason: a branch
   that edits a landed `0201_*
