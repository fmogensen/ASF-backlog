## Description
stories: S-14303
writes: asf/workers/stall.py, asf/workers/runtime.py, asf/workers/lifecycle.py, tests/test_tokens.py

Depends on T-14650: `capped` is `tokens.meter` + `tokens.over` + `tokens.cap_result`.

**Files**

- `asf/workers/stall.py`: `_signal`, `stop_session`, `capped`; the module docstring gains the cap's
  half of "a live session the factory must end". One new module-level import (PD7).
- `asf/workers/runtime.py`: `failure_reason`'s first clause.
- `asf/workers/lifecycle.py`: `'capped'` in `RUN_FIELDS` (PD10).
- `tests/test_tokens.py`: `CapStopTest`.

**Steps**

1. `runtime.failure_reason(rec)` gains, before the text signatures, exactly the spec's clause: an
   `asf` value that is a dict whose `cap` is a dict returns `'token cap'`. The docstring gains one
   sentence saying the structured field is read first and why (D9: a session's own report text
   lands in `result` and is forgeable; the factory's field is not). `result_ok` is untouched — it is
   already False for an `is_error` record.
2. `lifecycle.RUN_FIELDS` gains `'capped'`, so a cap never folds onto the next run of the same job
   (B-0041).
3. `stall._signal(pid, sig)`: `os.killpg(os.getpgid(int(pid)), sig)`. The one line a test patches
   (PD5).
4. `stall.stop_session(session, alive, grace_s=tokens.STOP_GRACE_S)`: `_signal(pid, SIGTERM)`, then
   poll `alive(pid)` every 0.5 s up to `grace_s`, then `_signal(pid, SIGKILL)` if it is still there.
   `ProcessLookupError` and `PermissionError` are caught and are not errors — the run is gone or is
   not ours, and the caller still writes the cap line.
5. `stall.capped(product, now=None, alive=None, caps=None, stop=True, out=print)`, the spec's eight
   numbered steps in order:
   1. `caps` defaults to `tokens.caps(product)`; a `TokenCapError` prints `token cap: <why>` and
      returns `[]` — nothing signalled, nothing appended, every other health duty untouched (D13).
   2. `live = pool_mod.live_sessions(product)`; `alive` defaults to
      `health_mod.alive_for(product, live)` (PD9). For each session, `m = tokens.meter(s['log'])`;
      `m.result is not None` → skip, whatever it spent.
   3. `tokens.over(m.by_dim, tokens.cap_for(product, metrics_mod.session_kind(s)))`; `None` → skip.
   4. `alive(s['pid'])` is False → nothing is signalled and the run is left to health's `dead pid`
      path.
   5. `stop` → `stop_session(s, alive)`.
   6. `runtime_mod.read_result(s['log'])` again. Still `None` → append one line,
      `tokens.cap_result(kind, dimension, tokens_, limit, m.by_dim, now)`. A result that arrived in
      the meantime is left alone and the row carries a `finished first` detail instead.
   7. `pool_mod.update_session(product, s['job'], capped={'dimension': …, 'tokens': …,
      'limit': …, 'at': now})`.
   8. `out(f'CAP   {job}  {dimension} {tokens} over {limit} ({kind})')` per row, and `cap: none`
      when there are none.
   The return is `[(job, dimension, tokens, limit)]`, in `live_sessions` order.
6. `CapStopTest` as below. Its fixtures are `tests/test_workers.py`'s `Home` (a temp `ASF_HOME`) with
   a registry written through `pool_mod.append_session` and a hand-written job log; `_signal` is
   patched, so no real process is ever signalled and the runner's own pid is never used.
