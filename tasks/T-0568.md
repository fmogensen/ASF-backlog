The card's two named tests, plus the fence, written where the decision is actually made —
`land_spec.why_not_as_is` and `land_spec.adopt`, over a real origin, a real work clone and a real
pushed lane branch — and not at `landing_class`, which is one layer below the property the card
exists for (D8, spec §2.3).

**No product code changes in this Task.** All three methods pass against the trunk as it stands —
measured here at the branch point, `Ran 7 tests … OK` in 1.97 s (PD6). That is the point: they are
a lock on a property the trunk already has and nothing states, so that
`land_spec.why_not_as_is`, or anything between it and `landing_class`, cannot be narrowed again
without a red test. A coder who finds one of them red has found a regression to report, not a test
to relax.

The three methods go on the **existing** `LandTheApprovedSpec` (D8) — its `setUp` already builds
everything they need and `env.Product` takes the conventions per test. A new class that subclasses
that harness would re-run the host's own seven tests under a second name.

**Files**

- `tests/test_land_spec.py` — the `declared()` helper and three methods on `LandTheApprovedSpec`,
  placed after `runs()` (`:70-71`) and before the first `test_` method. Nothing else in the file
  is touched: `env`, `land_spec`, `lifecycle` and `pool_mod` are already imported at `:8-20`, and
  `push_branch`, `items` and `runs` already exist.

**Steps**

1. `declared(*globs)` and the three methods, copied from §3.2 byte for byte. Note what each one
   proves and do not weaken it:
   - `test_a_branch_touching_a_declared_doc_path_lands_as_it_stands` asserts **four** things — the
     empty `why_not_as_is`, `adopt`'s returned triple, the run held `PUSHED`, and **no** pending
     correction. The last is what says the branch lands *without a session*, which is the card's
     whole sentence; dropping it would leave a test that passes while a `landing-gate` correction
     sends an approved spec back to an Opus session.
   - `test_an_undeclared_path_is_not_docs_only` uses `self.product` — the harness's product, which
     declares nothing — against the same two files, so the pair differs in exactly the
     declaration.
   - `test_a_declared_doc_path_never_carries_code_in_with_it` is the fence: `src/a.py` beside the
     declared path, and the refusal still names *more than documents*.
2. `lifecycle.pending_correction` is called with one argument; its `path` is optional
   (`asf/workers/lifecycle.py:719`) and the harness's other tests call it the same way (`:81`).
3. Each method calls `push_branch` once in its own `setUp`-fresh temp repo; do not share a branch
   between them.
4. Do not add a fourth method that re-proves `landing_class` — `tests/test_lane.py:312-318` is
   that test, and it is Task 1's Gate.
