§2.5. One signature per tracked CI number whose seven-day rate misses its target, computed
through `metrics.ci_waste_numbers` — the scorecard's own function, so the Bug and the row are the
same number — and bumped at most once a week through the cap Task 3 built. Everything else is the
existing filer's: the `S3`'s `decided: false` sends it to the groom, `default_bug_epic` parents
it, and the `file_bug` approval class holds it with no new branch.

**Files**

- `asf/tick/file_bugs.py` — `CI_TARGET_WINDOW_DAYS`, `CI_TARGET_REFILE_DAYS = 7`,
  `CI_TARGET_SIGS`; `ci_target_signatures(root, now, conv=None)`; `cmd_file_bugs`' fourth
  `signatures.update` (`:237`); the module docstring's source list (`:3-7`) gains the line; the
  import of `asf.metrics.metrics`.
- `tests/test_file_bugs.py` — `CiTargetBugTests` (new), and the T5 scenario that needs this
  source, beside `RefileWindowTests`.

**Steps**

1. The three constants of §2.5, with its comments: `CI_TARGET_WINDOW_DAYS = metrics.CI_TARGET_WINDOW_DAYS`
   — the name §2.5 fences, bound to the window Task 2 owns, so the row and the Bug cannot drift
   apart by an edit to one module; `CI_TARGET_REFILE_DAYS = 7` ("a seven-day mean is not news
   every morning"); `CI_TARGET_SIGS = {'cancelled': 'ci waste: cancelled minutes', 'red': 'ci waste: red rate'}`.
2. `ci_target_signatures(root, now, conv=None)` reads `metrics/ci/*.jsonl` with the module's own
   `_jsonl_lines`, the way the other three sources read theirs, and keeps the lines whose
   `str(r.get('ts'))[:10]` is in `set(metrics.days_back(now.date().isoformat(), CI_TARGET_WINDOW_DAYS))`
   — the rollup's own day set, by the rule `append_event` used to write them (P8).
3. It hands that list to `metrics.ci_waste_numbers(ci, conv or DEFAULTS)` and yields one signature
   per number whose `verdict` is `'over'`, keyed by `CI_TARGET_SIGS[key]`. A `verdict` of `'ok'`
   or `'no verdict'` yields nothing at all — a floor that is not met is silence, never a Bug
   saying the number could not be computed.
4. Each info dict is shaped exactly as §2.5 fences it: the title naming the percentage, the window
   and the target, with `(gh-actions)` from the number's own `provider` and dropped entirely when
   the product names none (P6); `'severity': 'S3'`, `'found_in': 'ci'` (P13), `'runs': []`,
   `'refile_days': CI_TARGET_REFILE_DAYS`; and evidence — the window line first (`<first> … <last>:
   760 of 4210 runner-minutes cancelled (18 %), target 15 %, provider gh-actions`), then the split
   line (`by lane: …` / `by job: …`), then one line per day with runs, oldest first, from `by_day`.
   The evidence is rebuilt from the window as it stands on every run (§1.4), so each bump writes
   the newest window line into `## History`.
5. `cmd_file_bugs` adds `signatures.update(ci_target_signatures(root, now, conv))` as its fourth
   source, after `rule_violation_signatures`. The `--file-bug-level` hold path already loops over
   every signature (`:240-244`), so a product holding `file_bug` gets these two held too, printing
   `NEEDS OPERATOR: held file_bug on ci waste: red rate`, with no new branch.
6. The module docstring's source list gains "metrics/ci: a tracked waste number whose seven-day
   rate misses its target, at most once a week".
7. `CiTargetBugTests` per T4, over a hand-written `metrics/ci/<day>.jsonl` in a temp record root:
   a window 18 % cancelled and 21 % red against targets of 15 files two Bugs,
   `signature: ci waste: cancelled minutes` and `ci waste: red rate`, `severity: S3`,
   `decided: false`, `found_in: ci`, parented under `conventions.default_bug_epic`, each title
   carrying its percentage, its target and the provider, each body carrying the window line, the
   split line and one line per day with runs; both numbers under target files nothing; the window
   under its floor files nothing; only the red rate over target files e
