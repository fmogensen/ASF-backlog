## Description
stories: S-36751
writes: asf/debug_toggles.py, asf/doctor.py, tests/test_doctor.py
after: Task 1

The spec's §2.4 in full. After this lands, an operator running `asf doctor` reads which globs the
gate checks, how many markers, and the waiver — and reads a **red** row when a product declared
the block and left it checking nothing, which is the one way a session can switch this gate off by
accident and never hear about it.

**Read PD2 before writing the first assertion.** §3.5's filter indexes the wrong element of the
row tuple: the doctor's product rows are `(label, required, ok, detail)` and the label is `r[0]`.
Written as the spec writes it the filter is `[]` for every product and the test cannot see its own
row.

`findings` lands here, **with its reader**, so nothing ships a row nobody prints — that is Story
2's own sentence, and it is why this Task writes `asf/debug_toggles.py` as well as `asf/doctor.py`.
Keep `required=False`, the third element of the append, exactly as the `customer content` row beside
it does: a product that means to narrow or switch the gate off is not misconfigured, it is
configured, and the red is for the block that names no paths at all.

**Files**

- `asf/debug_toggles.py` — `findings(product)` appended to the module Task 1 created, mirroring
  `customer_content.findings`'s shape (`:269-297`): read `getattr(product, 'conventions', None)`,
  emit one `(False, …)` per `markers` entry that does not compile naming the pattern, then the one
  row — `(False, 'conventions.debug_toggles names no paths — no branch is checked for a
  switched-off test, breakpoint or debug flag')` when `paths(conv)` is empty **and the block was
  declared** (D8), else `(True, '<globs> · <n> marker(s) · waiver: …')`. An absent block is the
  green row naming the defaults: `configured(conv)` is the discriminator, and `paths()` already
  returns the defaults for an absent key and `[]` for a declared `paths: []` (Task 1). One row,
  plus one per bad marker — §2.4's table is the full enumeration.
- `asf/doctor.py` — §2.4's three lines, beside the `customer content` row (`:875-877`): the
  inline `from asf import debug_toggles` with its comment, the `for ok, detail in
  debug_toggles.findings(product):` loop, and `rows.append(('debug toggles', False, ok, detail))`.
  Inline import, as `customer_content` is at `:875` (PD9).
- `tests/test_doctor.py` — one new class beside `TestCheckClockSteps`, subclassing bare
  `unittest.TestCase` (PD8), with §3.5's four products: no block (green, naming the defaults and
  the marker count), a narrowed `paths` (green, naming them), the block with `paths: []` (red,
  naming `conventions.debug_toggles`), and a marker that does not compile (red, naming the
  pattern). Each asserted as `[r for r in rows if r[0] == 'debug toggles']` (PD2), reading `row[2]`
  for ok and `row[3]` for the detail. Where a case goes through `doctor.run`, follow the shape the
  module already uses at `:349-354` — `mock.patch.object(doctor, 'check_config', …)`,
  `check_cli_sessions` and `check_drift` — and write no absolute path into the file.

   a row appended after `customer content` cannot disturb).
3. The four cases in `tests/test_doctor.py`, with PD2's index.
