**Files**

- `tools/check_generic.sh`
- `.githooks/pre-commit`
- `.githooks/pre-push` (new, tracked)
- `tests/test_check_generic.py`, `tests/test_install.py`

**Steps**

1. `tools/check_generic.sh` keeps its usage (`[--extra <file>]`), its exit codes (0 clean, 1 found,
   2 usage or missing list) and its final `check_generic: clean` line. Its body becomes
   `PYTHONPATH="$HERE/.." python3 -m asf.redact --tree --names "$PATTERNS_FILE"
   ${EXTRA_FILE:+--names "$EXTRA_FILE"}`, run from the repo root, with its own messages around it.
   The one difference a reader sees: a finding prints `file:line: name (tools/forbidden-names.txt)`
   and not the offending line (D8). Its callers — `.githooks/pre-commit` and
   `tests/test_check_generic.py` — keep working unchanged (D11).
2. `.githooks/pre-commit` keeps the suite and `check_generic.sh`, and adds
   `python3 -m asf.redact --pre-commit` — the staged lines against every source, including the pool
   accounts and the private list, which the tree check does not load without `--extra`.
3. New tracked `.githooks/pre-push` running `python3 -m asf.redact --pre-push`, with the same
   `unset GIT_DIR GIT_WORK_TREE GIT_INDEX_FILE` preamble as `pre-commit` (the three names are
   `hermetic.GIT_HOOK`). Per P4 that preamble is symmetry with `pre-commit`, not a suite this hook
   runs; it is harmless because `--pre-push` reads refs from stdin and `git rev-list`, never the
   index. The hooks `asf hooks install` writes do **not** carry it — see D12.
4. `tests/test_check_generic.py`: every existing test passes unchanged, plus
   `test_a_finding_prints_file_and_line_not_the_word`.
5. `tests/test_install.py`: add `test_the_tracked_pre_push_hook_refuses_an_unpublished_secret`; the
   existing `test_pre_commit_hook_runs_the_suite_without_the_git_hook_environment` keeps passing.
