## Description
stories: S-80806
writes: asf/flake.py, tests/test_ci_red_class.py
after: none

The one-run rule is a stand-down on every real head: a head carries checks from more than one
workflow, so `infra_class` answers None on the very incident the card describes (P7). This Task
replaces it with a loop over the run ids the links name, each throttled by its own record, and is
the change the gate and the land probe read their answer through — which is why it lands first and
alone.

**Files**

- `asf/flake.py` — `_run_ids` new, module level, beside `_ids` (`:203`); `infra_class` (`:361`)
  rewritten to the spec's §1 body. `classify_red` (`:272`), `_lost_job` (`:265`), `run_jobs`
  (`:338`), `infra_rerun` (`:298`), `INFRA_CLASSES` (`:257`), `_UNFINISHED` (`:259`),
  `PHANTOM_PROBE_S` (`:358`), `load` (`:154`), `save` (`:179`) and `status_cell` (`:713`) are not
  touched — the spec's Out, and `status_cell` is Task 4's.
- `tests/test_ci_red_class.py` — the `GH` stub (`:54-73`) gains per-run answers; `TheOneAnswer`'s
  two-run assertion (`:91-92`) is replaced; the reader cases of S-80806 are added. `TheClassifier`
  (`:28-51`) is not touched.

**Steps**

1. `_run_ids(checks)` → the run ids behind `checks` in first-seen order, no duplicate: a list, not
   the landed set comprehension, because the order is the answer's tie-break. A member that is not
   a dict is skipped rather than raising, and the link is read `link` → `html_url` →
   `details_url`, the landed chain — the gate's `pr_checks` items carry `link`
   (`asf/harvest/lane.py:5356`) and the land path's `check_runs` items carry `html_url`, so both
   are needed. A check whose link carries no readable run id is skipped and contributes nothing,
   where the landed `None in rids` test kills the answer for the whole head.
2. `infra_class(slug, checks, required=None, gh=None, state_dir=None, now=None)` keeps its
   signature and its return shape `(class, run id, attempt)`. With `state_dir`: one `load` at the
   top, one `save` at the end, and per run id a `probe|<rid>` record — a run whose record is
   inside `PHANTOM_PROBE_S` is skipped with `continue`, never a return, and the remaining runs are
   still read (**PD6**). The record is stamped before the run is read, so a read that answers
   nothing still spends the interval.
3. Per run id: `run_jobs(slug, rid, gh)`, `continue` on an unreadable run, then
   `classify_red(run, jobs, required)`; the first class in `INFRA_CLASSES` is the answer and the
   loop `break`s — one head, one answer, one re-run (C5). `required` is passed whole to every run:
   a required job missing from *this* run is what makes that run a phantom.
4. Keep the `run_attempt` read and its `(TypeError, ValueError)` fallback to `1` exactly as landed.
5. Rewrite the docstring to say what it now does and why (C3), replacing "the one workflow run
   behind `checks`" and "checks from two runs" — the landed text states the rule this Task deletes.
6. The `GH` stub: accept a `{run id: (run, jobs)}` map beside the one-run form it has, so run 78
   can answer a test red while run 77 answers a lost runner, and the four other cases of
   `TheOneAnswer` keep their constructor and do not move (**PD8**).
7. Replace `:91-92` with the two cases S-80806 names — one infra run beside a green run's check
   answers the infra one, and two infra runs answer the first in check order — and add the order
   case, the `_run_ids` case, the skipped-link case, the per-run `probe|<rid>` case, the
   stop-at-the-first case, the interval cases, and the one that reads a throttled run beside an
   unthrottled one. Eleven of S-80806's sixteen lines are this Task's; the last five are the
   land path's and Task 3's.
