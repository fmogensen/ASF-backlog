## Description

The spec's command, `report.py` and `merge_branch`-adjacent CLI bullets, and `## The design` §7. The
five Tasks before this one built a pass with no way to run it; this one gives it a command, a table
and a read-only default.

**Read-only unless `--apply`** (D6). The card's own requirement is *"a dry-run table first"*, every
destructive pass in this factory is already opt-in, and a command whose first run could close 36 pull
requests and rewrite hundreds of cards must not write because someone forgot a flag. `--dry-run` is
accepted as the explicit spelling of the default, which keeps the card's own CLI text valid and costs
one line.

Read **PD6** (§7 gives the parser rows and no dispatch arm — the command would parse and do nothing,
and no test in the suite would notice), **PD13** (the pass lives in `run.py`, not `__init__.py`) and
**PD10** (`close_pr` does not honour `dry_run`, so the `--apply` branch is the only guard, with
`mutation_guard` as the backstop) before starting.

**Files**

- `asf/backfill/run.py` — **new** (PD13): `backfill_pass(...)` and `cmd_backfill(args, root)`
- `asf/backfill/report.py` — **new**: the one code-generated table
- `asf/cli.py` — the four parser rows of §7 in `build_parser` beside `p_ingest` (`:222-224`), **and**
  the dispatch arm beside `ingest`'s (`:494-496`), shaped on `groom`'s (PD6)
- `asf/surface.py` — the `backfill` row in `COMMANDS` (`:27`)
- `tests/test_cli.py` — the `backfill` parser cases
- `tests/test_backfill.py` — `DryRunAndApply`

**Steps**

1. `asf/backfill/run.py`: `backfill_pass(product, root, items, apply=False, since=None, out=print)`
   — gather through `read.py`, map through `history.landings`, decide through `prs.disposition`, and
   then, **only when `apply`**, write through `apply.type_landings` and `apply.unretire` and act
   through the two lane hand-offs. Returns the counts the table prints. One function, one order, no
   second path: the dry run is the same pass with the writers not called.
2. The read-only default is held two ways, not one. The call sites branch on `apply`; **and** the
   whole pass runs inside `with mutation_guard.active():` when it is false, so a mutating `gh` or
   `git push` refuses on its own even if a call site forgets to thread the flag
   (`asf/mutation_guard.py:34-45` — a context manager that nests safely). That is the structural
   backstop the module exists for, and PD10 is why it is not optional: `Lane.close_pr` has no
   `dry_run` test of its own.
3. With `--apply`, the card writes go through `stage.guarded(root, 'backfill', …)` (P13, D13) — the
   writer name is already `WRITERS[0]` and measured to have no caller, and first is exactly the
   position this design needs: type the answers, then let `ingest` derive from them in the same record
   step. An invariant violation refuses that writer's paths and leaves the rest of the record
   committable, its findings draining into Bugs through `stage.REFUSED` as ever.
4. `asf/backfill/report.py`: the table of §7, one code-generated block, printed either way and
   written to `backfill/<date>.md` in the record **only with `--apply`**. Follow `groom`'s idiom for
   the dated file (`asf/groom/groom.py:1236-1241`: join the dir, `os.makedirs(..., exist_ok=True)`,
   write). The block carries, in the spec's order and wording: the merge count, the pull-request
   count and **whether any page was truncated** (D12, P12 — the whole reason backfill pages its own
   list is that `pr_list`'s `--limit 300` truncates silently, so the count must be visible); the
   landings; the un-retired; the dispositions by count; and the residue rows. Without `--apply` the
   last line is `nothing written — run again with --apply`.
5. The residue block carries **one row per unmatched merge and per un-un-retired Feature** — the
   merges Task 2 returned as `Unmatched`
