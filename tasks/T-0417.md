§2.4. GitHub's own path, a forge convention, not a product's. Nothing else in the repository reads
these files, so this Task needs nothing landed and starts at once.

**Files**

- `.github/ISSUE_TEMPLATE/bug.yml`, `idea.yml`, `install.yml`, `config.yml`
- `tests/test_feedback.py` — new: `TemplateTests`

**Steps**

1. `bug.yml` — title prefix `bug: `, labels `feedback` and `bug`; fields: what happened, what was
   expected, `asf --version`, and the doctor row if any.
2. `idea.yml` — title prefix `idea: `, labels `feedback` and `idea`; fields: what you wanted to
   do, why the factory cannot do it today.
3. `install.yml` — title prefix `install: `, labels `feedback` and `install`; fields: the OS and
   version, the command run, the output, `asf doctor`'s failing row.
4. `config.yml` — `blank_issues_enabled: false`, and one contact link pointing a question at the
   public record.
5. Every field is `required: true` except the optional doctor row, so an issue that reaches the
   intake carries the four facts the intake needs. **No field asks for a name, an account or a
   path** — the record is public and `tools/check_generic.sh` forbids those tokens (D5).
6. `TemplateTests`: the four files parse; each form carries `feedback` plus its own label; blank
   issues are off; no field label, description or placeholder asks for a name, an account or a
   path. The parse uses the same yaml reader the rest of the suite uses, and the test says so
   rather than hand-rolling one.

**Gate**

```sh
python3 tools/run_tests.py 2>&1 | tail -3
```

**Acceptance**
