The spec's fifth and sixth **In** bullets and the `asf/doctor.py` block: two new problem strings, one
new green clause, the factory's own exemption (D9), and the operator-facing text that carries the
remedy. The doctor reads files and executes nothing (the spec's **Out**).

**Files**

- `asf/doctor.py` — `check_redaction_hooks`'s two new branches and its green detail
- `tests/test_doctor.py` — `RedactionHooksEntryPointTests`, and `:292`'s green-detail equality
- `docs/guide/troubleshooting.md` — a row for each new finding
- `docs/guide/getting-started.md` — the hooks step at `:64-65`

**Steps**

1. `check_redaction_hooks` keeps its shape — the repo list, the not-a-git-repo problem, the missing
   hook, the `asf init` older-form branch, the foreign branch — and gains, for each hook that is
   ours, the spec's two branches: `{path} names {entry}, which is not an executable asf` when
   `hook_entry` answered and the path is not an executable file, and `{path} names an editable
   install ({checkout})` when `entry_point_source` says `editable` and `is_factory_repo(product)` is
   false (D9, P16). A `None` entry (PD5's bare form) and a `None` source add nothing — neither a
   problem nor a claim.
2. The remedy the detail ends with becomes `— asf hooks install --product <p>, run from the install
   the hook should name`. `tests/test_doctor.py:284` asserts `asf hooks install --product sample` by
   containment, so it still holds.
3. The green detail gains the factory clause: `pre-commit, pre-push in <n> repos (editable install:
   this product is the factory's own source)` when `is_factory_repo(product)` and any hook's source
   is editable; otherwise `pre-commit, pre-push in <n> repos`, unchanged. `tests/test_doctor.py:292`
   asserts that string for equality and its fixture is not the factory, so it stays as it is — the
   new clause gets its own case.
4. The row's name, its position in the table (`asf/doctor.py:833-834`) and its `required` flag are
   untouched, so every consumer of the doctor table reads it as before. `asf/hooks.py`'s own
   identical green string is not this Task's and is not touched.
5. `RedactionHooksEntryPointTests`: a product whose hooks are written by `ensure_git_hooks`, then —
   the entry point deleted, giving the `not an executable asf` problem and a red row; the entry point
   pointed at an editable fixture install, giving the `names an editable install (<checkout>)` problem
   and its checkout path; the same editable hook with `is_factory_repo` true (patched the way the
   module's existing tests patch it, or a product whose `repo_dir` is the package root), green and
   carrying the factory clause; a `#!/bin/sh` stub whose source is unreadable, green and saying
   nothing about the install; and `asf init`'s bare-form record hook, green and untouched. One case
   asserts the row is still red-for-foreign and still never writes a hook file — `check_redaction_hooks`
   is read-only and the fixture's bytes are compared before and after.
6. `docs/guide/troubleshooting.md`: the redaction-hooks table gains a row for each new finding —
   `<hook> names <path>, which is not an executable asf` and `<hook> names an editable install
   (<checkout>)` — each with the same remedy: rerun `asf hooks install --product <p>` *from the
   install you want the hook to name*. Task 1 already replaced `:43`'s refusal row; these are new
   rows beside it, and `:45`'s foreign-hook row is unchanged.
7. `docs/guide/getting-started.md:64-65`: the `asf hooks install` step gains one clause — each hook
   names the install that ran the command, so run it from the install the product's gate should use.
   The step's other two bullets (the approvals hook, the rule-card hooks) are unchanged, and the
   `pipx install --force` paragraph at `:60-61` is not touched.
