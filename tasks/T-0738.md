## Description
stories: S-38950, S-38951
writes: asf/record/plan_tasks.py, tests/test_plan_tasks.py, tests/test_doc_lane_landing.py
after: none

The spec's §*The design* 1 and 2, and nothing else. After this Task an undecided Feature whose only
id carrier is its plan's own H1 mints its `### Task N:` cards, and every Feature whose plan is on
the trunk and mints nothing prints one line saying which plan was found and why.

The two scope items are one Task because they collide on one line and share one test module — see
the note at the top of this plan. Read **PD2** and **PD3** first: PD2 is why the implementation must
be `plan_alias` by path and not `fev['alias']`, PD3 is the only fixture shape that can tell the two
apart. Read **PD7** before the first edit — another card's Task may be rewriting `_mint` around you.

**Files**

- `asf/record/plan_tasks.py`
  - New module-level `plan_alias(ev, path)`, above the gate, exactly the spec's snippet: iterate
    `ev['features'].values()`, return the `alias` of the first entry whose `_path_only(f['plan'])`
    equals `path`, else None. `_path_only` is imported inside the function, as the spec writes it —
    `plan_tasks` already imports `is_retired` and `match_feature` from `ingest` at module level
    (`:23`), so a top-level import is also possible; keep the spec's form, the local import is what
    the design snippet pins. No sort, no tie-break (**PD6**).
  - `own_lane_plan` (`:52`) → `own_plan`, docstring restated as the spec writes it. Routes one and
    two unchanged byte for byte; route three replaces the bare `return` of route two with
    `if path in …: return True` and a final
    `return str(plan_alias(ev, path) or '').upper() == fid.upper()`.
  - `_mint` (`:73`): `plan_path = ref.split(':', 1)[1] if ':' in ref else ref` moves from `:102` to
    immediately after the `if not ref: continue` at `:92-93` — the value is identical, it is only
    computed earlier so the two new lines can name it. Delete the old `:102`.
  - `_mint`'s `:97` gate becomes `and not own_plan(fid, ref, ev)`, and its `continue` grows a line
    above it:
    `out(f'plan-tasks: {fid}: {plan_path} is on the trunk but names {fid} nowhere — not decided, so nothing minted')`.
  - `_mint`'s `:100-101` `if not text: continue` grows a line above it:
    `out(f'plan-tasks: {fid}: {plan_path} could not be read — nothing minted')`.
  - `:105` and `:122` are **not touched** — they are pinned to the byte by
    `tests/test_plan_tasks.py:96` and `:85`. The `continue` at `:92` stays silent (**D7**), as do
    `has_task_child`, `DONE_STATES` and `is_retired` above it.
- `tests/test_plan_tasks.py` — two new classes, no edit to `PlanTasksTests`.
  - `class HeaderRoute` — the S-38950 unit fence, over a synthetic `ev` in the shape
    `{'features': {'thing-plan': {'plan': 'origin/main:docs/plans/2026-09-25-thing-plan.md',
    'plan_on_main': True, 'spec_on_main': True, 'alias': 'F-0001'}}}` against the existing
    `PlanTasksTests` record helpers (`write_item`, `read`, `FOLDERS`):
    `plan_alias` returns the alias of the entry whose plan path matches and None for a path no entry
    carries; `own_plan` is True for the header route and False for an alias that is another id
    (`'M3'` — D2's floodgate, the exact case `tests.test_doc_lane_landing` asserts end to end);
    `own_plan` is still True for an id-named file whose entry has **no** alias at all (route one is
    not made to depend on route three); and `mint_plan_tasks` over an **undecided** F-0001 with that
    `ev` mints `T-0001`, `T-0002` with `links.plan` the dated path and one `2 Task(s) from
    docs/plans/2026-09-25-thing-plan.md` line. Measured against this tree with the spec's snippet
    monkeypatched in: today `own_lane_plan` is `False` and the mint is `([], [])`; with the third
    route it is `True` and `(['T-0001', 'T-0002'], …)`.
  - `class SkipsSayWhy` — the S-38951 fence. For a Feature whose `plan_ref` is set, each of the four
    outcomes produces **exactly one** line
