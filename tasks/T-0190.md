## Description
stories: S-18104, S-18105
writes: asf/chores.py, asf/cli.py, tests/test_chores.py
after: none

The spec's §2.6 and §2.7. One leaf module and one command. It imports `asf.env`,
`asf.redact` and `asf.workers.quota`, and nothing imports it yet — the hook wiring is Task 4's
(PD9), so this Task adds no boundary and changes no running behaviour. It names no product, no
`.claude/` path and no `tools/*.sh` path: every path comes from `env.log_dir()` and the product's
own directories at match time, which is what T11 checks.

**Files**

- `asf/chores.py` — **new**. The module docstring of §2.6, naming F-0035, "a controlling session is
  one with no `ASF_JOB`" and why the recorder cannot refuse a call.
  - `LEDGER_DAYS_KEPT = 60`, `CMD_MAX = 400`, `class ChoresError(Exception)`.
  - `ledger_path(day=None)` → `<ASF_HOME>/chores/<YYYY-MM-DD>.jsonl`, from `env.ASF_HOME` —
    product-less, because the controller spans products (§1.4).
  - `record(stdin_text, environ, now=None)` — one line for a `Bash` call in a controlling session,
    returning 0 always, including for a call it decided not to record and for an unwritable
    directory.
  - `read_days(days=1, now=None)` → the rows of the day files in the window, oldest first; a
    malformed line is skipped, not raised.
  - `COVERED` and `IGNORE` exactly as §2.7 writes them, with the comment saying `{logs}`,
    `{record}` and `{repo}` are expanded at match time and never written as literals.
  - `load_map(cfg, product=None)` → the compiled `(name, regex, use, table)` tuples and the
    compiled ignore list, with `chores.covered:` laid over by name (`name: off` drops one, a new
    name appends) and `chores.ignore:` appended; every regex case-insensitive; one that does not
    compile raises `ChoresError` naming it, so the whole call refuses rather than silently
    matching nothing.
  - `normalise(cmd)` — quoted strings, numbers and absolute paths replaced by `·`, so
    `tail -n 40 <log-a>` and `tail -n 80 <log-b>` are one chore.
  - `classify(rows, cfg=None, product=None)` → `{'covered': [Chore], 'repeated': [Chore],
    'own': [Chore], 'ignored': n}`, with `Chore` carrying `count`, `cmd`, `use` and `table` — the
    four fields §2.8's script reads. An `IGNORE` match is counted and in no list (R-0122).
  - `controller_account_name(cfg)` → `(cfg.get('controller') or {}).get('account')` — the name
    only; the match against `worker_pool.accounts` is `asf/hooks.py`'s (PD18).
  - `window(cfg)` → `(seven_d_pct or None, window_cap)` from `quota.source_from_config(cfg)` read
    for that account and `chores.window_pct` (default 60). An unconfigured `quota_command` reads
    0, a failing one reads `None` (PD16).
  - `render(result, day, days)` — the table of §2.7, header line and one line per row.
  - `cmd_chores(args)` — the table, or `--json` carrying
    `{'day', 'days', 'total', 'covered', 'repeated', 'own', 'ignored', 'window_pct',
    'window_cap', 'account'}` (PD17).
- `asf/cli.py` — `p_chores = sub.add_parser('chores', …)` beside `p_stale` (`:134`), with
  `--days` (int, default 1), `--json` and `--product`; and the dispatch beside `stale`'s
  (`:332`): `from asf.chores import cmd_chores; return cmd_chores(args)`. No record root — the
  ledger is under `ASF_HOME` and the config is the operator's.
- `tests/test_chores.py` — **new**: `LedgerTests` and `ClassifyTests`, on a temp `ASF_HOME` and
  synthetic ledger lines, no repo and no subprocess.
