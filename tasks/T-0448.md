The spec's §5 steps 1, 3, 4 and 5 against the source record, plus the declared surface (P19). One
command, one signed-off commit through `_published` (P3), every card through P2's writer, nothing
written at all if any one card would not come back as asked (D10). `--to` is Task 5's (PD8).

**Files**

- `asf/record/move.py` — new module: `add_arguments`, `select`, `check`, `table`, `cmd_move`
- `asf/record/setfield.py` — `set_typed`'s `apply=True` keyword (PD9)
- `asf/cli.py` — the `move` subparser and its `_published` dispatch
- `asf/surface.py` — the `move` row
- `tests/test_move.py` — new module: `BulkRemoveTests`, `SelectionTests`, `DryRunTests`
- `tests/test_surface.py` — the count literal, 49 → 50

**Steps**

1. `asf/record/setfield.py`: `set_typed(rec, updates, writer='set', apply=True)`. With `apply=False`
   the scratch render and the round-trip loop run exactly as now and the function returns their reason
   or `None` **before** `record_root`, `stage.guarded` and the `rec['text']` assignment — nothing on
   disk, nothing in the loaded record (PD9). The docstring gains one sentence saying so. Every existing
   caller is unchanged.
2. `asf/record/move.py`: module docstring — what the command is for (an adopted record holding another
   product's cards), that it writes both fields `asf set` refuses on purpose and why that is safe here
   (a closing with a reason, through the parser, all or nothing, in one commit).
3. `add_arguments(p)`: positional `ids` (`nargs='*'`), `--query` (`action='append'`,
   `metavar='FIELD=VALUE'`), a required mutually exclusive group holding `--remove REASON` (Task 5 adds
   `--to`), `--product`, `--dry-run`.
4. `select(items, ids, queries)` (D8, D9): ids and `--query` together is an error naming both; an id
   that names no card is an error naming it; `--query` is an exact string match on one typed field read
   off the loaded items, repeatable and AND-ed. A card already retired (P4) is dropped and counted, so
   a re-run of the same command is a no-op rather than a second write. An empty selection is
   `error: --query belongs_to=acme selects no card` (or the ids' equivalent) and exit 2.
5. `check(selection, updates)` (D10): `set_typed(rec, updates, writer='move', apply=False)` for every
   card, collecting `(id, reason)`. Any reason at all prints one line per refused card and exits 2 with
   nothing written — the check is P2's own render run twice, not a second parser.
6. `--dry-run` prints §5's table (`record:` line, the five columns, the `<n> cards, <n> already in the
   target` footer — the target column is `—` for `--remove`) and returns 0 here, having written
   nothing. `resolve_record`'s own `record: <path>` first line is the command's first line as it is for
   every record command.
7. The write: per card `set_typed(rec, {'removed': reason, 'belongs_to': None}, writer='move')`, then
   the History line `- <date> move: removed — <reason>` appended the way §5's table gives it, through
   this module's own two-line tail (PD10). The whole selection is written in one pass; by step 5 none
   of it can fail here.
8. `asf/cli.py`: the subparser, and the dispatch through `_published` with §5's message —
   `f"move: {n} cards removed"` for `--remove` (the `--to` half of that f-string arrives with Task 5) —
   so the cards, `index.json` and the derived sections are one signed-off, pushed commit (P3). A
   `--dry-run` run goes through the same dispatch and publishes nothing, because nothing changed.
9. `asf/surface.py`: §5's row, byte for byte, in `COMMANDS`; its description opens with `write`, which
   is in `VERBS`. `tests/test_surface.py:49`'s literal becomes 50.
