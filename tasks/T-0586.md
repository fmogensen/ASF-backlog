## Description
stories: S-36603

after: Task 3

The spec's §3 last bullet and its §4. Without this the deferral can livelock: a host with `strict`
on refuses to merge a branch that is behind, and every push that would bring it up to date is
exactly what Tasks 2 and 3 defer — PD7 measures that path to `wait(lane, f, f'merge refused: …')`
and confirms the PR would sit green and unmergeable for ever. One rebase, once, at the end, on a
head whose checks were read green a line above, is the whole of the card's *prefer update at merge
time*.

**Read PD7 before writing the green test** (there isn't one — `recheck` returning None is it) and
**PD8 before choosing a worktree** (the pass already owns one, and `push_branch`'s loss guard is
patch-id based, which is why a rebase may be pushed through it at all). **PD9** is the record.

**What changes for the machine when this lands.** Nothing at all on any product configured here:
P6 measured this product's trunk as unprotected (`gh api …/protection/required_status_checks` →
`404 Branch not protected`), so `_protection` reads `{}`, `protected_strict` is False, and
`update_for_merge` returns without a git command. Where a trunk **is** strict-protected, a green PR
that is behind it is rebased once in the pass's own checkout, pushed over a lease on the head read
before the rebase, recorded `WAITING_CI` at its new head, and merged by the next green pass.

**Files**

- `asf/harvest/lane.py` — `_protection(slug, trunk, state_dir, now=None)`, new; `protected_checks`
  rewritten as a one-line reader over it, **signature and result unchanged**; `protected_strict`,
  new; `update_for_merge(lane, f, number)`, new; one call in `merge_prs` between the `if stale:`
  block (`:2987-2991`) and `lane.set(f, MERGING, …)` (`:2992`). `GitHubHost.required_checks`
  (`:3306`) is untouched — it keeps calling `protected_checks`.
- `tests/test_lane.py` — `UpdateAtMergeTime(LaneFixture)` added. No existing class is touched.

**Steps**

1. `_protection(slug, trunk, state_dir, now=None)` is today's `protected_checks` body
   (`:3635-3664`) with three edits and no others:
   - the cache hit test gains C10's rule — `if isinstance(hit, dict) and 'strict' in hit and now -
     float(hit.get('at') or 0) < REQUIRED_TTL_S: return {'checks': tuple(hit.get('checks') or ()),
     'strict': bool(hit.get('strict'))}`. **An entry with no `strict` key is a miss, not a False**:
     it was written before this card and an hour-old pre-upgrade cache must not answer "not strict"
     for a trunk that is. Write that sentence into the docstring — it is the decision a later
     reader is most likely to undo.
   - `strict = bool(data.get('strict')) if isinstance(data, dict) else False`, off the **same**
     payload `contexts` and `checks` already come from. No second `gh` call: `strict` arrives beside
     them in GitHub's documented response for that path (P6), and a second round trip for a field
     that already arrived is what C10 refuses.
   - the entry written is `{'at': now, 'checks': names, 'strict': strict}` and the return is
     `{'checks': tuple(names), 'strict': strict}`. The file, its name, its TTL and its per-
     `<slug>@<trunk>` key do not change: no new file, no migration.
2. `protected_checks(slug, trunk, state_dir, now=None)` becomes
   `return _protection(slug, trunk, state_dir, now)['checks']` with its docstring kept, and
   `protected_strict(...)` is `…['strict']` with the spec's one-line docstring. The signature and
   the tuple result are unchanged, so `GitHubHost.required_checks` (`:3306`) and every test that
   reaches it are untouched — check that first, it is the cheapest proof the refactor is faithful.
3. `update_for_merge(lane, f, number)` — the spec's §3 docstring verbatim, and this body:
   - `b = f['branch']`; `if lane.dry_run or not lane.repo or not lane.slug: return False`.
   - `if not protected_strict(lane.slug, lane.trunk, lane.state_dir): return False` — the first
