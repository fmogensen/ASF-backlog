and it re-decides none of the bounce (D7).

**Files**

- `asf/harvest/lane.py` — `f['security']`, the `security=` arguments on `f['level']` and
  `f['precheck_faults']`, `f['precheck_dims']`, and the widened guard
- `tests/test_lane_security.py` — `SecurityFactTests`, `RequiredTests`, `BounceTests`

**Steps**

1. Import `asf.security.paths` as `security_paths` beside F-0060's `precheck_mod` import, with the
   one-line comment PD4 of F-0060's plan asks for kept as it is: the older `lane.precheck`
   (`:2443`) is the *merge* precheck and is not this.
2. In `branch_facts`, §2.4's four lines exactly: `f['security'] = security_paths.touched(conv,
   f['files'])` — free, `f['files']` is already in hand (P9, `:1337`); `f['level']` computed with
   `security=bool(f['security'])`; `f['precheck_dims'] = precheck_mod.security_dimensions(
   f['security'])`; `f['precheck_faults'] = precheck_mod.faults(text, f['level'],
   security=f['precheck_dims'])`.
3. Widen F-0060's guard around that block — `code` class and `conv.precheck_required()` — with `or
   bool(f['security'])`, in that one function, with the comment saying why: a class is configured
   *because* it may not land unread, so neither a waiver (`review.precheck: none`) nor a
   `docs`-class diff exempts it (D6). `landing_class` is computed from counts and extensions
   (`:318`), which is exactly why a `.github/workflows/**` change reads as docs and is
   `ci_credentials`.
4. The reason line: `precheck wanted: level high (size class small, floored by sensitive paths:
   auth, billing)` — the level's own `why` from Task 2, with `security_paths.describe`'s class list
   appended by the lane, and no class name spelled in `lane.py`.
5. Nothing else: no new state, no new hold kind, no change to `enter_back`, to `same_finding` or to
   the `finding:` keys (§1.2, D7). A missing class row is already *incomplete* through
   `f['precheck_faults']` and F-0060's `Tq`, capped by `lifecycle.LOOP_CAP` (P5).
6. `tests/test_lane_security.py`, its own file so it does not queue behind F-0060's
   `tests/test_lane.py` (PD14). Over a git fixture with a trunk and a branch, per §3's T3: a branch
   touching no class is asserted unchanged from today at every state, through the same
   `branch_facts`/`next_state` calls with the block unset; a branch touching `auth` gets the
   precheck fact and `Tq` fires **with `review.precheck: none`** and **for a `docs`-class diff**;
   its level is `high` where the footprint alone says `low`.
7. The incomplete case: a precheck answering the level's rows and not the class's keeps the branch
   at `PRECHECK` with `precheck incomplete: dimension not covered: …`.
8. The bounce — the card's second acceptance: a precheck holding a `fail` row at `high` confidence
   sends the branch BACK with kind `precheck`, the hold naming the path, the count and the level,
   and **no review round was launched for that head** (asserted on the rounds the fixture records,
   not on a log line). A precheck whose rows are all `pass` moves on to the round the branch owed.
