## Description
stories: S-37358
writes: asf/capacity.py, tests/test_capacity.py
after: Task 3

The spec's §2.4's first half — `batch_shape` and `batch_detail` — and nothing else. After this lands,
a product that has never tuned its batch shape gets one measured from the census and the run's
expected jobs instead of no shape at all, and the doctor's row names, per key, whether the number
came from the product or from the measure.

**Read PD6 before writing a line.** §2.4 says *"class **online** slots"*. The census record carries
no `online` key and `cached()` returns `PoolEntry` rows that have none either, so the only way to
know online is `backend.runners()` — and `batch_shape(product, cfg)` is called from
`capacity.py:594`, the `ASF_CAPACITY_*` environment every batch step is handed, and from
`harvest/lane.py:3117`. A `gh` round trip at either is exactly what D1 refused for `load_pool`, for
exactly the same reason. §3.6's own arithmetic settles it: the numbers are over the **census's**
slots with no online filter — `min(2//2, 4//4) = 1` and `min(4//2, 8//4) = 2`.

Two things are load-bearing. **The two keys are one shape** (D16): `parallel` and `runners` are
measured only when the product declares **neither**, because measuring one against an operator's
hand-set other produces a pair that was never chosen together, and it is the **pair** a batch run
receives as `ASF_CAPACITY_*` (P6). A product declaring `parallel: 3` gets `parallel` 3 and **no**
measured `runners`. **`per_run` is never measured** (O4): I9 measures capacity facts, and `per_run`
is a *work* count — batches per run, PR merges per run — which no runner reading bounds. A product
declaring `per_run` only still gets both of the others measured.

**Files**

- `asf/capacity.py` — two edits. `batch_shape(product, cfg)` keeps today's body as its first
  clause — only the keys of `capacity.batch` whose value is an `int >= 0` (P6) — and gains one
  branch: when the resulting dict contains **neither** `parallel` nor `runners`, both are measured.
  `runners` is `sum(expected_run_needs(product).values())`; `parallel` is
  `min(slots[c] // n for c, n in needs.items() if c in slots)` floored at 1, where `slots` is
  `ci_pool.slots_by_role(ci_census.cached(product))` — two file reads and **no network** (PD6). With
  no census or no measure, `needs` or `slots` is empty and **neither key appears, exactly as today**
  (P6) — that is the clause every existing caller depends on. `batch_detail(product, cfg)` →
  `(shape, {key: 'product' | 'measured'})`, and the doctor's row §2.4 shows:
  `capacity: batch runners 6, parallel 2 (measured: one full run asks asf-fast 2, asf-bulk 4; the
  pool holds 2)`. The docstring says **census slots**, not "online slots", so the next reader does
  not put the host call back (PD6).
- `tests/test_capacity.py` — one new class, `BatchMeasured`, over a temporary state dir holding a
  census and a queue file the test writes. A product declaring neither key, with a census of 2
  `asf-fast` and 4 `asf-bulk` and a cached measure of `{asf-fast: 2, asf-bulk: 4}`, returns `runners`
  6 and `parallel` 1; with 4 `asf-fast` and 8 `asf-bulk`, `parallel` 2. A product declaring
  `parallel: 3` gets `parallel` 3 and **no** measured `runners` (D16). A product declaring `per_run`
  only still gets both measured (O4). A product with **no census** gets neither key, exactly as today
  (P6). `batch_detail` names the source of every key it returns. And the assertion PD6 exists for:
  `ci_pool.backend_for` is never called and no `gh` process is spawned by any case in the class.
