The spec's `I3` and `## The design` §2 — `KEEP_MAX = 4`, `IN_USE_S = 3600`, and `prune` keeping
exactly `keep ∪ {used within in_use_s} ∪ {the keep_max most recently used}` while removing
everything else however young. Against P7's ~150 landings a day and ~26 MB a worktree, this is the
difference between a steady state of ~24 worktrees and one of ~150 and ~3.9 GB — every one of them
also carried by `git worktree list` in the development checkout.

It waits on Task 1 for the reason in **PD16**, which is the only reason that matters: `prune` runs
inside the installed `launch.py`, so a bound that no launcher carries bounds nothing that is
running. Both Tasks also write `asf/snapshot.py` and `tests/test_snapshot.py`.

`keep_unused_s` stays as the second bound, so a small idle pool still empties when the clock stops.
Read **PD8** (ten launches leave ten, not five — the cap bites only once the markers are past
`IN_USE_S`, and the test must age them), **PD9** (the survivors are computed before anything is
removed, ties broken on the sha) and **PD10** (`keep` is absolute; the age rule never reaches it).

**Files**

- `asf/snapshot.py` — `KEEP_MAX` and `IN_USE_S` beside `KEEP_UNUSED_S` (`:36-37`), each with the
  spec's `#:` comment; `prune`'s signature, docstring and body (`:127-151`); the module docstring's
  step 3 (`:16-17`), which today says only *"prunes the snapshots nothing has used for
  `KEEP_UNUSED_S`"*
- `tests/test_snapshot.py` — `BoundedPoolTests`, a new class built on `SnapshotCase`

**Steps**

1. `KEEP_MAX = 4` and `IN_USE_S = 3600` beside `KEEP_UNUSED_S` (`:36-37`), with the spec's `#:`
   comments byte for byte (§1's block carries both). They are module constants and not product
   settings, exactly as Records says: a product cannot tune how many worktrees of the factory's own
   source its clock keeps, and none has asked to.
2. `prune`'s signature becomes the spec's, byte for byte:
   `def prune(repo, code_dir, keep=(), now=None, keep_unused_s=KEEP_UNUSED_S, keep_max=KEEP_MAX, in_use_s=IN_USE_S):`
   — both new arguments keyword-with-default, so `ensure`'s call (`:181`) needs no change and every
   existing caller keeps working.
3. `prune`'s docstring becomes the spec's §2 block byte for byte: what survives, that everything
   else goes *however young*, why age alone is not a bound at ~150 commits a day, and that
   `keep_unused_s` stays the second rule so a pool under the cap still empties.
4. The body, in the shape PD9 requires. First pass over `sorted(os.listdir(code_dir))`, unchanged in
   its filters — `continue` on a name that is not a sha **or is in `keep`** (`:133`, PD10), then
   `used` from the marker's mtime or the directory's when there is no marker (`:137`), then
   `continue` on `OSError` (`:138-139`) — collecting `(name, used)` pairs instead of deciding.
   Then `survivors = {n for n, u in pairs if now - u < in_use_s} | {n for n, _ in sorted(pairs, key=lambda p: (p[1], p[0]), reverse=True)[:keep_max]}`.
   Then the removal loop: remove when `name not in survivors or now - used >= keep_unused_s`, through
   the existing `_remove` and the marker unlink (`:142-145`), appending to `removed`. The
   `git worktree prune` when anything went (`:146-150`) is unchanged, so the registrations leave the
   operator's checkout with the directories.
5. `keep` is never removed under any combination (PD10): it is skipped in the **first** pass, before
   `survivors` or the age rule is consulted, so no ordering of the three bounds can reach it. Note in
   a comment that `ensure` passes `keep={sha}` and that sha is the one the launch is about to
   `execve` into.
6. The module docstring's step 3 (`:16-17`) gains the count bound beside the age one, and keeps the
   existing parenthetical about a long tick keeping the previous snapshot — which is now the
   `in_use_s` grace and is worth naming as such.
