## Description

The spec's fourth **In** bullet and `## The design` §3's `delivered(run)` and its three-row table.
This is the Task that makes three shipped mechanisms — `settled` (B-0128), `overruling` (B-1377) and
`review_answered` (B-0149) — reachable in production for the first time, and it proves each one
through the arm that actually reads it: the feeder's no-second-adjudicate row and the lane's two
review arms. It waits on Task 1 for `NOTHING_TO_LAND`; it shares no file with Task 3 and runs beside
it.

**Files**

- `asf/workers/lifecycle.py` — `delivered(run)`, directly after `finished` (`:542`); the three call
  sites, `_settling_run` (`:614`), `overruling` (`:670`), `review_answered` (`:2116`)
- `tests/test_lifecycle.py` — `DeliveredReadersTests`
- `tests/test_harvest.py` — `RuledOnThisHeadTests`
- `tests/test_feeder.py` — `NoSecondAdjudicateTests`

**Steps**

1. `delivered(run)` directly after `finished` (`:542`), with the spec's docstring and body byte for
   byte:

   ```python
   def delivered(run):
       """Ended with its work delivered: :func:`finished` — pushed commits — or
       :data:`NOTHING_TO_LAND`, a deliverable the branch cannot show (F-0157). What a reader asking
       "did this session do its job" wants; :func:`finished` alone means "and it is on the branch"."""
       return finished(run) or (bool(run) and bool(run.get('ended'))
                                and run.get('end_reason') == NOTHING_TO_LAND)
   ```

2. `_settling_run` (`:614`): `finished(r)` → `delivered(r)`. Nothing else in that comprehension
   moves — the `kind == 'adjudicate'` clause and the `started >= at` clause stay.
3. `overruling` (`:670`): `finished(r)` → `delivered(r)` in the `ruled` comprehension. Every gate
   below it — `status != 'done'`, a non-empty `ruling`, no `blocked_on`, no `superseded_by`, the
   `pushed:` sha, the `commits: none` + `launch_head == head` clause at `:685-687`, the
   `unchanged_since` clause — stays byte for byte. `:685-687` is the clause this whole card exists
   to make reachable; do not touch it.
4. **PD3 — read it before this step.** `review_answered` (`:2116`) is not a `finished(` call.
   The line is `if r.get('kind') == CORRECT and r.get('end_reason') == FINISHED \` and becomes
   `if r.get('kind') == CORRECT and delivered(r) \`. The `quota_exhausted(r)` clause and the
   `launch_head == head` clause on the two lines below it stay byte for byte.
5. **Three sites, and no others.** Every other `finished(...)` in `asf/` is asking about the branch
   and keeps asking — `eligible` (`:551`) above all, which is B-0076's own guard and must keep
   meaning *pushed commits* (P11). Do not grep-and-replace.
6. `DeliveredReadersTests(unittest.TestCase)` in `tests/test_lifecycle.py`, over a registry the class
   writes itself. One case per reader, each written so it **fails before this Task** and passes
   after — that is what "proved reachable" means here:
   - `settled`: an item held, then an `adjudicate` run started after the hold that ended
     `NOTHING_TO_LAND` with a `status: done`, `commits: none`, `ruling:` report. Assert
     `_settling_run` finds it and that the correction the readers see carries `settled`. Assert the
     same run ended `failed: empty branch: nothing to land` is **not** found — the before-picture;
   - `overruling`: an adjudicate run ended `NOTHING_TO_LAND`, `commits: none`, whose `launch_head`
     is the head asked about, with no `pushed:` sha in its report at all. Assert `overruling`
     returns its job — this is the `:685-687` clause, and it is unreachable without `delivered`.
     Assert the `pushed:`-sha path and the `unchanged_since` path still work unchanged;
   - `review_answered`: an item whose latest `REVIEW` correction names a review path, then a
     `correct` run started after it, launched on the head, ended `NOTHING_TO_LAND`. Assert its job
