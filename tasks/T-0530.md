The spec's fourth and fifth **In** bullets, `## The design` §`asf/workers/stall.py` and the three
remaining rows of §*The prose that states the old rule*. `stall.classify` opens with the same
assumption `judge` just lost (P17), so a process `settle_quiesced` could not kill is today invisible
to `STALL`, `DEAD` and `STUCK` alike — and D7's whole answer to *"what if it survives SIGKILL"* is
that row. It waits on Task 2 because it is the operator's channel for the state Task 2 creates, and
because both write `tests/test_workers.py`.

Read **PD8** (a `STALL` row cannot relaunch anything — the measurement D7 rests on) and **PD9** (the
`progress:` write stays where it is) before touching `stall.py`. **PD12** is why this Task adds a
test class to `tests/test_readme.py` rather than just editing the guide.

**Files**

- `asf/workers/stall.py` — `classify` (`:79-93`): its docstring and the order of its four tests
- `asf/tick/step_health.py` — the docstring's second line (`:3-4`)
- `docs/guide/operating.md` — the `health` step row (`:20`); the *"holds a slot"* paragraph and the
  list under it (`:149-155`)
- `tests/test_workers.py` — `TestStall` (`:2230`)
- `tests/test_readme.py` — `SessionLivenessProseTests`

**Steps**

1. `stall.classify` becomes the spec's body byte for byte (D8, D9): `read_result` first but no longer
   returning; `if not alive(pid): return None if result is not None else 'DEAD'` — a pid **gone**
   after a result is `finished_unrecorded`'s state awaiting health's tick (P5), never `DEAD`, which
   is what today's first line already produces and must keep producing; the cloud exemption next,
   unchanged (P18); then `if result is not None: verdict = None` (D9 — `STUCK` asks whether a session
   is moving and a run that has written its result is not trying to, and its 20-minute limit would
   otherwise fire before `silent_min`'s 30 and send an operator after the wrong thing); then the
   `getmtime` silence test and the `STUCK` fall-through, both unchanged.
2. Its docstring gains the spec's paragraph byte for byte — the gone-after-a-result case, the
   alive-after-a-result case, and the sentence that a closed run is judged by silence alone.
3. Nothing else in `stall.py` moves. The progress sampler and the `progress=` write above the
   `classify` call (`:132-139`) stay exactly as they are (PD9), and `stall()`'s row handling, its
   `STALL`/`STUCK` print lines and `stop_session` are untouched.
4. `asf/tick/step_health.py:3-4`: *"ends the sessions whose pid is gone — on a result, or on nothing
   at all (`dead pid`) — and stops a process that wrote its result and will not exit"*. Docstring
   only: `dead_jobs` and `correct_once` are untouched, because `STALL` never reached them (PD8).
5. `docs/guide/operating.md:20`'s `health` row: *"end the sessions whose process is gone, stop one
   that will not exit"*, keeping the rest of the row and its `typical lines` cell as they are.
6. `docs/guide/operating.md:149`: the paragraph keeps its sentence and its three-item list, and gains
   the rule an operator reads a session state by — a session that wrote a result but whose process is
   still up **is** still working and still holds its slot; health stops it after five quiet minutes
   and records the end then. The **Working** and **Finished** rows at `:143-144` already say exactly
   this (P6) and are not edited.
7. `tests/test_workers.TestStall` gains one case per clause of the spec's fence: a pid gone after a
   result is **not** `DEAD` (and still not `STALL`); a live run with a result whose log has been
   silent past `silent_min` is `STALL`; the same run inside the limit is `None`; a live run with a
   result and a `STUCK` progress verdict is **not** `STUCK` (D9); a live run with **no** result and a
   `STUCK` verdict still is, so the suppression is scoped to a closed run;
