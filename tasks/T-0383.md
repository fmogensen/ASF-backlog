**Steps**

1. `ci_queue.stalled_runs(product)` — §2.7: `{run id: {'job': …, 'step': …, 'at': …}}`, read off
   the product's queue file once, from the `relief` records carrying `stall` and from the `stalls`
   history Task 4 writes (the relief record leaves the file the moment it is re-run, and the event
   is written only after the run completes). Never raises: no file, an unreadable file or a product
   with no state dir all give `{}`, the way `rerun_ids` (`:1186`) already answers.
2. `SCHEMAS['ci']` (`asf/metrics/metrics.py:117-123`): `'stall': (('str', 'null'), None)`.
   `JOB_SCHEMA` (`:160-161`): `'stall_step': (('str', 'null'), None)`. Both `str|null` with default
   `None`, so an old line still validates and a new key is additive for old and new (P18).
3. `validate` (`:204`): in the `ci` branch, a `stall` that is neither `STEP_SILENCE` nor `BUDGET`
   nor None raises `SchemaError`, in the shape of the `gates`/`conclusion` check at `:258`. The two
   words are imported from `ci_queue` rather than spelled again, so D1's vocabulary has one home.
4. `ci_from_api` (`:1657`): `stalled = ci_queue.stalled_runs(product)` once, before the run loop
   (`{}` when `product` is None). Per run, §2.7:
   - `stall = BUDGET` when the run's conclusion is `timed_out`, or any of its jobs' is;
   - `stall = STEP_SILENCE` when `stalled` holds this run id — step-silence wins when both are
     true — and `stall_step` is set on the job `stalled[run]['job']` names, on that job only;
   - else None, and every job's `stall_step` is None.
   `jobs_of`'s `jq` is unchanged: it already reads `steps[]` for `failed_step` (P19), and the step
   this card reports comes from the queue file, not from the API.
5. `CiStallClass` in `tests/test_metrics.py`, named as §3.8 names them:
   - `test_a_run_cancelled_for_step_silence_carries_stall_step_silence` — and the named job carries
     `stall_step`, and no other job does.
   - `test_a_timed_out_run_carries_stall_budget` — both from the run's conclusion and from a job's.
   - `test_step_silence_wins_when_a_run_is_both`
   - `test_a_healthy_run_carries_null_and_an_old_line_still_validates` — an event written before
     this card, with neither key, passes `validate` and reads `None` (P18).
   - `test_an_unknown_stall_class_is_refused_by_validate`
   - `test_a_product_with_no_queue_file_joins_nothing`
   - `test_the_history_record_outlives_the_relief_record_by_two_days` — the relief record removed
     (re-run), the `stalls` history record still there, and the join still made.
6. `SampleTests` in `tests/test_ci_step_silence.py` — §3.9, end to end over the fake host: a run
   whose job hangs inside a step, driven through `ci_queue.queue_pass` twice, then
   `metrics.ci_from_api` over the same host. Asserted in one test: the stalled line is printed on
   the first pass, the run is cancelled on the second, the relief record is written, the doctor row
   is red, and the `ci` event carries `stall: "step-silence"` with `stall_step` on its job.
