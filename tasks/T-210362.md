**Steps**

1. `trunk_wide_red(check, facts)` in the shape `quarantined` already has
   (`asf/kernel/decide.py:1732-1737`, P10), returning the spell's test ids this check's failing
   ids are covered by, or `()`. Its input is `blame.trunk_wide_tests(facts)`; the check's own
   failing ids are read with the same parse the trunk's red uses (`ports.failing_files`,
   `asf/kernel/ports.py:1405-1416`, P9), over the whole failed log and not the tail.
2. It keys on **failing test ids, never on the check name** (D-0010): the name is `tests (3.12)` for
   every red in this product, so a name match would silence real defects. A PR that genuinely
   breaks the same test still shows it failing beside the trunk's — the predicate drops only the
   ids the spell itself holds.
3. Read it in `_judge_pr`'s red loop at `:1613-1618`, **before** `on_pr` (P11), and partition
   `gating` **once, at the top** — this is the step the spec states only as an outcome (K15).
   Measured: a check dropped from `own` alone still falls into the rerun loop at `:1622-1632`,
   which reruns it to `max_reruns` and then returns `_Judged(State.STUCK, _stuck('%sN rerun(s)'
   % RED_OFF, 'ci'))`. So §2.6's "no Stuck" is false unless the trunk-wide ids leave `gating`
   before that loop sees them. Partition at `:1608`: the spell's checks out, everything else
   through the quarantine/`on_pr`/rerun path exactly as today.
4. The three readings, in `decide`'s own voice in the docstring: **every** failing id of the check
   is the spell's — not the PR's: one `A.NoteItem` reading
   `PR #<n>: <check> is red on main at <first red> too (<Bug>) — not a fix round`, and the check
   skipped (no fix round, no round charged, no archive, no Stuck). **Some** id is not the spell's
   — the red is the PR's for those ids, a fix round as today whose finding names only them. **No**
   ids read (an unread log) — the check is left exactly as it is today, the PR's own: a silent
   widening here would hide a real defect behind every red trunk.
5. The archive follows with no extra code and the Steps say so: nothing reaches `_fix_round`
   (`:1787`), so `kernel_fix_rounds` is not written, the cap at `:1793` is not reached and
   `ArchiveAndReset` is never planned for that check. Assert it rather than add to it.
