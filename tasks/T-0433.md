The spec's §`asf/tick/tick.py`, §`asf/tick/summary.py`, D3, and `release_report` steps 0–4. The
version check becomes an `if` over structure, the channel's `factory:` line lands, and `notify`
says its piece once per tag in the log and in the digest. The `auto` path is Tasks 4 and 5; until
Task 4 lands, `auto` announces and does not install (PD15).

**Files**

- `asf/upgrade.py` — the channel state (`_release_state_path`, `_read_release_state`,
  `_write_release_state`), `release_report` steps 0–4
- `asf/tick/tick.py` — the fork in `_run_steps` (`:394-412`), `Context.upgrade_line` (`:160-165`)
- `asf/tick/summary.py` — `digest`'s fourth argument and `run`'s read of it (`:177-207`)
- `tests/test_release_channel.py` — `NotifiesOncePerTagTests`, `TheTwoChannelsAreExclusiveTests`
- `tests/test_tick_summary.py`, `tests/test_tick.py`, `tests/test_drift.py` — the digest line and
  the fork

**Steps**

1. The channel state, one file per product at `<state_dir>/upgrade-release.json`, the spec's shape:
   `{"notified": <tag>, "last": {"from", "from_sha", "to", "at", "result"}}`. `notified` is the tag
   and not a timestamp — a tag notified stays notified until a newer one is cut. Read through a
   `try` returning `{}`; written through `_write_json`. `env.state_dir(product)` already makes the
   directory.
2. `release_report(ctx, out=print, now=None, run=subprocess.run)` → one of
   `'none' | 'notified' | 'held' | 'installed' | 'rolled-back' | 'failed'`. This Task returns only
   the first three. The whole body is inside one `try`/`except Exception` printing
   `factory: release check failed (<detail>)` and returning `'none'` — the shape `drift.report`
   uses (`asf/drift.py:139-142`): a version check has never been allowed to stop a tick.
3. Step 0: `policy = ctx.product.upgrade`. `off` prints the `factory:` line (step 2) and returns
   `'none'` — a log always says which release is running, on every policy, including the one that
   does nothing.
4. Step 1: `url = repo_url(run)`; `(tag, sha) = latest_release(url, now, run)`;
   `(old, old_sha) = installed_release()`.
5. Step 2: one line every tick —
   `factory: asf <old> @ <old_sha7> · release <tag> · <current|BEHIND|release unreadable>`, the
   parallel of `drift.line`'s `factory: asf … @ … · trunk … · …` (`asf/drift.py:130-135`), so the
   two channels' logs read the same. `release unreadable` is the `old is None` case (D6) and says
   what it could not read.
6. Step 3: `newer(tag, old)` False → `'none'`.
7. Step 4, `notify`: the channel state's `notified` already equal to `tag` → `'none'`, silently —
   that is notify-once. Otherwise print `UPGRADE AVAILABLE <old> → <tag>` (the trunk channel's own
   wording, `asf/drift.py:151`), set `ctx.upgrade_line` to the same string, write `notified: tag`,
   return `'notified'`.
8. `auto` falls through to the same branch for now, with a comment naming Task 4 as what replaces
   it (PD15): a product that asked to be upgraded gets the line rather than silence, which is the
   least-privileged half of the behaviour and the one that is safe to land alone.
9. `asf/tick/tick.py`: `Context.__init__` gains `self.upgrade_line = None` beside `stale_reason`
   (`:164`). The version check under the record lock becomes the spec's `if`:
   `drift.is_factory_source(product.repo_dir or '')` true → today's
   `drift.report(product, autonomy=…, upgrade=run_upgrade)` **byte for byte unchanged**; false →
   `released.append(upgrade.release_report(ctx))`. The channel is chosen by structure and never by
   name (D3), so no product file can get it wrong and `tools/check_generic.sh` stays satisfied.
10. Below it: `if released and released[-1] in ('installed', 'rolled-back', 'failed'):` print
    `tick: the install was changed under this tick; its steps run on t
