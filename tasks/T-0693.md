The spec's §2 in full and the classifier of §1 — `head_kind()`, `cause()` and `classify()`. **This is
the card.** Nothing in the tree today can tell a content-free re-push from a real one:
`explain_cancels` calls both `superseded` (PD2), and the card's Description asks which source
dominates. From here the question has an answer.

It waits on Task 1 because `cause()` reads Task 1's `HONOURED`/`REREAD` partition and returns a member
of its `CAUSES`, and because both write the same module (PD9).

Still no behaviour: `classify()` is a pure function over rows a caller hands it, and `head_kind` is
four `git` reads. Nothing imports this module yet; Task 3 is what puts it on a command line.

Read **PD2** (a `superseded` claim is re-read here, never honoured — get this backwards and the
`rewrite` row is zero forever), **PD11** (the `HeadKind` fence builds a real repo; a stubbed
`subprocess` proves nothing) and **PD12** (`lost_commits` is the shape to copy, not the function to
reuse) before starting.

**Files**

- `asf/ci_cancels.py` — `head_kind(repo, old, new, trunk='origin/main', fetch=True, run=None)`,
  `cause(run, claims, runs, timeouts, prs, repo, trunk, fetch)`, `classify(...)`
- `tests/test_ci_cancels.py` — the `HeadKind` class, and the rest of the `Causes` class

**Steps**

1. `head_kind(repo, old, new, trunk='origin/main', fetch=True, run=None)` with the spec's §2 docstring
   **byte for byte**, including its P8 reference and its `lost_commits` reference. `run` is the
   `subprocess.run` seam every other module in this tree takes for testability; it is **not** a way
   to prove the rule against a fake (PD11).
2. The rule, in `head_kind`, exactly as §2 states it and in this order:
   - `old` and `new` equal, or either falsy → decide before any git runs: equal shas are `'rewrite'`
     (a re-push of the same head carries nothing), a falsy sha is `'unresolved'`.
   - resolve both, copying PD12's shape: `cat-file -e <sha>^{commit}` for each; on failure, if
     `fetch`, **one** `git fetch -q origin <sha>` for that sha and re-check; still failing →
     `'unresolved'`. Fetch by **sha**, never by branch — the sha this wants is the one the branch no
     longer points at (C7).
   - `lost` = `git cherry <new> <old>`; any `+` line → `'newhead'`. A commit of `old`'s with no
     patch-equivalent in `new` means the work changed, which is never a content-free re-push
     (the spec's `test_a_dropped_commit_is_a_newhead`).
   - `gained` = `git cherry <old> <new>`; for each `+` line, `git merge-base --is-ancestor <sha>
     <trunk>`. Every one on the trunk → `'rewrite'`; any one not → `'newhead'`. No `+` at all →
     `'rewrite'` (a reword, a sign-off).
   - any git read exiting non-zero that the rule needs, and a `repo` that is not a git directory or
     is None → `'unresolved'`. **Never raises** — the docstring says so and the fence asserts it.
3. `'unresolved'` is a returned string on its own footing (C6), never folded into `'newhead'` and
   never assumed `'rewrite'`. Say in the docstring what C6 says: this is the one place the measure can
   lie, so it is the one place it is loud, and the table prints its share.
4. `cause(run, claims, runs, timeouts, prs, repo, trunk, fetch)` — one member of `CAUSES` for one
   cancelled run row, first match wins, in C4's order:
   1. **the claim.** `claims.get(str(run id))`; if its cause is in `HONOURED`, return
      `HONOURED[cause]`. If it is in `REREAD`, fall through — the run is re-classified from here
      (PD2). If it is in neither, return `'unclaimed'` and count it a stray (PD3).
   2. **`timeout`.** The run holds a job whose `started_at → completed_at` reaches its declared limit
      within one minute. The limit is `timeouts` (a `{job name: minutes}` dict the caller passes,
      built from `ci_pool.parse_timeouts` over the workflow file), else
      `ci_pool.DEFAULT_JOB_TIMEOUT_MIN`. Tried **before** eve
