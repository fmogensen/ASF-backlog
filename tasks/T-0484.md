keeps its comment (PD10).

**Files**

- `docs/guide/product-config.md` — one row in the `## Conventions` table (`:69-85`), and
  `### \`worktree_setup\` — the command a fresh worktree needs` between that table and
  `### Landing: fast-forward or pull-request` (`:86`)
- `tests/test_readme.py` — `WorktreeSetupProseTests`

**Steps**

1. The table row, the spec's, byte for byte, placed after the `amendable_paths` row and before
   `landing` so the two derived-or-declared rows stay together:
   `| \`worktree_setup\` | none | a shell command run in every fresh worker worktree before its
   session starts — the dependency install or codegen the product's gate needs. Must be idempotent —
   see below |`. The default column reads `none`, which is what `DEFAULT_WORKTREE_SETUP = None`
   means to a reader of a yaml file (`asf/conventions.py:195-197`).
2. The subsection, the spec's six bullets and its two opening paragraphs byte for byte, headed
   `### \`worktree_setup\` — the command a fresh worktree needs` — a `###`, not the spec's `####`,
   for the reason PD11 gives. Nothing in the prose changes: git gives a worker session a checkout
   and nothing else; the command runs in the **worktree** under the environment the session itself
   will have (the worker allow-list, the account's own HOME, the product's `auth_env`, never the
   operator's environment and never a value the tick happens to carry, with the cross-reference to
   operating.md's Safety); its output goes to `~/.ASF/state/<product>/briefs/<job>.setup.log` with
   every `auth_env` value masked; it gets **900 seconds**, and a failure or a timeout **refuses the
   launch and removes the worktree** and names the log, with the same failure twice in a row a
   `NEEDS OPERATOR` telling the operator which key to fix; it runs **once per worktree**, a reused
   worktree keeps the install it already has, and a recreated one or one whose recorded command is
   not the one the product declares now gets the command again; so **make it idempotent**, and
   `pnpm install`, `make deps` and a codegen step already are; and a session that runs off this host
   (`lane: cloud`) never runs it here — the command is handed to the run that needs it.
3. Every number and path in those bullets is the code's, not a restatement: 900 s is
   `WORKTREE_SETUP_TIMEOUT_S` (`asf/workers/spawn.py:668`), the log path is `setup_log_path`
   (`:671-672`), the `NEEDS OPERATOR` and its `clear` are the wave's (`asf/workers/wave.py:278-280`
   over the `SpawnError`'s `clear` at `:723-727`), and the two cloud paths are
   `asf/workers/actions.py:287-292` and `asf/workers/remote.py:166-168`. Re-read each before writing
   the sentence; a guide that names a number the code does not hold is worse than no guide.
4. `WorktreeSetupProseTests(unittest.TestCase)` in `tests/test_readme.py`, following
