after: Task 3

**This Task is written by the console, not a coder** (P14): `asf/briefs/templates/*.md` is in the
amendable set, so the feeder mints a CONSOLE → AMEND row for it and no worker session may edit it.
And it is itself **bundled** (PD4) — the two goldens and the test file are outside the set and
cannot land in a separate commit — which makes it this plan's own worked example of D2.

**Files**

- `asf/briefs/templates/plan.md` — insert between `:22` and `:24` (PD3).
- `asf/briefs/templates/spec-plan.md` — insert between `:35` and `:37`, **indented three spaces**
  (PD3).
- `tests/fixtures/briefs/golden/plan.md`, `tests/fixtures/briefs/golden/spec-plan.md` —
  regenerated, never hand-edited.
- `tests/test_briefs.py` — the S4 assertions.

**Steps**

1. `asf/briefs/templates/plan.md`, a new paragraph after the intersecting-`writes:` paragraph
   (`:20-22`) and before `Every Task carries, besides those three lines:` (`:24`), separated by a
   blank line each side:

   ```
   A path in the amendable set — {amendable_globs} — is edited by the console, never by a coder
   session. Give every such path its own Task: a Task whose `writes:` mixes one in with ordinary
   code sends the whole footprint to the console, and a human then hand-writes the code a coder
   should have written.
   ```

2. `asf/briefs/templates/spec-plan.md`, the same four lines **each indented three spaces**, after
   the `Then **Files**, **Steps**, …` paragraph (`:33-35`) and before `End the document with the
   line` (`:37`). Unindented, markdown closes numbered item 5 and the rule falls out of the block
   S4's acceptance asserts it is inside (PD3).

3. Regenerate the goldens, never by hand:

   ```
   ASF_UPDATE_GOLDEN=1 python3 -m unittest tests.test_briefs.GoldenBriefTest
   ```

   Then `git diff --stat` and read it: it must name `tests/fixtures/briefs/golden/plan.md` and
   `tests/fixtures/briefs/golden/spec-plan.md` and **nothing else**. Any third golden in that
   diff means the change reached a template it should not have (D8). Read the two diffs too: each
   is the four-line paragraph with `{amendable_globs}` replaced by the fixture product's ten
   globs, and nothing more.

4. `tests/test_briefs.py` gains the S4 assertions:

   - for each of `'plan'` and `'spec-plan'`: `build_mod.load_template(kind)` contains
     `'{amendable_globs}'` and the sentence `'is edited by the console, never by a coder'`;
   - the rendered brief interpolates it — `build_mod.placeholders(brief.text) == []`, the shape
     `tests/test_briefs.py:292` already uses — and the rendered text contains
     `asf/briefs/templates/*.md` (the fixture set's own member, so the interpolation is proved to
     have happened rather than merely not crashed);
   - **position**: in the raw template, `text.index('amendable set')` is greater than
     `text.index('writes: <the path globs')` and less than the block's end —
     `text.index('Every Task carries')` for `plan.md`, `text.index('End the document with the
     line')` for `spec-plan.md`;
   - **D8**: no other file under `asf/briefs/templates/` names the amendable set — iterate
     `glob.glob(os.path.join(TEMPLATES, '*.md'))` and assert `'amendable'` appears in exactly the
     two. This is the assertion that fails if a later edit spreads the rule to `replan.md` or
     `delivery-plan.md`.

5. `test_no_golden_brief_carries_a_forbidden_name` (`:1150`) must stay green: the interpolated
   globs are generic product paths and carry no operator name, but the test is the proof, not the
   argument.
