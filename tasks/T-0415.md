§2.1's third row and §2.2's checks 4 and 5, landing together (PD9). The page is the merge Task 3
made; this Task makes it complete and then turns on the two checks that hold it to the code — so a
command added later is red in CI until it is documented.

**Files**

- `docs/operator.md` — the merged page, completed
- `asf/docs.py` — checks 4 and 5
- `tests/test_docs.py` — `CoverageTests`'s command, skill and conventions cases

**Steps**

1. `asf/docs.py` check 4: every `/asf:*` skill from `asf.plugin_build.skill_names()` and every
   `asf <command>` from `asf.surface.COMMANDS` has a row or a heading in `docs/operator.md`.
   `asf.surface` is the declared table, `tests/test_surface.py` already refuses a parser that
   disagrees with it, and reading it needs no parser build and no argparse private — which is why
   it and not `asf.views.readme._commands_rows` is the source (PD6). `surface.RENAMED`'s keys are
   retired names and are **not** required.
2. `asf/docs.py` check 5: every annotated field of `asf.conventions.Conventions`, read with `ast`
   or `__annotations__`, is named in `docs/operator.md`. That is 58 fields once Tasks 1 and 8 have
   added `doc_pages` and `feedback` (PD18).
3. Both checks report `path:line: what` like the others — the path is `docs/operator.md`, the line
   is 1 when the page simply does not name the thing, and `what` names the missing command, skill
   or key one per complaint, so a red run says exactly what to write.
4. `docs/operator.md`: every `Conventions` field documented — the merge already covers most of
   them, and this step closes the gap the check finds. Every `/asf:*` skill and every `asf`
   command gets its row. Costs, budgets and quotas and where they are read.
5. One section defining **dead**, **held** and **NEEDS OPERATOR**: what each means, what causes it
   and what ends it. The card names these three by name and they are what a first-time operator
   meets first.
6. The page carries `asf uninstall` as F-0107 specifies it — documented here, not built here
   (§1.2) — and names `asf docs check` and `asf feedback sync` as the two commands this card adds.
7. Run `asf docs check` until it is clean, then commit. Checks 4 and 5 landing red would make the
   CI step Task 10 adds red on arrival.
