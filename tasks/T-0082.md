## Description
stories: S-15608
writes: asf/record/setfield.py, asf/tick/step_health.py, tests/test_tick_steps.py

§2.6's second half. A ruling that only a human can retype is a loop that has not ended; this Task
is what makes the prose the explanation and the fields the mechanism.

**Files**

- `asf/record/setfield.py` — `apply(path, relpath, updates)` → `(ok, why)`; `cmd_set` becomes a
  thin caller over it.
- `asf/tick/step_health.py` — `file_rulings` applies the three fields before it files the prose.
- `tests/test_tick_steps.py` — `FileRulingsTests`.

**Steps**

1. `apply(path, relpath, updates)`: the scratch-copy render, the parse-back and the per-key
   round-trip check that `cmd_set` does today (`setfield.py:34-56`, B-0084), lifted whole — writing
   the card only when every key reads back as exactly what was asked, and returning `(False, why)`
   with the card untouched otherwise. `cmd_set` keeps its messages and its exit codes by printing
   `why` — no behaviour of `asf set` changes, and this is the one writer (D10: a session running
   `asf set` from a product worktree is what B-0054 stopped).
2. `file_rulings`: after `report_mod.ruling(...)`, read `report_mod.ruling_fields(...)` and apply
   each claimed field through `apply`, per §2.6's table — `blocked_on` → `after:` on a task
   (sorted, de-duplicated) or `blockedBy:` on anything else; `writes` → `writes:` on a task or bug;
   `superseded_by` → `removed: superseded by <id> (adjudicate <job>)`.
3. Refusals (D11): an unknown id, a self-reference, or a value that does not round-trip writes no
   field, leaves the typed block untouched, still files the prose, and prints
   `NEEDS OPERATOR: adjudicate <job> set <field>=<value> on <item>, which the record refuses — <why>`.
4. Each applied field adds one `## History` line beside the prose ruling's, in §4's shape
   (`- <stamp> adjudicate (<job>): after → T-0001`), through the same `append_history_lines` the
   prose already uses. The `ruling` event gains `fields: {...}`.
5. Idempotence: a run already marked `adjudicated` is skipped exactly as today, and a second
   `file_rulings` over the same ledger changes no byte of the card — asserted, not assumed.
6. Tests: `FileRulingsTests` — after one ended adjudicate run whose report says
   `blocked_on: T-0001`, the Task's `after:` holds `T-0001`, `## History` carries the prose line and
   the field line, the card round-trips through `frontmatter.parse`, and a second `file_rulings`
   changes nothing; `superseded_by` writes `removed:`; `writes:` replaces the footprint; an unknown
   id writes no field, files the prose and prints one `NEEDS OPERATOR:` line.
