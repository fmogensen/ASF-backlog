  `CapStopTest` and `HealthStepTest` to the same file.

**Steps**

1. The module docstring says what the module is for in the card's own words: four dimensions,
   never summed, one pass, one cap table. It imports `asf.env` and the stdlib only (PD7).
2. The four constants exactly as the spec's design block writes them — `DIMENSIONS`, `USAGE_KEYS`,
   `DEFAULT_CAPS`, `STOP_GRACE_S`. `DEFAULT_CAPS` carries the `default` row only; D12's numbers are
   runaway ceilings and the comment beside them says so.
3. `usage_of(rec)`: `rec['message']['usage']` for `rec.get('type') == 'assistant'`, `rec['usage']`
   for `'result'`, `{}` otherwise; a non-dict `rec` or a non-dict usage is `{}`. Each dimension is
   `u.get(USAGE_KEYS[d])` when that is an `int` (and not a `bool`) and `>= 0`, else `None` — `0`
   stays `0` (D4), a negative and a string are both `None`.
4. `Meter` as a dataclass with `result`, `by_dim`, `lines`, `runs`. `meter(log_path)` opens the file
   once with `errors='replace'` and walks it: a `system`/`init` line sets `result = None`, resets the
   tally to four `None`s and adds one to `runs`; an `assistant` line folds `usage_of` into the tally
   (a dimension stays `None` until the first number arrives, then accumulates); a `result` line is
   kept. A blank line, a `JSONDecodeError` and a non-dict record are skipped, and a missing or
   unreadable file gives `Meter(None, four Nones, 0, 0)`. It never raises.
5. After the walk: when `result` is not None and `usage_of(result)` has at least one dimension that
   is not `None`, that dict *replaces* the tally wholesale (D2). Nothing adds the two.
6. `of_result(rec)` is `usage_of(rec)` under a name that says what the caller has.
7. `caps(product)`: read `product.data.get('token_caps')` (`None` → `DEFAULT_CAPS` copied). Collect
   **every** bad entry before raising, in the order the spec's four rules list them, and join them
   into one `TokenCapError` — a block with five faults names five. Then merge: per kind, the
   `default` row under the built-in `default`, and the kind's own row over that. `off` (the string
   `_scalar` leaves, `env.py:33-46`) becomes `None`.
8. `cap_for(product, kind)`: the kind's resolved row, else `default`'s, else four `None`s.
9. `over(by_dim, cap)`: walk `DIMENSIONS` in order and return the first
   `(dimension, tokens, limit)` whose tally is an `int` strictly greater than an `int` cap; a `None`
   on either side is never over. Order is the tie-break, so the verdict is deterministic.
10. `cap_text` and `cap_result` exactly as the spec's design block writes them. `cap_result`'s
    `usage` is built from `by_dim` through `USAGE_KEYS`, omitting a `None` dimension, and it carries
    no `duration_ms` and no `total_cost_usd`.
11. `env.PRODUCT_FIELDS` gains `'token_caps': _MAP`. `NESTED_FIELDS` does not (PD6).
12. `tests/test_tokens.py`: the three classes below. A log fixture is a temp file written line by
    line with `json.dumps`; nothing here needs an `ASF_HOME`, a registry or a process.
