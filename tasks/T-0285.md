## Description
stories: S-29754
writes: asf/tick/step_health.py, asf/workers/wave.py, tests/test_failure.py
after: Task 3, Task 4

§2.5's second branch. A session already routes when it *ends* on a spent window
(`asf/workers/health.py:445`); a session the window *killed*, and a launch a 429 refused, do not.
The assertion that matters is that all three now write the identical limits-table entry.

**Files**

- `asf/tick/step_health.py` — the routing block's `quota` branch and `quota_route`
- `asf/workers/wave.py` — a quota-classed `SpawnError` records the reset before the row is
  re-decided
- `tests/test_failure.py` — `QuotaRouteTests`

**Steps**

1. `step_health.quota_route(ctx, session, why, out=print)` — §2.5's second bullet:
   `headroom.note_exhausted(product, session, rec)` and its line, exactly as `health` writes it,
   where `rec` is `runtime.read_result(session['log'])` when there is one and
   `{'result': runtime.beat_text(runtime.last_beat(session['log']))}` when there is not (PD14).
   No correction, no round, no hold, no `rounds`, `relaunches` untouched. Returns `'quota'`.
2. The `quota` branch in §2.5's block, after the `credential` one.
3. `asf/workers/wave.py`: in `settle`'s failure branch, a `SpawnError` whose `cls` is
   `failure.QUOTA` calls `headroom.note_exhausted` for the account it was refused on before the
   seat is freed, so the row's next decision in the *same* wave sees the account stopped and
   `pick_account` picks another lane (§3.5's last sentence). `counts[QUOTA]` is incremented as
   Task 4's branch already does for every class; `relaunches` is not.
4. `tests/test_failure.py`: `QuotaRouteTests`, §3.5 sentence by sentence — `handle_dead` over a
   dead session whose last beat is `You've hit your session limit — resets 3pm` returning
   `quota`, launching nothing, holding nothing, spending no round; `headroom.active_limits()`
   stopping that account until the **parsed** reset, and the entry byte-identical to the one
   `health` writes today for a run that *ended* on a spent window (the two paths asserted against
   each other, not against a literal); `failures['quota']` 1 and `relaunches` 0;
   `lifecycle.attempts` not counting the run and `hold_failed_corrections` not holding it; a
   `Pool` over that limits table banding the account `STOP` and `pick_account` returning another
   account of the pool, and with every account stopped the row waiting with each reason named;
   and at launch, a `SpawnError` whose text carries `API Error: 429` classifying `quota`,
   recording the reset on that account, and the wave's next decision for the row picking a
   different lane in the same wave.
