## Description
stories: S-104408
writes: tools/cutover.sh, tests/test_cutover.py, tests/test_scheduler.py
after: Task 3

The spec's design §4, and `InstallExitStatusTest` as the pin on the exit status Task 3 landed. This
is the card's second half read from the other end: a command that loses a clock and reports success
teaches every caller above it — the installer, the upgrade, the cutover — that there is nothing to
look at.

`tools/cutover.sh:448` is `run_scheduler install … | sed …` under `set -euo pipefail` (`:48`), so a
non-zero rc would abort the script **before** `record_manifest scheduler_install` (`:449`) — which
is what `tools/rollback.sh` reads to undo the plist. That is a worse state than the one this card is
fixing, which is why §4 captures the rc, records the row either way, and sets `FAILED=1`. The script
already has the idiom for *carry on, then exit 1*: `FAILED=0` at `:301`, read at `:571-573`, with no
writer until now. `|| true` is not an option — it would re-create this card inside the cutover.

**Files**

- `tools/cutover.sh` — `install_job` (`:445-456`) rewritten as §4 writes it: `rc=0` in the `local`,
  the piped install under `set +e` with `rc=${PIPESTATUS[0]}` and `set -e` after, then
  `record_manifest` and `INSTALLED_LABELS` unconditionally, then the named failure line and
  `FAILED=1`, or today's `installed (clock …)` line. `PIPESTATUS` is safe here: the script is
  `#!/usr/bin/env bash` (`:1`), and the `set +e` / `RC=$?` / `set -e` shape is the script's own
  existing idiom (`:173-176`, `:273-280`). The `2>&1` §4 adds puts both streams through the same
  indent, which is also what makes Task 3's stdout choice need no second thought here. Keep the §4
  comment saying why the manifest row goes down either way.
- `tests/test_cutover.py` — one case for the failed install: the manifest row present, the label
  named, and the script exiting 1 after its remaining steps rather than aborting at the failed
  install. **Read PD10 before writing it** — `AppliedTest` is a `SharedFixture` already past its
  cutover with the marker written, so Route A (clear the marker, seed `refuse-<label>`, re-run
  `--force --apply` inside `AppliedTest`) is the one to try first, and Route B (a new
  `SharedFixture` subclass that seeds the refusal before its single `--apply`) is the fallback.
  `test_cutover_installs_the_declared_clocks` (`:487-496`) must still pass unchanged: exit 0 and
  one `scheduler_install` row per installed label, all four of them.
- `tests/test_scheduler.py` — `InstallExitStatusTest`, new, for S-104408's first six checklist
  lines.

**Steps**

1. Rewrite `install_job`. `FAILED=1` set inside it **does** reach `:571` — checked, and the
