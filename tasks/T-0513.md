## Description
stories: S-35850
writes: asf/views/freshness.py, tests/test_record_sha.py
after: F-0122

The spec's three `asf/views/freshness.py` design sections, whole: the module docstring stops
promising no git, `head_sha` answers the commit a copy is at, `Fresh` carries one for each copy
the line names, and `line` hangs `@ <sha>` off both paths. Nothing about **which** copy is read
changes — `pick`'s decision is F-0122's and no branch of it reads a sha.

**Files**

- `asf/views/freshness.py` — the module docstring's last paragraph; new `head_sha` and `_at`; two
  new fields on `Fresh`; `pick` filling them; `line` using them
- `tests/test_record_sha.py` — new module: `HeadSha`, `PickCarriesTheCommits`,
  `TheLineNamesTheCommit`, `BothCopiesNamed`, `NoGitNoSha`, `NextNamesBothCopies`

**Steps**

1. The module docstring's last paragraph, replaced by the spec's diff byte for byte
   (`docs/specs/f-0155.md:129-139`). F-0122 ships *"Two file reads, no git, no network"* as a
   contract; this change makes it false, and a module whose docstring forbids what its code does
   is the defect class this factory files Bugs for (spec D8). The replacement says what is true:
   two `index.json` reads decide *which* copy with no git, and naming the copy then costs at most
   two local `rev-parse`, no fetch, with an unreadable sha dropped rather than raised.
2. `head_sha(root)`, new, beside `generated_at`. The docstring is the spec's
   (`docs/specs/f-0155.md:147-158`) — what it is (the commit the copy *is at*, so two copies can
   be named and compared by hand), what it is not (a currency check; it runs no `fetch` and
   decides nothing, `pick` chooses from the two `generated` stamps with no git at all), and the
   list of what answers None. The body is the spec's block **with PD6's correction**:

   ```python
   try:
       out = subprocess.run(['git', '-C', root, 'rev-parse', '--show-toplevel', '--short', 'HEAD'],
                            capture_output=True, text=True, timeout=5)
   except (OSError, subprocess.TimeoutExpired):
       return None
   if out.returncode != 0:
       return None
   lines = out.stdout.strip().splitlines()
   if len(lines) != 2 or os.path.realpath(lines[0]) != os.path.realpath(root):
       return None
   return lines[1].strip() or None
   ```

   One process per copy, so the spec's *at most two `rev-parse` per command* still holds. Add a
   sentence to the docstring naming the case the comparison refuses: `rev-parse` walks **up**, so
   a record root that is not a work tree but sits inside one would otherwise answer the enclosing
   repository's HEAD — a sha that names a commit the record is not at, which is the confusion this
   card exists to end. Cite `cli._checkout_root` as the precedent for the shape.
3. `Fresh` gains two fields, exactly as the spec's diff writes it
   (`docs/specs/f-0155.md:171-181`): `Fresh = collections.namedtuple('Fresh', 'root source
   generated age_s checkout older_s sha checkout_sha')`, with the comment above it extended to say
   that `sha` is the short HEAD of `root`, `checkout_sha` that of `checkout`, and either is None
   when the copy is not a git work tree.
4. `pick` fills them **as its last act**, after it has decided the copy, so no branch of the
   decision can read one: one `head_sha` when it kept the checkout, two when it fell back. Read
   the namedtuple comment's parenthetical the one way that matches the spec's **In** bullet
   (*`checkout_sha` for the operator's own copy, set only when the clone was taken*):
   `checkout_sha` is **None when `source` is `'checkout'`** — in that case the copy read *is* the
   checkout and its sha is already `sha`, so there is no second copy to name. Do not set it to a
   duplicate of `sha`; `line` tests it to decide whether a second clause exists.
5. `_at(path, sha)` — the spec's helper (`docs/specs/f-0155.md:213-215`), one place so the two
   sites cannot drift: `f'{path} @ {sha}' if sha else path`.
