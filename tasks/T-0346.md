## Description

§2.6: `Run` gains the attempt number `ended_runs` is already in a position to count, `table` gains a
`relaunches` block, and the daily scorecard's Waste table gains one `relaunch` row beside `landing`.
Two windows of that row are the card's third acceptance; nothing asserts the direction, because a
test cannot make a week pass.

**Files**

- `asf/improve/measure.py` — `Run.attempt`, `ended_runs`, `table`
- `asf/metrics/metrics.py` — `scorecard_rows`, `render_daily`
- `tests/test_improve.py` — `RelaunchMeasureTests`
- `tests/test_metrics.py` — `ScorecardRelaunchRowTests`

**Steps**

1. `Run` gains `attempt: int = 1` as its last field, with §2.6's comment
   (`# 1-based, among this job's ended runs in ledger order`) — defaulted, so the one positional
   construction in the suite stays green (PD13).
2. `ended_runs` numbers it from `enumerate(zip(ended, minutes), 1)` in the per-job loop
   (`asf/improve/measure.py:118`) — before the flat sort and before the `since`/`as_of` filters, so a
   windowed relaunch keeps its true number (PD13).
3. `table` gains the block, using the `share` helper it already defines:

   ```python
   'relaunches': {
       'sessions': n, 'share': share(n, len(runs)),
       'usd_per_session': …, 'hours_per_session': …,          # attempt >= 2
       'first_usd_per_session': …, 'first_hours_per_session': …,   # attempt == 1
   },
   ```

   Each per-session figure is `None`, not zero, when its side has no sessions; usd rounds to 2 and
   hours to 1, as the rest of `table` does.
4. `scorecard_rows` gains `relaunches=None` after `landing` and appends one row immediately after the
   `landing` row (PD14):

   ```
   | relaunch | 7 of 31 sessions were relaunches | $2.10 per relaunch vs $3.40 per first launch (7 days) |
   ```

   `None` renders `('relaunch', '—', 'no product resolved — the session registry is machine-local')`,
   the same note and the same reason `landing` gives. A side with no sessions renders `—` for its
   figure rather than `$0.00`.
5. `render_daily` passes `t['relaunches']` beside `landing`, inside the same
   `if product is not None` / `os.path.isfile(pool.sessions_path(product))` guard, over the same
   7-day window and the same `runs` list — no second `ended_runs` call.
6. `RelaunchMeasureTests`: `ended_runs` numbers a job's three ended runs 1, 2, 3 and a single run 1;
   `table` over a mix reports the relaunch count, its share, and usd/hours per session for
   `attempt >= 2` and `attempt == 1` separately, with `None` (not zero) for a side with no sessions.
7. `ScorecardRelaunchRowTests`: one `relaunch` row carrying both numbers, and `—` with the registry
   note when no product resolved. The existing `scorecard_rows` cases
   (`tests/test_metrics.py:373-389`, `:1439`) must stay green untouched — the new parameter is
   keyword-defaulted for exactly that reason.
