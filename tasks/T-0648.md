The spec's `## The design` §2.1 in full, and nothing else in `asf/`. After this lands, a product
that lands through pull requests and has deleted its merge-queue script simply leaves `steps.batch`
out — and the tick runs, the clock loads, `asf tick --manifest` prints `batch  off  -`, a declared
command still runs at the same point in `STEPS`, and `batch: asf` is still refused.

**Read PD1 before writing a single test edit.** The spec's D6 names two pinned expectations; the
measured count is **five**, across `tests/test_tick.py` and `tests/test_clocks.py`, and the two
that D6 misses in `test_tick` are the tests that pin P2's *"the tick exits 2 before running
anything"*. Read **PD4 before re-pointing any of them** — the rule is the same for all three: keep
every assertion, change only the fixture, to `batch: asf`, the one ownerless spelling D2 leaves.

Three things are load-bearing. **The new condition goes ahead of the existing branch**, and the
order is the whole point: the test is on `text is None` **alone**, so it must be asked before
`text is None or text == 'asf'` or `batch: asf` falls into it and D2 is lost. **`check_owned` is
not touched** — it never sees an `undeclared` `batch` from absence again because `resolve()` no
longer produces one, and both of §0's refusals close through that one edit: the tick's own
preflight (P2) and `scheduler._clock_refusal` (P3), the latter with **no edit in
`asf/scheduler.py`** (measured: `scheduler.clocks(p)` returns `['dispatch']` for a clock naming
`batch` with `batch` absent). And **`lane.landing()` is not in this Task's `writes:`** — D3; the
`steps.batch` limb stays, so no product's landing mode moves on upgrade, and that is the accident
Task 2 exists to make visible rather than to commit here.
