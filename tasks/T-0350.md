§2.5's second half. The two rows become actions: a `STUCK` run is probed, stopped and left for its
own feeder row to relaunch on the branch it already pushed (P20 — nothing here launches anything),
and an `INPUT` run's question reaches the operator once. Plus `runtime.failure_reason`'s one
clause, which is what makes health end the stopped run as `failed: no progress` on its next pass.

**Files**

- `asf/tick/step_health.py` — `handle_stuck`, `handle_input`, `stopped_for_no_progress_before`,
  `no_progress_text`, `stuck_probe_line`; `run()`'s counter split and its two new branches;
  `progress.sweep` once a pass; the module docstring's two new sentences
- `asf/workers/runtime.py` — `failure_reason`'s `asf.no_progress` clause and its docstring line
- `tests/test_tick_steps.py` — `StuckRunTests`, `InputRowTests`

**Steps**

1. `asf/workers/runtime.py`: `from asf import budget, detach, env, hermetic, progress, tokens`
   (`:23`), and in `failure_reason`, beside the `asf.run_cap` clause (`:485-486`),
   `if isinstance(asf, dict) and isinstance(asf.get('no_progress'), dict): return
   progress.NO_PROGRESS`. Structured first, as the two above it are: a session's own text is
   forgeable and the factory's fields are not (P7, D12). The docstring gains the clause.
2. `run()` (`asf/tick/step_health.py:172-192`): `ctx.counts['stalls'] += len([r for r in stalled
   if r[1] != 'INPUT'])` — a question is no stall (§1.2, P12). `dead_jobs(found, stalled)` is
   unchanged: it already filters on `state == 'DEAD'`. After the `dead_jobs` loop, one pass over
   `stalled` dispatching `STUCK` → `handle_stuck` and `INPUT` → `handle_input`, each with
   `dict(sessions[job], job=job)` and `items=items`, skipping a job the ledger does not hold.
3. `progress.sweep(product)` once per pass, wrapped like `reap_worktrees` is — never raised, and
   one line only when it removed something.
4. `stuck_probe_line(session)`: the head, the commits above the trunk and the dirty files of the
   run's worktree — `progress.probe` for the head and the dirty count, and one
   `git rev-list --count <main>..HEAD` for the commits. Printed before anything is stopped, because
   what is on the branch is what the relaunch inherits and what the operator reads.
5. `stopped_for_no_progress_before(path, session)`: over `lifecycle.runs(path)`, any run of any job
   whose `item` equals this run's `item`, excluding this run itself, carrying `no_progress`
   (PD8 — a relaunch comes back under a new job name, so `died_before`'s per-job shape cannot see
   it).
6. `handle_stuck(ctx, session, minutes, out=print, items=None)` → `stopped` | `held` | `closed`.

   `runtime_mod.read_result(log)` is still None, `stall_mod._append_line(log,
   progress.result_record('stuck', minutes, evidence, at))`; then `pool_mod.update_session(product,
   job, no_progress={'minutes': minutes, 'evidence': evidence, 'at': at})`. Then: `closed` and
