## Description
stories: S-36203
writes: asf/feeder/tiers.py, tests/test_s1_gate.py, tests/test_backlog.py
after: Task 1

The spec's fourth **In** bullet and `## The design` §`asf/feeder/tiers.py`. Two strings gain the flag
Task 1 made mandatory, and the assertion that has never been possible gets written: the advice the
factory prints for an unworked S1 and the gate the command applies are the same rule. It waits on
Task 1 because its acceptance **executes** the printed command and expects exit 0.

Read **PD6** first — the spec puts the executed half in `tests/test_s1_gate.py`, and that module has
no record and no subprocess helper to run it with. The string assertion stays there; the execution
goes where the harness is.

**Files**

- `asf/feeder/tiers.py` — the `DOWNGRADE` constant with the spec's `#:` comment, and the two
  `_remedy` returns that use it (`:136`, `:144`)
- `tests/test_s1_gate.py` — the equality assertion at `:71-74`
- `tests/test_backlog.py` — `S1RemedyRunsTests`

**Steps**

1. `asf/feeder/tiers.py`: `DOWNGRADE = 'asf set {item_id} severity=S2 --why "<why this is not S1>"
   --product {name}'` as a module constant above `_remedy`, with the spec's three-line `#:` comment
   byte for byte — it is D8's whole argument, that the gate's own `reason` describes the queue and
   not the Bug, so a machine-written defence is not one. The placeholder is written **exactly** as
   the spec has it, angle brackets and all: it is what marks the line as a template a person
   finishes.
2. Both `_remedy` returns become `DOWNGRADE.format(item_id=item_id, name=name)` — `:136` (the
   `waits_on == 'operator'` branch) and `:144` (the fallback). Nothing else in `_remedy` moves: the
   `decision` branch's `decided=true`, the `held` branch's `approvals resolve`, and the `blocked by`
   branch's `blockedBy=` are untouched, and none of them needs a `--why` (Task 1 gated severity
   alone).
3. `tests/test_s1_gate.py:71-74`: the one equality assertion in the tree that carries this string
   (`grep -rn 'severity=S2' tests/` is that single line, P17) gains the flag, in the position
   measured in PD7 — `… — asf set B-0057 severity=S2 --why "<why this is not S1>" --product sample`.
   Keep it an equality over the whole `NEEDS OPERATOR` line: the arithmetic, the reason clause and
   the em dashes are all still being pinned, and this card changes exactly one of its tokens. The
   `decided=true` assertion in `test_an_undecided_s1_holds_nothing` (`:85-87`) is **not** touched —
   that remedy was always runnable.
4. `S1RemedyRunsTests` in `tests/test_backlog.py` (PD6), importing `asf.feeder.tiers` and using the
   module's own `make_repo`, `write_item` and `run()`: build a record with `E-0001` and a Bug at
   `severity: S1`, take the command **from the product** — `tiers.needs_operator(...)` for that Bug,
   or `tiers._remedy(id, 'operator', reason, product)` — never a hand-typed literal, since the point
   of the test is that the two agree. `shlex.split` the command, drop the leading `asf` and the
   `--product <name>` pair (the record is the subprocess's cwd, and the gate's product name is not a
   configured product in a temp record — `asf set` resolves the cwd without it, which is how every
   other case in this file runs), and pass the rest to `run()`. Assert: exit **0**; the card's
   `severity` now reads `S2`; a `## History` line was filed carrying the placeholder text verbatim.
   The assertion that matters is the first one — before Task 1 the same command exits 2, and before
   step 3 it exits 2 for the *other* reason, a missing `--why`.
5. Nothing else in `tiers.py` moves: the gate's arithmetic, `Gate.unworked`, the `skip` handling and
   the `NEEDS OPERATOR` line's shape are untouched (the spec's §Out — *the line's shape, its
   arithmetic and the conditions that raise it are unchanged*).
