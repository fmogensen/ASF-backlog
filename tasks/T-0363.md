## Description
stories: S-32255
writes: asf/rules/rules.py, asf/tick/file_bugs.py, tests/test_file_bugs.py
after: Task 5

§2.7: two optional trailing fields on a violation line. `rules.py` gains documentation and no
code; `file_bugs.rule_violation_signatures` gains a reader. A line carrying neither behaves exactly
as it does today — one Bug per rule, S2 — and that is asserted byte for byte (D10).

**Files**

- `asf/rules/rules.py` — the check contract docstring (`run_check`, `:126-140`) gains the two
  optional fields; no code changes
- `asf/tick/file_bugs.py` — `_FIELD_RE`, `LINE_SEVERITIES`, `line_fields`, and
  `rule_violation_signatures` reading them
- `tests/test_file_bugs.py` — `RuleViolationFieldTests`, `SecretAlertTests`

**Steps**

1. `rules.py`: the contract docstring gains one paragraph — a line may end in `sev=S1|S2|S3` and
   `sig=<key>`; the fields are the filer's, `rules.py` neither parses nor strips them, and a line
   without them is a line. No JSON mode, no per-card severity field, no second filing route
   (§1.2).
2. `file_bugs.py`: `_FIELD_RE = re.compile(r'\s(?P<key>sev|sig)=(?P<val>\S+)')`,
   `LINE_SEVERITIES = ('S1', 'S2', 'S3')`, and `line_fields(line)` → `(text, sev, sig)` — the line
   with its trailing known fields removed, the severity when it is one of `LINE_SEVERITIES`, the
   place key when there is one. A field this grammar does not know (`foo=bar`) stays in the text,
   where a reader can see it; `sev=S9` is ignored and left in neither place but the text, exactly
   as §2.7 says.
3. `rule_violation_signatures` (`:156`): per violation, `text, sev, sig = line_fields(line)`; the
   signature is `f'{rule}: {sig}'` when there is one, else today's `f'{rule}: rule violated'`; the
   severity is `sev` when valid, else `'S2'`. A per-place Bug's title is `truncate(text, 120)`, its
   evidence that one line, its acceptance ``asf rules check`` reporting no violation carrying that
   signature; a rule-level Bug's title, evidence, `places` and acceptance are unchanged.
4. The "One Bug per RULE, not per place" comment stays with its reason, and gains its exception in
   two sentences: a place carrying a stable key from a source outside this record — an alert
   number, a box and a port — *is* its own defect, and folding it into one Bug per rule loses the
   one thing that makes it actionable.
5. Nothing else on the filing path: `_file_or_bump_bug` (`:328`) already carries `severity` per
   signature and day-keys `last_filed` (P19), so an S1 needs no new route and a signature filed
   today is not filed again today.
6. `RuleViolationFieldTests` per §3's T6: `line_fields` splits the fields off, keeps `foo=bar` in
   the text, ignores `sev=S9`; two lines with distinct `sig=` file two Bugs, one S1 and one S2,
   each keyed `R-0009: <sig>` with its own line as evidence; two lines with none file exactly one
   S2 Bug per rule with both lines as evidence, asserted byte for byte against today's output; a
   second run the same day files nothing and bumps nothing.
7. `SecretAlertTests` — the card's third acceptance, hermetic per PD10: a fake host plants one open
   secret alert, `alerts.violations` produces the line, that line is handed to
   `rule_violation_signatures` as the `--json` payload's violation, and one `asf file-bugs` run
   over a temp record leaves an S1 Bug whose signature is that alert. No subprocess and no `gh`.
