## Description
stories: S-18108
writes: asf/hooks.py, tests/test_install.py
after: Task 2

The spec's §2.6, second half. `asf/hooks.py` is one of the three files exempt from the `.claude/`
path ban (P12), so the controlling account's settings path is named here and nowhere else. This
Task owns every line of hook wiring, including the dispatch `BUILTIN` now needs (PD9).

**Files**

- `asf/hooks.py`
  - `BUILTIN` gains `'chores': ('PostToolUse',)`.
  - `cmd_hook` (`:258`) dispatches by name instead of calling `approvals.run_hook`
    unconditionally: a `{name: callable}` mapping, `approvals` unchanged in behaviour,
    `chores` calling `asf.chores.record(sys.stdin.read(), os.environ)`. Both imported locally, as
    `approvals` already is.
  - `controller_account(cfg)` → `(Account, None)` or `(None, why)`: `controller.account` of
    `~/.ASF/config.yaml` matched against `pool.accounts_from_config(cfg)` (`asf/workers/pool.py:82`).
  - `install` (`:202`) — when it resolves, one more `_write_merged(account_settings_path(acct),
    [('PostToolUse', 'chores')], asf_path, None)`, product-less, exactly as it already does for
    `approvals`; when it does not, nothing is written there and the returned message gains the
    `NEEDS OPERATOR` line and the exact JSON of §2.6. The rc is unchanged either way: a missing
    recorder is a missing measurement, not a broken factory.
  - the module docstring gains one paragraph on the controller entry and on why an undeclared
    account is handed the JSON instead.
- `tests/test_install.py` — `ControllerHookTests`, on `HooksTest`'s shape (`:477`).

**Steps**

1. `BUILTIN['chores']` and `cmd_hook`'s dispatch mapping. Run
   `python3 -m unittest tests.test_approvals tests.test_install -v` immediately: `approvals` must
   answer exactly as it did, and `asf hook <unknown>` must still return 0.
2. `controller_account(cfg)`. `controller.account` unset, or naming an account
   `worker_pool.accounts` does not declare, are two different `why` strings — the operator reads
   them.
3. `install`'s two branches, and the message. Confirm by hand on a temp home that a worker account
   gets `PreToolUse/approvals` and *not* `PostToolUse/chores`, that the controlling account gets
   both when it is a declared one, and that a second run changes no byte (`merge` is idempotent,
   `:155-177`).
4. `ControllerHookTests`: the merge, the product-less command form, the untouched unrelated keys,
   the idempotence, the undeclared-account branch with its rc and its JSON, and that no worker
   account has the entry.

**Gate**

```sh
python3 -m unittest tests.test_install tests.test_approvals tests.test_hooks -v
python3 tools/run_tests.py
bash tools/check_generic.sh
bash tools/check_conventions.sh
```

**Acceptance**

**T9 — the recorder is installed where the operator said, or asked for.** `hooks.install` with
`controller.account` naming a declared account merges one `PostToolUse` `chores` entry into that
account's own settings file, product-less, leaves every unrelated key alone, and is idempotent
over a second run; with `controller.account` naming no declared account it writes nothing there,
returns the same rc, and its message carries the `NEEDS OPERATOR` line and the exact JSON. No
worker account gets the entry.

```bash
python3 -m unittest -v tests.test_install.ControllerHookTests
```
