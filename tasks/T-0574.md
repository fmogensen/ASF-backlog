The spec's §2. This is the Task that closes the card's measurement: after it, the live reproduction
in the spec's opening — two pools over one `ASF_HOME`, 8 sessions on a cap of 4 — answers 4.

**Read PD2 and PD3 before writing `_refresh`.** The rebuild as §2 words it discards a hand-built
pool's `live` and narrows `from_config`'s three-way registered filter to one clause; both are red
against tests the spec's own regression run names, and both are measured in the decisions above.

**What changes for the machine when this lands.** Two things. A wave's *pick* now counts every other
product's outstanding claims, so most rows that would have overcommitted never reach a refusal at
all. And `take` can now answer `False` — but its one caller in `wave.py` still ignores the bool until
Task 3, so a refused row still launches, exactly as today. Strictly fewer overcommits than the
trunk, never more (PD9). Nothing prints differently yet: `seats_degraded` is set here and read in
Task 3.

**Files**

- `asf/workers/pool.py` — `import` of `asf.workers.seats`; `Pool.__init__` gains `self._base`,
  `self.seats_degraded = ''` and the re-read slot; `from_config` counts claims and sets
  `seats_degraded`; new `Pool._refresh(ledger)` and the one claim-row layering helper it shares with
  `from_config`; `take` becomes the compare-and-set and returns a bool; `untake` also removes the
  claim; new `Pool.retake(account, seat, model)`. `load`, `under_caps`, `pick_account`, `headroom`,
  `cloud_load`, `band` and every other reader are untouched — they read `self.live`, and `self.live`
  keeps its shape.
- `tests/test_seat_claims.py` — `PoolClaims(Home)` added. `SeatLedger` is untouched.

**Steps**

1. `__init__`: `self._base = [dict(s) for s in live]` beside today's `self.live`; `self.seats_degraded
   = ''`; and a re-read slot (`self._reread = None`) that stays `None` for a hand-built pool. The
   signature gains nothing positional — every existing caller, in `asf/` and in the suite, keeps
   working unchanged. Extend the class docstring: `live` is now base + the host's outstanding claims,
   and a hand-built pool's base is the list it was given.
2. `from_config`: after it has computed `registered`, `extra` and `live`, call
   `seats.read(registered=registered)` → `(claims, why)`; set `self.seats_degraded = why` (PD5); and
   layer the claim rows onto `live` with the helper of step 4. Store the re-read as a closure over
   `(extras, seen_pids, seen_sessions)` (PD3) that returns a freshly filtered `registered + extras`
   — `observe.read` is **not** called again, here or anywhere (C3).
3. `_refresh(ledger)`: `base = self._reread() if self._reread is not None else self._base`, then
   `self.live = base + claim_rows(ledger.claims, base)` (PD2). Called only under the lock, only by
   `take`/`untake`/`retake`.
4. `claim_rows(claims, base)` — **one** function, called by `from_config` and by `_refresh`, so a
   claim looks the same however the pool was built. A claim whose `(product, job)` is already a row
   of `base` is dropped: the launch line landed and the registry holds that seat now, and counting
   both is the mirror of the defect. A claim whose `pid` is `os.getpid()` becomes the **exact** 7-key
   seat dict `take` appends — `{'job', 'account', 'model', 'product', 'kind', 'wave': True, 'lane'}`,
   those keys and no others — or `untake`'s identity scan (`asf/workers/pool.py:562-566`) silently
   fails and the seat leaks for `CLAIM_TTL_S` (P11). Another process's claim becomes
   `{'account', 'model', 'product', 'job', 'kind', 'lane', 'claim': True}`, which `load()` counts and
   `headroom` reads as a running session; it carries `lane`, so a cloud claim is read as cloud by
   `is_cloud_lane` and holds no local seat.
5. `take(account, model, job='', product=None, kind=None, lane=None)` → `True`/`False`, with the
   spec's docstring naming what a `False` obliges the cal
