The spec's fourth `## In` bullet and `## The design` §3: `_CLI_TOOLS` shrinks to its one non-vendor
entry, the rows come from data, and `findings` reaches the table.

Read **PD5** (two loops, not one relabelled loop — the spec's design and its own acceptance
disagree, and the acceptance wins), **PD6** (seven tuples, and the tests' own mirror of the six),
**PD7** (one existing test refuses any answer but a capability test) and **PD17** before starting.

**Files**

- `asf/doctor.py` — `_CLI_TOOLS` (`:370-378`) keeps one tuple; `check_cli_sessions` (`:381-393`);
  the row loop in `run` (`:835-836`) becomes two loops plus the `findings` loop
- `tests/test_doctor.py` — `ConnectorRowTests`, `NoConnectorsFallbackTests`

**Steps**

1. `_CLI_TOOLS` keeps **exactly one** tuple — `('git', True, ['git', '--version'])` — and its
   docstring loses its vendor sentence. Every other name leaves the file in this commit, and with
   them the `if name == 'gh'` special case at `:386-387` (PD7).
2. `check_cli_sessions(product)` keeps its signature and its `(name, required, ok_or_None, detail)`
   tuple, and gets the spec's new docstring byte for byte. It returns `git`, then — **only when the
   product declares no `connectors:` block** — one row per `legacy: true` catalogue entry, run the
   same way the tuples were: an optional tool `shutil.which` cannot find is
   `(name, required, None, 'not installed')`, everything else is probed. A `required: true` legacy
   entry that provides `code` is downgraded to optional when `has_pr_host(product)` is false (PD7),
   which is the capability test that replaces the name test.
3. `doctor.run`'s single loop at `:835-836` becomes **two** (PD5):

   ```python
   for name, required, ok, detail in check_cli_sessions(product):
       rows.append((f'cli:{name}', required, ok, detail))
   for name, required, ok, detail in connectors.rows(product):
       rows.append((f'connector:{name}', required, ok, detail))
   ```

   So `git` is `cli:git` for every product; a product declaring nothing gets byte-identical rows
   including its five `not installed` skips; and a product declaring connectors gets
   `connector:<name>` rows and **no row for any tool it did not declare**, which is the half of the
   card's complaint that pays.
4. Then the `findings` loop, after the connector rows, byte for byte from the spec's design:

   ```python
   for ok, detail in connectors.findings(product):
       rows.append(('connectors', False, ok, detail))
   ```

   Every finding is `required=False`, so **no finding turns a green doctor red** (P14) — an optional
   row that is unavailable is `ok=None`, which prints `skip`.
5. `ConnectorRowTests`: a product with connectors gets one `connector:<name>` row each; no row for
   any tool it did not declare; a declared connector whose tool is missing is `ok=None` when
   optional and `False` when required; `findings` reports D6's disagreement (`ci.runner_org` set and
   a `ci` connector carrying a different `org`, and the same for the deploy workflow) and the
   missing secret file; and `is_red(rows)` is unchanged by every finding.
6. `NoConnectorsFallbackTests`: the rows for a product declaring no `connectors:` block are
   **byte-identical** to today's — assert the row names in order against the literal
   `('cli:git', 'cli:gh', 'cli:gcloud', …)`, built from `tests.test_scheduler.DOCTOR_CLIS` so the
   test and the catalogue cannot drift (PD6). Keep `fake_clis` for the probes so the test is
   portable and instant (B-0071), and re-run the whole of `tests.test_doctor` — `TestNoPrHost`
   (`:494-527`) is the one that refuses a wrong answer to PD7, and `TestFormatAndExit` (`:658`) and
   `TestCmdDoctorSubprocess` (`:675`) are the ones that prove the table still reads.
