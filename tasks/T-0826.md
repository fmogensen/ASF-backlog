The spec's `## The design` §2 in full, and S-64355's Acceptance block whole. Three one-line
refusal sites in the shim, one `asf_refused` helper, one `_json` escaper, and four wiring lines
beside `pushlog`'s. **Read PD4 and PD8 before touching the shim**: PD8 is why the push-allow site
needs no capture, and PD4 is the exact shell for the two sites that do — a buffered capture here
would silence a pre-push check that runs for minutes and get the very session it is protecting
relaunched on top of itself.

**Files**

- `asf/workers/githooks.py` — inside `ASF_HOOK`'s `pre-push` arm (`:140-185`): the `asf_refused`
  helper and the `_json` escaper at the top of the arm; `msg=$(...)` at the push-allow site
  (`:158`, per **PD8**); the streaming capture at the product's own hook (`:163-165`) and at
  `trunk-check --pre-push` (`:171-176`), per **PD4**
- `asf/workers/spawn.py` — `refusals.clear(product, row.job)` beside `pushlog.clear` (`:1245`) and
  `**refusals.env_for(product, row.job)` beside `**pushlog.env_for(...)` (`:1263`); one import
- `asf/workers/heartbeat.py` — the same two, at `:616` and `:644`, with `job_name` for the job
- `tests/test_session_push_guard.py` — one new class, `ARefusedPushIsWrittenDown`
- `tests/test_workers.py` — one new class, `RefusalLogEnvAndClear`

**Steps**

1. In `ASF_HOOK`, at the top of the `pre-push` arm, `_json` — a two-line `sed` that escapes `\`
   and `"` and strips control characters, so the ledger stays one JSON object per line whatever a
   hook printed (§2). It is the only escaping; `refusals.ledger` drops what it cannot parse.
2. `asf_refused() { … }` exactly as §2 writes it: `[ -n "$ASF_REFUSAL_LOG" ] || return 0`, then
   one `printf '{"at":"%s","kind":"%s","where":"shim","line":%s}\n' "$(date -u
   +%Y-%m-%dT%H:%M:%SZ)" "$1" "$(printf '%s' "$2" | _json)" >> "$ASF_REFUSAL_LOG" 2>/dev/null
   || :`. Every failure swallowed: a pre-push hook that cannot write its ledger must still refuse
   the push, and the record of a refusal is not worth failing for (C4). The `date` format is the
   one `pool.now_iso()` writes, which is what makes **PD3**'s window a string comparison.
3. The push-allow site (`:158`), per **PD8**: `msg=$(echo "asf: push refused — an ASF session
   pushes only to factory branches, not:" $bad)` above the old line, which becomes `echo "$msg"
   >&2`, then `asf_refused push-allow "$msg"` before `exit 1`. Stderr stays byte-identical —
   assert that in the test, against the landed `PrePushAllow` class's own expectation.
4. The product's own hook (`:163-165`) and `trunk-check --pre-push` (`:171-176`), each with
   **PD4**'s streaming capture: two `mktemp`s, the `{ … ; printf %s $? > "$rcf"; } | tee "$outf"
   >&2` pipeline, `rc=$(cat "$rcf" 2>/dev/null || echo 1)`, `asf_refused hook-refused "$(cat
   "$outf" 2>/dev/null)"` when `rc` is not 0, and `rm -f "$rcf" "$outf"`. When either `mktemp`
   answers empty, fall through to today's line unchanged and write nothing. Do **not** reorder the
   `rc = 0` guard on `ASF_PUSH_LOG` (`:178-180`): a refused push still logs no push.
5. `spawn.py` — `from asf.workers import refusals` beside `pushlog` (`:45`), `refusals.clear(
   product, row.job)` at `:1245` and `**refusals.env_for(product, row.job)` at `:1263`. A cloud
   job's `env` file then carries `ASF_REFUSAL_LOG` harmlessly: nothing in the container writes it
   (P9), and leg 5 is what reads a cloud session's refusals.
