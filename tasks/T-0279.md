## Description
stories: S-29653

after: Task 1

§2.5. The standing fact goes where the reader's eye already is when the question is "has it run
out" — the **Spend / budget** cell, not the **State** cell, which speaks for the Epic's own
recorded state (D7). The cell's two numbers stop being computed in the view: `subtree_usd` and
`epic_spend` give it the same figures the feeder gated on and the groom asks about, which is what
makes it impossible for the table to read under-budget while the feeder holds (D3). This is also
`roadmap.render`'s first test (P10).

**Files**

- `asf/views/roadmap.py` — `from asf import budget`; the `spend`/`budget`/`spend_cell` block
  (`:54-57`) becomes §2.5's three statements.
- `tests/test_views.py` — `RoadmapEpicBudgetTests` (new), over a temp-dir `index.json`.

**Steps**

1. `from asf import budget` beside the two `asf.views` imports (`:7-8`). No cycle:
   `asf.budget` reads `asf.conventions` only.
2. The block at `:54-57` becomes exactly §2.5's:
   `s = budget.epic_spend(e['id'], ix.subtree_usd(items, e), e.get('budget_usd'))`, then the cell
   — empty when both figures are `None`, else `ix.money(s.usd)` and `ix.money(s.budget)` (or `—`
   when there is no budget), with `f' · {budget.OVER_MARK}'` appended when `s.over`. The
   `isinstance(budget, (int, float))` guard the line carries today is not dropped, it moves: it is
   `epic_spend`'s job now, which is why `s.budget is not None` is safe here (P10).
3. `ix.money` stays the formatter for this cell — `$512.40 / $500.00`, thousands separated — and
   `budget.OVER_MARK` supplies the marker text, so the view holds no literal of it (§3.4).
4. Nothing else in `render` moves: the seven columns, the row order, the `NEXT`/`Blocked` cells,
   the PR tally and `render(root, product=None)` are untouched. An Epic's budget needs no
   conventions, so the cell is right with no product loaded — the same reason §1.3 refuses a
   product-wide default.
5. `RoadmapEpicBudgetTests` per §3.4, writing an `index.json` into a temp dir: an Epic at `$512.40`
   of `$500` renders `$512.40 / $500.00 · over — work held`; at `$499.99` it renders
   `$499.99 / $500.00` with no marker; with `budget_usd` absent, `$512.40 / —`; with neither
   figure, empty. `render(root)` with `product=None` gives the same cells. The marker asserted
   against `budget.OVER_MARK`, not a literal. The table still has its seven headers and the row
   order is unchanged (two Epics by `rank`).
6. And P10's fifth case, the one §3.4 does not name: an Epic whose `budget_usd` is a string, with
   nothing measured beneath it, renders an **empty** cell — `epic_spend` reads a text budget as no
   budget, so the cell says nothing rather than `— / —`. Asserted here because this is the diff
   that changes it and there was no test to catch it before.
