## Description
stories: S-91157
writes: asf/workers/spawn.py, tests/test_workers.py
after: Task 1

The spec's design §4 — `_add_worktree` calls the `exclude()` Task 1 shipped, so the session's
cooperation stops being the defence (D-0003). P3 is why this Story exists, and **PD7** makes it sharper:
in this very checkout there is no exclude line at all, so a fresh clone has nothing.

**Before anything else, read PD6.** `tests.test_workers` is **already red at this base** — five
failures, all in `TestSpawn`, the class this Task touches, reproducing at `HEAD~20`. Their names are
in **PD6**. Five failures with those five names means this Task added none. Do not fix them, do not
widen to cover them, and do not read them as your own.

**Files**

- `asf/workers/spawn.py` — `_add_worktree` (`:593-605`) gains an explicit keyword parameter for the
  worktree path and calls `scratch.exclude(path)` on **both** success exits — the early `return` at
  `:600` and the fall-through at `:605` after `_reclaim` and the retry (**PD9**). Both call sites
  (`:792`, `:818`) pass the `path` they already hold. When `exclude` returned any names, the setup
  line `hardened <path>: <names> excluded` goes to `sys.stderr`, as every other line in that module
  does (`:580`, `:588`, `:777`). `spawn._commit_leftovers` (`:446`) is **not** touched: the spec's
  Out leaves it alone deliberately, since an archive ref carrying a notebook harms nothing and the
  exclusion would discard the work that ref exists to preserve.
- `tests/test_workers.py` — `SpawnScratchExcludeTests`, and the one new assertion in `BeatLoop`'s
  sibling position if a reclaim case needs it.

**Steps**

1. Run `python3 -m unittest tests.test_workers` **first**, before editing anything, and keep the
   output. It is the five failures of **PD6**; that list is what your Gate is read against.
2. Give `_add_worktree` the path parameter and restructure so there is one success exit rather than
   two returns to keep in step. Pass `path` at `:792` and `:818`.
3. Call `scratch.exclude(path)` on success and print what it added. A reclaimed worktree is the case
   most likely to be reused by a session that never runs the brief's line, so it must harden too
   (**PD9**).
4. Write `SpawnScratchExcludeTests`: a spawned worktree leaves every name in the repository's
   **shared** exclude file; the notebook reads as ignored in the new worktree straight after it is
   created; a reclaimed-and-retried worktree is hardened as well; and a spawn whose exclude file
   cannot be written still produces a usable worktree. The cases about idempotence, pre-existing
   lines and the return value are `ExcludeFileTests`' in Task 1 — S-91157's acceptance runs both.
5. Run the Gate. Compare `tests.test_workers` against step 1's output: the same five names is pass.

**Gate**

```bash
python3 -m unittest tests.test_workers.SpawnScratchExcludeTests tests.test_scratch.ExcludeFileTests
python3 -m unittest -q tests.test_workers    # read against PD6's five TestSpawn failures
bash tools/check_generic.sh && bash tools/check_conventions.sh \
  && bash tools/check_clients.sh --against origin/main \
  && python3 -m unittest -q tests.test_hermetic
```

