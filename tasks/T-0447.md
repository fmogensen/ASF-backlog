## Description
stories: S-32553
writes: asf/groom/groom.py, tests/test_adopt.py
after: Task 2

The second half of the spec's §4: `keep` and `remove: <why>` applied across every card the owner now
carries, each through P2's writer with one History line and one `groom_answer` event; any other answer
writes nothing, bars its own slot with the exact `asf move` command and prints one `NEEDS OPERATOR`
line (D6). The applier re-derives the set from the record and never parses the ids printed on the line.

**Files**

- `asf/groom/groom.py` — `FOREIGN_ANSWER_RE`, `FOREIGN_KEEP`, `FOREIGN_REMOVE`, the applier branch in
  `apply_groom_answers`, the in-place bar
- `tests/test_adopt.py` — `ForeignAnswerTests`

**Steps**

1. §4's three regexes beside `INBOX_ANSWER_RE`, byte for byte, with the comment naming the two answers
   the groom can apply.
2. `apply_groom_answers`: one branch immediately after the `INBOX_ANSWER_RE` branch (`:429-443`), so a
   line whose token is not a card id is handled before `ANSWER_LINE_RE` and the `canonical.get(iid)`
   that would drop it. The set is every open card whose `belongs_to:` equals the line's `name`, in id
   order — read off `canonical`, not off the line.
3. `keep`: per card `_write_card_checked(rec, {'belongs_to': None}, f"- {date} groom: {adopt.KEPT_LINE}")`.
   The wording is `asf.adopt.KEPT_LINE` itself, imported, not a second literal — D7 makes it
   load-bearing: `adopt.owner` reads it back out of the body to stay silent about the card for good.
4. `remove: <why>`: per card `_write_card_checked(rec, {'removed': f"{why} (groom {date})",
   'belongs_to': None}, f"- {date} groom: removed → {why} (belonged to {name})")` — one card, one
   `set_typed` call, both fields in it, so a card that would not round-trip is left whole.
5. One `event('groom_answer', item=<card id>, section='foreign', field=<'removed' or 'belongs_to'>,
   value=…, by=by)` per card actually written, through the injected `event` (P14), with `by` from
   `_attribution` as every other branch computes it. `section` is the literal `'foreign'` (PD7).
   `applied` grows by one per card written, so the int the three call sites add up keeps its meaning.
6. Anything else (D6): write nothing, and rewrite the line in place in `prev_path` —
   `re.sub(r'____$', f'____ (operator: asf move --query belongs_to={name} --to {name})', line)`, the
   shape `run_policy_pass` uses for a barred slot (`:996`) — then print §4's single
   `NEEDS OPERATOR:` line. By P12 the rewritten slot no longer matches `OPEN_QUESTION_RE`, so no
   further adjudicator is sent to it, and by P11 `merge_groom_text` adds no second line for the owner
   that day (PD12). An empty or `____` answer is not an answer: it is left alone, unbarred.
7. `tests/test_adopt.py`: `ForeignAnswerTests` — `keep` deletes the flag on every card with that owner,
   leaves `KEPT_LINE` in each body, and the next `cmd_groom` re-derives nothing for them (the memory
   survives a day); `remove: not ours` writes `removed: not ours (groom <date>)` on every one of them
   and the cards leave `index_reader.live`; both emit one `groom_answer` per card with
   `section='foreign'`; `move` writes no card, rewrites the slot to the `(operator: asf move …)` form,
   prints the `NEEDS OPERATOR` line, and leaves the line uncounted by `policy.open_questions`;
   re-applying the same answered file changes nothing (idempotent).
