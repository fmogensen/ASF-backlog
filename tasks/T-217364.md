**Steps**

1. `asf/record/core.py`: §2.1's block verbatim, beside `ITEM_FOLDERS` — `ARCHIVE_DIR = 'archive'`,
   `ARCHIVE_FOLDERS` derived from `ITEM_FOLDERS`, `archived_folder(folder)` and
   `working_folder(folder)`, each with the docstring §2.1 gives it. Nothing else in `core.py`
   changes: not `ITEM_FOLDERS`, not `load_items`, not `build_index_data` (**PD9**). Do **not** add
   `archive/` to `check.LAYOUT`, `asf init` or `tree.record_paths` (**PD3**, D-0003).
2. `asf/record/archive.py`, new. Under `asf/record/` nothing may `open(…, 'w')` but
   `writer.py` (P19), so this module writes through `os.replace` and
   `asf.record.writer.write_text` and in no other way; the docstring says that, with the
   `check_record_writers.sh` reason.
   - `load(root)` → `load_items(root, folders=core.ARCHIVE_FOLDERS)`, and nothing else. The
     docstring names the three things it inherits (the json-or-md decision, the view-beside-the-card
     skip, the parse cache) and the one thing a caller must not do: look `rec['folder']` up in
     `FOLDER_TO_TYPE` — `working_folder` first (§2.1, P2).
   - `manifest_path(root)` → `archive/manifest.json`; `read_manifest(root)` → the parsed dict, or
     `{'schema_version': …, 'generated': …, 'items': {}, 'notes': {}}` when there is none.
   - `entries_for(root, recs, why, archived, scrub=None)` → the `items` block for the cards in
     `recs`: `build_index_data` over exactly those cards and their derived sections, **before any
     move**, each entry plus `archived` and `why` (**PD2**). The docstring says why it is derived
     and not read off `index.json`: a stale index is a finding, not a refusal, so a card with no
     entry must still reach the manifest, and `folder` is right only while nothing has moved.
   - `move(root, recs, entries, notes=())` → the rename itself: for each card, `os.makedirs` the
     one archive folder it needs, then `os.replace(rec['path'], dest)` and `os.replace` of
     `card.view_path(rec['path'])` when it exists; then `write_text(manifest_path(root), …)` with
     `json.dumps(…, indent=2, sort_keys=True) + '\n'`. Returns the sorted relpaths it touched —
     both sides of each move and the manifest. `notes` is accepted and written through in Task 8;
     here it is `()` and the `notes` block is `{}`.
   - `bring_back(root, ids, why, product=None)` with §2.6's docstring verbatim: for each id the
     manifest holds, `os.replace` the card and its view back into `working_folder(entry['folder'])`,
     drop the manifest entry, rewrite the manifest, append the one
     `unarchived: <why>` `## History` line through the record's own writer, and call
     `schema.migrate_cards_to_json` for the record when the card that came back is below the
     record's shape. An id the archive does not hold is not an error. Returns the relpaths written.
     **It is called by nobody in this Task** — Task 4 is the four call sites (**PD5**) — and its
     own module here asserts it moves a card back byte for byte.
   - `find(root, text)` → the manifest's matching rows, by id or by title substring, each
