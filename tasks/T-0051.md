## Description
stories: S-7906
writes: asf/record/ingest.py, asf/record/check.py, asf/groom/groom.py, tests/test_ingest.py, tests/test_groom.py

The two fixes the spec lists under Preconditions as "Not yet true", and the merge apply of Task 2
depends on both: a Task marked `removed: merged into T-a` must leave the Feature's ladder and must
stop covering the Stories it used to list.

**Files**

- `asf/record/ingest.py` — `cmd_ingest`'s Feature ladder, `child_ids` (`asf/record/ingest.py:352-353`).
- `asf/record/check.py` — Story coverage, `task_story_ids` (`asf/record/check.py:121-126`).
- `asf/groom/groom.py` — `groom_stories_without_tasks`'s `task_story_ids` (`asf/groom/groom.py:168-174`).
- `tests/test_ingest.py` — new `RemovedTaskTests`.
- `tests/test_groom.py` — new `GroomSectionCoverageTests`.

**Steps**

1. In `ingest.cmd_ingest`, the `child_ids` comprehension skips a Task whose typed block carries
   `removed`: `... and not crec['meta'].get('removed')`. Read it off the typed half
   (`frontmatter.split_machine`) if the surrounding code already has it to hand; the field is typed,
   not machine-written.
2. In `check.py`, the `task_story_ids` collection skips the same Tasks, so a Story listed only by a
   removed Task is reported as uncovered while its Feature is `building`.
3. In `groom.groom_stories_without_tasks`, the same skip — one condition, same shape as (2). This is
   the whole of that function's change; the four new sections are Task 2's.
4. Tests, with the file's existing helpers (`tests/test_ingest.py`'s repo builder,
   `tests/test_groom.py`'s `make_repo` / `write_item` / `run`).
