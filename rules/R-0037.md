## Statement
A batch in CI never blocks the next one: the next batch is cut STACKED on it with the stacked-land script … --base <batch>, and the one after that on the new one; `--finish` runs in stack order. Idle runners while any approved PR waits is a tick defect.

## Why
Serial batching left runners idle with approved PRs waiting, which is the one thing the pool exists to prevent.

## Check
None yet. The source check for this rule sources a shared library bound to one product's repository, state directory, branch naming and scheduled job, so it cannot be carried as it stands. It becomes a check when the rule runner reads those four facts from the product's configuration.
