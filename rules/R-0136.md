## Statement
Before copying or trusting a configuration key, it is checked three ways against the version that
is actually installed: grep the installed package's `.d.ts` for the key, grep its dist JS for how
the key is handled and for a removal or deprecation warning, and load the config once and read its
warnings as a before/after control. A `DEPRECATED` line in a CI log is evidence — grep for it.

## Why
a package's test config carried a long, reasoned ruling for the gate-tests lock-table
ceiling and set `poolOptions: { forks: { maxForks: 2 } }` — Vitest 3's spelling. Vitest 4.1.11 has
no such key and only logs "`test.poolOptions` was removed in Vitest 4", so the bound never applied
and the same `out of shared memory` failure hit a package on a pull request (2026-09-10). The
dead line was nearly copied into privacy because the comment beside it said so. The real fix was
`maxWorkers: 2` in both packages.

## Check
None yet. The source check for this rule sources a shared library bound to one product's repository, state directory, branch naming and scheduled job, so it cannot be carried as it stands. It becomes a check when the rule runner reads those four facts from the product's configuration.
