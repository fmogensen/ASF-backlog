## Statement
A change is never hand-classified. the feeder computes its lane from the diff (size and paths)
and the batcher orders the stack. The lanes: 40 lines or fewer, or docs-only up to 300 → no
review session, PR straight to a batch; a customer-visible hotfix → alone and first on the stack;
a feature task → one review round, then a batch with scoped CI; shared code (core, db, runtime,
surface, scripts, `.the code host`, the lockfile, migrations) → review plus the full matrix; spec and plan
documents → deep-model rounds and `docs-check` only. Test scope follows the change. Every lane change is
an experiment row in the experiments notebook with a metric and a threshold the 07:02
optimizer judges.

## Why
Measured on 2026-09-20: a small code change took 4.9 h through the factory, docs-only 4.6 h, big
code 10.1 h open to merged — against about 15 minutes hand-held. The overhead on a small change was
a review that finds nothing in three lines plus the wait behind the batch stack, and batches ran
the full 17-job matrix regardless of the paths touched. The gate on the exact sha stays
([[R-0019]]).

## Check
None yet. The source check for this rule sources a shared library bound to one product's repository, state directory, branch naming and scheduled job, so it cannot be carried as it stands. It becomes a check when the rule runner reads those four facts from the product's configuration.
