## Statement
A plan reserves its migration and decision numbers with `node the number-band registry reserve <kind> <count> --plan <path>`, never by scanning the migrations directory or the decision register by hand. the number-band registry is the one table. A renumber is done only when every citation moves, not only the register row: grep the changed files for the old number and check the hit count against the diff's added lines before pushing.

## Why
Two plans scanning the same tree for "the next free number" at the same time will eventually pick the same one, and did. The register itself exists in materially different states per branch and the spec's own table lags it, so "the max of the README rows" is not a reservation either — three collisions came out of one day in 2026-09-06, and a plan's integration report, a plan's "numbered at merge" block and a spec clause cited straight from code each book numbers that never appear as a register row.

## Check
None yet. The source check for this rule sources a shared library bound to one product's repository, state directory, branch naming and scheduled job, so it cannot be carried as it stands. It becomes a check when the rule runner reads those four facts from the product's configuration.
