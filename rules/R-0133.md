## Statement
Every verification carries a control that must fire in the same command — a known positive: a set
compared with itself must overlap, a symbol known to be present must be found, the unpatched script
must fail the test. When the control does not fire, the result is discarded, never reinterpreted. A
check whose silence will be read as "none" is never run with `2>/dev/null`.

## Why
A broken check does not fail loudly; it returns the answer you were hoping for — "no overlap",
"gate empty", "0 anchors". In one session on 2026-09-10 at least five checks returned a clean
result that was really the check failing to see anything, and two of them nearly let a six-agent
batch dispatch on a false file-disjointness verdict.

The failure modes that produced it, kept here because each one reads as a pass: zsh does not
word-split `$var` (use `${=var}`, an array or a `while IFS= read -r` loop); `\]` inside an ERE
bracket closes it early; `\s` and `\b` are not classes in `git grep`'s POSIX ERE (use
`[[:space:]]`, `git grep -wF`); a control that asserts a symbol must NOT exist reads 0 whether the
check works or not, so the control must be a positive; zsh modifiers after an unbraced variable
mangle a refspec (`"${H}:path"`, never `"$H:path"`); a pipe masks the exit code; macOS
`/usr/bin/grep -Z` means decompress, not null-separated; the code host's API …/logs refuses ANSI output
without `--allow-escape-sequences` and its refusal message greps as "no match"; a "file named in
the brief?" grep counts a prohibition in the **Not yours** list as a declaration; and a
failing-first test must assert its scenario happened before it asserts the property, or a harness
failure passes for a bug.

## Check
None yet. The source check for this rule sources a shared library bound to one product's repository, state directory, branch naming and scheduled job, so it cannot be carried as it stands. It becomes a check when the rule runner reads those four facts from the product's configuration.
