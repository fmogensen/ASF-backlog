## Statement
When a rule lands on main — a lint gets stricter, a gate script grows a check, a migration adds a constraint, a repo function changes shape — the drift check <base> <new-main> maps it to the suites to re-run against every open PR branch, before that branch's own next push.

## Why
A branch that never touched the changed file fails anyway, and the failure is found on a 45-minute batch run instead of a two-minute targeted one.

## Check
None yet. The source check for this rule sources a shared library bound to one product's repository, state directory, branch naming and scheduled job, so it cannot be carried as it stands. It becomes a check when the rule runner reads those four facts from the product's configuration.
