## Statement
the CI workflow's `changes` job derives `docs_site_only` — true only when the ref is `main` or a batch AND every changed path is under `docs/`, a customer-facing app path, the review inputs directory or a top-level `*.md` — and every runtime job carries `&& needs.changes.outputs.docs_site_only != 'true'`. An ordinary branch push is scoped the same way by `full`.

## Why
A day of docs and site PRs paid for the web e2e set, a slow job, the computer drills and a slow job, none of which read a line of what changed.

## Check
None yet. The source check for this rule sources a shared library bound to one product's repository, state directory, branch naming and scheduled job, so it cannot be carried as it stands. It becomes a check when the rule runner reads those four facts from the product's configuration.
