## Statement
While a batch branch run is queued or in progress, nothing else lands on main: no docs trains, no registry rows, no lone merges, until `--finish` has run. They merge in the window right after it, before the next batch is cut. A main-red hotfix is the only exception, and it rebuilds the batch on purpose.

## Why
`--finish` refuses a batch whose base moved. On 2026-09-17 merging #442 mid-batch made it refuse a green batch, and the whole CI cycle was spent again.

## Check
None yet. The source check for this rule sources a shared library bound to one product's repository, state directory, branch naming and scheduled job, so it cannot be carried as it stands. It becomes a check when the rule runner reads those four facts from the product's configuration.
