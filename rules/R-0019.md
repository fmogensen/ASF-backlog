## Statement
A merge lands only when `gate` and `gate-tests` are `completed`/`success` on the pull request's exact head sha — not the branch, not an ancestor, not the code host's previewed merge commit. the direct-merge script is that check; a merge done by hand states the sha and both conclusions in the same breath, or it is not evidence.

## Why
Main has no required checks, so the code host merges whatever it is pointed at, and every runtime job is `needs: gate` — a red or unfinished gate leaves its siblings reporting `skipping`, which reads as "nothing wrong" rather than "nothing ran".

## Check
None yet. The source check for this rule sources a shared library bound to one product's repository, state directory, branch naming and scheduled job, so it cannot be carried as it stands. It becomes a check when the rule runner reads those four facts from the product's configuration.
