## Statement
Plan mode is never entered while agents are running. A planning request that arrives mid-build is
answered with read-only research and a plan document written normally; if plan mode is genuinely
needed, the operator is warned first that it will stop every running agent. After any plan-mode exit,
each agent is resumed explicitly and the shared resources — the database, the CPU — are
re-sequenced, because they all restart at once.

## Why
On 2026-09-05 the operator asked for a plan mid-build. Plan mode activated for the controller and with it
for all eight running subagents — integrators mid-gate, a fixer mid-commit, a cleanup mid-drop.
Each ended its turn with a "blocked by plan-mode gate" report and had to be resumed by message with
sequencing instructions. About fifteen minutes of eight seats, and uncommitted work left in several
worktrees, for a plan whose research was read-only anyway.

## Check
None yet. The source check for this rule sources a shared library bound to one product's repository, state directory, branch naming and scheduled job, so it cannot be carried as it stands. It becomes a check when the rule runner reads those four facts from the product's configuration.
