## Statement
When something should happen automatically, the code row is written — the feeder /
the feeder row, a rule check, an ingest state rule — and the model is left only the creative
step that row launches: write the spec, write the code, judge the review. "Remember to …" is never
added to a brief or to the tick file when a script can print the row.

## Why
Every one of the factory's incidents was a remembered rule a session missed: the stale `queue.md`,
the sibling runner teardown, the ungated merges. A row printed by the feeder fires every tick;
a rule recited in a prompt fires when the model happens to recall it.

## Check
None yet. The source check for this rule sources a shared library bound to one product's repository, state directory, branch naming and scheduled job, so it cannot be carried as it stands. It becomes a check when the rule runner reads those four facts from the product's configuration.
