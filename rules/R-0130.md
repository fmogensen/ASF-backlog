## Statement
When checking coverage, membership or "is X registered", match on the field that declares the relation (the path the
file says it covers); use the filename only as a fallback and combine both. Never `grep -m1` when a file may contain
several candidates. State the count with the command that produced it ([[R-0081]]).

## Why
2026-09-09: asked which plans the task register covers, a filename comparison reported a milestone–a milestone missing; a milestone was covered
(`<date>-<slug>.md` covers `…-a spec file`). The second try, `grep -m1` per register file,
took whichever plan path came first and reported five more wrong. Both errors were silent and produced a confident
wrong number that would have sent an agent to redo existing work. The working shape: same-named file, else
`grep -rqF "plans/$b" <register dir>`.

## Check
None yet. The source check for this rule sources a shared library bound to one product's repository, state directory, branch naming and scheduled job, so it cannot be carried as it stands. It becomes a check when the rule runner reads those four facts from the product's configuration.
