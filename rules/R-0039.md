## Statement
A merge commit whose files were independently reviewed and approved on their own branch says so in its own message — "carries in origin/<branch> (PR #n, approved — see the review directory), not new scope here".

## Why
Without the line, a later Files-list review has to re-derive the scope from two other PRs' history.

## Check
None yet. The source check for this rule sources a shared library bound to one product's repository, state directory, branch naming and scheduled job, so it cannot be carried as it stands. It becomes a check when the rule runner reads those four facts from the product's configuration.
