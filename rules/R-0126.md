## Statement
Before a CI failure is called unreproducible, the whole workspace runs once at CI's scope (the package manager test against one shared the database, `./the test-database wrapper`); when the host is too loaded for that, push and let CI be the gate. When a suite asserts a cluster-global invariant (roles, `alter system`), that invariant is read directly before and after the suspected polluter.

## Why
CI runs every package in one the package manager test against one the database service, and the harness isolates only a schema per test file; roles and settings are cluster-wide. On a pull request a package source file really executed `alter role the product with login …`, which a package asserts is NOLOGIN. Every package-scoped run was green; the proof took one minute once run at CI's scope (`rolcanlogin` flipped f → t).

## Check
None yet. The source check for this rule sources a shared library bound to one product's repository, state directory, branch naming and scheduled job, so it cannot be carried as it stands. It becomes a check when the rule runner reads those four facts from the product's configuration.
