## Statement
A spec's pasted tests must compile and run against the base before the PLAN is approved, and every task's Consumes must
exist on its base. A spec defect costs one round: the coder writes the erratum on its branch, and the reviewer's
default for a fixture or typo defect is "accept + erratum", not a Critical.

## Why
Measured 2026-09-17: 14 fix sessions against 34 build sessions — 7 were spec/plan defects the coder found first, 4 were
tooling that ate correct work, 3 were real coding errors. Dispatching 21 tasks whose specs were never tried against
the tree made 21 coders discover the gaps in parallel, and the "edited acceptance test = C" rubric turned each typo
into three rounds.

Folded in from the same memory: readiness is by ingredients, not wave number (the operator 15:50 "don't slow us down") — see
[[R-0088]]; tooling never loses finished work (no backgrounded gates, the harness lock); launcher and brief files are
generated from data (the brief generator, the dispatch record), never hand-patched with sed; addendum 17:10 — a task touching an
external vendor gets a dated research page (the research directory) before its brief, see another rule. The
number to watch: "spec defects found by coders" on the scorecard, towards 0; fixes per build from 1:2.4 to 1:10.

## Check
None yet. The source check for this rule sources a shared library bound to one product's repository, state directory, branch naming and scheduled job, so it cannot be carried as it stands. It becomes a check when the rule runner reads those four facts from the product's configuration.
