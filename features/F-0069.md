## Description
(1) A security review pass runs as a required check for every pull request touching authentication, billing, mail, connectors, secret handling or CI credentials — the path classes come from the product's configuration (`product:security_paths`, a new key); its findings land as a check table on the branch and a high finding bounces the pull request before any expensive review round. (2) A rule check reads the code host's secret-scanning and dependency alerts for the product's repository (`product:repo_slug`) every tick and files a severity-one Bug for a secret and a severity-two Bug for a dependency, with the alert as the signature. (3) An exposed-port check for every CI box (the product's runners, `product:ci.labels`) and every machine in the compute plane: on 2026-09-13 a scanner reached an end-to-end database through a publicly reachable port and dropped it. A nightly probe from a runner against each box's public address for the common database and daemon ports, filed as severity one.

## Acceptance
- [ ] the three checks exist as rule cards with scripts
- [ ] a fixture pull request touching a sensitive path is bounced by a planted finding
- [ ] a planted test secret in a branch is filed within one tick
