## Description
The feeder routes a correction to the console (CONSOLE → AMEND) whenever the item's `writes:` reach the amendable set (`asf/feeder/rows.py` correction_rows → `console_amend_row`). It does this even when the amendable file is already on the branch and the pending correction never touches it.

Live case: T-0056 (F-0023). Its branch `worker/T-0056` has carried `asf/briefs/templates/idea.md` since 2026-09-24, so the amendable edit is done. The pending correction is a `footprint` one: the gate was red in tests/test_ingest.py, test_roles.py, test_groom_policy.py, test_views.py and test_sample_product.py, which are outside `writes:`. The branch is also about 1,100 commits behind main. Since then `asf next` has shown "WAITS ON console: amendable asf/briefs/templates/idea.md", and there is no console edit that clears it. The row holds T-0073, T-0119, T-0189, T-0058, T-0166, T-0604, T-0719 and T-0301, and through T-0073 it holds F-0030's T-0140, which blocks the release.

`flags.console_wait: aside` (W8-PR1) releases the dependants. Tried on a scratch copy of the config: T-0073, T-0058 and T-0604 become launchable. It still leaves T-0056 itself stuck.

## Acceptance
- [ ] A correction row goes to the console only when the correction needs an amendable file: either the correction names one, or the branch does not yet carry the amendable paths in `writes:`. Otherwise it is an ordinary FIX → CORRECT or rebase row, and the worker's hook still refuses any write to the amendable set.
- [ ] A test reproduces T-0056's shape (amendable file already on the branch, footprint correction) and gets a launching correction row, not CONSOLE → AMEND.
- [ ] A stale CONSOLE → AMEND row (more than N days, with dependants behind it) surfaces as a NEEDS DECISION line naming its dependants, never a silent wait.
