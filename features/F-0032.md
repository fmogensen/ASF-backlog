## Description
`asf init` is an adopter, not a scaffold. It scans the repository — the specs and plans directories, the CI provider and its workflows, the deploy workflow, the test runner, the branch naming, the documentation directories — and proposes the product configuration file. The operator edits it; nobody writes it from blank. It then adopts existing backlog material into cards, each with a `source:` pointing at the file and line it came from and all undecided for the groom, and adopts existing code as evidence so a mature repository's first roadmap already shows what is done. Nothing is invented: a line that fits no pattern is listed in the first groom file.

## Acceptance
- [ ] init on an existing repository proposes a complete product config the operator only edits
- [ ] every adopted card carries a `source:`; zero cards without one
- [ ] adopting a repository that already has an ASF-shaped record produces zero new cards and a byte-identical roadmap
- [ ] a line that fits no pattern appears in the first groom file rather than being dropped
