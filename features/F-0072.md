## Description
As an operator, I want to install ASF with one command and upgrade it with one command, so that the factory keeps running across versions without anyone copying files, and a stale install refuses to write rather than corrupt a record.

## Acceptance
- [ ] `pyproject.toml` with `[project.scripts] asf = "asf.cli:main"`, version from `asf/__init__.py`; `pipx install git+<repo>@v0.1.0` yields `asf --version` printing `ASF — Autonomous Software Factory <version>`; a GitHub Actions job installs from the checkout with pipx and runs `asf --version` and the test suite.
- [ ] `asf init --product <p>` adopts an existing ASF-shaped record as-is (schema stamped, zero new cards) and writes `~/.ASF/products/<p>.yaml` from discovery; on a repo without a record it lays down the folder layout, README, pre-commit hook and empty index (closes B-0001).
- [ ] Every writing command checks `schema_version` (package vs record `index.json` vs `config.yaml`); a mismatch prints `NEEDS OPERATOR: run asf migrate — <what differs>` and exits 3 without writing; reads still work.
- [ ] `asf migrate [--drain]` applies forward-only, idempotent, numbered migrations per product, commits `migrate: schema a → b` to the record, refuses while sessions are in flight unless `--drain`.
- [ ] `asf scheduler install` and `asf hooks install` are idempotent, reference the absolute `asf` path resolved from PATH, and stamp `ASF_VERSION`; `asf doctor` shows installed version, each product's schema version, each loaded job's version, and flags a mismatch.
- [ ] `asf upgrade` wraps `pipx upgrade`, then runs the schema check and prints what to do next.
- [ ] No code path reads a tools directory under `~/.ASF` or a checkout path; `check_generic` and a test assert it.
