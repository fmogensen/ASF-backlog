## Description
First customer, 2026-09-24. A product's NEXT showed only 6 BUG→FIX rows, while 94 tier-2 rows (47 PLAN→CODE, 27 CARD→SPEC, 12 STARVED→PLAN, 8 STARVED→SPEC) sat behind the S1 gate (asf/feeder/tiers.py:26-44). One decided S1 Bug with no session held all Feature work, and no view said so. The operator's session found it only by tracing the code.

Separately, NEXT and the tick plan from different inputs. `asf next` reads product.backlog_dir/index.json (asf/feeder/render.py:93-95), which is the operator's checkout and can be days old. The tick reads its own record clone (asf/tick/step_wave.py:176) and applies plan_order.overlay, which next skips. So NEXT can show rows the tick would never launch, and miss rows it would.

## Acceptance
- [ ] NEXT and STATUS name the gate whenever a tier cut drops rows: `S1 gate: B-nnnn holds N rows (PLAN→CODE a, CARD→SPEC b, …)`. The same line goes in the tick log when the wave launches no tier-2 row because of it.
- [ ] An S1 that is not being worked (no session, not launchable, e.g. blocked, or waiting on the operator) does not hold the wave silently. After one tick it appears as NEEDS OPERATOR with the held count.
- [ ] `asf next` plans from exactly the tick's inputs: the tick's record clone (fetched if stale) plus plan_order.overlay plus the ledger reads it already shares, through one function both call. A test asserts that next and the wave produce the same rows from the same state.
