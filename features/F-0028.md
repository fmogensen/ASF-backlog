## Description
The prototype recorded 11.6 M input tokens for two phases of one run because the four token dimensions were never separated. `metrics/sessions` carries input, output, cache-read and cache-write per session; caps are set per job kind; the scorecard shows tokens per Feature beside the money.

## Acceptance
- [ ] every session line carries the four dimensions separately
- [ ] a job over its cap ends with a cap result line rather than an unbounded spend
- [ ] the scorecard shows tokens per Feature beside cost
