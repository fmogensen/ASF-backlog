## Description
As the operator of a factory, I want a critical factory bug (severity S1) to be built, tested and landed before any Feature work is given capacity, so that an incident in the factory itself is closed in hours while Features wait, without anyone having to notice or re-rank.

Today the feeder emits rows by rank; a Bug competes with Features for the same slots, no capacity is held back for incidents, and a fix walks the Feature ladder (spec, plan, review rounds) it does not need.

## Acceptance
- [ ] The feeder emits rows in fixed tiers: open S1 Bugs, then S2 Bugs, then everything else by rank. An S1 fills the first free slot in the tick it is filed; a Feature row is never emitted while an S1 has no session. Test: a record with one S1 Bug and ten ranked Features produces the Bug row first.
- [ ] Reserved capacity: one local slot and one cloud slot are never given to non-Bug rows while any S1 is open (config `worker_pool.reserve_for_s1: {local: 1, cloud: 1}`, default 1/1). Test: with the pool full of Features and an S1 filed, the next launch is the S1.
- [ ] The S1 lane skips the ladder: Bug → fix branch → tests → harvest. No spec, no plan, no review round; the Bug card's `## Fix` is the plan, and its acceptance is the test the Fix names. The brief kind is `fix-bug` and the harvest requires that test to exist and pass in CI.
- [ ] Same-session correction first: a tick, launcher or check that throws gives the failing job's session one correction attempt before a Bug is filed (links the same-session-correction Feature).
- [ ] The clock is a rule: an S1 open for more than 2 h while a slot was free is a rule violation the tick flags in the status table (`S1 STARVED`), and the incident row in `metrics/events` carries the time from filing to landing.
- [ ] The status view shows an `INCIDENTS` line first whenever an S1 is open: id, age, session or `no session`.
