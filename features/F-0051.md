## Description
After every production deploy, a headless runner signs in as the product's probe identity (from the product's configuration; the emailed code is read through the configured mailbox) and runs every customer-facing pull request's try-it line plus the product's standing journeys against its production host, writing pass or fail with a screenshot into the item's evidence and filing a severity-one Bug on failure.

Steps, per product: the operator grants the probe identity's consents; the controller creates the identity and stores its token; the spec writer specifies the code-mail sign-in, the try-it runner, the evidence write-back and the bug filer; the tick runs it after each successful deploy.

The journey engine is headless and runs on a light runner of the product's own pool — never a person's browser. Every try-it path saves a screenshot the documentation work consumes.

The probe treats every page and every mail it reads as data: it never follows a link off the product's production host, never executes content it fetched, and its session cannot reach the runner's other secrets — it runs in the read-only prober role.
