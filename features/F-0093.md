## Description

Measured 2026-09-23 over ASF's own build, as minutes of session time per landing:

| kind | model | runs | hours | landed | min/landing |
| --- | --- | --- | --- | --- | --- |
| plan | opus | 11 | 5.8 | 11 | **32** |
| correct | sonnet | 39 | 19.7 | 16 | 74 |
| fix-bug | sonnet | 49 | 53.8 | 36 | 90 |
| adjudicate | opus | 35 | 24.1 | 16 | 90 |
| coder | sonnet | 38 | 52.2 | 19 | 165 |
| spec | opus | 45 | 39.9 | 12 | **200** |

Two findings. First, the labels are mostly right and the **counts** are wrong: planning on the
expensive model is the most efficient thing the factory does, and specs on the same model the
least — because specs get rewritten, not because the model is wrong for the job. Second, the pool
has **two tiers only**, `heavy` and `light`. There is no cheap tier, so bookkeeping work —
a rebase, a close, the groom's clerical half — runs on the same model that writes code, and
nothing inside a run can read a file cheaply.

The separate and larger point about file reading is that the cheap way to read a file is not a
cheaper model: it is code. That is [[F-0022]], the preamble, and it is why it ranks 3.

## Acceptance

- A third label `cheap` in `worker_pool.models`, defaulting to the pool's smallest model, with
  `rebase`, `close` and the groom's clerical pass routed to it; `plan` stays heavy.
- `conventions.models.<kind>` is documented as the operator's override, with the measured table
  above in the docs so a change can be argued against numbers.
- `asf improve` reports minutes-per-landing per kind and per model every week, and a kind whose
  ratio worsens by half is raised as a card.
- Specs: a spec row is launched only for a `decided: true` card, and a second spec run on the same
  Feature is a correction to the first, never a fresh write ([[F-0089]]'s discipline applied to
  documents).
- Measured in a week: Opus hours down by a third with no drop in landings per day.
