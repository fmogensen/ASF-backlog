## Description
Three parts. (a) Check rules: every supersession target exists, there are no cycles, a superseded item carries its successor, and a superseded rule is excluded from the rule run. (b) A pass over the live rules and decisions that pairs candidates — statement token overlap above a half, or the same scope plus a shared named object — and writes them into `groom/<date>.md` under a conflicts heading with both statements, their sources and the precedence hint. (c) The groom's apply step understands `keep A`, `keep B`, `both` and `merge`, where merge gives the survivor the other's source line and history and marks the loser superseded.

## Acceptance
- [ ] check fails a dangling or cyclic supersession
- [ ] a pass over a live rule and decision set lists its pairs in the groom with no false pairs among the top twenty
- [ ] the groom's apply step executes all four answers
- [ ] a superseded rule no longer runs in the rule check

## Non-goals
Automatic resolution; a model pre-sort, except when the pair count is large.
