## Description
Every factory skill runs one script and prints its output verbatim — code, not a model — but the tools hardcode one product's name in over a hundred files, while a per-product configuration file already exists and only the spawner reads it. Work: (1) one configuration source, a module and a shell include, that every tool imports, so a product name appears only in that product's own file; (2) the tooling moves into its own repository, with the working copy becoming a checkout of it, which also takes the last factory scripts out of the product repository; (3) the missing operator commands are added, each one script: the groom, the rules, a new card, one item, the stale list, the cost, the releases, the last tick, the current product; (4) a hand-kept experiments notebook is dropped — an experiment is a Decision with a date and two readings, measured by the frozen eval set; (5) the status commands read the metrics streams and a cached queue so they print in under five seconds, and the dispatch record carries the item id; (6) output contracts, because a table whose shape keeps changing reads as model-generated: every table's header and column list is frozen in a data file and asserted by a test, a column change must change the golden in the same commit with a one-line reason, every output ends with a stamp line, and the tick's tables carry a hash a rule check recomputes — a rephrased or unstamped table is a violation.

## Acceptance
- [ ] a grep for any product name over the tools returns only that product's own configuration file
- [ ] adding a second product's configuration file makes every command print for that product
- [ ] each command prints in under five seconds
- [ ] every output carries the stamp line and matches its frozen header
- [ ] the tick's table hash check is enforced
