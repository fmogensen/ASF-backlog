## Description

Measured 2026-09-23 over ASF's own build: **22 items took three sessions or more and consumed
$164.86 — 62 % of all spend.** Had each stopped at its third session, the same items would have
cost about $96, so **roughly $68 of $267 (26 % of everything spent) went to sessions four and
beyond on items that were already in trouble.**

| item | sessions | spend |
| --- | --- | --- |
| B-0016 parallel spawns race on `.git/config` | 14 | $16.64 |
| F-0075 redaction is a gate on every write path | 7 | $16.59 |
| T-0021 harvest reads the merge classes | 9 | $13.53 |
| T-0017 the approvals hook | 10 | $8.65 |

A fourth session on an item is almost never a fourth attempt at the same problem — it is the
factory not knowing something (a missing dependency, a stale brief, a spec that cannot be built
as written). More sessions do not supply that knowledge; they pay for it again.

There is also **no cap of any kind on a single run today**: no turn limit, no wall clock. A coder
run averages 82 minutes and nothing stops a longer one.

## Acceptance

- Every item carries a budget — default **3 sessions or $10, whichever comes first**, set per
  product in `~/.ASF/products/<p>.yaml` and overridable per item.
- On the budget being reached the item stops: no new row of any kind is launched for it, the tick
  prints one `OVER BUDGET <id> — <sessions>/<usd>` line, and the item waits for a ruling (the
  operator's, or the factory's own under the product's autonomy level).
- A single run carries a wall-clock cap and a turn cap from the same config; a run that hits one
  is ended and recorded with that reason, not left to run.
- The budget and its consumption are in the card's `cost` block, so `asf backlog` can sort by it.
- A property test: no row is launched for an item whose budget is spent.
- Measured in a week: no item over 3 sessions without an explicit budget raise.
