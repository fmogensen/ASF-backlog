## Description
An eval is not a test. A test asserts a contract and is edited when the contract legitimately changes; an eval is a measurement instrument — frozen, scored as a rate, and compared between a candidate and an incumbent. A task edited after a failure is no longer a measurement.

An `evals/` set: must-fire and must-not-fire pairs for the item matcher, for every enforced rule check, and for the brief generator's kind detection; scored daily into the metrics; a set hash so a changed set produces a new instrument rather than a silently comparable reading; and a pre-commit hook that refuses a commit changing an eval task and the tool it measures in the same breath.

## Acceptance
- [ ] at least two tasks per judged tool, with the set hash recorded
- [ ] a daily scorecard line: evals passed over total, per lever
- [ ] the hook refuses a task-and-tool commit
- [ ] a lever the set has no task for lands with a recorded, counted exemption rather than silently

## Non-goals
Model and prompt evals — they need a live model and a seeded fixture repository; later.
