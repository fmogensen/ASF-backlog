## Description
A role file carries identity, doctrine (each rule with the incident behind it), its output contract including the named side file, its economy (what it may read before it is paying to read), and its boundaries (what it may write and what it explicitly does not do). Model, backend and effort are operator configuration, not identity; tools and gates come from the phase. Our set gains interrogator, diagnostician, security and documenter beside the existing writer, reviewer, coder, fixer, prober and harvester roles.

## Acceptance
- [ ] every role is one file with all five sections
- [ ] no role file names a model; the assignment is configuration
- [ ] a session's role file and rule set are recorded with its result
