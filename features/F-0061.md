## Description
Rules bite in the tick today — after the fact. Hooks in the worker configuration run a script at the tool boundary and can refuse the call. Before a shell call: refuse a blanket stage, a stash, a push to the main branch, a commit whose message lacks the item id when the working directory is a record or a product worktree, a card mint without an id range in a worktree, and a pull-request creation whose body lacks the lines its lane requires. After an edit or write inside a record: run the record's check on the touched file. At the end of a session: refuse to finish with uncommitted changes in a worktree, and print what is left.

Each hook is a small script named after the rule card it enforces, so a rule card gains a third field beside its check: a hook.

## Acceptance
- [ ] the named refusals fire in a fixture session
- [ ] every hook script is named by a rule card, and the rule cards list their hook
- [ ] the worker configuration loads them
- [ ] violations of hooked rules fall to about zero in the metrics
