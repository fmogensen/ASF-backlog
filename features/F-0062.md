## Description
(1) Skills as procedures: the review standard, the coder's pre-push gate, the spec template and the writer's report shape become plugin skills loaded on demand, so briefs shrink to the card, the row and the skill names. (2) Role agents: reviewer (read-only, no push), coder (edits and branch push, no merge), fixer, prober (read-only, no write, no external tools), spec-writer (read-only access to the memory interface) — model and effort per role, from configuration. (3) Per-job caps on every launch: a turn limit and a budget cap per kind, verified against the installed version's flags; the lowest effort for mechanical jobs. (4) Deny rules in every worker configuration: reading environment files and secret directories, printing the environment, fetching with key-shaped arguments; and a hook that redacts token-shaped strings from tool output before it reaches the transcript. (5) Permission modes per role: reviewer and prober read-only, coder accepting edits, and only the harvest step may push to the main branch. (6) An allow-list of external tool connections per role: none by default.

## Acceptance
- [ ] the role files exist and the launcher picks them by kind
- [ ] a fixture reviewer session cannot write or push
- [ ] a job over its cap ends with a cap result line in the session stream
- [ ] a fixture transcript contains no token after the redaction hook
- [ ] briefs are at most 40 % of today's size, measured as prompt tokens per launch
