## Description
A near miss is corrected in place, never restarted — the session that produced it holds the context. Today every review round launches a new fixer session (round 1 → fixer → round 2 → fixer), which is the biggest cost driver in the factory. Change: a review's findings are sent to the writer's still-live session with the check table attached; a new fixer session is launched only when the writer's session is dead (heartbeat stale past the product's configured limit, six minutes by default).

Both halves already exist in the harness: a local job continues by resuming its recorded session id, a remote one receives the findings through its trigger. No new mechanism.

## Acceptance
- [ ] a round-one review with findings reaches the writer's session and the writer pushes the fix without a new session
- [ ] a dead writer session falls back to today's fixer launch
- [ ] fixer sessions per merged pull request halve over seven days, from the product's own session stream

## Non-goals
Rewriting the review standard itself.
