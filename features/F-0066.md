## Description
Stall detection reads silence — no push and no log write for forty-five minutes — so a job that is alive but stuck, looping on a denied command or exiting early with a clean code, passes as healthy. Two such jobs did on 2026-09-21. The spawner writes a progress line into the job's own record every minute from the job's event stream: the last tool call time, the distinct tool classes in the last ten minutes, and the last commit in the worktree. The stall check flags a job with no new commit, file or tool class for twenty minutes as stalled on progress, and a job whose result text says it is blocked or waiting as needing input — both rows the tick acts on, by probing and relaunching from the branch or by raising a needs-operator line.

## Acceptance
- [ ] the two new row kinds appear in the stall check
- [ ] a fixture job that loops on a denied command is flagged within twenty minutes
- [ ] the session stream carries the progress class per session
