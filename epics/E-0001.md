## Description
`asf init` in any repo gives a product its record, its tick and its tables in 20 minutes; ASF builds itself through the same mechanism; the first product runs on it with the same tables it has today.

Where we start: the factory built by hand is about 70 % of an ASF and about 20 % generic — its tools hardcode one product, its conventions (spec and review paths, branch prefixes, deploy shas, runners, worker accounts, the scheduler) are baked in, and the factory's own roadmap lived inside a product's backlog. This Epic is the work that turns that into a product: a package, an operator config, a record of its own, and a public repository.

## Acceptance
- [ ] `asf init` on the sample product from a clean operator config: the backlog is created, the first `asf tick` commits, and `status` / `roadmap` / `backlog` print stamped tables — under 20 minutes, scripted as a test
- [ ] shadow mode on the first product: 3 days with zero unexplained differences; the six tick tables byte-identical modulo the stamp line
- [ ] this record holds the factory subtree migrated out of the first product's backlog, and `check` is green in both records
- [ ] core rules: `asf rules check` on the first product and on the sample runs the same core set, with product rules only where the product config adds them
- [ ] evals: `asf evals` prints a scorecard, and the hook refuses a commit that changes an eval task and the tool it measures together
- [ ] the public repository: CI green; a grep for any product, company, person, vendor or host name over the package returns nothing; the quickstart followed by a fresh session with no context succeeds
- [ ] dogfood: one ASF Feature goes card → spec → plan → build → harvest → release notes through ASF's own tick, with its cost and rounds on the scorecard; one factory Bug filed from an error becomes a proposed card that a human approves

## Non-goals
The hosted service; a web UI; adopting the prototype's code.
