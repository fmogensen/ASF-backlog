## Description

## Acceptance
- [ ] A record checkout cloned at `B-0267` while origin carries `B-0268` to `B-0270` returns `B-0271`, `B-0272`, `B-0273` from three successive `mint_id(root, {}, 'bug')` calls, never an id origin already holds
- [ ] `ids.origin_top(root, 'B')` reads `origin/<trunk>`'s tree and returns 270 for that checkout, while `ids.record_top(root, 'B')` still returns 267
- [ ] `origin_top` returns 0 rather than refusing when there is no origin, no trunk, or the fetch fails
- [ ] The `claim or worktree` gate is gone: `mint_id` called with `claim=False` outside a worktree, in a checkout that has an origin and has claims enabled, creates the one claim ref for the id it returns
- [ ] The floor a mint clears is the greater of the working tree's top and `origin_top`, in the claim path and in the local fallback alike
- [ ] Two checkouts cloned at the same commit that both mint do not come back with the same id
- [ ] The local fallback's step-over-a-claimed-block guard reads the claim mirror after the same fetch `origin_top` runs, so it is no longer as stale as the checkout
- [ ] `BACKLOG_ID_RANGE` still wins and claims nothing new: with `B:0500-0549` in the environment, `mint_id` returns `B-0500` and adds no claim ref
- [ ] A record with no `origin` keeps the local path: a checkout at `B-0267` mints `B-0268`
- [ ] A product at `conventions.flags.id_claim: off` keeps the local path but still clears origin's floor: a checkout at `B-0267` behind origin's `B-0270` mints `B-0271`
- [ ] `_resolve_by_ownership` tells add/add from modify/modify by the three stages it already reads, and returns the record-relative paths it discarded, or `None` for the conflicts it still refuses
- [ ] A push that discarded cards add/add prints one further line naming their ids, as in `tick: 3 card(s) discarded by the rebase — origin already holds these ids: B-0268, B-0269, B-0270`, and the tick raises one `NEEDS OPERATOR` naming the same ids as the ones to re-file
- [ ] A modify/modify resolution still prints exactly one line, `tick: origin moved — re-derived onto origin/main and pushed` — proven by tests/test_tick.py
- [ ] `idclaim`'s own contract is unchanged — one create-only ref per id, an existing ref never overwritten, a `ClaimError` when origin is unreachable, and the local block under `id_claim: off` — proven by tests/test_idclaim.py
