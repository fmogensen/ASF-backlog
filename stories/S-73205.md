## Acceptance
- [ ] `reviews.required('code')` is byte-identical to today; `reviews.required('spec', 'code')` is the five spec names then the six code names, each once, in checklist order
- [ ] `review_kinds('spec', CODE)` is `('spec', 'code')`, `review_kinds('spec', DOCS)` is `('spec',)`, and `review_kinds` of a code, fix, direct or unknown branch kind is `('code',)` at either class
- [ ] a filled spec+code table scores `APPROVED` against `required('spec', 'code')` **and** against `required('spec')` — the lane and ingest agree (P11, P14)
- [ ] a filled code-only table still scores `BOUNCE` against `required('spec', 'code')`
- [ ] `Lane.record` writes `class` on the record when `facts()` read one, and omits it when it did not; `occupancy` carries it onto the `review` and `landing` entries
- [ ] `lane_rows` sets `review_kinds` on the `PUSHED → REVIEW` row from that class, and `('spec', 'code')` when the record carries no class (C10)
- [ ] the lane's own transition is unmoved: a docs-only document branch is `review: none`, and `transplant_case` still refuses a `spec`/`plan`/`direct` branch
