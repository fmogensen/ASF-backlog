## Description

## Acceptance
- [ ] `'events' in metrics.STREAMS`, and `metrics.SCHEMAS['events']` carries exactly the keys `ts, kind, key, product, tick, item, job, account, branch, text, fields` and no others
- [ ] `validate('events', …)` fills `ts` when the line carries none, and defaults `fields` to `{}`
- [ ] `validate('events', …)` raises `SchemaError` for a `kind` outside `log.KINDS`, and for a line carrying no `key`
- [ ] `validate('events', obj, items, product='p')` fills `product` from the argument, and leaves it `None` when no product is passed
- [ ] `validate('events', …)` carries an `item` that `ID_RE` does not match — `inbox:<name>`, a five-digit id — through untouched instead of refusing it
- [ ] `validate` dispatches a `ticks` line by name, so an `events` line never reaches the ticks branch and never raises `KeyError: 'launches'`
- [ ] `_apply` fills a `PRODUCT`-defaulted field without raising `TypeError: Object of type object is not JSON serializable`
- [ ] `natural_key('events', ev)` is `(ev['kind'], ev['key'])`, and `natural_key('ticks', ev)` is still `(ev['tick'],)`
- [ ] `append_event` answers `'exists'` for a second line with the same `(kind, key)` in the same day file, and leaves one line in it
- [ ] `log.KINDS` contains `groom_answer` and `intake`, so the groom's `groom_answer` calls are not refused and the two intake-latency rows still measure
- [ ] `intake_latency_rows` reads `filed`, `field` and `value` from `ev['fields']` on a new line and from the top level on a line written before this Feature
- [ ] `product` defaults to the `PRODUCT` sentinel on `ci`, `sessions`, `ticks`, `landings` and `gates` as well
