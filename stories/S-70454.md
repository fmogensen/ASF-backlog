## Description

## Acceptance
- [ ] `references:` is a declared top-level field of the product file: a product carrying `references:
  - id: parity
    source: stories
    epic: <an Epic id>` validates with no "is not a field of the product file" problem
- [ ] `env._reference_problems` returns exactly one dotted-key problem, at the section's line, for each of: a non-list `references:`, a non-map entry, a missing or empty `id`, a duplicate `id`, a key outside `REFERENCE_FIELDS`, a `source`/`decide`/`evidence` outside its declared tuple, `source: stories` with no `epic`, `source: file` with no `path`, a `path` on a `source: stories` entry and an `epic` on a `source: file` entry
- [ ] a well-formed `references:` block of two entries produces no problem at all, and a key left `None` is "not filled in yet" rather than a problem
- [ ] `Product.references` returns a tuple of frozen `Reference` objects in the yaml's declared order, with `source: stories`, `decide: ask`, `evidence: test` and `name` falling back to `id` filled in the property and not in the checker
- [ ] `Product.reference()` returns the first declared reference, `Product.reference("<id>")` the named one, and both return None when the product declares none
- [ ] a product declaring no `references:` but a truthy `conventions.matrix_path` yields exactly one synthesised reference — `id: parity`, `source: file`, `path` the matrix path, `evidence: merge`, `decide: ask` — so every already-closed matrix Story keeps closing on `tasks-closed`
- [ ] a product with no `conventions:` key at all and a product with `conventions: {}` each yield `()`: the synthesis tests `matrix_path` for truth, not for presence, because `DEFAULT_MATRIX_PATH` is None and the key is present on every product
- [ ] `docs/products.example.yaml` documents a top-level `references:` block with every field commented and the Epic id as a comment placeholder, and `conventions.matrix_path`'s comment says it now reads as one `source: file` reference that `references:` supersedes
- [ ] `env.validate_product_text(docs/products.example.yaml)` is still `[]` — proven by tests/test_env.py
- [ ] both shipped product yamls, `sample/product.yaml` and `tests/e2e/product/product.yaml`, still validate clean and still resolve to no reference, neither file edited
