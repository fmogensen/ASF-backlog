## Description

## Acceptance
- [ ] worker_perms.settings appends every derived rule the operator's object does not already carry, after every entry already there, in the derivation's order
- [ ] the operator's own allow entries and their order come back unchanged, and nothing of theirs is reordered or deduplicated
- [ ] every unrelated top-level key of the operator's object, and every unrelated key inside its permissions block, comes back untouched
- [ ] an operator permissions block with no deny key comes back with no deny key, so ASF invents no key in a file the operator reads
- [ ] an operator deny list, where they have one, is carried through and no rule of theirs is removed
- [ ] two composition calls over an unchanged product give one list, with no rule duplicated
- [ ] worker_perms.path writes the composed object under the product's own state directory, and leaves the file's modification time alone when the rule set has not changed
- [ ] a worker pool settings file that is configured but not on disk still raises out of path and refuses the launch
- [ ] the command line a session is launched with names the composed file as its settings, including for a pool that configures no settings file of its own and today carries none
