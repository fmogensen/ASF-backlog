## Acceptance
- [ ] [ ] heartbeat.verdict returns one of exactly five names: alive, unknown, no-first-beat, frozen, looping
- [ ] [ ] an observation whose unknown flag is set reads unknown whatever else it carries, and its why says origin was unreadable
- [ ] [ ] a run with no beat ever seen reads alive before grace_min plus limit_min has passed and no-first-beat after it
- [ ] [ ] a run whose last movement is older than limit_min reads frozen, and the minutes it returns are the minutes quiet
- [ ] [ ] frozen outranks looping: a run with a stale same-tree counter and no movement at all reads frozen
- [ ] [ ] a run whose same_tree counter has reached loop_beats while its branch head has not moved for loop_beats times interval_min reads looping
- [ ] [ ] the same run with its branch head moved inside that window reads alive, so a committing session is never called looping
- [ ] [ ] a run with a movement inside limit_min reads alive however old it is, asserted at ten times limit_min
- [ ] [ ] verdict is pure: called twice on one observation it returns the same answer and mutates neither it nor the settings
- [ ] [ ] Settings carries loop_beats with a default of 4, and limit_min is still interval_min times missed
- [ ] [ ] kernel_settings turns a read kernel heartbeat block into Settings, and a block with a key left out takes that key's default
- [ ] [ ] heartbeat.judge keeps its signature and its answer for every case the landed tests cover, because verdict calls it
