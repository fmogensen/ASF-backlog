## Acceptance
- [ ] [ ] the action order puts every landing write, every Done mark and every session end before the first launch, asserted off the order itself so a new action type appended after a launch fails
- [ ] [ ] a plan carrying a landing write, a Done mark, a session end and a launch applies them in that order
- [ ] [ ] the tick block gains a max seconds key with a default of 600 and a launch budget key with a default of 0
- [ ] [ ] both keys are validated as non-negative integers and a malformed value refuses the product load
- [ ] [ ] the applier takes a deadline and checks it immediately before each launch and nowhere else
- [ ] [ ] past the deadline the remaining launches are not applied, leave no attempt on their items and are not failures
- [ ] [ ] the launches a budget held are returned on the apply result and logged in one line naming the budget
- [ ] [ ] no action other than a launch is ever skipped by the budget
- [ ] [ ] a launch budget of zero applies every launch exactly as it does today
- [ ] [ ] every applied tick appends one row to its own new ledger with its wall seconds, its step times, its slowest step, its seats, its live sessions, its Ready count and its launches
- [ ] [ ] the slowest step may name the action class the applier spent its time in, not only the apply step as a whole
- [ ] [ ] a tick over the max seconds records the breach on that row and logs a breach line naming the limit and the slowest step
- [ ] [ ] a tick under it logs its own line with the same figures and records no breach
- [ ] [ ] a max seconds of zero records the row and never breaches
- [ ] [ ] a blind tick records its row and a tick that failed before it applied records none
- [ ] [ ] the kernel status carries one alarm line for a recent tick breach, above the biggest wait
- [ ] [ ] a ledger that cannot be written is one line and never the end of the tick
