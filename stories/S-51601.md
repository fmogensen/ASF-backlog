## Acceptance
- [ ] `plan_order.plan_own_ids` maps an id token that a `### Task N:` heading or the first lines of that section name onto Task number N, and does not map an id that only the section prose mentions.
- [ ] `derived_after` keeps an `after:` id that neither `known` nor the plan own-id map holds, so a Task carrying `after: T-14651` reaches the record with that id instead of an empty list.
- [ ] `derived_after` still drops an `after:` naming the card itself or its parent, and leaves an id that `known` holds unmapped even when a heading names it.
- [ ] `task_rows` answers a Task whose `after:` names an id in neither `items` nor `landed` with a non-launching `WAITS ON <id>` row plus one `RESHAPE → PLAN` row per Feature whose reason starts `unminted after:` and names the id.
- [ ] A predecessor that is minted but has not landed still gives the plain `after: <id> has not landed` row and no reshape row.
- [ ] `hold_unlanded` leaves the paired reshape row alone instead of rewriting it into the symptom.
- [ ] `asf/briefs/templates/plan.md` states the rule the refusal quotes: an `after:` names the plan own Task numbers, `none`, or an id the record already holds.
