## Acceptance
- [ ] The one gate in process_inbox is `severity_of(card) in DECIDED_BY_SEVERITY`, and no other call site reads the severity to decide whether to supply
- [ ] A supplied card carries a `## Intake` section holding one line per supply plus a closing line naming the severity
- [ ] The History of a supplied card carries the shape token `by-rule-<rule>`, so a default Epic supply reads `shape: by-rule-default -> feature`
- [ ] asf index and asf check are both rc 0 over a record holding a supplied card
- [ ] The groom line for a supplied card under "Inbox cards to decide" reads `from inbox as <type> (by-rule-<rule>), awaiting a decision`, and the card appears in no "Inbox cards with a question" list
- [ ] Every intake Bug at S1 or S2 is minted `decided: true`, supplied or not, with the closing `## Intake` clause saying why
- [ ] The same intake Bug card at S3 is minted `decided: false` and carries no `## Intake` section
- [ ] A supplied S1 Feature is minted `decided: false`
- [ ] process_inbox prints one `groom: intake ruled <intake_dir>/<file> -> <id> (<Sn>): <clauses>` line per supplied card, naming the record-relative intake path, the new id, the severity and every clause
- [ ] That printed line carries no absolute path and no machine path
- [ ] The `## Intake` text of a supplied card matches no card-id token but the parent it supplied, and the derived Backlinks of the minted card hold only the chain of that parent
- [ ] The `inbox N card(s)` and `asked N` summary of cmd_groom counts a supplied card in inbox and not in asked
- [ ] bash tools/check_generic.sh and bash tools/check_conventions.sh are both clean over the change
- [ ] The inbox paragraph of docs/guide/operating.md names the S1/S2 rule, the three residues and the `## Intake` section, and no longer says that a `type:` line is not read
