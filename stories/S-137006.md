## Acceptance
- [ ] [ ] a Feature's Stories come back in rank order then id order, and a retired or removed Story is not among them
- [ ] [ ] a Task is owned by the first Story of that order it covers, whatever order its own stories line lists
- [ ] [ ] a Task whose parent is a Story is owned by that Story when it covers no earlier one
- [ ] [ ] a Task covering no Story of the Feature is owned by none and appears in no slice
- [ ] [ ] each slice holds exactly the free Tasks one Story owns, in plan order, and the lead is the first of them
- [ ] [ ] the slices come back in the Feature's Story order, not in the order their Tasks appear
- [ ] [ ] a Story owning nine Tasks is one slice of nine and is not cut, where the feature unit would cut it at six
- [ ] [ ] a Story whose union footprint is twenty-two entries is one slice and is not cut, where the feature unit would cut it at fifteen
- [ ] [ ] a Story owning one free Task forms no delivery and that Task keeps its own lane
- [ ] [ ] a size s Feature with two Stories becomes two slices, not one whole delivery
- [ ] [ ] the preview and the pass return the same three-tuples for the same record, and the third element is the Story under the story unit and None under the feature unit
- [ ] [ ] a member whose after edge points at a Task outside its slice that itself waits on a member of that slice is left out of the delivery, which lands without it
- [ ] [ ] that left-out member gets its own PLAN to CODE row and is not re-bundled by a later pass
