## Acceptance
- [ ] `dead_why` is an entry in `lifecycle.RUN_FIELDS`, so it belongs to one launch and never folds into the next
- [ ] health writes `dead_why` beside `dead_class` for a cloud `dead pid` death, and leaves it unwritten for a local one
- [ ] `cloudpid.why(tok)` answers the token's `why` from the status file, and `''` for a token it does not hold
- [ ] `end_reason` is byte-identical to today's and `lifecycle.is_dead_reason` still answers True on it
- [ ] `refusals.dead_reason(run, product)` composes the stored `dead_why` with a refusal recorded after the run ended, so a naming refusal the lane records in a later pass still appears
- [ ] `refusals.dead_reason` answers `''` for a run that carries no `dead_why`
- [ ] `health.dead_census` counts a `by_refusal` axis beside `dead_class`
- [ ] `health.dead_census_line` appends `; refusals: naming 3, pre-push 1` when any refusal is known, appends nothing when none is, and its `ok` rule is unchanged
- [ ] `views.sessions`' Dead group carries a `Why` column reading the composed line cut to one line, and `-` when there is none
- [ ] A replay of 2026-10-07 (a cloud coder run whose commits name no item, the lane's naming refusal held on it, the workflow run completing `succeeded` with no report commit, the health pass that ends it) has the sync's line, `cloud-sessions.json`'s `why`, the run's `dead_why`, the doctor's dead-session line and the Dead row all name `commits do not name T-44931`
- [ ] That same replay with `refusals.last` stubbed to None has each of those five read back exactly `run <id> ended succeeded without the report commit`, so no later change can quietly restore the old answer
