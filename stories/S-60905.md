## Description

## Acceptance
- [ ] A line whose answer slot is unfilled is not carried: nothing is pending in the state dir after the tick and the card is still undecided on origin
- [ ] A line the checkout's own `HEAD` copy of that groom file already carries verbatim is not carried, so an answer the operator committed themselves leaves nothing pending
- [ ] A groom file the checkout's `HEAD` does not hold at all is read as all new, and every filled slot in it is carried
- [ ] The comparison is the checkout's `HEAD` and never `origin/<trunk>`: a checkout many commits behind origin carries only its own uncommitted edit, not every answered line origin already holds
- [ ] The carry performs no fetch and no network call: it still carries the uncommitted answer out of a checkout whose `origin` is unreachable
- [ ] Two consecutive ticks over one unchanged dirty checkout leave the state dir's `groom` directory exactly as the first tick left it — the same answer is carried once, not once per tick
- [ ] A line already held by a `<date>.operator.answers`, `.answers.done` or `.answers.superseded` file beside the pending one counts as carried, and nothing at all is written when the remainder is empty
- [ ] `asf.groom.answers._ANSWERS_FILE_RE` accepts both `<date>.answers` and `<date>.<word>.answers` — the shape the applier in `asf/groom/groom.py` already accepts — so `2026-10-06.operator.answers` is listed by `pending_answers_files`
- [ ] `pending_answers_files` yields `(path, date)` pairs and `apply_pending_answers` uses that `date`: for `2026-10-06.operator.answers` the date is `2026-10-06`, not `2026-10-06.operator`
- [ ] With a `2026-10-07.answers.done` beside it, `2026-10-06.operator.answers` is reported superseded by `2026-10-07` — the comparison the basename slice made nonsense of
- [ ] An operator's `<date>.operator.answers` and an adjudicate session's `<date>.answers` for the same day both apply on one tick, neither overwriting the other: both cards come out decided on origin
- [ ] A filled slot whose text falls outside `parse_answer`'s grammar is carried, changes nothing, and fails neither the groom step nor the tick
