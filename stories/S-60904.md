## Description

## Acceptance
- [ ] A record checkout whose `groom/<today>.md` carries one filled answer slot for a card, with nothing else carrying it, ends a single `record,groom` tick with that card at `decided: true` on origin
- [ ] That tick prints one line `groom: carried 1 answered line from the record checkout — groom/<date>.md`, naming the groom file record-relative and never by filesystem path
- [ ] An `inbox:<name>` line answered by hand in today's groom file types the intake card on that same tick: an answer of `bug <title>` leaves a Bug carrying that title on origin
- [ ] The tick writes nothing in the operator's record checkout: its `HEAD`, its `git status --porcelain` and the text of `groom/<date>.md` are identical before and after the tick
- [ ] `asf.groom.answers.carry_checkout_answers` writes the lines it carried to `<state dir>/<product>/groom/<date>.operator.answers`, one carried line per line, and returns the paths it wrote
- [ ] `apply_pending_answers` calls `carry_checkout_answers` immediately after `carry_staged_answers`, so a file the carry writes is applied on the tick that wrote it and not on the next one
- [ ] `carry_checkout_answers` reads nothing and writes nothing when `backlog_dir` is unset, is not a git checkout, or resolves to the tick's own record clone — the three guards `sync_operator_checkout` opens with
- [ ] The card the carried answer decides is published from the tick's clone, attributed `groom-operator-<date>`, with no commit in the operator's checkout contributing to it
- [ ] `asf groom --apply` applies the previous day's groom file and today's own, in that order and idempotently, which is the applier the carry hands its file to — proven by tests/test_groom_adjudicate_reach.py
