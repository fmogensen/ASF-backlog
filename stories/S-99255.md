## Description

## Acceptance
- [ ] a plain bullet under an Acceptance heading is an acceptance line, where it was in neither the list nor the body
- [ ] every ordinary Markdown list marker reads the same acceptance line: dash, star, plus, one dot, one paren, and an indented dash
- [ ] a checkbox is still read and the checkbox itself is not part of the item, for an unticked, a ticked and a capital-X box
- [ ] an empty checkbox with no text after it says nothing, yields no acceptance line, and does not keep its block in the body
- [ ] an Acceptance heading is read at any heading depth and in any case, from two hashes to four and from capitals to lower case
- [ ] a nested heading inside an Acceptance block ends the block, and its own heading and paragraph stay in the body
- [ ] a line of hashes that is not a heading does not end the block: a hash run with no space after it and a seven hash line leave the bullets under them acceptance lines
- [ ] a Features list reads the same markers, so a star-bulleted Features list is two features and not none
- [ ] a card under a Feature with plain-bullet acceptance is minted a Story by the parent-feature rule, where it was asked for the list it already had
- [ ] a prose line inside an Acceptance block stays in the body under its own heading instead of being deleted with the block
- [ ] a block that is part list and part prose keeps both halves: the bullets become acceptance lines and the prose stays in the body
- [ ] a block intake read whole leaves no heading behind in the body, exactly as it did before
- [ ] every non-blank line of the card's own note shape reaches the acceptance list, a header, or the Description, and none reaches nowhere
- [ ] the four acceptance lines of that note are on the minted card as four checkbox lines, and the empty placeholder line is not there
- [ ] the severity that note declared is in the minted Feature's Description as the line the operator wrote, and is not written as a typed field
- [ ] the minted card still passes asf index and asf check with no error
- [ ] a note that mints a Bug carries the severity it declared below its body as the typed field, and its Description does not carry the line as well
- [ ] a note that declared no severity mints the card it minted before, with nothing added to its Description
- [ ] a severity line written as the last line of a note is read as the field and leaves the body
- [ ] a severity line written inside the Acceptance block is read as the field and the acceptance list still survives
- [ ] a severity line reads the same whatever its case and whatever the spacing around its colon and value
- [ ] a severity declared in the header block still wins over one written below the body, and the line that disagrees stays in the body
- [ ] two severity lines below the body that disagree are read as neither severity, and both lines stay in the body
- [ ] two severity lines below the body that agree are read as that one severity, and both lines leave the body
- [ ] a line outside the grammar is prose and stays prose: an unclear value, a fourth severity, an empty value, a line with words before the key, and a line with words after the value
- [ ] a note with no severity line at all carries no severity header and keeps its body exactly as written
- [ ] a title severity prefix still grades a card whose body names none, and the prefix is still cut from the title
- [ ] a severity line below the body beats a title prefix, as a header line already did
- [ ] a card stuck on a question whose body grades it S1 is said aloud as one NEEDS OPERATOR line naming its file
- [ ] that same card's groom question line carries the S1 token between its inbox token and its title
- [ ] the question block is cut before the card is parsed, so the severity is read from the card's own body and not from the question text
