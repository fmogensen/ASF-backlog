## Description

## Acceptance
- [ ] [ ] Under auto, with a newer tag and nothing mid-landing, the channel installs that tag through the existing install protocol, leaving the pending marker, the drain and the red-CI refusal unchanged
- [ ] [ ] It then runs scheduler install and doctor for the product through the new install's own asf binary, never in the process that still holds the old package
- [ ] [ ] It logs the card's own upgrade line naming the old and the new release, and the sha-shaped line reading "tick: ran asf upgrade" with the two shas and exit 0
- [ ] [ ] asf release-readiness counts a release-channel upgrade off that sha-shaped line
- [ ] [ ] A doctor that exits zero records the outcome installed in the product's channel state, and the channel reports installed
- [ ] [ ] With an item mid-landing the channel prints the held line counting the items and naming each item and its branch, installs nothing, and reports held
- [ ] [ ] An install that defers reports held and files nothing; one that exits non-zero prints the FAILED line with that exit code, records it, and reports failed
