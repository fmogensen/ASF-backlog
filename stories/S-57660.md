## Description

## Acceptance
- [ ] `log.render(root, product, days)` is a pure function returning the text, and `cmd_log` only prints it
- [ ] `asf log --root tests/fixtures/log/record --product sample --day 2026-09-25` is byte-identical to `tests/fixtures/log/2026-09-25.expected.log`
- [ ] the same render under `TZ=Asia/Tokyo` is byte-identical to the same file — no local clock is read anywhere in the renderer
- [ ] two renders over the same files emit the same bytes in the same order
- [ ] every line is `HH:MM <text>`, the `HH:MM` taken from the event's `ts` in UTC, and the day opens with a `# <day>` header
- [ ] the day's lines are ordered by `(ts, kind, key)` — a total order over the stream
- [ ] one line per event whose `kind` is in `RENDER`; a kind the map does not name is in the stream and not in the log
- [ ] the `WAVE` line comes from the `ticks` stream, placed at its own `ts`
- [ ] `text` is printed as the emitter wrote it, whitespace collapsed and capped at 200 characters, never re-derived from `fields`
- [ ] the render holds no machine path and no account name, and every float carries a fixed precision (`{:.1f}s`)
- [ ] the output has exactly one `\n` per line, no trailing spaces, and ends with `\n`
- [ ] `--days N` renders N day blocks, oldest first, separated by one blank line
- [ ] `log` is a registered command and is absent from `asf.views.header.TITLES`, so it prints neither the title line nor a clock
- [ ] `asf log` never clones, fetches, resets or commits
