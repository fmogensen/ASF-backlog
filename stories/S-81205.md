## Acceptance
- [ ] the newest tag whose every landing check succeeded is the candidate, and the older green tags are not
- [ ] a tag whose CI is red is skipped and the next older one is examined
- [ ] a tag with no run at all is not a candidate: the weaker clear verdict of the upgrade guard is never read here
- [ ] a tag whose checks are pending, or whose checks could not be read, is not a candidate either
- [ ] a repo whose product names no landing checks advances nothing, and the line says why
- [ ] at most the configured number of tags is examined, and the scan stops at the first green one
- [ ] the publication is one fast forward push of the commit to the channel head, through the ref guard
- [ ] a dry run publishes nothing and says what it would have pushed
- [ ] a push the guard or git refuses leaves the log unchanged, so the next run tries the same candidate again
- [ ] the head is never moved backwards: a candidate older than the published one is not published
