## Acceptance
- [ ] A brief for a card whose `writes:` names `db/migrations/0320_add.sql`, under a product that declares the `migrations` sequence, carries `Reserved for this card: migrations 0320 — book exactly this; the next free number is not yours to take.`
- [ ] Every brief of a product that declares a sequence carries the standing rule naming `asf reservations --check`, whatever the kind and even when the card reserves no number at all
- [ ] `asf reservations --check` exits 1 for the branch of a card that reserves `0320` and books `0319`, and names the card's number before the branch's: `holds bands 0320`, then `books 0319`
- [ ] The same card's branch that books `0320` exits 0 and prints `reservations: clean`
- [ ] A file the worktree has added but never staged is checked too: the branch of a card reserving `0320` that has written an uncommitted `0319-x.md` is refused, and the refusal says `uncommitted`
- [ ] `declared` and `writes_bookings` read the same numbers out of one card's `writes:` globs, so the brief's reservation and the lane's hold can never name different numbers
- [ ] `--check` on a branch whose card id is five digits (`worker/T-36950`) finds no card, exits 0, and prints `no card id in the branch name` rather than passing silently
- [ ] Both brief lines survive the cap: with `preamble_max_lines` set to 1 the rendered brief still carries the reservation line and the standing rule
