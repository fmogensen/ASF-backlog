## Acceptance
- [ ] the scripted runtime's job-name item regex is built from the one id grammar in asf.record.core, and takes the whole run of digits before its end anchor, so a five-digit id is never read as its last four
- [ ] on the job name coder-t-49891 the capture is the letter t and the digits 49891, where today there is no match at all, and on coder-t-0891 it stays t and 0891
- [ ] a scripted session's stub writes fill the item and lower-case-item placeholders from a five-digit job name, in the written path and in the commit subject, as they already do for a four-digit one
- [ ] the scorecard's job-name split is built from the same constant, so it no longer depends on a missing word boundary for the kind it returns
- [ ] session_kind returns the same kind for every job name it reads today, five-digit and four-digit alike
