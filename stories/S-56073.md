## Acceptance
- [ ] The FACTORY STATUS table carries a `Features` row whose cell is `landed today n (<id>) · building n · spec/plan n · decided, waiting n · undecided n · median to land <span> (<w>d, n=<measured>)`, the clauses in exactly that order
- [ ] The ` (<id>)` after `landed today n` names the newest-landed Feature and is absent when `n` is 0
- [ ] The cell reads `median to land unknown (7d, n=0)` when no Feature landed inside the window
- [ ] `land_window_days: 14` in the product's conventions measures the median over 14 days and the cell prints `(14d, n=…)`
- [ ] An index carrying no Feature at all gives `no Features in the record`, never a bare `—`
- [ ] `conventions.land_window_days` defaults to 7 and is declared once, as `conventions.DEFAULT_LAND_WINDOW_DAYS` — proven by tests/test_conventions.py
- [ ] A duration in these rows renders in the tables' own `25m` / `5h` / `3d` buckets through `index_reader.span(seconds)`, with `age(ts)` unchanged against `span` over a known timestamp and `age(None)` still `—` — proven by tests/test_views.py
