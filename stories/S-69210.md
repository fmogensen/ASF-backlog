## Description

## Acceptance
- [ ] [ ] A test over `MIGRATIONS` and `CONFIG_MIGRATIONS` is red unless every non-additive entry raises the minor version above the previous entry's.
- [ ] [ ] `schema.snapshot(product, version)` pushes the tag `asf-schema-<a>` at the record clone's pre-migration commit and copies `config.yaml` and every `products/*.yaml` under `~/.ASF/state/backups/config-<a>-<stamp>/`.
- [ ] [ ] A non-additive step snapshots before it applies; an additive step snapshots nothing.
- [ ] [ ] `schema.restore(version)` puts the record back as a new commit, never as a history rewrite and never as a force-push.
- [ ] [ ] `asf upgrade --to <ref>` restores the newest snapshot at or below `<ref>`'s `CONFIG_VERSION` and then installs `<ref>`.
- [ ] [ ] With no snapshot and no `--force`, `asf upgrade --to <ref>` exits 2 naming each file and key the older release would refuse, and installs nothing.
- [ ] [ ] `--to <ref>` and `--ref <ref>` reach the same argument and `pipx` receives the ref as the operator gave it — proven by tests/test_install.py
- [ ] [ ] The previous patch release still reads a record a same-minor migration produced, because every same-minor entry is additive.
