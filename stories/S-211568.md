## Acceptance
- [ ] [ ] the archive folders are the seven item folders under archive, derived from ITEM_FOLDERS and not spelled a second time
- [ ] [ ] an archived card's bytes are identical to the bytes it had in its item folder, and so are its generated view's
- [ ] [ ] the archive is read by the record's own loader given the archive folders, and no module opens an archived card file by name
- [ ] [ ] git records each move as a rename, so following the archived path reaches every commit the card had before it moved
- [ ] [ ] a commit made before the move still answers for the card at its old path
- [ ] [ ] asf show on an archived card prints a first line naming the archive path, the state and date it closed, and the date it was archived
- [ ] [ ] asf show on an archived card prints the card itself below that line, with its children and backlinks derived over the working set and the archive together
- [ ] [ ] asf show on a working-set card prints exactly what it prints today and loads the working set only
- [ ] [ ] asf show on an id neither place holds still says not found and exits non-zero
- [ ] [ ] asf archive --find matches an archived card by id and by title substring and prints one row per match saying it is archived
- [ ] [ ] asf archive --find prints no row for a card the working set still holds
- [ ] [ ] a relative link inside an archived card onto a card that moved with it resolves to the archived file
