## Acceptance
- [ ] [ ] the blame probe runs the test ids it is given on a fresh detached worktree of the sha it is given
- [ ] [ ] the probe reports which of those ids ran, which failed and which the loader could not load
- [ ] [ ] the probe spends one of the per-tick test runs, is cached by its sha and ids, and runs nothing in a dry run
- [ ] [ ] the unittest parser reports the ids that did not load beside the keys it already reports
- [ ] [ ] the suspect of a red spell is the single merged candidate, and its parent is the trunk commit below it
- [ ] [ ] the ids the probe runs are the failing test ids of the red required checks
- [ ] [ ] a spell naming more failing ids than the cap allows is unproven and nothing is reverted
- [ ] [ ] the failing ids passing on the parent classes the spell guilty
- [ ] [ ] the failing ids failing on the parent classes the spell trunk-wide
- [ ] [ ] an id that does not load on the parent classes the spell guilty
- [ ] [ ] a spell with no failing test ids, no parent in the facts or more than one candidate is unproven
- [ ] [ ] a probe that has not run yet, or returned an error, leaves the spell unproven
- [ ] [ ] a revert is planned only when the class is guilty, and its body names the parent, the ids and their verdict there
- [ ] [ ] no revert is planned on a trunk-wide or an unproven class, whatever the candidate count and the revert knob say
- [ ] [ ] with the blame probe class off, no revert is ever planned and the spell goes to its Bug
- [ ] [ ] the blame probe takes the per-tick cap before the question and still-needed probes
- [ ] [ ] the verdict is pure: it reads the facts and the config and touches no disk, network or clock
