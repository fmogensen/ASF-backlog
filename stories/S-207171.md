## Acceptance
- [ ] [ ] a trunk-wide red holds every fresh launch and leaves reviews, fix rounds, rebases and the merge train untouched
- [ ] [ ] a green pull request still merges while the trunk is red
- [ ] [ ] a held item carries the trunk-red idle reason
- [ ] [ ] the hold is recorded on the wait ledger under its own class, with its own target
- [ ] [ ] a hold past its target is a breach on the tick line
- [ ] [ ] the hold lifts on the tick the trunk reads green
- [ ] [ ] the hold lifts on the tick blame lands on a merge
- [ ] [ ] the Bug filed for the spell is exempt from the hold and launches
- [ ] [ ] exactly one Bug is filed for one red spell, however many commits land red on top of it
- [ ] [ ] the spell key names the last green commit and the first red commit, not the moving red head
- [ ] [ ] the Bug title names the failing test and the first red commit
- [ ] [ ] the Bug body names the class, the blame read, the first red commit, the last green commit and the candidates
- [ ] [ ] the Bug body carries a Fixes line per failing test id, so its own proving tests are the red ones
- [ ] [ ] the Bug is ranked ahead of every item on the record
- [ ] [ ] a second tick of the same spell files no second Bug and waits on the open one
- [ ] [ ] a spell whose Bug is already Done files no new Bug and waits for the trunk to rerun
- [ ] [ ] with the hold knob off nothing is held and the Bug alone answers the spell
