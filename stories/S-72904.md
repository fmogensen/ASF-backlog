## Acceptance
- [ ] harvest.gate_commands returns the test command alone for a product whose checkout is not this package's own
- [ ] for this package's own checkout it returns the test command followed by one bash argv per entry of the gate's script registry, in that registry's order
- [ ] both of the registry's two scripts are in that list, so neither of the repo's own lints is allowed while the other is refused
- [ ] a leading NAME=value token of the test command comes back in the returned environment and is absent from the returned argv
- [ ] with the bisection's targeted re-run asked for, the scripts are absent even for this package's own checkout
- [ ] a conventions object with no test command returns an empty command list and an empty environment for a checkout that is not this package's own, and the two scripts alone for one that is
- [ ] a third name appended to the gate's script registry comes back as a third argv, in place, with no other edit
- [ ] product_gate builds its command list by calling gate_commands and merges the returned environment into the gate environment, and the only-modules variable stays product_gate's to set
- [ ] every gate case the harvest suite already carries stays green, so the extraction changes neither what the gate runs nor its per-command timeout, red-module parse or timing line
