## Acceptance
- [ ] an Active Task whose reshape is pending yields exactly one reshape row, on the plan branch, launching
- [ ] the same Task also yields its code row held, waiting on the reshape
- [ ] the pair is identical in kind, action, wait and brief kind to the pair a New Task with the same reshape yields, asserted side by side
- [ ] an Active Task whose reshape has already been recorded as applied yields no reshape row
- [ ] a Resolved or Closed Task yields no reshape row, stopped by the row builder's own loop filter
- [ ] a card that is Active and removed and still carries a pending reshape yields no reshape row either, the case that reaches the predicate's own removed guard
- [ ] an Active Task with a conflicting pull request and a pending reshape yields the reshape pair and no rebase row
- [ ] an Active Task whose pull request is closed unmerged and whose reshape is pending yields the reshape pair and no stale-close row, and that close row returns on the tick after the reshape is recorded as applied
- [ ] an Active Task a delivery speaks for yields no reshape row and no held code row, so the pair never re-cuts a member the delivery is building on its lead's branch
- [ ] an Active Task with a pending reshape and an unparked correction pending on it yields no reshape row and no held code row, so the item has exactly one launching session that tick — the correction — the same single row the New state yields
- [ ] the same Task with that correction parked likewise yields no reshape row, because a parked correction still speaks for the item, and the one row it keeps is the parked row waiting on the operator
- [ ] that parked Task gets its reshape pair back on the tick after the correction is cleared
- [ ] an Active Task whose id the trunk already names yields no reshape row, the same answer the New state gets from its on-trunk skip
- [ ] a Task a session already holds yields nothing
- [ ] the reshape row takes the slot and the waiting row takes none
- [ ] the replan module's own suite passes unchanged
