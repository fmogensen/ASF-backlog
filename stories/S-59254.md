## Acceptance
- [ ] parse_all on the card claim `Proves: S-0021 line 6 — tests/guard.test.ts (type guard, size guard, EXIF strip only)` returns ([], [one]) with the refusal `partial claim: "only"` and `raw` the whole trailer line, and `parse` of that same text is []
- [ ] `proves.claim_prose` is the empty string for each of `tests/only-guard.test.ts`, `tests/e2e/half/upload.spec.ts`, `src/guards/except.test.tsx`, `tests/partial.test.js::"refuses a qualified claim"` and `tests/minus.spec.ts`, so `parse_all` counts all five rather than refusing them
- [ ] Each of the seven default markers (only, partial, partly, half, except, not yet, minus) refuses a claim case-insensitively, `half-done` fires on half, the two-word `not yet` matches across tokens, and the refusal names the marker that fired
- [ ] A quoted span is blanked in all three quote shapes, so `tests/guard.test.ts "refuses a half-open range"` is counted — and a marker written inside the quotes is counted too, which is the hole the briefs guard instead
- [ ] A marker in the commit subject only — `fix(B-0001): the first half` above `Proves: S-0077 line 1 — tests/test_a.py` — leaves exactly one counted claim and no refusal
- [ ] `proves.parse_not_proved` reads `Not proved: <S-id> line <n> — <gap>` into a Claim with `test` empty and `refusal` the stated gap, across all three dash forms and a bullet prefix, duplicates collapsed, and does not read a `Proves:` line as one
- [ ] `render_not_proved` renders a refused claim as `- <S-id> line <n> — <refusal> (<test>)` and a declared gap with no parenthesis, `render_not_proved([])` is the empty string, and `render` of a counted claim is byte-identical to its output today
- [ ] `proves.unproved(body, refused={6: partial claim: "only"})` gives line 6 that `why` while line 5 keeps `no proof`, a bare iterable of line numbers gives `partial claim`, and a line that is already proved is absent from the result even when `refused` names it
- [ ] `config_keys.value("proves.partial_markers", PARTIAL_MARKERS)` does not raise, an operator list replaces the built-in seven wholesale, `[]` refuses nothing, and a malformed value keeps the default
- [ ] `proves.partial_markers` is registered in `TYPED` as LIST, is in `KNOWN_CONFIG_KEYS`, and is documented by a `proves:` / `partial_markers:` block in `docs/config.example.yaml`
- [ ] All seven existing classes of `tests/test_proves.py` stay green unchanged and `Claim(story, line, test, raw)` still constructs positionally — proven by tests/test_proves.py
