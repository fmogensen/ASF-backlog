## Acceptance
- [ ] [ ] a row that waits on an item which has no row of its own makes that target the sink, and the waiting item is not a finding
- [ ] [ ] the target's detail says it is waited on, and names the item waiting
- [ ] [ ] a wait whose target is not an item id is never a sink, for each of the keywords decision, landing and build slot
- [ ] [ ] a wait whose target is removed is never a sink
- [ ] [ ] a wait whose target is Resolved or Closed is never a sink
- [ ] [ ] a wait whose target the item map holds no entry for at all is not read as done, and the target is reported
- [ ] [ ] a chain of three waits, where only the last target has no row, reports only the last target
- [ ] [ ] over the same rows and the same item map, the pairs the existing waits_on_without_a_row check returns are the targets sinks reports, so the tick check and the test that states the same property cannot drift
- [ ] [ ] the back-index over the rows is built once per call, asserted by a row list in which many rows wait on the same target
