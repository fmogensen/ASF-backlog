## Acceptance
- [ ] [ ] the module's tree root is the existing env helper, not a second definition of the path
- [ ] [ ] a clock transcript path, a host clock transcript path and both kernel transcript paths come from the module
- [ ] [ ] a job transcript path and the jobs directory of a product come from the module, one implementation each
- [ ] [ ] the metrics module's job transcript path returns the same path as the runtime's, for the same product and job
- [ ] [ ] the two callers that recovered the jobs directory with a fake job name ask the module for it instead
- [ ] [ ] no module in the package but the new one and the env module builds a path under the tree by hand
- [ ] [ ] the installer's ledger gets its path from the module and is rotated by nothing, at no cap
- [ ] [ ] a root log in the tree that no module in the package opens is given no cap and no rotation call site
- [ ] [ ] the module decides a root log's cap from what the factory does to the file, so a name it neither opens nor renders as a clock transcript is capless without being listed as an exception
- [ ] [ ] rotate moves a file over its cap to the one generation suffix and leaves a file under its cap alone
- [ ] [ ] rotate replaces an existing generation rather than keeping a second one
- [ ] [ ] rotate on a path that does not exist does nothing and raises nothing
- [ ] [ ] rotate on a path it cannot write does nothing and raises nothing
- [ ] [ ] the approvals hook traceback log still rotates at its own cap, through the module, keeping one generation
- [ ] [ ] a red gate's output log still rotates at its own cap, through the module, keeping one generation
- [ ] [ ] the asf-opened cap is the value both logs used before this change
- [ ] [ ] the background harvest's log, the product checks' log and the rebuild check's log are each rotated by the parent immediately before the open that hands the file to the detached child
- [ ] [ ] a detached child's log under its cap is left alone by the spawn that opens it
- [ ] [ ] the whole output of the detached child a spawn starts is in the live file, never in the generation that spawn's own rotation made
- [ ] [ ] a detached child's log is rotated at the same cap as a log asf opens per write, not at the clock cap
- [ ] [ ] the path of each detached child's log comes from the module, not from a hand-built join under the tree
