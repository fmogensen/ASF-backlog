## Description

## Acceptance
- [ ] A required check absent from every completed Actions run on the head and declared by no workflow file at that head is not satisfied: the gate returns no merge and the branch records WAITING_CI naming that check
- [ ] The lane prints one line per refused name saying no workflow at the head declares a job for it, so an operator can tell a third-party check from a path-filtered one
- [ ] A required check absent from every run but declared by a job of a workflow at the head is still satisfied and the PR merges on its checks, and the satisfied line names the file that declared it
- [ ] A declared job's literal name answers for a required check, and a required name whose first word is a declared job (a matrix leg, a called workflow's caller/inner) is satisfied by that job
- [ ] When the head's workflow directory, or any single file in it, does not read, no missing required check is satisfied: each waits, with a line saying the workflows at the head did not read
- [ ] A skipped required check whose every answering job concluded skipped is still satisfied with no workflow read, in the same pass in which an undeclared missing check is refused
- [ ] A PR with no missing required check makes no workflow-contents read, and under merge_skipped: never neither the runs nor the workflows at the head are read
- [ ] The workflow scan yields a file's job keys and each job's literal name only: a step's name, a run-block body's jobs-shaped lines and an expression name are not yielded (the expression job's key still is), and a file with no jobs block yields nothing
- [ ] The workflows at a head are read once per head per pass: the gate and the recheck before MERGING reach the same verdict off one read
