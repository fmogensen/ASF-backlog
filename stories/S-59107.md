## Acceptance
- [ ] `declare_entry` renders the `ci.pool` entry a live runner would be, deriving `provider` from its one `provider-<name>` label, `role` from the one label of its own that is a declared role, and `class` from a `class-<name>` label, and leaving `box`, `size` and `slots` out
- [ ] `declare_entry` derives `provider` from the pool's single declared provider when the runner carries no `provider-` label
- [ ] `declare_entry` returns an empty line and a non-empty why naming the declared roles when the runner carries no declared-role label, and an empty line and a non-empty why when it carries two `provider-` labels the pool both declares
- [ ] Every line `declare_entry` renders contains no newline and has balanced braces
- [ ] `pool_insert` adds its lines as new items after the last item of the existing `ci.pool:` list at that list's indentation, leaving every other line of the product text byte-identical -- comments above `pool:` and blocks below it included
- [ ] `pool_insert` returns the text unchanged and a non-empty why for a file with no top-level `ci:`, for a `pool:` under another top-level key, for `pool: discover`, and for an empty `pool:` list
- [ ] `env.loads` of the text `pool_insert` returns does not raise
- [ ] `cmd_reconcile` with `--declare` and `ASF_JOB` set in the environment exits 2, prints a line naming the rule that a session never edits the file that holds its own authority, and leaves the product file byte-identical
- [ ] `cmd_reconcile` with `--declare` exits 2 and writes nothing under `ci.pool: discover`
- [ ] `cmd_reconcile` with `--declare` exits 2 carrying the `ci.pool[N]` problem and writes nothing when the merged pool list would not validate
- [ ] `cmd_reconcile` with `--declare` and no complete entry to write exits 0 saying nothing to write, and leaves the product file byte-identical
- [ ] After `cmd_reconcile` with `--declare` succeeds, `env.validate_product_text` of the new file is empty, `load_pool` of the reloaded product holds the new entry, and the printed line names the runner and the product file path
- [ ] `cmd_reconcile` without `--declare` prints the undeclared-runner count and the rendered entries, leaves the product file byte-identical, and makes no host write
- [ ] `cmd_reconcile` prints a NEEDS OPERATOR line per live runner whose entry cannot be derived, naming what is missing
- [ ] An undeclared runner's action cell in the plan table carries the verdict of its derivation in place of 'not in ci.pool -- untouched', and every declared runner's row is unchanged
- [ ] `--declare` is registered on the `reconcile` parser beside `--apply`, and the two may be given together with the product-file write happening before the label writes
