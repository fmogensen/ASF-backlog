## Description

## Acceptance
- [ ] [ ] a launch with a base cuts its fresh branch from the base branch on origin, not from the trunk
- [ ] [ ] a launch with no base cuts from the trunk, exactly as it does today
- [ ] [ ] a fresh stacked branch is rebased onto its base branch, never onto the trunk
- [ ] [ ] a stacked branch already on origin is not rebased onto the trunk by the launch
- [ ] [ ] a worktree reused for a stacked branch checks the branch out without recutting it from the trunk
- [ ] [ ] the session's environment carries the base branch
- [ ] [ ] the pre-push footprint check diffs the pushed head against the base branch when the environment names one
- [ ] [ ] that diff holds the Task's own paths only, so a stacked push whose paths are inside its footprint is not refused
- [ ] [ ] the same check diffs against the trunk when no base is named
- [ ] [ ] a base the repository cannot resolve leaves the footprint unchecked rather than refusing the push
- [ ] [ ] the brief names the base branch, the fork point and the predecessor card
- [ ] [ ] the brief tells the session not to merge or cherry-pick either the trunk or the base into its branch
- [ ] [ ] the brief's cut-from line names the base branch, never the trunk, for a stacked launch
- [ ] [ ] a cloud session's own checkout line names the base branch as its base
- [ ] [ ] no branch prefix, document path or trunk name is written as a literal by any of this, so the conventions check stays green
