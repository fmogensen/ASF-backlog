## Acceptance
- [ ] [ ] the tests a proof must cover are the test ids the card itself names, read by the still-needed gate's own parser
- [ ] [ ] a test red on the base and green on the head reads as proved
- [ ] [ ] a test whose module is absent at the base and green on the head reads as proved
- [ ] [ ] a test green on the base and green on the head reads as failed, and the reason says it passes without the change
- [ ] [ ] a test green on the base reads as failed even when every other test of the same proof is proved
- [ ] [ ] a test red on the head reads as failed, and the reason says the head is red on a test the checks called green
- [ ] [ ] a test absent at the head reads as failed, and the reason names the missing id
- [ ] [ ] a test whose run returned an error reads as pending, never as failed
- [ ] [ ] a proof with no result at all reads as pending
- [ ] [ ] a pending proof launches no review and charges no round
- [ ] [ ] a failed proof opens a fix round on the pull request's own branch and launches no review session
- [ ] [ ] a failed proof's reasons reach the author as findings, one per test
- [ ] [ ] a proved proof launches the review on the pull request's branch, exactly as the trunk does today
- [ ] [ ] the proof is only asked once the required checks are green, so the check gate still runs first
- [ ] [ ] a pull request whose head already carries a verdict is never proved again
- [ ] [ ] the base side of a proof is the merge base of the head and the trunk, not the trunk's tip
- [ ] [ ] a head that moved produces a new proof rather than reading the old one
- [ ] [ ] a head that did not move reads the cached proof and runs nothing
- [ ] [ ] each side of a proof runs on a fresh detached worktree of its own sha, and the worktree is removed afterwards
- [ ] [ ] the two runs of a proof count against the per-tick test-run budget
- [ ] [ ] a tick whose budget is spent leaves the proof pending rather than guessing it
- [ ] [ ] a dry run runs no test and writes no proof
- [ ] [ ] a document pull request has no acceptance test and reads as proved, so a spec or a plan reaches its review unchanged
- [ ] [ ] with the proof knob off, every pull request reads as proved and the review launch is identical to the trunk's
- [ ] [ ] with the trunk-tests resolver off, the proof is never run and the review launch is identical to the trunk's
- [ ] [ ] a proof the probe could not read leaves the review launch as it is today rather than blocking it forever
- [ ] [ ] the review brief of a proved pull request carries the proof's rows as a fact, beside the checks fact
- [ ] [ ] the judge is a pure function of its proof value and returns the same verdict for the same argument
