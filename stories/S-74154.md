- [x] `trunk_watch.landed_prs` takes both row shapes — `{'sha', 'subject'}` dicts from `trunk_watch.first_parent` and `(sha, subject, …)` tuples from `evidence.main_commits` — and when two rows name one PR number it returns the newest row's sha
- [x] `evidence.queue_landed([(sha, 'merge-queue: #1046 (cloud/T-10485 @ 243ce531)')])` is still `{1046}`, and `evidence.id_evidence` still leaves `1047` in `T-10486`'s `open_prs` while `T-10485`'s is empty — proven by tests/test_pr_cache_trunk.py
- [x] `evidence.chosen_pr` returns the PR list's MERGED candidate with its `merged` sha, and prefers it over a candidate the trunk carries as landed
- [x] `evidence.chosen_pr` returns `(1046, 'MERGED', <the trunk sha>)` for a candidate the PR list still says OPEN whose number `landed` names
- [x] `evidence.chosen_pr` returns `(1046, 'OPEN', None)` when `landed` names nothing, skips a CLOSED candidate, and is `(None, None, None)` with no candidate
- [x] `closing.state_of('task', Ev(merged_sha=<the trunk sha>, green=True, pr_state='MERGED'))` is `Closed` on rule `landed-green`, while `Ev(pr_state='OPEN')` is `Active` on `in-flight` and `Ev(open_prs=(1046,))` is `New` on `planned`
- [x] Over a git clone whose trunk carries the queue's commit while the PR list still says the PR is OPEN, `evidence.facts` builds that Task's plan row with `pr_state` `MERGED` and `merged_sha` set, and ingest's evidence line for the row reads `PR #1046 merged (<sha9>)` and not `PR #1046 OPEN`
- [x] A second pass over the same trunk reads the same row, and the plan row for a PR the trunk does not name keeps the `pr`, `pr_state` and `merged_sha` it has today
