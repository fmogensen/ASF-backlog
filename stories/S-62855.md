## Acceptance
- [ ] lane.head_since(prev, head, now, lane_heads=(head,)) returns prev['head_at'] — a head the lane built in this pass does not move the ruler
- [ ] head_since also honours the chain prev['lane_heads'] carries, so a head the lane built in an earlier pass still keeps head_at
- [ ] With lane_heads empty and the head changed, head_since still returns now, and with the head unchanged it still returns prev['head_at'], then prev['at'], then now — proven by tests/test_gated_correction.py
- [ ] Lane.record persists the chain as lane_heads on the lane record, newest last, and writes it only while the current head is one of them
- [ ] A later pass whose lane_built is empty, on a head the stored chain names, still keeps head_at — the P12 case where normalise_commits and publish_rebuilt write no record in their own pass
- [ ] A session's push — a head in neither lane_built nor the stored chain — moves head_at to now and drops lane_heads from the record
- [ ] The chain is capped at LANE_HEADS_MAX = 20, newest kept, duplicate heads collapsed
- [ ] Lane._repair_naming, Lane.publish_rebuilt and Lane.normalise_commits each append the head they build to f['lane_built'], so a reword, a copy-drop, a sign-off repair and a trunk rebase all leave head_at where the session left it
- [ ] correction_turns_back(rec, corr) answers True for a ruling written 17 s before a lane reword that moved the head — the 2026-10-06 sequence, P4's before-picture
- [ ] correction_turns_back(rec, corr) answers False once a session's push moves the head past the ruling
