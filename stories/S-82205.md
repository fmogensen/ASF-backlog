## Acceptance
- [ ] a Feature with a two-Task bundle and one started Task whose writes are disjoint from both members leaves the lead's after list exactly as it was
- [ ] a lead that already declared an after edge of its own still declares it, and nothing more
- [ ] a started Task whose glob matches a member's path binds the lead
- [ ] a started Task sharing a path with a member that is not the lead binds the lead, not that member
- [ ] a started Task that a member already declares an after edge on is not added to the lead a second time, whether their paths meet or not
- [ ] a started Task whose only common glob is the product's declared shared path does not bind the lead
- [ ] a Task declaring no footprint at all binds nothing and is bound by nothing
- [ ] the migration case still binds the lead on a started Task that shares a path with a member, and adds nothing for a second started Task that shares none
