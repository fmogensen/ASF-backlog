## Description

## Acceptance
- [ ] [ ] a stacked item whose predecessor is being rebuilt keeps its own branch, its pull request and its stack key
- [ ] [ ] that item carries a plan note naming its base branch and the rebuild, and the note is never written to its card
- [ ] [ ] nothing is merged and no auto-merge is enabled on it while it waits
- [ ] [ ] the item is not in LIMBO and is not a merge breach while it waits
- [ ] [ ] once the predecessor pushes its rebuilt head, the successor's conflicting pull request takes one rebase round like any other conflict
- [ ] [ ] that rebase round's launch carries the fork point recorded on the card, so only the successor's own commits are replayed
- [ ] [ ] once the predecessor is Done the successor is retargeted to the trunk and lands, with no manual step at any point
- [ ] [ ] a predecessor whose rebuilds are spent and which is stuck with an owner has the successor torn down, exactly as today
- [ ] [ ] a predecessor that was reverted still tears the stack down
- [ ] [ ] a predecessor that is parked still tears the stack down
- [ ] [ ] a base branch gone from origin with the predecessor not Done still tears the stack down
- [ ] [ ] a base branch kept on origin with no pull request at all still tears the stack down
- [ ] [ ] a tick that plans no write still leaves the stack key in place
