## Description

## Acceptance
- [ ] [ ] `release.DEFAULTS['ci_steps']['upgrade_matrix']` is `upgrade-matrix`, overridable under a product's `release.ci_steps`.
- [ ] [ ] A ninth `Criterion('upgrade_matrix', …)` is met only when every `upgrade-matrix` step of the newest finished trunk run is `success`, and red when the step is absent or any leg is not.
- [ ] [ ] When the forge did not answer, the criterion reads pending in the same wording its neighbours use, not red.
- [ ] [ ] `release.compute` returns the criterion for every product, so a release is not ready while `upgrade_matrix` is unmet.
- [ ] [ ] `schema.changelog_notes()` returns the `note` of every migration introduced since a given version.
- [ ] [ ] A release's `CHANGELOG.md` entry carries a `### Migrations` heading whose lines are those notes.
- [ ] [ ] The `### Migrations` heading is present exactly when a migration landed in that release's range, and absent when none did.
- [ ] [ ] `docs/guide/upgrading.md` states that an upgrade migrates by itself, that an older install reads a newer file with a warning, and how `asf upgrade --to` rolls back.
