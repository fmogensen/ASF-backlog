## Description

## Acceptance
- [ ] [ ] The tick migrates a record below the package's `SCHEMA_VERSION` before its first step, under the record lock, and then runs its steps instead of returning the mismatch.
- [ ] [ ] Each applied step is its own `migrate: schema a → b` commit in the record clone, and running the same migration again commits nothing — proven by tests/test_install.py
- [ ] [ ] The tick log carries `tick: schema a → b pending (additive) — migrating` and then one `migrate: schema a → b` line per applied step.
- [ ] [ ] The tick's drain is bounded by `schema.TICK_DRAIN_S`, overridable as `upgrade.migrate_drain_s`, and never by the module's `DRAIN_TIMEOUT_S`.
- [ ] [ ] Past the bound with an additive gap, the tick logs `tick: schema a → b still pending — N session(s) in flight; the next tick retries` and runs its steps anyway.
- [ ] [ ] Past the bound with a non-additive gap, the tick prints the `NEEDS OPERATOR: run asf schema-migrate --drain` line and returns 3.
- [ ] [ ] A drain that gives up at its bound names the sessions still in flight and returns non-zero — proven by tests/test_install.py
- [ ] [ ] A refused push leaves the migration commit local and says so, and the next tick pushes it.
