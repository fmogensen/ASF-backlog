## Acceptance
- [ ] [ ] version_tuple reads v0.1.62 as (0, 1, 62, 0) and v0.1.62+7 as (0, 1, 62, 7), and reads nothing out of a ref that is not a release tag
- [ ] [ ] newer puts v0.1.9 before v0.1.62, holds v0.1.63 newer than both v0.1.62 and v0.1.62+7, and reports v0.1.62 as not newer than v0.1.62+7
- [ ] [ ] newer is false whenever either side cannot be read as a release, so an install whose release cannot be read is never upgraded on a guess
- [ ] [ ] Two products and three calls inside the hour run git ls-remote once; a call past RELEASE_POLL_S runs it again
- [ ] [ ] latest_release returns the sha from the newest tag's peeled line, not the tag object's own
- [ ] [ ] A failed read stamps the cache entry's timestamp and returns the tag and sha that entry already held; a first-ever failed read returns neither
- [ ] [ ] The remote-release branch of asf status reads that same shared cache and runs no git ls-remote of its own while the entry is fresh
- [ ] [ ] mid_landing returns the item and branch of a product with a landing row, and an empty list for an empty or an unreadable ledger
- [ ] [ ] An install handed a tag runs pipx install --force against that tag, while the red-CI check and the post-install verification are both asked about the tag's sha
