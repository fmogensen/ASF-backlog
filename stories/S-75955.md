## Acceptance
- [ ] GitHub's conflicting is decisive and a clean local merge never overrides it, because it is GitHub's merge that gates the workflow
- [ ] GitHub's mergeable is decisive the other way: the checks are coming and the request waits, even where the local merge names conflicting paths
- [ ] where GitHub reads unknown, or its answer cannot be read, git's own merge of the branch onto the trunk decides, on the refs the pass has already fetched and with no second host call
- [ ] a conflict only git names takes the same two routes as one GitHub names: back to the lane, or red
- [ ] a request whose required checks have none started, where GitHub has not answered its own mergeability and git merges clean, says both of those in its pending line
- [ ] a pending request with a check already in progress keeps its plain line: the clause is for the shape that may never end
