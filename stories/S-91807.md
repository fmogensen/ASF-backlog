## Description

## Acceptance
- [ ] [ ] with a contention re-run claim on the batch's sha the judge asks the host for nothing and the batch stays pending
- [ ] [ ] it writes no claim of its own on that run, so the start queue's once-per-head guarantee is still readable in the cancels file
- [ ] [ ] the pending line names runner contention and the start queue as the half that re-ran it
- [ ] [ ] a contention re-run claim older than the re-run grace with nothing live on the sha cuts the batch again, with an alarm line and no member blamed
- [ ] [ ] a contention re-run claim older than the grace with a run still in progress on the sha leaves the batch pending
- [ ] [ ] a contention refused claim cuts the batch again at once, never red
- [ ] [ ] a contention alarm claim cuts the batch again at once, never red
- [ ] [ ] a contention claim that cuts the batch again writes the queue's existing alarm claim under its batch-sha key, raises the queue cancels doctor row, and leaves the start queue's own claim on the run untouched
- [ ] [ ] a contention claim for another sha is not this batch's and is ignored
- [ ] [ ] the newest claim decides when more than one names the sha
- [ ] [ ] the refused cause is a named constant in the start queue module and the claim its one call site writes is read back by that name
- [ ] [ ] the alarm cause the start queue writes is the constant that already existed, and the string on disk is unchanged
- [ ] [ ] all three contention constants are keys of the honoured-cause table that map to timeout, and members of the runner-claims tuple the red metrics read, so the read side still classifies every claim the start queue writes
