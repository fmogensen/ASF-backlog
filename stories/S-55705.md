## Description

## Acceptance
- [ ] Two `WorktreeStatus.lines(wt)` calls for one unchanged worktree run one `git status --porcelain` process and return the same lines
- [ ] A `git commit` in the worktree between two `lines(wt)` calls runs a second process, because HEAD moved
- [ ] A `git add` that rewrites only the index between two `lines(wt)` calls runs a second process
- [ ] A path that is not a git worktree is answered every time and cached never
- [ ] Two different worktrees never share a cache entry
- [ ] `gather` on a worktree with one uncommitted file, then `commit_leftovers`, then `gather` again through the same snapshot reports `uncommitted == 1` and then `uncommitted == 0`
- [ ] `gather(..., status=None)` and `unpublished(..., status=None)` run their own `git status`, so every existing caller's behaviour is unchanged
- [ ] An untracked file in a worktree still counts as uncommitted work, so `Evidence.pushed` is False and the run is held
