## Description

## Acceptance
- [ ] an ended adjudicate run declaring a successor the record says is Closed retires the item, writing both the removal and the link in one card write
- [ ] the removal text opens with the word retired, in the same words the hand retire command builds, so the two are indistinguishable on the card
- [ ] the successor's own card gains the matching supersedes entry, in a second write of that card alone
- [ ] a supersedes list the successor already carried is kept, the new id merged into it once, and the result sorted
- [ ] the record's own supersession check reports nothing over the applied pair, where it reports one finding when only the item's half is written
- [ ] one History line is appended to each card, naming the field, the counterpart and the job that declared it
- [ ] each write is one signed-off commit of that one card, whose subject names the card it changes
- [ ] the feeder returns no row at all for the retired item, where it returned a launching row before
- [ ] a successor the record says is Resolved passes the gate, and one it says is removed passes too
- [ ] a successor that is still open is refused, the card is byte-identical afterwards, and the item keeps its row
- [ ] a successor the index does not hold is refused, and the line says which clause refused
- [ ] an item naming itself as its own successor is refused
- [ ] a successor already superseded by the item is refused because the new edge would close a ring, both cards are byte-identical, and the line names the ring
- [ ] a declared successor of none is no claim and nothing is written
- [ ] the run is marked read and a second pass over the same run writes nothing
- [ ] two rulings in one pass against the same successor leave both ids in its supersedes list, and the record's supersession check reports nothing over either pair
- [ ] a reciprocal ruling later in that same pass is refused as a ring, because the item's own half was mirrored into the pass's record and not only onto the card
- [ ] that reciprocal ruling is refused even when the successor's own half failed to write, since the item's half is mirrored the moment it lands and not after the pair
- [ ] a second ruling naming the successor the item already carries writes nothing at all: no commit, no History line, both cards byte-identical, the run still marked read, and one line saying it is already applied
- [ ] the removal reason on a card ruled superseded three times is the deciding ruling's words, not the last session's
- [ ] a second ruling naming a different closed successor is refused, both cards stay byte-identical, the line names the successor the item already has, and the record's supersession check still reports nothing
- [ ] a successor the index holds but the pass's own record does not refuses that one ruling and the pass goes on to apply the next, rather than losing the rest of the tick's rulings
- [ ] a pass handed no readable record applies nothing, prints one line, raises nothing, and leaves every run unread so the next tick retries
- [ ] the items map the pass was handed carries the removal and the link once the pass returns, not only the record on disk
- [ ] the same tick's widening rule, reading that same map after the pass, builds nothing for the retired item: no footprint update and no relaunch correction on a removed card
- [ ] an overlap refusal of an applied ruling names the applier as the writer in its line, not the widening rule
- [ ] the existing retire command's own tests pass unchanged
