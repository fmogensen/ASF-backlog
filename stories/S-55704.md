## Acceptance
- [ ] `workflow_id` resolves a selector that is a workflow's display name, its file name or its numeric id to the same id, and asks `actions/workflows` once per instance however many times it is asked — proven by tests/test_flaky.py
- [ ] `runs()` lists `actions/workflows/<id>/runs` and returns a run whose display name differs from the selector — the row today's display-name filter discards — proven by tests/test_flaky.py
- [ ] An unresolvable selector prints one line naming the configured value and the workflow names the listing held, then falls back to the old `actions/runs` listing and filter with today's rows — proven by tests/test_flaky.py
- [ ] A listing that does not answer is never read as "no runs": `runs()` returns None, is asked again on the next call, and the pass leaves `window_from` where it was — proven by tests/test_flaky.py
- [ ] `window_since` is `now - LOOKBACK_DAYS` for a state with no `window_from`, is that value when it is inside the lookback, and is the floor when it is older — proven by tests/test_flaky.py
- [ ] `next_window` is `now - SINCE_OVERLAP_HOURS` when the pass left nothing unread, and one second before the oldest unread run's `created_at` rather than its `ts` when it did — proven by tests/test_flaky.py
- [ ] A run that two passes leave unread because its `jobs()` listing failed is read by the third, the window never having moved past its `created_at` — proven by tests/test_flaky.py
- [ ] A listing of `TRUNCATED_ROWS` rows prints the truncation line carrying that count and still reads its `MAX_RUNS_PER_PASS` batch — proven by tests/test_flaky.py
