## Acceptance
- [ ] [ ] A doctor that exits non-zero after an auto install prints the rollback line naming the release it is leaving and the pin it is restoring, then reinstalls the previous pin's sha through the bare install, writing no second pending marker and draining no second time
- [ ] [ ] The rollback re-renders the clocks through the restored binary
- [ ] [ ] It files one Bug of severity S1 under the signature naming the tag and its RED doctor, titled for the release that failed and the pin the product is held at, with the doctor's own RED rows as the body
- [ ] [ ] A second RED of the same release, on another product or on another tick, bumps that one Bug instead of filing a second
- [ ] [ ] The channel commits and pushes that Bug in the record clone itself, because the tick ends before its record step
- [ ] [ ] It records the outcome rolled-back in the product's channel state and reports rolled-back
- [ ] [ ] The rollback line is matched by the rollback pattern asf release-readiness mines, so it reaches the upgrade-safety criterion as a rollback and holds the next release gate
