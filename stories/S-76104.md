## Description

## Acceptance
- [ ] a correction the lane holds for a conflict with the trunk runs on the host, never in the cloud lane, because the cloud lane collects a session by one commit pushed to the branch and a rebased branch cannot be pushed
- [ ] the trunk-copies rebuild and the commit-subject reword go home for the same reason, named together as one closed list
- [ ] the rule is a floor and not a preference: it holds with the cloud lane as the default executor and it holds on the overflow path, under every rows, mode and accounts setting
- [ ] a correction of any other kind still goes to the cloud lane, a merge correction and the merge-the-trunk-in row included, because their push is a fast-forward the lane carries
- [ ] the decision reads the kind the lane wrote on the hold, carried as a declared fact from the feeder row to the launch, never matched out of the correction's prose
- [ ] the item's own local-only mark keeps its own meaning and its own field: the two reasons a row stays home are not folded into one
- [ ] a row an operator hands the pool by hand routes the same way as one a tick's wave builds
- [ ] what stays on the host is named where an operator reads it: the status view's cloud clause and the cloud doctor's mode row, both composed from the list itself
