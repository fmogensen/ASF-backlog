## Description

## Acceptance
- [ ] [ ] one parse of one text counts the claim whose named test the quarantine list does not hold and refuses the claim whose named test it does, which is the acceptance the card names
- [ ] [ ] a refused claim carries the reason quarantined test and names the entry that quarantined it
- [ ] [ ] a refused claim is never among the counted ones, so nothing that reads the counted half can tick its line
- [ ] [ ] the quarantine list is read one id per line, in file order, with duplicates collapsed
- [ ] [ ] a whole-line comment and the tail of a line after whitespace are dropped, and a blank line yields nothing
- [ ] [ ] a leading list marker and surrounding quotes are stripped, so a plain list file and a yaml list of strings read the same
- [ ] [ ] a leading dot-slash is stripped from both an entry and a claim before they are compared
- [ ] [ ] an entry naming a file quarantines a claim on that file and a claim on any node inside it
- [ ] [ ] an entry naming a node quarantines a claim on the file whole, because a named test one of whose cases does not run is not a whole proof
- [ ] [ ] an entry and a claim match only on a node-separator boundary, so an entry naming one case does not quarantine a claim on a case whose name merely starts with it
- [ ] [ ] an entry and a claim naming different files never match, and no path-suffix or glob match is made
- [ ] [ ] an empty quarantine list refuses nothing, and so does no list at all
- [ ] [ ] a claim that is both qualified in its prose and on a quarantined test is refused as a partial claim, because the claim's own words are read before any product file
- [ ] [ ] a claim on a story the record holds no card for is still refused as unknown story when both checks apply
- [ ] [ ] the refusal renders in the not-proved block with its reason and the test it refused, through the renderer that already exists
- [ ] [ ] the claim grammar, the partial-marker rules, the acceptance-bullet reader, the tick and the untick are unchanged
