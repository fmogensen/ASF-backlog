## Description

## Acceptance
- [ ] `record_health.record` takes the sync's refusal as an argument and stores it as a `checkout` object in `<state dir>/<product>/record-health.json`, beside `ok`
- [ ] The `checkout` object is kept whatever `ok` says: a tick whose record step landed and whose sync refused leaves `ok` true and `checkout.why` equal to `local-changes` in that file
- [ ] `checkout.paths` holds the record-relative blocking paths and no machine path
- [ ] The `checkout` field is written after the sync has run rather than by the in-step `record(...)` call that precedes it, so a refusal that happens in `finish` still reaches the file
- [ ] `record_health.line` reports the checkout when the record step itself is fine, in the shape `CHECKOUT 28 BEHIND since 10:41 — local changes: groom/2026-10-06.md (12 ticks)`
- [ ] `status.stale_cell` prints that sentence for a product whose twelve ticks landed over a dirty checkout, and the row no longer reads `no fresh record in <span>`
- [ ] The row still reports the board as stale rather than being suppressed, so a frozen checkout is never shown as a current board
- [ ] A landed record step and a clean checkout still produce no Stale row at all
- [ ] No new field is added to `metrics/ticks`, and `[step:record]`'s `ok=` is unchanged by whatever the sync did
