## Acceptance
- [ ] [ ] flow is a member of SCOPES, and the three existing scopes are unchanged and in their existing order
- [ ] [ ] an Invariant whose id is I16 and whose scope is flow is in INVARIANTS, exactly once
- [ ] [ ] run on a bare dict returns nothing, and so does run on a bare dict scoped to flow, so the contract that a context without facts has nothing to judge still holds
- [ ] [ ] run over a FlowContext scoped to flow returns one Finding per sink, each with scope flow and with the item id as its subject
- [ ] [ ] run over that same FlowContext scoped to feeder, record or lane returns nothing
- [ ] [ ] a check_i16 that raises costs one line naming the invariant and the error, and no finding, so a broken check never stops a tick
- [ ] [ ] with I16 live and firing, the feeder gate returns every row it was given, including every launching row
- [ ] [ ] with I16 live and firing, the pass that turns a refused row into a waiting row rewords no row
- [ ] [ ] FlowContext carries the item map, the rows, the inflight sessions and the occupancy answer, and defaults to empty rather than raising when a caller has none
- [ ] [ ] flow_context asks for every row the index supports rather than a plan cut to capacity, with the decision rows uncut
- [ ] [ ] flow_context passes only the arguments the candidates call accepts, so a plan inputs mapping that also carries held, gate, bandwidth and failing does not raise a TypeError
- [ ] [ ] the sinks of a plan cut to one seat are strictly more than the sinks of the uncut rows, and the check point reads the uncut ones
