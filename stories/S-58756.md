## Acceptance
- [ ] `tools/check_factory_only.sh` forwards `--head/--base/--ref/--files` to `python3 -m asf.factory_only --product-file .asf/product.yaml` and exits 1 naming `merge.factory_only` for `--head feat/round-j --base main --files asf/cli.py`
- [ ] it exits 1 naming `merge.require_item_id` for `--head fix/exact-path-overlap --base main --files asf/cli.py`, and exits 0 with `is a factory branch` for every prefix of the committed file followed by `T-0001`
- [ ] it exits 0 for each escape: `--head release-bot --base main --files CHANGELOG.md`, `--ref refs/tags/v0.1.214`, and `--head feat/x --base next --files asf/cli.py`; and exits 0 with `not a pull request` when no head, base or `GITHUB_BASE_REF` is given
- [ ] it exits 1 for `--head release-bot --base main --files CHANGELOG.md asf/cli.py`, so the bot escape needs the whole file list to be bot paths
- [ ] with `FACTORY_ONLY_PRODUCT_FILE` pointing at a missing path it exits 2 naming the missing file, never 0
- [ ] given no `--files` and a `GITHUB_BASE_REF`, in a checkout whose `HEAD^1` cannot be read it exits 2 naming the diff it could not read, never an empty file list
- [ ] every entry-point case runs hermetically as a subprocess under `asf.hermetic.build(...)`: no network, no operator config directory, no GitHub
- [ ] `.github/workflows/tests.yml` holds a step whose `run`, read through `env.loads`, is exactly `bash tools/check_factory_only.sh`, at a lower index than the `install with pipx` step
- [ ] that step sits in the single job whose matrix names equal the `MERGE_PR_CHECKS` default read from `tools/merge-pr.sh` text, so the check is required with nothing outside the repository changed
- [ ] the workflow triggers are unchanged with the step added — push only on the trunk, `pull_request` kept — proven by tests/test_workflow.py
- [ ] the four other modules that read `tests.yml` stay green with the step added — proven by tests/test_install.py, tests/test_release.py, tests/test_hermetic.py and tests/test_ci_class.py
