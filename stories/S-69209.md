## Acceptance
- [ ] [ ] An unknown key — top level or in a checked nested table — comes back as a warning and the product still loads, while a shape or enum problem still raises `ConfigError` — proven by tests/test_env.py
- [ ] [ ] `validate_product_text(text)` still returns the fatal problems as the same 3-tuples in the same order, so every existing caller compares like with like — proven by tests/test_env.py
- [ ] [ ] An unknown key is tolerated only when the file's `schema_version` is greater than `schema.CONFIG_VERSION`; in a file at or below the package's version it stays fatal.
- [ ] [ ] `load_config` tolerates an unknown key in `worker_pool` and `cloud` under a newer stamp and raises `ConfigError` on it otherwise.
- [ ] [ ] `asf doctor` shows a non-required `schema` row reading `record <n>, config <n>, package <n>` when the three agree.
- [ ] [ ] Each tolerated key is one `schema` warning line naming the key and `written by a newer asf? (file schema <a>, this package <b>)`.
- [ ] [ ] A pending additive gap is a `schema` warning saying `the next tick migrates`; a pending non-additive gap is red and says `run asf schema-migrate --drain`.
- [ ] [ ] `doctor.check_config` no longer collapses the table to one row when the only problems are tolerated ones: the rest of the rows still render.
