## Description

## Acceptance
- [ ] [ ] `schema.CONFIG_VERSION` is a second number, starting at 1, compared only against `config.yaml`'s and `products/*.yaml`'s own `schema_version` and never against the record's.
- [ ] [ ] `schema.check` reads `config.yaml`'s stamp and names `config.yaml at schema <n>` in its detail when it differs from the package's — proven by tests/test_install.py
- [ ] [ ] `asf schema-migrate` rewrites an existing `schema_version:` line and prints `config.yaml schema_version → <n>` — proven by tests/test_install.py
- [ ] [ ] A `config.yaml` with no `schema_version:` line is given one as the file's first key, and every `products/*.yaml` is stamped the same way.
- [ ] [ ] `PRODUCT_FIELDS` knows `schema_version`, so a stamped product file loads on this release with no unknown-key finding.
- [ ] [ ] A `CONFIG_MIGRATIONS` entry's `renames` and `removes` are applied to `config.yaml` and every `products/*.yaml` on upgrade.
- [ ] [ ] Every file a config migration rewrites is copied to `~/.ASF/state/backups/config-<a>-<stamp>/` before it is rewritten.
- [ ] [ ] `asf init` writes the stamp into the `products/<p>.yaml` it creates.
- [ ] [ ] Neither `docs/config.example.yaml` nor `docs/products.example.yaml` requires `schema_version`: an unstamped file still loads, so every released tag still reads the examples.
