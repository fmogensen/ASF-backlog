## Acceptance
- [ ] [ ] a recorded verdict writes one row naming the item, the pull request, the head, the verdict, the finding count, the round and whether it was charged
- [ ] [ ] the row is written where the verdict is recorded, so the ledger and the stream cannot disagree
- [ ] [ ] a row with an unknown key is refused by the stream's schema
- [ ] [ ] a row missing a required key is refused by the stream's schema
- [ ] [ ] the changes share is the share of verdicts in the window whose verdict is changes
- [ ] [ ] the changes share passes at or below its target and fails above it
- [ ] [ ] the greatest round is the highest charged round any item reached in the window
- [ ] [ ] the greatest round passes at or below its target and fails above it
- [ ] [ ] an uncharged round is not counted by the greatest round
- [ ] [ ] a window with no verdict at all reads as information rather than as a failure
- [ ] [ ] both rows read only the gate's own window
- [ ] [ ] both targets are knobs with the documented defaults of thirty per cent and three rounds
- [ ] [ ] a value of the wrong type under the gate block refuses the product load, naming the key
- [ ] [ ] the gate exits non-zero when either row fails, and zero when every row passes
- [ ] [ ] the two rows read a ledger and a stream only, and run no test and no network call
