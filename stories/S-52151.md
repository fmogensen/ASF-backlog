## Acceptance
- [ ] health.refusal_heads(ev) renders the pair as '<head> <tip>'
- [ ] health.refusal_heads(ev) renders '<head> -' when ev.remote_sha is ''
- [ ] health.refusal_stands(run, ev) is True when the run's publish_refused_heads equals the pair the evidence reads
- [ ] health.refusal_stands(run, ev) is False when the run carries no publish_refused, whatever the pair says
- [ ] A refused publish writes publish_refused_heads as '<worktree HEAD> <origin tip or ->' into the run's registry row beside publish_refused
- [ ] lifecycle.publish is not called again on a second health tick with the local head and the origin tip both unchanged (pub.call_count stays 1)
- [ ] A tick that skips a remembered refusal adds no entry to the pass's found and writes no registry field
- [ ] health.refusal_stands is False when ev.uncommitted is non-zero although both halves of the pair match
- [ ] health.refusal_stands is False when ev.head is '', including when the recorded pair is ' <tip>'
- [ ] health.refusal_stands is False for a run carrying publish_refused but no publish_refused_heads, so a ledger written before this card publishes once more and records the pair
- [ ] A refusal lifecycle.push_failure classes NETWORK_ERROR records no publish_refused_heads
- [ ] publish_gap re-gathers the evidence on its publish-refusal exit, so the recorded pair names the HEAD the worktree holds after the attempt
- [ ] A successful publish clears publish_refused and publish_refused_heads together
- [ ] run_steps drives a republish_steps generator that returns before its first yield without handing any entry to publish_gap — proven by tests/test_health_publish_steps.py
