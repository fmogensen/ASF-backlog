## Description

## Acceptance
- [ ] [ ] `python3 tools/upgrade_matrix.py --plan` prints JSON, oldest first and de-duplicated: the oldest and newest tag of every `major.minor` line, both sides of every tag where `SCHEMA_VERSION` or `CONFIG_VERSION` changed, the newest `KEEP_RECENT` tags, and everything in `PINNED`.
- [ ] [ ] `tools/upgrade_matrix.py` imports nothing from `asf`, and no file under `asf/**/*.py` names it, so `tools/check_conventions.sh` stays clean.
- [ ] [ ] A leg builds its fixture from the tag's own `sample/` with `git archive <tag> sample`, with bare origins for `sample/repo` and `sample/backlog` and a `gh` stub on `PATH`.
- [ ] [ ] A leg installs the tag into its own venv from `git+file://`, then `asf init` and `asf tick` with that install both exit 0.
- [ ] [ ] A tag carrying no `sample/config.yaml` prints `skipped: <tag> carries no sample/`, exits 0, and is counted in the job's summary.
- [ ] [ ] A tag whose `init` or `tick` fails is a leg failure, never a skip.
- [ ] [ ] After `asf upgrade --skip-pipx` from HEAD's venv, one `asf tick` exits 0, `asf doctor --product sample` exits 0, and `index.json`'s `schema_version` equals HEAD's `SCHEMA_VERSION`.
- [ ] [ ] When a migration was due on a leg, the tick's output carried `migrate: schema a → b` and the record clone carries a commit with that subject.
- [ ] [ ] `--mixed <tag>` ticks two products sharing one `config.yaml`, one on the tag's venv and one on HEAD's, and both doctors exit 0 with neither `config.yaml` load raising.
- [ ] [ ] `upgrade-matrix` is a job in `.github/workflows/tests.yml` with a step named `upgrade-matrix`, and that file stays the repository's only workflow.
