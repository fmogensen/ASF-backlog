# Epic: ASF 1.0 — stable core: a small, excellent factory proved on a real product

ASF 1.0, stable core: a small, excellent factory, proved on a real product.

Approved by the operator, 2026-10-08 ("Sounds right .. create a plan for this"). botseon is the reference customer; its real record and load are the proving ground.

## Goal
1.0 means the core loop (spec → plan → build → review → land → report) runs a real product for 7 days on the stable channel with:
- zero S1 reported by the product;
- repair sessions per Feature ≤ 3 (6.4 on 2026-10-08);
- first-push-green rate ≥ 70%;
- every release-readiness criterion met.

## Phase 1: focus (days 1–2)
1. Scope freeze for ASF. Every open Feature outside the core loop is parked (`priority: later`, `parked: stable-core`) by one rule. About 25–30 core Features stay open; the rest stay on the record, untouched, for after 1.0.
2. Bulk-close the auto-filed noise Bugs ("ended N times", "launchable row while a seat is free", "CI red: …" on heads that later went green) by rule, with a History line naming the rule. Only real S1/S2 Bugs stay open.
3. Stability before features, enforced in the feeder: while any S1 Bug is open, no new Feature work launches for that product. Bugs and the ranked stability Features run first.

## Phase 2: prove on real data (days 2–7)
4. F-0305: the staged-guard regression (groom's inbox→done move).
5. F-0306: release rehearsal. Every main push runs the CLI and hooks end to end on a sanitised snapshot of a real record before a version can be offered.
6. Every product-reported defect lands with the regression test that would have caught it. A fix with no such test isn't accepted (review rubric line).
7. F-0301: first-pass-right PRs (path-matched pre-push checks enforced by the hook, a rubric checklist in briefs, the first-push-green metric).
8. F-0300: cheap adjudication (a rule pass before any adjudicate session).
9. The remaining real S1/S2 Bugs, oldest first (B-0014, B-0020, B-0037, B-0134, …).

## Phase 3: channels and learning (week 2)
10. Release channels:
    - edge: ASF runs each green tag on itself;
    - stable: a product receives a version once a week, after rehearsal plus 48 h on edge with no S1;
    - `asf upgrade` defaults to stable.
11. A weekly learning review, generated by code from the record: the product's defects grouped by class. A class seen twice gets one structural fix.
12. A daily scorecard per product: repair per Feature, first-push-green, lead time, cost per Feature, S1 count. It's reported in the daily readiness line.

## Phase 4: 1.0 (week 3)
13. The stable channel runs botseon for 7 days against the goal criteria. A release cut happens only on measured numbers.
14. Then 0.2 (E-0002, self-improvement) reopens the parked scope, ranked by the learning-review data.

## Rules for the whole plan
- No hand-built code. Everything goes through the factory, except when production fully stops and the operator says so.
- One bottleneck at a time: the ranking above is the order.
- The operator gets one daily line (scorecard plus readiness) and one weekly review.
