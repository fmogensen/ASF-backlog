## Statement
Once a product's first release is done, new capability stops being numbered as milestones and accumulates into packs: hotfix packs at any time, feature packs after the trigger the product sets. A pack is one branch, one ledger, one CI run on its final head, one pull request and one row in the roadmap table; a feature pack follows the same plan process a milestone does.

## Context
A burst of small pull requests hides what shipped. A pack gives every fix a code the operator can point at. The trigger for opening feature packs is a business event the product's own configuration names, not a state of the plan.
