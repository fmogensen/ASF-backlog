## Statement
One configuration folder per worker account, each signed in as that account, plus the spawner, the status and login helpers and a shared settings file carrying the accept-edits mode and the deny list. The main session stays on the primary account while jobs use the other accounts' limits. Worker folders are untouched by any account switch.

## Context
Two traps: the login is keyed to the folder's exact path, so copying or moving a folder gives a not-logged-in error; and the sign-in command authenticates whoever the open browser profile is, so the printed URL must be opened in that account's own profile and the page checked before authorising. One caveat stands unresolved and stated to the operator: subscription seats are per person, so running one person's work on colleagues' accounts may breach the provider's terms — team or API billing is the sanctioned route.
