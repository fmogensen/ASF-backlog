## Statement
Dispatch feature work continuously up to the capacity cap whatever the state of open pull requests. Merging requires only the fast required gates green on the exact head; the slow end-to-end jobs never block a merge. A red slow job gets one rerun on the same head; red again, the failing case is quarantined in a follow-up and noted, never debugged inside a feature pull request. One review per wave; fix only critical and important findings; no re-reviews for documentation or test changes. A proof the harness cannot give is recorded as owed, not chased. No planning or housekeeping pass runs unless it unblocks a dispatch. Kept as safety and not as process: never print or source a secret, never sign a commit as someone else, stage explicitly and never stash, stop a job by its process id, never start a model server locally, never touch infrastructure containers, and never give a subagent a browser tool.

## Context
A single pull request took seven commits to make one click-through pass, a flaky job held another, and a rule that nothing starts while anything is open or red kept waves undispatched for hours. The test before starting anything: does this ship or unblock a feature?
