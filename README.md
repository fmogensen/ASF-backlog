# ASF — Autonomous Software Factory: the record

The factory's own backlog, kept the way ASF keeps any product's record: one markdown file per work
item, in git, readable on GitHub, editable by a person or by an agent session, read by every
command through `index.json`. The schema and the tooling live in the code repo
(https://github.com/fmogensen/ASF); this repo is the data — and, because ASF builds itself, the
demo.

This README is the schema. It describes the record as ASF defines it, not as one product happens to
use it: every path, branch prefix and limit named below is a key in the operator's product config
(`~/.ASF/products/<name>.yaml`), never a literal in a tool.

## Vocabulary

| Type | Folder | Id | Parent | What it is |
| --- | --- | --- | --- | --- |
| Epic | `epics/` | `E-0001` | — | a GOAL: a business outcome |
| Feature | `features/` | `F-0042` | Epic | one spec + one plan |
| User Story | `stories/` | `S-0187` | Feature | one requirement row a customer can see |
| Task | `tasks/` | `T-0913` | Story or Feature | one plan task = one branch = one PR |
| Bug | `bugs/` | `B-0007` | Feature, Story or an Epic | something broken, with a severity |
| Decision | `decisions/` | `D-0007` | — | a ruling, who made it and when; items cite it |
| Rule | `rules/` | `R-0042` | — | a factory rule with a check script, or `enforced: false` |

Plus the folders that are not items:

| Folder | What |
| --- | --- |
| `inbox/` | raw thoughts, one file each; the groom pass turns them into cards or writes one question back |
| `groom/` | `YYYY-MM-DD.md`, generated daily; the operator answers one word per line |
| `releases/` | `YYYY-MM-DD-<sha>.md`, generated per prod deploy: every item that reached prod |
| `metrics/` | `ci/`, `sessions/`, `ticks/` — JSONL, one line per event, item id on every line; `daily/` — generated md |
| `docs/` | documents about this record that are not items (e.g. `CONSTITUTION.md`) |
| `tools/checks/` | one read-only script per enforced Rule |

`index.json` — generated by `asf index`: every item's frontmatter and derived fields, keyed by id.
**Scripts read this file, never the md files.** `check` fails when it is stale.

Ids are type prefix + zero-padded number. Id = filename = link target. Only `asf new` (and the
groom/bug-filer paths that share its id minter) mints an id. Folders are flat; moving a Story to
another Feature is a one-line `parent:` change. Ids are unique *within* one backlog; a reference to
another product's record carries that product's prefix (`<product>:F-0019`), never a bare id.

## One item file

```markdown
---
id: F-0042
type: feature
title: A feature
parent: E-0001
priority: need                # need | nice — typed, never derived (the customer's call)
rank: 2                       # epics and features: the operator's order within the parent
decided: true                 # only decided items get work
blockedBy: [F-0051, "operator: an account and a key"]   # items or a named human
area: billing
legacy_id: FREE-1
source: "prototype:docs/specs/23-preamble.md"           # where a card came from, when it was adopted
links:
  spec: docs/specs/2026-09-20-a-feature.md
  plan: docs/plans/2026-09-21-a-feature.md
  prs: [601, 623]
  branches: [spec/a-feature]
# ---- machine ----            written by the tick, never by hand
state: Active
stage: building 2/6
stage_since: 2026-09-21T06:40:00Z
cost: {sessions: 14, fix_rounds: 3, runner_min: 212, usd: 41.20}
evidence:
  - spec on origin/main (2026-09-20 22:40)
  - plan approved r2
  - 2/6 tasks Closed
updated: 2026-09-21T09:10:00Z
---
## Description
What it is and for whom.

## Acceptance
- [ ] one checkable line each

## Non-goals

## History
- 2026-09-21 tick: state New → Active (plan approved)

## Children
- [[S-0187]] Sign-up without a card — Closed

## Backlinks
- [[B-0007]] A banner shows on the wrong plan
```

Type-specific typed fields:

- Task: `stories: [S-0187]` (every Story of the Feature must be on ≥ 1 Task before the plan is
  approved); `writes: ['apps/web/billing/**']` (footprint; omitted = unknown = serialised on purpose).
- Bug: `severity: S1|S2|S3`, `found_in: prod|dev|ci`, `signature: "<job>: <first error line>"`,
  `count: 3`. Same signature = same Bug.
- Epic: `closed: true` (typed by the operator), `budget_usd: 500` (optional; shown, not enforced).
- Decision: `decided_by`, `date`, `supersedes: [D-0027]`.
- Rule: `scope: tick|merge|launch|ci|session|docs|console|quota|infra`, `source:` (where the ruling
  came from), and then either `check: tools/checks/r0042.sh` or `enforced: false` + `reason:` naming
  the data a check would need; `supersedes: [R-0007]` when a later ruling replaced an earlier one —
  both cards stay. Body: `## Statement`, `## Why`, `## Check`, `## Source`.
- Any: `removed: <reason>` (typed, never derived).

**Links:** `[[ID]]` in bodies, plain ids in frontmatter. `index` rewrites `## Children` and
`## Backlinks` in every file; inside those two sections an id is written
`[F-0042](../features/F-0042.md)` so GitHub makes it clickable. Bodies are never rewritten by
`index` — they keep the `[[ID]]` form, and `check` accepts both forms. A bare `D171` in a new body
fails `check`; it must be `[[D-0171]]`.

**The machine block** (everything after `# ---- machine ----`) is written by one function through
the same strict frontmatter parser `check` uses. Frontmatter is a flat, controlled subset of YAML:
scalars, `[a, b]` lists, one level of `key:` nesting for `links` and `cost`, `- item` lists for
`evidence`. No anchors, no multi-line strings, no third-party YAML.

## State — typed intent, derived state

**Typed** (a person or a spec agent): title, description, acceptance, non-goals, parent, priority,
rank, decided, blockedBy, removed, an Epic's `closed`, a Bug's severity. **Derived** (the tick, from
evidence): everything in the machine block. A status a human maintains is a status that lies.

| Type | New | Active | Resolved | Closed |
| --- | --- | --- | --- | --- |
| Epic | typed | any child Active | all children Closed | `closed: true` typed by the operator |
| Feature | no spec on main | spec on main or plan approved | every Task Closed | every Task Closed + merge sha in the prod deploy + the operator's ✓ |
| Story | no impl cited | any Task Active | impl on disk, tests missing | impl + tests on disk |
| Task | in an approved plan, no branch | branch or PR exists | — | PR merged to main |
| Bug | filed | fixer branch/PR | merged to main | in the prod deploy + signature absent 3 days |

`Blocked` is derived from `blockedBy` (any listed item not Closed, or any human string) and shown
beside the state. Feature `stage` is finer than state and drives the board:
`card → spec-draft → spec-review rN → spec-approved → plan-draft → plan-review rN → plan-approved →
building k/n → landed → on-prod`.

Evidence sources are providers, configured per product: the product repo's git (`origin/main` and
the worker branches), the host's PR API, the review files at the path
`conventions.review_pattern` names, the deployed sha (`deploy_sha.provider`), and `metrics/`.

## Who writes

The controller (by hand, small-change lane) and the tick. Nobody else pushes here. Agents'
deliverables in the product repo are the input: a spec → a Feature's Stories; an approved plan →
Tasks; a hotfix brief/report or a CI red → a Bug. `asf ingest` reads them.

## Process rules — enforced by `check`, the feeder and the health table, never by memory

- **Bugs.** S1 → hotfix lane the same tick; S2 → ahead of Feature work in the next capacity pass;
  S3 → groomed. A CI `signature` seen twice in 24 h is auto-filed under the factory Epic. Closed =
  merged + on prod + signature absent 3 days.
- **Prioritising.** Typed: `priority`, `rank`. Derived order: Epic rank → Feature rank → need before
  nice → oldest; first `decided`, unblocked item with a ready mechanical step and no footprint
  overlap wins.
- **Grooming.** `groom/<date>.md` is generated at the retro slot: inbox cards, undecided > 3 d,
  Features without Stories, Stories without Tasks after plan-approved, blocked items whose blocker
  Closed, near-duplicate titles, undecided > 14 d. The operator answers `yes` / `no` / `rank 2` /
  `close` per line; the tick applies it.
- **Breakdown.** A Feature cannot pass `spec-approved` without ≥ 1 Story. A plan cannot be approved
  until every Story is on ≥ 1 Task (`stories:` per task; preflight coverage check).
- **Stale.** Stage limits come from the product config (`stage_limits:`). Over the limit =
  ATTENTION in the health table.
- **Overlap.** `new` refuses a title overlapping an open item of the same type (> 0.6 token overlap)
  and prints the matches. The feeder dispatches a Task only if its `writes:` intersect no Active
  Task's; `check` flags two Active Tasks that intersect.
- **Rules.** `asf rules check` runs every Rule's `check:` in parallel, 10 s each, and prints
  `== RULES <n> checked, <v> violations, <u> unenforced` then one line per violation. A check script
  is read-only — it never merges, cancels, pushes, switches account or starts a container — exits 0
  when clean and 1 with one line per violation; a script that times out, crashes or exits 1 saying
  nothing is itself reported as a violation, so an unrunnable check can never read as a pass. The
  unenforced count is the visible half of the gap: every one of those cards names the data that
  would let it become a check.
- **Learning loop.** CI signatures, refusal patterns and rule violations file factory Bugs; the
  retro ranks them.
- **Front door.** Drop a file in `inbox/`; the groom pass makes a card or asks one question.

## Metrics

`metrics/ci/<day>.jsonl` — one line per CI run: `{run, sha, pr, batch, jobs, minutes, verdict, box,
cancelled, superseded, items: [T-0913]}`.
`metrics/sessions/<day>.jsonl` — one line per session end: `{task, account, model, kind, item,
result, round, pushes, minutes, usd}`.
`metrics/ticks/<day>.jsonl` — one line per tick: `{duration, launches, merges, stalls, refusals,
quota}`.
`metrics/daily/<day>.md` — the scorecard + per-Feature cost rows.

Every event line carries `product:`; a stream file never mixes products. Every item's `cost:` is
summed from these by id. `releases/` is written by the same rollup when the prod sha changes. An
item's `cost:` counts only events matched to that id; a Feature's row in the scorecard and an Epic's
`spend_usd` (next to the typed `budget_usd`, shown, never enforced) sum the subtree.

## Tooling

The commands below come from the `asf` package; this repo ships no tools of its own except
`tools/checks/`.

```
asf new <type> --title "…" [--parent ID] [--priority need|nice] [--area …]
                           [--legacy-id …] [--body-file f] [--force]
asf check [paths…]
asf index
asf ingest [--fresh]
asf groom [--date D] [--apply]
asf stale [--json]
asf file-bugs
asf rules check [--json] [--verbose]
asf evidence --json [--fresh]
asf harvest [--product P] [--dry-run]
asf pr-hygiene [--product P]
tools/checks/rNNNN.sh   one per enforced rule; read-only, < 10 s
.githooks/pre-commit    runs `asf check`; enable with `git config core.hooksPath .githooks`
```

## No CI, no PRs for this repo

The record is edited in a worktree, checked with `asf check`, committed `-s` and pushed to `main`.
The code repo has the tests and the CI.
